34.1 指针再讲一遍：地址、->、nullptr

为什么需要它。 树和链表的每一道题都在和 TreeNode* 打交道。很多人看答案时能跟上，自己写时却不知道 root->left->val 到底做了几件事、什么时候会崩溃。这一节把指针拆到最细。

变量住在带门牌号的格子里

内存可以想成一排很长的格子，每个格子有一个编号，叫地址（address，就像门牌号）。我们写 int a = 42;，编译器就挑一个格子，比如门牌 0x1000，把 42 放进去，并约定"名字 a 指的就是这个格子"。

指针（pointer）也是一个变量，只是它的格子里装的不是普通数字，而是另一个格子的地址。int* p = &a; 读作"p 是一个指向 int 的指针，它的值是 a 的地址"。&a 的意思是"取 a 的地址"。

每个变量占一个带编号（地址）的格子；指针 p 这个格子里装的是另一个格子的地址

有了地址，就能顺着地址找到那个格子：*p 读作"p 指向的那个对象"，这里就是 a 本身，值是 42。写 *p = 7; 之后，a 也变成了 7，因为两者是同一个格子。[1]

结构体指针和 ->

树节点是一个结构体，一个对象里有三个成员：val、left、right。left 和 right 都是指针，装着孩子节点的地址。

struct TreeNode {
    int val;           // 节点里存的数
    TreeNode* left;    // 左孩子的地址；没有左孩子时是 nullptr
    TreeNode* right;   // 右孩子的地址；没有右孩子时是 nullptr
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

逐行读：

行作用
int val;每个节点存一个整数
TreeNode* left;一个指针，值是某个 TreeNode 对象的地址
TreeNode* right;同上，指向右孩子
构造函数new TreeNode(5) 时把 val 设为 5，两个孩子指针设为 nullptr（初始化列表的写法见 22.11）[3]

拿着一个节点指针 root，想读它的 val，要先顺着地址找到对象，再取成员。完整写法是 (*root).val，括号必须有，因为 . 比 * 先结合。这个写法太啰嗦，C++ 提供了等价的简写 root->val。所以 -> 就是"顺着地址找到对象，再取它的成员"。[4]

root 只存一个地址；真正的节点（val、left、right 三个成员）在那个地址上

nullptr 是一个特殊的指针值，意思是"不指向任何对象"。树里它的含义很具体：这里没有节点。叶子的 left 和 right 都是 nullptr。

完整走一遍：root->left->val 做了几件事

一个表达式里有几个 ->，就顺着地址走几步。每走一步前，手里的地址必须真的指向一个对象。

-> 每用一次，就顺着地址走一步

第5步 · 再对 nullptr 用 ->：要顺着一个不存在的地址找对象，程序崩溃

对 nullptr 用 -> 属于未定义行为（C++ 标准不规定会发生什么），在常见平台上表现为程序立刻崩溃，评测平台显示"运行时错误"或"段错误"（Segmentation fault）。[5]

考场结论

  1. 指针的值是地址；-> 每出现一次，就顺着地址走一步。
  2. p->x 等价于 (*p).x。
  3. nullptr 表示"没有"；对 nullptr 用 -> 会崩溃。
  4. 写 p->left->val 之前，要保证 p 和 p->left 都非空。树的递归函数第一行写 if (node == nullptr) return ...;，就是为了让后面的 node-> 永远安全。

练一练：安全地读左孩子

题面：写 int leftValOr(TreeNode* p, int fallback)：p 有左孩子时返回左孩子的值，否则返回 fallback。p 本身也可能是 nullptr。

提示：表达式 p->left->val 里有两个 ->，就有两个地方需要检查。

int leftValOr(TreeNode* p, int fallback) {
    if (p == nullptr) return fallback;          // p 自己是空：没有对象可以 ->
    if (p->left == nullptr) return fallback;    // p 存在，但没有左孩子
    return p->left->val;
}

逐行读：第 1 个 if 保护第一个 ->；第 2 个 if 保护第二个 ->；走到 return 时两个地址都指向真实对象。对 34.2 的树，leftValOr(root, -1) 返回 3，leftValOr(root->right, -1) 返回 −1（8 没有左孩子）。和例题相比改了哪一处：例题只演示了"读"，这里把每一步的空检查都写成了代码。

多选 · 理解检查 1　root 指向值为 5 的节点，它的 left 指向值为 3 的节点，right 为 nullptr；值为 3 的节点两个孩子都是 nullptr。下面哪些表达式能安全求值？

A. root->left->val，结果 3

B. root->right->val

C. root->left->left == nullptr，结果 true

D. (*root).val，结果 5

查看答案与每个选项的解析

A · 正确：root 非空、root->left 非空，两次 -> 都顺着真实地址走。

B · 错误：root->right 是 nullptr，第二个 -> 要在空地址上找对象，运行时崩溃。

C · 正确：只用了两个 ->，都作用在非空指针上；读出的 left 成员值本身是 nullptr，比较结果为 true。

D · 正确：(*root).val 和 root->val 完全等价。

易错点

  • *root.val 会被读成 *(root.val)，编译报错；要写 (*root).val 或 root->val。
  • 只检查了 p != nullptr，就去读 p->left->val：第二步仍可能踩到空指针。
  • 指针没有初始化就使用，里面是随机地址。声明时直接写 TreeNode* p = nullptr;。

速记： 指针存地址；-> 是顺着地址取成员；nullptr 是"没有"，对它用 -> 必崩，先判空再访问。

34.2 二叉树节点：手动 new 出一棵树

为什么需要它。 题目给你的是一个 TreeNode* root，树是怎么在内存里连起来的，需要亲手搭一次才有体会。搭过之后，读题时看到 root->left->right 就能在脑子里画出位置。

二叉树是什么

二叉树（binary tree）由节点组成：最上面有一个根（root）；每个节点最多有两个孩子（child），分成左孩子和右孩子；除根以外，每个节点恰好有一个父亲（parent）。在代码里，"父亲指向孩子"就是父亲的 left 或 right 指针里存着孩子的地址。

一行代码接一个节点

我们用 5 行代码搭出一棵 5 个节点的树。new TreeNode(5) 在堆（heap，程序运行时动态申请的内存区）上造出一个节点，返回它的地址。[6]

TreeNode* makeFiveNodeTree() {
    TreeNode* root = new TreeNode(5);
    root->left = new TreeNode(3);
    root->right = new TreeNode(8);
    root->left->left = new TreeNode(1);
    root->left->right = new TreeNode(4);
    return root;
}

为什么第 4 行要写成 root->left->left，而不是 left->left？ 因为函数里只有 root 这一个变量，其他节点都没有名字，只能从根出发一步步走过去。树题里我们手里永远只有根，这就是为什么几乎所有树的代码都是"从根出发往下走"。

本章约定根在第 1 层、空树高度为 0、只有根的树高度为 1，这与 LeetCode 104 "最大深度"和国内教材常用说法一致。有的书把根的深度记作 0、高度按边数算，遇到时看题目定义即可。

子树是理解递归的钥匙：以 3 为根的子树本身就是一棵完整的二叉树。所以"对整棵树做某事"可以拆成"对根做一点事 + 对左子树做同样的事 + 对右子树做同样的事"，34.4 起的每个函数都是这样写的。

用完要释放

new 出来的节点要用 delete 还回去，否则就是内存泄漏。刷题平台不检查，但自己写测试时养成习惯更好。释放必须先释放孩子、再释放自己：先删了自己，就再也读不到 root->left 了。[7]

void freeTree(TreeNode* root) {
    if (root == nullptr) return;
    freeTree(root->left);
    freeTree(root->right);
    delete root;
}

逐行读：空树没东西可删，直接返回；接着把左子树、右子树整体释放（相信递归能做到）；最后两棵子树都没了，再删自己。这个"先处理孩子、最后处理自己"的顺序，就是 34.4 要讲的后序。

练一练：照着数组手搭一棵树

题面：不用任何建树函数，只用 new 和 ->，搭出层序数组为 [7,2,9,null,6,null,null,5] 的树：7 的左孩子 2、右孩子 9；2 没有左孩子、右孩子是 6；6 的左孩子是 5。

提示：每一行只接一个节点，从根出发写清路径。

TreeNode* makeExerciseTree() {
    TreeNode* root = new TreeNode(7);
    root->left = new TreeNode(2);
    root->right = new TreeNode(9);
    root->left->right = new TreeNode(6);
    root->left->right->left = new TreeNode(5);
    return root;
}

practice 中用 34.3 的 toLevelArray 检查：结果正是 [7,2,9,null,6,null,null,5]，并断言 root->left->right->left->val == 5。和例题相比改了哪一处：节点 5 挂在"左孩子的右孩子的左边"，路径更长，要连写三个 ->。

易错点

  • 先写 root->left->left = ... 再写 root->left = ...：此时 root->left 还是 nullptr，第一行就崩溃。父亲必须先接上，孩子才能挂。
  • 把"深度"和"高度"混着用：深度说的是某个节点在第几层，高度说的是一棵（子）树有几层。
  • 释放顺序写成先 delete root 再递归孩子，读已释放的内存属于未定义行为。

速记： 手里只有根，所有节点都靠 root->… 一路走到；父亲先接上孩子才能挂；先放孩子再放自己。

34.3 从数组建树，再把树写回数组

为什么需要它。 面试官出新题时，常用 LeetCode 的写法描述输入，例如"树 = [1,2,3,null,5]"。你要能把它变成真正的树来测试自己的代码，也要能把自己的树写成这种格式，跟期望结果对比。有了这两个工具函数，任何一道树题都能在本地跑起来。

层序数组怎么读

LeetCode 用层序（一层一层、每层从左到右）列出节点；null 表示这个位置没有节点。

[1,2,3,null,5]：一层一层、从左到右写；null 表示这个位置没有节点

读法的关键一条：只有真实存在的节点，才会在后面占两个位置给自己的孩子；null 没有孩子，也就不再给它留位置。所以我们按顺序给"排队的节点"分配孩子：根 1 领走 2、3；接着 2 领走 null、5；接着轮到 3，可数组已经用完，3 就没有孩子。

"排队、先来先领"正是队列（queue，先进先出）。C++ 的 queue 有三个操作：push(x) 放到队尾，front() 看队首，pop() 删掉队首（不返回值）。[2]

代码：buildTree

为了能直接粘贴 LeetCode 的输入，这里用 vector<string> 存数组，"null" 表示空。

TreeNode* buildTree(const vector<string>& a) {
    if (a.empty() || a[0] == "null") return nullptr;
    TreeNode* root = new TreeNode(stoi(a[0]));
    queue<TreeNode*> q;                 // 等着领孩子的节点
    q.push(root);
    size_t i = 1;                       // 下一个要读的数组下标
    while (!q.empty() && i < a.size()) {
        TreeNode* cur = q.front();
        q.pop();
        if (a[i] != "null") {           // 左孩子
            cur->left = new TreeNode(stoi(a[i]));
            q.push(cur->left);
        }
        ++i;
        if (i < a.size() && a[i] != "null") {   // 右孩子
            cur->right = new TreeNode(stoi(a[i]));
            q.push(cur->right);
        }
        ++i;
    }
    return root;
}

逐行读：

行作用与此刻的状态（以 [1,2,3,null,5] 为例）
第 2 行空数组或根是 null：空树，返回 nullptr
第 3 行stoi 把字符串 "1" 转成整数 1，建根
第 4–5 行队列里放"建好了、还没领孩子"的节点；开始时只有根
第 6 行i = 1：a[0] 已用掉
第 7 行队列有节点、数组也没读完，才继续；任何一个用完就结束
第 8–9 行取出队首，它来领下两个元素
第 10–13 行a[i] 是数字就建左孩子并入队；入队是为了以后轮到它领自己的孩子
第 14 行不管是不是 null，a[i] 都消耗掉了
第 15 行右孩子前先检查 i < a.size()：数组可能正好在左孩子处结束，例如 [1,2]

为什么不能用"下标 i 的孩子在 2i+1、2i+2"？ 那个公式只在每个位置都写出来的完全二叉树上成立。[1,null,2,3] 里，3 在下标 3，按公式会算成 null（下标 1）的孩子，实际它是 2 的左孩子。队列读法只给真节点分配孩子，所以总是对的。

vector<string> toLevelArray(TreeNode* root) {
    vector<string> out;
    queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        TreeNode* cur = q.front();
        q.pop();
        if (cur == nullptr) { out.push_back("null"); continue; }
        out.push_back(to_string(cur->val));
        q.push(cur->left);              // 空孩子也入队，出队时写成 null
        q.push(cur->right);
    }
    while (!out.empty() && out.back() == "null") out.pop_back();   // 去掉末尾的 null
    return out;
}

逐行读：第 4 行即使 root 是空也入队，出队时写一个 null，最后又被删掉，所以空树得到空数组；第 8 行遇到空指针只写 null、continue 跳过后面，空指针没有孩子可入队；第 10–11 行这里没有判空，正是为了让 null 占位；第 13 行删末尾 null，否则 [1,2,3,null,5] 会写成后面多 4 个 null 的样子。

vector<string> splitLevelString(const string& s) {
    vector<string> out;

        if (c == ',' || c == ']') {

            cur.clear();

from collections import deque
def build_tree(a):
    if not a or a[0] is None: return None
    root = TreeNode(a[0]); q = deque([root]); i = 1
    while q and i < len(a):
        cur = q.popleft()
        if a[i] is not None: cur.left = TreeNode(a[i]); q.append(cur.left)
        i += 1
        if i < len(a) and a[i] is not None: cur.right = TreeNode(a[i]); q.append(cur.right)
        i += 1
    return root

考场结论

  1. 层序数组按层、从左到右；null 占一个位置，但它自己不再有孩子位置。
  2. 建树用队列：队首节点依次领走数组里的下两个元素，新建的孩子入队。
  3. 写回数组时，空孩子也入队，出队写 null；最后删末尾 null。
  4. 判断题常考：一般的树不能用 2i+1、2i+2 下标公式读层序数组。

34.4 三种 DFS 遍历：前序、中序、后序

为什么需要它。 "遍历"就是把每个节点恰好访问一次。树题里的大部分代码，本质上都是在遍历的某个时刻做点事。前、中、后序回答的是同一个问题：在递归的哪个时刻处理当前节点。

先在 3 个节点上手跑

void preorder(TreeNode* node, vector<int>& out) {
    if (node == nullptr) return;
    out.push_back(node->val);       // 第一次到达：前序
    preorder(node->left, out);
    preorder(node->right, out);
}

逐行读：第 2 行是递归出口，空节点什么也不做；第 3 行在两次递归调用之前，所以一到达节点就写下它；第 4 行把左子树整棵交给递归（相信它会按前序把左子树写完）；第 5 行再交出右子树。out 按引用传，所有层往同一个数组里写。

一次 DFS 里的三个时刻

DFS（Depth-First Search，深度优先搜索）的意思是：能往下走就一直往下走，走到底再退回来换一条路。树的递归天然就是 DFS。

对每个节点，递归函数会经过三个时刻：

  1. 刚到达，还没进左子树（递归调用之前）；
  2. 左子树走完回来，还没进右子树（两次递归调用之间）；
  3. 右子树也走完，马上要离开（递归调用之后）。

在第 1 个时刻写下节点就是前序（根左右），第 2 个时刻是中序（左根右），第 3 个时刻是后序（左右根）。三种遍历走的路线完全一样，只是"写下"这一行放的位置不同。

void inorder(TreeNode* node, vector<int>& out) {
    if (node == nullptr) return;
    inorder(node->left, out);
    out.push_back(node->val);       // 左边回来：中序
    inorder(node->right, out);
}
void postorder(TreeNode* node, vector<int>& out) {
    if (node == nullptr) return;
    postorder(node->left, out);
    postorder(node->right, out);
    out.push_back(node->val);       // 右边也回来：后序
}

手写结果的方法

考试要你写出某棵树的遍历序列时，按"子树整体"来写最快：

  • 前序：先写根，再把左子树的前序整段写上，再写右子树的前序。[1,2,3,4,5,6,7] → 1，(2 4 5)，(3 6 7) → 1 2 4 5 3 6 7。
  • 中序：左子树的中序整段，根，右子树的中序整段 → (4 2 5)，1，(6 3 7) → 4 2 5 1 6 3 7。
  • 后序：左子树后序，右子树后序，根 → (4 5 2)，(6 7 3)，1 → 4 5 2 6 7 3 1。

每一段括号里又按同样规则展开，这就是递归。写完后用下面这张图核对：前序里根总在自己子树的最前面，后序里根总在最后，中序里根把左右子树隔开。

每个节点标出它在三种序列里排第几。前序：根总在子树最前；中序：根夹在左右子树中间；后序：根总在子树最后

考场结论

  1. 前序 = 递归前写，中序 = 两次递归之间写，后序 = 递归后写。
  2. 前序第一个一定是根，后序最后一个一定是根。
  3. 二叉搜索树（左子树都比根小、右子树都比根大）的中序是从小到大的有序序列。
  4. 需要"先知道孩子的结果才能算自己"的题（求高度、释放内存）用后序；需要"把父亲的信息带给孩子"的题（记录路径、深度）在前序位置处理。

34.5 层序遍历 BFS：队列一层一层往外推

为什么需要它。 有些题关心的是"第几层"：每层的最大值、第 k 层有几个节点、离根最近的叶子。DFS 一头扎到底，层与层交错着访问；我们需要另一种顺序：先把第 1 层全部处理完，再处理第 2 层。

队列让"先发现的先处理"

BFS（Breadth-First Search，广度优先搜索）用一个队列：处理一个节点时，把它的孩子排到队尾。同一层的节点都是上一层的节点按顺序放进来的，所以它们在队列里挨在一起，并且排在下一层的前面。

一轮循环固定四步：看队首（front）→ 删队首（pop）→ 处理它 → 孩子入队（push）。

vector<int> bfsOrder(TreeNode* root) {
    vector<int> out;
    if (root == nullptr) return out;
    queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        TreeNode* cur = q.front();     // 1. 看队首
        q.pop();                       // 2. 删掉队首
        out.push_back(cur->val);       // 3. 处理它

    }
    return out;
}

逐行读：第 3 行空树直接返回，否则第 5 行会把 nullptr 入队，第 9 行的 cur->val 就崩溃；第 7–8 行先 front 再 pop，因为 pop() 不返回被删的元素；第 10–11 行 if (cur->left) 等价于 if (cur->left != nullptr)，只让真节点入队。

vector<vector<int>> levelGroups(TreeNode* root) {
    vector<vector<int>> res;
    if (root == nullptr) return res;
    queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        int sz = (int)q.size();        // 这一层有几个节点，先记下来
        vector<int> level;
        for (int i = 0; i < sz; ++i) {
            TreeNode* cur = q.front();
            q.pop();
            level.push_back(cur->val);
            if (cur->left) q.push(cur->left);
            if (cur->right) q.push(cur->right);
        }
        res.push_back(level);
    }
    return res;
}

为什么 sz 要先存起来？ 如果写成 for (int i = 0; i < (int)q.size(); ++i)，循环里一边出队一边入队，q.size() 每轮都在变。第 2 轮开始时队列是 [2,3]：i=0 出队 2、入队 4，size 仍是 2；i=1 出队 3、入队 5 和 6，size 变成 3，条件 2 < 3 成立，于是把第 3 层的 4 也算进第 2 层。实际输出会变成 [[1],[2,3,4],[5,6]]。

Python 对照（Python 的队列用 collections.deque，popleft() 是 O(1)）：[8]

from collections import deque
def level_groups(root):
    res, q = [], deque([root] if root else [])
    while q:
        level = []
        for _ in range(len(q)):          # range 在开头就算好了次数
            cur = q.popleft(); level.append(cur.val)
            if cur.left: q.append(cur.left)
            if cur.right: q.append(cur.right)
        res.append(level)
    return res

考场结论

  1. BFS 用队列，DFS 用栈（递归时是系统的调用栈）。
  2. 队列先进先出，所以节点按层出队，每层内部从左到右。
  3. 按层分组：每轮先记 sz = q.size()，再出队 sz 个。
  4. 每个节点入队、出队各一次，时间 O(n)；队列里最多同时放一层，空间是最宽那一层的节点数。

练一练 1：第 k 层有几个节点

题面：根在第 1 层，返回第 k 层的节点个数；树没有那么多层时返回 0。

提示：每轮开头的 sz 就是这一层的节点数，数到第 k 轮直接返回 sz。

int countLevelK(TreeNode* root, int k) {
    if (root == nullptr || k < 1) return 0;
    queue<TreeNode*> q;
    q.push(root);
    int depth = 1;
    while (!q.empty()) {
        int sz = (int)q.size();
        if (depth == k) return sz;     // 队列里正好是第 k 层
        for (int i = 0; i < sz; ++i) {
            TreeNode* cur = q.front();
            q.pop();
            if (cur->left) q.push(cur->left);
            if (cur->right) q.push(cur->right);
        }
        ++depth;
    }
    return 0;                          // 树没有这么多层
}

对 [1,2,3,4,null,5,6]，k=1、2、3、4 分别返回 1、2、3、0。和例题相比改了哪一处：多了层号 depth，并且不需要记录值，到第 k 层就提前返回。

34.6 树上递归的两种写法：遍历型与分解型

为什么需要它。 面试出的树题千变万化：节点个数、高度、叶子数、和、最大值、是否存在某个值……它们都能用同一个思路写出来，而且只有两种写法。学会这两种写法，新题的第一步就有了方向。

两种写法

  • 遍历型：把树走一遍（通常用前序位置），手里拿着一个外部变量记答案，走到每个节点时更新它。函数本身返回 void。就像拿着计数器从楼顶走到楼底，每见到一个人按一下。
  • 分解型：函数返回值就是"以 node 为根的子树"的答案。当前节点的答案，用左子树的答案和右子树的答案拼出来。就像每层楼的楼长只向上汇报"我这层及以下一共几个人"。

写分解型之前，先用一句话定下函数含义，然后回答三个问题：

  1. 函数含义：f(node) 返回什么？必须对"以任意节点为根的子树"都成立。
  2. 空树返回什么？这是递归出口。
  3. 知道了 f(node->left) 和 f(node->right)，怎样算 f(node)？

void heightWalk(TreeNode* node, int depth, int& best) {
    if (node == nullptr) return;
    best = max(best, depth);                      // depth：node 在第几层
    heightWalk(node->left, depth + 1, best);
    heightWalk(node->right, depth + 1, best);
}
int heightByWalk(TreeNode* root) { int best = 0; heightWalk(root, 1, best); return best; }

逐行读：depth 按值传，每层有自己的副本，从父亲那里拿到 depth、给孩子传 depth + 1，回到父亲时父亲的 depth 没被改动；best 按引用传（int&），所有层改的是同一个变量，这就是"外部变量"。入口函数里根在第 1 层，所以传 1；空树时 best 保持 0。

怎样选

  • 题目要的量能由"左右子树的同一个量"拼出来（个数、高度、和、是否平衡），优先分解型，代码最短，也没有外部变量要重置。
  • 节点需要"从上面带下来的信息"（深度、路径、到根的和），或者答案是"在遍历过程中顺便统计"的东西，用遍历型，信息用参数往下传。
  • 很多中等题两者混用：函数返回子树的答案给父亲用，同时在外部变量里更新全局答案（第 26 章的"直径""最大路径和"就是这种）。

练一练 2：两棵树是否完全相同

题面：两棵树结构相同、对应位置的值也相同，才算完全相同。写 isSameTree(a, b)。

提示：函数含义是"以 a、b 为根的两棵子树是否完全相同"。出口要分三种：都空、一个空、都不空。

bool isSameTree(TreeNode* a, TreeNode* b) {
    if (a == nullptr && b == nullptr) return true;   // 都空：相同
    if (a == nullptr || b == nullptr) return false;  // 一个空一个不空：不同
    if (a->val != b->val) return false;
    return isSameTree(a->left, b->left) && isSameTree(a->right, b->right);
}

逐行读：第 3 行执行时已经排除了"都空"，所以只要有一个空就是不同；第 4 行两者都非空，才可以安全地用 ->val；第 5 行左对左、右对右，两边都相同才相同。[1,null,2,3] 和 [1,2,null,3] 值的集合一样，但结构不同，结果是 false。和例题相比改了哪一处：递归函数同时拿着两棵树往下走。

  • 遍历型的外部变量写成全局变量，在同一个程序里测第二棵树时忘了清零，答案会叠加。用"入口函数里初始化 + 引用参数"可以避免。
  • 分解型没先写函数含义，合并时就会犹豫"要不要加 1""叶子算不算"。先用一句话写出含义，再写代码。
  • 最大值的出口返回 0，遇到全负数的树就错。

速记： 遍历型 = 走一遍 + 外部变量 + 参数往下传；分解型 = 定含义、空树出口、用左右答案拼自己。

void collectPaths(TreeNode* node, vector<int>& path, vector<vector<int>>& res) {
    if (node == nullptr) return;
    path.push_back(node->val);                       // 走进 node：记下
    if (node->left == nullptr && node->right == nullptr) {
        res.push_back(path);                         // 叶子：复制一份当前路径
    } else {
        collectPaths(node->left, path, res);
        collectPaths(node->right, path, res);
    }
    path.pop_back();                                 // 离开 node：撤销
}
vector<vector<int>> allRootToLeafPaths(TreeNode* root) {
    vector<int> path;
    vector<vector<int>> res;
    collectPaths(root, path, res);
    return res;
}

为什么要 pop_back？ 去掉这一行，path 只增不减。对 [5,3,8,1,4] 的实际输出是：

[5,3,1]
[5,3,1,4]
[5,3,1,4,8]

原因：从 1 回到 3 时 1 还留在 path 里，走进 4 时路线变成 5→3→1→4，可 1 和 4 是兄弟，并不在一条路上。改法就是在函数末尾 pop_back，进门 push 几次，出门 pop 几次。practice 里专门写了少 pop 的 collectPathsNoPop，断言它的输出正是上面这三行错误结果。

另一种写法：path 按值传。 把参数写成 vector<int> path（没有 &），每层函数拿到的是父亲那份的副本，孩子怎么改都影响不到父亲，于是不需要 pop_back。代价是每层都复制一次 path，树很深时更慢。面试中两种都能写，按引用 + pop_back 是更通用的回溯模板。

void collectPathsByValue(TreeNode* node, vector<int> path, vector<vector<int>>& res) {
    if (node == nullptr) return;
    path.push_back(node->val);
    if (node->left == nullptr && node->right == nullptr) { res.push_back(path); return; }
    collectPathsByValue(node->left, path, res);
    collectPathsByValue(node->right, path, res);
}

考场结论

  1. path 表示"从根到当前节点的路线"；进节点 push，出节点 pop，这是回溯的"做选择、撤销选择"。
  2. 判断"到头"用叶子（两个孩子都空），而不是空节点：空节点会让每条路径被记录两次（左空一次、右空一次）。
  3. 简单的数（当前和、当前深度）按值传就行，回到上层自动恢复；vector 这种大对象按引用传、手动 pop。

34.8 从树到图：节点、边、邻接表和 visited

为什么需要它。 社交关系、城市道路、课程依赖都不是树：一个点可以连很多点，走着走着可能绕回原地，有些点之间根本不通。这些结构叫图（graph）。树上的 DFS、BFS 搬到图上，只需要补两样东西：怎样存图，以及怎样避免重复走。

图 = 节点 + 边

图由节点（也叫顶点，vertex）和边（edge）组成，边连接两个节点。边没有方向叫无向图（朋友关系），有方向叫有向图（关注关系、课程先修）。和树相比，图有两个新情况：

  • 可能有环（cycle）：从一个点出发，沿着边能走回自己。
  • 可能不连通：有些点之间没有任何路可走。

树其实是"连通且没有环"的特殊图，所以树上从根往下走永远不会回头，图上就要自己防着。

6 个点、5 条无向边。1→2→4→3→1 能绕回起点（有环）；5、6 和其他点之间没有边（不连通）

邻接表：每个点记下它的邻居

题目通常给边列表：点数 n 和若干对 (u, v)。我们把它转成邻接表（adjacency list）：adj[u] 是一个 vector，列出所有和 u 直接相连的点。点编号从 1 开始时，开 n+1 个位置，下标 0 空着不用，这样 adj[u] 直接对应点 u。[9]

vector<vector<int>> buildGraph(int n, const vector<pair<int, int>>& edges) {
    vector<vector<int>> adj(n + 1);          // 点编号 1..n，下标 0 不用
    for (auto [u, v] : edges) {
        adj[u].push_back(v);                 // 无向边：两头都记
        adj[v].push_back(u);
    }
    return adj;
}

逐行读：第 2 行建 n+1 个空 vector；第 3 行 auto [u, v] 把每个 pair 拆成两个变量（结构化绑定，见 22.10）；第 4–5 行无向边要记两次，否则从 v 出发找不到 u。建完后 adj[1] = {2, 3}、adj[4] = {2, 3}、adj[5] = {6}。

ACM 模式读入通常是这样：

void dfsNoVisited(const vector<vector<int>>& adj, int u, vector<int>& order, int limit) {
    if ((int)order.size() >= limit) return;  // 真代码里没有这一行，会一直递归到栈溢出
    order.push_back(u);
    for (int v : adj[u]) dfsNoVisited(adj, v, order, limit);
}

limit = 8 时输出 1 2 1 2 1 2 1 2。去掉上限，调用栈越堆越高，最后栈溢出（stack overflow），评测显示运行时错误；用 BFS 不加 visited，队列会无限变长，表现为超时或内存超限。

改法是准备一个 vector<bool> visited(n + 1, false)：第一次到达某个点就把它标记为 true，以后再遇到它直接跳过。visited 回答的问题只有一个："这个点以前来过吗？"它保证每个点最多处理一次，所以图的 DFS、BFS 都是 O(n + m) 的时间，n 是点数、m 是边数。

考场结论

  1. 图 = 节点 + 边；可能有环，可能不连通。树是连通且无环的图。
  2. 刷题存图用邻接表 vector<vector<int>> adj(n + 1)；无向边两头都要 push。
  3. 图的搜索必须有 visited；没有它，遇到环就死循环。
  4. 想走遍不连通的图，要在外层对每个点检查"没访问过就从它出发搜一次"（34.9 的 countComponents）。

34.9 图的 DFS（递归与显式栈）和 BFS

为什么需要它。 有了邻接表和 visited，就能回答图上最常见的三类问题：从起点能到哪些点、图有几块、从起点到每个点最少走几步。前两类 DFS、BFS 都行，第三类要用 BFS。

递归 DFS：进门先做标记

void graphDfs(const vector<vector<int>>& adj, int u, vector<bool>& visited, vector<int>& order) {
    visited[u] = true;                       // 进门先做标记
    order.push_back(u);
    for (int v : adj[u]) {
        if (!visited[v]) graphDfs(adj, v, visited, order);
    }
}

显式栈 DFS：自己维护那摞盘子

递归 DFS 依靠系统的调用栈记住"回来以后还要看哪些邻居"。我们也可以自己用 stack 记，效果一样，还能避免递归太深时栈溢出。[10]

vector<int> graphDfsStack(const vector<vector<int>>& adj, int start) {
    vector<bool> visited(adj.size(), false);
    vector<int> order;
    stack<int> st;
    st.push(start);
    while (!st.empty()) {
        int u = st.top();
        st.pop();
        if (visited[u]) continue;            // 同一个点可能被压过两次，第二次跳过
        visited[u] = true;
        order.push_back(u);
        for (int i = (int)adj[u].size() - 1; i >= 0; --i) {   // 倒着压，顺着出
            int v = adj[u][i];
            if (!visited[v]) st.push(v);
        }
    }
    return order;
}

两种写法在这张图上的访问顺序都是 1 2 4 3，practice 里断言了二者相等，在 6 个点的环上也相等。等价的原因：递归时每一层函数"停在 for 循环的某个位置"，等价于栈里还压着"这一层还没看的邻居"；显式栈只是把这些待办事项摆到了明面上。

BFS：按距离一圈一圈往外扩

图的 BFS 和树的层序遍历是同一个骨架，只多了 visited。这里用一个 dist 数组同时扮演 visited：dist[v] == -1 表示还没到过，否则就是从起点到 v 的最少边数。

vector<int> bfsDist(const vector<vector<int>>& adj, int start) {
    vector<int> dist(adj.size(), -1);        // -1 表示还没到过，同时充当 visited
    queue<int> q;
    dist[start] = 0;
    q.push(start);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int v : adj[u]) {
            if (dist[v] == -1) {             // 第一次见到 v
                dist[v] = dist[u] + 1;
                q.push(v);
            }
        }
    }
    return dist;
}

BFS 为什么能求无权最短步数

队列里的点按距离排好了队：先是距离 0 的起点，然后是所有距离 1 的点，再是所有距离 2 的点……因为距离 d 的点只会把距离 d+1 的点放到队尾。所以一个点第一次被发现时，一定是从最近的那一层走过来的，此时写下的 dist 就是最少步数，之后再也不会被改。

DFS 做不到这一点：它会沿一条路一直走下去，第一次到达某点时走的未必是最近的路。看一个 6 个点的环：

6 个点连成一圈。DFS 从 1 出发顺着 2→3→4→5→6 一路走（粗线），到 6 时已走了 5 步；BFS 按层扩展，6 和 2 都在第 1 层

从 1 出发，DFS 顺着 2→3→4→5→6 走，到 6 时已经走了 5 步，而 6 其实和 1 直接相连，最短 1 步。bfsDist(ring, 1) 给出 dist[6] = 1、dist[5] = 2、dist[4] = 3。注意前提：每条边代价相同（都算 1 步）。边有不同权重时要用 Dijkstra（第 26 章）。

Python 对照：

from collections import deque
def bfs_dist(adj, s):
    dist = [-1] * len(adj); dist[s] = 0; q = deque([s])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1: dist[v] = dist[u] + 1; q.append(v)
    return dist

考场结论

  1. 图的递归 DFS：进门标记，只往没访问过的邻居走。
  2. 显式栈 DFS 与递归 DFS 等价；弹出时检查是否已访问，倒序压邻居可让顺序与递归一致。
  3. BFS 入队时就标记；dist[v] = dist[u] + 1。
  4. 无权图（每步代价相同）求最少步数用 BFS；DFS 第一次到达的路线未必最短。
  5. 两种搜索都让每个点处理一次、每条边检查常数次，时间 O(n + m)。

练一练 2：图有几个连通块

题面：无向图（点 1..n）由几块互不相通的部分组成？

提示：外层循环扫每个点；遇到没访问过的点，就是发现了新的一块，从它出发 DFS 一次，把这一块全部标记。

int countComponents(const vector<vector<int>>& adj) {
    int n = (int)adj.size() - 1;
    vector<bool> visited(n + 1, false);
    int comps = 0;
    for (int u = 1; u <= n; ++u) {
        if (!visited[u]) {
            vector<int> order;
            graphDfs(adj, u, visited, order);
            comps++;
        }
    }
    return comps;
}

查看答案与每个选项的解析

A · 正确：1 出队时入队 2、3；2 出队，邻居 1 已有距离，4 第一次见到，入队。

B · 错误：adj[1] = {2, 3}，2 先入队，先出队。

C · 正确：4 由距离 1 的 2 带入；5 和 1 不连通，始终是 -1。

D · 错误：1 的 dist 已经是 0，不会再次入队；这正是 dist 充当 visited 的作用。

易错点

  • BFS 出队时才标记，同一个点会被多次入队，结果虽可能仍对，但效率变差，网格题会超时或内存超限。
  • 显式栈 DFS 在入栈时标记、出栈时不检查，访问顺序会和递归版不同；两者都能走遍连通块，但输出顺序题会答错。
  • 用 BFS 求最短路却给边加了不同权重：BFS 只适用于每步代价相同的情况。

速记： DFS 进门标记、一路走深；BFS 入队标记、一圈圈扩，先到的就是最近的。

34.10 网格就是图：方向数组、越界判断、BFS 与 DFS

为什么需要它。 迷宫、岛屿、地图染色、机器人走格子……笔试里一大半的搜索题是在二维网格上出的。它们看起来没有"边列表"，其实每个格子就是一个节点，相邻的格子之间就有一条边。只要换一种找邻居的方法，前两节的代码可以原样照搬。

怎样把网格看成图

  • 节点：格子 (r, c)，r 是行号，c 是列号，都从 0 开始。
  • 边：上下左右相邻的两个格子之间有边（有的题允许八个方向）。
  • 邻居：不用建邻接表，现算：用两个方向数组表示四个方向的行、列变化量。

第 k 个方向的邻居 = (r + DR[k], c + DC[k])，一个 for k in 0..3 就走遍四个方向

const int DR[4] = {-1, 1, 0, 0};   // 上 下 左 右
const int DC[4] = {0, 0, -1, 1};

找 (r, c) 的邻居就是 for k in 0..3: (r + DR[k], c + DC[k])。每个邻居先过三道检查：是否出界（nr < 0 || nr >= R || nc < 0 || nc >= C）、是否是墙、是否来过。出界检查必须放在最前面，因为它不通过时 g[nr][nc] 本身就是越界访问。

int mazeShortest(const vector<string>& g) {
    int R = (int)g.size(), C = (int)g[0].size();
    int sr = 0, sc = 0, er = 0, ec = 0;
    for (int r = 0; r < R; ++r)
        for (int c = 0; c < C; ++c) {
            if (g[r][c] == 'S') { sr = r; sc = c; }
            if (g[r][c] == 'E') { er = r; ec = c; }
        }
    vector<vector<int>> dist(R, vector<int>(C, -1));
    queue<pair<int, int>> q;
    dist[sr][sc] = 0;
    q.push({sr, sc});
    while (!q.empty()) {
        auto [r, c] = q.front();
        q.pop();
        if (r == er && c == ec) return dist[r][c];   // 第一次取出终点就是最少步数
        for (int k = 0; k < 4; ++k) {
            int nr = r + DR[k], nc = c + DC[k];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;   // 出界
            if (g[nr][nc] == '#') continue;                          // 墙
            if (dist[nr][nc] != -1) continue;                        // 来过
            dist[nr][nc] = dist[r][c] + 1;
            q.push({nr, nc});
        }
    }
    return -1;                                       // 走不到
}

输出路径：记住每个格子从哪来

只要最少步数，dist 就够了；要输出路径，就让每个格子记住"我是从哪个格子走过来的"（from 数组）。BFS 结束后，从 E 开始顺着 from 一路倒退到 S，再把序列反转。

从 E 顺着 from 记录倒着走回 S，再反转：(0,0)→(1,0)→(1,1)→(2,1)→(2,2)→(2,3)→(2,4)→(3,4)→(4,4)，共 8 步

vector<pair<int, int>> mazePath(const vector<string>& g) {
    int R = (int)g.size(), C = (int)g[0].size();
    int sr = 0, sc = 0, er = 0, ec = 0;
    for (int r = 0; r < R; ++r)
        for (int c = 0; c < C; ++c) {
            if (g[r][c] == 'S') { sr = r; sc = c; }
            if (g[r][c] == 'E') { er = r; ec = c; }
        }
    vector<vector<pair<int, int>>> from(R, vector<pair<int, int>>(C, {-1, -1}));
    vector<vector<bool>> seen(R, vector<bool>(C, false));
    queue<pair<int, int>> q;
    seen[sr][sc] = true;
    q.push({sr, sc});
    while (!q.empty()) {
        auto [r, c] = q.front();
        q.pop();
        for (int k = 0; k < 4; ++k) {
            int nr = r + DR[k], nc = c + DC[k];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            if (g[nr][nc] == '#' || seen[nr][nc]) continue;
            seen[nr][nc] = true;
            from[nr][nc] = {r, c};                   // 记下"我是从 (r,c) 走来的"
            q.push({nr, nc});
        }
    }
    vector<pair<int, int>> path;
    if (!seen[er][ec]) return path;                  // 走不到：空路径
    for (pair<int, int> p = {er, ec}; p.first != -1; p = from[p.first][p.second])
        path.push_back(p);                           // 从终点倒着走回起点
    reverse(path.begin(), path.end());
    return path;
}

逐行读要点：from 初值 {−1, −1}，起点的 from 不会被改，所以倒退到起点后下一步的 p.first 是 −1，循环停止；每个格子只在第一次被发现时写 from，写进去的就是最短路上的前一格；路径有 9 个格子、8 步，和 mazeShortest 一致。

from collections import deque
def maze_shortest(g, s, e):
    R, C = len(g), len(g[0]); dist = [[-1] * C for _ in range(R)]
    dist[s[0]][s[1]] = 0; q = deque([s])
    while q:
        r, c = q.popleft()
        if (r, c) == e: return dist[r][c]
        for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C and g[nr][nc] != '#' and dist[nr][nc] == -1:
                dist[nr][nc] = dist[r][c] + 1; q.append((nr, nc))
    return -1

void floodFill(vector<string>& g, int r, int c) {
    int R = (int)g.size(), C = (int)g[0].size();
    if (r < 0 || r >= R || c < 0 || c >= C) return;  // 出界
    if (g[r][c] != '1') return;                      // 水或已经淹过
    g[r][c] = '0';                                   // 淹掉 = 标记 visited
    for (int k = 0; k < 4; ++k) floodFill(g, r + DR[k], c + DC[k]);
}
int countBlocks(vector<string> g) {                  // 按值传：不改调用者的网格
    int cnt = 0;
    for (int r = 0; r < (int)g.size(); ++r)
        for (int c = 0; c < (int)g[0].size(); ++c)
            if (g[r][c] == '1') {
                cnt++;                               // 发现一个新连通块
                floodFill(g, r, c);                  // 把它整块淹掉
            }
    return cnt;
}

逐行读：floodFill 采用"先走过去，进门再检查"的写法：出界返回、不是陆地返回，剩下的一定是没淹过的陆地；第 5 行先淹掉再递归四个方向，与图 DFS"进门先标记"相同，否则两个相邻陆地会互相递归、无限往返。countBlocks 的参数按值传，函数里改的是副本，调用者的网格保持原样。

考场结论

  1. 网格题：格子是节点，相邻格子之间有边；邻居用 DR/DC 方向数组现算。
  2. 每个邻居三道检查，出界检查放第一位。
  3. 最少步数用 BFS + dist；要输出路径再加 from，最后从终点倒退、反转。
  4. 数连通块：外层扫描 + 每块 DFS 一次；改格子本身可以代替 visited。

练一练：最大连通块的面积

题面：同样的 '1'/'0' 网格，返回最大那一块陆地的格子数。上图答案是 4。

提示：让 DFS 返回"从 (r, c) 出发淹掉了多少格"：自己 1 格，加上四个方向各自淹掉的格数。这就是 34.6 的分解型。

int areaDfs(vector<string>& g, int r, int c) {
    int R = (int)g.size(), C = (int)g[0].size();
    if (r < 0 || r >= R || c < 0 || c >= C || g[r][c] != '1') return 0;
    g[r][c] = '0';
    int area = 1;                                    // 自己这一格
    for (int k = 0; k < 4; ++k) area += areaDfs(g, r + DR[k], c + DC[k]);
    return area;
}
int maxBlockArea(vector<string> g) {
    int best = 0;
    for (int r = 0; r < (int)g.size(); ++r)
        for (int c = 0; c < (int)g[0].size(); ++c)
            if (g[r][c] == '1') best = max(best, areaDfs(g, r, c));
    return best;
}

另一个测试：["111","101","111"] 是一个中间空心的环，只有 1 块，面积 8。和例题相比改了哪一处：DFS 从 void 改成返回面积；外层从"计数加 1"改成"取最大"。迷宫输出路径（mazePath）是本节的另一道练习，代码见上。

多选 · 理解检查 10　迷宫 ["S.#", "..#", "#.E"]，方向顺序上、下、左、右，用 mazeShortest 求解。哪些正确？

A. 最少步数是 4

B. dist[1][1] = 2

C. 第 1 层（距离 1）的格子是 (0,1) 和 (1,0)

D. 答案是 3，因为曼哈顿距离 |2-0|+|2-0| = 4 减去起点

查看答案与每个选项的解析

A · 正确：S(0,0)→(1,0)→(1,1)→(2,1)→(2,2)，共 4 步；(0,2)、(1,2) 是墙，只能从 (2,1) 进入 E。

B · 正确：(1,1) 可由 (0,1) 或 (1,0) 一步到达，它们的距离都是 1。

C · 正确：S 的上、左出界，下是 (1,0)，右是 (0,1)，都是空地。

D · 错误：步数就是经过的边数 4；而且有墙时最短步数可能大于曼哈顿距离，要靠 BFS 算。

易错点

  • 先读 g[nr][nc] 再判断出界，边缘格子会越界访问。
  • 网格 DFS 先递归再标记，两个相邻陆地互相调用，直到栈溢出。
  • 行列搞反：g[r][c] 的 r 是行（第几个字符串），c 是列（字符串里第几个字符），R = g.size()，C = g[0].size()。

速记： 网格 = 图；DR/DC 找邻居，出界、墙、来过三道检查；最短步数 BFS，数块和面积 DFS。

34.11 DFS 还是 BFS：按题目要的答案来选

为什么需要它。 遇到一道新题，确认要"搜索"之后，下一个问题就是选哪一种。选错了不一定写不出来，但可能得到错误答案（DFS 求最短步数），或者代码长一倍。

先看题目要的答案是什么，再选搜索方式

题目要的答案选择原因
所有方案、所有路径、路径本身的内容DFS + path 回溯DFS 一次只走一条路，path 天然记录这条路
最少步数、最近的目标、第几层（每步代价相同）BFS + dist按层扩展，第一次到达即最短
能不能到、有几块、每块多大两者都行只关心"走遍"，顺序无所谓；DFS 递归写起来最短
树的层相关（每层最大值、右视图）BFS 分层每轮的 sz 就是一层
需要子树信息（高度、平衡、直径）DFS 后序（分解型）先拿到孩子的结果再算自己
网格很大、递归可能很深（如 1000×1000 全是陆地）BFS 或显式栈 DFS递归深度可达 10⁶，可能栈溢出

练一练：同一个迷宫，用 DFS 判断能否到达

题面：只问 S 能不能到 E，不问步数。用 DFS 写。

bool reachDfs(const vector<string>& g, int r, int c, vector<vector<bool>>& seen) {
    int R = (int)g.size(), C = (int)g[0].size();
    if (r < 0 || r >= R || c < 0 || c >= C) return false;
    if (g[r][c] == '#' || seen[r][c]) return false;
    if (g[r][c] == 'E') return true;
    seen[r][c] = true;
    for (int k = 0; k < 4; ++k)
        if (reachDfs(g, r + DR[k], c + DC[k], seen)) return true;
    return false;
}
bool mazeReachableDfs(const vector<string>& g) {
    vector<vector<bool>> seen(g.size(), vector<bool>(g[0].size(), false));
    for (int r = 0; r < (int)g.size(); ++r)
        for (int c = 0; c < (int)g[0].size(); ++c)
            if (g[r][c] == 'S') return reachDfs(g, r, c, seen);
    return false;
}

逐行读：函数含义是"从 (r, c) 出发能否到达 E"；出界、墙、来过都返回 false；自己就是 E 返回 true；否则标记后试四个方向，任何一个方向能到就立刻返回 true。34.10 的迷宫返回 true，被墙围住的迷宫返回 false。和例题相比改了哪一处：容器从队列换成递归，答案从 int 步数换成 bool；它能判断可达，但第一次找到的那条路不保证最短。

多选 · 理解检查 11　下面哪些题应该优先用 BFS？

A. 国际象棋棋盘上，马从 A 格跳到 B 格最少要几步

B. 输出二叉树中所有根到叶路径

C. 二叉树每一层的平均值

D. 判断无向图里 1 号点和 n 号点是否连通

查看答案与每个选项的解析

A · 正确：每跳一次代价相同，问最少步数，按层扩展第一次到达即答案；邻居是马的 8 种跳法。

B · 错误：要的是路径本身，用 DFS + path 回溯。

C · 正确：按层分组，每轮 sz 个节点求平均。

D · 错误：只问能否到达，DFS、BFS 都可以，并不需要 BFS；递归 DFS 代码更短。

易错点

  • 用 DFS 求最少步数，然后在所有路径里取最小：结果对，但要枚举所有路径，网格稍大就超时。
  • 用 BFS 输出所有路径：BFS 每个点只访问一次，天然只保留一条路。
  • 以为 BFS 一定比 DFS 快：走遍整张图时两者都是 O(n + m)，差别只在顺序。

速记： 要路径、要方案用 DFS；要最少步数用 BFS；只问能不能到、有几块，两者都行。
