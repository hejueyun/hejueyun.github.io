1.1 一个 C++ 程序长什么样

我们先看一个最小的完整程序：读入两个整数，输出它们的和。

#include <iostream>          // 引入"输入输出"功能
using namespace std;         // 之后可以直接写 cin、cout，不用写 std::cin

int main() {                 // 程序从 main 开始执行
    int a, b;                // 声明两个整数变量
    cin >> a >> b;           // 从标准输入读两个数
    cout << a + b << "\n";   // 把结果写到标准输出
    return 0;                // 0 表示正常结束
}

每一行都有固定作用：#include 引入库，using namespace std; 省掉 std:: 前缀，main 是入口，cin >> 读、cout << 写。刷题时最省事的写法是 #include <bits/stdc++.h>（GCC 提供的"一次引入全部标准库"），平台一般都支持；本书的示例逐个写出所需的头文件，以便看清每个容器来自哪个库。

写完代码到运行，要经过编译。 C++ 是编译型语言：编译器（如 g++）先把源代码翻译成机器码，再运行。语法错误在编译阶段就会被拦下（"编译错误"）；数组越界、空指针这类问题要到运行时才出现（"运行时错误"）。

两种做题模式

笔试平台的题目有两种形式，区别在于"谁负责读输入"。

左：只写函数；右：输入输出全部自己处理

  • 核心代码模式：题目给出函数签名，例如 int maxProfit(vector<int>& prices)，你只写函数体，用 return 交出答案。LeetCode 全部是这种。
  • ACM 模式：你写完整的程序，自己从标准输入读数据、按格式打印结果。牛客和很多银行、互联网公司的笔试采用这种模式，读输入的写法见 1.12。

小结： #include 引入库，main 是程序的入口；核心代码模式只写函数并用 return 返回答案，ACM 模式要写完整的 main，自己读输入、打印输出。

1.2 变量与类型：先选对能装下答案的类型

变量就是"有名字、有类型的一块存储"。类型决定这块存储能放什么、放多大。刷题最常用的类型如下：

类型存什么范围（常见平台）典型用途
int整数，4 字节约 −2.1×10⁹ ～ 2.1×10⁹（INT_MAX=2147483647）下标、计数、一般数值
long long整数，8 字节约 ±9.2×10¹⁸大数相加相乘、求和、取模运算
double小数（浮点）约 15–16 位有效数字平均值、几何
char一个字符，本质是小整数'a' 的编码是 97字符串处理
booltrue / false—标记、visited 数组

溢出：结果超过类型范围

int 最大约 21 亿。两个 10 万相乘是 100 亿，放不进 int。有符号整数溢出在 C++ 中是未定义行为，结果不可信。解决方法是在计算发生前就转成 long long：

long long big = 1LL * 100000 * 100000;   // 1LL 让整个乘法按 long long 计算，得到 10000000000

写成 long long big = 100000 * 100000; 不行：右边两个 int 先相乘（已经溢出），之后才转换成 long long，转换来得太晚。

怎样判断要不要 long long？ 看题目给的数据范围：n 个数、每个最大 10⁹，求和最大可到 n×10⁹，只要 n≥3 就超过 int；两个 10⁵ 级别的数相乘超过 10⁹ 时也要用 long long。

整数除法和取余

两个整数相除，结果仍是整数，小数部分向零截断（直接丢掉）；取余 % 的符号跟被除数一致。[1]

表达式结果原因
7 / 233.5 向零截断
-7 / 2−3−3.5 向零截断（不是 −4）
-7 % 2−1满足 (−7/2)×2 + (−7%2) = −7
7.0 / 23.5有一边是 double，就按小数除

这条规则有两个实际用处：判断奇偶要写 x % 2 != 0（负奇数的余数是 −1，写 x % 2 == 1 会漏掉负数）；求平均值要先转 double，写成 sum / 2.0。

二分查找里的 mid 为什么写成 lo + (hi − lo) / 2

lo 和 hi 都接近 21 亿时，lo + hi 会超出 int。改写成 lo + (hi - lo) / 2：先算距离（不会溢出），再加回起点，数学上与 (lo+hi)/2 相同。

先算差再加回起点，中间结果始终在 int 范围内

字符就是小整数

char 存的是字符编码。小写字母编码连续，所以 c - 'a' 得到 0～25，正好当数组下标：

'c' - 'a'          // 2
char('a' + 3)      // 'd'

这个技巧把"统计 26 个字母出现次数"变成"一个长度 26 的数组计数"，1.6 会用到。

多选 · 理解检查 1　int 范围约 ±2.1×10⁹。下列哪些写法能正确得到 10⁵×10⁵ = 10¹⁰？

A. long long r = 1LL * 100000 * 100000;

B. long long r = 100000 * 100000;

C. long long r = (long long)100000 * 100000;

D. int r = 100000LL * 100000;

查看答案与每个选项的解析

A · 正确：1LL 是 long long，乘法从第一步起就按 long long 计算。

B · 错误：右边先按 int 相乘、先溢出，之后才赋值给 long long。

C · 正确：先把第一个数转成 long long，乘法按 long long 计算。

D · 错误：计算正确，但结果放回 int 时装不下。

单选 · 理解检查 2　C++ 中 -7 / 2 和 -7 % 2 分别是多少？

A. -3 和 -1

B. -4 和 1

C. -3.5 和 0

D. -3 和 1

查看答案与每个选项的解析

A · 正确：整数除法向零截断，余数符号与被除数相同。

B · 错误：这是向下取整的规则（Python 的 // 和 % 就是这样），C++ 不是。

C · 错误：两个 int 相除结果仍是整数。

D · 错误：(-3)×2 + 1 = -5 ≠ -7，余数应为 -1。

小结： 根据数据范围选择 int 还是 long long，相乘之前先转换类型；整数除法向零截断；c-'a' 把小写字母变成 0～25 的下标。

1.3 条件与循环：用"循环变量的含义"控制边界

if / else 做选择，for / while 做重复。刷题中大部分 bug 出在循环边界上：多走一步越界，少走一步漏掉元素。

vector<int> a = {4, 7, 1, 9};
int best = a[0];                         // 当前见过的最大值
for (int i = 1; i < (int)a.size(); ++i) {
    if (a[i] > best) best = a[i];
}
// best == 9

写循环前先用一句话说出循环变量的含义："i 是下一个要看的下标，[0, i) 已经看过，best 是 [0, i) 的最大值"。有了这句话，边界就能推出来：

  • 开始时只看过 a[0]，所以 i = 1、best = a[0]；
  • 所有下标都要看到，最后一个下标是 size()-1，所以条件是 i < size()；
  • 循环结束时 i == size()，[0, size()) 全部看过，best 就是答案。

逐步执行：求最大值

1 / 5

第1步 · 开始：只看过下标 0，best=4

best = 4
2 / 5

第2步 · i=1：7 > 4，更新 best

best = 7
3 / 5

第3步 · i=2：1 不大于 7，不变

best = 7
4 / 5

第4步 · i=3：9 > 7，更新 best

best = 9
5 / 5

第5步 · i=4 = size()，条件不成立，循环结束

[0,4) 全部看过，答案 best = 9

范围 for 是更短的写法，适合"每个元素都看一遍、不需要下标"的场合：

for (int x : a) sum += x;              // x 是每个元素的副本
for (int& x : a) x *= 2;               // 加 & 后 x 就是元素本身，可以修改

while 适合"不知道要循环几次，只知道何时停"的场合，例如链表遍历 while (p != nullptr)、二分查找 while (lo < hi)。

小结： 写循环之前先说清循环变量代表什么、哪些元素已经处理过，边界由这句话推出；只读元素用 for (int x : a)，要修改元素用 for (int& x : a)。

1.4 函数与参数传递：值、引用、const 引用

函数把一段逻辑打包，起个名字，以后反复调用。参数有三种常见写法，区别在于函数里拿到的是副本还是原对象。[2]

void addOneByValue(int x) { x += 1; }     // 拿到副本
void addOneByRef(int& x)  { x += 1; }     // 拿到原变量本身（引用 = 别名）

int a = 5;
addOneByValue(a);   // a 仍是 5
addOneByRef(a);     // a 变成 6

按值：改副本，不影响 a；按引用：x 和 a 是同一个变量

为什么 LeetCode 的函数签名常写 vector<int>& nums？

  1. 省时间：按值传递会把整个数组复制一遍，n=10⁵ 时每次调用都复制 10⁵ 个数；引用不复制。
  2. 允许原地修改：像"移动零""旋转数组"要求直接改输入数组，必须用引用。

只读又不想复制时，写 const vector<int>& nums：引用避免复制，const 保证函数里不会误改。

long long sumOf(const vector<int>& v) {   // 只读，不复制
    long long s = 0;
    for (int x : v) s += x;
    return s;
}
void swapByRef(int& a, int& b) { int t = a; a = b; b = t; }   // 交换必须用引用
写法拿到什么能改调用者吗复制开销典型场合
int x副本不能小类型可忽略int、char 等小参数
vector<int>& v原对象能无需要原地修改
const vector<int>& v原对象（只读）不能无大对象只读

易错点： 递归时把 vector<int> path 按值传，每层都复制一份，速度慢但逻辑仍对；按引用传更快，但"做选择后要撤销"（见 8.5 回溯）。

小结： 小类型按值传递，大对象只读时用 const 引用，需要修改原数据时用引用。

1.5 vector：会自动变长的数组

vector<T> 是刷题用得最多的容器：元素连续存放，可以用下标 O(1) 访问，在尾部添加、删除元素均摊 O(1)。

vector<int> v;               // 空数组
v.push_back(3);              // [3]
v.push_back(1);              // [3,1]
v.push_back(4);              // [3,1,4]
v.pop_back();                // [3,1]   删掉最后一个
v.size();                    // 2
v.back();                    // 1       最后一个元素
v[0];                        // 3
vector<int> zeros(5, 0);     // [0,0,0,0,0]  5 个 0

合法下标是 0 ~ size()-1；size() 本身是越界位置

二维 vector：矩阵、DP 表、网格

m 行 n 列、全部初始化为 0：

vector<vector<int>> grid(m, vector<int>(n, 0));
grid[i][j] = 7;              // 第 i 行第 j 列
grid.size();                 // 行数 m
grid[0].size();              // 列数 n

读法：外层 vector 有 m 个元素，每个元素都是一个"长度为 n、全 0 的 vector<int>"。

grid(3, vector<int>(4, 0)) 后执行 grid[2][3] = 7

最容易错的一点：size() 是无符号数

size() 返回的类型是 size_t，它是无符号整数，只能表示 0 和正数（64 位平台上最大为 18446744073709551615）。当一个表达式里同时出现 size_t 和 int 时，C++ 先把 int 一侧转换成 size_t，再做比较或运算。非负的 int 转过去，数值不变；负的 int 转过去，会绕回成一个极大的正数，例如 −1 变成 18446744073709551615。所以判断一种写法是否安全，只需看两件事：参与比较的 int 会不会是负数；减法的结果会不会是负数。

vector<int> v;                 // 空数组
deque<int> d{1, 2, 3};
int k = -1;
d.size() > 1                   // true：1 是非负常量，转成 size_t 后还是 1
d.size() > k                   // false！k 被转成 18446744073709551615，3 比它小
(int)d.size() > k              // true：两边都是 int，按普通整数比较 3 > -1
v.size() - 1                   // 18446744073709551615：无符号的 0 减 1 绕回成最大值
(int)v.size() - 1              // -1

逐条来看：

  • 和非负常量比较是安全的。 d.size() > 1、v.size() == 0、s.size() >= 2 中，常量转成 size_t 后数值不变，比较结果就是"元素个数是否大于 1"，不需要改写，编译器也不会警告。1.9 的 while (d.size() > 1) 就属于这种情况。

  • 做减法要先转 int。 空数组上 v.size() - 1 不是 −1，而是极大的数，所以下面的循环会一直往后读，越界：

    for (int i = 0; i <= v.size() - 1; ++i)    // v 为空时，v.size()-1 是一个巨大的数

    写成 i < (int)v.size()，或者在减法之前先转换：(int)v.size() - 1。

  • 和可能为负的变量比较，必须先转 int。 上面的 d.size() > k 在 k = −1 时得到 false，结果是错的。这类变量很常见：初值为 −1 的"答案"、i - 1、j - k 这样的差值。用 -Wall 编译时，编译器会对 size_t 与 int 变量的比较给出 -Wsign-compare 警告，看到这条警告就要检查另一边会不会是负数。

  • 循环变量是 int 时，也写成 i < (int)v.size()。 i < v.size() 中 i 从 0 开始，不会是负数，结果其实是对的，但同样会触发 -Wsign-compare 警告。统一转成 int，两边类型一致，警告里就只剩下真正需要检查的地方。

为什么转成 int，而不是把所有变量都改成 size_t？刷题时内存限制只有几百 MB，容器不可能装下超过 INT_MAX（约 21 亿）个元素，所以 (int)v.size() 总是准确的；转换之后所有运算都是普通的带符号整数运算，出现负数时也是真正的负数，不会悄悄绕回。反过来，把变量都声明成 size_t，i - 1、j - i 这样的减法又会在结果为负时绕回。支持 C++20 的平台还可以写 std::ssize(v)，它直接返回带符号的长度，效果和 (int)v.size() 相同。

写法是否安全怎么写
d.size() > 1、v.size() == 0：和非负常量比较安全不用改
i < v.size()：int 循环变量从 0 开始结果正确，但有警告写成 i < (int)v.size()
d.size() > k：k 是可能为负的 int 变量错误写成 (int)d.size() > k
v.size() - 1、v.size() - k：做减法空数组或 k 较大时错误写成 (int)v.size() - 1，或先判断非空
v.size() >= 0恒为真，判断没有意义想判断非空写 !v.empty()

多选 · 理解检查 3　vector<int> v{5, 6}; int best = -1; 下列哪些表达式的值与"把 v.size() 当作普通整数 2"时的直觉不同？

A. v.size() > 1

B. v.size() > best

C. v.size() - 3 < 0

D. (int)v.size() - 3 < 0

查看答案与每个选项的解析

A · 错误：1 是非负常量，转成 size_t 不变，结果为 true，与直觉一致。

B · 正确：best = −1 被转成 18446744073709551615，2 比它小，结果为 false；直觉上 2 > −1 应为 true。要写成 (int)v.size() > best。

C · 正确：无符号减法 2 − 3 绕回成极大的正数，它不会小于 0，结果为 false；直觉上 −1 < 0 应为 true。

D · 错误：先转成 int 再减，得到 −1，−1 < 0 为 true，与直觉一致。

操作作用复杂度
push_back(x) / pop_back()尾部加 / 删均摊 O(1)
v[i]访问第 i 个O(1)，不检查越界
size() / empty()元素个数 / 是否为空O(1)
insert(v.begin()+i, x) / erase(v.begin()+i)中间插 / 删O(n)，后面元素整体移动
clear()清空O(n)
sort(v.begin(), v.end())升序排序O(n log n)
reverse(v.begin(), v.end())反转O(n)

v.begin() 和 v.end() 是迭代器，可以理解为"指向第一个元素"和"指向最后一个元素之后"的位置标记；标准库算法都接收这样一个左闭右开区间 [begin, end)。

多选 · 理解检查 4　vector<vector<int>> g(3, vector<int>(4, 0)); 之后，哪些正确？

A. g.size() 是 3，g[0].size() 是 4

B. g[3][0] 是合法访问

C. g[2][3] 是最后一行最后一列

D. g 中共有 12 个 int

查看答案与每个选项的解析

A · 正确：外层 3 个元素（行），每行长度 4（列）。

B · 错误：行下标只能是 0、1、2。

C · 正确：行 0~2、列 0~3。

D · 正确：3×4=12。

小结： 合法下标是 0 到 size()−1；二维 vector 写成 vector<vector<int>> g(m, vector<int>(n))；size() 是无符号数，和非负常量比较可以直接写，做减法或和可能为负的 int 变量比较时先转成 int，循环条件写成 i < (int)v.size()。

1.6 string：字符组成的 vector

string 的用法和 vector<char> 很像，另外多了拼接、截取、查找等字符串专用操作。[3]

string s = "hello";
s += " world";            // 拼接："hello world"
s.size();                 // 11

1.7 unordered_map 与 unordered_set：O(1) 查"见没见过"

哈希表回答两类问题：某个键是否出现过（set），某个键对应什么值（map）。查找、插入平均 O(1)。[4]

经典例子：两数之和

题目：数组中找两个数，和等于 target，返回它们的下标。

暴力做法是两层循环，O(n²)。换个角度：扫描到 nums[i] 时，我们需要的另一个数是 target - nums[i]；只要能 O(1) 回答"它之前出现过吗、在哪个下标"，一次扫描就够了。这正是哈希表的用途。

seen 保存之前出现过的值到其下标的映射，i 是当前下标，need 是当前数需要配对的值。

vector<int> twoSum(const vector<int>& nums, int target) {
    unordered_map<int, int> seen;            // 值 -> 下标（只存 i 之前的元素）
    for (int i = 0; i < (int)nums.size(); ++i) {
        int need = target - nums[i];
        auto it = seen.find(need);
        if (it != seen.end()) return {it->second, i};
        seen[nums[i]] = i;                   // 先查后存：不会把自己和自己配对
    }
    return {};
}

1.8 map 与 set：自动保持有序

map 和 set 的接口和哈希版本几乎一样，区别是内部按键排序（红黑树实现，见 第 15 章），所以：

  • 遍历时按键从小到大；
  • 能回答"第一个不小于 x 的键是谁"（lower_bound）；
  • 查找、插入、删除是 O(log n)，比哈希表的平均 O(1) 慢一些。
map<int, string> m = {{3, "c"}, {1, "a"}, {2, "b"}};
for (const auto& [key, val] : m) cout << val;   // 输出 abc：按键 1,2,3 的顺序
set<int> st = {10, 20, 30};
*st.lower_bound(15);   // 20：第一个 >= 15 的元素
*st.lower_bound(20);   // 20
st.upper_bound(30) == st.end();   // true：没有 > 30 的元素

lower_bound：第一个 ≥ x；upper_bound：第一个 > x

选哪个？ 只需要"存在吗 / 计数"用 unordered_*；需要有序遍历、找前驱后继、维护一个动态有序集合时用 map/set。有重复元素的有序集合用 multiset。

小结： map 和 set 按键有序，操作是 O(log n)，支持 lower_bound；unordered 版本无序，操作平均 O(1)。

1.9 stack、queue、deque、priority_queue

vector 可以在任意位置读写，这四个容器则只开放特定的进出口：栈只能在一端进出，队列一端进、另一端出，双端队列两端都能进出，优先队列每次只能取出当前最大（或最小）的元素。进出口受到限制，下一个被处理的元素也就随之确定，所以选哪个容器，取决于题目要求“下一个该处理谁”。

四种受限容器：用哪个，取决于下一个该处理谁

容器下一个取出的是典型题型
stack最后放进去的括号匹配、单调栈、DFS 的显式栈
queue最早放进去的BFS、层序遍历、按到达顺序排队处理
deque两头都可以滑动窗口最大值（单调队列）、两端同时收缩
priority_queue当前最大（或最小）的前 K 大、合并 K 个有序链表、Dijkstra

注意 pop() 不返回值。 四个容器的 pop() 都只删除元素、不返回它，所以要先用 top()、front() 或 back() 读出来，再 pop()。对空容器调用 top()、front()、pop() 是未定义行为，调用前要先用 empty() 检查。[5]

栈：括号匹配

括号必须按“后打开的先关闭”的顺序配对，这正是栈后进先出的顺序。规则是：遇到左括号就压栈；遇到右括号时，栈顶必须是与之配对的左括号，然后把它弹出；扫描结束时栈必须为空。

bool isValid(const string& s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') { st.push(c); continue; }
        if (st.empty()) return false;          // 右括号多了
        char open = st.top(); st.pop();
        if ((c == ')' && open != '(') || (c == ']' && open != '[') || (c == '}' && open != '{')) return false;
    }
    return st.empty();                         // 左括号多了也不合法
}

队列：按到达顺序处理

队列从队尾 push 进入，从队头 front 读取、pop 删除，先到的先处理。一个元素处理到一半、还要再处理时，把它重新放回队尾，就得到“轮流处理”的效果。下面模拟操作系统的时间片轮转：第 i 个任务需要 need[i] 个时间单位，每次最多运行 q 个单位，没做完就回到队尾排队，函数返回各任务完成的先后顺序。

vector<int> roundRobin(const vector<int>& need, int q) {
    queue<pair<int, int>> qu;                  // (任务编号, 还需要的时间)
    for (int i = 0; i < (int)need.size(); ++i) qu.push({i, need[i]});
    vector<int> order;                         // 完成的先后顺序
    while (!qu.empty()) {
        auto [id, rest] = qu.front(); qu.pop(); // 先读队头，再删除
        if (rest <= q) order.push_back(id);     // 这一轮能做完
        else qu.push({id, rest - q});           // 做不完，回到队尾
    }
    return order;
}
// roundRobin({5, 2, 7}, 3) == {1, 0, 2}

以 need = {5, 2, 7}、q = 3 为例：任务 0 运行 3 个单位后还剩 2，回到队尾；任务 1 只需 2，第一个完成；任务 2 运行 3 后还剩 4，回到队尾；任务 0 用 2 完成；任务 2 再运行 3 后剩 1，回到队尾，最后完成。所以完成顺序是 1、0、2。图和树上的广度优先搜索（BFS）也是同样的模式：先发现的点先扩展，见 6.5 层序遍历 和 10.10 广度优先搜索。

双端队列：两端都能进出

deque（double-ended queue）在头尾两端插入和删除都是 O(1)，还能像 vector 一样用下标 d[i] 访问。它的接口是 push_back、push_front、pop_back、pop_front，以及读取两端的 front()、back()。[6]

vector<int> dequeOps() {
    deque<int> d;              // []
    d.push_back(2);            // [2]
    d.push_back(3);            // [2, 3]
    d.push_front(1);           // [1, 2, 3]
    d.push_front(0);           // [0, 1, 2, 3]
    d.pop_back();              // [0, 1, 2]
    d.pop_front();             // [1, 2]
    d[0] = 7;                  // [7, 2]：deque 也能用下标访问
    return vector<int>(d.begin(), d.end());
}
// dequeOps() == {7, 2}

例一：从两端向中间比较。 判断回文串时，要不断比较并去掉首尾两个字符，正好用到 deque 两端都能删除的能力：

bool isPalindromeDeque(const string& s) {
    deque<char> d(s.begin(), s.end());
    while (d.size() > 1) {
        if (d.front() != d.back()) return false;   // 两端字符不同
        d.pop_front();                             // 两端都去掉，继续比较里面
        d.pop_back();
    }
    return true;                                   // 剩 0 个或 1 个字符
}
// isPalindromeDeque("level") == true，isPalindromeDeque("abca") == false

循环条件 d.size() > 1 不需要转成 int：另一边是非负常量 1，转成 size_t 后数值不变（规则见 1.5）。

例二：滑动窗口最大值。 长度为 k 的窗口从左向右滑动，要求每个窗口中的最大值。deque 中存放下标，并保持这些下标对应的值从队头到队尾递减：新元素 a[i] 进来时，队尾比它小或相等的元素以后不可能再成为最大值，从尾部弹出；队头的下标一旦滑出窗口，就从头部弹出。这样队头始终是当前窗口的最大值。这里两端都要删除，所以必须用 deque。

vector<int> windowMax(const vector<int>& a, int k) {
    deque<int> d;              // 存下标，对应的值从队头到队尾递减
    vector<int> out;
    for (int i = 0; i < (int)a.size(); ++i) {
        // 队尾不大于 a[i] 的元素，以后不可能再是最大值
        while (!d.empty() && a[d.back()] <= a[i]) d.pop_back();
        d.push_back(i);
        if (d.front() <= i - k) d.pop_front();     // 队头滑出窗口
        if (i >= k - 1) out.push_back(a[d.front()]); // 窗口凑满后记录
    }
    return out;
}
// windowMax({1, 3, -1, -3, 5, 3, 6, 7}, 3) == {3, 3, 5, 5, 6, 7}

每个下标最多进队、出队各一次，总时间 O(n)。这种保持单调的 deque 叫作单调队列，完整的推导和逐步图见 9.10 单调队列。

优先队列：每次取出最大值

有些问题需要反复取出“当前最大的元素”，同时还会不断加入新元素，例如任务调度总是先处理优先级最高的任务。如果用有序数组保存，取最大值是 O(1)，但插入要移动元素，是 O(n)；如果用无序数组，插入是 O(1)，取最大值却要扫描一遍，也是 O(n)。堆让插入和取出最大值都只需 O(log n)，priority_queue 的内部就是一个堆。

堆是什么。 大根堆是一棵完全二叉树（除最后一层外每层都是满的，最后一层的结点靠左排列），并且每个结点都不小于它的孩子，所以根就是最大值。完全二叉树可以不用指针，直接按层序存进数组：下标 i 的结点，左孩子在 2i+1，右孩子在 2i+2，父结点在 (i−1)/2（整数除法）。下图是数组 [9, 6, 4, 1, 3] 对应的大根堆：

堆只要求父子之间有大小关系，兄弟之间没有顺序（6 在左、4 在右，也可以反过来），所以它不是有序数组，只保证堆顶最大。

插入（push）：放到末尾，再上滤。 新元素先放到数组末尾，这样树仍然是完全二叉树；然后与父结点比较，比父结点大就交换，一直向上，直到不比父结点大或者到达根为止。删除堆顶（pop）：末尾补到根，再下滤。 把数组最后一个元素移到根的位置并删去末尾，然后与两个孩子中较大的一个比较，比它小就交换，一直向下，直到不小于两个孩子为止。树高是 ⌊log₂n⌋，所以两种操作都是 O(log n)；读取堆顶 top() 只看 a[0]，是 O(1)。

struct MaxHeap {
    vector<int> a;                                  // a[0] 是堆顶
    void push(int x) {
        a.push_back(x);                             // 放到末尾
        int i = (int)a.size() - 1;
        while (i > 0 && a[(i - 1) / 2] < a[i]) {    // 比父结点大就交换（上滤）
            swap(a[(i - 1) / 2], a[i]);
            i = (i - 1) / 2;
        }
    }
    int top() const { return a[0]; }
    void pop() {
        a[0] = a.back();                            // 末尾元素补到根
        a.pop_back();
        int i = 0, n = (int)a.size();
        while (true) {                              // 与较大的孩子交换（下滤）
            int l = 2 * i + 1, r = l + 1, big = i;
            if (l < n && a[l] > a[big]) big = l;
            if (r < n && a[r] > a[big]) big = r;
            if (big == i) break;                    // 已经不小于两个孩子
            swap(a[i], a[big]);
            i = big;
        }
    }
    bool empty() const { return a.empty(); }
};
// 依次 push 9、6、4、1、3 后 a == {9, 6, 4, 1, 3}
// 再 push(8) 后 a == {9, 6, 8, 1, 3, 4}
// 再 pop() 后 a == {8, 6, 4, 1, 3}

用另一个容器的 begin()、end() 来构造新容器，是各种容器之间互相转换的通用写法（vector 转 set、map 转 vector<pair> 等），完整的对照表见 2.12 容器互转。

为什么写 greater 反而得到小根堆。 priority_queue 的第三个模板参数是比较器 cmp(a, b)，它返回 true 表示 a 的优先级比 b 低，a 应当排在 b 的下面。默认的 less<int> 在 a < b 时返回 true，即较小的数优先级低、沉在下面，所以堆顶是最大值；greater<int> 在 a > b 时返回 true，即较大的数沉下去，堆顶就变成了最小值。这与 sort 中“cmp(a, b) 为 true 表示 a 排在前面”的规则正好相反，所以容易写反，可以记住结论：默认是大根堆，加 greater 是小根堆。[7]

元素是 pair 或结构体时。 pair 按先比较 first、再比较 second 的字典序比较，所以 priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> 会先弹出 first 最小的元素。Dijkstra 算法把（距离，结点）放进这样的小根堆，每次取出距离最小的结点，见 16.14 Dijkstra。元素是自己定义的结构体时，用 lambda 写比较器，并把它的类型 decltype(cmp) 作为第三个模板参数：

struct Task { int id, deadline; };
int firstDeadline(const vector<Task>& tasks) {
    auto later = [](const Task& a, const Task& b) { return a.deadline > b.deadline; };
    priority_queue<Task, vector<Task>, decltype(later)> pq(later);   // 截止时间早的先出
    for (const Task& t : tasks) pq.push(t);
    return pq.top().id;
}
// firstDeadline({{1, 30}, {2, 10}, {3, 20}}) == 2

later(a, b) 在 a 的截止时间更晚时返回 true，表示 a 的优先级更低，所以截止时间最早的任务在堆顶。比较器的更多写法见 2.10 容器接口与比较器。

前 K 大问题：找出最大的 k 个数时，维护一个大小为 k 的小根堆，堆顶是目前入选的 k 个数中最小的一个，相当于入选的门槛。每放入一个新数后，如果堆中超过 k 个数，就弹出堆顶，即把门槛以下的数淘汰。扫描结束后，堆中剩下的就是最大的 k 个数。每次操作的堆大小不超过 k+1，时间 O(n log k)。

vector<int> topK(const vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> heap;   // 小根堆
    for (int x : nums) {
        heap.push(x);
        if ((int)heap.size() > k) heap.pop();               // 弹出最小的
    }
    vector<int> out;
    while (!heap.empty()) { out.push_back(heap.top()); heap.pop(); }
    reverse(out.begin(), out.end());                        // 从大到小
    return out;
}
// topK({3,1,4,1,5,9,2,6}, 3) == {9, 6, 5}

堆的更多做题用法，包括第 K 大元素、前 K 个高频元素、合并 K 个有序链表、数据流的中位数，见 10.16 堆；Python 中对应的 heapq 见 3.9 heapq。

1.10 pair、auto、排序与 lambda

pair 和结构化绑定

pair<A, B> 把两个值绑成一个，用 .first、.second 访问。排序时先比 first，相同再比 second。

vector<pair<int,int>> ps = {{2,1}, {1,5}, {2,0}};
sort(ps.begin(), ps.end());          // {1,5}, {2,0}, {2,1}
auto [a, b] = ps[0];                 // 结构化绑定：a=1, b=5

auto 让编译器自己推断类型，刷题时可以少写很长的类型名，例如 auto it = m.find(x);。

自定义排序：lambda 比较器

sort(begin, end, cmp) 的第三个参数是一个"比较函数"：cmp(a, b) 返回 true，表示 a 应该排在 b 前面。最方便的写法是 lambda（就地写的匿名函数）：

struct Student { string name; int score; };
void sortStudents(vector<Student>& v) {
    sort(v.begin(), v.end(), [](const Student& a, const Student& b) {
        if (a.score != b.score) return a.score > b.score;   // 分数高的在前
        return a.name < b.name;                             // 分数相同按名字
    });
}
// {Bob,90}, {Amy,95}, {Cat,90}  →  Amy(95), Bob(90), Cat(90)

lambda 的结构是 [捕获](参数) { 函数体 }。[] 里可以写 &，表示可以使用外部变量，例如按另一个数组的值排序下标：

vector<int> idx = {0, 1, 2};
vector<int> val = {30, 10, 20};
sort(idx.begin(), idx.end(), [&](int i, int j) { return val[i] < val[j]; });   // idx = {1, 2, 0}

易错点： 比较器必须是"严格小于"的含义。写成 return a.score >= b.score; 在两个元素相等时也返回 true，违反 sort 的要求，可能导致崩溃或错误结果。

1.11 struct、指针与链表 / 二叉树节点

链表和树的题目会给出节点类型。先把这段定义读懂：

struct ListNode {
    int val;                 // 节点里存的值
    ListNode* next;          // 指向下一个节点的指针
    ListNode(int x) : val(x), next(nullptr) {}   // 构造函数
};
  • struct 把几个变量打包成一种新类型；
  • ListNode* 是"指向 ListNode 的指针"，保存另一个节点的地址；
  • nullptr 是空指针，表示"不指向任何节点"，链表的结尾就是 next == nullptr；
  • ListNode(int x) : val(x), next(nullptr) {} 是构造函数，冒号后面是初始化列表，创建节点时把 val 设为 x、next 设为空。
ListNode* a = new ListNode(1);   // 在堆上新建一个节点，a 保存它的地址
a->val;                          // 1。指针访问成员用 ->，等价于 (*a).val
a->next = new ListNode(2);       // 接上第二个节点

每个节点 = 值 + 指向下一节点的指针；最后一个节点的 next 是 nullptr（∅）

用虚拟头节点建链表

ListNode* buildList(const vector<int>& v) {
    ListNode dummy(0);                // 虚拟头：不是真实数据，只为了统一"接在尾巴后面"
    ListNode* tail = &dummy;          // tail 永远指向当前最后一个节点
    for (int x : v) {
        tail->next = new ListNode(x);
        tail = tail->next;
    }
    return dummy.next;                // 真正的头是 dummy 的下一个
}

没有 dummy 时，第一个节点要单独处理（"头指针是空吗"）；有了 dummy，每个节点都是"接在 tail 后面"，代码只有一种情况。这个技巧在删除节点、合并链表时还会反复出现（见 8.8）。

二叉树节点和递归

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};
int treeDepth(TreeNode* root) {
    if (root == nullptr) return 0;                                  // 空树深度 0
    return 1 + max(treeDepth(root->left), treeDepth(root->right));  // 自己这一层 + 更深的子树
}

上图这棵树：treeDepth(4) = 1，treeDepth(2) = 1 + max(1, 0) = 2，treeDepth(3) = 1，treeDepth(1) = 1 + max(2, 1) = 3。树的递归套路（"空节点返回什么、当前节点如何用左右子树的结果"）会在刷题模式章系统展开。

易错点： 访问 p->next 或 root->left 之前，必须确认 p、root 不是 nullptr，否则运行时崩溃（空指针解引用）。

小结： 指针保存地址，用 -> 访问成员，nullptr 表示空；虚拟头节点使每个新节点都以同一种方式接在 tail 之后。

输出格式：小数位数、宽度、对齐与进制

题目常要求“保留两位小数”“每个数占 5 格右对齐”“输出十六进制”。cout 的格式由一组操纵符（manipulator）控制，把它们像数据一样用 << 写进输出流即可：setw、setprecision、setfill 在头文件 <iomanip> 中，fixed、left、hex 等在 <iostream> 中就能用。[8]

操纵符分为两类，这是最容易出错的地方：setw 只对紧跟其后的那一项输出有效，输出完就恢复为 0；其余的操纵符（fixed、setprecision、setfill、left、hex 等）设置之后一直有效，直到再次修改。

浮点数的默认输出。 不加任何设置时，cout 最多输出 6 位有效数字，末尾的 0 和多余的小数点会省略；数值太大或太小时自动改用科学计数法：

cout << 3.14159265;   // 3.14159      （6 位有效数字）
cout << 100.0;        // 100          （末尾的 .0 被省略）
cout << 1234567.0;    // 1.23457e+06  （整数部分超过 6 位，改用科学计数法）
cout << 0.00001;      // 1e-05

setprecision 的两种含义。 单独使用时，setprecision(n) 规定的是有效数字的位数；与 fixed 一起使用时，规定的是小数点后的位数，这才是题目中“保留 n 位小数”的意思。scientific 改用科学计数法，此时 n 是尾数小数点后的位数。

写法3.141592651234.5678含义
setprecision(3)3.141.23e+033 位有效数字
fixed << setprecision(2)3.141234.57小数点后 2 位，位数不足时补 0（2.0 输出 2.00）
scientific << setprecision(3)3.142e+001.235e+03科学计数法，尾数保留 3 位小数

fixed 一直有效，后面所有的浮点数都会按同样的位数输出；要回到默认格式，写 cout << defaultfloat << setprecision(6);。

舍入的结果可能和手算不同。 小数在计算机中以二进制存储，大多数十进制小数只能近似表示（见 13.5 浮点数的特殊值与精度）。例如 2.675 实际存成 2.67499999999999982…，所以 fixed << setprecision(2) << 2.675 输出 2.67 而不是 2.68；0.15 存成 0.1499999…，保留一位输出 0.1。对于恰好能精确表示的“正中间”值，GCC（glibc）舍入到偶数：0.125 保留两位输出 0.12，2.5 保留 0 位输出 2，3.5 输出 4。所以涉及金额时，应当用以“分”为单位的整数计算，最后再输出；需要把小数四舍五入成整数时，用 lround(x)（恰好在中间时远离 0 取整，lround(2.5) 为 3，lround(-2.5) 为 −3）；(int)x 则是直接截掉小数部分，(int)2.99 为 2，(int)-2.99 为 −2。

宽度、对齐与填充。 setw(n) 让下一项至少占 n 个字符，默认右对齐，不足的部分在左边补空格；内容比 n 长时不会截断，按原样完整输出。left、right 改变对齐方向，setfill(c) 改变补充用的字符，这三个都一直有效：

cout << "[" << setw(5) << 42 << "][" << 42 << "]";                 // [   42][42]  第二个 42 没有宽度
cout << "[" << left << setw(6) << "ab" << "]";                     // [ab    ]
cout << "[" << right << setw(6) << "ab" << "]";                    // [    ab]
cout << "[" << setw(5) << setfill('0') << 42 << "]";               // [00042]  补 0
cout << "[" << setw(2) << 12345 << "]";                            // [12345]  太长也不截断
cout << "[" << setw(8) << fixed << setprecision(2) << 3.14159 << "]";  // [    3.14]

用了 setfill('0') 之后，后面的 setw 也会继续补 0，用完要写 setfill(' ') 改回空格。

进制与布尔值。 hex、oct、dec 切换整数的进制，一直有效，用完要切回 dec；showbase 加上 0x 前缀，uppercase 让字母大写；boolalpha 把 bool 输出成 true、false，否则输出 1、0：

cout << hex << 255;                        // ff
cout << showbase << uppercase << 255;      // 0XFF
cout << noshowbase << nouppercase << dec;  // 恢复：不加前缀、小写、十进制
cout << oct << 8 << dec;                   // 10
cout << boolalpha << (1 < 2);              // true

多选 · 理解检查 11　下列场景与容器的搭配，哪些合适？

A. BFS 层序遍历用 queue

B. 判断括号是否匹配用 stack

C. 需要按键从小到大输出统计结果，用 unordered_map 直接遍历

D. 合并 k 个有序链表时，每次取当前最小的头节点，用小根堆

查看答案与每个选项的解析

A · 正确：先发现的节点先处理，正是先进先出。

B · 正确：最近打开的括号必须最先关闭，是后进先出。

C · 错误：unordered_map 遍历顺序不固定；应使用 map，或把结果取出后排序。

D · 正确：堆可以 O(log k) 取出 k 个候选中的最小值。
