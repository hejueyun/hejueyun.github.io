1.1 从源文件到可执行文件：预处理、编译、汇编、链接

为什么先学这个：笔试常问"#define 在哪个阶段处理""undefined reference 是哪一步报的错"，面试常问"静态链接和动态链接有什么区别"。这些问题都挂在同一条流水线上，把流水线画出来，答案就能顺着图读出。

gcc main.c util.c -o app 一条命令，背后有四个程序依次工作：

  1. 预处理（cpp）：处理所有以 # 开头的指令。把 #include 的头文件原样复制进来，把 #define 的宏做文本替换，按 #if/#ifdef 删掉不参与编译的代码，去掉注释。产物 .i 仍是 C 源码。
  2. 编译（cc1）：做词法分析、语法分析、类型检查和优化，把 C 翻译成汇编语言，产物是 .s。缺分号、类型不匹配、"未声明的标识符"都在这一步报。
  3. 汇编（as）：把汇编指令翻译成机器码，产物是可重定位目标文件 .o。如果代码调用了别的文件里的函数，这个函数的地址此时还空着，只留下一条"待填"记录。
  4. 链接（ld）：把多个 .o 和库合在一起，给每个函数、全局变量定下最终地址，再把所有"待填"位置补上。找不到某个函数的定义，就报 undefined reference to 'xxx'。[4] [5]

四个阶段与产物：.c → .i → .s → .o → 可执行文件；链接把多个目标文件和库合成一个程序

逐步执行过程

我们用 gcc 的选项让流水线在每一步停下来，亲眼看到每个产物：

$ gcc -E main.c -o main.i     # 只做预处理：打开 main.i，能看到 stdio.h 被整段展开
$ gcc -S main.i -o main.s     # 编译到汇编：main.s 里是 mov、call 等指令
$ gcc -c main.s -o main.o     # 汇编成目标文件：二进制，用 objdump -d 可反汇编
$ gcc -c util.c -o util.o
$ gcc main.o util.o -o app    # 链接：合并两个 .o，再连上 C 标准库

如果 main.c 调用了 add()，而 add 定义在 util.c 里，最后一步漏写 util.o，前三步都能通过，第四步报 undefined reference to 'add'。原因是编译 main.c 时只需要 add 的声明（知道参数和返回类型），找定义是链接器的工作。

头文件与 include guard

头文件（.h）放声明：函数原型、结构体定义、宏、extern 变量声明；.c 文件放定义。#include "x.h" 先在当前目录找，再找系统目录；#include <x.h> 直接去系统目录找。[6]

一个头文件可能被间接包含两次。下图里 main.c 包含了 a.h 和 b.h，它们又都包含 point.h，于是 struct Point 在 main.i 里出现两遍，编译器报"重复定义"。

菱形包含：没有 include guard 时 point.h 的内容被展开两次

解决办法是给每个头文件加 include guard：第一次展开时定义一个宏，第二次再遇到时宏已存在，整段内容被预处理器跳过。

// point.h
#ifndef POINT_H
#define POINT_H
struct Point { int x, y; };
#endif

#pragma once 效果相同，写法更短，主流编译器都支持，但它是编译器扩展而非标准。

make：只重新编译改动过的文件

项目有几十个 .c 时，每次全量编译很慢。make 读取当前目录的 Makefile，按"目标: 依赖"规则判断：某个依赖文件比目标新，才重新执行这条规则的命令。[8]

CFLAGS = -Wall -g

app: main.o util.o
	$(CC) $(CFLAGS) -o app main.o util.o

main.o: main.c util.h
	$(CC) $(CFLAGS) -c main.c

util.o: util.c util.h
	$(CC) $(CFLAGS) -c util.c

.PHONY: clean
clean:
	rm -f app *.o

只改了 util.c 时执行 make：util.o 比 util.c 旧，重新编译；main.o 比它的依赖都新，跳过；app 比新的 util.o 旧，重新链接。make clean 执行清理命令；.PHONY 声明 clean 是"伪目标"，即使目录里恰好有个叫 clean 的文件也照样执行。

valgrind：运行时查内存错误

valgrind 的 memcheck 工具在程序运行时检查每一次内存访问，能发现越界读写、读未初始化的值、内存泄漏、重复释放。编译时加 -g，报告里就有源码行号。[9]

#include <stdlib.h>
int main(void) {
    int *p = malloc(10 * sizeof *p);   // 40 字节，合法下标 0..9
    p[10] = 1;                         // 越界写
    return 0;                          // 没有 free：泄漏
}
$ gcc -g vg.c -o vg && valgrind --leak-check=full ./vg
==8840== Invalid write of size 4
==8840==    at 0x10916B: main (vg.c:4)
==8840==  Address 0x4a7e068 is 0 bytes after a block of size 40 alloc'd
==8840== 40 bytes in 1 blocks are definitely lost in loss record 1 of 1
==8840== ERROR SUMMARY: 2 errors from 2 contexts

两条报告分别对应两个缺陷：第 4 行写了 4 字节到 40 字节块的紧后面；程序结束时 40 字节没有释放（definitely lost）。博客里的例子 printf("I am %d years old.\n"); 少传了参数，valgrind 报"Conditional jump or move depends on uninitialised value(s)"——格式串要求的参数没传，printf 读到的是未初始化的值，属于未定义行为。[7] [10]

要点

  • 四个阶段依次是预处理、编译、汇编、链接，产物依次是 .i、.s、.o、可执行文件。
  • 宏替换、头文件展开、条件编译都在预处理阶段完成，此时只做文本处理，没有类型检查。
  • "undeclared identifier"是编译错误；"undefined reference"和"multiple definition"是链接错误。
  • 静态链接把库代码复制进可执行文件（.a/.lib），文件大，运行时无需依赖；动态链接（.so/.dll）在加载或运行时才连上库，多个程序共享一份，库可单独升级。

A. 链接阶段报 undefined reference to 'add'

B. 预处理阶段报错，因为找不到 util.c

C. 编译阶段报 add 未声明

查看答案与每个选项的解析

A · 正确：编译 main.c 只需要声明，能生成 main.o；链接时找不到 add 的定义。

C · 错误：util.h 提供了声明，编译能通过。

易错点：

  • Makefile 里命令行必须以 TAB 开头，用空格会报 missing separator。
  • 在头文件里写变量定义（如 int count = 0;），被两个 .c 包含后会在链接时报 multiple definition；头文件里应写 extern int count;，定义放在一个 .c 里。

小结： 源文件依次经过预处理（得到 .i）、编译（得到 .s）、汇编（得到 .o）、链接，最后生成可执行文件；宏在预处理阶段展开，undefined reference 是链接阶段的错误；make 根据时间戳只重新编译修改过的文件。

1.2 类型、sizeof 与隐式转换：先换算再比较

为什么需要：读代码题里最常见的"反直觉输出"，几乎都来自类型转换。-1 > sizeof(int) 为真、unsigned 加负数变成大正数、两个 unsigned char 相加不会回绕，这些结果只要按规则把类型换算一遍就能推出来。

sizeof 在编译期给出类型或对象占的字节数，结果类型是无符号的 size_t。标准只规定了下限和大小关系（char 为 1，short ≤ int ≤ long ≤ long long），具体数值由平台决定。下表是本章默认平台的值：[11] [12]

sizeof 的操作数通常不求值：int a = 14; int b = sizeof(a++); 之后 a 仍是 14，b 是 4。（可变长数组 VLA 是唯一例外。）[13]

整型提升

比 int 小的整数类型（char、short、bool 及其无符号版本）参加算术运算前，先转换成 int。这叫整型提升。所以两个 unsigned char 相加不会在 255 处回绕：

unsigned char a = 200, b = 100;
int s = a + b;                 // 300：先提升为 int 再相加
unsigned char c = a + b;       // 44：300 存回 1 字节时取模 256

普通算术转换：两边类型不同时向"更高"的一边看齐

二元运算符两边类型不同时，编译器先把它们转成同一类型。规则可以画成一条阶梯：整型提升之后，类型低的一边转换成类型高的一边。[14] [15]

从上往下等级升高：混合运算时等级低的一边转成等级高的一边。int 遇到 unsigned int，int 转成 unsigned

最关键的一条：同样宽度的有符号数和无符号数相遇，有符号数转成无符号数。负数转无符号的规则是"加上 2^位数"，位模式完全不变，只是换了解释方式。

逐步执行：-1 > sizeof(int) 为什么为真

if (-1 > sizeof(int)) puts("yes"); else puts("no");   // 输出 yes

同样的道理：

unsigned int a = 6;
int b = -20;
puts(a + b > 6 ? ">6" : "<=6");   // 输出 >6

b 转成 unsigned int，值为 2^32 − 20；再加 6 得 4294967282，远大于 6。

还有一个依赖平台的例子：long l = -1; unsigned int u = 1; 比较 l < u。在 LP64 上 long 是 8 字节，能装下所有 unsigned int 的值，所以 u 转成 long，-1 < 1 为真；在 long 只有 4 字节的平台上，两者都转成 unsigned long，结果为假。规则是：有符号类型能表示无符号类型的全部值时，转成有符号类型；否则都转成无符号。

显式转换与截断

把大类型存进小类型叫截断：整数保留低位字节（unsigned char c = 300 得 44），浮点转整数直接丢小数（(int)3.9 得 3，(int)-3.9 得 -3）。char 本身是有符号还是无符号由平台决定，x86 上的 GCC 是有符号，所以 char c = 0xFF; 打印 (int)c 得 -1。

C 与 C++ 有一处常考差异：字符常量 'a' 在 C 中类型是 int（sizeof('a') 为 4），在 C++ 中是 char（为 1）。

要点

  • 看到 sizeof、strlen、vector::size() 与负数比较，先想到"负数会被转成很大的无符号数"。
  • 比 int 小的类型运算前先提升为 int；int 与 unsigned 混合运算，结果按 unsigned 计算。
  • 标准答案句：有符号数与无符号数比较时，有符号数会被隐式转换为无符号数，负数变为一个很大的正数。

查看答案与每个选项的解析

A · 正确：b 转成 unsigned int 后为 2^32−20，a+b = 4294967282 > 6。

B · 错误：这是按数学值 -14 计算的结果，忽略了 b 被转成无符号数。

易错点：

  • for (int i = 0; i <= v.size() - 1; ++i) 在 v 为空时，v.size() - 1 是 size_t 的最大值，循环越界；写成 i < (int)v.size()。

小结： 比 int 小的类型参与运算时先提升为 int；有符号数与无符号数一起运算时，转换为无符号数；负数转换为无符号数等于加上 2 的位数次方，位模式不变。

自增：i++ 与 ++i

i++ 的值是 i 的旧值，副作用是 i 加 1；++i 先加 1，值是新值。

int a = 5;
int b = a++ * 2;   // b = 10，a = 6
int c = ++a * 2;   // a = 7，c = 14

*p++ 最常考。后缀 ++ 优先级高于 *，所以它是 *(p++)：表达式的值是 *p（旧位置），然后 p 后移。(*p)++ 则是把 p 指向的元素加 1，p 不动。

int arr[3] = {10, 20, 30}; int *p = arr;

同一个变量在一个表达式里被修改两次，例如 i++ + i++、i = ++i + i++，C 和 C++ 都没有规定结果，属于未定义行为。读代码题遇到这种写法，应选"结果不确定/未定义"，不去硬算。（C++17 让 i = i++ + 1 这类"右边先算完再赋值"的写法有了确定结果，但 C11 中仍是未定义。）[18]

短路求值

&& 左边为假、|| 左边为真时，右边不再计算，右边的副作用也不会发生。

int x = 1, y = 1;
int r = (x-- > 1) && (y++ > 0);
// r = 0, x = 0, y = 1

推导：x-- > 1 用旧值 1 比较，1 > 1 为假，然后 x 变成 0；&& 左边为假，右边 y++ 被跳过，y 仍是 1。

赋值表达式与逗号表达式

赋值表达式本身有值，值就是赋完后左边的新值。所以 if (x = 0) 永远为假，if (x = 5) 永远为真，并且 x 被改掉了。这是 CERT C 的 EXP45 规则所防范的错误；确实想在条件里赋值时，写成 if ((x = f()) != 0)。[19]

逗号运算符从左到右计算每一项，整个表达式的值是最后一项。m = (t = 1, t + 2) 先让 t 为 1，再算 t + 2，m 为 3。逗号的优先级最低，所以 a = 1, 2, 3; 等价于 (a = 1), 2, 3;，a 是 1。

位运算基础

运算规则例（5 = 101，3 = 011）
& 与两位都为 1 才得 15 & 3 = 001 = 1
| 或有一位为 1 就得 15 | 3 = 111 = 7
^ 异或两位不同得 15 ^ 3 = 110 = 6
~ 取反每一位翻转~0 = -1（int）
<< / >>左移 / 右移1 << 3 = 8；-8 >> 1 在 GCC 上为 -4（算术右移）

三个刷题常用技巧：x & 1 判断奇偶；n & (n - 1) 去掉最低位的 1（循环到 0 的次数就是二进制中 1 的个数，13 = 1101 得 3）；n & -n 取出最低位的 1（12 = 1100 得 4）。x ^ x = 0、x ^ 0 = x，所以对一组数全部异或，成对出现的会抵消。

int countBits(unsigned int n) {
    int cnt = 0;
    while (n != 0) {
        n &= n - 1;     // 每次清掉最低位的 1
        ++cnt;
    }
    return cnt;
}

要点

  • ==、!= 的优先级高于 &、^、|，位运算参与比较时必须加括号。
  • *p++ 等价于 *(p++)：取当前值，指针后移。
  • &&、|| 短路：右边可能不执行，其中的 ++ 也不会发生。
  • 同一变量在一个表达式中无序地修改两次是未定义行为。

1.4 宏：文本替换的陷阱与 inline 函数

为什么需要：宏在预处理阶段做纯文本替换，不懂运算优先级，也不管参数被计算几次。"写出 SQ(1+2) 的值"是 C 笔试的保留题目。

#define SQ(x) x*x 告诉预处理器：遇到 SQ(某段文本)，就把 x 换成这段文本，原样拼进去。替换完才轮到编译器按优先级解析。[20]

逐步执行过程

#define SQ_BAD(x)  x * x
#define SQ_GOOD(x) ((x) * (x))

SQ_BAD(1 + 2)        // 展开为 1 + 2 * 1 + 2，值为 5
10 / SQ_BAD(2)       // 展开为 10 / 2 * 2，值为 10
SQ_GOOD(1 + 2)       // 展开为 ((1 + 2) * (1 + 2))，值为 9
10 / SQ_GOOD(2)      // 展开为 10 / ((2) * (2))，值为 2

宏先原样替换文本，编译器再按优先级解析；括号决定了结合方式

规则：宏的每个参数加括号，整个宏体再加一层括号。参数括号防止 1+2 被拆开，外层括号防止宏外的 10 / 抢先结合。

即使括号加全，宏还有一个函数没有的问题：参数可能被计算多次。SQ_GOOD(i++) 展开为 ((i++) * (i++))，同一表达式修改 i 两次，是未定义行为；MAX(a, b) 写成 ((a) > (b) ? (a) : (b)) 时，MAX(x++, y) 可能让 x 加两次。内联函数没有这个问题：

inline int square(int x) { return x * x; }   // square(1 + 2) == 9，参数只算一次

宏inline 函数

inline 的含义—对编译器的建议；是否真的展开由编译器决定

宏仍用于 include guard、条件编译（#ifdef DEBUG）和 __LINE__ 这类文本位置信息。多条语句的宏惯用 do { ... } while (0) 包起来。[21]

要点

  • 宏在预处理阶段展开，只做文本替换，不检查类型，不计算。
  • 带参宏要给每个参数和整体都加括号；带副作用的实参（i++）传给宏有风险。
  • 标准答案句：inline 函数在编译期展开，有类型检查，参数只求值一次；宏在预处理期做文本替换，没有类型检查。

1.5 控制流：switch 穿透与循环的执行次数

为什么需要：switch 少写 break、while 和 do-while 的执行次数，是读代码题的两类固定题型。只要知道 case 标签只是"入口"，答案就能一步步数出来。

switch：case 只决定从哪里进，break 才决定从哪里出

switch (表达式) 计算表达式，跳到值相等的那个 case 标签；没有相等的就跳到 default。跳进去之后，一路往下执行，直到遇到 break 或 switch 结束，经过的其他 case 标签不会拦住它。这种行为叫穿透（fallthrough）。[22]

int switchDemo(int k) {
    int s = 0;
    switch (k) {
        case 1: s += 1;           // 没有 break
        case 2: s += 2;           // 没有 break
        case 3: s += 3; break;
        default: s += 100;
    }
    return s;
}
// switchDemo(1) == 6, switchDemo(2) == 5, switchDemo(3) == 3, switchDemo(9) == 100

虚线是 switch 的跳转入口；实线是顺序执行。k=1 时依次执行 +1、+2、+3，遇到 break 离开，s=6

default 写在中间时也一样：它只是"没有匹配时的入口"，执行起来照样按书写顺序往下走。

switch (k) {               // k = 5，没有 case 5
    case 1: s += 1;
    default: s += 10;      // 从这里进入
    case 2: s += 2;        // 穿透到这里
}                          // s = 12；若 k = 1，s = 1 + 10 + 2 = 13

switch 的表达式必须是整数类（int、char、枚举等），case 后必须是编译期常量，因此字符串、浮点数不能直接用于 switch。在某个 case 里定义带初始化的变量时要加花括号，否则跳过初始化会编译报错。确实需要穿透时，C++17 可以写 [[fallthrough]]; 表明是故意的。

while 与 do-while

while 先判断后执行，可能一次都不执行；do-while 先执行后判断，至少执行一次。

左：先判断，条件一开始为假时循环体 0 次；右：先执行，循环体至少 1 次

数循环次数的题，按"判断时用的是哪个值"逐步记录：

int i = 3, n = 0;
while (i--) ++n;     // n = 3，循环结束时 i = -1
第几次判断判断用的 i（旧值）判断后 i是否进入循环n
132是1
221是2
310是3
40-1否3

第 4 次判断时条件为假，但 i-- 的副作用照样发生，所以 i 最后是 -1。for (初始化; 条件; 更新) 的执行顺序是：先执行一次初始化，然后判断条件、执行循环体、执行更新，再判断条件，如此反复；continue 会跳到更新这一步。

要点

  • case 标签是入口，break 是出口；没有 break 就继续执行下一个 case 的语句。
  • default 的位置只影响穿透路线，不影响匹配。
  • do-while 至少执行一次；while (i--) 结束时 i 比 0 再小 1。

1.6 数组与指针：类型决定步长

为什么需要：a、&a、*a、a+1、&a+1 的值和步长，是 C 读代码题中最常见的一类。本节的方法是：先写出每个表达式的类型，类型决定 +1 跳多少字节。

指针是什么

指针变量存放的是一个地址，它的类型说明"这个地址上放的是什么"。int *p 表示 p 存一个地址，地址上是一个 int。*p 是取出该地址上的 int，&x 是取 x 的地址。[23]

指针算术：p + 1 前进的字节数是 sizeof(*p)。int* 加 1 前进 4 字节，double* 加 1 前进 8 字节。两个指向同一数组的指针相减，得到的是相差的元素个数，而非字节数。

数组名在表达式中变成首元素指针

数组 int a[5] 是 5 个 int 连续排列的一块内存。在大多数表达式里，数组名 a 会自动转换成"指向首元素的指针"，类型 int*。这个转换叫数组退化。有两个例外：sizeof(a) 得到整个数组的大小，&a 得到指向整个数组的指针。[24]

表达式类型含义+1 的步长sizeof
a退化为 int*首元素地址4 字节20（例外：整个数组）
&a[0]int*首元素地址4 字节8
&aint (*)[5]整个数组的地址20 字节8
*aint首元素的值—4

a、&a[0]、&a 打印出来的地址数值相同，区别在于类型，于是 +1 的步长不同。

逐步执行：经典题

int a[5] = {1, 2, 3, 4, 5};
int *ptr = (int *)(&a + 1);
printf("%d %d\n", *(a + 1), *(ptr - 1));   // 输出 2 5

a+1 跨 1 个 int；&a+1 跨整个数组，落在末尾之后（即 ptr）；转成 int* 后退 1 个 int 就到 a[4]

  1. a + 1：a 退化为 int*，加 1 前进 4 字节，指向 a[1]，*(a+1) 为 2。
  2. &a + 1：&a 的类型是 int (*)[5]，加 1 前进 20 字节，指向数组末尾之后的位置。
  3. 强转成 int* 赋给 ptr，ptr - 1 后退 4 字节，指向 a[4]，值为 5。

二维数组与 int**

int b[2][3] 是"2 个元素，每个元素是长度 3 的 int 数组"，6 个 int 在内存里一行接一行连续存放。b 退化为 int (*)[3]（指向一行），b + 1 跨过一整行 12 字节；b[1] 是第 1 行，再退化为 int*；所以 b[i][j] 等价于 *(*(b + i) + j)。

二维数组按行连续存放：b+1 跨一行（12 字节），*(b+1)+2 再跨 2 个 int，指向 b[1][2]=6

int** 是"指向指针的指针"，常见用法是先开一个指针数组，每个指针再各自指向一块独立分配的行。两者内存结构不同：

int** 形式：中间多一层指针数组，各行可以分散在堆的不同位置；int b[2][3] 没有这一层

因此 b 传给形参 int **m 会编译失败。二维数组作参数要写出列数：void f(int m[][3], int rows) 或等价的 void f(int (*m)[3], int rows)。

数组作函数参数会退化成指针

size_t paramSize(int arr[10]) { return sizeof(arr); }   // 返回 8，arr 实际是 int*

形参写成 int arr[10]、int arr[] 或 int *arr，含义完全相同，都是指针，数组长度 10 被忽略。函数内部拿不到数组长度，所以 C 函数惯例是同时传长度：int sumArray(const int *a, int n)。GCC 对上面这行会给出 -Wsizeof-array-argument 警告。

记法：const 在 * 左边，锁住的是被指的值（指向常量的指针）；const 在 * 右边，锁住的是指针本身（常量指针）。[25]

灰色表示被 const 锁住的一层：上行锁值，下行锁指针

函数指针

函数也有地址。int (*fp)(int, int) = add; 声明 fp 是一个指针，指向"接收两个 int、返回 int"的函数；fp(2, 3) 和 (*fp)(2, 3) 都能调用。括号不能省：int *fp(int, int) 声明的是一个返回 int* 的函数。函数指针的典型用途是回调（qsort 的比较函数）和"操作表"：

int calc(char op, int a, int b) {
    int (*table[3])(int, int) = {add, sub, mul};    // 函数指针数组
    const char ops[] = "+-*";
    for (int i = 0; i < 3; ++i)
        if (ops[i] == op) return table[i](a, b);
    return 0;
}
// calc('*', 6, 3) == 18

要点

  • 指针 +1 前进 sizeof(所指类型) 字节；同一数组内两指针相减得元素个数。
  • 数组名在表达式中退化为首元素指针；sizeof(数组名) 和 &数组名 是两个例外。
  • &a + 1 跳过整个数组；二维数组名的类型是"指向行的指针"，与 int** 不通用。
  • 数组作函数参数退化为指针，函数内 sizeof 得到指针大小。

int myStrcmp(const char *a, const char *b) {
    while (*a != '\0' && *a == *b) { ++a; ++b; }
    return (unsigned char)*a - (unsigned char)*b;
}
// "abc" vs "abd"：第 3 个字符 'c' < 'd'，返回负数
// "ab"  vs "abc"：比到 '\0' 与 'c'，返回负数

strcpy 的核心只有一行，也正好说明了它的危险：循环只看源串何时结束，完全不知道目标有多大。

char *myStrcpy(char *dst, const char *src) {
    char *d = dst;
    while ((*d++ = *src++) != '\0') {}   // 连 '\0' 一起复制
    return dst;
}

memset(arr, 1, sizeof arr) 把 int 数组的每个字节都设成 0x01，每个 int 变成 0x01010101 = 16843009，而不是 1。

安全替代

危险写法替代要点
gets(buf)fgets(buf, sizeof buf, stdin)gets 已从 C11 删除；fgets 最多读 size-1 个字符并补 '\0'，会保留换行符
strcpy(dst, src)snprintf(dst, sizeof dst, "%s", src)总会写入结尾 0；返回值 ≥ size 说明被截断
strncpy(dst, src, n)用后手动 dst[n-1] = '\0'src 长度 ≥ n 时 strncpy 不会补 '\0'
sprintf(buf, …)snprintf(buf, sizeof buf, …)同上
strcatsnprintf 或先算剩余空间
bool safeCopy(char *dst, size_t size, const char *src) {
    int n = snprintf(dst, size, "%s", src);
    return n >= 0 && (size_t)n < size;      // false 表示内容被截断
}
// char small[4]; safeCopy(small, 4, "hello") 返回 false，small 为 "hel"

CERT C 的 STR31-C 规则要求：为字符串分配的空间必须同时容纳字符数据和结尾的 '\0'。[27]

要点

  • 字符串长度 = strlen，不含 '\0'；数组大小 = sizeof，含 '\0'，指针的 sizeof 是指针大小。
  • 字符串字面量存在只读区，通过指针修改是未定义行为；char[] 是副本，可以修改。
  • strcmp 返回 0 表示相等，if (strcmp(a, b)) 为真表示不相等。

1.8 结构体与联合体：对齐、填充与大小端

为什么需要：sizeof(struct) 手算是 C 笔试必考题，面试也常问"为什么要内存对齐""怎么判断大小端"。三条对齐规则加一张字节布局图，任何结构体都能算。

为什么要对齐

CPU 按"字"读内存，一个 4 字节 int 放在 4 的倍数地址上，一次就能读完；跨了边界就要读两次再拼起来，有的 CPU 干脆不支持。所以编译器会在成员之间插入填充字节（padding），让每个成员都落在自己的对齐边界上。用空间换速度。[28]

三条规则

  1. 每个成员的起始偏移量必须是该成员对齐值的整数倍（基本类型的对齐值通常等于它的大小：char 1、short 2、int 4、double 8、指针 8；数组按元素类型对齐）。
  2. 结构体的总大小必须是最大成员对齐值的整数倍，不够就在末尾补。
  3. 嵌套结构体成员按它内部最大的对齐值对齐。

例 1：struct A { char a; int b; short c; }

sizeof(struct A) 手算

1 / 4

第1步 · a 是 char，对齐 1，放在偏移 0

2 / 4

第2步 · b 是 int，对齐 4：偏移 1 不是 4 的倍数，填充 1~3，b 放在 4~7

3 / 4

第3步 · c 是 short，对齐 2：偏移 8 是 2 的倍数，放在 8~9

4 / 4

第4步 · 已用 10 字节；最大对齐是 4，总大小要是 4 的倍数，末尾补 2 字节

有效数据 7 字节，填充 5 字节

例 2：调整顺序，struct B { char a; short c; int b; }

a 在 0；c 对齐 2，偏移 1 补 1 字节，c 在 2~3；b 对齐 4，偏移 4 正好，b 在 4~7。共 8 字节，已是 4 的倍数。同样三个成员，按从小到大排列就从 12 字节降到 8 字节。

成员按对齐值从小到大（或从大到小）排列，填充最少

例 3：含 double 和数组

struct C { char a; double d; int i; }：a 在 0，d 对齐 8 放在 8~15（填充 7），i 在 16~19，已用 20，最大对齐 8，补到 24。

struct S3 { char a; char b[5]; int c; char d; }：a 在 0，b 是 char 数组、对齐 1，放在 1~5；c 对齐 4，偏移 6 补到 8，c 在 8~11；d 在 12；已用 13，最大对齐 4，补到 16。

char 数组按 char 对齐，不需要整体对齐到 5；sizeof(S3) = 16

#pragma pack

#pragma pack(n) 把对齐上限改成 n：每个成员的对齐值取 min(自身对齐, n)，总大小也按 min(最大对齐, n) 补齐。

写法A 的布局sizeof(A)
默认a + 3 填充 + b + c + 2 填充12
#pragma pack(2)a + 1 填充 + b（偏移 2）+ c（偏移 6）8
#pragma pack(1)a + b + c 紧挨着7

pack(1) 常用于网络协议头、文件格式；代价是成员未对齐，访问变慢。

union：所有成员共用一块内存

联合体的所有成员都从偏移 0 开始，共享同一块存储，大小是最大成员的大小再按最大对齐补齐。同一时刻只有最后写入的那个成员有意义。[29]

union U5 { char c[5]; int i; }：最大成员 5 字节，最大对齐 4，补到 8。

大小端

一个多字节整数在内存里，低地址放哪一字节？小端（little-endian）低地址放低位字节，x86、ARM 默认如此；大端（big-endian）低地址放高位字节，网络字节序就是大端。

0x12345678 在两种字节序下的存放方式：看最低地址（0x100）上是低位 78 还是高位 12

判断方法：存一个整数 1，看最低地址那个字节是不是 1。

bool isLittleEndian() {
    uint32_t x = 1;
    unsigned char first;
    memcpy(&first, &x, 1);         // 取最低地址的字节
    return first == 1;
}

C 里也常用 union 判断：union { int i; char c; } u; u.i = 1; return u.c == 1;。这在 C 中是允许的写法；在 C++ 中读非最后写入的成员属于未定义行为，所以 C++ 代码用 memcpy 或 reinterpret_cast<unsigned char*>。网络编程中用 htonl/ntohl 在主机字节序和网络字节序之间转换。

要点

  • 标准答案句：结构体大小 = 各成员按自身对齐值放置（中间补齐）后，总长再补到最大对齐值的整数倍。
  • 成员按大小排序可以减少填充；#pragma pack(n) 把对齐上限压到 n。
  • union 大小 ≥ 最大成员，并按最大对齐补齐；成员共享起始地址。
  • 小端：低地址存低位字节（x86）；大端：低地址存高位字节（网络序）。

单选 · 理解检查 8　x86-64 下 struct C { char a; double d; int i; }; sizeof(struct C) 是多少？

A. 24

B. 13

C. 16

D. 20

查看答案与每个选项的解析

A · 正确：a 在 0，d 对齐 8 放 8~15，i 放 16~19，共 20，补到 8 的倍数 24。

B · 错误：这是不考虑对齐的直接相加 1+8+4。

C · 错误：double 需要从 8 的倍数开始，a 后面要补 7 字节。

D · 错误：总大小还要补到最大对齐 8 的倍数。

易错点：

  • 用 memcmp 比较两个结构体会连填充字节一起比，而填充内容不确定；应逐个成员比较（CERT C EXP42-C）。[30]
  • 空结构体在 C++ 中 sizeof 为 1（每个对象要有唯一地址）；在 C 中空结构体是 GCC 扩展，大小为 0。

小结： 结构体的每个成员对齐到自身大小的倍数，结构体总长度补齐到最大对齐值的倍数；#pragma pack(n) 限制对齐的上限；union 的成员共用同一块内存；小端模式在低地址存放低位字节。

1.9 存储期、作用域、链接与进程内存布局

为什么需要：面试题"static 有哪几种用法""全局变量和局部变量放在哪里""未初始化的全局变量在哪个段"，都要求把变量的声明位置和进程内存中的区域对应起来。

三个概念

  • 作用域：名字在源代码的哪一段可以使用。块作用域（花括号内）、文件作用域（函数之外）。
  • 存储期：对象在运行时存在多久。自动存储期（进入块时创建、离开时销毁，局部变量）、静态存储期（程序开始到结束，全局变量和 static 变量）、动态存储期（malloc/new 到 free/delete）。
  • 链接：不同源文件里的同名声明是否指向同一个实体。外部链接（全局变量、函数，其他文件可用 extern 引用）、内部链接（加 static 的全局变量和函数，只在本文件可见）、无链接（局部变量）。[31]

static 的三种用法

位置作用影响的是
函数内 static int x = 0;只初始化一次，函数返回后值保留存储期（变成静态），作用域仍在函数内
函数外 static int g; 或 static void f()只在本 .c 文件可见链接（变成内部链接）
C++ 类内 static int count;所有对象共享一份（1.11）属于类而非对象
int nextId() {
    static int id = 0;     // 只在第一次调用时初始化
    return ++id;
}
// nextId() 连续调用返回 1、2、3

extern int count; 是声明：告诉编译器"count 定义在别处"，不分配存储。跨文件共享全局变量的做法是：一个 .c 里定义 int count = 0;，头文件里写 extern int count;，其他文件包含头文件后使用。

进程内存布局

一个运行中的 C 程序，虚拟地址空间从低到高大致分为以下几个区域：[32]

栈从高地址向低地址增长，堆从低向高增长；text 与 rodata 只读

逐步执行：每个变量放在哪里

int g1 = 5;                  // data：已初始化的全局变量
int g2;                      // bss：未初始化的全局变量（自动为 0）
static int s1 = 0;           // bss：初始化为 0 也放在 bss
const int K = 10;            // rodata（C++ 中常被直接折叠成常量）
const char *msg = "hi";      // msg 本身在 data；"hi" 在 rodata

int main() {
    int local = 1;           // 栈
    static int cnt = 3;      // data：静态局部变量，和全局变量放在一起
    int *p = (int *)malloc(4);   // p 在栈；p 指向的 4 字节在堆
    char arr[] = "abc";      // arr 的 4 字节在栈（从 rodata 复制过来）
    free(p);
}
变量区域生命周期
g1、cntdata整个程序
g2、s1bss整个程序，启动时清零
"hi"、Krodata整个程序，只读
local、p、arr栈所在函数返回时结束
*p（malloc 的 4 字节）堆直到 free
main 的代码text整个程序

bss 段在可执行文件里只记录大小，加载时由系统清零。

栈和堆的对比是面试常题：

栈堆
谁来分配释放编译器自动（进出函数）程序员（malloc/free、new/delete）
大小小，Linux 默认 8 MB大，受虚拟内存限制
速度快：移动栈指针即可较慢：要在空闲块中查找
碎片无有
典型问题递归过深、超大局部数组导致栈溢出内存泄漏、重复释放、悬空指针

要点

  • 标准答案句：static 修饰局部变量改变其存储期（只初始化一次，值在调用间保留）；修饰全局变量或函数改变其链接属性（只在本文件可见）。
  • 已初始化（非 0）的全局/静态变量在 data 段，未初始化或初始化为 0 的在 bss 段，字符串字面量在 rodata 段。
  • 局部变量在栈，malloc/new 得到的内存在堆，指向堆的指针变量本身可能在栈。
  • 返回局部变量的地址会得到悬空指针：函数返回后那块栈空间会被下一次调用复用。

多选 · 理解检查 9　关于下面变量的存放位置，哪些正确？int a = 1; int b; void f(){ static int c = 2; int d; char *e = "xy"; }

A. a 在 data 段，b 在 bss 段

B. c 在栈上，每次调用 f 都重新初始化为 2

C. d 和 e 本身在栈上

D. "xy" 这三个字节在 rodata 段

查看答案与每个选项的解析

A · 正确：已初始化非 0 的全局变量在 data，未初始化的在 bss。

B · 错误：静态局部变量在 data 段，只初始化一次。

C · 正确：它们是普通局部变量。

D · 正确：字符串字面量放在只读数据区，e 只保存它的地址。

易错点：

  • 静态局部变量的作用域仍只在函数内，外部访问不到；变的只是生命周期。
  • int mat[100000][100000]; 写在函数内会让栈溢出；写成全局变量则放在 bss 段，可执行文件和栈都不受影响，但仍需要约 40 GB 虚拟内存。

小结： 作用域决定名字在哪里可见，存储期决定对象存在多久，链接属性决定能否跨文件访问；内存布局从低地址到高地址依次是代码段、只读数据段、数据段、BSS 段、堆和栈；static 局部变量改变的是存储期，static 全局变量改变的是可见范围。

1.10 动态内存：分配、释放与常见错误

为什么需要：堆内存由程序员手动管理，最容易出错。笔试会给一段代码问"哪一行有问题"，面试会问"内存泄漏、野指针、悬空指针有什么区别"。

四个 C 函数与 C++ 的 new/delete

函数作用初始值失败时
malloc(n)分配 n 字节不确定返回 NULL
calloc(cnt, size)分配 cnt×size 字节全部清零返回 NULL
realloc(p, n)把 p 的块调整为 n 字节，可能搬到新地址并复制旧内容新增部分不确定返回 NULL，旧块仍在
free(p)释放 p 指向的块；free(NULL) 什么也不做——

C++ 的 new T 先分配内存再调用构造函数，delete p 先调用析构函数再释放；new T[n] 构造 n 个对象，必须用 delete[] p 释放，让每个元素的析构函数都被调用。malloc 配 free，new 配 delete，new[] 配 delete[]，三组不能交叉。new 分配失败默认抛 std::bad_alloc 异常，而不是返回空指针。[33] [34]

分配时写 malloc(n * sizeof *p) 而不是 malloc(n * sizeof(int))：以后 p 的类型改成 long* 时，sizeof *p 会自动跟着变，避免分配不足（CERT C MEM35-C）。

realloc 要先用临时变量接住结果：写成 p = realloc(p, n) 时一旦失败，返回的 NULL 覆盖了 p，原来那块内存再也找不到，造成泄漏。

bool growArray(int **arr, size_t newCount) {
    int *tmp = (int *)realloc(*arr, newCount * sizeof **arr);
    if (tmp == NULL) return false;      // 失败：*arr 原样保留，调用者仍可使用或释放
    *arr = tmp;
    return true;
}

四类经典错误

野指针从没指向合法内存；悬空指针曾经合法、现在失效；泄漏是内存还在但没有指针指向它

名称成因后果预防
野指针指针定义后没初始化读写随机地址定义时初始化为 NULL/nullptr 或有效地址

逐步执行：释放链表

释放链表是最经典的悬空指针题。下面左边的写法在 free(p) 之后才去读 p->next，读的是已归还的内存（CERT C MEM30-C）。[37]

// 错误：for (Node *p = head; p != NULL; p = p->next) free(p);
//       每轮结束时执行 p = p->next，此时 p 已经被 free
void freeList(Node *head) {
    while (head != NULL) {
        Node *next = head->next;   // 先保存 next
        free(head);                // 再释放当前节点
        head = next;
    }
}

正确释放 1→2→3

1 / 3

第1步 · 保存 next 指向节点 2

2 / 3

第2步 · free(head)：节点 1 归还；next 仍握着剩余链表

3 / 3

第3步 · head = next，进入下一轮

重复直到 head 为 NULL，共释放 3 个节点

段错误的常见成因

段错误（SIGSEGV）是操作系统发出的信号：进程访问了没有映射的地址，或者以不允许的方式（写只读页）访问了已映射的地址。常见原因：

  1. 解引用空指针（地址 0 附近不映射）；
  2. 访问已释放并归还给系统的内存，或野指针指向的未映射地址；
  3. 写只读内存，例如修改字符串字面量 char *s = "abc"; s[0] = 'x';；
  4. 栈溢出：无限递归、超大局部数组；
  5. 数组越界访问到未映射区域。

越界不一定立刻段错误。内存保护以页（通常 4 KB）为单位，malloc 的小块越界写往往仍落在已映射的页内，程序看似正常，实际已经破坏了相邻数据。博客实验里 malloc 1024 个 int 后写到第 1200 个元素没有崩溃，正是这个原因；valgrind 能报出 Invalid write。[32]

未定义行为（UB）

未定义行为是标准对某些操作"不作任何要求"：程序可能崩溃、可能输出看似正确的结果、可能在开优化后表现不同。编译器可以假设 UB 不会发生，并据此优化。所以"我机器上跑出了 X"不能证明程序正确。[38]

三个典型例子：

  1. 有符号整数溢出：int x = INT_MAX; x + 1;。编译器可以把 if (x + 1 > x) 直接优化成恒真。
  2. 越界访问：int a[3]; a[3] = 1; 可能改坏相邻变量，也可能段错误。
  3. 同一变量无序修改两次：i = i++ + ++i;。

与之相关的另两个类别：未指定行为——标准给出几种可能，实现任选一种且不必说明，如函数参数的求值顺序 f(g(), h())；实现定义行为——由实现选择并写进文档，如 sizeof(long)、负数右移。

要点

  • 标准答案句：野指针是未初始化的指针；悬空指针是指向已释放内存的指针；内存泄漏是已分配的内存失去了所有引用而无法释放。
  • malloc/free、new/delete、new[]/delete[] 必须成对使用。
  • 释放链表要先保存 next；realloc 的结果先存到临时变量。
  • 遇到 UB 的读代码题，选"结果不确定/未定义"。

多选 · 理解检查 10　下列哪些属于未定义行为？

A. int x = INT_MAX; x = x + 1;

B. unsigned int u = 0; u = u - 1;

C. free(p); free(p);（p 中间未修改）

D. int *p = NULL; free(p);

查看答案与每个选项的解析

A · 正确：有符号整数溢出是未定义行为。

B · 错误：无符号运算按模回绕，结果确定为 UINT_MAX。

C · 正确：重复释放同一块内存是未定义行为。

D · 错误：free(NULL) 被标准规定为不做任何事。

易错点：

  • free(p) 只归还内存，不会把 p 改成 NULL；其他指向同一块内存的指针也都变成悬空指针。
  • 对栈上数组或字符串字面量调用 free 是错误的，只能 free 由 malloc/calloc/realloc 返回的指针（CERT C MEM34-C）。
  • sizeof(p) 对 malloc 得到的指针只给出指针大小，拿不到分配了多少字节。

小结： 申请和释放要配对；释放链表结点前先保存 next；realloc 的结果先存入临时变量；野指针是未初始化的指针，悬空指针指向已释放的内存，内存泄漏是已分配的内存没有任何指针指向；未定义行为不能靠实际运行的结果来判断。

1.11 C++ 类基础：构造、析构、拷贝与 Rule of Three

为什么需要：C++ 面试的第一组问题几乎固定：class 和 struct 的区别、初始化列表、拷贝构造什么时候被调用、深拷贝和浅拷贝、Rule of Three。它们都围绕一件事：对象创建、复制、销毁时，编译器替我们调用了哪个函数。

class 与 struct

C++ 里两者都能有成员函数、构造函数、继承，唯一的区别是默认访问权限：class 的成员和继承默认是 private，struct 默认是 public。习惯上，只装数据的类型用 struct，有不变量需要保护的用 class。

构造函数与初始化列表

构造函数与类同名、没有返回类型，在对象创建时自动调用；析构函数是 ~类名()，在对象销毁时自动调用。初始化列表写在构造函数参数表之后的冒号后面，直接初始化成员，而写在函数体里的 x = v; 是先默认构造再赋值。const 成员、引用成员、没有默认构造函数的成员只能在初始化列表里初始化。[39]

成员的初始化顺序按它们在类中声明的顺序，与初始化列表的书写顺序无关：

class InitOrder {
public:
    int a;                 // 先声明
    int b;                 // 后声明
    InitOrder(int v) : b(v), a(b + 1) {}   // 实际顺序：先 a(b + 1)，此时 b 尚未初始化；再 b(v)
};

a 读到的是未初始化的 b，结果不确定。GCC 的 -Wreorder 会警告"b will be initialized after a"。修正方法是让初始化列表的顺序与声明顺序一致，并且不依赖后声明的成员。

拷贝构造函数何时被调用

拷贝构造函数的签名是 T(const T& other)，用一个已有对象创建一个新对象时调用。以下三种情况会调用它：[40]

Tracker a;
Tracker b = a;          // ① 用已有对象初始化新对象（等价于 Tracker b(a);）
byValue(a);             // ② 按值传参：形参是用实参拷贝出来的
Tracker c;
c = a;                  // 不调用拷贝构造：c 已经存在，调用的是拷贝赋值 operator=
byRef(a);               // 不调用：引用传参不产生新对象
passThrough(a);         // Tracker passThrough(Tracker t) { return t; }
                        // 传参拷贝一次；③ 按值返回时用 t 构造返回值，又一次
代码调用拷贝构造次数（累计）
Tracker b = a;拷贝构造1
byValue(a);拷贝构造（形参）2
byRef(a);无2
c = a;拷贝赋值2
passThrough(a);形参 + 返回值4

按值返回局部对象时，编译器常做返回值优化（RVO）省掉拷贝：return Tracker(); 这类返回临时对象的写法在 C++17 中保证不调用拷贝或移动；返回具名局部变量时，编译器通常也会省略，没省略时优先用移动构造。形参 t 例外，它不能被优化掉，所以上表计 2 次。拷贝构造函数的参数必须是引用：若写成 T(T other)，传参本身又要调用拷贝构造，无限递归。

浅拷贝与深拷贝

编译器自动生成的拷贝构造函数逐个成员复制。成员是指针时，只复制指针的值，两个对象指向同一块堆内存，这叫浅拷贝。两个对象析构时各 delete 一次，就是重复释放。

左：浅拷贝，两个指针共用一块，析构时释放两次；右：深拷贝，各自拥有一块

深拷贝是在拷贝构造函数里为新对象重新分配内存，再复制内容：

class Buffer {
    char *data_;
public:
    explicit Buffer(const char *s) : data_(new char[strlen(s) + 1]) { strcpy(data_, s); }
    Buffer(const Buffer &o) : data_(new char[strlen(o.data_) + 1]) { strcpy(data_, o.data_); }
    Buffer &operator=(const Buffer &o) {
        if (this != &o) {                          // 自赋值保护
            char *fresh = new char[strlen(o.data_) + 1];
            strcpy(fresh, o.data_);
            delete[] data_;
            data_ = fresh;
        }
        return *this;
    }
    ~Buffer() { delete[] data_; }
};

Rule of Three / Five / Zero

  • Rule of Three：如果一个类需要自定义析构函数、拷贝构造函数、拷贝赋值运算符中的任何一个，通常三个都需要。原因：需要自定义析构，说明类直接管理着资源，默认的逐成员复制会出问题。
  • Rule of Five（C++11）：再加上移动构造函数、移动赋值运算符（1.13），让资源可以被"搬走"而不是复制。
  • Rule of Zero：最好的做法是一个都不写，让成员自己管理资源——用 std::string、std::vector、std::unique_ptr 代替裸指针，编译器生成的默认版本就是正确的。[41]

this、const 成员函数、static 成员、友元

  • this：每个非静态成员函数都有一个隐含参数 this，指向调用它的对象。return *this; 返回对象自身，支持 p.moveBy(1).moveBy(1) 这样的链式调用。
  • const 成员函数：int x() const 承诺不修改对象，此时 this 的类型是 const T*。const 对象只能调用 const 成员函数。
  • static 成员：属于类而不属于某个对象，所有对象共享一份。静态成员变量要在类外定义一次（int Counter::alive = 0;，C++17 也可在类内写 inline static）；静态成员函数没有 this，只能访问静态成员，可以用 类名::函数() 调用。[42]
  • 友元：friend int distSq(const Point&); 让一个外部函数或类访问本类的私有成员。友元关系是单向的，也不能继承。[43]
class Counter {
public:
    static int alive;            // 声明
    Counter() { ++alive; }
    Counter(const Counter&) { ++alive; }
    ~Counter() { --alive; }
};
int Counter::alive = 0;          // 定义
// { Counter a; { Counter b, c; Counter d = a; /* alive == 4 */ } /* alive == 1 */ }

要点

  • class 默认 private，struct 默认 public。
  • 成员按声明顺序初始化，与初始化列表顺序无关。
  • 标准答案句：拷贝构造函数在三种情况下调用：用一个对象初始化另一个同类对象；对象按值传递给函数参数；函数按值返回对象（可能被编译器优化省略）。
  • 类中有指针成员指向自己分配的资源时，需要深拷贝，并遵循 Rule of Three/Five；更好的做法是 Rule of Zero。

B · 错误：按值传参和按值返回都会创建新对象。

隐藏最容易出错：派生类只要定义了同名函数，基类中所有同名函数（不论参数）都被遮住。

struct HideBase {
    std::string f(int) const    { return "Base f(int)"; }

virtual 与动态绑定

struct Base {
    virtual std::string who() const { return "Base"; }
    std::string plain() const { return "Base::plain"; }
    virtual ~Base() {}
};
struct Derived : Base {
    std::string who() const override { return "Derived"; }
    std::string plain() const { return "Derived::plain"; }   // 隐藏
};
Base *p = new Derived;
p->who();     // "Derived"：虚函数，按对象实际类型
p->plain();   // "Base::plain"：非虚函数，按指针的静态类型

动态绑定的条件有两个：函数是 virtual，并且通过指针或引用调用。override 关键字让编译器检查确实重写了基类虚函数，签名写错时直接报错。[44]

虚函数表是怎么工作的

主流编译器（GCC、Clang、MSVC）都这样实现虚函数：

  1. 每个含虚函数的类有一张虚函数表（vtable），是一个函数指针数组，存放该类每个虚函数的最终实现地址，放在只读数据区。
  2. 每个含虚函数的对象在开头多一个隐藏成员虚指针（vptr），指向所属类的 vtable。构造函数负责设置它。
  3. 派生类的 vtable 先复制基类的表，重写了哪个函数就把对应槽位换成自己的地址，新增的虚函数追加在后面。

对象头部的 vptr 指向本类的 vtable；p->who() 先取 vptr，再取槽 [1] 的地址去调用

p->who() 的调用过程

1 / 4

第1步 · 编译期：who 是 Base 的第 1 号虚函数，编译器生成"取 vptr → 取槽 1 → 调用"的指令

编译器此时并不知道 p 指向的实际类型
2 / 4

第2步 · 运行期第 1 步：从 p 指向的对象开头读出 vptr

Derived 对象的 vptr 指向 Derived 的 vtable
3 / 4

第3步 · 第 2 步：在 vtable 中取下标 1 的函数地址

得到 Derived::who 的地址
4 / 4

第4步 · 第 3 步：以 p 作为 this 调用该地址

返回 "Derived"。如果 p 指向 Base 对象，vptr 指向 Base 的表，就会调用 Base::who

由此可以推出几个常考结论：

  • 含虚函数的对象比同样成员的普通对象多一个指针。x86-64 上 struct { int x; virtual void f(); } 的 sizeof 是 16（vptr 8 + int 4 + 填充 4），去掉 virtual 是 4。
  • 虚调用比普通调用多两次内存读取，且通常无法内联。
  • 构造函数不能是虚函数：调用构造函数时对象还没建好，vptr 还没设置。
  • 在构造函数和析构函数里调用虚函数，不会调用到派生类的版本：Base 构造期间 vptr 指向 Base 的表。
  • static 成员函数没有 this，也就无法通过对象的 vptr 派发，所以不能是虚函数。

纯虚函数与抽象类

virtual double area() const = 0; 是纯虚函数：基类只规定接口，不给实现。含有纯虚函数的类叫抽象类，不能创建对象，只能作为基类，用指针或引用指向派生对象。派生类必须重写全部纯虚函数，否则自己也是抽象类。[45]

struct Shape { virtual double area() const = 0; virtual ~Shape() = default; };
struct Rect : Shape {
    double w, h;
    Rect(double a, double b) : w(a), h(b) {}
    double area() const override { return w * h; }
};
// Shape s;  编译错误：抽象类不能实例化
// std::vector<std::unique_ptr<Shape>> 里放 Rect(2,5) 和 Square(4)，面积和为 10 + 16 = 26

虚析构函数

用基类指针 delete 派生类对象时，如果基类析构函数不是虚函数，delete p 只按静态类型调用 ~Base()，派生类的析构函数不执行，派生部分持有的资源就泄漏了（标准规定这是未定义行为）。基类析构函数声明为 virtual 后，delete 会经过 vtable 找到 ~Derived()，按"先派生、后基类"的顺序完整销毁。[46]

标准答案句：作为多态基类使用的类，析构函数应声明为虚函数，否则通过基类指针删除派生类对象时，派生类的析构函数不会被调用。

对象切片

把派生类对象按值赋给基类对象时，只复制基类那一部分，派生部分被"切掉"，vptr 也是 Base 的。之后调用虚函数得到的是基类版本：

Derived d;
Base b = d;        // 切片：b 是一个纯粹的 Base 对象
b.who();           // "Base"
Base &r = d;       // 引用不切片
r.who();           // "Derived"

所以多态对象要用指针或引用传递，容器里存 unique_ptr<Base> 而不是 Base。

构造与析构顺序

规则：构造时先基类，再成员（按声明顺序），最后自己的构造函数体；析构顺序完全相反。

struct Member { char tag; Member(char t); ~Member(); };   // 构造打印 M1/M2，析构打印 ~M1/~M2
struct Base    { Member m1{'1'}; Base();    virtual ~Base(); };     // 打印 B / ~B
struct Derived : Base { Member m2{'2'}; Derived(); ~Derived(); };   // 打印 D / ~D
{ Derived d; }

Derived d; 的构造与析构

1 / 4

第1步 · 构造 Base 部分：先构造 Base 的成员 m1，再执行 Base() 函数体

输出：M1 B
2 / 4

第2步 · 构造 Derived 自己的成员 m2

输出：M1 B M2
3 / 4

第3步 · 执行 Derived() 函数体，对象构造完成

输出：M1 B M2 D
4 / 4

第4步 · 离开作用域，按相反顺序析构：~Derived 函数体 → m2 → ~Base 函数体 → m1

输出：~D ~M2 ~B ~M1

多个基类时，按继承列表中的声明顺序构造；虚基类最先构造。

多继承与菱形继承

Horse 和 Donkey 都继承 Animal，Mule 同时继承两者，形成菱形。普通继承下，Mule 对象里有两份 Animal 子对象，m.age 有二义性，必须写 m.Horse::age 或 m.Donkey::age，而且两个 age 可以不同。

左：普通继承，Mule 中有两份 Animal；右：虚继承，两条路径共享一份基类子对象

虚继承：struct VHorse : virtual VAnimal {}、struct VDonkey : virtual VAnimal {}，最终的 VMule 中只有一份 VAnimal，v.age 不再二义。代价是对象里要多存定位虚基类的信息（虚基类指针或 vtable 中的偏移），访问虚基类成员多一次间接寻址；虚基类由最终派生类直接负责构造。[47]

要点

  • 多态由虚函数加上基类指针或引用实现；实现机制是每个类有一张虚函数表（vtable），每个对象有一个虚表指针（vptr）。

易错点：

  • 派生类重写时签名必须完全相同（含 const），否则成了隐藏；加 override 能让编译器帮你检查。
  • 默认参数按静态类型确定：基类虚函数默认参数是 1、派生类是 2，通过基类指针调用时运行派生类函数体，却用基类的默认参数 1。

小结： virtual 函数通过指针或引用调用时才发生动态绑定；每个类有一张虚函数表，每个对象有一个虚表指针；含纯虚函数的类是抽象类；作为多态基类的类要有虚析构函数；构造顺序是基类、成员、自身，析构顺序相反；菱形继承用虚继承解决。

粗略的判断方法：能取地址、有名字的表达式是左值；临时的、即将消亡的值是右值。x、arr[0]、*p 是左值；42、x + 1、函数按值返回的临时对象是右值。[49]

std::move 的本质

std::move(x) 本身不移动任何东西，它只是一个类型转换：把 x 转成右值引用 T&&，让重载决议选中接收 T&& 的那个函数（移动构造、移动赋值）。真正"搬资源"的是移动构造函数。被 move 之后的对象处于"有效但未指定"的状态：可以析构、可以重新赋值，但不应依赖它的值。[50]

移动构造

class Blob {
public:
    int *data; size_t n;
    Blob(const Blob &o) : data(new int[o.n]), n(o.n) {        // 拷贝：新分配并复制
        memcpy(data, o.data, n * sizeof(int));
    }
    Blob(Blob &&o) noexcept : data(o.data), n(o.n) {          // 移动：接管指针
        o.data = nullptr;                                     // 源对象放空，避免重复释放
        o.n = 0;
    }
    ~Blob() { delete[] data; }
};

拷贝的代价是 O(n)（分配 + 复制），移动是 O(1)（复制一个指针）。标准容器、std::string、std::unique_ptr 都实现了移动。函数按值返回局部对象、push_back 一个临时对象时，编译器会自动使用移动构造。移动构造函数应标记 noexcept：vector 扩容时只有确认移动不会抛异常，才会用移动代替拷贝搬运旧元素。[51]

要点

  • 引用是别名，必须初始化、不能改绑、不能为空；指针可以。
  • 标准答案句：std::move 只做类型转换，把左值转为右值引用，真正的资源转移由移动构造函数或移动赋值运算符完成。
  • 移动构造接管源对象的资源并把源对象置于可析构的空状态；它让临时对象的"复制"从 O(n) 变成 O(1)。

1.14 智能指针与 RAII：让析构函数替你释放

为什么需要：1.10 的四类内存错误，根源都是"释放要靠人记得"。C++ 的答案是 RAII（资源获取即初始化）：把资源交给一个局部对象管理，构造时获取，析构时释放。对象离开作用域时析构函数一定被调用（包括因异常提前离开），资源就一定被释放。[52]

RAII 不限于内存：std::lock_guard 构造时加锁、析构时解锁；std::fstream 析构时关闭文件。智能指针是 RAII 管理堆内存的标准工具。

循环引用

两个对象各用 shared_ptr 指向对方：

struct Person { std::shared_ptr<Person> partner; };
{
    auto a = std::make_shared<Person>();
    auto b = std::make_shared<Person>();
    a->partner = b;
    b->partner = a;
}   // 离开作用域后，两个 Person 都没有被析构

a、b 析构后各减 1，但 A 和 B 互相持有，计数停在 1，永远无法归零：泄漏

推导：赋值后 A、B 的强计数都是 2（局部变量一个、对方的 partner 一个）。离开作用域，局部变量 a、b 析构，各减 1，剩下 1。要让 A 的计数归零，需要 B 先析构释放 partner；要让 B 析构，又需要 A 先释放——互相等待。解决办法：把其中一个方向（或两个方向）改成 std::weak_ptr，weak_ptr 不增加强计数，离开作用域时两个对象的计数都从 1 降到 0，正常析构。需要访问时用 partner.lock() 临时得到一个 shared_ptr，对象已不在时返回空。

要点

  • 标准答案句：RAII 把资源的生命周期绑定到对象的生命周期上，在构造函数中获取资源，在析构函数中释放资源，即使发生异常也能保证释放。
  • unique_ptr 独占、只能移动；shared_ptr 共享、引用计数；weak_ptr 观察、不增加计数。
  • shared_ptr 互相引用会形成循环引用导致内存泄漏，用 weak_ptr 打破环。
  • 优先用 make_unique/make_shared 创建，避免 new 出现在代码中。

1.15 模板与 STL 机制：迭代器失效与容器底层

为什么需要：面试问 STL 不考接口（「算法导论」第 1 章已经讲过用法），考的是机制："vector 怎么扩容""哪些操作会让迭代器失效""map 和 unordered_map 底层是什么"。

模板

函数模板让同一段代码适用于多种类型，编译器在调用处根据实参推导出类型，为每种用到的类型生成一份具体函数，这个过程叫实例化：

template <typename T>
T myMax(T a, T b) { return a < b ? b : a; }
myMax(3, 7);                      // 推导 T = int，得 7
myMax(2.5, 1.5);                  // 推导 T = double，得 2.5
myMax<std::string>("b", "a");     // 显式指定 T，得 "b"

类模板的类型参数要写出来（C++17 起部分情况可推导），参数还可以是整数常量：

template <typename T, int N>
class FixedStack {
    T items_[N];
    int top_ = 0;
public:
    bool push(const T &x) {
        if (top_ == N) return false;
        items_[top_++] = x;
        return true;
    }
    T pop() { return items_[--top_]; }
    int size() const { return top_; }
};
// FixedStack<int, 2> st; push(1)、push(2) 成功，push(3) 返回 false

模板代码要在使用处看到完整定义才能实例化，所以模板一般整个写在头文件里，分开到 .cpp 中会在链接时报 undefined reference。模板是编译期多态，虚函数是运行期多态。[56]

vector 扩容

vector 在一块连续内存里存元素，记录两个量：size（已有元素数）和 capacity（这块内存能放多少个）。push_back 时 size 已等于 capacity，就要扩容：

  1. 申请一块更大的新内存（libstdc++ 为原容量的 2 倍，MSVC 为 1.5 倍）；
  2. 把旧元素移动（移动构造为 noexcept 时）或拷贝到新内存；
  3. 析构旧元素、释放旧内存；
  4. 在末尾放入新元素。

vector 扩容：capacity 4 → 8

1 / 3

第1步 · size = 4 = capacity，it 指向 v[1]

2 / 3

第2步 · push_back(50)：申请 8 个位置的新内存，把 4 个元素搬过去，放入 50

3 / 3

第3步 · 旧内存被释放：it 仍保存着旧地址，变成悬空迭代器

此后再用 *it 是未定义行为

从空 vector 连续 push_back 9 次，GCC 下 capacity 依次为 1、2、4、8、16，共扩容 5 次，搬运元素 0 + 1 + 2 + 4 + 8 = 15 次。一般地，n 次 push_back 总搬运次数小于 2n，所以 push_back 的均摊复杂度是 O(1)。已知元素个数时，先 reserve(n) 预留容量，可以避免多次扩容；reserve 只改 capacity 不改 size，resize 改 size 并构造新元素。[57]

迭代器失效规则

迭代器是"指向容器中某个位置"的对象，对 vector 来说就是一个包装过的指针。容器修改后，原来指向的内存可能被释放或元素被挪动，迭代器就失效了。[58]

循环中删除元素的标准写法：用 erase 的返回值（指向被删元素的下一个）更新迭代器，没删时才 ++it。

std::vector<int> removeEvens(std::vector<int> v) {
    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 == 0) it = v.erase(it);   // erase 返回下一个有效迭代器
        else ++it;
    }
    return v;
}
// removeEvens({1, 2, 2, 3, 4, 5}) == {1, 3, 5}

要点

  • 模板在编译期按实际类型实例化，定义通常放在头文件。
  • 标准答案句：vector 容量不足时会申请更大的连续内存（GCC 为 2 倍），把旧元素移动或拷贝过去并释放旧内存，因此所有指向旧内存的迭代器、指针、引用都会失效；push_back 的均摊复杂度为 O(1)。

1.16 安全编码：缓冲区溢出与 CERT C 规则

为什么需要：银行科技岗的安全题常问"什么是缓冲区溢出""为什么 strcpy 危险""怎么防范"。本节从防御角度讲原理和安全写法。

缓冲区溢出是什么

缓冲区溢出：程序向缓冲区写数据时越过了它的边界，覆盖了相邻内存。C/C++ 不检查数组下标，strcpy、gets 这类函数也不知道目标缓冲区有多大，所以输入一旦比缓冲区长，多出来的字节就会写到后面的内存里。溢出既可以发生在栈上的局部数组（栈溢出），也可以发生在 malloc 的堆块中（堆溢出）。它对应 CWE-787（越界写）。[61] [35]

为什么越界写会改掉返回地址

调用函数时，CPU 把"函数结束后回到哪里"的返回地址压入栈中，然后为局部变量分配空间。x86 上栈从高地址向低地址增长，而数组从低地址向高地址填写，于是局部数组的"后面"（更高地址）正是保存的帧指针和返回地址。

strcpy(buf, src) 从 buf[0] 向高地址写；src 超过 10 字节就依次覆盖旧帧指针和返回地址

函数返回时，CPU 从栈上取出返回地址跳过去。这个地址如果被溢出的数据覆盖，程序就会跳到一个错误的位置：轻则崩溃，重则执行攻击者控制的代码。用户博客的实验正是关掉编译器和系统的保护后观察到了返回地址被覆盖。[62] [63]

现代系统有多层缓解措施：

机制原理

整数溢出检查

整数溢出常常是缓冲区溢出的前一步：malloc(n * sizeof(int)) 中 n 很大时乘积回绕成一个小数，分配了很小的块，随后按 n 个元素写入就越界了。检查要在运算之前做，因为有符号溢出一旦发生就是未定义行为，事后检查可能被编译器优化掉（CERT C INT32-C）。[65]

bool checkedAdd(int a, int b, int *out) {
    if ((b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b)) return false;
    *out = a + b;
    return true;
}
bool mulSizeOk(size_t n, size_t elem) {
    return elem == 0 || n <= SIZE_MAX / elem;     // n * elem 不会回绕
}
// checkedAdd(INT_MAX, 1, &r) 返回 false；mulSizeOk(SIZE_MAX / 2, 4) 返回 false

  • 标准答案句：缓冲区溢出是指向缓冲区写入的数据超过其容量，覆盖相邻内存；栈溢出可覆盖函数返回地址，导致程序崩溃或控制流被劫持。

多选 · 理解检查 17　void sub(const char *x) { char y[10]; strcpy(y, x); } 关于这段代码，哪些说法正确？

A. x 长度达到 10 个字符或更多时（加上 '\0' 超过 10 字节），会越界写栈

B. 越界写可能覆盖保存的帧指针和返回地址

C. 改为 snprintf(y, sizeof y, "%s", x) 后不会越界

D. 加上 #define _CRT_SECURE_NO_WARNINGS 就能消除风险

查看答案与每个选项的解析

A · 正确：strcpy 连 '\0' 一起复制，不检查 y 的大小。

B · 正确：它们位于局部数组的高地址一侧。

C · 正确：snprintf 最多写 sizeof y 字节并保证 '\0' 结尾。

D · 错误：它只关闭编译警告，代码行为不变。

易错点：

  • strncpy(dst, src, sizeof dst) 在 src 过长时没有结尾 '\0'，之后对 dst 的字符串操作仍会越界读。
  • 栈溢出（stack overflow）有两种含义：递归过深耗尽栈空间，以及栈上缓冲区越界写（stack buffer overflow）；答题时按上下文区分。

小结： 越界写会覆盖相邻的内存，栈上的越界可能改写返回地址；gets、strcpy、sprintf 应换成 fgets、snprintf；运算之前先检查是否溢出；不要把用户输入作为格式字符串；栈金丝雀（canary）、ASLR 和 NX 是最后的防线。

1.17 附：Go 速览

部分互联网公司的笔试会出几道 Go 读代码题。Go 的语法与 C 很像，但 slice、map、channel、defer 有自己的规则。本节按“代码、输出、原因”的形式列出最常考的几条，以 Go 1.24 的实际运行结果为准。[68] [69]

数组与 slice

Go 数组的长度是类型的一部分，[3]int 和 [4]int 是不同类型；数组赋值、传参都复制全部元素。slice 是一个三元组：指向底层数组的指针、长度 len、容量 cap。复制 slice 只复制这个三元组，底层数组是共享的。

a := []int{1, 2, 3}
b := a[:2]          // b 与 a 共享底层数组，len 2，cap 3
b[0] = 9            // a 变成 [9 2 3]
b = append(b, 7)    // cap 够用，直接写到底层下标 2：a 变成 [9 2 7]
b = append(b, 8)    // cap 不够，分配新数组（本例 cap 变为 6），b 与 a 分离
b[0] = 100          // 只改 b；a 仍是 [9 2 7]

容量够用时 append 写回共享的底层数组；超出容量时分配新数组，之后两者互不影响

结论：append 是否影响原 slice，取决于是否超出 cap。函数要修改调用者的 slice 长度时，要把 append 的结果 return 回去。

map

map 是哈希表，引用语义：赋值或传参后修改，双方都能看到。var m map[string]int 得到的是 nil map，读取返回零值、len 为 0，写入会 panic，要先 m = make(map[string]int)。map 的遍历顺序被刻意随机化，每次运行可能不同。多个 goroutine 同时读写同一个 map 需要加锁（或用 sync.Map），否则运行时会直接报 fatal error。

接口与 nil

接口值由两部分组成：动态类型和动态值。只有两部分都为空时，接口才等于 nil。

var p *T = nil
var i I = p          // i 的动态类型是 *T，动态值是 nil
fmt.Println(i == nil, p == nil)   // false true

函数返回 error 时，如果返回了一个值为 nil 的具体错误指针，调用方的 err != nil 会为真。正确做法是直接 return nil。接口由方法集隐式实现，不需要 implements 关键字。

defer

defer 把函数调用推迟到外层函数返回前执行；多个 defer 后进先出；被 defer 的函数的参数在 defer 语句执行时就求值。

x := 1
defer fmt.Println("defer x =", x)   // 参数此刻求值为 1
x = 2
for i := 0; i < 3; i++ {
    defer fmt.Print(i, " ")
}
// 函数返回时输出：2 1 0 defer x = 1

defer 的匿名函数可以修改命名返回值：func f() (r int) { defer func() { r *= 2 }(); return 3 } 返回 6。执行顺序是先把 3 赋给 r，再执行 defer，最后真正返回。recover 只在 defer 的函数里调用才能捕获 panic。

goroutine 与 channel

go f() 启动一个 goroutine，由 Go 运行时调度到少量系统线程上（M:N 调度），开销远小于线程。goroutine 之间推荐用 channel 通信。

操作无缓冲 channel有缓冲 channel（容量 n）已关闭的 channelnil channel
发送阻塞到有人接收缓冲满才阻塞panic永久阻塞
接收阻塞到有人发送缓冲空才阻塞先取完剩余数据，之后返回零值和 ok=false永久阻塞

main 函数返回时，所有 goroutine 随之结束，不会等待它们；需要等待时用 sync.WaitGroup 或 channel。

要点

  • 数组是值类型，赋值即复制；slice、map、channel 赋值后共享底层数据。
  • append 超出 cap 会换底层数组；未超出时会改到共享的数组。
  • nil map 可读不可写；向已关闭的 channel 发送会 panic；从已关闭的 channel 接收得到零值和 false。
  • defer 后进先出，参数在登记时求值；装着 nil 指针的接口不等于 nil。

单选 · 理解检查 18　Go 中 a := []int{1,2,3}; b := a[:2]; b = append(b, 7); 之后 a 是什么？

A. [1 2 7]

B. [1 2 3]

C. [1 2 3 7]

D. 编译错误

查看答案与每个选项的解析

A · 正确：b 的 cap 是 3，append 不扩容，直接写到共享底层数组的下标 2。

B · 错误：只有超出 cap 时 append 才会分配新数组。

C · 错误：append 作用于 b，a 的 len 仍是 3。

D · 错误：对子切片 append 是合法操作。

易错点：

  • for i, v := range s 中的 v 是元素的副本，修改 v 不会改到 s；要改用 s[i] = …。
  • 在循环里 defer f.Close() 会把所有关闭推迟到函数结束，打开大量文件时可能耗尽句柄。

小结： Go 的数组赋值时复制，slice 共享底层数组，超过容量时才分配新数组；nil map 可以读、不能写；向已关闭的 channel 发送会 panic，接收得到零值；defer 按后进先出的顺序执行，参数在 defer 语句处就已求值；接口值只有在类型和值都为空时才等于 nil。
