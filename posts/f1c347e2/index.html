4.1 数据挖掘做什么：KDD 过程与 CRISP-DM

一家银行每天产生几千万条交易流水。业务部门想知道三件事：哪些客户下个月可能逾期，哪些产品常被一起购买，哪些交易像是盗刷。以第一件为例，从原始数据到结论要走这几步：

  1. 清洗：有位客户的月收入是空的，另一笔还款被录成了 −5000 元。先补上空值、改掉错值（4.2）。
  2. 整合：贷款系统和信用卡系统各有一张表，用身份证号把同一个人的记录合到一行。
  3. 选择与变换：只留和逾期有关的列（收入、负债、近半年逾期次数），把金额类的列换到同一尺度（4.3）。
  4. 挖掘：用算法找规律，例如"负债超过收入一半、近半年逾期过的人，下月逾期率 40%"。
  5. 评估与表示：这条规律在新数据上还成立吗？覆盖的人够多吗？有用的写进报告、画成图，没用的回到前面重做。

这一整套从原始数据到可用结论的过程叫知识发现（KDD，Knowledge Discovery in Databases）。其中第 4 步"用算法找规律（模式）"叫数据挖掘。前三步合称数据预处理，实际项目里最花时间。[1]

KDD 过程：前三步是预处理，第 4 步才是狭义的数据挖掘（教材常把它细分成 7 步，内容相同）

挖掘任务分成两大类。描述性任务刻画数据本身的规律，包括关联分析、聚类、异常检测；预测性任务用已知数据推断未知标签，包括分类和回归。

工业界更常用的项目流程把项目分成 6 个阶段：业务理解、数据理解、数据准备、建模、评估、部署。它从业务目标出发，到模型上线结束，阶段之间可以来回跳。这套流程叫 CRISP-DM（跨行业数据挖掘标准流程）。[2]

CRISP-DM 六阶段：双向箭头表示两阶段之间常来回迭代

要点：

  1. 狭义的数据挖掘是 KDD 中的一个步骤；广义上人们也用"数据挖掘"指整个 KDD 过程。
  2. CRISP-DM 从业务目标出发，强调各阶段之间来回迭代。
  3. 关联、聚类、异常检测属于描述性任务；分类、回归属于预测性任务。

4.2 缺失值与异常值：先补洞，再找离群点

拿到一张客户表，第一件事是数一数有多少空格子、有没有离谱的数字。月收入一栏有人没填，交易金额一栏有一笔 180 万的大单，这两种情况都会把均值、方差和模型带偏。

缺失值的处理方法

用 6 位客户的月收入（千元）走一遍：[5, 6, 7, 8, 缺, 30]。已知的 5 个数平均是 (5+6+7+8+30)/5 = 11.2，被 30 这个大值拉高了；从小到大排在正中间的数（中位数）是 7，更能代表"普通客户"。用中位数填补得到 [5, 6, 7, 8, 7, 30]，同时加一列缺失标记 [0, 0, 0, 0, 1, 0]。不愿填收入的人风险可能更高，这列标记往往就是有用的特征；评分卡也常把"缺失"单独作为一段（4.17）。[3]

常用做法汇总：

方法做法适用场合
删除元组整行丢掉缺失很少、样本很多
全局常量填"未知"或 −1类别变量；让模型自己学"未知"
均值 / 中位数用该列的均值或中位数填数值变量；有极端值时用中位数
同类均值只用同一类（如同职业）样本的均值类别间差异大

异常值：3σ 原则与 IQR 箱线图

下面是 10 笔交易金额（万元）：52, 55, 58, 60, 63, 65, 68, 70, 72, 180。180 看着离谱，怎样让程序自动把它挑出来？有两种常用办法。

办法一：看排在四分之一、四分之三处的数。 先求整体中位数，把数据分成下半 52…63 和上半 65…180（个数为奇数时，两半都不含中位数本身）。下半的中位数 58 叫下四分位数 Q1，上半的中位数 70 叫上四分位数 Q3，两者之差 70 − 58 = 12 叫四分位距（IQR）。落在 [Q1 − 1.5·IQR, Q3 + 1.5·IQR] = [40, 88] 之外的点视为异常，180 被抓到。四分位数只看排序位置，极端值改变不了它。这就是箱线图的画法。

办法二：看离平均值几个标准差。 平均值 μ（读作"缪"）= 74.3，标准差 σ（读作"西格玛"，衡量数据离平均值有多散）= 35.76。数据近似正态分布时，落在 μ ± 3σ 之外的概率只有约 0.27%（第 2 章 2.5），于是把 |x − μ| > 3σ 的点视为异常，这叫 3σ 原则。本例上界 μ + 3σ = 181.59，180 没超过，没抓到。

IQR=12，上界 70+18=88，180 落在界外被标为异常

3σ 失手的原因是 180 自己把 σ 撑大了：去掉 180 后，其余 9 个数的 μ = 62.56、σ = 6.47，180 远在 μ + 3σ ≈ 82 之外。异常值会"掩护"自己，这叫掩蔽效应。

要点：

  1. 有极端值时，用中位数填补比均值稳健。
  2. 3σ 原则依赖正态假设，均值和标准差会被异常值本身拉偏；样本小时更明显。
  3. IQR 基于分位数，对极端值稳健。
  4. 风控里"异常"可能正是要找的目标（大额盗刷），先查明原因再决定删、改还是保留。

多选 · 理解检查 2　数据 10, 12, 13, 15, 16, 18, 40 用本节的中位数分两半法求四分位数，哪些结论正确？

A. Q1 = 12，Q3 = 18

B. IQR = 6，上界为 27

C. 40 被判为异常

D. 10 被判为异常

查看答案与每个选项的解析

A · 正确：中位数是 15；下半 10, 12, 13 的中位数是 12，上半 16, 18, 40 的中位数是 18。

B · 正确：18 − 12 = 6，18 + 1.5×6 = 27。

C · 正确：40 > 27。

D · 错误：下界 12 − 9 = 3，10 在界内。

易错点

  • 四分位数有多种算法（Excel、NumPy 用插值），结果会差一点；考题一般会给出算法或位置，按题目约定算。
  • 3σ 里的 σ 用总体标准差还是样本标准差，题目没说时两者都能接受，本章统一用总体标准差（除以 n）。

小结： 处理缺失值先看缺失比例以及缺失本身是否带有信息，有极端值时用中位数填补并加上缺失标记；3σ 法的均值和标准差容易被异常值拉大，IQR 法基于分位数，更加稳健。

4.3 分箱平滑、相关分析与规范化

数据里的噪声是随机误差，比如价格录入时多了几块钱。把相邻的值放进同一个"箱子"，再用箱内的代表值替换，就能抹掉小波动，这叫分箱平滑。合并多张表时还要判断两列是否重复表达同一件事（相关分析）；最后把单位不同的列变到同一尺度（规范化）。

分箱平滑

9 个排好序的价格分 3 箱，有两种分法：每箱放 3 个，叫等频分箱；每箱的取值区间一样宽，叫等宽分箱。分好后用箱均值、箱中位数或箱边界（离哪个边界近就变成哪个边界）替换箱内的值。

相关分析：皮尔逊系数与卡方检验

5 位客户的月收入 x = (3, 5, 6, 8, 8) 千元，月刷卡消费 y = (2, 3, 5, 6, 9) 千元，两列是不是"一起涨"？

平均 x̄ = 6，ȳ = 5。每人的 x、y 各减去平均，两个差相乘再相加：Σ(x−x̄)(y−ȳ) = 9+2+0+2+8 = 21，正数说明收入高于平均的人消费也多半高于平均。为了不受单位影响，再除以 √(Σ(x−x̄)²·Σ(y−ȳ)²) = √(18×30)，得 r = 21/√540 ≈ 0.904。这个 r 叫皮尔逊相关系数，取值在 [−1, 1]，|r| 越接近 1 线性关系越强。0.904 是强正相关；合并数据时若两列 r 接近 1，可以只留一列。

两列都是类别（如"有没有房贷""办没办信用卡"）时，用卡方检验（第 2 章 2.10）。200 位客户：有房贷的 100 人中 60 人办了信用卡，无房贷的 100 人中 30 人办了。若两者无关，每组都该有 90/200 = 45% 办卡，四格的期望人数是 45、55、45、55（期望 = 行合计 × 列合计 / 总数）。χ² = Σ(实际 − 期望)²/期望 = 225/45 + 225/55 + 225/45 + 225/55 ≈ 18.18，远大于 2×2 表在 5% 显著性水平下的门槛 3.841，判定"有房贷"和"办信用卡"相关。

规范化

5 个账户余额 200, 300, 400, 600, 1000 元，要和"交易笔数"放在一起算距离，得先变到同一尺度。三种常用办法：

方法公式账户余额 200, 300, 400, 600, 1000 的结果
最小-最大(x − min)/(max − min)0, 0.125, 0.25, 0.5, 1
z-score（标准化）(x − μ)/σ，即离平均值几个标准差μ=500，σ=282.84；200 → −1.061，600 → 0.354
小数定标x / 10^j，j 取让所有结果的绝对值都小于 1 的最小整数1000/10³ = 1 还不够小，j = 4：0.02, 0.03, 0.04, 0.06, 0.1

最小-最大规范化把训练集压到 [0, 1]。上线后来了一个余额 1200 的新客户，(1200−200)/800 = 1.25，跑出了区间。z-score 没有固定上下界，对这种情况更从容。规范化的参数（min、max、μ、σ）只能在训练集上算，再原样用到测试集和线上。[4]

要点：

  1. 等频分箱每箱个数相同，等宽分箱每箱区间宽度相同；等宽对极端值敏感。
  2. 数值属性看皮尔逊 r，类别属性看卡方 χ²；r 只刻画线性关系，相关也说明不了因果。
  3. 距离类算法（KNN、K-means、SVM）对尺度敏感，必须先规范化；树模型对单调变换不敏感。

多选 · 理解检查 3　某列取值为 −986, 120, 45。下列计算哪些正确？

A. 小数定标的 j = 3，−986 变为 −0.986

B. 最小-最大规范化后 120 约为 0.99

C. 最小-最大规范化后 45 约为 0.932

D. 小数定标的 j = 4

查看答案与每个选项的解析

A · 正确：最大绝对值 986，除以 10³ 后为 0.986 < 1，除以 10² 还大于 1。

B · 错误：120 正是最大值，规范化后为 1。

C · 正确：(45 + 986)/(120 + 986) = 1031/1106 ≈ 0.932。

D · 错误：j 取满足条件的最小整数，3 已经满足。

易错点

  • 边界平滑时"离哪个边界近"按差的绝对值比，两边一样近时本章取左边界。
  • 用全量数据算 min、max 再切训练集和测试集，会把测试集的信息泄漏给训练过程。

小结： 等频分箱每箱个数相同，等宽分箱每箱区间宽度相同；数值变量看皮尔逊 r，类别变量看卡方；min-max 落在 [0,1]，z-score 看离均值几个标准差，小数定标除以 10 的 j 次方。

4.4 类别编码与不平衡样本：独热编码与 SMOTE

大部分算法只吃数字，"职业 = 学生"这种类别值要先变成数字。另一个常见麻烦是样本极不平衡：1 万个贷款客户里只有 200 个违约，模型把所有人都判成"不违约"也有 98% 的准确率，却一个坏人都抓不到。

类别编码

3 位客户的职业是学生、职员、个体。把"职业"拆成 3 列 0/1，每人只在自己那一列填 1：

一个有 3 种取值的类别变量拆成 3 列，每行只有一个 1

这叫独热编码（One-Hot）。几种编码方式对比：

编码方式做法适用
独热编码（One-Hot）k 个类别拆成 k 列 0/1无序类别，类别数不多
序号编码按顺序编 1, 2, 3有序类别：学历 高中 < 本科 < 硕士
频数 / 目标编码用类别出现次数或该类的平均违约率代替取值很多的类别，如几百个城市
证据权重编码用该类坏人集中程度的一个分数代替（4.18）评分卡

无序类别用序号编码，会让模型以为"职员(3) > 学生(2) > 个体(1)"，凭空造出大小关系。目标编码要像交叉验证那样算：把训练集分成几份，每份客户的"该类违约率"只用其余几份来算。否则一个客户自己的标签会混进自己的特征，造成标签泄漏。

不平衡样本的三层处理

回到 1 万人里 200 个违约的例子，有三个层面的办法：

  • 数据层：让训练集里好坏人数接近：随机丢掉一部分好人（欠采样），复制坏人（过采样），或照着坏人的样子造新样本（下面的 SMOTE）。
  • 算法层：告诉模型"漏掉一个坏人比误判一个好人代价大"，例如给坏人样本 49 倍的权重（scikit-learn 的 class_weight 参数），或调低判"坏"的门槛。
  • 评估层：别看准确率，改看召回率（坏人里被抓到的比例，第 1 章），以及 4.10、4.20 的排序指标。

合成新样本：取一个坏人 x = (2, 3)，在离它最近的几个坏人里随机挑一个 x_nn = (4, 7)，在两点连线上随机取一点。两点相差 (2, 4)，取 0 到 1 之间的随机数 λ：λ = 0.5 时新点是 (3, 5)，λ = 0.25 时是 (2.5, 4)。公式 x_new = x + λ·(x_nn − x)。新点落在两个真实坏人之间，比简单复制更不容易过拟合。这种方法叫 SMOTE（合成少数类过采样）。[5]

两个少数类样本连线上合成新点：λ=0.5 得 (3,5)，λ=0.25 得 (2.5,4)；灰色是多数类

要点：

  1. 无序类别用独热编码，有序类别用序号编码，评分卡用证据权重编码（4.18）。
  2. 不平衡问题可以在数据层、算法层、评估层分别处理；评估时少看准确率。
  3. 采样只对训练集做，先划分数据集再采样。

4.5 数据仓库与 OLAP：星型模型和数据立方体

一笔交易"张三 3 月 5 日在徐汇网点买了 1 万元理财"。柜台系统记下它，是为了马上扣款、更新张三的余额；这类系统每秒要处理大量这样的短操作，只关心当前状态。管理层问的却是"过去三年各地区每季度卖了多少理财"：要把成千上万条这样的记录按地区、季度加起来，还要保留多年历史，合并多个系统的数据。

前一种为"一笔一笔快速记账"设计的系统叫 OLTP（联机事务处理）。它的表拆得很细，同一条信息只存一处，修改时不会前后矛盾，数据库设计里把这种拆法叫范式化。后一种分析在数据仓库上做：多个系统的数据统一口径后装进来，按"客户""贷款"这样的分析主题组织，保留多年历史，装入后基本只读。这四点（面向主题、集成、相对稳定、反映历史变化）就是常考的数据仓库四个特征。在数据仓库上做的汇总分析叫 OLAP（联机分析处理）。[1]

维度建模：星型、雪花、事实星座

回到张三那笔交易：1 万元是可以加总的数字，张三、3 月 5 日、徐汇网点、理财是看这笔交易的四个角度，叫维度。存数字（金额、笔数）和各维度编号的表叫事实表；存每个维度描述信息（客户年龄、网点所在城市）的表叫维度表。[6]

实线部分是星型模型；把网点维再拆出城市维、地区维（虚线），就成了雪花模型

  • 星型模型：一张事实表居中，维度表直接围绕，维表不再拆分。查询只需一层连接，速度快，维表有冗余。
  • 雪花模型：把维表再拆成多级（网点、城市、地区）。冗余少，查询要多做几次连接。
  • 事实星座模型（星系模型）：多张事实表共享维度表，例如"交易事实"和"还款事实"共用客户维和时间维。

4.6 关联规则与 Apriori：逐层连接与剪枝

手机银行想做交叉营销：已经买了理财的客户，推荐什么产品成功率最高？把每位客户买过的产品看成一个"购物篮"，从大量购物篮里找出"买了 X 的人往往也买 Y"，就是关联规则挖掘。

三个度量

100 位客户中，40 人买了理财 A，50 人办了信用卡 B，30 人两样都有。规则"买了 A 的人也会办 B"（写作 A→B）有多可信？

  • 30/100 = 30% 的客户同时有 A 和 B，这是规则的覆盖面，叫支持度；同时含 A、B 的人数 30 叫支持度计数。
  • 买 A 的 40 人里 30 人办了 B，30/40 = 75%，这是规则的可靠程度，叫置信度。
  • 全体客户本来就有 50% 办 B，买了 A 的人里变成 75%，75%/50% = 1.5，叫提升度。大于 1 表示 A 让 B 更常出现（正相关），等于 1 表示无关，小于 1 表示负相关。

每位客户持有的产品是一个集合，叫项集（每种产品是一"项"）。一般地，X、Y 是两个不重叠的项集，N 是交易总数：支持度 = 同时含 X 和 Y 的交易数 / N；置信度 = 同时含 X 和 Y 的交易数 / 含 X 的交易数，即 P(Y|X)；提升度 = 置信度 / P(Y)。同时满足最小支持度和最小置信度的规则叫强规则。

Apriori 性质与算法

找强规则分两步：先找出所有出现次数达标（支持度计数 ≥ 最小支持度计数）的项集，叫频繁项集；再从频繁项集生成规则。第一步最费时，Apriori 用一条性质大幅减少要数的项集：

Apriori 性质：频繁项集的所有非空子集也是频繁的。 反过来说，BC 只出现 2 次、不频繁，那么 ABC 出现的次数只会更少，一定也不频繁。[7]

于是算法一层一层来：先数单项，再拼两项组合计数，再拼三项组合……每一层从上一层的频繁项集出发，做两个动作：

  1. 连接：两个项集按字母排好后，如果只有最后一项不同，就合并成大一号的项集，例如 AB 和 AC 合成 ABC。
  2. 剪枝：检查新候选的每个小一号子集，只要有一个不频繁，就删掉这个候选。例如 ABC 的子集 BC 不频繁，ABC 直接删掉，不用扫描数据库。

剩下的候选再扫描一遍数据库计数，计数达标的就是这一层的频繁项集。教材把第 k 层的候选记作 C(k)，频繁项集记作 L(k)。

代码

变量表：transactions 是交易列表（每条是一个集合）；min_count 是最小支持度计数；C 是本层候选；L 是本层频繁项集；counts 是候选的计数；pruned 记录被剪掉的候选；trace 保存每一层的快照。

def apriori(transactions, min_count):
    """返回 (frequent, trace)。frequent: {项集元组: 支持度计数}；trace 记录每层 C_k、剪掉的候选、L_k。"""
    items = sorted({i for t in transactions for i in t})
    C = [(i,) for i in items]
    frequent, trace, k = {}, [], 1
    while C:
        counts = {c: support_count(c, transactions) for c in C}
        L = [c for c in C if counts[c] >= min_count]
        frequent.update({c: counts[c] for c in L})
        nextC, pruned = [], []
        Lset = set(L)
        for a, b in itertools.combinations(L, 2):          # 连接：前 k-1 项相同
            if a[:-1] == b[:-1]:
                cand = tuple(sorted(set(a) | set(b)))
                if all(s in Lset for s in itertools.combinations(cand, k)):   # 剪枝：所有 k 子集都频繁
                    nextC.append(cand)
                else:
                    pruned.append(cand)
        trace.append({'k': k, 'C': counts, 'L': L, 'pruned_next': pruned})
        C, k = nextC, k + 1
    return frequent, trace

代码里 k 是本层项集的大小，a[:-1] == b[:-1] 就是"只有最后一项不同"。用上面的 9 条交易运行 apriori(TX, 3)，第 2 层的 pruned_next 正好是 ABC、ABD、ACD。

要点：

  1. 支持度 = 同时含 X、Y 的比例，置信度 = P(Y|X)，提升度 = P(Y|X)/P(Y)。
  2. Apriori 性质：频繁项集的子集都频繁；非频繁项集的超集都不频繁。
  3. 每层两步：连接（只有最后一项不同才合并）、剪枝（有一个小一号子集不频繁就删），然后扫库计数。
  4. 置信度高的规则也可能提升度 < 1，后件本身很常见时尤其如此；提升度也说明不了因果。

4.7 FP-growth：一棵树压缩全部交易

Apriori 每生成一层候选就要扫一遍数据库，候选数也可能爆炸：如果有 10⁴ 个频繁 1 项集，就要产生超过 10⁷ 个候选 2 项集。FP-growth 只扫描数据库两遍，把所有交易压进一棵 FP 树（频繁模式树），然后在树上递归挖掘，整个过程不产生候选项集。[8]

建树：两遍扫描

第一遍扫描数出每个项的计数，删掉不频繁的项，按计数从大到小排成项头表：E:8、A:7、B:5、C:4、D:3（计数相同时按字母序）。

第二遍扫描把每条交易里的项按项头表顺序重排，再从根开始插入：路径已有的节点计数加 1，没有的就新建一个计数为 1 的子节点。9 条交易重排后依次是 EAD、EAC、EB、EAD、EAC、EABC、EABD、EB、ABC。项头表中每个项还用一条节点链串起树中所有同名节点，挖掘时顺着链找。

def cond_pattern_base(header, item):
    base = []
    for node in header[item]:
        path, p = [], node.parent
        while p.item is not None:
            path.append(p.item)
            p = p.parent
        if path:
            base.append((path[::-1], node.count))
    return base

写成一般形式（贝叶斯公式见第 2 章 2.2），x₁…xₙ 是申请人的各项特征，c 是类别：

P(c | x) ∝ P(c) × P(x₁|c) × P(x₂|c) × … × P(xₙ|c)

∝ 表示"正比于"：分母 P(x) 对所有类别相同，可以省略，最后归一化。拉普拉斯平滑写成：

  • 先验：P(c) = (|D_c| + 1) / (|D| + N)，|D_c| 是类别 c 的样本数（违约 4），|D| 是总样本数（10），N 是类别数（2）；
  • 条件概率：P(xᵢ|c) = (|D_c,xᵢ| + 1) / (|D_c| + Nᵢ)，|D_c,xᵢ| 是类别 c 中取这个值的样本数，Nᵢ 是第 i 个特征的取值个数（职业为 3）。

代码

变量表：rows 是训练数据，每行最后一列是类别；x 是待预测样本的特征元组；alpha 是平滑参数（1 即拉普拉斯平滑，0 即不平滑）；VALUES[f] 是第 f 个特征的全部可能取值；scores 存每个类别未归一化的后验。

def naive_bayes_predict(rows, x, alpha=1):
    """返回 {类别: 未归一化后验}。alpha=1 即拉普拉斯平滑。"""
    classes = sorted({r[-1] for r in rows})
    scores = {}
    for c in classes:
        rc = [r for r in rows if r[-1] == c]
        p = (len(rc) + alpha) / (len(rows) + alpha * len(classes))      # 先验也平滑
        for f, v in enumerate(x):
            k = len(VALUES[f])
            p *= (sum(1 for r in rc if r[f] == v) + alpha) / (len(rc) + alpha * k)
        scores[c] = p
    return scores

要点：

  1. 朴素贝叶斯的"朴素"指：给定类别后，特征之间条件独立。
  2. 优点：训练只需计数，速度快，小样本可用；缺点：独立假设常不成立，概率值偏极端。

横轴每 0.05 取一点：三处竖直上升（FPR = 0、0.25、0.5）画成了很陡的斜线；阶梯下方面积 = 13/16

面积法：阶梯下方由三个矩形组成，FPR 在 [0, 0.25) 时高 0.5，在 [0.25, 0.5) 时高 0.75，在 [0.5, 1] 时高 1：AUC = 0.25×0.5 + 0.25×0.75 + 0.5×1 = 0.8125 = 13/16。

配对法：AUC 等于"随机挑一个坏样本和一个好样本，坏样本分数更高"的概率。4 × 4 = 16 对中，0.95 和 0.85 各胜 4 对，0.70 胜 3 对（0.60、0.40、0.30），0.52 胜 2 对，合计 13 对，AUC = 13/16。分数相同的一对记 0.5。

def roc_points(scored):
    """按分数从高到低逐个降低阈值，返回 [(FPR, TPR)]，起点 (0,0)。"""
    P = sum(y for _, y in scored)
    N = len(scored) - P
    tp = fp = 0
    pts = [(0.0, 0.0)]
    for _, y in sorted(scored, reverse=True):
        if y:
            tp += 1
        else:
            fp += 1
        pts.append((fp / N, tp / P))
    return pts

def auc_pairs(scored):
    pos = [s for s, y in scored if y]
    neg = [s for s, y in scored if not y]
    win = sum(1 if p > n else 0.5 if p == n else 0 for p in pos for n in neg)
    return win / (len(pos) * len(neg))

要点：

  1. ROC 横轴 FPR、纵轴 TPR；对角线是随机猜测（AUC = 0.5），左上角 (0, 1) 是完美分类。
  2. AUC 的含义：随机取一正一负，正样本得分高于负样本的概率。
  3. AUC 只看排序，与阈值无关；好坏人数比例变了，AUC 本身不变。但坏人极少时，AUC 可能很高而误报仍多，要同时看 PR 曲线（1.9）。

A · 正确：6 对中坏样本胜出：0.9 胜 2 对，0.6 胜 0.3，0.4 胜 0.3，共 4 对。

B · 错误：0.6 < 0.7、0.4 < 0.7，这两对坏样本输了。

C · 错误：0.5 对应随机排序，这里胜出的对数超过一半。

D · 错误：分母是正负样本对数 3 × 2 = 6，不是样本总数。

易错点

  • 有多个样本分数相同时，要一次性越过它们，走一段斜线（对应配对法里的 0.5）。
  • AUC 高说明排序好，概率值未必准确；需要准确概率时还要看校准。

小结： 画 ROC 曲线时，阈值从高到低扫描，遇到正样本向上走，遇到负样本向右走；AUC 等于随机取一个坏样本、其得分高于随机取的一个好样本的概率。
