10.4 对撞双指针：每一步排除一整行或一整列 必读

对撞双指针适用于在有序数组（或排序后的数组）中寻找满足条件的一对数，以及答案由左右两端共同决定的问题，例如容器和接雨水。典型题有 167 题有序数组的两数之和、11 题盛最多水的容器、15 题三数之和、16 题最接近的三数之和、42 题接雨水。

下标 l 从左端、r 从右端出发，向中间移动。暴力解法要检查所有下标对 (i, j)（i < j）。把它们排成一张表：第 i 行第 j 列的格子代表 a[i] 与 a[j] 这一对。对撞双指针每比较一次，就能断定下面两件事之一：

  • l 与它右边直到 r 的每个数配对都不可能更优：第 l 行剩下的格子一次全部排除，l 加 1。
  • r 与它左边直到 l 的每个数配对都不可能更优：第 r 列剩下的格子一次全部排除，r 减 1。

每一步排除一整行或一整列，所以最多 n − 1 步就处理完整张表。它保持的不变式是：

若答案存在，一定在 [l, r] 之内；每次移动只舍弃已经证明不可能更优的那一端。

以有序数组的两数之和为例：若 a[l] + a[r] < target，那么 a[l] 与区间内最大的 a[r] 相加仍然不够，与其他更小的数相加更不够，所以 a[l] 不可能出现在答案中，令 l 加 1。同理，和大于 target 时令 r 减 1。

例如 a = [1, 3, 5, 8, 11]，target = 13：

  1. 1 + 11 = 12 < 13，1 和最大的 11 配都不够，1 出局，l 移到 3。
  2. 3 + 11 = 14 > 13，11 和剩下最小的 3 配都超了，11 出局，r 移到 8。
  3. 3 + 8 = 11 < 13，3 出局，l 移到 5。
  4. 5 + 8 = 13，找到答案，返回下标 [2, 3]。
// 有序数组的两数之和（对撞双指针）：参数 a 是升序数组，target 是目标和。
// 返回和为 target 的两个下标 {l, r}（l < r）；不存在时返回空数组。
vector<int> twoSumSorted(const vector<int>& a, int target) {   // a 升序
    int l = 0, r = (int)a.size() - 1;  // l = 左指针（left），r = 右指针（right）；答案只可能在 [l, r] 里
    while (l < r) {               // 两指针相遇：没有两个不同的数了
        int s = a[l] + a[r];      // s = 当前这一对的和
        if (s == target) return {l, r};  // 正好凑出：返回两个下标
        if (s < target) ++l;      // 和太小：a[l] 配最大的 a[r] 都不够，a[l] 出局
        else --r;                 // 和太大：a[r] 配最小的 a[l] 都超了，a[r] 出局
    }
    return {};                    // 没有这样的一对
}
# 有序数组的两数之和（对撞双指针）：参数 a 是升序列表，target 是目标和。
# 返回和为 target 的两个下标 [l, r]（l < r）；不存在时返回空列表。
def two_sum_sorted(a, target):        # a 升序
    l, r = 0, len(a) - 1              # l = 左指针（left），r = 右指针（right）；答案只可能在 [l, r] 里
    while l < r:                      # 两指针相遇：没有两个不同的数了
        s = a[l] + a[r]               # s = 当前这一对的和
        if s == target:               # 正好凑出
            return [l, r]             # 返回两个下标
        if s < target:
            l += 1                    # 和太小：a[l] 配最大的 a[r] 都不够，a[l] 出局
        else:
            r -= 1                    # 和太大：a[r] 配最小的 a[l] 都超了，a[r] 出局
    return []                         # 没有这样的一对

l, r尚未排除的区间的两端，区间外的元素都已证明不在答案中
s当前两端之和

例题 11 盛最多水的容器

在 x 轴上的位置 0、1、……、n−1 各立着一条竖线，第 i 条的高度是 h[i]。任选两条竖线，它们和 x 轴围成一个容器，能盛的水量等于两条线之间的距离（下标之差）乘以较矮那条线的高度。求所有选法中盛水量的最大值；不足两条线时返回 0。[1]

样例 1：h = [1, 8, 6, 2, 5, 4, 8, 3, 7]，答案 49。选下标 1（高 8）和下标 8（高 7）的两条线，距离 7，较矮的高 7，盛水 7 × 7 = 49，其他选法都不超过它。

样例 2：h = [1, 1]，答案 1。只有一种选法，距离 1，高 1。

要求时间 O(n)。代码中 l、r 是当前选取的左、右两条线的下标，开始时是第一条和最后一条；best 是已检查过的组合中的最大盛水量。每一步做两件事：

  1. 计算当前组合的盛水量 (r − l) × min(h[l], h[r])，更新 best。
  2. 把较矮的一边向内移动一格：h[l] < h[r] 时 l 加 1，否则 r 减 1。

为什么可以丢掉较矮的那条线：设 h[l] < h[r]。l 与 l、r 之间的任何一条线配对，距离都比 r − l 小，高度又不超过 h[l]，盛水量不会超过当前组合，而当前组合已经算进了 best。例如样例 1 开始时 l = 0（高 1）、r = 8（高 7），盛水 8 × 1 = 8；第 0 条线和其他任何一条线配对，高度最多是 1，距离不到 8，盛水都不超过 8，所以第 0 条线可以排除。

因此始终成立：所有已被排除的组合，盛水量都不超过 best。每步区间缩小 1，l == r 时所有组合都已检查或排除。

// 盛最多水的容器（LeetCode 11）：参数 h 是每条竖线的高度，h[i] = 第 i 条线的高。
// 返回两条线与 x 轴围成的容器的最大盛水量（宽 × 较矮线的高）；少于两条线时返回 0。
int maxArea(const vector<int>& h) {
    // l、r = 当前选的左、右两条线的下标；best = 目前最大面积
    int l = 0, r = (int)h.size() - 1, best = 0;  // 答案只可能在 [l, r] 里；best 是目前最大面积
    while (l < r) {               // 两板相遇就停
        best = max(best, (r - l) * min(h[l], h[r]));  // 面积 = 宽 × 矮板的高
        if (h[l] < h[r]) ++l;     // 左边矮：左板配任何更近的右板都不会更大，左板出局
        else --r;                 // 右边不高于左边：右板出局，理由对称
    }
    return best;                  // 最大面积
}
# 盛最多水的容器（LeetCode 11）：参数 h 是每条竖线的高度，h[i] = 第 i 条线的高。
# 返回两条线与 x 轴围成的容器的最大盛水量（宽 × 较矮线的高）；少于两条线时返回 0。
def max_area(h):
    # l、r = 当前选的左、右两条线的下标；best = 目前最大面积
    l, r, best = 0, len(h) - 1, 0     # 答案只可能在 [l, r] 里；best 是目前最大面积
    while l < r:                      # 两板相遇就停
        best = max(best, (r - l) * min(h[l], h[r]))  # 面积 = 宽 × 矮板的高
        if h[l] < h[r]:               # 左边矮
            l += 1                    # 左边矮：左板配任何更近的右板都不会更大，左板出局
        else:
            r -= 1                    # 右边不高于左边：右板出局，理由对称
    return best                       # 最大面积

时间 O(n)，空间 O(1)。两条线一样高时移动哪一边都可以：此时较矮的高度已经确定，任何一边向内移动，距离只会变小，盛水量不会超过当前值。

例题 15 三数之和

给一个整数数组 nums，从三个不同的位置各取一个数，组成一个"三元组"。找出所有三个数之和为 0 的三元组。如果两个三元组用到的三个值相同（不管顺序），就算重复，只输出一次。三元组之间、三元组内部的顺序都不限；一个都没有时返回空列表。[2]

样例 1：nums = [-1, 0, 1, 2, -1, -4]，返回 [[-1, -1, 2], [-1, 0, 1]]。两个 −1 加 2 得 0；−1、0、1 也得 0，数组里有两个 −1，用哪一个组出的都是同一个三元组，只算一次。

样例 2：nums = [0, 0, 0, 0]，返回 [[0, 0, 0]]。任取三个 0 和都是 0，但值都相同，只输出一次。

样例 3：nums = [0, 1, 1]，返回 []。只能取 0、1、1，和是 2，不是 0。

先排序，然后固定三元组中最小的数 nums[i]，在它右侧用对撞双指针寻找和为 −nums[i] 的两个数。

要求时间 O(n²)。代码中的变量：

  • i：三元组中最小数的下标。
  • l、r：在 i 右边相向移动的两个指针，开始时 l = i + 1、r = n − 1。
  • ans：保存找到的三元组。

固定 i 后，三数之和小于 0 时令 l 加 1，大于 0 时令 r 减 1，等于 0 时记录这个三元组。

为避免重复，去重分两层进行（C++ 代码注释把后一层的左右两半分别标为第 2、3 层）：

  1. 若 nums[i] 与上一个 nums[i−1] 相同，以它为最小数的三元组已经全部找过，跳过这一轮。例如排序后的 [-4, -1, -1, 0, 1, 2] 中，i = 2 的 −1 与 i = 1 的 −1 相同，整轮跳过。
  2. 找到一个答案后，l 和 r 各自跳过与当前值相同的元素。

当 nums[i] > 0 时，三个数都是正数，和必大于 0，可以提前结束。

// 返回所有和为 0 的不重复三元组，每个三元组内部升序；没有时返回空。
vector<vector<int>> threeSum(vector<int> nums) {     // 按值传入：排序不影响调用者
    sort(nums.begin(), nums.end());                          // 升序：才能对撞，相同值也挨在一起便于去重
    int n = nums.size();                                     // n = 元素个数

    for (int i = 0; i < n - 2; ++i) {                        // i = 三元组最小数（首项）的下标，后面至少留两个数
        if (nums[i] > 0) break;                              // 最小的都大于 0，凑不出 0
        if (i > 0 && nums[i] == nums[i - 1]) continue;       // 第 1 层去重：同一个首项只做一次
        // l = 左指针，r = 右指针；在 i 右边相向移动
        int l = i + 1, r = n - 1;                            // 在 i 右边的 [l, r] 里找两数之和为 -nums[i]

            if (s < 0) ++l;                                  // 和太小：左指针右移换个大点的数
            else if (s > 0) --r;                             // 和太大：右指针左移换个小点的数
            else {                                           // 正好为 0
                ans.push_back({nums[i], nums[l], nums[r]});  // 记下这个三元组
                while (l < r && nums[l] == nums[l + 1]) ++l;  // 第 2 层去重：跳过相同的左值
                while (l < r && nums[r] == nums[r - 1]) --r;  // 第 3 层去重：跳过相同的右值
                ++l; --r;                                    // 两边都换成新值，继续找
            }
        }
    }
    return ans;                                              // 全部不重复的三元组
}

# 返回所有和为 0 的不重复三元组，每个三元组内部升序；没有时返回空。
def three_sum(nums):
    nums = sorted(nums)               # sorted 返回新列表，不影响调用者（对应 C++ 的按值传入）；升序才能对撞和去重
    n, ans = len(nums), []            # n = 元素个数；ans：所有和为 0 的三元组
    for i in range(n - 2):            # i = 三元组最小数（首项）的下标，后面至少留两个数
        if nums[i] > 0:               # 最小的都大于 0，凑不出 0
            break
        if i > 0 and nums[i] == nums[i - 1]:  # 和前一个首项相同
            continue                  # 首项去重
        # l = 左指针，r = 右指针；在 i 右边相向移动
        l, r = i + 1, n - 1           # 在 i 右边的 [l, r] 里找两数之和为 -nums[i]
        while l < r:                  # 两指针相遇就停
            s = nums[i] + nums[l] + nums[r]  # s = 三数之和
            if s < 0:                 # 和太小
                l += 1                # 左指针右移换个大点的数
            elif s > 0:               # 和太大
                r -= 1                # 右指针左移换个小点的数
            else:                     # 正好为 0
                ans.append([nums[i], nums[l], nums[r]])  # 记下这个三元组
                while l < r and nums[l] == nums[l + 1]:  # 下一个左值和当前相同
                    l += 1            # 左值去重
                while l < r and nums[r] == nums[r - 1]:  # 下一个右值和当前相同
                    r -= 1            # 右值去重
                l += 1                # 两边都换成新值，继续找
                r -= 1
    return ans                        # 全部不重复的三元组

变式 16 最接近的三数之和

给一个整数数组 nums（至少 3 个数）和一个目标值 target。从三个不同的位置各取一个数相加，在所有取法中找出和与 target 最接近（两者之差的绝对值最小）的那个和，返回这个和。题目保证答案唯一。[3]

样例 1：nums = [-1, 2, 1, -4]，target = 1，答案 2。所有取法的和是 −1 + 2 + 1 = 2、−1 + 2 − 4 = −3、−1 + 1 − 4 = −4、2 + 1 − 4 = −1，与 1 相差 1、4、5、2，最接近的是 2。

样例 2：nums = [0, 0, 0]，target = 1，答案 0。只有一种取法，和是 0。

框架与 15 题相同，只是把"和等于 0"换成比较 |s − target|：每一步先用当前的和更新答案，再根据 s 与 target 的大小关系移动指针，二者相等时直接返回。

// 最接近的三数之和（LeetCode 16）：参数 nums 是整数数组（n >= 3，按值传入，排序的是副本），target 是目标值。
// 返回与 target 差的绝对值最小的三数之和（题目保证唯一）。
int threeSumClosest(vector<int> nums, int target) {   // 题设 n >= 3
    sort(nums.begin(), nums.end());                   // 升序：才能对撞
    int n = nums.size(), best = nums[0] + nums[1] + nums[2];  // n = 元素个数；best：目前最接近的和，先取前三个
    for (int i = 0; i < n - 2; ++i) {                 // i = 首项下标；枚举首项 i
        int l = i + 1, r = n - 1;                     // l、r = 左右指针；在 i 右边的 [l, r] 里对撞
        while (l < r) {                               // 两指针相遇就停
            int s = nums[i] + nums[l] + nums[r];      // s = 当前三数之和
            if (abs(s - target) < abs(best - target)) best = s;   // 先更新答案
            if (s < target) ++l;                      // 和偏小：换个大点的左值
            else if (s > target) --r;                 // 和偏大：换个小点的右值
            else return s;                                      // 差为 0，已经最近
        }
    }
    return best;                                      // 最接近 target 的三数之和
}

例题 42 接雨水（双指针版）

一排宽度都是 1 的柱子紧挨着立在地上，h[i] 是第 i 根柱子的高度（可以是 0，表示那里没有柱子）。下雨以后，矮处被两边更高的柱子挡住，就会积水。问一共能积多少格水，一格是宽 1、高 1 的一块。[4]

样例 1：h = [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]，答案 6。积水的位置是：下标 2 积 1 格，下标 4 积 1 格，下标 5 积 2 格，下标 6 积 1 格，下标 9 积 1 格，合计 6 格；最左边和最右边没有挡板，存不住水。

样例 2：h = [3, 3, 3]，答案 0。所有柱子一样高，没有凹下去的地方。

第 i 列上方的水面高度等于它左边最高柱子与右边最高柱子中较低的那个，这一列的水量等于水面高度减去 h[i]。

高度 [4,2,0,3,2,5]：深色是墙，"水"是积水；每列水量 [0, 2, 4, 1, 2, 0]，共 9

要求时间 O(n)、空间 O(1)，因此不能预先算出每一列左右两侧的最大值。代码用两个指针从两端向中间收，变量含义如下：

  • l、r：左右两个指针。从 l 到 r 的列还没结算，l 左边和 r 右边的列都已结算。
  • leftMax：左侧已扫描部分的最高值。结算第 l 列时先把 h[l] 也算进去。
  • rightMax：右侧已扫描部分的最高值，同理。
  • water：已结算各列的水量之和。

每一步比较两端：若 h[l] < h[r]，结算第 l 列，它的水量是 leftMax − h[l]，然后令 l 加 1；否则对称地结算第 r 列，水量是 rightMax − h[r]，然后令 r 减 1。

为什么第 l 列的水面高度恰好是 leftMax：每次移动的都是较矮（或等高）的一端，所以较高的那一端始终不低于所有已扫描过的柱子。h[l] < h[r] 时较高的是 h[r]，它不低于 leftMax；第 l 列右边最高的柱子至少有 h[r] 那么高，于是"左边最高与右边最高中较低的那个"就是 leftMax。例如上图的高度 [4, 2, 0, 3, 2, 5]，结算第 1 列时 leftMax = 4，h[r] = 5，水面高 4，存水 4 − 2 = 2。

l == r 时剩下的一列不低于其他所有柱子，是全局最高的柱子之一，上方不存水。

// 返回下雨后总共能接多少格水；少于 3 根柱子时为 0。
int trap(const vector<int>& h) {
    int l = 0, r = (int)h.size() - 1;           // l、r = 左右指针，两端向中间收；[l, r] 是还没结算的格子
    // leftMax = h[0..l-1] 的最高，rightMax = h[r+1..n-1] 的最高，water = 已结算的总水量
    int leftMax = 0, rightMax = 0, water = 0;   // h[0..l-1] 的最高、h[r+1..n-1] 的最高
    while (l < r) {                             // 相遇时剩下的那格是最高墙，不存水
        if (h[l] < h[r]) {                      // 右边有更高的墙：l 格水位只由 leftMax 决定
            leftMax = max(leftMax, h[l]);       // 先把 l 格算进左侧最高
            water += leftMax - h[l];            // l 格水量 = 左侧最高 - 自身高度（自己最高时为 0）
            ++l;                                // l 格结算完毕
        } else {                                // 左边有不矮的墙：r 格水位只由 rightMax 决定
            rightMax = max(rightMax, h[r]);     // 先把 r 格算进右侧最高
            water += rightMax - h[r];           // r 格水量 = 右侧最高 - 自身高度
            --r;                                // r 格结算完毕
        }
    }
    return water;                               // 总水量
}

    sort(a.begin(), a.end());                           // 升序：才能对撞
    long long count = 0;                                // count = 满足条件的对数，最多约 n²/2

    while (l < r) {                                     // 两指针相遇就停

    }
    return count;                                       // 能力和低于 T 的组合数
}

练习 10.4-3【综合】最少几条皮划艇 选做

题面：有 n 名游客，w[i] 是第 i 人的体重（n ≤ 10⁵，1 ≤ w[i] ≤ L）。每条皮划艇最多坐 2 人，而且艇上的人体重之和不能超过 L。每个人都要上艇，问最少需要几条艇。（相近题型：LeetCode 881）

样例 1：w = [3, 2, 2, 1]，L = 3，答案 3。体重 2、2、3 这三人中任意两人的体重和都超过 3，不能合坐；只有体重 1 的人能和一个体重 2 的人合坐（和 3）。所以最多凑出一对，4 个人至少要 3 条艇。

样例 2：w = [3, 5, 3, 4]，L = 5，答案 4。任意两人的体重和至少是 3 + 3 = 6，都超过 5，只能每人一条。

样例 3：w = [1, 2]，L = 3，答案 1。两人体重和 3，正好能合坐一条。

提示

排序后对撞。最重的人 a[r] 总要上一条艇：最轻的 a[l] 能和他同船就一起走（l 前进），否则他独占一条；两种情况下 r 都出局、艇数 +1。为什么"和最轻的配"不会更差：如果最优方案里 a[r] 和另一个人 x 同船，把 x 换成更轻的 a[l] 依然合法，艇数不变。边界：l == r 时只剩一个人，也要一条艇，所以循环条件是 l <= r，而不是例题里的 l < r。

易错点和变式。

  • 对撞指针依赖"移动一端就能排除一整行"的单调性；无序数组找两数和要先排序（只要值）或用哈希（要下标，见 10.2）。
  • 三数之和 nums[i] + nums[l] + nums[r] 在值域到 10⁹ 时会溢出 int，用 long long；LeetCode 15 的值域是 ±10⁵，int 够用。
  • 对撞指针和快慢指针容易混淆：对撞是两端相向走，快慢是同向不同速（10.5）。

小结： 对撞指针每一步都排除一端的一个元素：盛水容器移动较矮的一侧，接雨水先结算较矮的一侧，三数之和先排序再逐层去重。

10.5 快慢指针：在链表上测量距离 必读

单链表只能从头向后逐个访问，不能按下标直接定位。判断是否有环、找环的入口、找中点、找倒数第 k 个节点这类问题，如果要求 O(1) 额外空间（不能把节点存进哈希表），就用快慢指针。典型题有 141 题环形链表、142 题环形链表 II、876 题链表的中间结点、19 题删除链表的倒数第 N 个结点（见 10.11）以及 287 题寻找重复数。

两个指针都从头节点出发，fast 每次走两步，slow 每次走一步，因此：

任意时刻，fast 走过的步数是 slow 的 2 倍。

若链表无环，fast 会先走到末尾。若链表有环，两个指针最终都会进入环中；进入环以后，fast 每走一次就比 slow 多走一步，两者在环上的距离每次缩小 1，所以 fast 一定会追上 slow。

环的入口。 先看下图的例子：链表 1→2→…→8，8 的 next 又指回 4，所以 4 是环的入口。从头节点 1 走到入口 4 要 3 步，环上有 4、5、6、7、8 五个节点。快慢指针走 5 轮后在节点 6 相遇：slow 走了 5 步，fast 走了 10 步，比 slow 正好多绕了一圈。相遇点 6 在入口之后 2 步；从 6 再往前走 3 步（经过 7、8）又回到入口 4，这个 3 恰好等于从头节点到入口的步数。

一般地，用三个字母记这三段长度：

  • a 是从头节点走到环入口的步数。
  • c 是环长，即环上的节点个数。
  • b 是相遇点在入口之后的步数。

相遇时 slow 走了 a + b 步。fast 比 slow 多绕了若干整圈，设为 k 圈，共走了 a + b + kc 步。fast 的步数是 slow 的 2 倍，所以 2(a + b) = a + b + kc。两边同时减去 a + b，得到 a + b = kc，移项得 a = kc − b = (k − 1)c + (c − b)。这个式子说明：一个指针从头节点出发走 a 步到达入口；另一个指针从相遇点出发走同样的 a 步，先绕 k − 1 整圈回到相遇点，再走 c − b 步，也恰好到达入口。所以让两个指针分别从头节点和相遇点以相同速度出发，它们第一次相遇的位置就是环的入口。

链 1→…→8，8 又指回 4：a=3，环长 c=5；快慢指针第一次在 6 相遇，b=2，c−b=3=a

图中 a = 3，c = 5，b = 2，c − b = 3，正好等于 a（此时 k = 1）。

练习 10.5-1【基础】环形跑道有几个打卡点 必做

题面：一条跑道上的打卡点连成单链表，可能有环（有环的含义同例题 141）。返回环上有几个节点；无环返回 0。要求 O(1) 额外空间。

样例 1：链表 1→2→3→4→5，尾节点 5 的 next 指回节点 3，答案 3。走到 5 以后回到 3，再经过 4、5 又回到 3，环上是 3、4、5 三个节点。

样例 2：链表 1→2→3，尾节点的 next 为空，答案 0。走到 3 之后就是空指针，没有环。

样例 3：只有一个节点，它的 next 指向自己，答案 1。环上只有它一个节点。

提示

前半段和 141 一模一样：快慢指针相遇就说明有环。相遇点一定在环上，此后让一个指针从相遇点出发，一边走一边数，回到相遇点时数到的就是环长。和 142 相比，第二阶段从"一个回到头、同速再走"换成"原地绕一圈计数"。

参考答案
// 环上有几个节点：参数 head 是链表头（可为 nullptr，可能有环），不修改链表。
// 返回环上的节点个数；无环返回 0。ListNode：val = 值，next = 下一个节点。
int cycleLength(ListNode* head) {
    ListNode *slow = head, *fast = head;     // slow = 慢指针，fast = 快指针；都从头出发：slow 一次一步，fast 一次两步
    while (fast && fast->next) {             // fast 还能走两步才继续
        slow = slow->next;                   // 慢指针走一步
        fast = fast->next->next;             // 快指针走两步
        if (slow == fast) {                  // 相遇点一定在环上
            int len = 1;                     // len = 已数到的环上节点数；先算上 slow 自己这一个
            for (ListNode* p = slow->next; p != slow; p = p->next) ++len;   // p 从 slow 的下一个出发，绕一圈数节点
            return len;                      // 环长
        }
    }
    return 0;                                // fast 走到了尽头：无环
}
# 环上有几个节点：参数 head 是链表头（可为 None，可能有环），不修改链表。
# 返回环上的节点个数；无环返回 0。ListNode：val = 值，next = 下一个节点。
def cycle_length(head):
    slow = fast = head                # slow = 慢指针，fast = 快指针；都从头出发：slow 一次一步，fast 一次两步
    while fast and fast.next:         # fast 还能走两步才继续
        slow = slow.next              # 慢指针走一步
        fast = fast.next.next         # 快指针走两步
        if slow is fast:              # 相遇点一定在环上
            length = 1                # length = 已数到的环上节点数；先算上 slow 自己这一个
            p = slow.next             # 从 slow 的下一个开始数
            while p is not slow:      # 绕一圈数节点
                length += 1
                p = p.next
            return length             # 环长
    return 0                          # fast 走到了尽头：无环

练习 10.5-2【变形】密码锁数字会不会变成 1 选做

题面：密码锁上显示一个正整数 x。每操作一次，就把当前的数换成"它每一位数字的平方之和"，例如 82 换成 8² + 2² = 68。一直这样操作下去，问显示的数会不会在某一时刻变成 1；会就返回 true，不会就返回 false。1 ≤ x ≤ 2³¹−1，要求 O(1) 额外空间，也就是不能用集合记录见过的数。（相近题型：LeetCode 202）

样例 1：x = 19，返回 true。19 换成 1 + 81 = 82，82 换成 64 + 4 = 68，68 换成 36 + 64 = 100，100 换成 1 + 0 + 0 = 1。

样例 2：x = 2，返回 false。2 依次变成 4、16、37、58、89、145、42、20，然后又回到 4，此后这几个数反复出现，永远不会出现 1。

样例 3：x = 1，返回 true。一开始就是 1。

提示

把"数 → 下一个数"看成链表的 next，这是一条隐式链表。序列只有两种结局：到达 1（1 的下一个还是 1，自环），或者进入一个不含 1 的环。快慢指针照样适用：slow = f(slow)，fast = f(f(fast))，相遇后看相遇点是不是 1。和链表版相比改了两处：next 改成函数计算；永远不会走到空，所以用 do-while 一直走到相遇。

参考答案
// 下一个数：参数 x 是正整数。返回 x 各位数字的平方和（如 19 -> 1 + 81 = 82）。
int digitSquareSum(int x) {
    int s = 0;                                           // s = 平方和的累加值
    while (x > 0) { int d = x % 10; s += d * d; x /= 10; }  // d = 当前个位数字；累加 d²，再去掉个位
    return s;                                            // x 的下一个数
}
// 快乐数（LeetCode 202）：参数 x 是正整数（1..2^31-1）。反复把 x 换成各位数字平方和，
// 返回最终会不会变成 1。隐式链表：x 的 next 是 digitSquareSum(x)
bool reachesOne(int x) {
    int slow = x, fast = x;                              // slow = 慢指针（每轮一步），fast = 快指针（每轮两步）；都从 x 出发
    do {                                                 // 永远不会走到空，先走再判断
        slow = digitSquareSum(slow);                     // 一步
        fast = digitSquareSum(digitSquareSum(fast));     // 两步
    } while (slow != fast);                              // 一定会相遇：要么都停在 1，要么在环里追上
    return slow == 1;                                    // 相遇点是 1 就说明会变成 1（1 自环）
}
# 下一个数：参数 x 是正整数。返回 x 各位数字的平方和（如 19 -> 1 + 81 = 82）。
def digit_square_sum(x):
    s = 0                             # s = 平方和的累加值
    while x > 0:                      # 还有数字没取完
        x, d = divmod(x, 10)          # 一次得到商和余数：d = 当前个位数字，x 去掉个位
        s += d * d                    # 累加个位的平方
    return s                          # x 的下一个数

# 快乐数（LeetCode 202）：参数 x 是正整数（1..2^31-1）。反复把 x 换成各位数字平方和，
# 返回最终会不会变成 1。隐式链表：x 的 next 是 digit_square_sum(x)
def reaches_one(x):
    slow = fast = x                   # slow = 慢指针（每轮一步），fast = 快指针（每轮两步）；都从 x 出发
    while True:                       # Python 没有 do-while，用 while True + break
        slow = digit_square_sum(slow)                     # 一步
        fast = digit_square_sum(digit_square_sum(fast))   # 两步
        if slow == fast:              # 一定会相遇：要么都停在 1，要么在环里追上
            break
    return slow == 1                  # 相遇点是 1 就说明会变成 1（1 自环）

练习 10.5-3【综合】传送门数组的入环房间 选做

题面：有 n 个房间，编号 0 到 n−1（n ≤ 10⁵）。每个房间里有一扇单向传送门，从房间 i 进门会被送到房间 to[i]（0 ≤ to[i] < n，可以送回自己）。从房间 s 出发，一次又一次地穿过传送门。因为每个房间只有一个出口，房间又是有限的，迟早会回到之前到过的房间，从此在几个房间之间不停地兜圈子，这一圈房间叫作"环"。返回两个数：第一个到达的环上房间的编号，以及环上有几个房间。要求 O(1) 额外空间。（相近题型：LeetCode 287、142）

样例 1：to = [1, 2, 3, 4, 2]，s = 0，返回 {2, 3}。路线是房间 0、1、2、3、4，然后又回到 2，此后一直在 2、3、4 之间兜圈；第一个到达的环上房间是 2，环上有 3 个房间。

样例 2：to = [0]，s = 0，返回 {0, 1}。房间 0 的门送回它自己，出发点就在环上，环只有 1 个房间。

样例 3：to = [1, 1, 0]，s = 2，返回 {1, 1}。从 2 被送到 1，房间 1 的门又送回 1，此后一直留在 1；环上只有房间 1。

提示

下标当节点、to[i] 当 next，就是一条"必然有环"的链表：每个房间恰好一个出口，走 n 步之内必然重复。三步：①slow 走一步、fast 走两步直到相遇；②一个回到 s，一个留在相遇点，同速走，相遇处就是入口（a = (k−1)c + (c−b)）；③从入口绕一圈数环长（练习 10.5-1）。边界：起点 s 本身在环上时 a = 0，第二阶段一步不走就相遇；自环的环长是 1。

参考答案
// 传送门数组的入环房间：参数 to 是传送门数组，to[i] = 从房间 i 传送到的房间（0 <= to[i] < n）；s 是起点房间。
// 返回 {第一个进入的环上房间, 环长}。把 to 看成隐式链表：房间 i 的 next 是 to[i]。
pair<int, int> portalCycle(const vector<int>& to, int s) {   // 返回 {入环房间, 环长}
    int slow = s, fast = s;                                  // slow = 慢指针所在房间，fast = 快指针所在房间；都从起点 s 出发
    do {                                                     // 先走再判断：起点处两者本来就相等
        slow = to[slow];                                     // 慢指针走一步
        fast = to[to[fast]];                                 // 快指针走两步
    } while (slow != fast);                  // 每个房间都有出口，fast 永远不会"走到空"
    int p = s;                                               // p 回到起点，slow 留在相遇点
    while (p != slow) { p = to[p]; slow = to[slow]; }   // 同速再走 a 步，在入口相遇
    int len = 1;                                             // len = 环长计数；先算上入口自己
    for (int q = to[p]; q != p; q = to[q]) ++len;        // q 从入口的下一个房间出发，绕一圈
    return {p, len};                                         // 入环房间和环长
}
# 传送门数组的入环房间：参数 to 是传送门列表，to[i] = 从房间 i 传送到的房间（0 <= to[i] < n）；s 是起点房间。
# 返回 (第一个进入的环上房间, 环长)。把 to 看成隐式链表：房间 i 的 next 是 to[i]。
def portal_cycle(to, s):              # 返回 (入环房间, 环长)
    slow = fast = s                   # slow = 慢指针所在房间，fast = 快指针所在房间；都从起点 s 出发
    while True:                       # 先走再判断：起点处两者本来就相等
        slow = to[slow]               # 慢指针走一步
        fast = to[to[fast]]           # 快指针走两步
        if slow == fast:              # 每个房间都有出口，fast 永远不会"走到空"
            break
    p = s                             # p 回到起点，slow 留在相遇点
    while p != slow:                  # 同速再走 a 步，在入口相遇
        p = to[p]                     # 两者各走一步
        slow = to[slow]
    length = 1                        # length = 环长计数；先算上入口自己
    q = to[p]                         # q = 正在数的房间；从入口的下一个房间开始数
    while q != p:                     # 从入口绕一圈
        length += 1
        q = to[q]
    return (p, length)                # 入环房间和环长

易错点和变式。

  • 循环条件写 fast && fast->next，两次 ->next 之前都确认非空；顺序写反会空指针崩溃。
  • 判断相遇要比较地址 slow == fast，值相同的不同节点不算相遇。
  • 287 寻找重复数把"下标 → 值"看成链表的 next，用同样的两阶段找入口，入口就是重复数。

小结： fast 每次走两步、slow 每次走一步，两者相遇说明有环；相遇后让一个指针回到头节点，两者同速前进，再次相遇的位置就是环的入口（a = (k−1)c + c−b）。
