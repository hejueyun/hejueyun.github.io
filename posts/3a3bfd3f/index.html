13.1 计算机由哪五部分组成：冯·诺依曼结构

早期计算机靠插线编程，换一个任务就要重新接线。冯·诺依曼提出把程序也当作数据存进存储器，让机器自动逐条取出执行，这就是存储程序思想。今天的电脑和手机都按它工作。

冯·诺依曼结构由五个部件组成：运算器、控制器、存储器、输入设备、输出设备，其中运算器和控制器合称 CPU。它的特点笔试常原样考：

  1. 指令和数据都用二进制表示，存放在同一个存储器中，按地址访问；
  2. 指令由操作码和地址码组成，顺序存放；控制器按程序计数器 PC 逐条取出执行，执行完 PC 自动指向下一条；
  3. 早期以运算器为中心；现代计算机改为以存储器为中心，I/O 设备可以直接与主存交换数据（13.15 的 DMA）。

实线是数据和指令的流动，虚线是控制信号；指令和数据存在同一个存储器里，按地址访问

指令和数据放在一起，CPU 怎样区分？靠取出的时机：取指周期读到的是指令，执行周期读到的是数据。** 哈佛结构**把指令存储器和数据存储器分开，可以同时取指令和取数据；现代 CPU 常在 L1 Cache 这一级分开，更低层统一存放。

系统的层次。 从用户到电路，计算机可以看成一层层"虚拟机器"，每层用下一层提供的功能实现自己：

编译器把高级语言翻译到 ISA 这一层；组成原理研究 ISA 以下怎样实现

指令系统（ISA，指令集体系结构）是软件和硬件的分界面，规定机器有哪些指令、寄存器和寻址方式，例如 x86、ARM、RISC-V。同一个 ISA 可以有多种内部实现。计算机体系结构指程序员看得见的属性（有没有乘法指令），计算机组成指这些属性怎样实现（乘法用专门电路还是反复相加）。

13.2 性能指标：CPI、MIPS 与 Amdahl 定律

一台 3 GHz、一台 2 GHz，哪台跑同一个程序更快？只看主频会选错，因为每条指令花的周期数、程序编译出的指令条数都可能不同。

先认识几个量：

  • 时钟周期 T：CPU 最小的时间单位，主频 f = 1/T。2 GHz 的时钟周期是 0.5 ns。
  • CPI（Cycles Per Instruction）：平均每条指令花几个时钟周期；IPC 是它的倒数。
  • MIPS：每秒执行多少百万条指令，MIPS = f / (CPI × 10⁶)。

把它们连起来就是 CPU 时间公式：

CPU 执行时间 = 指令条数 IC × CPI × 时钟周期 = IC × CPI / f

示例： 程序有 10⁹ 条指令：算术类占 50%（CPI = 1）、访存类占 30%（CPI = 2）、分支类占 20%（CPI = 3），主频 2 GHz。

  1. 平均 CPI = 0.5×1 + 0.3×2 + 0.2×3 = 1.7（按比例加权）；
  2. CPU 时间 = 10⁹ × 1.7 / (2×10⁹) = 0.85 s；
  3. MIPS = 2×10⁹ / (1.7×10⁶) ≈ 1176.5。

另一台机器 B 的指令更简单：同一程序编译出 1.5×10⁹ 条，CPI = 1.2，主频也是 2 GHz。B 的 MIPS ≈ 1666.7，比 A 高；可是时间 = 1.5×10⁹ × 1.2 / (2×10⁹) = 0.9 s，反而更慢。所以 MIPS 只适合比较同一指令系统的机器，衡量性能最可靠的是执行同一程序所用的时间。

Amdahl 定律回答"优化一部分能快多少"：原执行时间中比例为 p 的部分加速 s 倍，整体加速比 = 1 / ((1−p) + p/s)。p = 0.8、s = 4 时为 1/(0.2 + 0.2) = 2.5 倍；s 趋于无穷时上限是 1/(1−p) = 5 倍。

Amdahl 定律：p 不大时，把局部加速 10 倍和 4 倍差别很小

要点：

  • CPU 时间 = IC × CPI / f，三个因素都要看。
  • 平均 CPI 按各类指令所占比例加权。
  • 吞吐率是单位时间完成的任务数，响应时间是单个任务从开始到结束的时间，两者分别衡量。
  • Amdahl 定律：整体加速受未优化部分限制，上限 1/(1−p)。

查看答案与每个选项的解析

A · 正确：总周期数 = 3 × 2×10⁹ = 6×10⁹，CPI = 6×10⁹ / 4×10⁹ = 1.5；MIPS = 2×10⁹ / (1.5×10⁶) ≈ 1333.3。

B · 错误：把 CPI 算成了 IPC（指令数 / 周期数）。

A. 整体加速 2.5 倍

易错点：

  • MIPS 高的机器未必更快：指令系统不同，同一程序的指令条数也不同。
  • 题目给"各类指令条数"时，先换算成比例再加权。

小结： CPU 时间 = 指令条数 × CPI / 主频；MIPS = 主频 / (CPI×10⁶)；Amdahl 定律给出的加速比为 1/((1−p)+p/s)，上限是 1/(1−p)。

13.3 定点与浮点运算：浮点加减分五步

01 章讲了补码加减法和 IEEE 754 的格式换算，那是"数怎样存"。本节补上"两个浮点数怎样相加"：阶码不同的两个数，尾数没法直接对位相加，硬件要分五步处理。

定点运算回顾。 整数用补码运算：减法变成加法，[A−B]补 = [A]补 + [−B]补；溢出用双符号位（01 正溢、10 负溢）或"最高位进位与次高位进位异或"判断（01.3 节）。乘除法在硬件中用"移位 + 加减"实现：原码一位乘每次看乘数的一位，为 1 就把被乘数加到部分积，再把部分积右移一位。

浮点加减的五个步骤（标准答案顺序）：

  1. 对阶：比较两数阶码，小阶向大阶看齐。阶码小的数尾数右移、阶码加 1，直到两阶相等。右移丢掉的是低位，误差小。
  2. 尾数加减：阶码相同后，尾数按定点数相加减。
  3. 规格化：让尾数回到 1.xxx 形式。尾数 ≥ 2 时右规（右移 1 位、阶码加 1）；尾数 < 1 时左规（左移、阶码减 1，可能多次）。
  4. 舍入：处理对阶和右规时移出的低位。IEEE 754 默认"就近舍入，正好在中间时取偶数"[1]；408 教材还讲"0 舍 1 入"和"恒置 1"两种简单方法。
  5. 溢出判断：看阶码。阶码上溢（单精度规格化数的指数超过 127）是浮点溢出；阶码下溢时结果按机器零或非规格化数处理。

  • 浮点是否溢出看阶码；尾数 ≥ 2 通过右规修正。

查看答案与每个选项的解析

小结： 浮点加减运算依次进行：对阶（小阶向大阶看齐）、尾数加减、规格化（尾数绝对值 ≥ 2 时右规，< 1 时左规）、舍入，最后根据阶码判断是否溢出。

13.4 存储器层次与主存：SRAM、DRAM、刷新与带宽

我们想要又快、又大、又便宜的存储器，但三者互相矛盾：快的 SRAM 贵且容量小，便宜的磁盘慢。解决办法是分层，并利用局部性让大多数访问落在快的那一层。

局部性原理。 时间局部性：刚访问过的数据很可能很快再被访问（循环变量）；空间局部性：刚访问过的地址附近很可能很快被访问（顺序执行的指令、按行遍历数组）。

存储层次：上层保存下层中最常用的一小部分。Cache—主存由硬件管理，主存—辅存由操作系统管理（虚拟存储）

SRAM 与 DRAM。 Cache 用 SRAM，主存用 DRAM：

SRAM（静态）DRAM（动态）
存储原理双稳态触发器（约 6 个晶体管）电容上的电荷（1 个晶体管 + 1 个电容）
刷新无需刷新电荷会泄漏，必须定期刷新
速度 / 集成度 / 每位价格快 / 低 / 高慢 / 高 / 低
读出非破坏性破坏性读出，读后要再生
地址送入一次送全行地址、列地址分两次送（地址复用），地址线减半
用途Cache主存

ROM（只读存储器）断电后内容保留，用来存 BIOS 等固件；RAM 断电丢失。CPU 上电复位后寄存器被置为预定值，PC 指向固定地址，从 ROM 中的固件开始执行。

DRAM 刷新以行为单位，一次刷新一整行。设刷新周期 2 ms、芯片 128 行，有三种安排：

  • 集中刷新：在 2 ms 末尾集中刷完 128 行，这段时间无法访存，叫"死区"；
  • 分散刷新：每次读写后紧跟刷新一行，没有死区，但存取周期变长；
  • 异步刷新：把 128 次刷新均匀分布在 2 ms 中，每隔 2 ms / 128 = 15.625 μs 刷新一行。最常用，死时间短而分散。

主存带宽 = 每次存取的字节数 / 存取周期。数据总线 64 位（8 B）、存取周期 100 ns 时，带宽 = 8 B / 100 ns = 80 MB/s。

多体交叉存储器把主存分成 m 个独立的体。** 低位交叉**：用地址低位选体，相邻地址落在相邻的体，各体轮流启动、重叠工作。设 m = 4，存取周期 T = 200 ns，总线传一个字 r = 50 ns（T = m·r，恰好流水）。连续读 4 个字：单体要 4T = 800 ns；4 体低位交叉只要 T + 3r = 350 ns。高位交叉相邻地址在同一个体，用于扩大容量。

要点：

  • SRAM 快、贵、免刷新，做 Cache；DRAM 密度高、便宜、要刷新、地址复用，做主存。
  • 刷新以行为单位；异步刷新间隔 = 刷新周期 / 行数。
  • 低位交叉连续访问 m 个字的时间为 T + (m−1)r。

单选 · 理解检查 5　DRAM 芯片有 256 行，刷新周期 2 ms，采用异步刷新。相邻两次刷新的间隔是多少？

A. 7.8125 μs

B. 15.625 μs

C. 2 ms

D. 取决于芯片的列数

查看答案与每个选项的解析

A · 正确：2 ms / 256 = 7.8125 μs，每次刷新一行。

B · 错误：这是 128 行时的结果。

C · 错误：2 ms 是每一行都要被刷到的周期，256 行要均匀分布在其中。

D · 错误：刷新以行为单位，一次刷新整行，与列数无关。

易错点：

  • 刷新按行进行，与列数无关；"刷新周期"指同一行两次刷新之间的最大间隔。
  • 低位交叉提高的是连续访问的带宽，单个字的存取时间仍是 T。

小结： SRAM 用触发器存储，速度快、价格高，用作 Cache；DRAM 用电容存储，需要刷新，用作主存；异步刷新的间隔等于刷新周期除以行数；低位交叉编址的 m 体存储器连续读 m 个字需要 T + (m−1)r。

13.5 存储器扩展：芯片数、地址线与片选

单片存储芯片的容量和字长都有限，例如 2K×4 位（2048 个单元，每单元 4 位）。要组成 8K×8 位的主存，就得把多片连起来。笔试常问：要几片？地址线怎样分？每组芯片的地址范围是多少？

三种扩展方式。 记号"M×N"表示 M 个字、每字 N 位。

  • 位扩展（字长不够）：各片的地址线、片选线、读写线全部并联，数据线分别接到数据总线的不同位。例：1K×4 → 1K×8，2 片，一片管高 4 位、一片管低 4 位。
  • 字扩展（字数不够）：数据线并联，低位地址线并联，高位地址线经译码器产生各片的片选信号。例：1K×8 → 4K×8，4 片，2 根高位地址线经 2-4 译码器选片。
  • 字位同时扩展：先位扩展成"组"，再对组做字扩展。

芯片数 = (目标字数 / 芯片字数) × (目标位数 / 芯片位数)

完整走一遍：用 2K×4 芯片组成 8K×8 主存。

  1. 芯片数：(8K / 2K) × (8 / 4) = 4 × 2 = 8 片，每 2 片一组，共 4 组；
  2. 地址线：8K = 2¹³，CPU 用 13 根地址线 A12～A0；芯片 2K = 2¹¹，片内地址用 A10～A0；
  3. 片选：剩下的 A12、A11 接 2-4 译码器，4 个输出各选一组；
  4. 地址范围：A12A11 = 00 为第 0 组 0000H～07FFH，01 为 0800H～0FFFH，10 为 1000H～17FFH，11 为 1800H～1FFFH；
  5. 反过来判断：地址 1A3CH = 1 1010 0011 1100B，最高两位 A12A11 = 11，落在第 3 组。

字位同时扩展：先 2 片并成 2K×8（位扩展），再 4 组串成 8K×8（字扩展）；高 2 位地址经译码选组

要点：

  • 位扩展：地址并联、数据分接；字扩展：数据并联、高位地址译码出片选。
  • 片内地址位数 = log₂(芯片字数)，译码用的高位数 = log₂(组数)。
  • 每组地址范围：组号拼上全 0 的片内地址，到组号拼上全 1 的片内地址。

13.6 Cache 的地址划分与三种映射方式

CPU 访问主存要几十到上百纳秒，访问 Cache 只要几纳秒。Cache 比主存小得多，所以必须规定"主存的某一块该放在 Cache 的哪里"，查找时还要能快速判断"它在不在"。

基本概念。 主存和 Cache 以块（Cache 中也叫行、line）为单位交换数据。Cache 每行除数据外还有：** 标记 tag**（记录这是主存哪一块）、有效位（这行是否装了数据）、脏位（写回策略下是否被改过）和替换控制位。

三种映射方式：

  • 直接映射：主存块只能放进固定的一行，行号 = 主存块号 mod 行数。电路简单，冲突多。
  • 全相联映射：可以放进任意一行，冲突最少；查找时要与所有行的 tag 同时比较，电路最复杂。
  • 组相联映射：Cache 分成若干组，每组 k 行（称 k 路）；组号 = 主存块号 mod 组数，组内任选一行。是前两者的折中，最常用。

同一组主存块在三种映射方式下能放到哪里（Cache 共 4 行）

没有固定位置，查找时要和所有行的 tag 比较

冲突最少，比较电路最多

地址划分。 设 Cache 容量 C、块大小 B、每组 k 行，则块数 = C/B，组数 S = C/(B×k)。主存地址从低到高分三段：

  • 块内偏移 = log₂B 位；
  • 组号（索引） = log₂S 位：直接映射时就是行号，全相联时 S = 1、组号 0 位；
  • tag = 地址总位数 − 组号位数 − 偏移位数。

示例： 32 位字节地址，Cache 32 KiB，块 64 B：

  1. 块数 = 32768 / 64 = 512，偏移 = log₂64 = 6 位；
  2. 4 路组相联：组数 = 512 / 4 = 128，组号 7 位，tag = 32 − 7 − 6 = 19 位；
  3. 直接映射：512 行，行号 9 位，tag 17 位；全相联：tag 26 位。

32 KiB、64 B 块、4 路组相联：块数 512，组数 128；tag = 32 − 7 − 6 = 19

再拆一个具体地址：16 位地址、8 行直接映射、块 16 B，访问 1234H。偏移 4 位，就是最低的十六进制位 4；主存块号 = 1234H / 16 = 123H，行号 = 123H mod 8 = 3；tag = 1234H 右移 7 位 = 24H。所以 1234H 进第 3 行，tag 为 24H。

额外存储开销。 上面的 4 路组相联 Cache 若用写回和 LRU，每行要存：有效位 1 + 脏位 1 + LRU 位 2（4 路用 2 位计数）+ tag 19 = 23 位，512 行共 512 × 23 = 11776 位，这些都在数据区之外。

要点：

  • 组数 = 容量 / (块大小 × 路数)；偏移 = log₂块大小，组号 = log₂组数，tag 取剩余高位。
  • 直接映射 = 1 路组相联；全相联 = 只有 1 组。
  • 路数越多，tag 越长、比较器越多，冲突缺失越少。

13.7 Cache 命中率、LRU 替换与写策略

映射方式决定"能放在哪"；组满了还要决定"换掉谁"；写数据时还要决定"何时写回主存"。三件事合起来决定命中率和平均访问时间。

命中率与平均访问时间。 命中率 H = 命中次数 / 总访问次数。平均访问时间（AMAT）要看题目给的缺失时间是什么：

  • 缺失时"先查 Cache 再访主存"，给的是额外的缺失惩罚：AMAT = 命中时间 + (1−H) × 缺失惩罚。命中 2 ns、缺失率 5%、惩罚 80 ns 时，AMAT = 2 + 0.05 × 80 = 6 ns。
  • 给的 80 ns 已经是缺失时的全部时间：AMAT = 0.95 × 2 + 0.05 × 80 = 5.9 ns。

替换算法。 组满时换出一块：** 随机**（RAND）、先进先出（FIFO，换最早装入的）、最近最少使用（LRU，换最久没被访问的）。LRU 利用时间局部性，命中率通常最好，是考试主角。

示例： Cache 共 4 行，初始为空，访问主存块号序列 0 4 0 8 0 4 1 0，比较三种映射：

  • 直接映射（行号 = 块号 mod 4）：0、4、8 都进第 0 行，互相挤出，8 次全部缺失，命中率 0。
  • 全相联 + LRU：不同的块只有 0、4、8、1 四个，4 行装得下，只有第一次访问缺失，命中 4 次，命中率 50%。
  • 2 路组相联 + LRU（组号 = 块号 mod 2）：逐步看下图，命中 3 次，命中率 37.5%。

代码：用 Python 模拟。 blocks 是访问的块号序列；lines 是 Cache 的总行数；ways 是每组的行数（为 1 时是直接映射，等于 lines 时是全相联）；state[s] 是第 s 组当前装入的块，从左到右按最久未使用到最近使用的顺序排列；victim 是被换出的块。

def simulate_cache(blocks, lines, ways):
    """LRU cache of `lines` lines, `ways`-way set associative (ways=lines: fully, 1: direct).
    Returns (hit list, final state). State per set is list ordered oldest -> newest."""
    sets = lines // ways
    state = [[] for _ in range(sets)]
    hits = []
    trace = []
    for b in blocks:
        s = state[b % sets]
        if b in s:
            s.remove(b)
            s.append(b)
            hits.append(True)
            trace.append((b, 'hit', None))
        else:
            victim = None
            if len(s) == ways:
                victim = s.pop(0)
            s.append(b)
            hits.append(False)
            trace.append((b, 'miss', victim))
    return hits, state, trace

调用 simulate_cache([0, 4, 0, 8, 0, 4, 1, 0], 4, 2) 得到命中 3 次，和手算一致。命中时把块移到表尾，就是 LRU 的"更新为最近使用"；缺失且组满时弹出表头，就是"换出最久未用"。

写策略。 写命中时有两种做法：

  • 写直达（write-through，全写法）：同时写 Cache 和主存。简单，主存总是最新，但写主存次数多，常配写缓冲。
  • 写回（write-back）：只写 Cache，并把该行脏位置 1；这行被换出时才写回主存。写主存次数少。

写不命中时：写分配先把块调入 Cache 再写，常与写回搭配；非写分配直接写主存，常与写直达搭配。多核 CPU 每个核有私有 Cache，同一数据可能有多个副本，用 MESI 等缓存一致性协议维护，四个状态是已修改 M、独占 E、共享 S、无效 I：一个核写某行时，其他核中该行的副本变为无效。

要点：

  • 同一序列、同样容量下，命中次数通常是全相联 ≥ 组相联 ≥ 直接映射。
  • LRU 命中时要更新使用顺序，FIFO 命中时顺序不变。
  • 写回 + 写分配、写直达 + 非写分配是两种常见搭配。

13.8 虚拟存储器：主存—辅存这一层（与 07 章对照）

Cache 解决"主存太慢"，虚拟存储器解决"主存不够大、多个程序要隔离"。07 章从操作系统角度讲了页表、缺页和页面置换，本节只补硬件这一侧：一个地址怎样一路变成数据。

程序使用虚拟地址，硬件 MMU（内存管理单元）借助页表把它翻译成物理地址。页表在主存里，为免每次访存都先查页表，CPU 中有一个专门缓存页表项的小 Cache，叫 TLB（快表）。虚拟存储器的最大容量取"2^虚拟地址位数"与"主存 + 辅存容量"中较小的一个。

一次访存的完整路径：先把虚拟地址变成物理地址，再用物理地址查 Cache

Cache—主存主存—辅存（虚拟存储）
目的提速扩容、隔离
交换单位块（几十字节）页（如 4 KiB）
由谁管理全部由硬件完成硬件（MMU、TLB）+ 操作系统（缺页处理）
缺失代价几十个周期访问磁盘，约百万个周期
映射方式直接、组相联、全相联全相联（任一页可放进任一页框）
写策略写回或写直达只用写回

完整走一遍（沿用 07.3 的数字）：TLB 查询 10 ns，访存 100 ns，TLB 命中率 90%。命中：10 + 100 = 110 ns；未命中先查页表再取数据：10 + 100 + 100 = 210 ns；平均 0.9 × 110 + 0.1 × 210 = 120 ns。32 位虚拟地址、4 KiB 页时，页内偏移 12 位，虚页号 20 位。

要点：

  • 访存顺序：虚拟地址 → TLB/页表 → 物理地址 → Cache → 主存。
  • 虚拟存储用全相联和写回，因为缺页代价极高，要尽量降低缺页率。
  • TLB、页表、Cache 三者各自可能缺失，组合题要逐个判断是否可能。

13.9 指令格式与扩展操作码

一条指令要告诉 CPU "做什么"（操作码）和"对谁做"（地址码）。指令长度固定时，地址码多的指令留给操作码的位就少；扩展操作码让不同类的指令合理分享这些位。

指令格式。 指令由操作码 OP 和若干地址码组成。按地址码的个数分为：三地址指令，完成 (A1) op (A2) 并把结果送到 A3；二地址指令，结果送回 A1；一地址指令，另一个操作数在累加器 ACC 中；零地址指令，操作数在栈顶。RISC（如 RISC-V、ARM）多用定长的 32 位指令；CISC（如 x86）的指令长度从 1 到 15 字节不等。

扩展操作码让操作码长度随地址码个数变化。核心规则：** 短操作码不能是长操作码的前缀**，否则译码时分不清。做法是每一类留出若干编码作"扩展标志"，下一类在标志后面再接位。

示例： 指令字长 16 位，地址码 4 位，要设计 15 条三地址、15 条二地址、15 条一地址、16 条零地址指令：

  1. 三地址：操作码 16 − 3×4 = 4 位，用 0000～1110 共 15 个，留 1111 作扩展标志；
  2. 二地址：在 1111 后再取 4 位，1111 0000～1111 1110 共 15 条，留 1111 1111；
  3. 一地址：1111 1111 0000～1111 1111 1110 共 15 条，留 1111 1111 1111；
  4. 零地址：1111 1111 1111 0000～1111 1111 1111 1111 共 16 条，全部用完。

16 位指令、地址码各 4 位：每类留出全 1（十六进制 F = 二进制 1111）作为"扩展标志"，下一类在它后面再取 4 位

最多条数：下一类最多 = 上一类留下的扩展编码数 × 2^(新增操作码位数)。例：16 位指令、地址码 4 位，三地址用了 14 条，留下 16 − 14 = 2 个扩展码，二地址最多 2 × 2⁴ = 32 条。

要点：

  • 扩展操作码要满足前缀条件：短码不能是长码的前缀。
  • 下一类最多条数 = (本类编码总数 − 本类已用数) × 2^新增位数。
  • 定长操作码译码简单；扩展操作码更充分地利用指令字。

单选 · 理解检查 11　指令字长 16 位，地址码 6 位，采用扩展操作码。已有二地址指令 12 条，其余全为一地址指令，一地址指令最多几条？

查看答案与每个选项的解析

13.10 九种寻址方式与有效地址计算

地址码里写的数不一定是操作数所在的地址：它可能是操作数本身，也可能要加上某个寄存器。寻址方式规定"怎样从形式地址得到操作数"，让短短几位地址码也能访问很大的空间，并支持数组、指针和程序浮动。

指令中的地址码叫形式地址 A，操作数在主存中的真实地址叫有效地址 EA，(X) 表示 X 中的内容。下表用同一组数据算出每种方式的结果：A = 100；主存 (100) = 300、(300) = 700、(200) = 400、(1100) = 55、(105) = 11、(2102) = 66、(500) = 77；寄存器 R1 = 200，基址寄存器 BR = 1000，变址寄存器 IX = 5，取指后 PC = 2002，栈指针 SP = 500。

寻址方式有效地址本例 EA操作数取指后访存次数典型用途
立即A 本身就是操作数—1000给常量
直接EA = A1003001访问固定变量
间接（一次）EA = (A)3007002指针，扩大寻址范围

直接寻址访存 1 次拿到操作数；一次间接寻址先取地址、再取操作数，共访存 2 次

基址与变址怎样区分。 基址寄存器由操作系统设定，程序执行中不变，A 是可变的偏移，面向系统，解决程序重定位；变址寄存器由用户程序修改（如循环中每次加 1），A 是固定的数组首址，面向用户，处理数组。

相对寻址用的是更新后的 PC。 设转移指令长 2 字节，存放在地址 2000，取指后 PC = 2002，位移 A = 100，转移目标为 2102。位移用补码表示，可正可负。

要点：

  • 立即寻址最快（不访存取操作数），一次间接寻址要访存两次。
  • 基址面向系统、变址面向用户；相对寻址以取指后的 PC 为基准。
  • 堆栈寻址的地址隐含在 SP 中，零地址指令用它。

13.11 CPU：数据通路、取指过程与两种控制器

前面讲了指令的格式，现在看 CPU 内部怎样一步步执行它。CPU 内部、CPU 与主存之间的数据传送路径叫数据通路。

主要寄存器：

  • PC（程序计数器）：下一条指令的地址；IR（指令寄存器）：当前正在执行的指令；
  • MAR（存储器地址寄存器）：要访问的主存地址，位数与地址总线一致；
  • MDR（存储器数据寄存器）：从主存读出或要写入的数据，位数与存储字长一致；
  • 通用寄存器、ALU，以及存放进位、溢出、零等标志的程序状态字 PSW。

x86 汇编阅读题常见的寄存器：EAX 是 32 位，其低 16 位叫 AX，AX 又分为高 8 位 AH 和低 8 位 AL；AX 常作累加器，BX 作基址，CX 作循环计数，DX 作数据；SP 是栈指针，BP 是基址指针，SI/DI 是源/目的变址；IP（EIP）就是 PC；CS/DS/SS/ES 是段寄存器 [2]。

CPU 数据通路简图：PC 指向下一条指令，MAR/MDR 是 CPU 与主存之间的地址、数据缓冲，IR 存当前指令

指令周期是一条指令从取出到执行完的全部时间，包括取指周期、间址周期（有间接寻址时）、执行周期、中断周期（有中断请求时）。取指周期对所有指令都一样：

取指周期的 4 个微操作

1 / 4

第1步 · (PC) → MAR

把下一条指令的地址送到地址寄存器
2 / 4

第2步 · M(MAR) → MDR

控制器发"读"命令，主存把这个地址的内容送到数据寄存器
3 / 4

第3步 · (MDR) → IR

取到的是指令，放进指令寄存器，随后交给控制器译码
4 / 4

第4步 · (PC) + 1 → PC

PC 指向下一条指令（按字编址加 1；按字节编址加指令字节数）。这一步可与第 2 步同时进行

两种控制器。 控制器根据 IR 中的操作码和当前节拍，发出一串控制信号（微命令），如"PC 内容送 MAR"。产生这些信号有两种做法：

硬布线控制器微程序控制器
原理用组合逻辑电路直接产生微命令每条机器指令对应一段微程序，存在控制存储器 CM（ROM）中，逐条读出微指令
速度快较慢，每一步要读一次控存
修改与扩展难，要重新设计电路容易，改写控存即可
典型RISCCISC

层次关系：一条机器指令对应一段微程序，微程序由若干微指令组成，一条微指令包含若干微命令。

微指令编码。 直接编码每个微命令占 1 位，最快但很长。** 字段直接编码把互斥**的微命令（同一周期不会同时出现）放进同一字段，用二进制编码，每个字段还要留一个"不发命令"的码。若互斥组分别有 3、7、12 个微命令，字段长度为 ⌈log₂4⌉ + ⌈log₂8⌉ + ⌈log₂13⌉ = 2 + 3 + 4 = 9 位，比直接编码的 22 位短得多。

要点：

  • 取指四步：(PC) → MAR，M(MAR) → MDR，(MDR) → IR，(PC) + 1 → PC。
  • 硬布线快、难改，适合 RISC；微程序慢、灵活，适合 CISC。
  • 字段直接编码：每个互斥组占 ⌈log₂(n+1)⌉ 位。

13.12 指令流水线：时空图、性能计算与三类冒险

洗衣服分洗、烘、叠三步，第一批进烘干机时第二批就可以开始洗。CPU 也一样：把指令执行分成几个阶段，让不同指令的不同阶段重叠执行，理想情况下每个周期完成一条指令。

五段流水线依次为 IF（取指）、ID（译码并读寄存器）、EX（执行或计算地址）、MEM（访存）、WB（写回寄存器）。段与段之间有流水寄存器保存中间结果，时钟周期取最慢的那一段所需的时间。

时空图：横轴是时钟周期，纵轴是指令。T5 这一列 5 个阶段全部有活干，流水线"充满"；5 条指令共用 5+5−1 = 9 个周期

性能公式（k 段，每段 Δt，连续执行 n 条指令，无停顿）：

  • 总时间 T = (k + n − 1) Δt：第一条指令用 k 个周期，之后每周期再完成一条；
  • 吞吐率 TP = n / T；
  • 加速比 S = 不用流水线的时间 / 用流水线的时间 = n·k·Δt / T；
  • 效率 E = 各段实际工作的时空区面积 / 总时空区面积 = n / (k + n − 1)。

示例： 5 段、Δt = 1 ns、n = 10：

  1. T = (5 + 10 − 1) × 1 = 14 ns；
  2. TP = 10 / 14 ns ≈ 7.14×10⁸ 条/秒，即约 714.3 MIPS；
  3. S = 50 / 14 ≈ 3.57；
  4. E = 10 / 14 ≈ 71.4%。

n 越大，S 越接近 k，E 越接近 1：4 段、100 条、Δt = 10 ns 时，T = 1030 ns，S ≈ 3.88，E ≈ 97.1%。各段时间不等时（如 2、2、3、1、2 ns），Δt 取最大值 3 ns，10 条指令用 (5 + 10 − 1) × 3 = 42 ns；不用流水线是 10 × (2+2+3+1+2) = 100 ns，加速比 100 / 42 ≈ 2.38。

三类冒险（也叫相关），它们让流水线停顿：

冒险原因解决方法
结构冒险多条指令同时争用同一硬件，如取指和取数据都要访存指令 Cache 与数据 Cache 分开；资源重复设置；后一条暂停
数据冒险后一条指令要用前一条的结果，而结果还没写回插入气泡（停顿）；数据旁路（转发）把 ALU 结果直接送给下一条；编译器调整指令顺序
控制冒险转移指令的目标要到后面的阶段才知道分支预测；延迟转移；尽早计算转移地址

数据冒险按读写顺序分为 RAW（写后读）、WAR（读后写）、WAW（写后写）；按序执行的五段流水线只会出现 RAW。

无转发时的数据冒险：ADD R1,R2,R3 后接 SUB R4,R1,R5，SUB 要读 R1，必须等 ADD 在 T5 写回（前半周期写、后半周期读），插入 2 个气泡

上图中 ADD 在 T5 的 WB 段把 R1 写回，没有转发时 SUB 的 ID 要等到 T5（约定寄存器前半周期写、后半周期读），插入 2 个气泡，两条指令共 8 个周期。有转发时，ADD 在 EX 末尾得到结果就送给 SUB 的 EX，无需停顿；但前一条若是 LOAD（数据在 MEM 之后才有），仍要停 1 个周期，叫 load-use 冒险。

CPI 能否小于 1。 单发射流水线每周期最多完成一条指令，理想 CPI 的下限是 1，有冒险时大于 1。要让 CPI 小于 1 必须多发射：超标量每周期发射多条指令（配多套功能部件），VLIW（超长指令字）由编译器把多个操作打包成一条长指令。

Flynn 分类按指令流和数据流的个数：SISD（单指令流单数据流，传统单核）、SIMD（一条指令同时处理多个数据，如向量指令）、MISD（几乎没有实际机器）、MIMD（多核、多处理机）。GPU 采用的 SIMT（单指令多线程）是 SIMD 的变体：一组线程同时执行同一条指令，每个线程处理自己的数据。

要点：

  • T = (k+n−1)Δt；S = nk/(k+n−1)；E = n/(k+n−1)；n → ∞ 时 S → k、E → 1。
  • 流水线提高吞吐率，单条指令的执行时间没有缩短。
  • 结构冒险靠分离资源，数据冒险靠转发和停顿，控制冒险靠分支预测。

13.13 总线：带宽计算与仲裁方式

CPU、主存、I/O 设备之间若两两连线，线数会随部件数平方增长。总线是一组共享的传输线，所有部件都挂在上面，同一时刻只允许一个部件发送。于是要弄清两件事：它能传多快（带宽），由谁来用（仲裁）。

分类。 按传输内容分为数据总线（双向，位数等于一次传送的数据位数）、地址总线（单向，由 CPU 发出，位数决定寻址空间）、控制总线（读写、中断请求等信号）。按定时方式分为同步总线（统一时钟，快，适合速度相近的部件）和异步总线（靠"请求—应答"握手，适合速度差别大的部件）。

总线带宽 = 每次传送的字节数 × 每秒传送次数：

  • 32 位、100 MHz、每个时钟周期传一次：4 B × 100 M = 400 MB/s；
  • 同一总线每两个周期传一次：200 MB/s；
  • 64 位、100 MHz，上升沿和下降沿各传一次（DDR）：8 B × 100 M × 2 = 1600 MB/s。

集中式总线仲裁有三种方式：

  • 链式查询：总线同意信号 BG 从控制器出发，逐个设备往下传，第一个有请求的设备截住它。离控制器越近优先级越高；只需 BS（忙）、BR（请求）、BG（同意）3 根线；对电路故障敏感，一个设备坏了，后面的设备都拿不到总线。
  • 计数器定时查询：控制器的计数器依次发出设备地址，地址与计数值相同且有请求的设备获得总线。计数可每次从 0 开始（固定优先级），也可从上次停止处继续（轮流）。n 个设备需要 ⌈log₂n⌉ 根设备地址线。
  • 独立请求：每个设备有自己的请求线 BRi 和同意线 BGi，由控制器内部排队。响应最快，优先级可编程，n 个设备需要 2n 根线。

链式查询：BG 信号逐个设备往下传，离控制器最近的请求者先截住 BG。只需 BS、BR、BG 三根线，但对电路故障敏感

要点：

  • 带宽 = 总线宽度（字节）× 时钟频率 × 每周期传送次数 / 每次传送占用的周期数。
  • 链式 3 根线、对故障敏感；计数器查询 ⌈log₂n⌉ 根；独立请求 2n 根、最快。
  • 地址总线单向，数据总线双向。

  • 计数器从上次停止处继续计数时，各设备机会均等。

小结： 总线带宽等于总线宽度乘以频率再除以每次传输所需的周期数；链式查询需要 3 根控制线，计数器定时查询需要 log₂n 根，独立请求需要 2n 根。

13.14 中断：响应过程、中断向量与屏蔽字

CPU 比外设快几个数量级。若 CPU 一直询问"打印机好了吗"，大部分时间都在空等。中断让设备在准备好时主动通知 CPU：CPU 暂停当前程序去处理，处理完再回来接着执行。07 章从操作系统角度讲了 I/O 软件层次，本节讲硬件这一侧的过程。

中断的分类。 外中断来自 CPU 外部（I/O 完成、时钟）；内中断也叫异常，来自 CPU 内部（除以零、缺页、执行系统调用的陷入指令）。外中断又分可屏蔽中断（INTR，可被屏蔽字或关中断挡住）和非屏蔽中断（NMI，如掉电，必须立即响应）。

响应中断的三个条件是：有中断请求；CPU 允许中断，即中断允许触发器 IF = 1（开中断）；当前指令执行完毕，CPU 在指令周期的末尾检查中断。缺页这类异常是例外：它发生在指令执行的过程中，处理完后重新执行这条指令。

中断隐指令：响应后硬件自动完成三件事——关中断、保存断点（把 PC 存入栈）、引出中断服务程序（把入口地址送入 PC）。它是硬件动作，指令系统里没有这条指令。

中断向量：每个中断源有一个编号（中断类型号），主存中有一张中断向量表，第 n 项存放第 n 号服务程序的入口地址。硬件由编号算出表项地址（向量地址），再从表中取出入口地址。x86 实模式下每项 4 字节，n 号中断的向量地址是 4n。

单级中断省掉 ⑤ 和 ⑦，服务过程中一直关中断；多重中断在 ⑤ 处开中断，允许更高优先级嵌套

多重中断与屏蔽字。 多重中断允许高优先级的中断打断正在执行的服务程序。优先级有两种：

  • 响应优先级：多个请求同时到达时先响应谁，由硬件排队电路决定，固定不变；
  • 处理优先级：一个服务程序运行时谁能打断它，由屏蔽字决定，可以用软件修改。

每个中断源对应屏蔽字的一位，1 表示屏蔽，0 表示开放。每个服务程序都屏蔽自己；它屏蔽了谁，谁的处理优先级就比它低。

13.15 I/O 控制方式与 DMA

有的设备一次传一个字符（键盘），有的一次传一大块（磁盘）。按 CPU 参与的多少，从多到少有四种方式：程序查询、程序中断、DMA、通道。

I/O 接口与编址。 设备经 I/O 接口（设备控制器）连到总线，接口中有数据寄存器、状态寄存器、控制寄存器，统称端口。端口编址有两种：** 统一编址**（内存映像，端口占用一部分主存地址，用普通访存指令访问）和独立编址（端口有单独的地址空间，用专门的 IN/OUT 指令访问，x86 采用）。

四种控制方式：

  • 程序查询：CPU 反复读状态寄存器，直到设备就绪再传数据。CPU 和设备串行工作，CPU 大量时间在原地等待。
  • 程序中断：设备就绪时发中断，CPU 在服务程序中传送数据。CPU 和设备并行工作，但每传一个字就中断一次。
  • DMA（直接存储器存取）：由 DMA 控制器在设备和主存之间直接传送整块数据，每传完一块才中断一次，数据传送期间不经过 CPU。
  • 通道：专用的 I/O 处理器，执行通道程序，可以管理多台设备、完成多块传送，CPU 只在开始和结束时介入。

DMA 的三个阶段：CPU 只做开头的预处理和结尾的后处理，中间整块数据由 DMA 控制器直接搬进主存

DMA 与 CPU 分享主存的三种方式：一是停止 CPU 访存，整块数据传完后再交还主存；二是周期挪用（又称周期窃取），DMA 需要访存时借用一个存取周期，这是最常用的方式；三是交替访存，把一个存取周期分成两半，CPU 和 DMA 各用一半。

DMA 与中断的区别（笔试原样考）：中断传送靠程序（CPU 执行服务程序），DMA 靠硬件；中断在一条指令结束时响应，DMA 在一个存取周期结束时响应；中断要保护现场，DMA 无需保护现场；DMA 请求的优先级高于中断请求，因为响应慢了数据会丢失。

完整走一遍：算 CPU 开销。 设备传输率 400 KB/s（K = 1000），CPU 主频 500 MHz。

  1. 中断方式：每 4 B 中断一次，每次服务 200 个时钟周期。每秒中断 400000 / 4 = 100000 次，占用 100000 × 200 = 2×10⁷ 个周期，占 CPU 时间 2×10⁷ / 5×10⁸ = 4%。
  2. DMA 方式：每块 4 KB，每块的预处理和后处理共 500 个周期。每秒 400000 / 4000 = 100 块，占用 100 × 500 = 5×10⁴ 个周期，占 0.01%。

要点：

  • CPU 介入程度：程序查询 > 程序中断 > DMA > 通道。
  • 中断以字为单位打断 CPU，DMA 以块为单位；DMA 由硬件传送，无需保护现场。
  • DMA 在存取周期结束时响应，中断在指令周期结束时响应。

我们写的 x = a + b * 2; 只是一串字符，CPU 只认识机器指令。编译器把高级语言程序（源程序）翻译成等价的目标程序，过程像翻译一篇文章：先认出单词，再分析句子结构，再理解意思，最后用另一种语言写出来。

13.17 词法分析：正规式、NFA、DFA 与最小化

词法分析器要从字符流中识别出标识符、整数等单词。单词的构成规则用正规式描述最方便，识别时则用有限自动机逐个字符判断。从规则到高效的识别程序，要经过四步：由正规式构造 NFA，由 NFA 构造 DFA，再把 DFA 最小化。

单词与 token。 单词分五类：关键字（保留字，如 if、while）、标识符、常数、运算符、界符（逗号、分号、括号）。词法分析器把每个单词输出为二元组 <种别码, 属性值>。语法分析器每需要一个单词，就调用一次词法分析器。

基本符号概念。 字母表 Σ 是符号的有限集合，如 {a, b}；符号串是字母表中符号组成的有限序列，空串记 ε；方幂 xⁿ 是 x 自身连接 n 次；闭包 Σ* 是 Σ 上所有符号串（含 ε）的集合，正闭包 Σ⁺ 是去掉 ε 后的集合。

正规式由三种运算构成：** 或** a|b、连接 ab、闭包 a*（重复 0 次或多次），优先级为闭包 > 连接 > 或。例如 (a|b)ab 表示"由 a、b 组成、以 ab 结尾的串"；标识符可写成 letter(letter|digit)。

有限自动机是五元组 (S, Σ, δ, s₀, F)：状态集、字母表、转移函数、初态、终态集。DFA（确定的）每个状态读一个符号只有唯一的下一状态，且没有 ε 转移；NFA（不确定的）读一个符号可以到多个状态，还可以有 ε 转移（不读符号就转移）。

def eps_closure(states, nfa):
    stack = list(states)
    seen = set(states)
    while stack:
        s = stack.pop()
        for t in nfa.get((s, EPS), ()):
            if t not in seen:
                seen.add(t)
                stack.append(t)
    return frozenset(seen)

def move(states, ch, nfa):
    out = set()
    for s in states:
        out |= nfa.get((s, ch), set())
    return out

def subset_construction(nfa, start, accept, alphabet):
    """Return (dfa states in discovery order, transitions dict, accepting set)."""
    first = eps_closure({start}, nfa)
    order = [first]
    trans = {}
    i = 0
    while i < len(order):
        S = order[i]
        i += 1
        for ch in alphabet:
            T = eps_closure(move(S, ch, nfa), nfa)
            if not T:
                continue
            if T not in order:
                order.append(T)
            trans[(S, ch)] = T
    acc = {S for S in order if S & accept}
    return order, trans, acc

对上面的 NFA 运行，得到 {0,1,2}、{1,2,3}、{1,2}、{1,2,4} 四个状态，与手算一致。

DFA 最小化（分割法）：把"行为完全一样"的状态合并。

  1. 按是否接受分成两组：{D} 和 {A, B, C}；
  2. 检查 {A, B, C}：读 b 时 A → C、C → C 都留在本组，B → D 去了另一组，拆成 {A, C} 和 {B}；
  3. 检查 {A, C}：读 a 都到 B，读 b 都到 {A, C}，无法再拆；
  4. 最终三组 {A, C}、{B}、{D}，把 A、C 合并为 P。

最小 DFA（3 个状态）：D 是接受状态，意思是"刚读完 ab"

用最小 DFA 识别 abab：P →a→ B →b→ D →a→ B →b→ D，停在终态，接受；识别 abba：P → B → D → P → B，停在 B，拒绝。

三者等价。 正规文法（3 型）、正规式、有限自动机描述同一类语言，可以互相转换；NFA 与 DFA 的识别能力相同，DFA 的状态数可能更多。任意深度的括号配对超出了正规式的能力（有限个状态记不住任意多层未闭合的括号），要交给语法分析。

要点：

  • 子集构造：初态 = ε-闭包(NFA 初态)；新状态 = ε-闭包(move(T, a))；含 NFA 终态的集合是 DFA 终态。
  • 最小化：先分终态与非终态，再按"转移到哪一组"反复拆分，直到稳定。
  • 正规文法 ⇔ 正规式 ⇔ 有限自动机；NFA 与 DFA 等价。

13.18 文法：推导、语法树、二义性与句柄

表达式可以任意嵌套括号，语句可以嵌套语句，这种递归结构要用上下文无关文法描述。语法分析就是判断一串 token 能否由文法推导出来，并建出语法树。

文法的定义。 文法 G 是四元组 (V_N, V_T, P, S)：V_N 是非终结符集合（一般大写，如 E、T），V_T 是终结符集合（就是 token，如 i、+），P 是产生式集合（形如 A → α），S 是开始符号。同一左部的候选可以合写：E → E+T | T。** BNF** 用 ::= 代替 →；EBNF 再加 { } 表示重复 0 次或多次、[ ] 表示可选，如 E ::= T { + T }。

乔姆斯基四型文法，限制逐级加强，语言类逐级缩小（0 型 ⊃ 1 型 ⊃ 2 型 ⊃ 3 型）：

类型名称产生式限制对应自动机
0 型短语文法左部至少含一个非终结符图灵机
1 型上下文有关文法右部长度 ≥ 左部长度（S → ε 除外）线性有界自动机
2 型上下文无关文法左部是单个非终结符下推自动机（带栈）
3 型正规文法A → aB 或 A → a有限自动机

程序设计语言的语法用 2 型描述，单词用 3 型描述。

推导与归约。 用产生式右部替换左部叫推导（⇒），反过来叫归约。从开始符号推导出的串叫句型，只含终结符的句型叫句子，全部句子组成文法的语言 L(G)。每步替换最左边的非终结符叫最左推导；每步替换最右边的叫最右推导，也叫规范推导。

示例： 文法 G[E]：E → E+T | T，T → TF | F，F → i。句子 i+ii 的

  • 最左推导：E ⇒ E+T ⇒ T+T ⇒ F+T ⇒ i+T ⇒ i+TF ⇒ i+FF ⇒ i+iF ⇒ i+ii；
  • 最右推导：E ⇒ E+T ⇒ E+TF ⇒ E+Ti ⇒ E+Fi ⇒ E+ii ⇒ T+ii ⇒ F+ii ⇒ i+i*i。

两种推导的顺序不同，对应的却是同一棵语法树：根是开始符号，内部结点是非终结符，每个结点的孩子从左到右就是所用产生式的右部，叶子从左到右连起来就是句子。

二义性。 一个句子对应两棵不同的语法树（等价地，有两个不同的最左推导），文法就是二义的。E → E+E | E*E | i 就是二义文法：

短语、直接短语与句柄。 给定句型和它的语法树：

  • 短语：任一子树的叶子从左到右组成的串；
  • 直接短语（简单短语）：只有一层的子树（根的孩子全是叶子）的叶子串；
  • 句柄：最左边的直接短语。自底向上分析每一步归约的就是句柄。

分析树与抽象语法树。 完整记录每步推导的树叫分析树（具体语法树）；编译器后续阶段常用抽象语法树（AST），省掉 T、F 这类中间结点和括号，只保留运算符和运算对象。

要点：

  • 文法四元组 (V_N, V_T, P, S)；只含终结符的句型是句子。
  • 0 型 ⊃ 1 型 ⊃ 2 型 ⊃ 3 型；2 型对应下推自动机，3 型对应有限自动机。
  • 二义 = 某个句子有两棵语法树；用分层的 E/T/F 文法消除。
  • 句柄 = 最左直接短语；规范归约每步归约句柄，是最右推导的逆过程。

13.19 自顶向下分析：FIRST、FOLLOW 与 LL(1) 分析表

自顶向下分析从开始符号出发推导出输入串。难点是一个非终结符有多个候选时选哪个。LL(1) 方法只看当前一个输入符号就能唯一确定，依据是 FIRST 和 FOLLOW 两个集合。

LL(1) 中第一个 L 表示从左到右扫描输入，第二个 L 表示构造最左推导，1 表示向前看 1 个符号。LL 分析就是自顶向下分析。

先改造文法。 自顶向下有两个障碍：

  • 左递归（如 E → E+T）会让分析程序无限递归。改写规则：A → Aα | β 变为 A → βA'，A' → αA' | ε。
  • 左公因子（如 A → ab | ac）让分析器无法凭 a 选候选。提取为 A → aA'，A' → b | c。

把 13.18 的 G[E] 消除左递归并加上括号，得到：E → TE'，E' → +TE' | ε，T → FT'，T' → *FT' | ε，F → (E) | i。

两个集合。 FIRST(α) 是 α 能推导出的串的第一个终结符组成的集合，α 能推出 ε 时也包含 ε。** FOLLOW(A)** 是在某个句型中紧跟在 A 后面的终结符组成的集合，开始符号的 FOLLOW 集包含结束符 $。求 FOLLOW 集有三条规则：$ ∈ FOLLOW(S)；有产生式 A → αBβ 时，把 FIRST(β) − {ε} 加入 FOLLOW(B)；有产生式 A → αB，或者 A → αBβ 且 β 能推出 ε 时，把 FOLLOW(A) 加入 FOLLOW(B)。反复应用这些规则，直到各集合不再变化。

示例：

  1. FIRST(F) = {(, i}；T 以 F 开头，FIRST(T) = FIRST(F)；同理 FIRST(E) = {(, i}；FIRST(E') = {+, ε}，FIRST(T') = {*, ε}。
  2. FOLLOW(E)：开始符号得 $；F → (E) 中 E 后跟 )，所以 FOLLOW(E) = {), $}。
  3. E → TE' 中 E' 在末尾，FOLLOW(E') = FOLLOW(E) = {), $}。
  4. E → TE' 中 T 后跟 E'：加入 FIRST(E') − {ε} = {+}；E' 能推出 ε，再加入 FOLLOW(E)，FOLLOW(T) = {+, ), $}；T' 在 T → FT' 末尾，FOLLOW(T') = FOLLOW(T)。
  5. T → FT' 中 F 后跟 T'：加入 {}；T' 能推出 ε，再加 FOLLOW(T)，FOLLOW(F) = {, +, ), $}。

  • ε 产生式按 FOLLOW 集填表。

13.20 自底向上分析：移进—归约与 LR 分析

自底向上分析从输入串出发，反复把句柄归约成非终结符，直到得到开始符号。它对文法的限制比 LL(1) 少得多，允许左递归；yacc、bison 等语法分析器生成工具都属于这一类。

移进—归约。 分析器用一个栈：把输入符号逐个移进栈；栈顶形成句柄时就归约（弹出句柄，压入产生式左部）；栈中只剩开始符号且输入读完时接受；无路可走时报错。

LR 分析中 L 表示从左到右扫描，R 表示构造最右推导的逆过程（规范归约），属于自底向上分析。关键问题是"什么时候栈顶是句柄"，LR 用状态栈和分析表来判断：

  • ACTION[状态, 终结符]：sN 移进并转到状态 N；rK 用第 K 条产生式归约；acc 接受；空白报错；
  • GOTO[状态, 非终结符]：归约后按新的栈顶状态和刚压入的非终结符，查出要转到的状态。

项目与项目集。 在产生式右部加一个圆点表示"已经识别到哪里"，叫项目。例如 T → T·*F 表示已看到 T，正等待 *F。圆点在最右端的是归约项目。分析表由这些项目的集合（状态）构造。

B · 错误：只数了 F→i 和两个二元运算，漏了 T→F、E→T 这类单产生式归约。

C · 错误：接受动作 acc 不算归约。

D · 错误：每个 i 都要先归约成 F，光 F→i 就有 3 次。

易错点：

  • 归约时状态栈弹出的个数等于产生式右部长度，再按 GOTO 压入新状态。
  • LL 对应最左推导，LR 对应最右推导的逆过程，方向容易记反。

小结： LR 分析器由状态栈和 ACTION、GOTO 两张表组成；s 表示移进，r 表示归约；LR(0)、SLR、LALR、LR(1) 的分析能力依次增强；每次归约的都是句柄。

13.21 语义分析、属性文法与中间代码

语法正确的程序未必有意义：int x = "abc"; 结构完整，但类型不匹配。语义分析负责这类检查，并把语法树翻译成中间代码。

静态语义检查（编译时就能做）分四类：** 类型检查**（运算对象类型是否相容）、控制流检查（break 是否位于循环或 switch 内）、唯一性检查（同一作用域内名字是否重复定义）、名字的上下文相关检查（使用的名字是否已声明）。

符号表登记每个名字的属性（种类、类型、作用域、地址等），各阶段都要查和填：语义分析用它检查使用与声明是否一致，代码生成用它分配地址。组织方式有线性表、排序表（可二分查找）和散列表（最常用）。

属性文法。 在上下文无关文法的基础上，给每个文法符号附加属性（如 E.val 表示值，T.type 表示类型），给每条产生式附加语义规则，说明属性怎样计算。属性分两种：

  • 综合属性：由子结点的属性计算，信息自下而上传递，如 E.val := E₁.val + T.val；终结符只有综合属性，由词法分析提供（如 digit.lexval）。
  • 继承属性：由父结点或兄弟结点的属性计算，信息自上而下或从左到右传递。例如声明 int a, b 中，规则 L.in := T.type 把类型 int 传给后面的每个变量。

下图是表达式 3*5+4 的注释语法树，每个结点标出了属性值；这里 val 全是综合属性，从叶子往上算：

语法制导翻译：语法分析过程中，每当用某条产生式推导或归约，就执行它附带的语义动作。只含综合属性的叫 S-属性文法，适合在 LR 分析归约时计算；继承属性只依赖父结点和左边兄弟的叫 L-属性文法（S-属性文法是它的特例），适合在 LL 分析中按深度优先、从左到右计算。一般情况可以先画依赖图（属性为结点，依赖关系为有向边），再按拓扑序计算。

中间代码的形式：

  • 逆波兰式（后缀式）：运算符写在运算对象之后，a+b*c 写作 a b c * +（02.6 节有中缀转后缀算法）；
  • 三地址码：每条最多三个地址，形如 x := y op z，另有 goto L、if x relop y goto L、param x、call p 等；
  • 四元式 (op, arg1, arg2, result)：结果写成显式的临时变量，便于优化时移动代码；
  • 三元式 (op, arg1, arg2)：用三元式的编号代表结果，省空间，但移动代码要改引用；间接三元式另加一张执行顺序表来解决；
  • 树形表示：抽象语法树，以及相同子表达式只画一次的 DAG（有向无环图）。

示例： x := (a+b)*(c−d) 的两种写法：

序号四元式三元式
(1)(+, a, b, T1)(+, a, b)
(2)(−, c, d, T2)(−, c, d)
(3)(*, T1, T2, T3)(*, (1), (2))
(4)(:=, T3, _, x)(:=, x, (3))

控制语句译成带跳转的四元式。while a<b do x := y+z 可译为：(1) (j<, a, b, (3))；(2) (j, _, _, (6))；(3) (+, y, z, T1)；(4) (:=, T1, _, x)；(5) (j, _, _, (1))；(6) 循环后的第一条。生成第 (2) 条时还不知道出口在哪，先留空，生成到出口时再填回去，这叫回填。

现代编译器（如 LLVM）常用 SSA（静态单赋值形式）作中间表示：每个变量只被赋值一次，再次赋值就换新名字（x1、x2）；在 if 两个分支汇合的位置（合流点）用 φ 函数选出来自哪个分支的值，如 x3 := φ(x1, x2)。这样每次使用对应哪次定义一目了然，便于优化 [3]。

要点：

  • 静态语义检查四类：类型、控制流、唯一性、名字相关。
  • 综合属性自下而上，继承属性自上而下；S-属性配 LR，L-属性配 LL。
  • 四元式结果显式、便于优化；三元式用编号、省空间；间接三元式兼顾两者。

单选 · 理解检查 23　把 y := a + b * c 翻译成四元式（临时变量从 T1 起编号），正确的序列是？

A. (*, b, c, T1) (+, a, T1, T2) (:=, T2, _, y)

B. (+, a, b, T1) (*, T1, c, T2) (:=, T2, _, y)

C. (*, b, c) (+, a, (1)) (:=, y, (2))

D. a b c * + y :=

查看答案与每个选项的解析

A · 正确：乘法优先，先算 b*c 存入 T1，再算 a+T1，最后赋值给 y。

B · 错误：这是 (a+b)*c 的翻译，忽略了乘法优先。

C · 错误：这是三元式，用编号代表结果，没有 result 字段。

D · 错误：这是逆波兰式（后缀式）的写法。

易错点：

  • 终结符没有继承属性，它的综合属性来自词法分析。
  • 逆波兰式中运算对象的先后顺序与原式一致，只是运算符后移。

小结： 语义检查分为四类；综合属性自下而上计算，继承属性自上而下传递；S-属性文法适合 LR 分析，L-属性文法适合 LL 分析；四元式写成 (op, a1, a2, res)，三元式用编号引用中间结果。

13.22 基本块、流图与代码优化

优化要保证"变换后结果不变"。在一段没有跳进跳出的代码里，语句一定从头到尾顺序执行，分析最简单。这样的代码段叫基本块，是局部优化的单位。

基本块：顺序执行的语句序列，只有一个入口（第一条）和一个出口（最后一条）。只要第一条被执行，其余语句就按顺序各执行一次。

划分算法：先找入口语句（也叫首指令）：

  1. 程序的第一条语句；
  2. 转移语句（条件或无条件）的目标语句；
  3. 紧跟在转移语句之后的语句。

从每个入口语句到下一个入口语句之前（或到一条转移语句、停机语句为止）就是一个基本块。不属于任何块的语句永远执行不到，可以删除。以基本块为结点、按控制转移连有向边，就得到程序流图。

示例： 求 s = 1 + 2 + … + n 的中间代码：(1) i := 1　(2) s := 0　(3) if i > n goto (8)　(4) t1 := s + i　(5) s := t1　(6) i := i + 1　(7) goto (3)　(8) write s。

  1. 找入口：(1) 是第一条；(3) 是 (7) 的转移目标；(8) 是 (3) 的转移目标；(4) 紧跟转移语句 (3)。入口为 (1)、(3)、(4)、(8)；
  2. 划分：B1 = (1)～(2)，B2 = (3)，B3 = (4)～(7)，B4 = (8)；
  3. 连边：B1 顺序到 B2；B2 条件成立跳到 B4，不成立顺序到 B3；B3 末尾 goto (3) 跳回 B2。

程序流图：B2 和 B3 构成循环，B3→B2 是回边

代码：划分基本块。 变量表：prog 语句列表，编号从 1 起；target_of(st) 取出语句中 goto 的目标编号，没有则返回 None；leaders 入口语句编号集合；blocks 每块的 [首, 尾] 编号；edges 流图的边 (块号, 块号)。

def target_of(stmt):
    if 'goto (' in stmt:
        return int(stmt.split('goto (')[1].rstrip(')'))
    return None

def basic_blocks(prog):
    """prog: list of statements numbered from 1. Returns (blocks as [first,last] lists, edges)."""
    n = len(prog)
    leaders = {1}
    for k, st in enumerate(prog, 1):
        t = target_of(st)
        if t is not None:
            leaders.add(t)
            if k + 1 <= n:
                leaders.add(k + 1)
    ls = sorted(leaders)
    blocks = [[a, (ls[i + 1] - 1 if i + 1 < len(ls) else n)] for i, a in enumerate(ls)]
    where = {b[0]: i for i, b in enumerate(blocks)}
    edges = []
    for i, (a, z) in enumerate(blocks):
        last = prog[z - 1]
        t = target_of(last)
        if t is not None:
            edges.append((i, where[t]))
        if not last.startswith('goto') and i + 1 < len(blocks):
            edges.append((i, i + 1))
    return blocks, sorted(edges)

优化的分类。 按范围分：** 局部优化**（基本块内）、循环优化、全局优化（跨基本块，需要数据流分析）。按是否依赖机器分：与机器无关的优化（在中间代码上做）和与机器有关的优化（在目标代码上做，如寄存器分配、窥孔优化）。

常见的局部优化：

  • 合并已知量（常量折叠）：运算对象都是常数时，编译时就算出结果；
  • 删除公共子表达式：同一表达式已算过且操作数没变，直接用上次的结果；
  • 复写传播：有 x := y 后，在后面用 y 代替 x；
  • 删除无用赋值：赋值后再也没被用到的变量，删去它的赋值。

在基本块内常借助 DAG 完成：相同的运算只建一个结点，公共子表达式自然合并。

循环优化收益最大，因为循环体反复执行：** 代码外提**（把循环中结果不变的计算移到循环前）、强度削弱（用加法代替乘法，如数组下标 i*4 改为每次加 4）、删除归纳变量（只用来控制循环的变量用别的变量代替）。

目标代码生成主要做三件事：** 指令选择**（同一操作选最便宜的指令）、寄存器分配（常用变量放寄存器，减少访存）、指令调度（调整顺序减少流水线停顿，对应 13.12 的冒险）。优化以保持程序语义为前提；C/C++ 的未定义行为（UB，语言标准没有规定结果的操作，如有符号整数溢出、数组越界）例外，编译器可以假设它们从不发生，所以含 UB 的程序在不同优化级别下结果可能不同。

要点：

  • 入口语句三条：第一条语句、转移目标、转移语句的下一条。
  • 局部优化四种：合并已知量、删除公共子表达式、复写传播、删除无用赋值。
  • 循环优化三种：代码外提、强度削弱、删除归纳变量。

小结： 基本块的入口语句是程序的第一条语句、转移的目标语句以及紧跟在转移语句之后的语句；局部优化包括合并已知量、删除公共子表达式、复写传播、删除无用赋值；循环优化包括代码外提、强度削弱、删除归纳变量。
