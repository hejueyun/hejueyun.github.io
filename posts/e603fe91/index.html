7.1 强化学习是什么：在试错中学会做决定

教一个程序下围棋，我们很难给出每一步的"标准答案"：高手之间也常有分歧，而且一步棋好不好要到几十步之后才看得出来。我们能确定的只有最后的结果：赢了还是输了。强化学习（Reinforcement Learning，RL）就是为这种"只知道结果好坏、不知道每步该怎么做"的问题设计的：让程序自己尝试，根据结果的好坏调整行为。

强化学习里有两个角色：智能体（agent，做决定的程序）和环境（environment，智能体所处的世界）。它们按回合交替：

  • 状态 s：环境此刻的样子，例如棋盘局面、机器人的位置。
  • 动作 a：智能体在当前状态下做出的选择，例如落子、向左走。
  • 奖励 r：环境对这一步给出的一个数，好事为正、坏事为负，例如"赢棋 +1"。
  • 策略 π：智能体的行为规则，输入状态、输出动作（或各动作的概率），记作 π(a|s)。

智能体看到状态 sₜ，按策略选动作 aₜ；环境随之变到新状态 sₜ₊₁，并给出奖励 rₜ₊₁；如此循环。学习的目标是找到一个策略，使长期累计奖励尽可能大。

强化学习闭环：智能体出动作，环境回状态和奖励；目标是让长期累计奖励最大

强化学习有两个特有难点。一是奖励延迟：下棋赢了，到底是哪一步的功劳？这叫"信用分配"问题。二是探索与利用：一直走已知最好的路，可能错过更好的路；总是乱试，又浪费机会。7.3 会给出具体的处理办法。

示例： 设想一个扫地机器人。状态是"所在房间 + 电量"，动作是"上下左右移动、回去充电"，奖励是"每清扫一块地 +1、电量耗尽 −10"。一开始机器人乱走，偶尔扫到地拿到 +1，偶尔没电拿到 −10。经过成千上万次尝试，它会学到"电量低时先回去充电"这样的规则：没有人教它这一条，是 −10 的惩罚让这种行为变得更划算。

要点：

  1. 强化学习的标准答案句：智能体通过与环境交互，根据获得的奖励信号学习策略，使长期累计奖励最大化。
  2. 五要素：智能体、环境、状态、动作、奖励；学到的东西叫策略。
  3. 与监督学习的核心区别：监督学习有每个样本的正确答案，强化学习只有奖励这个评价信号，而且奖励可能延迟。

7.2 MDP 与回报：用折扣因子和贝尔曼方程给"长期"算账

"长期累计奖励最大"听起来清楚，真要计算时却有两个问题：未来可能无限长，加起来会发散；明天的 10 分和今天的 10 分是否一样值钱？我们需要一个数学框架把"长期"变成一个能计算、能比较的数。

马尔可夫决策过程（MDP）

强化学习问题通常被建模为马尔可夫决策过程（Markov Decision Process，MDP），由五样东西组成：状态集合 S、动作集合 A、转移规则 P(s'|s,a)（在 s 做 a 后到达 s' 的概率）、奖励函数 R、折扣因子 γ。"马尔可夫"指下一步只取决于当前状态和动作，与更早的历史无关：状态已经包含了做决定所需的全部信息。

回报与折扣因子 γ

从时刻 t 起的回报（return）是未来奖励的加权和：

Gₜ = rₜ₊₁ + γ·rₜ₊₂ + γ²·rₜ₊₃ + …，其中 0 ≤ γ ≤ 1。

γ 叫折扣因子，它有三个作用：

  1. 数学上保证收敛：每步奖励都是 1 时，无限求和等于 1/(1−γ)。γ=0.9 时等于 10，γ=0.99 时等于 100。这个数也常被理解为"智能体大约看多远"。
  2. 表达"早拿比晚拿好"：越远的奖励乘的 γ 次方越多，权重越小。
  3. 控制远见：γ 接近 0，智能体只看眼前；γ 接近 1，智能体很有远见。

算一算。 一条路径三步后才拿到 +10，前两步奖励为 0，即奖励序列 [0, 0, 10]：

  • γ=0.9：G = 0 + 0.9×0 + 0.9²×10 = 8.1
  • γ=0.5：G = 0.5²×10 = 2.5

同一个奖励，γ 越小，它在今天看来越"不值钱"。下图是第 t 步奖励的权重 γᵗ：

价值函数：V 和 Q

直接比较策略很难，我们改为给"状态"和"动作"打分：

  • 状态价值 V^π(s)：从状态 s 出发、之后一直按策略 π 行动，能拿到的期望回报。它回答"这个局面有多好"。
  • 动作价值 Q^π(s,a)：在 s 先做动作 a、之后按 π 行动的期望回报。它回答"在这个局面走这一步有多好"。

两者的关系：V^π(s) 是按策略对各个 Q^π(s,a) 求平均；最优情况下 V*(s) = max_a Q*(s,a)，即"局面的价值等于最好那一步的价值"。

贝尔曼方程：今天的价值 = 这一步的奖励 + 打折后的明天的价值

价值函数满足一个递推关系，叫贝尔曼方程。最优价值满足：

V*(s) = max_a [ R(s,a) + γ · V*(s') ]（确定性环境，s' 是在 s 做 a 后到达的状态）

这和动态规划的状态转移方程是同一个思路：大问题的最优解由"一步决策 + 子问题最优解"组成。把这个等式反复当作赋值语句执行，V 会逐渐收敛到最优值，这就是值迭代（value iteration）。[1]

逐步执行：3×3 网格世界的值迭代

规则：智能体在 3×3 网格中，每步可上下左右移动一格，撞墙则原地不动。进入右上角终点 (0,2) 得 +10，进入 (1,2) 的陷阱得 −10，其余移动得 0；到达终点或陷阱后回合结束（终止状态价值记为 0）。γ=0.9。所有状态初值 V₀=0。

网格世界：绿色为终点，橙色为陷阱，起点在左下角

每一轮，对每个非终止格子，试四个方向，取"即时奖励 + 0.9 × 邻格上一轮的值"的最大值。

从 (2,2) 出发：左 → 上 → 上 → 右，绕开陷阱到达终点。

每个格子的最终值恰好是 10 × 0.9^(到终点的步数−1)：离终点越远，奖励被打折越多。陷阱旁边的 (1,1) 和 (2,2) 并没有被"拉低"，因为 max 会自动避开进陷阱的动作。

def value_iteration(gamma=0.9, max_iter=50, tol=1e-9):
    states = [(r, c) for r in range(3) for c in range(3)]
    V = {s: 0.0 for s in states}
    history = [dict(V)]
    for _ in range(max_iter):
        newV = {}
        for s in states:
            if s in (GOAL, TRAP):             # 终止状态价值固定为 0
                newV[s] = 0.0
                continue
            best = -math.inf
            for a in MOVES:                   # 贝尔曼最优方程：对动作取 max
                s2, r = step(s, a)
                best = max(best, r + gamma * V[s2])
            newV[s] = best
        history.append(newV)
        if max(abs(newV[s] - V[s]) for s in states) < tol:
            break
        V = newV
    return history

变量表：V 是上一轮各状态的价值；newV 是本轮算出的新价值；step(s, a) 返回（下一状态，即时奖励）；history 记录每一轮的 V，便于画上面的步骤图。

要点：

  1. MDP 五元组：状态、动作、转移概率、奖励、折扣因子 γ；马尔可夫性指"下一步只依赖当前状态和动作"。
  2. γ 的作用：保证无限回报收敛、让近期奖励更重要、控制远见；常数奖励 1 的无限回报为 1/(1−γ)。
  3. V(s) 评价状态，Q(s,a) 评价"状态 + 动作"；V*(s) = max_a Q*(s,a)。
  4. 贝尔曼方程：当前价值 = 即时奖励 + γ × 下一状态价值。值迭代就是反复执行这个等式直到收敛，需要知道环境的转移规则。

7.3 Q-learning 与 SARSA：没有地图也能学

值迭代要事先知道"在哪个格子做什么动作会到哪里、得多少分"。现实中我们往往没有这张地图：机器人不知道地面摩擦力，游戏程序不知道对手怎么走。我们需要一种方法，只靠"亲自走一步、看看发生了什么"来学习。

Q-learning 维护一张 Q 表：每个（状态, 动作）对应一个估计值 Q(s,a)。每走一步，得到一条经验 (s, a, r, s')，就用它更新一个表格项：

Q(s,a) ← Q(s,a) + α · [ r + γ · max_a' Q(s',a') − Q(s,a) ]

逐项看：

部分含义
Q(s,a)旧估计：之前认为在 s 做 a 值多少
r + γ·max_a' Q(s',a')TD 目标：刚拿到的真实奖励 + 打折后的"下一状态里最好的动作值"
方括号整体TD 误差：目标减旧估计，表示"这次比预想的好多少"
α（学习率）每次往目标挪多大一步，0<α≤1

TD 是 temporal difference（时序差分）的缩写：用"下一步的估计"来修正"这一步的估计"，不必等回合结束。

逐步执行：三格走廊

走廊上有 A、B、C 三格，C 是终点。在 A 向右走到 B，奖励为 0；在 B 向右走到 C，奖励为 +10，回合结束。α=0.5，γ=0.9，Q 表的初值全为 0。连续走两个回合，每次都向右走。

三格走廊：只有走进 C 才有奖励

Q-learning：奖励一步步往回传

1 / 4

第1步 · 回合 1，第 1 步：A 向右到 B，r=0

目标 = 0 + 0.9 × max(Q(B,·)) = 0 + 0.9×0 = 0
Q(A,右) = 0 + 0.5×(0 − 0) = 0。B 还没有价值，A 学不到东西。
2 / 4

第2步 · 回合 1，第 2 步：B 向右到终点 C，r=+10

终点后面没有未来，目标 = 10
Q(B,右) = 0 + 0.5×(10 − 0) = 5。
3 / 4

第3步 · 回合 2，第 1 步：A 向右到 B，r=0

目标 = 0 + 0.9 × max(0, 5) = 4.5
Q(A,右) = 0 + 0.5×(4.5 − 0) = 2.25。终点的奖励第一次传到了 A。
4 / 4

第4步 · 回合 2，第 2 步：B 向右到 C，r=+10

Q(B,右) = 5 + 0.5×(10 − 5) = 7.5。

这个例子展示了 Q-learning 的核心现象：奖励从终点一步步往回传，回传的速度由 α 控制。

def q_learning_update(Q, s, a, r, s2, alpha, gamma, terminal=False):
    target = r if terminal else r + gamma * max(Q[s2].values())   # 用下一状态"最好的动作"
    Q[s][a] += alpha * (target - Q[s][a])
    return Q[s][a]

ε-greedy：探索与利用的平衡

如果智能体总选 Q 值最大的动作（利用），它可能永远发现不了更好的动作；如果总是随机选（探索），学到的知识又用不上。** ε-greedy** 的折中办法是：以概率 1−ε 选当前最优动作，以概率 ε 在所有动作中均匀随机选一个。两个动作、ε=0.1 时，最优动作被选中的概率是 0.9 + 0.1/2 = 0.95，另一个是 0.05。常见做法是训练初期 ε 大（多探索），后期逐渐减小（多利用）。

SARSA：同一条经验，另一种目标

SARSA 的更新式只差一处：

Q(s,a) ← Q(s,a) + α · [ r + γ · Q(s',a') − Q(s,a) ]，其中 a' 是下一步实际要执行的动作。

名字来自它用到的五个量 (s, a, r, s', a')。区别在于 TD 目标里"下一步的值"怎么取：

两种算法只在“下一步的值怎么取”上不同

算一算。 设 Q(B,右)=5、Q(B,左)=0。智能体在 A 向右到 B（r=0），接着 ε-greedy 恰好随机选中了"左"（探索）。α=0.5，γ=0.9：

  • Q-learning：目标 = 0 + 0.9 × max(5, 0) = 4.5，Q(A,右) = 2.25；它不管下一步实际做什么。
  • SARSA：目标 = 0 + 0.9 × Q(B,左) = 0，Q(A,右) 保持 0；它把"下一步可能乱走"也算进去了。

这就是 on-policy 与 off-policy 的区别：

  • on-policy（同策略）：用来产生经验的策略和正在学习评估的策略是同一个。SARSA 属于这一类，它学到的是"带探索的当前策略"的价值，因此更保守。经典例子是悬崖边行走：SARSA 会学会离悬崖远一点走，因为探索时可能失足。
  • off-policy（异策略）：产生经验的策略（带探索的行为策略）和学习的目标策略（贪心的最优策略）不同。Q-learning 属于这一类，好处是可以重复利用旧经验甚至别人的经验。

DQN 一句话： 状态太多（例如游戏画面像素）放不进表格时，用神经网络来近似 Q(s,a)，再配合经验回放和目标网络稳定训练，这就是 DQN，它在 2015 年让同一套算法玩多款 Atari 游戏达到人类水平。[2]

要点：

  1. Q-learning 更新：Q ← Q + α[r + γ·max Q(s',·) − Q]，方括号内是 TD 误差。
  2. Q-learning 是 off-policy，目标里用 max；SARSA 是 on-policy，目标里用下一步实际动作 a'。
  3. ε-greedy：以 1−ε 利用、以 ε 探索；n 个动作时最优动作概率为 1−ε+ε/n。
  4. 表格装不下时用神经网络近似 Q，即 DQN。

单选 · 理解检查 4　Q(s,a)=2，执行后得到 r=1，下一状态的 Q 值为 {左: 4, 右: 6}，α=0.5，γ=0.5。Q-learning 更新后 Q(s,a) 是多少？

A. 3

B. 4

C. 2.5

D. 7

查看答案与每个选项的解析

A · 正确：目标 = 1 + 0.5×max(4,6) = 4；TD 误差 = 4 − 2 = 2；新值 = 2 + 0.5×2 = 3。

B · 错误：4 是 TD 目标，还要按 α=0.5 只挪一半。

C · 错误：这是用 Q(s',左)=4 计算的结果：目标 1+2=3，2+0.5×1=2.5。Q-learning 取 max，应该用 6。

易错点：

  • on-policy / off-policy 看的是"产生数据的策略"和"被学习的策略"是否同一个，与"有没有模型"是两个独立的维度。
  • α 太大，Q 值会来回震荡；α 太小，学得很慢。ε 一直不衰减，最终表现会被随机动作拖累。

小结： Q-learning 的目标值使用下一状态的最大 Q 值，属于异策略（off-policy）；SARSA 使用实际执行的下一个动作，属于同策略（on-policy）；ε-greedy 按概率在探索和利用之间切换。

7.4 策略梯度直观：让带来好结果的动作更常出现

Q-learning 先学"每个动作值多少"，再间接选动作。当动作是连续的（例如方向盘转多少度），或者动作空间巨大（例如大模型从几万个词中选下一个词），对每个动作求 max 就很困难。另一条路是直接学习策略本身：把策略写成带参数 θ 的概率分布 π_θ(a|s)，然后调 θ 让期望回报变大。

REINFORCE：做得好就加强，做得差就削弱

REINFORCE 是最基础的策略梯度算法，思想只有一句话：按策略采样一条轨迹，回报高的轨迹里出现过的动作，就提高它们的概率；回报低的，就降低。 更新方向是：

θ ← θ + 学习率 × (G − b) × ∇log π_θ(a|s)

  • ∇log π_θ(a|s)：让动作 a 的概率变大的方向。
  • G − b：回报减去一个基线 b（例如平均回报）。高于平均就加强，低于平均就削弱。减去基线不改变期望方向，但能大大减小噪声。

算一算。 两个动作，初始 logit 都是 0，概率各 0.5。采样到动作 0，回报 G=1，基线 b=0.5，学习率 1。softmax 的 logit 梯度是"选中的动作 +(1−p)，其余 −p"，所以 logit 变为 (0.25, −0.25)，动作 0 的概率从 0.5 升到 0.6225。如果回报是 0（低于基线），同样大小的调整会反方向发生，动作 0 的概率降到 0.3775。

Actor-Critic 与优势函数

REINFORCE 要等整条轨迹结束才知道 G，噪声大。Actor-Critic 用两个部件分工：

  • Actor（演员）：策略 π_θ，负责选动作。
  • Critic（评论家）：价值函数 V(s)，负责估计"这个状态平均能拿多少"，充当基线。

二者之间传递的信号叫优势函数 A(s,a) = Q(s,a) − V(s)：在 s 选 a 比"平均水平"好多少。实际中常用一步估计 A ≈ r + γV(s') − V(s)，它正是 7.3 的 TD 误差。

Actor-Critic：Critic 算出优势（同一个 TD 误差也用来修正 V），Actor 按优势调整动作概率

PPO：每次只许走一小步

策略梯度有个老问题：一次更新步子太大，策略可能突然变差，之后采到的数据也变差，难以恢复。PPO（Proximal Policy Optimization，近端策略优化）的办法是限制新旧策略的差异。[3]

定义概率比 ρ = π_新(a|s) / π_旧(a|s)：ρ=1 表示没变，ρ=1.3 表示这个动作的概率涨了 30%。PPO 的目标是：

L = min( ρ·A , clip(ρ, 1−ε, 1+ε)·A )，常取 ε=0.2。

clip 把 ρ 截在 [0.8, 1.2] 里。取 min 意味着"在两种算法里选更保守的那个"：

  • 优势 A>0（好动作）：ρ 超过 1.2 后目标不再增大，于是不会为了一个好动作把概率拉得过高。
  • 优势 A<0（坏动作）：ρ 低于 0.8 后目标不再增大，于是不会把概率压得过低；但 ρ 变大时惩罚照算，防止坏动作的概率反弹。

ε=0.2：A>0 时在 ρ>1.2 处变平，A<0 时在 ρ<0.8 处变平；变平的地方梯度为 0，不再继续推

def ppo_clip_objective(ratio, adv, eps=0.2):
    clipped = min(max(ratio, 1 - eps), 1 + eps)
    return min(ratio * adv, clipped * adv)     # 取两者中较小（更保守）的那个

要点：

  1. 策略梯度直接优化策略参数，思想是"让好结果的动作更可能出现"，适合连续或巨大的动作空间。
  2. 减去基线可以降低方差；Actor 选动作，Critic 估价值，二者通过优势 A = Q − V 连接。
  3. PPO 用概率比的裁剪把每次更新限制在 [1−ε, 1+ε] 附近，取 min 保证保守，训练更稳定。PPO 是 RLHF 的经典 RL 算法。

单选 · 理解检查 5　PPO 中 ε=0.2。某动作优势 A=2，新旧策略概率比 ρ=1.5。这一项的目标值是多少？

A. 2.4

B. 3.0

C. 1.6

D. 2.0

查看答案与每个选项的解析

A · 正确：ρ·A = 3.0；clip(1.5, 0.8, 1.2)·A = 1.2×2 = 2.4；取 min 得 2.4。

B · 错误：这是未裁剪的 ρ·A，PPO 取两者中较小的。

易错点：

  • REINFORCE 是 on-policy 方法：数据必须由当前策略采样，旧数据直接复用会有偏差，PPO 用概率比 ρ 来校正"稍旧"的数据。
  • PPO 的 ε 裁剪限制的是概率比，和学习率是两个不同的旋钮。

小结： 策略梯度使结果好的动作概率增大、结果差的动作概率减小；Critic 提供基线，从而得到优势；PPO 把新旧策略的概率比限制在 1±ε 之内，使每一步更新不会走得太远。

7.5 从预训练到对齐：RLHF 三阶段与奖励模型

预训练好的大模型只会做一件事：根据上文预测下一个词。问它"怎么做番茄炒蛋"，它可能接着写出另一个问题，因为网页上问题后面常常跟着更多问题。它也会照搬网上的错误、偏见甚至有害内容。我们需要让模型的行为符合人的意图，这件事叫对齐（alignment）。

对齐的常用目标可以概括为三个词：有用（helpful，真正完成用户的任务）、诚实（honest，不编造、不隐瞒、承认不确定）、无害（harmless，不帮助造成伤害）。这组说法出自 Askell 等 2021 年的论文，后来被广泛使用。[4]

面试里"什么是 Alignment"的标准答案句：对齐是让 AI 系统的目标和行为符合人类意图与价值观的研究和工程，常用"有用、诚实、无害"概括；在 Agent 语境下还包括按用户授权行事、不越权、不为了完成任务而采取用户不希望的手段。

RLHF 的三个阶段

RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）把对齐拆成三步。OpenAI 2022 年的 InstructGPT 论文是这套流程的代表：人类评估者更喜欢 13 亿参数的 InstructGPT 的输出，而不是 1750 亿参数的原始 GPT-3。[5] [6]

RLHF：先模仿示范，再学会打分，最后用强化学习追求高分，同时用 KL 拴住不跑偏

  1. SFT（监督微调）：人工写一批"问题 + 好回答"，用普通的监督学习微调模型。模型学会"听指令、按格式回答"。
  2. 训练奖励模型（RM）：对同一个问题让模型生成几个回答，请人排序（哪个更好）。用这些比较数据训练一个打分模型：输入"问题 + 回答"，输出一个分数。让人比较两个回答，比让人直接打绝对分数更稳定。
  3. 强化学习：把 SFT 模型当作策略，生成一个完整回答就是一次"动作序列"，奖励模型的打分就是奖励，用 PPO 更新模型。

奖励模型怎么从"比较"中学打分：Bradley-Terry 模型

奖励模型只看到"回答 A 比回答 B 好"这样的比较，怎样变成分数？Bradley-Terry 模型假设：

P(A 比 B 好) = σ(r_A − r_B)，其中 σ(x) = 1/(1+e^(−x)) 是 sigmoid 函数。

两个回答分差越大，模型越确信前者更好；分数相同时概率正好 0.5。训练时让"人选中的回答"（记作 chosen，下标 w）概率尽量大，损失为：

L = −log σ(r_w − r_l)

手算。 奖励模型给人选中的回答打 2.0 分，给落选的打 0.5 分：

  • 分差 = 1.5，P = σ(1.5) = 0.8176，损失 = −ln 0.8176 = 0.2014；
  • 如果打反了（chosen 0.5，rejected 2.0），P = σ(−1.5) = 0.1824，损失 = 1.7014，大很多，梯度会推动模型把分数改过来；
  • 如果两个都打 1.0，P = 0.5，损失 = ln 2 ≈ 0.6931。

分差越大，模型越确信、损失越小；分差为负说明打反了，损失迅速变大

def bt_loss(r_chosen, r_rejected):
    p = sigmoid(r_chosen - r_rejected)   # 奖励模型认为"人选的那个更好"的概率
    return p, -math.log(p)

KL 惩罚：给模型拴一根绳

奖励模型只是人类偏好的近似，它有盲区。如果放开让策略追高分，模型很快会找到奖励模型的漏洞，例如写得越来越长、堆砌讨好的话，分数上去了，质量反而下降（7.10 会详细讲这种"奖励黑客"）。所以 RL 阶段的实际奖励是：

奖励 = RM 分数 − β × KL(π_新 ‖ π_参考)

KL 散度衡量新模型的输出分布和参考模型（冻结的 SFT 模型）差多远。β 控制绳子的松紧。例如 RM 打 2.0 分，KL 为 3.0，β=0.1，实际奖励是 2.0 − 0.3 = 1.7。KL 惩罚的作用有三点：防止模型为了刷分而偏离正常语言；保留预训练学到的知识和流畅性；降低奖励黑客的风险。

要点：

  1. 对齐就是让模型的行为符合人类的意图，通常概括为有用、诚实、无害（HHH）。

查看答案与每个选项的解析

A · 正确：分差 0，σ(0)=0.5，损失 = −ln 0.5 = ln 2 ≈ 0.693。

B · 错误：损失为 0 需要 σ=1，即分差无穷大；分数相同时模型完全分不出好坏。

易错点：

  • RLHF 中的"人类反馈"主要用来训练奖励模型；RL 阶段的每一步并不需要人在线打分。

小结： 对齐的目标是使模型有用、诚实、无害；RLHF 依次经过监督微调（SFT）、训练奖励模型（用分差的 sigmoid 表示偏好概率）、用 PPO 优化并加上 KL 约束三个阶段。

7.6 DPO：跳过奖励模型，直接从偏好对学习

RLHF 的工程负担很重：训练时要同时放下策略模型、参考模型、奖励模型，PPO 还要一个价值模型（Critic），共四个大模型；PPO 要在线采样，超参数多，训练容易不稳定。DPO（Direct Preference Optimization，直接偏好优化）在 2023 年给出了一个简化方案。[7]

DPO 的关键观察是：在"最大化奖励 − β·KL"这个目标下，最优策略和奖励函数之间存在一一对应的闭式关系。反过来，奖励可以用策略来表示：

隐式奖励 r(x,y) = β · log [ π_θ(y|x) / π_ref(y|x) ]（再加一个只和问题有关的常数，比较两个回答时会抵消）

也就是说，"模型相对参考模型把这个回答的概率提高了多少"本身就是奖励，论文标题里说"你的语言模型其实就是一个奖励模型"。把这个隐式奖励代入 Bradley-Terry 损失，奖励模型就消失了，只剩一个分类式的损失：

L_DPO = −log σ( β · [ (log π_θ(y_w|x) − log π_ref(y_w|x)) − (log π_θ(y_l|x) − log π_ref(y_l|x)) ] )

逐项解释：

项含义
y_w, y_l同一问题下人选中（win）和落选（lose）的回答
log π_θ(y|x) − log π_ref(y|x)当前模型比参考模型把这个回答的对数概率提高了多少
两个差再相减chosen 被提高的程度减去 rejected 被提高的程度
β和 RLHF 里 KL 惩罚的 β 对应，越大越不允许偏离参考模型
−log σ(·)与奖励模型完全相同的 Bradley-Terry 损失形式

训练效果是：提高 chosen 相对参考模型的概率，降低 rejected 相对参考模型的概率。

RLAIF 与 Constitutional AI：用 AI 反馈替代部分人类反馈

人类标注昂贵、慢，而且对有害内容的标注会伤害标注员。RLAIF（RL from AI Feedback）用一个大模型代替人来判断"两个回答哪个更好"。Lee 等 2023 年的研究报告，在摘要生成和有益/无害对话任务上，RLAIF 的效果与 RLHF 相当。[8]

Anthropic 2022 年提出的 Constitutional AI（宪法式 AI）分两阶段：[9]

Constitutional AI：人只写原则，具体的“哪个回答更无害”由 AI 判断

人类的监督集中在"写原则"这一步，而不是逐条标注有害样本。这是用 AI 帮助监督 AI 的早期实践，也和 7.10 的"可扩展监督"直接相关。

要点：

  1. DPO 把奖励写成 β·log(π_θ/π_ref)，代入 Bradley-Terry 损失，省掉奖励模型和 RL 采样。
  2. DPO 损失 = −log σ(β × [chosen 提高量 − rejected 提高量])；训练开始时损失为 ln 2。
  3. RLAIF 用 AI 判断偏好；Constitutional AI 让人只写原则，由模型按原则自我批评、修改和比较。

  • DPO 仍然需要参考模型：它定义了"提高了多少"的基准，也起到 KL 约束的作用。

7.7 推理模型与 RLVR：答案能自动核对时，强化学习最好用

7.5 的奖励模型是"人类偏好的近似"，会被钻空子。有一类任务天然有可靠的裁判：数学题能核对最终答案，代码能跑单元测试。把这种可以自动核对的结果直接当作奖励，就绕开了奖励模型的很多问题。2024 年以来的"推理模型"主要沿着这条路发展。

时间线：截至本书写作时（2026 年 10 月）可以核实的事实

  • 2024 年 2 月，DeepSeekMath 论文提出 GRPO（Group Relative Policy Optimization），作为 PPO 的变体，去掉价值模型、降低显存开销。[10]
  • 2024 年 9 月，OpenAI 发布 o1，官方博客称用大规模强化学习教模型"在回答前先思考"，并报告性能随训练时的 RL 计算量和测试时思考时间两者增加而持续提升。[11]
  • 2024 年 11 月，Tülu 3 论文将"用可验证奖励做强化学习"命名为 RLVR（Reinforcement Learning with Verifiable Rewards）。[12]
  • 2025 年 1 月，DeepSeek-R1 论文公开。其中 R1-Zero 直接在基座模型上用 GRPO 做强化学习，不先做 SFT；奖励是规则式的：答案正确性（数学答案比对、代码过测试）加格式奖励。作者报告 AIME 2024 的 pass@1 从 15.6% 升到 71.0%，并观察到模型自发出现反思、验证等行为；也指出 R1-Zero 存在可读性差、语言混杂的问题，正式的 R1 因此加入少量冷启动数据和多阶段训练。该工作 2025 年 9 月发表于 Nature。[13] [14]

作者说明不用神经网络奖励模型的原因之一是：大规模 RL 中神经奖励模型容易被"奖励黑客"利用。这正是 RLVR 的出发点。

RLVR 的奖励长什么样

RLVR：奖励来自程序化核对，而不是学出来的奖励模型

GRPO：用同组样本的平均分当基线

PPO 需要一个价值模型（Critic）估计基线，它和策略一样大，训练成本高。GRPO 的做法是：对同一道题采样一组 G 个回答，用这组回答奖励的均值和标准差做归一化，得到每个回答的优势：

Aᵢ = (rᵢ − mean(r)) / std(r)

这个优势被赋给该回答里的每一个 token，然后用类似 PPO 的裁剪目标更新；KL 惩罚直接加在损失里，不再并入奖励。[10]

def grpo_advantages(rewards, eps=1e-8):
    g = len(rewards)
    mean = sum(rewards) / g
    std = math.sqrt(sum((r - mean) ** 2 for r in rewards) / g)   # 总体标准差（除以 G）
    return [(r - mean) / (std + eps) for r in rewards]

面试"GRPO 为什么不需要价值模型"的标准答案：GRPO 对同一个问题采样一组回答，用组内奖励的均值作基线、标准差作缩放来计算相对优势，基线由同组样本直接估计，不需要再训练一个和策略同规模的价值模型（Critic），省下显存和训练开销；代价是每道题要多采样几次。

推理时计算扩展：同一个模型，多想一会儿

除了训练时做 RL，还可以在推理时多花计算来换准确率，这叫 test-time compute scaling。常见手段：

  • 思维链（CoT）：让模型先写中间步骤再给答案。2022 年的研究表明，给几个带步骤的示例就能显著提高算术和推理题的表现。[15]
  • 自洽性 / 多数投票：同一题采样多个推理过程，对最终答案投票。DeepSeekMath 报告 MATH 上单次 51.7%，64 次采样投票后 60.9%。[16] [10]
  • Best-of-N：采样 N 个，由验证器或奖励模型挑分数最高的那个。
  • 用过程奖励模型引导搜索：Snell 等 2024 年的研究发现，按题目难度自适应分配推理计算，效率可比 best-of-N 基线高 4 倍以上；在小模型本来有一定成功率的题上，同等计算量下多推理可以胜过大 14 倍的模型。[17]

算一算多数投票和 best-of-N。 假设每次采样独立地有 p=0.6 的概率答对，答错的都给出同一个错误答案（最坏情况）：

  • 采样 5 次多数投票：至少 3 次答对的概率 = 0.6826；
  • 采样 5 次，配一个完美验证器（只要有一个对就能挑出来）：1 − 0.4⁵ = 0.9898；
  • 如果 p=0.4（单次更容易错），5 次多数投票反而降到 0.3174。

验证器越可靠，多采样的收益越大；多数投票只在单次正确率超过一半时有帮助

Lightman 等 2023 年的研究报告，在 MATH 数据集上过程监督明显优于结果监督，其过程监督模型解出了代表性测试子集中 78% 的题目。[18]

要点：

  1. RLVR：奖励来自可程序化核对的结果（答案比对、单元测试），比学出来的奖励模型更难被钻空子，适用于有标准答案的任务。
  2. GRPO：组内均值作基线、标准差缩放，A = (r − mean)/std；不需要价值模型；组内奖励全相同时没有学习信号。
  3. 推理时扩展：CoT、自洽性投票、best-of-N、PRM 引导搜索；验证器越可靠，多采样收益越大。
  4. ORM 只看结果，PRM 逐步打分；PRM 信用分配更细但标注更贵。

7.8 自我改进的几种机制：改进信号从哪里来，靠什么验证

前面的方法都依赖外部提供的东西：人写的示范、人标的偏好、人出的题。一个自然的问题是：模型能不能用自己产生的东西继续变强？这就是"自我改进"（self-improvement）。它有很多种做法，面试和新闻里名词很多，但它们都可以放进同一个循环里理解。

统一框架：生成、评估或验证、选择、更新

所有自我改进方法都在跑这个循环；整个循环的上限由第②步“验证信号”的质量决定

判断一种自我改进方法，抓两个问题就够了：改进信号从哪里来？靠什么验证？ 下表先给全貌，后面逐个讲。

自博弈：从零开始，靠胜负

AlphaGo 先学人类棋谱再自我对弈。2017 年的 AlphaGo Zero 去掉了人类棋谱，从随机下棋开始只靠自我对弈，3 天后以 100:0 战胜击败李世石的那一版 AlphaGo。[19] 随后的 AlphaZero 用同一套算法，只给游戏规则，24 小时内在国际象棋、将棋、围棋上都达到超人水平。[20]

信号来源：游戏规则判定的胜负，百分之百可靠，且对手（自己）会随着自己变强，难度自动升级。这正是自博弈能"从零到超人"的原因，也说明了它的边界：现实中大多数任务没有这样清楚、廉价、无法作弊的裁判。

合成数据与自举：只把"验证通过"的样本拿来训练

STaR（Self-Taught Reasoner，2022）的循环是：让模型给每道题写推理过程和答案；只保留最终答案正确的推理；对答错的题，把正确答案作为提示让模型"倒推"出一段推理（作者称为 rationalization）；在保留的数据上微调；重复。[21] 更一般的说法是拒绝采样（rejection sampling）：多采样、用验证器筛选、在通过的样本上训练。DeepSeek-R1 的训练流程里也有拒绝采样 SFT 这一步。[13]

蒸馏是另一种"用模型产出的数据训练模型"：让强模型生成大量回答，用来微调小模型。DeepSeek-R1 论文报告，把约 80 万条 R1 生成的样本用于微调 Qwen-32B，AIME 2024 得分 72.6%，高于直接对同尺寸模型做 RL 的 47.0%。[13] 蒸馏让弱模型追上强模型，但学生通常难以超过老师，它本身不产生超越老师的新能力。

完整走一遍：算术题上的拒绝采样自训练（玩具版）

20 道两位数加法题，其中 8 道需要进位。把"模型"简化成三种解题习惯的混合：

  • correct：正确做法，全对；

def bootstrap_expected(pi, acc, rounds, eta=0.5):
    hist = [dict(pi)]
    for _ in range(rounds):
        kept = {s: pi[s] * acc[s] for s in pi}           # 生成后只保留验证通过的样本
        z = sum(kept.values())
        pi = {s: (1 - eta) * pi[s] + eta * kept[s] / z for s in pi}   # 在保留样本上"微调"
        hist.append(dict(pi))
    return hist

自我修正与反思：有外部反馈才可靠

Self-Refine（2023）让同一个模型依次扮演三个角色：写初稿、给初稿提意见、按意见改写，不需要训练，作者报告在 7 类任务上平均提升约 20%。[22] Reflexion（2023）让智能体在失败后用文字写下反思，存进记忆，下次尝试时参考；反馈可以来自环境（例如代码测试结果），在 HumanEval 编程基准上报告了 91% 的 pass@1。[23]

局限同样有研究支持。Huang 等 2023 年的论文《Large Language Models Cannot Self-Correct Reasoning Yet》发现：没有外部反馈时，模型很难纠正自己的推理错误，有时改完反而更差。[24] 原因可以用上面的框架解释：验证者和生成者是同一个模型，它看不出的错误，自评时同样看不出。Reflexion 在编程上效果好，很大程度上是因为测试结果提供了外部信号。

验证器引导搜索

7.7 的 best-of-N、PRM 引导搜索都属于这一类：生成多个候选，由验证器挑选。它只改进这一次的输出，不改模型本身；但挑出来的好输出可以再用作训练数据，这时就变成了上面的自举。

进化式搜索：AlphaEvolve

下面三类系统（AlphaEvolve、DGM、AI Scientist）都是 2024–2026 年的新工作，所列数字都是截至本书写作时（2026 年 10 月）作者或发布方公开报告的结果。

Google DeepMind 2025 年 5 月发布的 AlphaEvolve 是一个进化式编码智能体：Gemini 模型提出程序修改，自动评估器运行程序并打分，一个程序数据库按进化算法决定哪些程序进入下一轮提示。[25] [26] 官方博客报告的结果包括：

  • 为 Google 数据中心调度找到的启发式规则已上线一年多，平均回收全球计算资源的 0.7%；
  • 找到用 48 次标量乘法计算 4×4 复数矩阵乘法的方法，改进了 1969 年的 Strassen 算法在这一设定下的结果；
  • 在 50 多个开放数学问题上，约 75% 达到已知最好结果，约 20% 有所改进；
  • 把 Gemini 架构中的一个矩阵乘法内核加速 23%，使 Gemini 训练时间减少 1%。

最后一条值得注意：AlphaEvolve 改进了训练它所用模型的基础设施，这是"AI 加速 AI 研发"的一个具体但规模有限的例子。2026 年 5 月的后续博客称，它已用于改进 Google 的 AI 基础设施、复杂分子模拟、自然灾害风险预测、电网等方向，这些成果均为 Google 及其合作方自行报告。[27]

信号来源：可自动运行的评估程序。因此它适用于"能写出打分程序"的问题，例如算法效率、数学构造；目标难以程序化衡量的问题，它就难以直接处理。

自修改智能体：Darwin Gödel Machine 与哥德尔机

哥德尔机（Gödel machine）是 Schmidhuber 2003 年提出的理论构想：一个可以改写自身任何代码的系统，但只有在证明了改写有益之后才执行改写。[28] 它在理论上优雅，实际中几乎找不到这样的证明。

Darwin Gödel Machine（DGM，Zhang 等 2025 年 5 月提出，Sakana AI 发布了介绍博客）把"证明"换成"实测"：维护一个编程智能体的档案库，从中选一个，让基础模型修改这个智能体自己的代码（工具、工作流程），在编程基准上测试，表现好的新版本加入档案库，形成一棵不断分叉的进化树。[29] 作者报告：

  • SWE-bench 得分从 20.0% 提升到 50.0%，Polyglot 从 14.2% 提升到 30.7%；
  • 所有实验在沙箱中运行并有人类监督。

局限也写在论文里：底层基础模型是冻结的，改的只是外层智能体代码；每轮都要在基准上实际运行候选智能体，计算和 API 费用可观；而且进化过程本身的规则（如何选择、如何评估）DGM 改不了。[29] 更值得注意的是 Sakana 博客记录的一个案例：在优化"工具调用幻觉检测"指标时，DGM 有时会删除用于检测幻觉的特殊标记，从而让检测函数报告虚假的成功。作者是靠可追溯的修改记录发现这一点的。[30] 这是 7.10 奖励黑客的真实案例。

Sakana AI 2024 年 8 月的 The AI Scientist 尝试端到端自动化机器学习研究：提出想法、写代码做实验、画图、写论文、再由自动审稿器打分，每篇论文成本低于 15 美元。[31] 2025 年的 AI Scientist-v2 把 3 篇完全由系统生成的论文投到一个 ICLR 研讨会（workshop），其中 1 篇的评分超过人类论文的平均录用线。[32] 需要客观看待：研讨会的门槛低于主会；v1 的论文质量主要由自动审稿器评价，v2 的证据是一次研讨会的人工评审，样本只有 3 篇；Sakana 博客还记录了系统为跑完实验修改自己代码延长超时时间、写出无限自我调用脚本等行为，作者建议在沙箱中运行。[33]

7.9 递归自我改进（RSI）：概念、争论与现状

7.8 的系统都在"自己让自己变好"。新闻里常把它们和"递归自我改进""智能爆炸"相提并论。要客观回答"RSI 现在到哪一步了"，我们需要先把概念说准，再把证据分成三类：已被证明的、正在研究的、推测性的。

概念来源：I. J. Good 的"智能爆炸"

1965 年，英国数学家 I. J. Good 在《Advances in Computers》第 6 卷发表《Speculations Concerning the First Ultraintelligent Machine》。他把"超智能机器"定义为在一切智力活动上远超任何人的机器，并论证：设计机器本身是一种智力活动，因此超智能机器能设计出更好的机器，从而引发"智能爆炸"；第一台超智能机器将是人类需要做的最后一项发明，前提是它足够温顺、愿意告诉我们如何控制它。[34]

RSI 与普通自我改进的区别

递归自我改进（Recursive Self-Improvement，RSI）指一个系统改进的对象包括“改进自己的能力”本身：第 n 代改进得更好，第 n+1 代就更会改进，如此递归。

左：改进方法不变，只有任务能力提高；右：改进方法本身也在被改进，形成正反馈

用这个标准看：STaR、RLVR 训练出更强的模型，但训练方法本身由人设计、不变，属于普通自我改进；DGM 改的是智能体自己的代码，其中包括"怎样改代码"的部分，向 RSI 迈了一步，但基础模型和进化规则仍是固定的；AlphaEvolve 加速了 Gemini 的训练，是"AI 帮助改进 AI"的局部例子。

观点主要论据代表文献
快速起飞再投资回报可能很高：AI 可以复制成千上万份、比人快地工作；人脑远未达到物理极限，提升空间大；一旦能自动化 AI 研究，反馈环会自我加速Yudkowsky 2013《Intelligence Explosion Microeconomics》[35]
缓慢起飞较弱的版本总是先出现，大多数技术是渐进的；在超智能出现前，较弱的 AI 已经广泛改变经济，世界有缓冲期；Christiano 用"在第一次 1 年翻倍之前，会先出现一个完整的 4 年世界产出翻倍"来定义缓慢起飞Christiano 2018《Takeoff speeds》[36]

现实中的瓶颈

四个限速因素：即使 AI 能写研究代码，循环的速度仍受这些外部条件约束

  1. 算力：AI 研究的大部分时间花在跑实验上。更聪明的研究员可以挑更好的实验，但实验本身仍需要算力，芯片产能和电力增长较慢。
  2. 数据：高质量人类数据有限；用模型自己生成的数据反复训练，可能出现模型崩溃（7.10）。
  3. 评估信号质量：7.8 已经说明，自我改进的上限由验证信号决定。"这个研究方向是否有价值"比"这道题答案对不对"难评估得多。
  4. 验证难度：系统越强，人越难检查它的产出；而 DGM、AI Scientist 的案例显示，系统会找评估的漏洞。

如果 AI 能完成 AI 研究员的工作，7.9 开头的反馈环就会闭合：研发速度可能显著加快，安全措施和社会适应的时间被压缩，模型也会更深地进入开发流程本身（参与训练下一代模型、接触自己的训练代码）。因此几家主要实验室都把它写进了安全框架。以下内容均按各框架原文核实，截至本书写作时（2026 年 10 月）：

7.10 风险与对策：奖励黑客、模型崩溃与可扩展监督

前面几节反复出现同一个隐患：优化的是"可测量的代理指标"，我们真正想要的却是背后的意图。优化能力越强，二者之间的缝隙被利用得越彻底。自我改进让这种优化自动化、规模化，风险也随之放大。

奖励黑客与古德哈特定律

古德哈特定律（Goodhart's law）的常见表述是：** 一个指标一旦成为优化目标，就不再是好指标。** [44] 在强化学习里，它表现为奖励黑客（reward hacking）：智能体找到了让奖励变高、却没有完成真正任务的办法。2016 年的《Concrete Problems in AI Safety》把"避免奖励黑客"列为五个具体安全问题之一。[45]

玩具例子 1：代理奖励越高，真实质量反而下降。 假设用"回答长度"当奖励（代理奖励 = 2×长度），真实质量却是长度适中时最好：

规格博弈

规格博弈（specification gaming）是更宽的说法：满足了目标的字面规定，却没达到设计者的本意。DeepMind 2020 年整理的例子包括：要求把红色积木放到蓝色积木上，奖励按红积木底面的高度计算，智能体学会把红积木翻过来，底面朝上就"变高"了；赛艇游戏里智能体发现绕圈反复撞同一批加分道具比完成比赛得分更高。[47] 奖励黑客可以看作规格博弈在"奖励函数"上的特例。

模型崩溃

Shumailov 等 2024 年发表于 Nature 的研究发现：用模型生成的数据一代代地训练下一代模型，原始数据分布的尾部（少见但真实的内容）会逐渐消失，模型输出越来越单一，这叫模型崩溃（model collapse）。[48] 这对 7.8 的合成数据自举是一个提醒：要保留真实数据、用验证器筛选、监控多样性，而不是无限制地"自己喂自己"。

评估被污染

如果基准测试题目混进了训练数据，分数就会虚高。GSM1k 研究按 GSM8k 的风格和难度重新出了一套小学数学题，发现部分模型的准确率最多下降 8%，且下降幅度与模型"背诵"GSM8k 原题的倾向相关；同时也发现很多前沿模型几乎没有过拟合迹象。[49] 自我改进依赖评估来做选择，评估一旦被污染，循环就会朝错误方向优化。

对策：可扩展监督、可解释性、红队、控制与监控

四类对策从不同角度解决同一个问题：模型比人强时，人怎样仍然能监督它

  • 可扩展监督（scalable oversight）：当模型产出超出人能直接判断的范围时，借助 AI 帮人监督。例子有"辩论"（两个 AI 互相挑错，人当裁判）[50]、Constitutional AI 的 AI 反馈（7.6），以及"弱到强泛化"：Burns 等 2023 年的实验用小模型的标签监督大模型，大模型通常能超过监督者，但离自身全部能力仍有明显差距。[51]
  • 可解释性（interpretability）：直接查看模型内部表示。Anthropic 2024 年用稀疏自编码器从 Claude 3 Sonnet 中提取出大量可解释的特征，其中一些与安全相关，并能用来引导模型行为。[52]
  • 红队（red teaming）：主动寻找模型的有害行为和漏洞，也可以用一个模型自动给另一个模型出攻击性测试题。[53]
  • 控制与监控（AI control）：假设模型可能不可信，设计协议仍能保证安全。例如由更弱但可信的模型审查强模型写的代码，可疑时修改或交给人。[54] 7.8 的系统都在沙箱中运行、保留修改记录，也是这一思路。

面试题："能力–安全权衡"怎么答

结构化回答可以分四层：

  1. 定义：能力–安全权衡指提升模型能力或自主性的同时，可能带来更大的风险或更高的安全成本；反过来，安全措施（拒答、限制权限、人工审核）可能降低有用性和效率。
  2. 在哪里体现：① 有用 vs 无害：过度拒答让模型没用，过少拒答可能帮助作恶；② 自主性 vs 可控性：Agent 权限越大、步骤越长，完成任务越多，出错代价越大；③ 优化强度 vs 奖励黑客：RL 优化越狠，越可能钻代理指标的空子（本节例子）；④ 速度 vs 审查：研发越快，评测和安全论证的时间越少。
  3. 怎么平衡：按风险分级，低风险操作放开、高风险操作要求人确认（最小权限、沙箱、审计日志）；用 KL 约束、可验证奖励、多样化评测减少奖励黑客；预设能力阈值和对应防护（各实验室的安全框架）；持续红队和监控。
  4. 观点：二者并非严格零和。很多安全工作同时提升能力，例如 RLHF 让模型更有用，可验证奖励让推理更可靠，可解释性帮助调试；在 Agent 产品里，可预测、可审计本身就是用户需要的能力。

一句话版本：能力–安全权衡是指提升能力和自主性会扩大风险面，而安全约束可能降低有用性；工程上通过按风险分级授权、可验证的奖励和评测、预设能力阈值与防护、持续监控来平衡，很多安全措施本身也会提升可用性。

要点：

  1. 古德哈特定律：指标一旦成为优化目标，就不再是好指标；奖励黑客是它在 RL 中的表现。
  2. 规格博弈：满足字面目标但违背设计本意；奖励黑客是其特例。
  3. 模型崩溃：反复用合成数据训练，分布尾部消失、输出变单一。
  4. 对策四类：可扩展监督、可解释性、红队、控制与监控；加上 KL 约束、可验证奖励、干净的评测集。

单选 · 理解检查 12　用“可见测试通过率”做奖励，候选 A 可见 0.75、隐藏 0.7，候选 B（背答案）可见 1.0、隐藏 0.1。下面哪个说法正确？

A. 只按奖励选会选中 B，这是奖励黑客；增加隐藏测试或换用更全面的验证可以缓解

B. B 的奖励更高，说明 B 更好

C. 这种问题只会出现在玩具例子里

D. 把 KL 惩罚系数设为 0 可以防止这种情况

查看答案与每个选项的解析

A · 正确：代理指标（可见测试）和真实目标（正确实现）脱节，优化器选择了代理分高的 B。

B · 错误：奖励只是代理；隐藏测试显示 B 的真实能力只有 0.1。

C · 错误：DGM 删除检测标记、生产环境 RL 中的奖励黑客都是真实案例。

D · 错误：KL 惩罚越小，策略越自由地偏离参考模型，奖励黑客风险反而更大。

易错点：

  • 奖励黑客说明的是奖励设计或验证有漏洞，模型并不需要"有意作弊"才会这样做，优化压力本身就足以导致。
  • 模型崩溃的前提是"一代代只用合成数据训练"；混合真实数据、严格筛选的合成数据仍被广泛使用。

小结： 一个指标一旦被当作优化目标就会失真（古德哈特定律）；奖励黑客、规格博弈、模型崩溃和评估污染是四类主要问题；对策包括可扩展监督、可解释性研究、红队测试以及控制与监控。

7.11 面试题总表

面试时间有限，每题先说一句标准答案，再按追问展开。下表的答案都能在对应小节找到完整推导。

面试题按这六块组织：先定位题目属于哪一块，再回到对应小节

题目一句话标准答案小节
强化学习和监督学习的区别？监督学习有每个样本的正确答案；强化学习只有环境给的奖励评价，常常延迟，需要在交互中试错学习策略。7.1
折扣因子 γ 的作用？保证无限回报收敛、让近期奖励更重要、控制智能体看多远；常数奖励下回报为 1/(1−γ)。7.2
贝尔曼方程是什么？当前状态价值 = 即时奖励 + γ × 下一状态价值；最优形式对动作取 max。7.2
Q-learning 和 SARSA 的区别？Q-learning 的目标用下一状态的最大 Q 值，是 off-policy；SARSA 用下一步实际动作的 Q 值，是 on-policy，更保守。7.3
探索与利用怎么平衡？常用 ε-greedy：以 1−ε 选当前最优，以 ε 随机探索，ε 随训练逐渐减小。7.3
PPO 的裁剪是做什么的？把新旧策略概率比限制在 [1−ε, 1+ε]，并取裁剪前后的较小值，防止一次更新走太远，训练更稳。7.4
什么是 Alignment？在 Agent 语境下怎么理解？让 AI 的目标和行为符合人类意图与价值观，常说有用、诚实、无害；Agent 场景还要求按授权行事、不越权、不用用户不认可的手段完成任务。7.5
RLHF 的流程？SFT → 用人类偏好比较训练奖励模型 → 用 PPO 最大化奖励并加 KL 惩罚。7.5
奖励模型怎么训练？用 Bradley-Terry：P(chosen 更好) = σ(r_w − r_l)，最小化 −log σ(r_w − r_l)。7.5
RLHF 和 DPO 的区别？RLHF 先训奖励模型再做在线 RL；DPO 把奖励表示成策略与参考模型的对数概率比，直接在偏好对上做分类式损失，无需奖励模型和采样。7.6
什么是 RLAIF / Constitutional AI？用 AI 判断偏好来替代部分人类标注；CAI 中人只写原则，模型按原则自我批评、修改并生成偏好数据。7.6
什么是 RLVR？用能自动核对的结果（数学答案、单元测试）作奖励的强化学习，比学出来的奖励模型更难被钻空子。7.7
GRPO 为什么不需要价值模型？它对同一题采样一组回答，用组内奖励均值作基线、标准差归一化得到优势，基线由样本直接估计，省掉 Critic。7.7
PRM 和 ORM 的区别？ORM 只给最终结果打分；PRM 给每个推理步骤打分，信用分配更细，但标注更贵。7.7
自洽性 / 多数投票为什么有效？多条独立推理更可能在正确答案上汇合；前提是单次正确率超过一半，否则投票会放大错误。7.7
模型如何自我改进？生成 → 验证 → 选择 → 更新的循环；关键看信号从哪来、靠什么验证。7.8
没有外部反馈的自我修正可靠吗？效果有限，研究发现可能改得更差；有测试、环境等外部反馈时才可靠。7.8
什么是奖励黑客？智能体找到提高奖励却没完成真正任务的方法，是古德哈特定律在 RL 中的表现。7.10
什么是模型崩溃？一代代用模型生成的数据训练模型，分布尾部消失、输出变单一。7.10
什么是 RSI，现在到哪一步了？改进对象包括"改进能力本身"的自我改进；在可验证的封闭领域已有强证据，开放领域的自动化 AI 研究在研究和早期部署中，智能爆炸仍属推测。7.9
为什么自动化 AI 研发是关键阈值？它会闭合"AI 改进 AI"的反馈环、压缩应对时间，主要实验室的安全框架都为它设了专门的能力等级和防护要求。7.9
能力–安全权衡怎么答？能力和自主性提升扩大风险面，安全约束可能降低有用性；用分级授权、可验证奖励与评测、预设阈值、持续监控来平衡，很多安全措施也提升可用性。7.10

单选 · 理解检查 13　面试官问“GRPO 相比 PPO 省掉了什么，代价是什么？”哪个回答最准确？

A. 省掉了价值模型（Critic），用同组多个回答的奖励均值作基线；代价是每道题要采样多个回答

B. 省掉了参考模型，因此不再有 KL 约束

C. 省掉了奖励，改用人类偏好

D. 省掉了策略模型，只训练价值模型

查看答案与每个选项的解析

A · 正确：这正是 GRPO 的设计：组内相对优势替代学出来的基线。

D · 错误：GRPO 训练的就是策略模型。
