12.1 安全目标与威胁模型：先问"保护什么、防谁"

银行转账系统要防的事很多：有人偷看余额，有人把"转 100 元"改成"转 10000 元"，有人让系统瘫痪，客户事后说"这笔不是我转的"。性质不同，办法也不同，所以分析安全问题先说清：保护哪种性质，对手能做什么。

三要素与扩展属性

信息安全的核心目标是 CIA 三要素：

属性含义典型手段
机密性 Confidentiality未授权的人看不到信息内容访问控制 + 加密
完整性 Integrity信息未经授权不会被改，改了能发现访问控制 + 摘要/MAC/签名
可用性 Availability授权用户需要时能正常使用冗余、备份、限流、抗 DDoS

在三要素之外，考试常把下面两条并列为扩展属性：

  • 真实性（认证性）：确认消息来源或通信对方确实是它声称的那个人。分为实体认证（对方是谁）和消息认证（消息从谁来、有没有被改）。
  • 抗抵赖性（又称不可否认性，Non-repudiation）：发送者事后赖不掉自己发过的消息，靠数字签名实现。

有的教材还加上可控性和可审查性（事后可追查）。

四种攻击形式与主动/被动攻击

按"攻击者在消息从 A 到 B 的路上做了什么"，攻击分四种，每种破坏一个属性：

截获属于被动攻击；中断、篡改、伪造属于主动攻击

被动攻击（窃听、流量分析）不改数据，受害者通常察觉不到，所以重在预防，主要手段是加密。** 主动攻击**（篡改、伪造、重放、拒绝服务）会改变数据或系统状态，完全预防很难，所以重在检测和恢复，手段是 MAC、签名、序号和冗余。

ISO 7498-2 定义的五类安全服务正好对应这些目标：认证、访问控制、数据机密性、数据完整性、抗抵赖。

密码学术语与两种安全

  • 明文、密文、加密算法（密码算法）、密钥；密码编码学研究怎样设计密码，密码分析学研究怎样在不知道密钥时破译，两者合称密码学。
  • Kerckhoffs 原则：密码系统的安全只依赖密钥保密，算法本身可以公开。AES、SM4 都是公开算法。
  • 无条件安全：对手算力无限也破不了，一次一密属于这类。** 计算安全**：在现实算力和时间内破不了，AES、RSA 都属于这类。

按攻击者掌握的材料从少到多，密码分析分为唯密文攻击、已知明文攻击、选择明文攻击、选择密文攻击。一个算法要能扛住最强的那一类才算合格。

要点：

  • CIA = 机密性、完整性、可用性；扩展属性中，抗抵赖靠数字签名，真实性靠认证。
  • 中断→可用性，截获→机密性，篡改→完整性，伪造→真实性。
  • 被动攻击（截获）重在预防；主动攻击（中断、篡改、伪造、重放）重在检测。

多选 · 理解检查 1　攻击者在网络上录下一笔合法的转账报文，稍后原样再发一次，使转账执行了两遍。关于这次攻击，哪些说法正确？

A. 这是重放攻击，属于主动攻击

B. 它主要破坏的是机密性

C. 在报文里加入序号或时间戳，并由 MAC 保护，可以检测出这类攻击

D. 对报文加密就足以完全阻止这种攻击

查看答案与每个选项的解析

A · 正确：攻击者向系统注入了报文，改变了系统状态。

B · 错误：攻击者甚至不需要读懂报文内容；被破坏的是完整性（消息的新鲜性）。

C · 正确：接收方发现序号重复或时间过期即可拒绝。

D · 错误：重放的是密文本身，加密只隐藏内容，接收方照样能解密并执行。

易错点

  • 加密主要解决机密性；服务器宕机这类可用性问题要靠冗余和备份，加密帮不上忙。
  • "不可否认性"由签名提供；MAC 的双方共享同一把密钥，任何一方都能算出标签，所以 MAC 提供不了抗抵赖。

小结： 信息安全的目标是 CIA 三要素，再加上真实性和抗抵赖性；中断、截获、篡改、伪造四种攻击分别破坏可用性、机密性、完整性和真实性；对被动攻击重在预防，对主动攻击重在检测。

12.2 密码学的数学基础：模运算、逆元与欧拉定理

RSA 的密钥生成要算"e 在模 φ(n) 下的逆元"，加解密要算"一个数的几百次方再取模"。这一节只讲到能手算 RSA 为止：模运算、最大公约数、扩展欧几里得、欧拉函数、费马小定理、快速模幂。[1]

模运算与同余

a mod n 是 a 除以 n 的余数，取值 0 到 n−1。如果 a 和 b 除以 n 余数相同，就说 a 与 b 模 n 同余，记作 a ≡ b (mod n)，例如 31 ≡ −2 (mod 33)。模运算有一条好用的性质：加、减、乘都可以先取模再算，结果不变：

(a × b) mod n = ((a mod n) × (b mod n)) mod n

这条性质让我们在算 31⁷ mod 33 时，每乘一步就取一次模，数字始终很小。

最大公约数与扩展欧几里得

欧几里得算法（辗转相除）：gcd(a, b) = gcd(b, a mod b)，直到余数为 0。两数的最大公约数为 1 时称为互素。

扩展欧几里得在求 gcd 的同时，找出整数 x、y 使 a·x + b·y = gcd(a, b)。当 gcd(e, m) = 1 时，e·x + m·y = 1，两边对 m 取模得 e·x ≡ 1 (mod m)，这个 x（调整到 0 到 m−1）就是 e 模 m 的乘法逆元，记作 e⁻¹ mod m。逆元存在的充要条件是 gcd(e, m) = 1。

我们求 3 模 20 的逆元。先正向辗转相除，再从下往上回代：

左列正向相除，右列把余数写成被除数与除数的组合；最后 7×3 ≡ 1 (mod 20)，所以 3⁻¹ mod 20 = 7

欧拉函数与欧拉定理

欧拉函数 φ(n)：1 到 n 中与 n 互素的整数个数。三条够用的规则：

  • p 是素数：φ(p) = p − 1，例如 φ(13) = 12；
  • p、q 是不同素数：φ(pq) = (p−1)(q−1)，例如 φ(35) = 4×6 = 24，φ(33) = 2×10 = 20；
  • 素数幂：φ(pᵏ) = pᵏ − pᵏ⁻¹，例如 φ(9) = 9 − 3 = 6。

欧拉定理：若 gcd(a, n) = 1，则 a^φ(n) ≡ 1 (mod n)。 费马小定理是它在 n 为素数 p 时的特例：若 p 不整除 a，则 a^(p−1) ≡ 1 (mod p)。

费马小定理可以把大指数降下来。求 3²⁰⁰ mod 7：因为 3⁶ ≡ 1 (mod 7)，200 = 6×33 + 2，所以 3²⁰⁰ ≡ (3⁶)³³ × 3² ≡ 9 ≡ 2 (mod 7)。

快速模幂（平方-乘）

直接算 31⁷ 再取模，指数一大就算不动。平方-乘算法把指数写成二进制，从低位到高位扫：底数每步平方一次，遇到 1 位就把当前底数乘进结果。指数有 k 位，只需约 2k 次乘法。

变量表：result 是已经乘进去的部分；base 是当前位对应的 31^(2^i) mod 33；exp 是还没处理的高位。

def mod_pow(base, exp, mod):
    """快速模幂（平方-乘）：从低位到高位扫描指数的二进制位。"""
    result = 1
    base %= mod
    while exp > 0:
        if exp & 1:              # 当前位是 1：把这一位对应的幂乘进结果
            result = result * base % mod
        base = base * base % mod  # 底数平方，对应下一位
        exp >>= 1
    return result

手工模拟 31⁷ mod 33，7 = 111₂：第 1 位为 1，result = 31，base 变为 31² mod 33 = 4；第 2 位为 1，result = 31×4 mod 33 = 25，base 变为 16；第 3 位为 1，result = 25×16 mod 33 = 400 mod 33 = 4。结果为 4。另一种心算：31 ≡ −2，(−2)⁷ = −128 ≡ −128 + 132 = 4。

扩展欧几里得和逆元的代码：

def egcd(a, b):
    """返回 (g, x, y)，满足 a*x + b*y == g == gcd(a, b)。"""
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inverse(a, m):
    """a 在模 m 下的乘法逆元；gcd(a, m) != 1 时不存在。"""
    g, x, _ = egcd(a, m)
    if g != 1:
        raise ValueError('no inverse')
    return x % m

egcd(20, 3) 返回 (1, -1, 7)，即 20×(−1) + 3×7 = 1；mod_inverse(3, 20) 返回 7。Python 3.8 起 pow(3, -1, 20) 也能直接求逆元。

要点：

  • 逆元存在 ⇔ gcd(e, m) = 1；用扩展欧几里得求。
  • φ(p) = p−1，φ(pq) = (p−1)(q−1)。
  • 欧拉定理 a^φ(n) ≡ 1 (mod n)；费马小定理 a^(p−1) ≡ 1 (mod p)，可用于把指数对 φ 取模降幂。

查看答案与每个选项的解析

单选 · 理解检查 3　计算 φ(77) 和 2⁶⁰ mod 77。

A. φ(77)=60，2⁶⁰ mod 77 = 1

B. φ(77)=76，2⁶⁰ mod 77 = 1

C. φ(77)=60，2⁶⁰ mod 77 = 0

D. φ(77)=18，2⁶⁰ mod 77 = 2

查看答案与每个选项的解析

A · 正确：77 = 7×11，φ = 6×10 = 60；gcd(2,77)=1，由欧拉定理 2⁶⁰ ≡ 1。

B · 错误：77 不是素数，φ(77) ≠ 76。

C · 错误：2 与 77 互素，任何次幂都与 77 互素，余数不会是 0。

D · 错误：18 = 7 + 11，这里把乘法误写成了加法。

易错点

  • φ(pq) = (p−1)(q−1) 只在 p、q 为不同素数时成立；φ(n) 对合数 n 一般小于 n−1。
  • 求出的 x 可能是负数，要加上模数调到 0 到 m−1 之间，例如 −13 mod 20 = 7。

小结： 求模逆元用扩展欧几里得算法；φ(pq)=(p−1)(q−1)；计算大指数的模幂用平方-乘算法，每一步都取模。

12.3 古典密码与现代密码概述：代换、置换与两类体制

古典密码的两种基本操作代换和置换，至今仍是分组密码的积木；它们被破的原因，正是现代密码要避开的坑。[2]

代换与置换

  • 代换密码：把每个字符换成另一个字符，位置不变。代换表就是密钥。
  • 置换密码：字符本身不变，打乱它们的位置。例如把 "HELLO" 按顺序 (2,1,4,3,5) 重排得 "EHLLO"。

凯撒密码是最简单的代换：每个字母循环后移 k 位，E(x) = (x + k) mod 26，D(x) = (x − k) mod 26。k = 3 时 HELLO → KHOOR。它只有 25 个有效密钥，暴力试一遍就破了。换成任意的单表代换，密钥空间变成 26! ≈ 4×10²⁶，暴力行不通，但单表代换保留了字母频率：英文里 E 最常见，密文里出现最多的字母大概率就是 E 的代换结果，这就是频率分析。

维吉尼亚密码是多表代换：密钥是一个单词，第 i 个字母按密钥第 i 个字母（循环使用）的位移做凯撒。同一个明文字母在不同位置会变成不同密文字母，频率被抹平了。

HELLO 用密钥 KEY 加密为 RIJVS；两个 L 分别变成 J 和 V，频率分析失效

维吉尼亚的弱点是密钥循环：猜出密钥长度 L，密文就拆成 L 组凯撒分别破解；Kasiski 测试用重复片段间距的公约数推测 L。

def caesar(text, shift):
    """凯撒密码：每个大写字母循环后移 shift 位，其他字符原样保留。"""
    out = []
    for c in text:
        if 'A' <= c <= 'Z':
            out.append(chr((ord(c) - 65 + shift) % 26 + 65))
        else:
            out.append(c)
    return ''.join(out)

def vigenere(text, key, decrypt=False):
    """维吉尼亚密码：第 i 个字母按密钥第 i 个字母（循环使用）的位移做凯撒。"""
    out = []
    for i, c in enumerate(text):
        k = ord(key[i % len(key)]) - 65
        if decrypt:
            k = -k
        out.append(chr((ord(c) - 65 + k) % 26 + 65))
    return ''.join(out)

一次一密：密钥真随机、与明文等长、只用一次，与明文逐位异或。Shannon 证明它具有完善保密性（密文不泄露明文的任何信息），属于无条件安全。代价是密钥和明文一样长，而且每次都要安全地送到对方手里，所以只用于极少数场合。它的思想演化成了序列密码：用短密钥生成很长的伪随机密钥流，再与明文异或，RC4、国密 ZUC（祖冲之算法，用于 4G 移动通信）都是序列密码。

现代密码的两类体制

现代密码按"加密和解密用不用同一把密钥"分成两类：

上：对称加密双方共用 K；下：非对称加密用接收方的公钥加密、接收方的私钥解密

对称密码非对称（公钥）密码
密钥加解密同一把公钥公开、私钥保密，一对
速度快，适合大量数据慢，比对称慢几个数量级
难点密钥分发、密钥数量多、无法抗抵赖计算量大，公钥要可信（需要 PKI）
代表DES、3DES、AES、SM4、RC4、ZUCRSA、ElGamal、ECC、SM2、SM9
主要用途加密数据本身传递对称密钥、数字签名、密钥协商

密钥数量是笔试常考的计算。n 个用户两两之间都要能保密通信：

  • 对称密码每一对用户共享一把，需要 C(n,2) = n(n−1)/2 把密钥。100 人需要 4950 把。
  • 公钥密码每人一对（公钥 + 私钥），共 n 对、2n 把。100 人需要 100 对、200 把，其中私钥 100 把。

实际系统把两者结合起来，叫混合加密：用公钥算法安全地送出一把随机的对称密钥，再用对称算法加密数据。HTTPS 和 12.9 的数字信封都是这个思路。

要点：

  • 代换换字符，置换换位置；单表代换可被频率分析，多表代换（维吉尼亚）能掩盖频率。
  • 一次一密：密钥真随机、等长、只用一次，无条件安全。
  • 对称快、密钥分发难；非对称慢、解决分发和签名；n 人对称需 n(n−1)/2 把，非对称需 n 对。

D · 错误：公钥公开，任何人都能用接收方的公钥加密，不必按用户对分配。

易错点

  • 公钥密码速度慢，一般只加密很短的数据（如会话密钥或摘要），大文件由对称算法加密。
  • 维吉尼亚的密钥会循环重复，所以它仍属于计算上可破的古典密码，与一次一密的安全性相差很远。

小结： 代换密码改变字符，置换密码改变位置；单表代换怕频率分析，多表代换怕周期分析；n 个人两两通信，对称密码需要 n(n−1)/2 个密钥，非对称密码需要 n 对密钥。

12.4 分组密码：Feistel 结构、DES/3DES、AES 与 SM4

银行加密海量交易报文的主力是对称的分组密码：把明文切成固定长度的块，每块在密钥控制下变成等长密文块。本节讲两种骨架和 DES、3DES、AES、SM4 的参数。[3] [4]

混淆、扩散与两种骨架

Shannon 给分组密码定了两条设计原则：

  • 混淆：让密文与密钥的关系尽量复杂，主要靠非线性的代换（S 盒）实现。
  • 扩散：让明文或密钥的每一位影响尽量多的密文位，主要靠置换和线性混合实现。扩散做得好，就会出现雪崩效应：输入改 1 位，大约一半输出位翻转。

把代换和置换交替叠加很多轮，就是现代分组密码。叠加方式有两种骨架：

  • Feistel 结构：每轮把分组分成左右两半 Lᵢ、Rᵢ，只用轮函数 F 处理右半，结果异或到左半，再交换左右：Lᵢ₊₁ = Rᵢ，Rᵢ₊₁ = Lᵢ ⊕ F(Rᵢ, Kᵢ)。DES 用的就是它。
  • SP 网络（代换-置换网络）：每轮对整个分组做代换和置换。AES 属于这一类。

Feistel 的一轮：右半原样搬到左边，左半与 F(右半) 异或后放到右边

Feistel 的妙处在于解密用同一套结构，只把子密钥倒序。已知 Lᵢ₊₁ 和 Rᵢ₊₁，先得 Rᵢ = Lᵢ₊₁，再算 Lᵢ = Rᵢ₊₁ ⊕ F(Rᵢ, Kᵢ)。整个过程只需要"正向算一次 F"，所以 F 本身可以是不可逆函数。

几个必背细节：

  • DES：64 位密钥每字节含 1 位奇偶校验，有效 56 位，密钥空间 2⁵⁶ ≈ 7.2×10¹⁶。轮函数依次是 E 扩展（32→48 位）、与 48 位子密钥异或、8 个 S 盒（48→32 位）、P 置换。S 盒是唯一的非线性部件。1998 年专用硬件 56 小时就穷举出了密钥。
  • 2DES 为什么没人用：中间相遇攻击从两端各穷举 2⁵⁶ 次，在中间比对，约 2⁵⁷ 次就能破解，强度只比单 DES 多 1 位。
  • 3DES 采用 EDE：C = E_K3(D_K2(E_K1(P)))。中间用解密，使 K1 = K2 = K3 时退化为单 DES、兼容旧设备。三密钥 168 位，受中间相遇攻击，强度约 112 位。
  • AES 在 4×4 字节的状态矩阵上运算，轮数 Nr = 密钥字数 + 6（128 位密钥是 4 个 32 位字，所以 10 轮）。每轮四步：SubBytes（S 盒字节代换，唯一的非线性步骤）、ShiftRows（行移位）、MixColumns（列混合）、AddRoundKey（轮密钥加）。最后一轮省略 MixColumns。
  • SM4 由国家密码管理局发布，分组和密钥都是 128 位，32 轮，加解密结构相同、轮密钥倒序使用。[5]

AES 加密流程：先做一次轮密钥加，中间 Nr−1 轮四步齐全，末轮省掉列混合

要点：

  • DES：分组 64 位、密钥 56 位有效、16 轮、Feistel；S 盒提供非线性。
  • AES：分组固定 128 位，密钥 128/192/256 位对应 10/12/14 轮，SP 结构，末轮无 MixColumns。
  • 3DES 用 EDE，三密钥 168 位、有效强度约 112 位；2DES 受中间相遇攻击，强度约 57 位。
  • SM4：128 位分组、128 位密钥、32 轮。

GCM：加密和认证一次完成

GCM（Galois/Counter Mode）= CTR 模式加密 + 在 GF(2¹²⁸) 上计算的 GHASH 认证标签。它属于认证加密（AEAD）：解密前先校验标签，密文被改 1 位标签就对不上，整条报文被拒绝；它还能顺带认证不需要加密的"附加数据"，比如报文头。GCM 加解密都可并行，TLS 1.3 的主力套件就是 AES-GCM。[8]

要点：

  • ECB 相同明文块得相同密文块，会暴露模式，只适合加密很短的随机数据（如单个密钥）。
  • CBC 需要不可预测的 IV，加密串行、解密可并行；一个密文块出错只影响 2 个明文块。
  • CFB、OFB、CTR 把分组密码变成序列密码，无需填充；CTR 加解密都可并行、可随机访问。
  • 同一密钥下，CTR/GCM 的 nonce 必须唯一：重复使用时 C₁ ⊕ C₂ = P₁ ⊕ P₂。
  • 需要机密性加完整性时选 GCM 这类认证加密。

12.6 RSA：从两个素数到一对密钥

RSA 让接收方公开一把"锁"（公钥），谁都能用它加密，只有持"钥匙"（私钥）的人能解开。它的安全性建立在一个事实上：两个大素数相乘很容易，把乘积分解回去极难，这就是大整数分解难题。这种"正向容易、反向极难，但掌握陷门信息就容易"的函数叫单向陷门函数。[9]

密钥生成、加密与解密

RSA 密钥生成：p、q、φ(n)、d 都要保密，只公开 e 和 n

  • 加密：C = Mᵉ mod n（要求 0 ≤ M < n）
  • 解密：M = Cᵈ mod n

为什么解得回来：e·d ≡ 1 (mod φ(n))，即 e·d = 1 + kφ(n)。由欧拉定理 M^φ(n) ≡ 1，所以 Cᵈ = M^(ed) = M × (M^φ(n))ᵏ ≡ M (mod n)。

    n = p * q
    phi_n = (p - 1) * (q - 1)
    d = mod_inverse(e, phi_n)      # e*d ≡ 1 (mod φ(n))
    return (e, n), (d, n), phi_n   # 公钥, 私钥, φ(n)

实际使用的要点

  • 密钥长度：RSA 模长 1024 位已不安全，目前至少用 2048 位，3072 位对应 128 位安全强度。[10]
  • 填充：教材式 RSA 是确定性的，还有乘法同态（密文相乘对应明文相乘），会被选择密文攻击利用。实际加密用 OAEP，签名用 PSS。
  • 工程：用 Miller-Rabin 素性检测挑大素数；解密用中国剩余定理（CRT）加速约 4 倍。

要点：

  • n = pq，φ(n) = (p−1)(q−1)，e 与 φ(n) 互素，d = e⁻¹ mod φ(n)；公钥 {e, n}，私钥 {d, n}。
  • 加密 C = Mᵉ mod n，解密 M = Cᵈ mod n；安全性基于大整数分解。
  • RSA 速度慢，实际只用来加密会话密钥和做数字签名。

D · 错误：2¹² mod 11 = 4096 mod 11 = 4。

易错点

  • DH 的中间人攻击针对的是"缺少认证"，换更大的 p 也挡不住。
  • ECC 的优势是同等强度下密钥更短、运算更快，它依赖的难题是 ECDLP，与 RSA 的分解问题是两回事。

小结： DH 依靠离散对数问题的困难性，只协商密钥而不认证身份，会受到中间人攻击，需要用签名和证书补充认证；ECC 依靠 ECDLP，256 位的 ECC 相当于 3072 位的 RSA；SM2 是国密标准中的椭圆曲线算法。

12.8 哈希函数与消息认证码：MD5、SHA、SM3、HMAC

下载安装包时核对 SHA-256 值，确认文件没被损坏或替换；网银报文附带 MAC，证明它出自持有密钥的一方。这两件事分别由哈希函数和消息认证码完成。[11] [12]

哈希函数：任意长输入，固定长摘要

哈希函数 H 把任意长的消息压缩成固定长度的摘要，公开、无密钥、计算快。密码学哈希还要满足三条安全性质：

性质含义别名
单向性给定摘要 h，找不到 M 使 H(M) = h抗原像
抗弱碰撞给定 M，找不到 M' ≠ M 使 H(M') = H(M)抗第二原像
抗强碰撞找不到任何一对 M ≠ M' 使 H(M) = H(M')抗碰撞

输入无限、输出有限，碰撞一定存在；安全的含义是"找不到"。生日攻击说明找碰撞比想象中容易：23 个人里有两人同一天生日的概率已达 50.7%。同理，n 位哈希只需约 2^(n/2) 次尝试就能找到一对碰撞，所以 128 位的 MD5 只有约 2⁶⁴ 的抗碰撞强度。

算法摘要长度现状
MD5128 位2004 年王小云团队给出碰撞构造，已不能用于签名和证书
SHA-1160 位2017 年公开了实际碰撞，已淘汰
SHA-256（SHA-2 族）256 位主流；同族还有 SHA-224/384/512
SHA-3224–512 位Keccak 海绵结构，作为 SHA-2 的备选
SM3256 位国密杂凑算法，配合 SM2 签名使用

雪崩效应在 SHA-256 上很明显：abc 与 abd 只差 1 个字符，两个 256 位摘要有 122 位不同。

MAC 与 HMAC

消息认证码 MAC = F(K, M)：发送方用共享密钥 K 对消息算出一个短标签附在后面，接收方用同一个 K 重算并比对。标签对得上，说明消息完整、并且来自持有 K 的一方。MAC 有两类构造：基于分组密码（CBC-MAC、CMAC）和基于哈希（HMAC）。

为什么不直接算 H(K ‖ M)？MD5、SHA-1、SHA-256 采用 Merkle-Damgård 结构，摘要就是处理完最后一块的内部状态，攻击者可以从 H(K ‖ M) 接着"续算"，不知道 K 也能得到 H(K ‖ M ‖ 填充 ‖ 追加内容)，这叫长度扩展攻击。HMAC 用两层嵌套哈希堵住了它：

HMAC(K, M) = H((K' ⊕ opad) ‖ H((K' ⊕ ipad) ‖ M))

HMAC 的两层结构：外层哈希把内层摘要再“封”一次，攻击者无法在末尾续算

手写的 HMAC 与标准库 hmac 的结果逐字节相同：

def hmac_sha256_manual(key, msg):
    """按 RFC 2104 手写 HMAC：H((K' xor opad) || H((K' xor ipad) || m))。"""
    block_size = 64
    if len(key) > block_size:
        key = hashlib.sha256(key).digest()
    key = key.ljust(block_size, b'\x00')
    ipad = bytes(k ^ 0x36 for k in key)
    opad = bytes(k ^ 0x5C for k in key)
    inner = hashlib.sha256(ipad + msg).digest()
    return hashlib.sha256(opad + inner).hexdigest()

认证来源不能能能
抗抵赖不能不能能

要点：

  • 哈希三性质：单向（抗原像）、抗弱碰撞（抗第二原像）、抗强碰撞；n 位哈希抗碰撞强度约 2^(n/2)。
  • MD5（128 位）、SHA-1（160 位）已不安全；用 SHA-256、SHA-3 或 SM3（256 位）。
  • MAC 提供完整性和来源认证，不提供抗抵赖；HMAC 用双层哈希抵抗长度扩展攻击。

12.9 数字签名与数字信封

客户用 U 盾确认转账后，银行要能向第三方证明"这笔指令确实由该客户发出且未被改动"，这靠数字签名；数字信封则解决"既要保密、又要对称算法的速度"。[14] [15]

先哈希，再签名

签名者用自己的私钥对消息摘要运算得到签名；任何人用签名者的公钥验证。

上：签名；下：验证。签名只能由私钥持有者生成，验证人人都能做

为什么先哈希：公钥运算很慢，而摘要短且定长，签摘要比签整条消息快得多；同时也避开了教材式 RSA 的乘法同态问题。

用 12.6 的密钥（公钥 {3, 33}，私钥 {7, 33}）做一次教材式签名：设摘要 h = 5，签名 S = 5⁷ mod 33 = 14；验证者算 14³ mod 33 = 5，与自己重算的摘要一致，验证通过。

签名提供三项保证：完整性（消息改了摘要就对不上）、来源认证（只有 Alice 的公钥能验过）、抗抵赖（私钥只有 Alice 持有，她无法否认）。常见签名算法有 RSA-PSS、DSA、ECDSA、SM2。其中 DSA 只能签名，不能加密，也不能用于密钥交换。DSA、ECDSA 每次签名都要一个新的随机数 k，k 一旦重复或泄露，私钥就能被算出来。

数字信封：对称加密正文，公钥加密密钥

Alice 给 Bob 发一份既保密又有签名的报文

2 / 6

3 / 6

4 / 6

用 Bob 的公钥加密 K，得到 E_Bob(K)，这就是“信封”；C 与 E_Bob(K) 一起发出

要点：

  • 签名：发送方私钥签名，接收方用发送方公钥验证；先哈希再签名。
  • 签名提供完整性、认证和抗抵赖，不提供机密性。
  • 数字信封：随机对称密钥加密数据，接收方公钥加密对称密钥。
  • DSA 只用于签名；签名随机数 k 不能重复。

12.10 PKI 与数字证书：X.509、证书链、CRL 与 OCSP

公钥密码有个前提：你拿到的"Bob 的公钥"真是 Bob 的。攻击者把自己的公钥冒充成 Bob 的，加密和签名就全部失效，这正是 12.7 的中间人攻击。PKI（公钥基础设施）用可信第三方给公钥"做担保"。[16]

PKI 的组成与 X.509 证书

  • CA（证书颁发机构）：用自己的私钥给"身份 + 公钥"签名，签出来的就是数字证书。
  • RA（注册机构）：审核申请者身份，再交给 CA 签发。
  • 证书库：发布证书。
  • 撤销服务：发布作废证书的信息（CRL、OCSP）。

证书的标准格式是 X.509 v3，主要字段：

字段内容
版本、序列号v3；同一 CA 下唯一的编号，撤销时就用它
签名算法例如 sha256WithRSAEncryption、SM3withSM2
颁发者 Issuer签发这张证书的 CA 名称
有效期Not Before 至 Not After
主体 Subject证书持有者名称
主体公钥信息持有者的公钥及算法
扩展主体备用名 SAN（域名列表）、基本约束（是否为 CA）、密钥用途等
CA 的签名颁发者私钥对以上全部内容的签名

证书链：一层一层往上验证

浏览器和操作系统预装了少量根证书（自签名，颁发者等于主体）。根 CA 通常离线保管，日常由中间 CA 签发服务器证书，形成证书链：

验证方向自下而上：服务器证书 → 中间 CA → 信任库中的根

证书撤销：CRL 与 OCSP

私钥泄露或员工离职时，证书要在到期前作废：

  • CRL（证书撤销列表）：CA 定期发布签名的"作废序列号清单"，客户端下载自查；清单可能很大，且有更新延迟。
  • OCSP（在线证书状态协议）：客户端实时询问某序列号的状态，得到签名的"有效 / 已撤销 / 未知"应答。OCSP Stapling 让服务器预取应答、在 TLS 握手时一并发送，减少延迟、保护隐私。[17]

要点：

  • 证书 = CA 对"主体身份 + 主体公钥 + 有效期等"的签名，格式为 X.509。
  • 证书链自下而上验证，止于信任库中的自签名根证书。
  • 校验内容：域名、有效期、签名、签发者是否为 CA、撤销状态。
  • CRL 是定期发布的撤销清单，OCSP 是实时查询。

12.11 随机数：为什么密钥必须来自 CSPRNG

会话密钥、IV、DH 指数、签名随机数 k、盐、会话 ID、CSRF 令牌都要用随机数，攻击者能预测其中一个，整套密码就被绕开。[18] [19]

三类随机数发生器

  • 真随机数发生器（TRNG）：从物理噪声（热噪声、时钟抖动）采样，不可预测，但速度慢。
  • 伪随机数发生器（PRNG）：用确定性算法从一个种子展开出长序列。种子相同，序列就相同。
  • 密码学安全伪随机数发生器（CSPRNG）：用真随机熵作种子，并保证即使看到之前的全部输出，也无法预测下一个输出。NIST SP 800-90A 中的 Hash_DRBG、HMAC_DRBG、CTR_DRBG 都属于这一类。

安全用途一律走 CSPRNG；普通 PRNG 只用于模拟和游戏

线性同余为什么不安全

线性同余发生器 xₙ₊₁ = (a·xₙ + c) mod m 快且可复现，C 的 rand() 常用它。取 a = 5，c = 3，m = 16，种子 7：5×7+3 = 38 ≡ 6，5×6+3 = 33 ≡ 1，接着是 8、11……知道参数并看到一个输出，就能推出后面全部输出。

各语言的正确用法：Python 用 secrets 模块或 os.urandom（random 模块是梅森旋转，可预测）；Java 用 SecureRandom；Linux 上读 /dev/urandom 或调用 getrandom()。

要点：

  • 密钥、IV、盐、会话 ID、令牌都必须来自 CSPRNG。
  • 线性同余、梅森旋转等普通 PRNG 可预测，只能用于非安全场景。
  • 一次一密的密钥要求真随机；序列密码的密钥流来自密码学安全的发生器。

12.12 口令存储与多因素认证

2011 年国内一个大型开发者社区的数据库外泄，600 万用户密码是明文保存的，攻击者拿去其他网站批量尝试登录（撞库）。服务器怎样保存口令，才能在被拖库后仍保护用户？[20] [21]

口令存储的四个阶段

每一步都在提高攻击者“猜一次”的成本，第 ④ 种是当前推荐做法

  • 彩虹表：预先算好大量常见口令的哈希值，拿到摘要直接查表。无盐的 MD5("123456") 永远是 e10adc39…，一查就出。
  • 盐：每用户一个随机值（约 16 字节），与口令一起哈希，和结果一起存库。盐可以公开，它让每个用户的哈希各不相同，彩虹表只能逐个盐重建。
  • 慢哈希：故意算得慢。PBKDF2 把 HMAC 迭代几十万次（OWASP 对 PBKDF2-HMAC-SHA256 建议 60 万次），bcrypt、scrypt、Argon2 还占用内存，让 GPU 并行猜测更贵。
def hash_password(password, salt=None, iterations=600_000):
    """注册时：生成随机盐，用慢哈希 PBKDF2-HMAC-SHA256 计算，存 (盐, 迭代次数, 哈希)。"""
    if salt is None:
        salt = secrets.token_bytes(16)
    digest = hashlib.pbkdf2_hmac('sha256', password.encode(), salt, iterations)
    return salt, iterations, digest

def verify_password(password, record):
    salt, iterations, digest = record
    candidate = hashlib.pbkdf2_hmac('sha256', password.encode(), salt, iterations)
    return hmac.compare_digest(candidate, digest)   # 恒定时间比较

登录时取出该用户的盐和迭代次数重新计算，再用恒定时间比较，避免泄露时间差。由于盐是随机的，同一口令注册两次，得到的存储值也不同。

多因素认证

认证因素分三类：

类别例子
你知道的口令、PIN、密保问题
你拥有的U 盾、手机（短信验证码、动态口令 App）、硬件令牌
你本身的指纹、人脸、声纹

多因素认证（MFA） 要求至少两类不同因素。网银转账"登录密码 + U 盾"就是双因素。动态口令（TOTP）用共享密钥对当前 30 秒时间片做 HMAC，再截取 6 位数字，口令每半分钟变一次。

U 盾常用挑战-应答：服务器发随机数，U 盾用内部密钥算 HMAC 或签名作应答。密钥始终留在芯片里，网络上只有一次性应答。

要点：

  • 口令存储：每用户随机盐 + 慢哈希（PBKDF2、bcrypt、scrypt、Argon2），比对用恒定时间。
  • 加盐使彩虹表失效、使相同口令得到不同存储值；盐可以公开存放。
  • MFA 必须来自不同类别；挑战-应答用随机数防重放。

12.13 Kerberos、单点登录、OAuth 2.0 与 JWT

银行内部有几十个系统，每个都输一遍密码既麻烦又增加泄露机会。单点登录（SSO） 让用户登录一次就能访问所有互信系统。企业内网的经典实现是 Kerberos；互联网上的"第三方授权登录"则基于 OAuth 2.0。[22] [23]

Kerberos：用"票据"代替密码

Kerberos 是基于对称密码的可信第三方认证协议。KDC（密钥分发中心）由两部分组成：** AS**（认证服务器）和 TGS（票据授予服务器）。核心思想是：密码只在第一步用来解开一个会话密钥，之后全程出示票据。

  • TGT（票据授予票据）用 TGS 的密钥加密，客户端只能原样出示。
  • 认证符含客户端名和时间戳、用会话密钥加密，证明出示者知道会话密钥；时间戳防重放，所以要求时钟同步（默认允许 5 分钟偏差）。
  • 缺点：KDC 是单点，被攻破则全域失守；KDC 要保存所有用户的密钥。

OAuth 2.0：授权，而不是把密码交出去

理财 App 想读你在银行的账户列表，最糟的做法是把网银密码交给它。OAuth 2.0 让你在银行页面登录并同意授权，银行发给 App 一个访问令牌，只含你同意的权限范围（scope），有有效期，可随时撤销。

这是最常用的授权码模式：浏览器只经手短命的授权码，令牌在后端换取；手机 App、单页应用再加 PKCE 防授权码被截用；state 参数防 CSRF。OAuth 2.0 管"授权"，加上身份信息（ID Token）就是 OpenID Connect。

JWT：自包含的令牌

JWT（JSON Web Token）由三段 Base64URL 编码组成：头部.载荷.签名。头部写算法（HS256、RS256），载荷写用户 ID、角色、过期时间 exp，签名覆盖前两段。验签通过就信任载荷，不必查会话表。[24]

下面的 jwt_verify_hs256 演示了验证方的三条规则：修改载荷后签名对不上、过期的令牌被拒绝、把 alg 改成 none 的令牌被拒绝。

  1. 服务端固定允许的算法，拒绝令牌自己声明的 none 或意料之外的算法；
  2. 用恒定时间比较验签；
  3. 检查 exp 等时间声明。

要点：

  • Kerberos：AS 发 TGT，TGS 发服务票据；基于对称密码和可信第三方，靠时间戳防重放，要求时钟同步。
  • SSO 的优点是只需保护一个登录点，缺点是该点一旦失守影响全部系统。
  • OAuth 2.0 是授权框架，授权码模式 + PKCE 最常用；OIDC 在其上提供身份认证。
  • JWT = 头部.载荷.签名；载荷只是编码、谁都能读；服务端要固定算法、验签、查过期。

12.14 访问控制：DAC、MAC、RBAC 与 ABAC

认证回答"你是谁"，访问控制回答"你能对什么做什么"：判定主体（用户、进程）能否对客体（文件、表、接口）执行某操作。设计原则：每次访问都检查、最小权限、默认拒绝。[25] [26]

四种模型

四种模型及其典型应用

  • DAC（自主访问控制）：属主决定谁能访问，可转授他人。实现有按客体存的访问控制表 ACL 和按主体存的能力表。Linux 的 rw-r-----（属主读写、同组只读、其他无权，八进制 640）就是简化的 ACL。DAC 管不住信息流向：木马可借用户权限把文件复制给别人。
  • MAC（强制访问控制）：系统给主体分配许可级别、给客体分配密级，按固定规则判定，用户自己无权更改。
  • RBAC（基于角色）：权限分给角色，用户担任角色获得权限，调岗只需改角色。支持角色继承和职责分离：同一人不能同时拥有"发起转账"和"复核转账"。
  • ABAC（基于属性）：按主体属性（部门、级别）、客体属性（密级）、环境属性（时间、网络位置）和策略动态判定，例如"信贷部员工、工作时间、行内网络、密级不高于本人许可，才能看授信档案"。

BLP 与 Biba：方向正好相反

BLP 模型保护机密性，两条规则：

  • 不上读（简单安全性）：主体只能读密级不高于自己的客体。
  • 不下写（*-性质）：主体只能写密级不低于自己的客体，防止高密信息被抄到低密文件里。

Biba 模型保护完整性，规则方向反过来：** 不下读、不上写**。低可信的数据不能污染高可信的主体，低可信的主体也不能改高可信的数据。

一个“秘密”级主体，面对三个级别的文件

1 / 5

第1步 · BLP 读

读“公开”✓，读“秘密”✓，读“机密”✗（不上读）
2 / 5

第2步 · BLP 写

写“公开”✗（不下写，防止泄密），写“秘密”✓，写“机密”✓
3 / 5

读“公开”✗（不下读，防止被低可信数据污染），读“秘密”✓，读“机密”✓
4 / 5

写“公开”✓，写“秘密”✓，写“机密”✗（不上写）
5 / 5

第5步 · 对照

BLP 的“可读”集合恰好等于 Biba 的“可写”集合，practice 中对所有级别组合做了断言
LEVELS = {'公开': 0, '秘密': 1, '机密': 2, '绝密': 3}

def blp_can_read(subject, obj):
    """BLP 简单安全性：不上读（主体级别 ≥ 客体级别才能读）。"""
    return LEVELS[subject] >= LEVELS[obj]

def blp_can_write(subject, obj):
    """BLP *-性质：不下写（主体级别 ≤ 客体级别才能写），防止高密信息流到低处。"""
    return LEVELS[subject] <= LEVELS[obj]

Web 应用最常见的访问控制漏洞是越权：垂直越权是普通用户用到管理员功能，水平越权是同级用户访问对方数据（如改 URL 里的订单号）。防御是服务端对每个请求校验"当前用户是否拥有这个资源"，隐藏按钮起不到保护作用。

要点：

  • DAC 属主自主授权；MAC 系统按标签强制判定；RBAC 用户-角色-权限；ABAC 按属性和策略动态判定。
  • BLP 保机密：不上读、不下写。Biba 保完整：不下读、不上写。
  • RBAC 的两大原则：最小权限、职责分离。

12.15 浏览器安全：同源策略、CORS、Cookie 与会话

你登录网银后又在另一个标签页打开了陌生网站，它的脚本能读你网银页面里的余额吗？浏览器的同源策略拦住了它。本节讲同源策略、它的"开门机制"CORS，以及会话 Cookie、会话固定和点击劫持。[27] [28]

同源与同源策略

两个 URL 的协议、主机、端口三者都相同才算同源，路径不参与比较。以 https://www.bank.example/a/index.html 为基准：

同源判定：协议 + 主机 + 端口

同源策略限制跨源读取：脚本读不到其他源的 DOM、Cookie、LocalStorage 和跨源响应。<img>、<script>、<iframe> 等标签却可以跨源加载，表单也能跨源提交。这种"能发不能读"正是 CSRF 得以发生的原因。

前端 app.bank.example 要调用 api.bank.example 的接口，属于跨源。CORS 让服务器在响应头里声明"允许哪个源读取"：

PUT、DELETE、带自定义头、JSON 类型等非简单请求，会先发送 OPTIONS 预检请求。服务器要按白名单精确回显源，带凭据时不能使用 *，下面的 cors_headers 实现了这两条。[29]

会话 Cookie 的三个属性

登录成功后，服务器把会话 ID 放在 Cookie 里，浏览器之后每次请求自动带上。会话 ID 就等于登录状态，所以它的 Cookie 要设置：

属性作用
HttpOnly脚本读不到这个 Cookie，XSS 后无法直接偷走会话
Secure只通过 HTTPS 发送，防止明文链路上被窃听
SameSite=Lax / Strict跨站请求不带 Cookie，防 CSRF；Lax 只在跨站顶层 GET 导航时带，Strict 一律不带

会话 ID 用 CSPRNG 生成，设空闲超时和绝对超时，退出时服务端销毁。[30]

会话固定

会话固定：攻击者先拿到一个未登录的会话 ID，设法让受害者带着它登录；网站若登录后沿用原 ID，攻击者手里的 ID 就变成了"已登录"。就像买二手车不换锁，原车主的备用钥匙照样能开门。

点击劫持

攻击页面把目标网站用透明的 <iframe> 叠在诱导按钮上方，用户以为点"领取奖品"，实际点中了网银页面的"确认"。这是界面欺骗，同源策略管不到。

防御是让目标页面声明"不允许被别人嵌入"：响应头 Content-Security-Policy: frame-ancestors 'self'（现代标准），或旧式的 X-Frame-Options: DENY / SAMEORIGIN。敏感操作再加二次确认（输入密码、短信验证码），透明层就没法替用户完成。[32] [33]

要点：

  • 同源 = 协议 + 主机 + 端口相同；同源策略限制跨源读取，不限制跨源加载和提交。
  • CORS 由服务器通过 Access-Control-Allow-Origin 授权跨源读取；带凭据时不能用 *。
  • 会话 Cookie 设 HttpOnly、Secure、SameSite；登录后重新生成会话 ID 防会话固定。
  • 点击劫持用 CSP frame-ancestors 或 X-Frame-Options 防御。

12.16 SQL 注入与 XSS：数据被当成了代码

SQL 注入和 XSS 本质相同：程序把不可信的输入拼进了会被解释执行的文本（SQL 语句、HTML 页面），特殊字符改变了文本结构，"数据"越界成了"代码"。防御的总原则也相同：让数据始终只作为数据。[34] [35] [36] [37]

SQL 注入：原理与参数化查询

上：拼接让数据参与了语法解析；下：参数化查询把语法和数据分两路送给数据库

用一个完全无害的输入就能看出问题。用户表里有一位客户叫 O'Brien：

def find_user_concat(db, name):
    """反例：把输入拼进 SQL 文本，输入里的引号会改变语句结构。"""
    return db.execute("SELECT balance FROM users WHERE name = '" + name + "'").fetchall()

def find_user_param(db, name):
    """正确做法：SQL 结构先固定，输入只作为参数值传入。"""
    return db.execute('SELECT balance FROM users WHERE name = ?', (name,)).fetchall()

拼接版本里，单引号提前结束了字符串，后面的 Brien' 成了 SQL 语法，数据库报语法错误；参数化版本正确返回余额 50。普通引号都能改变语句结构，精心构造的输入就能让条件恒真、绕过登录或读出其他表，这就是 SQL 注入。页面不显示错误时，攻击者还能靠页面差异或响应时间推断数据（盲注）。

防御措施按重要性排列：

  1. 参数化查询（预编译语句）：根本解法，如 JDBC 的 PreparedStatement、Python 的 ? 占位符、MyBatis 的 #{}（${} 是拼接，要避免）。
  2. 白名单：表名、列名、ORDER BY 字段无法参数化，只能从预定义列表里选。
  3. 最小权限：数据库账号只给需要的表和操作。
  4. 统一错误页：数据库报错只记日志，用户只看到通用提示。

转义函数是黑名单思路，遇到宽字节编码等情况会失效，只能辅助。

XSS：脚本被注入到页面里

跨站脚本（XSS） 让攻击者的脚本在受害者浏览器里以目标网站的身份运行，同源策略保护的页面内容、非 HttpOnly 的 Cookie 都向它敞开。按恶意内容来源分三类：

类型恶意内容在哪触发方式典型位置
存储型保存在服务器数据库任何人浏览该页面都会触发评论、留言、个人简介
反射型在请求参数里，服务器原样“反射”回页面诱导用户点击特制链接搜索结果页、错误提示
DOM 型在 URL 片段等客户端数据里，由前端脚本写入页面同样靠特制链接，可能不经过服务器前端用 innerHTML 渲染 URL 参数

存储型 XSS 的路径；在“拼进 HTML”这一步做编码就能切断

XSS 的防御层次：

  1. 按输出上下文编码：HTML 正文做实体编码（< 编码为 &lt;，& 编码为 &amp;，" 编码为 &quot;），HTML 属性、JS 字符串、URL 各有对应的规则。模板引擎（Thymeleaf、Jinja2、React）默认自动编码，应保持开启。

要点：

  • SQL 注入和 XSS 的共同本质：不可信输入被当作代码解释。
  • SQL 注入首选参数化查询，辅以白名单、最小权限、隐藏错误信息。
  • XSS 分存储型、反射型、DOM 型；首选按上下文输出编码，辅以 CSP、HttpOnly、富文本白名单。

12.17 CSRF、文件上传、SSRF 与反序列化

这四类漏洞同出一源：系统过度信任了某样东西。CSRF 信任了浏览器自动带上的 Cookie，文件上传信任了用户给的文件，SSRF 替用户访问用户指定的地址，反序列化信任了外部传来的对象数据。[38] [39] [40]

CSRF：借用户的身份发请求

用户登录网银后没退出，又打开了一个恶意页面，页面里藏着自动提交到网银转账接口的表单。浏览器自动带上网银的 Cookie，服务器看到合法会话就执行了转账。攻击者没拿到 Cookie，只是"借用"了它。

防御措施：

  1. CSRF 令牌：服务器为会话生成随机令牌嵌入表单，提交时校验；恶意网站受同源策略限制读不到它。
  2. SameSite Cookie：跨站 POST 不带会话 Cookie。
  3. 校验 Origin / Referer 头：作为补充。
  4. 敏感操作二次验证：转账前再输支付密码或短信验证码。

文件上传

服务器把上传文件放进会被解释执行的 Web 目录，上传一个脚本就等于在服务器上执行任意代码。漏洞要同时满足三个条件：文件能被当作脚本解释、能通过 URL 访问、内容没被处理改变。防御就是逐个拆掉这些条件：[41] [42]

  • 服务端扩展名白名单（只看最后一个扩展名、统一小写），结合文件头校验类型；
  • 随机重命名，弃用用户给的文件名和路径；
  • 存储目录不可执行，最好放独立文件服务器，用单独域名下载；
  • 限制大小，图片可重新压缩。

例如 upload_ok 允许 photo.JPG，而拒绝 shell.php、a.jpg.php 和含有空字符的文件名。

SSRF：让服务器替你访问内网

"按 URL 抓取图片""网页预览"这类功能由服务器按用户给的地址发请求。服务器位于内网，能访问内部管理接口、数据库、云平台元数据服务（如 169.254.169.254）。不加限制，攻击者就能借服务器之手访问这些资源，这叫服务端请求伪造（SSRF）。[43]

防御方法是目标白名单加网络隔离：只允许 https 协议和白名单中的主机；校验域名解析后的 IP，拒绝回环地址、内网地址和链路本地地址；禁止自动跟随重定向；在网络层限制出站流量。下面的 ssrf_target_ok 实现了应用层的检查。

反序列化

反序列化把字节流还原成对象。Java 原生序列化、Python pickle 在还原时会按数据内容构造对象、调用特定方法。数据若来自外部（Cookie、请求体），攻击者就能让还原过程触发现有类的危险操作，甚至远程执行代码；2016 年某 Java 安全框架的"记住我"Cookie 漏洞就是典型。[44]

防御：对外部数据只用 JSON 等纯数据格式；必须用原生序列化时，对数据做签名校验并设置类白名单；及时升级存在已知漏洞的组件。

要点：

  • CSRF 利用浏览器自动携带 Cookie；防御首选 CSRF 令牌 + SameSite，辅以 Origin 校验和二次验证。
  • 文件上传：白名单扩展名、重命名、存储目录不可执行、独立域名。
  • SSRF：服务器按用户给的地址发请求；防御是目标白名单、校验解析后 IP、禁止重定向、网络层出口限制。
  • 反序列化：外部数据不要用原生对象序列化，改用 JSON 或签名 + 类白名单。

12.18 网络边界防护：防火墙、DMZ、IDS、IPS 与 WAF

网银服务器要对整个互联网开放，核心账务数据库却只应被少数内部系统访问。管住"谁能连到谁"靠防火墙和边界架构；在放行的流量里找出攻击靠 IDS、IPS 和 WAF。[45] [46] [47]

包过滤按规则自上而下首次匹配，都不匹配时执行默认拒绝。

def packet_filter(rules, pkt):
    """无状态包过滤：自上而下找第一条匹配的规则；都不匹配就默认拒绝。"""
    for r in rules:
        if all(r[k] in ('*', pkt[k]) for k in ('src', 'dst', 'proto', 'dport')):
            return r['action']
    return 'deny'

用三条规则模拟一遍：规则一，任意源访问 203.0.113.10 的 TCP 443 端口，允许；规则二，访问 203.0.113.10 的 TCP 22 端口，拒绝；规则三，运维机 10.0.0.8 访问 TCP 22 端口，允许。运维机访问 203.0.113.10:22 时先命中规则二，被拒绝；访问 10.0.0.9:22 时命中规则三，放行；外部访问 203.0.113.10 的 UDP 53 端口不匹配任何规则，默认拒绝。可见规则的顺序决定了规则的含义，具体的例外要放在宽泛的规则前面。

状态检测解决"回包怎么放"：内网主动访问外部时，防火墙在状态表记下这条连接，回包匹配才放行；外部主动发来的包表里没有记录，被拒绝。

边界架构与 DMZ

屏蔽子网结构：对外服务放在两道防火墙之间的 DMZ，互联网无法直达内网

经典体系结构有四种，安全性逐级提高：筛选路由器（路由器兼做包过滤）、双宿主主机（两块网卡、关闭路由转发，内外网只能经它代理）、屏蔽主机（筛选路由器 + 唯一对外可见的堡垒主机）、屏蔽子网（两道防火墙之间划出 DMZ）。

DMZ 的规则：互联网只能访问 DMZ 中指定服务的端口；DMZ 只能按需访问内网少数接口；互联网到内网一律拒绝。DMZ 的 Web 服务器即使被攻破，前面还有第二道防火墙。运维人员统一经运维堡垒机登录服务器，集中做认证、授权和操作录像审计。

IDS、IPS 与 WAF

防火墙放行的流量里仍可能藏着攻击。

  • IDS（入侵检测系统）：** 旁路部署**，分析镜像流量，发现攻击就告警；不在转发路径上，不影响网络，也无法实时阻断。分主机型 HIDS（看日志、进程、文件）和网络型 NIDS（看网段流量）。
  • IPS（入侵防御系统）：** 串联部署**在必经之路上，发现攻击当场阻断；误报会直接影响业务。
  • WAF（Web 应用防火墙）：专门检查 HTTP/HTTPS，拦截 SQL 注入、XSS、CC 攻击等。它按规则拦"长得像攻击"的请求，用弱口令正常登录这类请求拦不住，所以代码层面的修复仍要做。

检测方法分为两类：误用检测（特征检测）比对已知的攻击特征，准确但发现不了新的攻击；异常检测在行为偏离正常模式时报警，能发现未知攻击，但误报较多。

要点：

  • 防火墙三类：包过滤（无状态）、状态检测、应用代理；包过滤首次匹配、默认拒绝。
  • 屏蔽子网在两道防火墙之间划出 DMZ，对外服务放在 DMZ，互联网不能直达内网。
  • IDS 旁路检测告警；IPS 串联检测并阻断；WAF 专防 Web 应用层攻击。
  • 误用检测查已知、误报低；异常检测能发现未知、误报高。

12.19 拒绝服务、中间人攻击与 VPN/IPsec

拒绝服务破坏可用性，让合法用户用不了服务；中间人攻击插在通信双方之间，威胁机密性和完整性；VPN 和 IPsec 在不可信网络上建立可信通道。[48]

DoS 与 DDoS

DoS 用大量请求耗尽目标的某种资源；DDoS 由成千上万台被控制的"肉鸡"（僵尸网络）同时发起，流量大且来源分散，难以按 IP 封堵。

攻击耗尽什么原理一句话主要防御
SYN Flood服务器半连接队列只发 SYN、不完成三次握手，半连接占满队列SYN Cookie、缩短超时、前置清洗
UDP / ICMP Flood带宽海量无用数据包挤满链路运营商清洗、高防 IP

中间人攻击

攻击者设法让双方的流量都经过自己，就能窃听或篡改。常见手段与对应防御：

  • ARP 欺骗：冒充网关的 MAC 地址。防御：动态 ARP 检测、静态 ARP 绑定。
  • DNS 欺骗 / 缓存投毒：让域名解析到攻击者的 IP。防御：DNSSEC、可信的加密 DNS。
  • 伪造 Wi-Fi 热点、SSL 剥离（把 HTTPS 降级成 HTTP）。防御：HSTS，让浏览器只用 HTTPS 访问该站。

这些手段只能把流量"引过来"。只要使用 TLS 并正确校验证书，攻击者没有合法私钥，就读不懂也改不了。所以最根本的防御是 12.10 的证书校验，App 还可以做证书锁定。

VPN 与 IPsec

VPN 在公共网络上建立加密隧道，让分支机构或出差员工像在内网一样访问资源。两大类：** IPsec VPN**（网络层，常用于站点互联）和 SSL VPN（基于 TLS，常用于远程办公）。

IPsec 由三部分组成：

组件作用
AH（认证头，协议号 51）数据完整性与来源认证，防重放；不加密
ESP（封装安全载荷，协议号 50）加密 + 完整性与来源认证，防重放
IKE（密钥交换，UDP 500）双方认证身份、协商算法、用 DH 生成会话密钥

隧道模式把整个原始 IP 包加密后再套一个新 IP 头；传输模式只保护原包的载荷

传输模式只保护载荷、原 IP 头不变，用于主机到主机；隧道模式封装整个原 IP 包、加新 IP 头，用于网关到网关，可隐藏内网地址。

要点：

  • DoS 破坏可用性；DDoS 来自僵尸网络；SYN Flood 用 SYN Cookie 防，CC 攻击用 WAF、限流、验证码防。
  • 中间人的根本防御是 TLS + 正确的证书校验，辅以 HSTS、DNSSEC、动态 ARP 检测。
  • IPsec：AH 只认证不加密，ESP 加密并认证，IKE 协商密钥；传输模式保护载荷，隧道模式保护整个原包。

  • 反射放大攻击中，攻击者伪造的是受害者的源地址，被利用的反射服务器本身也是受害者。
  • AH 会认证外层 IP 头，经过 NAT 改写地址后校验就会失败；需要穿越 NAT 时一般用 ESP（配合 NAT-T）。

小结： DoS 攻击破坏可用性，SYN Flood 用 SYN Cookie 防御，CC 攻击用 WAF 加限流防御；中间人攻击靠证书校验来防范；IPsec 中 AH 提供认证，ESP 提供加密和认证，IKE 负责交换密钥，隧道模式会把整个原始数据包封装起来。

12.20 软件安全：缓冲区溢出、系统级防护与模糊测试

还有一类漏洞来自程序实现中的内存错误，最经典的是缓冲区溢出。C/C++ 不检查数组边界，原理和安全编码规则见第 1 章，这里从防御体系的角度串起来。[49] [50]

栈溢出的原理

栈帧从高地址到低地址依次放着参数、返回地址、旧栈底指针、局部变量。向局部数组写入超长数据，多出的字节向高地址覆盖，直到返回地址；函数返回时 CPU 跳到被篡改的地址，控制流被劫持。

buf 写越界会先碰到 canary，再碰到返回地址；canary 被改，函数返回前就会检测到

三道系统级防线

机制原理应对的问题
栈保护（Stack Canary）编译器在返回地址前放一个随机值，函数返回前检查它是否被改连续写越界覆盖返回地址
DEP / NX（数据执行保护）把栈、堆等数据页标记为不可执行把恶意代码写进数据区再跳过去执行
ASLR（地址空间布局随机化）每次运行时随机化栈、堆、共享库的基址；程序编译为 PIE 后自身代码段也能随机化攻击者预先知道要跳转的地址

GCC 用 -fstack-protector-strong 开启栈保护，MSVC 对应 /GS。单项防护可能被组合已有代码片段等手法绕过，所以三者同时开启，再叠加控制流完整性（CFI）。根本之道在源头：用带长度检查的函数、C++ 用 std::string 和 std::vector、开启编译器警告和 AddressSanitizer。

模糊测试

模糊测试（Fuzzing） 自动生成大量畸形、随机或边界输入喂给程序，监视崩溃和内存错误，是发现溢出类漏洞的主力手段。

覆盖率引导的模糊测试循环

1 / 5

第1步 · 准备种子

收集几份合法输入作为种子，例如几个正常的报文文件
2 / 5

第2步 · 变异

对种子做位翻转、插入、删除、拼接，生成新输入
3 / 5

第3步 · 执行并观察

运行被测程序，配合 AddressSanitizer 记录崩溃和越界访问
4 / 5

第4步 · 按覆盖率筛选

新输入走到了以前没覆盖的代码分支，就把它加入种子库
5 / 5

第5步 · 循环并报告

反复迭代，导致崩溃的输入保存下来，交给开发者复现和修复

按生成方式分基于变异（改已有样本）和基于生成（按格式规范构造）；AFL、libFuzzer 属于覆盖率引导的变异式模糊测试，与静态分析、代码审计互补。

要点：

  • 栈溢出：写越界覆盖返回地址，函数返回时控制流被劫持。
  • 栈保护检测返回地址前的 canary；DEP/NX 让数据区不可执行；ASLR 随机化地址；三者同时开启。
  • 模糊测试用大量畸形输入自动发现崩溃，覆盖率引导效果最好。

多选 · 理解检查 22　下面每项防护与它的作用，哪些对应正确？

A. DEP/NX：栈和堆上的数据不能被当作指令执行

B. ASLR：让每次运行时的库和栈地址都不同

C. Stack Canary：阻止数组越界写入的发生

D. 模糊测试：在程序运行时实时拦截攻击

查看答案与每个选项的解析

A · 正确：数据页被标记为不可执行。

B · 正确：攻击者难以预先确定跳转目标。

C · 错误：canary 是在函数返回前“发现”被改写并终止程序，越界写本身已经发生。

D · 错误：模糊测试是上线前的测试手段，用来发现缺陷。

易错点

  • ASLR 是操作系统提供的机制，Linux 和 Windows 都有；PIE 是编译选项，让可执行文件本身也能被随机加载。
  • Java、Python 等内存安全语言会检查数组边界，但它们调用的 C 扩展库和虚拟机本身仍可能有溢出。

小结： 缓冲区溢出可以改写返回地址；栈金丝雀检查是否被改写，DEP 禁止执行数据区的代码，ASLR 使地址随机化，三者叠加使用；Fuzzing 用畸形的输入寻找程序崩溃。

12.21 等级保护 2.0 与 AI 应用安全概述

技术之外，国家对信息系统安全有统一的制度要求，银行笔试常考；大模型应用又带来了新一类安全问题。本节各做概述。

等级保护 2.0

网络安全等级保护由《网络安全法》（2017 年 6 月 1 日施行）确立为法定义务。** 等保 2.0** 的核心标准是 GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》，2019 年 12 月 1 日实施，保护对象扩展到云计算、移动互联、物联网、工业控制系统和大数据。[51]

保护对象按"受侵害的客体"和"受侵害的程度"分为五级：

级别名称被破坏后的影响
第一级自主保护级损害个人和组织的合法权益
第二级指导保护级严重损害上述权益，或损害社会秩序、公共利益
第三级监督保护级严重损害社会秩序、公共利益，或损害国家安全
第四级强制保护级特别严重损害社会秩序、公共利益，或严重损害国家安全
第五级专控保护级特别严重损害国家安全

上：等保工作的五个环节；下：等保 2.0 技术框架“一个中心、三重防护”

基本要求分技术要求（安全物理环境、通信网络、区域边界、计算环境、管理中心）和管理要求（管理制度、机构、人员、建设管理、运维管理），共 10 类。第三级系统一般每年至少测评一次；银行网银、核心账务等系统通常定为第三级或更高。

AI 应用安全概述

大模型应用把自然语言变成了新的输入通道，主要风险如下，详见「AI导论」第 6 章：

  • 提示注入：输入或检索到的文档里藏着"指令"，诱导模型偏离任务，与 SQL 注入同构。
  • 敏感信息泄露：模型输出训练数据、系统提示或其他用户的数据。
  • 过度授权：Agent 握有发邮件、改数据库的工具权限，被注入后造成真实损害。
  • 数据投毒与对抗样本：污染训练数据，或给输入加人眼看不出的扰动。

防御沿用本章原则：外部内容只当数据、工具权限最小化、高风险操作人工确认、输出先校验再使用，加上沙箱和审计日志。[52]

要点：

  • 等保 2.0 核心标准 GB/T 22239-2019，2019 年 12 月 1 日实施；分五级，第三级为监督保护级。
  • 工作环节：定级、备案、建设整改、等级测评、监督检查；技术框架"一个中心、三重防护"。
  • AI 应用的主要风险：提示注入、敏感信息泄露、过度授权、数据投毒；防御核心是最小权限和"外部内容只当数据"。

多选 · 理解检查 23　关于等级保护 2.0，下面哪些说法正确？

A. 核心标准是 GB/T 22239-2019

B. 共分五个安全保护等级，第五级最高

C. “一个中心、三重防护”中的一个中心是安全管理中心

D. 等保 2.0 只适用于传统信息系统，云平台不在范围内

查看答案与每个选项的解析

A · 正确：《网络安全等级保护基本要求》。

B · 正确：第五级为专控保护级。

C · 正确：三重防护是安全通信网络、安全区域边界、安全计算环境。

D · 错误：等保 2.0 专门增加了云计算、移动互联、物联网、工业控制等扩展要求。

易错点

  • 定级依据是"被破坏后受侵害的客体和程度"，与系统规模、投入大小没有直接关系。
  • 提示注入无法单靠"在系统提示里写清楚不要听用户的"来解决，需要在权限和架构层面限制模型能做的事。

小结： 等级保护 2.0 依据 GB/T 22239-2019，分为五级，流程包括定级、备案、整改、测评、检查，框架是一个中心、三重防护；AI 应用的安全要求是：外部内容只作为数据处理，工具只授予最小权限，高风险操作需要人工确认。
