1. 5. 取舍 (Trade-offs)

工程上的”完美 sound + complete + 高效”往往是不可达三角。明智的取舍能让工具在实际使用中可用。

1.1. 5.1 Precise modeling — 假设上限

问题：动态数组、链表、合约实例数等没有静态上界。理论上要建模到无穷。实践中绝大部分 bug 在很小的状态空间就能找到。

模式：暴露一个 --precise-modeling 之类的开关，假设某些维度的上限（如”合约实例数 ≤ 16”）。低于上限的所有行为都精确建模；超出上限时给出警告或 unsound 标记。

适用标准（实战经验）：

只有”truly extreme cap“（真正极端的上限）才适合做开关。如果一个小型现实测试就能命中这个上限并暴露 bug，那它不是合理的上限——应该把上限调高甚至取消，或重新设计建模。

例：合约实例数 16。一个真实的 DeFi 协议很少在一次交易里创建 17 个合约实例；如果某个测试故意创建 17 个来 stress 工具，那个测试不代表真实场景。让一个真实场景永不命中的上限承担”精确建模”的代价是合理的。

反例：动态数组上限 5。常见的列表长度在 10-100，5 太小，会被现实测试命中。这种上限不应该做成 trade-off 选项。

1.2. 5.2 Sound over-approximation：nondet 替代复杂状态

某些操作（外部调用、密码学哈希、低层 assembly）的精确建模代价巨大。用 nondet 替代是 sound 的过近似：

  • nondet 表示”任何值都可能”
  • 求解器看到 nondet 后会探索所有可能值，包括最不利的
  • 如果即使在最不利情况下断言都不被违反，证明就成立
  • 反过来：如果 nondet 让一个本来不可能的反例成立，会出现虚假反例 (spurious counterexample)，需要人工 review

适用场景：

  • 外部库的不透明接口（合约调用、系统调用）
  • 模拟无法精确建模的物理操作（时钟、随机数、网络）

风险：过近似过强会让证明 fail，falsification 找出虚假反例。设计时给”关键 invariant”留有专用的精确建模，nondet 留给真正不能精确的部分。

1.3. 5.3 Under-approximation 的危险：silent truncation

欠近似 = 把状态空间缩小，使得在缩小后的空间里成立不代表原问题成立。

最常见的反模式：--unwind N --no-unwinding-assertions（或同类组合）。这个组合的语义是”所有循环最多展开 N 次，超出的路径静默截断（不报错）”。

危险：用户以为程序被完整验证，实际超出 unwind 上限的路径根本没被检查。如果 bug 在 N+1 步处发生，工具会自信地报告”无 bug”。

正确做法：

  • 找漏洞模式（bug-finding, falsification）：用欠近似可以接受——找到的反例真，找不到不代表无 bug。
  • 证明无漏洞模式（verification）：必须 sound；要么用 unwind assertion（超出时报失败），要么用归纳。

核心 takeaway

Sound 与 unsound 不是开关而是 spectrum。bounded soundness + 显式 unwind assertion 通常是工程上的甜区：在用户给定的深度内 sound，超出时显式提示。最危险的设计是”看起来完整但实际静默丢路径”。

2. 6. 空间换时间 —— 在形式化验证中并不总是有效

2.1. 6.1 直觉 vs 现实

经典的程序优化里，空间换时间是有效的：

  • 哈希表：用 O(n) 空间换 O(1) 查找
  • Memoization：缓存历史结果避免重算
  • Lookup table：预计算函数值

这些技巧在有运行时的程序里能加速。但在编译期分析的形式化验证里，它们通常让事情变慢。

2.2. 6.2 为什么缓存在 BMC 中往往是反模式

考虑一个想法：”频繁访问的 mapping 加一个 cache 层，避免每次都走完整 SMT array select。”

实现：

在 SMT 编码后会发生什么？

  • cache_key == key 是一个新的 if-then-else，每次调用都展开成 ITE 链。
  • cache_value 是一个新的全局符号变量；每次写都生成 SSA 赋值，每次读都涉及 path constraint。
  • 求解器原本只面对 mapping[key] 一条 array select；现在多了 cache 路径上的 5+ 条公理。
  • 切片器无法消除——因为 cache 是全局状态，可能影响后续读。

净效果：求解器要做更多工作来推理 cache 一致性。原本的”加速”在静态分析里变成”加重负担”。

类似的反例：

  • 过大的 lookup table：256 entries × 256-bit 值 = 65536 bit 的 SMT 状态，每次访问都是一次 array select。如果原始函数本身简单（如 sha256 的 round 函数），直接用 nondet 或 uninterpreted function 反而便宜。
  • 预分配的”对象池”：如果对象数量不大，让求解器自由分配反而比预分配 + 索引管理便宜。

2.3. 6.3 何时空间换时间在 BMC 中有效

并非所有”加内存”的优化都是反模式。关键标准：

替代物必须是公理 (axiom)，不是状态变量 (mutable state)。

合格的”空间换时间”：

  • Memoization 用 SMT array + 哨兵零初始化（见 2.5）：array 本身是单条结构，求解器对它有专用 decision procedure；额外的 distinctness 公理是一次性消化，不进入 path。
  • 编译期常量预计算：把运行时计算挪到前端，求解器看到的是字面量，零成本。
  • Lazy allocation 退化为 eager flat encoding（见 2.4）：用 bit-shift 索引代替嵌套 array，状态量没变但求解器看到的结构更简单。

不合格的：”空间换时间”：

  • 任何在 IR 里加新全局变量、新条件分支、新切片器盲区的方案。
  • 任何让求解器的 path constraint 变长的方案。

核心 takeaway

在形式化验证中，让求解器看到尽可能少的”中间状态”。如果你在前端加一层缓存，问问自己：求解器看到的 path 是变短还是变长？变长就是反优化。

3. 7. 抽象设计原则

把全文核心 takeaway 汇总成可迁移的 10 条：

  1. 建模正确不等于建模高效。同语义的两个模型，求解时间可能相差万倍。
  2. 每条 SSA = 一条 SMT 公式等式。优化 = 减少 SSA 数量。
  3. 类型表示要贴合求解器原生理论：用 native bitvector，少用结构体代理；用 native array，少用嵌套数组。
  4. 常量必须在前端就 fold。任何让常量经过运行时 helper 往返的降级路径都是杀手。
  5. 编译期常量边界 >> 符号边界。固定步数的循环要么硬展开，要么用 macro 展开，避免靠 --unwind 配置。
  6. 切片器友好的 IR：尽量用局部变量、避免无谓的全局写、避免不必要的副作用调用。
  7. 求解器选择是建模的一部分：你的问题域决定该用哪个 solver；让工具自动 hint 选择。
  8. Bounded soundness 通常足够：精确建模到一个”真实场景永不命中”的上限，比追求无界完美高效得多。
  9. 空间换时间在 BMC 中常常是反优化：缓存只在它”是公理而非状态”的时候有效。
  10. 测量优先：raw SSA / post-slice SSA / VCC / encoding time / solving time 这五个数字告诉你瓶颈在哪。直觉常常错。

4. 8. 替代验证策略：BMC 不是唯一路径

BMC 的核心 trade-off 是”用 bounded 完备性换 unbounded 不完备性”。这一节介绍 BMC 之外的几条主线，并说明 ESBMC 为什么明确不走它们——理解放弃了什么，比假装拥有一切更有价值。

4.1. 8.1 函数摘要 / Compositional verification

通用原理：把验证拆为”为每个函数独立验证 pre → body → post“。caller 在调用点用 post 作为 stand-in，跳过 callee body。整体状态空间从 O(|program|) 降到 O(Σ|function|)。

何时奏效：

  • 函数边界清晰、副作用局限
  • pre/post 容易形式化表达（类型系统强、ownership 显式的语言：Rust 的 Verus、Dafny、Why3）
  • 验证目标本身就是局部性质（接口契约、模块不变量）

何时失败：

  • 低层指针操作（C 的 void *、地址算术）
  • 回调函数、函数指针表（callee 的 post-condition 必须覆盖所有可能 callback）
  • 全局可变状态（每个函数的 post 都要描述对全局的影响 → 指数膨胀）

4.1.1. ESBMC 不走的原因

  • C/C++/Solidity 都有大量低层语义（指针强制转换、storage layout、ABI 边界）
  • 自动推 post-condition 在这些场景下失败率太高
  • 「中间件(下)」§3.8 value-set 的指针追踪是路径敏感的——路径外不再有效，跨函数失效
  • 用户手写 contract 在 ESBMC 设计哲学里被明确拒绝：”No user-supplied loop invariants ever”——这条原则同样适用于函数级 contract，因为用户写错就是 unsound 入口

替代位置：ESBMC 用 GOTO 内联（「前端篇」§2.6）+ 全程符号执行覆盖跨函数语义，付出的是 SSA 规模膨胀，换来的是不依赖人工抽象。

4.2. 8.2 Loop invariant inference

通用原理：循环用 invariant 替代展开。如果能找到强到足以证明 post-condition 的 invariant，步数无关，避免 unwind。

寻找方法：

方法原理代表
模板法（Houdini）枚举候选 invariant 模板（x ≤ y、a[i] = 0、…），逐个测试是否被循环保持Spec#
抽象解释推断「中间件(上)」§3.5 区间分析的不动点天然就是 invariant 候选ASTREE, IKOS
机器学习 / 数据驱动从循环执行轨迹学候选DIG, CLN2INV
Craig interpolation从反例的 UNSAT proof 提取 invariantIMPACT, Z3

4.2.1. ESBMC 状态

  • --loop-invariant 提供初步框架；记忆里 “Stream 2.2 param-subst attempt = 0 flips” 记录了工程实现遭遇的困难
  • 自动推断在 dispatcher harness 风格（while(nondet) { handle_call(); }）下根本失败——dispatcher loop 的真 invariant 是”任何可达状态”，不携带信息
  • ESBMC 的替代：k-induction 的 inductive step 形式上就是”假设 invariant 在 k 步成立，证明 k+1 也成立”——一种隐式的 invariant inference，invariant 不显式表达而是由 SSA 拓扑承载。代价是它对一般循环完备性弱（「中间件(下)」§3.14 双向搜索就是为补它的弱点而设）

4.2.2. 关键 takeaway

自动 invariant 推断与”人工写 contract” 表面上都给出 invariant，本质却是不同的可信度等级：

  • 工具推断的 invariant 是程序的 fact（由抽象域承认），sound 自动成立
  • 人写 invariant 是程序员的 claim（可能错），引入新的 trust 入口

ESBMC 选择前者作为有限的辅助（k-induction、--loop-invariant），拒绝后者作为主线。

4.3. 8.3 CEGAR / 谓词抽象 / Lazy abstraction

通用原理（CEGAR = Counterexample-Guided Abstraction Refinement）：

代表工具：SLAM（微软驱动验证）、BLAST、CPAchecker、SeaHorn。

优势：

  • 抽象状态空间可以远小于具体——某些理论上 unbounded 的程序在抽象上有 finite model
  • 谓词集合自动增长，工具自己发现需要哪些谓词
  • 对某些性质（控制流可达性、简单数值不变量）极强

劣势：

  • refinement loop 在最坏情况指数次迭代
  • 抽象层选择不当 → 永远不收敛
  • 实现复杂度极高（要维护”抽象模型 ↔ 具体程序”双向映射）
  • 反例的 trace 在抽象空间，需要”具体化”才能给用户看

4.3.1. ESBMC 不走的原因

  • BMC + bit-blast 已能处理大部分 C/C++ 程序的具体语义，无需先抽象后细化
  • 智能合约（Solidity）状态空间不大，bounded BMC 够用，CEGAR 收益不显著
  • CEGAR 引擎对工具实现是巨大的工程投入：需要专门的 abstract domain framework、refinement strategy、predicate discovery 算法
  • 与 ESBMC “实用主义、能用 SMT 解决的就丢给 SMT” 的设计哲学冲突

4.3.2. Lazy abstraction（McMillan IMPACT 风格）

CEGAR 的一个变体：沿程序路径 lazily 引入谓词，每条路径只抽象成必要的精度。技术核心是 Craig interpolation：从一条 spurious 反例的 SMT UNSAT proof 中提取最弱的谓词，用作该路径的新抽象。

ESBMC 同样不走这条路，原因相同。但 Craig interpolation 本身在 SMT 求解器内部被广泛使用（unsat core extraction），所以这一技术并非”ESBMC 不知道”，而是”ESBMC 选择不用作主分析方法”。

5.1. 9.1 关键指标的层次

  • Solving：纯求解时间。这才是求解器的真实工作量。

5.2. 9.2 等价语言对比作为后端 baseline

诊断”前端 vs 后端谁慢”最有效的办法：把同一段语义用一种已知后端友好的语言重写。

实战案例：某个 Solidity 合约 napp_struct_multifield_fail 在 BMC 工具里 timeout（symex 28s, 49K SSA）。猜测是后端 SMT 求解器的瓶颈。但用 C++ 写一个byte-identical 等价的程序（同样的 struct 嵌套数组、同样的 push/pop、同样的 dispatcher harness）：

symex 时间raw SSA
Solidity 版本28s49,155
C++ 等价版本0.044s902

640× SSA 膨胀。这立即告诉我们：问题不在后端——同样的 SMT 工作量，C++ 前端只产生 1/640 的 SSA。瓶颈在 Solidity 前端的降级逻辑。

后续诊断聚焦于”为什么 Solidity 前端把同一段语义生成了 640 倍 IR”，定位到了 bytes32(uint256(N)) 嵌套 cast 的 round-trip bug，修复后 raw SSA 降到 32K（-34%）。

核心 takeaway

诊断 BMC 工具瓶颈时，用一种你信任的低成本语言写一份等价程序，对比关键指标。这能立刻分清”前端慢”还是”后端慢”。前者在你的工具里能修；后者通常要换求解器或改建模。

6. 10. 结语：建模即设计

形式化验证的”建模”不只是”把语言翻译成逻辑”，更是一个设计活动：

  • 设计每个数据类型的 SMT 投影
  • 设计每个语言构造的 IR 降级路径
  • 设计跨阶段（前端 / 中间件 / 后端）的成本分配
  • 设计哪些维度精确建模、哪些过近似
  • 设计哪些工具自动选择、哪些用户配置

差的设计让一个简单测试 timeout；好的设计让复杂合约毫秒级出结果。这种差距来源于对每个层级成本的清晰认识，而非某种神秘的”工程功夫”。

希望读完本文后，下一次遇到”我的 BMC 工具好慢”时，你不再问”求解器是不是太弱”，而是问：

  1. SSA 数量是多少？切片切掉了多少？
  2. 哪个函数贡献了 most live SSA？
  3. 求解时间是不是远小于 symex+encoding 时间？
  4. 我的类型表示是不是直接落在求解器原生理论上？
  5. 我的常量在前端就 fold 了吗？
  6. 我的循环边界是常量还是符号？
  7. 这个 trade-off 有没有被一个真实测试命中过？

带着这些问题去看你的工具的 IR / 公式 / 求解器输出。优化建模的本质，是让逻辑公式成为程序员的合作伙伴，而不是负担。

7. 附录 A：本文涉及的关键技术清单

为了快速回顾，这里列出本文讨论的所有具体技术，每条一行：

  1. 类型选择：用 native bitvector 表示固定长度二进制串。
  2. 常量折叠：嵌套类型转换中，每层独立处理 hint，不透传外层期望。
  3. 库函数 vs 内联：常量边界小操作内联展开，大状态操作库函数。
  4. Macro unroll：STEP(0); STEP(1); ...; STEP(31) 替代符号边界 for 循环。
  5. 嵌套数组展平：(zext(k) << bits) | offset 索引代替嵌套 array。
  6. Memoization via SMT array：哨兵零初始化 + 一致性公理。
  7. Per-pair distinctness assume：让 SMT array memo 同时具有”无碰撞”性质。
  8. Typed-element store：arr[i] = elem 单条 SSA，避免字节级 memcpy。
  9. Strong update via VSA：用 VSA 让单点写入对应单条 SMT array store。
  10. Field-level havoc：循环不变量推导只 havoc 实际写过的字段。
  11. Fresh symbol freezing：跨帧表达式先冻结到 fresh SSA 变量。
  12. Eager static analysis vs lazy runtime check：能在前端做的不留给后端。
  13. Forward-condition auto-disable：dispatcher 风格的程序跳过 forward 阶段。
  14. Realloc copy-count cap：常量大小用精确值，符号大小用配置上限。
  15. Inline modifier substitution：函数修饰符直接替换源码，避免函数调用开销。
  16. Compile-time field write tracking：循环体扫描决定 havoc 字段集。
  17. Wide-BV concat for hash inputs：变宽 array 桶替代固定宽度溢出。
  18. Multi-arg fold (FNV-style)：order-sensitive 多参数哈希用 multiplicative fold。
  19. Address-replicated XOR fold：每实例 address 与索引交叉防碰撞。
  20. Per-mapping flat encoder：替代全局 mapping pool 的索引展平。
  21. Solver auto-hint：基于问题特征自动选择 Z3 / Bitwuzla / CVC5。
  22. Native datatype tuples：CVC5 mkTupleSort 替代 SMT-LIB flatten。
  23. Bounded scope soundness：确定性的有限上限优于无界的精确。
  24. Approximation warning visibility：每次过近似留下显式日志。
  25. SSA-cost histogram：按函数归类活 SSA，定位热点。
  26. Equivalent-language baseline：用 C/C++ 等价程序对比定位瓶颈。
  27. Slicer-friendly IR：局部优于全局，pure 函数优于副作用。
  28. Loop unwind clamp：把符号循环边界硬限制到一个常量上限。
  29. Layered solving (k-induction)：base / forward / inductive 三阶段，各自不同优化策略。
  30. Empirical measurement first：永远先测量再优化，直觉是不可靠的。
  31. 死代码先于切片：语法 no-op 与 CFG 不可达消除是廉价、精确、可叠加的 pass，应在切片之前部署。
  32. Cleanup pass 双部署：每个会引入新指令的 instrumentation pass 后必须再跑一次清理；覆盖率模式必须可关闭清理以保留诊断信号。
  33. 反向单遍 SSA 切片：SSA 单赋值让切片从复杂数据流分析降级为单次反向扫描；对 ASSERT 反向追踪 depends，过 step 后立刻把 lhs 移出集合。
  34. 数组索引集追踪：用 arr ↦ {const_idx, ...} 替代”整数组依赖”，对未访问索引上的 store 改写为透传，避免 store-select 链膨胀。
  35. 切片器分层职责：末段死代码消除（廉价） + 中段不相关消除（昂贵）；--no-slice 只关后者，不关前者。
  36. 简化器作为前端合作伙伴：memcpy/memset 特殊化、解引用断言剪枝、常量 cast 消除都依赖简化器把表达式压到可识别的常量形式；关闭简化器会级联触发慢路径。
  37. SSA-time 常量传播：在 L2 重命名表里给每个符号挂一个 constant 槽；BMC 因单路径展开而无需 lattice，传播退化为 O(1) 的赋值时判定与读时查表，并与简化器级联完成「propagate-then-fold」。
  38. 抽象解释三件套：「抽象域 + 传递函数 + worklist 不动点」是任何静态值域分析的骨架；区间域是其最经典实例，可证明 sound 地过近似数值集。
  39. Widening / Narrowing：循环中区间单调增长不一定到达不动点；widening 把扩张方向直接推到 ±∞ 强制收敛，narrowing 在不动点后用循环出口条件回收精度。后者在 ESBMC 当前实现里 abort，由 assume-asserts 迂回替代。
  40. 离线 pass + 在线 domain 双部署：同一个区间域既作 GOTO-level 静态 pass（一次性 fixpoint + 表达式重写 + ASSUME 插入），又作 symex-time 单实例在线域（每条指令喂数据、loop GOTO 永真剪枝、ASSERT 永真剪枝）；后者要求「只剪 TRUE、不剪 FALSE、不在 branch 上 assume」三条硬约束防止单实例污染。
  41. 多属性独立求解：单次 symex 产生一份完整 SSA；按 assert 逐条切片复制等式、独立调用 solver；用户得到 N 条独立判决而非”程序至少有一个 bug”。代价是 N 次切片 + N 次 solver 初始化，依赖切片器线性闭包与 solver 启动开销可控。
  42. 用户断言优先重排序：multi-property job 队列按”源码 vs 库”做 stable_sort，把用户写的 assert 放在 c2goto/library 注入的前面，避免 fail-fast 配额被库模型的 spurious 检查吃光。
  43. k-induction + multi-property 全局清空：FC 或 IS 成功后把 goto 程序里所有 is_assert() 改成 skip，下一轮 k 检测到 0 个 active assert 即可干净退出，避免在空公式上跑到 max-k。
  44. runtime_encoded_equation + push/pop：增量 SMT 求解的承载结构；每个 SSA step 立即 convert+assert 到 solver，再通过 push_ctx/pop_ctx 实现”问完即撤”的临时假设。
  45. 双向 tvt 推断：ask_solver_question(q) 必须问两次（q 可满足？¬q 可满足？），由两个 SAT/UNSAT 的笛卡尔积推 tvt；单向 SMT 调用无法直接回答”恒为真”。
  46. symex-time 不可达分支剪枝：在 GOTO 的 guard 上调 ask_solver_question，UNSAT 即跳过整个分支的 symex；只在小程序 + 启动快的 solver 上划算。
  47. symex-time 平凡断言剪枝：在 assertion 上即时调 solver，能证明的 assert 转成 assume 不进最终公式；与 multi-property、interval-symex-assert 互补但语义层次不同（后者是抽象域代价、前者是真求解器调用）。
  48. encoding strategy vs verification strategy：--smt-during-symex 是编码层（同一 solver 全程持续 push/pop）；--incremental-bmc 是策略层（多轮独立 symex+solver，跨轮不复用上下文）；名字接近但完全正交。
  49. 函数内联三档：no-inlining / partial（默认 size 阈值）/ full；前端选择影响 slicer 跨帧能力 vs SSA 规模指数膨胀的 trade-off。
  50. 解引用 ITE 重写：*p 按 points-to 集合展开为嵌套 ITE 树；与「中间件(下)」§3.8 value-set 配套——前者提供集合，后者据此构造 cases。函数指针 / 虚函数表是 ITE 爆炸的典型来源。
  51. 并发 BMC 四类压缩：POR 等价交错合并、context-bound N=2-3 实践奏效、state hashing 状态去重、schedule recording 单调度。互不替代；POR 与 schedule 互斥。
  52. conv-assert-to-assume：bounds/pointer check 转 assume 让后续路径继承 fact；sound 当且仅当 check 是 prerequisite（违反即 UB），不可用于 obligation（程序责任）。
  53. 跨 k 迭代 SSA 缓存：缓存”claim 已证 UNSAT”这一 fact 是 sound 的（§6 缓存反模式的正面例外）；key 漂移在理论上 unsound 但工程上几乎不命中。
  54. IBEX 非线性约束传播：区间分析的线性限制由 IBEX box-consistency / HC4 contractor 补；仅在物理仿真 / 几何约束 / 连续数学场景启用，普通业务代码用不到。
  55. 双向搜索补 k-induction 完备性：从 inductive-step CEX 反推到 entry，过滤 spurious；理论 sound 工程不稳的活案例（SV-COMP 上引入 100+ errors）。
  56. 浮点编码四选一：floatbv (默认, SMT FP 理论)、fixedbv（定精度 BV，非 IEEE）、fp2bv（bit-blast，sound 但慢）、int-encoding（LIA 整数，仅在确证不溢出时 sound）。
  57. Tuple/Array 展平三策略：node flattener（简单 tuple 最快）、sym flattener（嵌套更紧凑）、CVC5 native datatype（≥3 维嵌套唯一可行）。
  58. BMC 不走的几条路：函数摘要（信任 user contract，违反 ESBMC 原则）、loop invariant 显式推断（dispatcher harness 下失败）、CEGAR/lazy abstraction（工程投入过大、bit-blast 已足够）。
  59. Online ↔ offline 语义不变：C ∧ ¬P 始终完整；online 改变的只是 C 进入 solver 的时机——assertion 的程序点局部性是 sound 的根本依据，不是工程 hack。
  60. Online 收益三支柱：早期不可行路径剪枝（省 symex+encoding）、solver 内部状态复用（learned clauses / theory propagation）、assertion 局部性（push/add(¬P)/check/pop 贴合语义）。
  61. Online 五类退化模式：query 无剪枝 / push/pop 破坏 solver 优化 / 前缀信息量不足 / 全局重写机会丢失 / CEX 构造复杂度上升——后三类只让 timeout 数变多，不让结果错，最难抓。
  62. Query placement 是决定性变量：信息密度跃升点（assume 后、循环边界、函数调用前）适合 query；assignment 后多半不值得问。”开 online” 是错误视角，”在哪 query” 才是性能变量。
  63. 示例集（/optimization-examples/）：6 个最小 C 程序 + run.sh 重放，分别演示 --no-remove-no-op/--no-remove-unreachable、--no-slice、--no-simplify、--interval-analysis-dump、--unwind N 边界敏感性、--multi-property 的可见 dump 差异。一手实证「中间件(上)」§3.1 / §3.2 / §3.3 / §3.5、「中间件(下)」§3.6、「后端篇」§4.4 的核心 takeaway。

8. 附录 B：进一步阅读

经典与现代的 BMC / SMT 文献：

  • Decision Procedures: An Algorithmic Point of View (Kroening & Strichman, 2008) —— SMT 求解器内部算法。
  • Handbook of Satisfiability (Biere, Heule, et al., 2009) —— SAT/SMT 综述。
  • Satisfiability Modulo Theories (Barrett, Sebastiani, Seshia, Tinelli, 2009) —— SMT 理论与工具。
  • CBMC: Bounded Model Checking for ANSI-C —— BMC 教科书级实现。
  • Verified Software: Theories, Tools, Experiments (VSTTE 系列会议) —— 工业实践。
  • CAV / TACAS / SAT 会议每年的 SMT 求解器竞赛 —— 不同求解器在不同 benchmark 上的性能数据。

工具源码（学习不同优化策略）：

  • Z3 (Z3Prover/z3) —— 通用 SMT，干净的 C++ API，源码可读。
  • Bitwuzla (bitwuzla/bitwuzla) —— bitvector 专用，看 BV decision procedure 实现。
  • CVC5 (cvc5/cvc5) —— QF_ABV、native datatype 实现的标杆。
  • CBMC / ESBMC —— 工业级 BMC 工具，前端到后端的完整 pipeline 可读。

本文从一段实际 BMC 工具的优化经验中提炼写就。具体工具可能不同，但其中讨论的原则、模式、陷阱都是 tool-independent 的——希望读者能在自己的工具上找到这些模式的具体投影。
