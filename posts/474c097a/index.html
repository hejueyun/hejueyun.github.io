很多数组题，最先想到的写法是两重循环：对每个元素，回头把别的元素再扫一遍。数据一多，这样就太慢了。本章的六种技巧，都在回答同一个问题：怎样不用回头再扫一遍。读完这一章，你应该能够：

  • 说出暴力写法回头扫的时候在找什么，并据此挑出合适的技巧；
  • 写出哈希查找、前缀和与差分、三种双指针、滑动窗口、单调栈与单调队列、二分边界；
  • 说清每种技巧为什么不会漏掉答案，以及它需要什么前提。

阅读本章需要第 1 章的 vector 和 unordered_map。链表、栈、队列的基本操作见 20.3～20.7，散列表的原理见 22.1，折半查找见 23.3。

12.1 技巧从哪里来：两重循环慢在哪里

暴力写法慢，是因为对每个元素都要回头把别的元素再扫一遍；每种技巧都是把这次"回头扫"换成一次查询或一个指针的移动。

一个例子：账单里找两笔

一张账单上有 5 笔金额：35、80、25、65、50。哪两笔加起来正好是 100 元？

最直接的办法：拿第一笔，和后面每一笔都加一加；再拿第二笔，和它后面每一笔都加一加……

// 账单 a 里找两笔加起来正好是 target 的，返回它们的下标；找不到返回 {-1, -1}。
pair<int, int> findPairBrute(const vector<int>& a, int target) {
    int n = (int)a.size();
    for (int i = 0; i < n; ++i) {              // 第一笔
        for (int j = i + 1; j < n; ++j) {      // 第二笔：再从头扫一遍后面的
            if (a[i] + a[j] == target) return {i, j};
        }
    }
    return {-1, -1};
}
# 账单 a 里找两笔加起来正好是 target 的，返回它们的下标；找不到返回 (-1, -1)。
def find_pair_brute(a, target):
    n = len(a)
    for i in range(n):                         # 第一笔
        for j in range(i + 1, n):              # 第二笔：再从头扫一遍后面的
            if a[i] + a[j] == target:
                return (i, j)
    return (-1, -1)

两重循环把每一对都试一遍：5 笔要试 10 对，第 1 行第 4 列找到 35 + 65

5 笔要试 10 对。n 笔就要试大约 n²/2 对：10 万笔就是约 50 亿次，太慢了。

回头扫的时候在找什么

慢就慢在内层循环：每拿到一笔 a[j]，都要回头扫一遍。仔细看，回头扫其实只是在找一个东西：有没有一笔正好等于 100 − a[j]。

不同的题，回头找的东西不同，省掉这一层的办法也不同：

回头扫在找什么技巧节

遇到一道新题，先写出暴力的两重循环，再问内层循环在找什么，就知道该用哪种技巧了。

要点

  1. 两重循环慢，是因为每个元素都要回头再扫一遍，总共约 n² 次。
  2. 内层循环往往只是在找一个东西；找的是什么，决定了用哪种技巧。
  3. 先写暴力，再问"回头扫在找什么"。

单选 · 理解检查 1　对每一天，都回头把前面所有天的气温扫一遍，看有没有哪天的气温和今天一样。内层循环在找什么，该用哪种技巧？

A. 找某个值有没有出现过，用哈希表

B. 找一段的总和，用前缀和

C. 找右边第一个更大的，用单调栈

D. 没有办法，只能两重循环

查看答案与每个选项的解析

A · 正确：把出现过的气温放进哈希表，查一下就知道。

B · 错误：这里不求和，只问某个值出没出现过。

C · 错误：找的是相等的值，而且在左边。

D · 错误：哈希表能把回头扫换成一次查询。

12.2 哈希表：把"再找一遍"变成"查一下"

哈希表能按值一步查到它在不在、在哪；把扫过的东西放进哈希表，以后要找它就不用再扫一遍。

想法

还是找两笔加起来是 100 的账单。从左往右扫，扫到 a[j] 时，要找的是前面有没有一笔等于 100 − a[j]。

如果把扫过的每一笔都记在一张"能按金额一步查到"的表里，这一步就从扫一遍变成了查一下。这样的表就是 哈希表，C++ 里是 unordered_map，Python 里是 dict。它为什么能一步查到，见 22.1。

// 同一个问题，用哈希表记下"见过的金额在哪个下标"，一遍扫完。
pair<int, int> findPairHash(const vector<int>& a, int target) {
    unordered_map<int, int> seen;              // seen[金额] = 它出现的下标
    for (int j = 0; j < (int)a.size(); ++j) {
        int need = target - a[j];              // 要和 a[j] 配对的金额
        auto it = seen.find(need);
        if (it != seen.end()) return {it->second, j};  // 前面见过：找到了
        seen[a[j]] = j;                        // 没见过：把自己记下来
    }
    return {-1, -1};
}
# 同一个问题，用哈希表记下"见过的金额在哪个下标"，一遍扫完。
def find_pair_hash(a, target):
    seen = {}                                  # seen[金额] = 它出现的下标
    for j, x in enumerate(a):
        need = target - x                      # 要和 a[j] 配对的金额
        if need in seen:                       # 前面见过：找到了
            return (seen[need], j)
        seen[x] = j                            # 没见过：把自己记下来
    return (-1, -1)

seen 记的是"金额 → 下标"。要先查再记：如果先把自己记进去，target 正好是自己的两倍时（比如 50 + 50），就会和自己配成一对。

扫一遍，每次查和记都是平均 O(1)，总时间 O(n)；代价是哈希表要占 O(n) 的空间。这是用空间换时间。

什么时候想到哈希表

题目问"有没有出现过""出现了几次""和它配对的在哪"，或者暴力写法的内层循环在找一个确定的值，都可以先想哈希表。

要点

  1. 把扫过的东西放进哈希表，以后要找它查一下就行。
  2. 先查再记，避免自己和自己配对。
  3. 时间从 O(n²) 降到 O(n)，代价是 O(n) 的空间。

单选 · 理解检查 2　用 findPairHash 在 [50, 50] 里找和为 100 的两笔，为什么要先查再记？

A. 先记再查的话，扫到第一个 50 就会查到自己，配成一对

B. 先记再查会更慢

C. 哈希表不能存相同的金额

D. 顺序无所谓

查看答案与每个选项的解析

A · 正确：先查时表里还没有自己，只能和前面的配对。

B · 错误：速度一样，问题是会把自己和自己配对。

C · 错误：能存，后存的会覆盖下标，但这不是这里的原因。

D · 错误：顺序决定了会不会和自己配对。

12.3 前缀和与差分：一段的总和变成两个数之差

先把"从开头到每个位置的总和"算好，任意一段的总和就等于两个前缀和相减；反过来，给一段批量加值时，只改两端，最后求一次前缀和。

前缀和

一周记了 5 天的步数（单位：千步）：3、8、2、6、5。之后会问很多次"第 l 天到第 r 天一共走了多少"。

每问一次都从 l 加到 r，最坏要加 n 个数。换个办法：先算好 前缀和 p[i]，表示前 i 天的总和，p[0] = 0。第 l 到第 r 天的总和，就是前 r + 1 天减去前 l 天：

第 l 到第 r 天的总和 = p[r + 1] − p[l]

第 1 到第 3 天：8 + 2 + 6 = 16，等于 p[4] − p[1] = 19 − 3

// 前缀和：p[i] = a[0] + ... + a[i-1]，p[0] = 0，长度比 a 多 1。
vector<long long> prefixSums(const vector<int>& a) {
    vector<long long> p(a.size() + 1, 0);
    for (int i = 0; i < (int)a.size(); ++i) p[i + 1] = p[i] + a[i];
    return p;
}

// 第 l 到第 r 天（两端都含）的总和 = p[r+1] − p[l]。
long long rangeSum(const vector<long long>& p, int l, int r) {
    return p[r + 1] - p[l];
}
# 前缀和：p[i] = a[0] + ... + a[i-1]，p[0] = 0，长度比 a 多 1。
def prefix_sums(a):
    p = [0] * (len(a) + 1)
    for i, x in enumerate(a):
        p[i + 1] = p[i] + x
    return p


# 第 l 到第 r 天（两端都含）的总和 = p[r+1] − p[l]。
def range_sum(p, l, r):
    return p[r + 1] - p[l]

算 p 要扫一遍，O(n)；之后每问一次只做一次减法，O(1)。p 比 a 多一格，是为了让 p[0] = 0 表示"前 0 天"，这样 l = 0 时也不用特判。

差分：反过来，给一段批量加

另一种问法：有很多次操作"第 l 到第 r 天每天加 v"，最后问每天是多少。每次都把 l 到 r 逐个加一遍，同样慢。

想一想"每天加 v"对相邻两天的 差 有什么影响：第 l 天比第 l − 1 天多了 v，第 r + 1 天比第 r 天少了 v，中间各天之间的差都不变。所以只记差的变化，每次操作只改两个数：d[l] += v，d[r + 1] −= v。最后对 d 求一次前缀和，就得到每天的值。这个 d 叫 差分数组。

每次操作只在两端各改一个数；最后一行是 d 的前缀和，正好是每天的值

// 差分：一共 n 天，每条记录 {l, r, v} 表示第 l 到第 r 天每天加 v。
// 返回加完以后每天的值。
struct RangeAdd {
    int l, r, v;
};

vector<long long> applyRangeAdds(int n, const vector<RangeAdd>& ops) {
    vector<long long> d(n + 1, 0);             // d = 差分数组，多留一格
    for (const RangeAdd& op : ops) {
        d[op.l] += op.v;                       // 从第 l 天起多了 v
        d[op.r + 1] -= op.v;                   // 从第 r+1 天起又少了 v
    }
    vector<long long> day(n);
    long long run = 0;                         // run = 差分的前缀和，就是当天的值
    for (int i = 0; i < n; ++i) {
        run += d[i];
        day[i] = run;
    }
    return day;
}
# 差分：一共 n 天，ops 的每条 (l, r, v) 表示第 l 到第 r 天每天加 v。
# 返回加完以后每天的值。
def apply_range_adds(n, ops):
    d = [0] * (n + 1)                          # d = 差分数组，多留一格
    for l, r, v in ops:
        d[l] += v                              # 从第 l 天起多了 v
        d[r + 1] -= v                          # 从第 r+1 天起又少了 v
    day, run = [], 0                           # run = 差分的前缀和，就是当天的值
    for i in range(n):
        run += d[i]
        day.append(run)
    return day

前缀和与差分是一对相反的操作：前缀和把"逐个的值"变成"累计"，差分把"累计"变回"逐个的值"。

要点

  1. 前缀和：一段的总和 = p[r + 1] − p[l]，p[0] = 0。
  2. 差分：给一段加 v，只改 d[l] 和 d[r + 1]，最后求一次前缀和。
  3. 预处理 O(n)，之后每次询问或操作 O(1)。

12.4 双指针：同向、相向、快慢

用两个下标代替两重循环：每一步只让其中一个往前走一格，总共最多走 2n 步；关键是说清楚，为什么跳过的那些情况不会有答案。

同向：一个读，一个写

把 0、4、0、7、2 里的 0 去掉，非零的保持原来的顺序挪到前面，不能开新数组。

用两个下标：read 从左到右读每个数，write 指着"下一个非零数该写到哪里"。读到非零数，就写到 write，write 往后挪一格；读到 0，跳过。

// 同向：把 a 里的 0 都去掉，非零的保持原来的顺序挪到前面，返回剩下几个。
int removeZeros(vector<int>& a) {
    int write = 0;                             // write = 下一个非零数该写到哪里
    for (int read = 0; read < (int)a.size(); ++read) {  // read = 正在读的位置
        if (a[read] != 0) a[write++] = a[read];
    }
    return write;
}

相向：一头一尾往中间走

账单金额从小到大排好：25、35、50、65、80，找两笔和为 100。

lo 从最左、hi 从最右出发，看 a[lo] + a[hi]：

  • 和太大：a[hi] 和最小的 a[lo] 配都太大，和别人配只会更大，a[hi] 不可能在答案里，hi 往左挪；
  • 和太小：同理，a[lo] 和最大的 a[hi] 配都不够，a[lo] 不可能在答案里，lo 往右挪；
  • 正好：找到了。

25 + 80 = 105 太大，排除 80；25 + 65 = 90 太小，排除 25；35 + 65 = 100，找到

// 相向：a 从小到大排好，找两数之和为 target 的下标；找不到返回 {-1, -1}。
pair<int, int> pairInSorted(const vector<int>& a, int target) {
    int lo = 0, hi = (int)a.size() - 1;        // 一个从最左，一个从最右
    while (lo < hi) {
        int s = a[lo] + a[hi];
        if (s == target) return {lo, hi};
        if (s < target) ++lo;                  // 和太小：左边这个数配谁都太小，排除它
        else --hi;                             // 和太大：右边这个数配谁都太大，排除它
    }
    return {-1, -1};
}
# 相向：a 从小到大排好，找两数之和为 target 的下标；找不到返回 (-1, -1)。
def pair_in_sorted(a, target):
    lo, hi = 0, len(a) - 1                     # 一个从最左，一个从最右
    while lo < hi:
        s = a[lo] + a[hi]
        if s == target:
            return (lo, hi)
        if s < target:                         # 和太小：左边这个数配谁都太小，排除它
            lo += 1
        else:                                  # 和太大：右边这个数配谁都太大，排除它
            hi -= 1
    return (-1, -1)

每一步都排除一个数，最多走 n 步。它要求数组有序：只有有序，才能从"和太大"推出"a[hi] 配谁都太大"。

快慢：一个走一步，一个走两步

一群人玩传纸条，每人手里的纸条写着下一个人的编号，写 −1 的表示到头了。从某人出发，跟着纸条一直走，会不会绕圈？

用两个人同时出发：慢的每次走一步，快的每次走两步。

  • 没有圈：快的先走到头，结束。
  • 有圈：两人迟早都进圈；进圈以后，快的每次比慢的多走一步，两人的距离每次缩短 1，一定会在圈里相遇。

3 号的纸条写着 1，于是 1→2→3→1 绕成一个圈；快慢两人会在圈里相遇

// 快慢：next[i] 是 i 号手里纸条写的下一个编号，-1 表示到头。
// 从 start 出发跟着纸条走，会不会绕圈？
bool hasCycle(const vector<int>& next, int start) {
    int slow = start, fast = start;
    while (fast != -1 && next[fast] != -1) {   // 快的还能再走两步
        slow = next[slow];                     // 慢的走一步
        fast = next[next[fast]];               // 快的走两步
        if (slow == fast) return true;         // 在圈里追上了
    }
    return false;                              // 快的走到了头：没有圈
}
# 快慢：nxt[i] 是 i 号手里纸条写的下一个编号，-1 表示到头。
# 从 start 出发跟着纸条走，会不会绕圈？
def has_cycle(nxt, start):
    slow = fast = start
    while fast != -1 and nxt[fast] != -1:      # 快的还能再走两步
        slow = nxt[slow]                       # 慢的走一步
        fast = nxt[nxt[fast]]                  # 快的走两步
        if slow == fast:                       # 在圈里追上了
            return True
    return False                               # 快的走到了头：没有圈

这个办法不用记"谁走过"，只用两个变量。链表上判断有没有环、找中点，都是这个办法：链表的每个节点就是一个人，next 指针就是纸条（链表本身见 20.3）。

要点

  1. 同向：read 读、write 写，write 不超过 read，原地筛选元素。
  2. 相向：有序数组一头一尾往中间走，每一步排除一个不可能的数。
  3. 快慢：快的走两步、慢的走一步，有圈就一定相遇。

12.5 滑动窗口：右端扩展，左端收缩

求满足条件的最长（或最短）一段时，让窗口的右端一格格往右扩；不满足条件了，就让左端往右收，直到又满足。左端只往右走、从不回头，所以一共只走 2n 步。

题目

每天的花费是 30、20、50、10、10、40 元，预算 70 元。最多能连续几天，总花费不超过预算？

暴力的办法：对每个起点，往右一天天加，超了就停。每个起点都要重新加一遍，O(n²)。

想法

注意一件事：花费都是正数。一段已经超预算了，把它往左再加长只会更超。所以当右端停在 right 时，可行的左端是连成一片的，而且 right 往右走，可行的左端只会往右挪，不会往左。

于是用一个"窗口" [left, right]：

  1. right 往右扩一天，把这天的花费加进总和；
  2. 总和超了预算，就把 left 那天减掉、left 往右挪，直到不超；
  3. 这时窗口就是"以 right 结尾、不超预算的最长一段"，用它的长度更新答案。

// cost[i] 是第 i 天的花费（都是正数），budget 是预算。
// 返回总花费不超过预算的最长连续天数。
int longestWithinBudget(const vector<int>& cost, long long budget) {
    long long sum = 0;                         // sum = 窗口 [left, right] 的总花费
    int left = 0, best = 0;
    for (int right = 0; right < (int)cost.size(); ++right) {
        sum += cost[right];                    // 右端扩展一天
        while (sum > budget) {                 // 超了：左端收缩，直到不超
            sum -= cost[left];
            ++left;
        }
        if (right - left + 1 > best) best = right - left + 1;
    }
    return best;
}
# cost[i] 是第 i 天的花费（都是正数），budget 是预算。
# 返回总花费不超过预算的最长连续天数。
def longest_within_budget(cost, budget):
    total = 0                                  # total = 窗口 [left, right] 的总花费
    left = best = 0
    for right in range(len(cost)):
        total += cost[right]                   # 右端扩展一天
        while total > budget:                  # 超了：左端收缩，直到不超
            total -= cost[left]
            left += 1
        best = max(best, right - left + 1)
    return best

right 走 n 步，left 也最多走 n 步，总共 O(n)。

前提：越长越难满足

滑动窗口能用，靠的是 "一段不满足，加长了也不满足"。花费有正有负时就不成立了：加进一个负数，总和反而变小，左端就不该只往右走。那种情况要换别的办法，比如前缀和加哈希表。

要点

  1. 右端扩展，不满足条件就收缩左端，左端从不回头。
  2. 总共 O(n)：每个元素进窗口一次、出窗口一次。
  3. 前提是"一段不满足，加长了也不满足"，比如数都是正数。

12.6 单调栈与单调队列：让还没等到答案的元素排队等着

找"右边第一个比它大的"时，把还没等到答案的元素放进一个栈里等着；新来的元素比栈顶大，栈顶就等到了答案。栈里的元素从底到顶始终是递减的，所以叫单调栈。

单调栈：往右看第一个更高的人

5 个人从左到右站成一排，身高是 160、150、170、155、180。每个人往右看，第一个比自己高的人是谁？

暴力：每个人都往右一个个看，O(n²)。

换个角度：从左往右，每来一个人，看他能替前面哪些人"揭晓答案"。

  • 160 来了，前面没人，160 等着。
  • 150 来了，没有 160 高，揭晓不了，150 也等着。等着的人：160、150。
  • 170 来了，比 150 高，150 的答案就是 170；也比 160 高，160 的答案也是 170。两人都不用等了。170 自己等着。
  • 155 来了，没有 170 高，等着。等着的人：170、155。
  • 180 来了，155、170 的答案都是 180。最后 180 没等到答案，记 −1。

等着的人有个规律：后来的一定比前面的矮（要是更高，前面的早就揭晓走了），所以从早到晚身高递减。新来一个人，只要从最晚等着的那个开始比，比他矮的就揭晓、离开，碰到比他高的就停：后面那些更早的人更高，也揭晓不了。"最晚来的先离开"，正好用栈。

栈里的人从底到顶越来越矮；新来的人从栈顶开始比，矮的都等到了答案

// h[i] 是第 i 个人的身高。返回每个人往右看、第一个比他高的人的下标；没有就是 -1。
vector<int> nextTaller(const vector<int>& h) {
    int n = (int)h.size();
    vector<int> ans(n, -1);
    stack<int> st;                             // 还在等答案的人，从底到顶越来越矮
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && h[st.top()] < h[i]) {  // i 比栈顶的人高
            ans[st.top()] = i;                 // 栈顶的人等到了答案
            st.pop();
        }
        st.push(i);                            // i 自己也等着
    }
    return ans;
}
# h[i] 是第 i 个人的身高。返回每个人往右看、第一个比他高的人的下标；没有就是 -1。
def next_taller(h):
    ans = [-1] * len(h)
    st = []                                    # 还在等答案的人，从底到顶越来越矮
    for i, x in enumerate(h):
        while st and h[st[-1]] < x:            # i 比栈顶的人高
            ans[st.pop()] = i                  # 栈顶的人等到了答案
        st.append(i)                           # i 自己也等着
    return ans

每个人进栈一次、出栈最多一次，总共 O(n)。

单调队列：窗口里的最大值

数组 1、3、−1、−3、5、3、6、7，求每个长度为 3 的窗口里的最大值。

窗口往右滑时，有一个现象：如果一个数比后来的某个数小，它就再也不可能当最大值了，因为后来的那个更大，而且会比它更晚离开窗口。所以只需要留下"可能当最大值"的那些数，它们从早到晚是递减的。

  • 新来一个数，从队尾把比它小的都扔掉，再把它放到队尾；
  • 队头如果已经滑出窗口，就从队头扔掉；
  • 窗口满了以后，队头就是这个窗口的最大值。

两头都要进出，用双端队列 deque（20.7）。

// a 里每个长度为 k 的窗口的最大值。
vector<int> windowMax(const vector<int>& a, int k) {
    vector<int> ans;
    deque<int> dq;                             // 可能当最大值的下标，值从头到尾递减
    for (int i = 0; i < (int)a.size(); ++i) {
        // 比 a[i] 小的再也当不了最大，从队尾扔掉
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();
        dq.push_back(i);
        if (dq.front() <= i - k) dq.pop_front();  // 队头已经滑出窗口
        if (i >= k - 1) ans.push_back(a[dq.front()]);  // 窗口满了：队头就是最大
    }
    return ans;
}
# a 里每个长度为 k 的窗口的最大值。
def window_max(a, k):
    ans = []
    dq = deque()                               # 可能当最大值的下标，值从头到尾递减
    for i, x in enumerate(a):
        while dq and a[dq[-1]] <= x:           # 比 a[i] 小的再也当不了最大
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:                     # 队头已经滑出窗口
            dq.popleft()
        if i >= k - 1:                         # 窗口满了：队头就是最大
            ans.append(a[dq[0]])
    return ans

结果是 3、3、5、5、6、7。每个数进出队列各一次，O(n)。

要点

  1. 单调栈：还没等到答案的元素在栈里等着，新来的元素替栈顶揭晓答案。
  2. 单调队列：比后来者小的元素永远当不了最大值，扔掉；队头就是窗口最大值。
  3. 每个元素进出各一次，都是 O(n)。

12.7 二分查找的边界：lo 和 hi 圈出还没确定的范围

在有序数组里找"第一个满足条件的位置"时，用 [lo, hi) 圈出还没确定的范围，每一步看中间那个，把不可能的那一半整个排除，直到范围变空。

题目

一组成绩从低到高排好：45、58、60、60、72、90。第一个及格（≥ 60）的成绩在哪个位置？

23.3 的折半查找是找某个值在不在。刷题时更常见的是这种"第一个满足条件的位置"：有重复值时找最左边那个，没有正好相等的值时找插入的位置。

想法

答案只可能在 0 到 6 之间（6 表示一个都不及格）。用 lo、hi 把数组分成三段：

  • [0, lo)：已经确定 不及格；
  • [lo, hi)：还不知道及不及格；
  • [hi, n)：已经确定 及格。

开始时什么都不知道，lo = 0，hi = 6。我们要找的"第一个及格的位置"，永远是第三段的开头，也就是 hi。每一步看中间的 mid：

  • a[mid] ≥ 60：mid 及格了，它和它右边的都划进"确定及格"那一段：hi = mid。mid 离开了"还不知道"的范围，但没有丢：它现在就是 hi，是目前已知的第一个及格的位置；
  • a[mid] < 60：mid 和它左边的都不及格，划进"确定不及格"那一段：lo = mid + 1。

"还不知道"的范围空了（lo == hi）时，hi（也就是 lo）就是答案。

范围变空（lo == hi）时，lo 就是答案。

// a 从小到大排好。返回第一个 >= x 的下标；都比 x 小时返回 a.size()。
int firstAtLeast(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size();            // [lo, hi) 是还没确定的范围
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= x) hi = mid;             // mid 可能就是答案，右边都不用看了
        else lo = mid + 1;                     // mid 太小，连同左边都排除
    }
    return lo;                                 // 范围缩成空：lo 就是答案
}
# a 从小到大排好。返回第一个 >= x 的下标；都比 x 小时返回 len(a)。
def first_at_least(a, x):
    lo, hi = 0, len(a)                         # [lo, hi) 是还没确定的范围
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] >= x:                        # mid 可能就是答案，右边都不用看了
            hi = mid
        else:                                  # mid 太小，连同左边都排除
            lo = mid + 1
    return lo                                  # 范围缩成空：lo 就是答案

每一步至少排除一个数，范围一定会变空，不会死循环；每次排除一半，O(log n)。mid 写成 lo + (hi − lo) / 2，是为了在 C++ 里 lo + hi 很大时不溢出。

为什么这样写不容易错

二分最容易错在边界：hi 是 n 还是 n − 1，循环条件是 < 还是 ≤，更新是 mid 还是 mid ± 1。只要始终记住三段：[0, lo) 确定不满足，[lo, hi) 还不知道，[hi, n) 确定满足，这些都能推出来：

  • 一开始什么都没确定，答案可能是 0 到 n（n 表示都不满足），所以 lo = 0，hi = n；
  • 范围不空就继续，所以是 lo < hi；
  • a[mid] 满足条件，它属于"确定满足"那一段，所以 hi = mid（mid 就成了这一段的开头，答案没有丢）；不满足，它属于"确定不满足"那一段，所以 lo = mid + 1。

注意"还不知道"指的是还不知道满不满足，不是"还可能是答案"：答案住在 hi 这个边界上。

写法和 firstAtLeast 一样用 [lo, hi) 圈出还没确定的范围，只是判断反过来：

  • a[mid] ≤ x：mid 满足，但它右边可能还有满足的，mid 连同左边都不是"第一个不满足"的，lo = mid + 1；
  • a[mid] > x：mid 不满足，它可能就是第一个不满足的，留住它，hi = mid。

停下来时 lo 是第一个 > x 的位置，lo − 1 就是最后一个 ≤ x 的位置；都 > x 时 lo 是 0，返回 −1，表示没有。

// a 从小到大排好。返回最后一个 <= x 的下标；都比 x 大时返回 -1。
int lastAtMost(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size();            // [lo, hi) 是还没确定的范围
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] <= x) lo = mid + 1;         // mid 满足，右边可能还有：连它一起排除
        else hi = mid;                         // mid 不满足：可能就是第一个不满足的
    }
    return lo - 1;                             // lo 是第一个 > x 的位置，前一个就是答案
}
# a 从小到大排好。返回最后一个 <= x 的下标；都比 x 大时返回 -1。
def last_at_most(a, x):
    lo, hi = 0, len(a)                         # [lo, hi) 是还没确定的范围
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= x:                        # mid 满足，右边可能还有：连它一起排除
            lo = mid + 1
        else:                                  # mid 不满足：可能就是第一个不满足的
            hi = mid
    return lo - 1                              # lo 是第一个 > x 的位置，前一个就是答案

停下来的那个下标到底是什么

二分停下来的下标是什么意思，不是循环结束后再去猜的，而是写循环之前就定好的：先说清"区间里装的是什么"，每一步都保持这句话成立，停下来时这句话自然告诉你答案。

写任何二分之前，先回答三个问题：

  1. 区间里装的是什么？ 比如"还没确定的位置"，或者"答案一定在这里面"。
  2. 看完 mid，答案还可能是 mid 自己吗？ 可能，挪过去的那个边界就停在 mid 上；不可能，就越过它（mid + 1 或 mid − 1）。
  3. 停下来时区间剩几个？ 循环写 lo < hi，停下时 lo == hi，剩一个，它就是答案；循环写 lo <= hi，停下时 lo > hi，一个不剩，答案要靠循环里另外记下来（比如 34 题的 ans）。

第 2 个问题用找第一个及格的成绩来说明：

  • mid 是 60，及格了。第一个及格的可能就是它，也可能在它左边，所以 hi 挪过来 停在 mid 上：hi = mid。
  • mid 是 58，不及格，绝不可能是第一个及格的，所以 lo 越过 mid：lo = mid + 1。往左越过写 hi = mid − 1，只在闭区间、lo <= hi 的写法里出现（比如 34 题的 findLeft）。

所以 +1、−1 的意思就是"mid 已经确定不是答案，跳过它"；不加，就是"mid 可能是答案，停在它身上"。

拿"旋转排序数组的最小值"练一次。数组 4、5、6、7、0、1、2 是一个升序数组切开、后半段挪到前面得到的，找最小值。

  1. 区间 [left, right] 两端都含，最小值一定在这里面。开始时整个数组，当然成立。
  2. 看 nums[mid] 和 nums[right]：
    • nums[mid] < nums[right]：从 mid 到 right 是一路上升的，最小值不会在 mid 右边，但 mid 自己可能就是最小值，所以 right = mid，留住它；
    • 否则 nums[mid] > nums[right]：从 mid 到 right 中间一定有一次"掉下来"，最小值在掉下来之后，mid 自己不可能是最小值，所以 left = mid + 1。
  3. 两种情况都保持"最小值在 [left, right] 里"。循环写 left < right，停下时 left == right，区间只剩一个数，按第 1 句它就是最小值。

// 旋转排序数组的最小值（各不相同）：闭区间 [left, right]，最小值始终在区间里。
int findMinRotated(const vector<int>& nums) {
    int left = 0, right = (int)nums.size() - 1;
    while (left < right) {                     // 区间里还不止一个数
        int mid = left + (right - left) / 2;   // 向下取整，所以 mid < right
        if (nums[mid] < nums[right]) right = mid;  // mid 到 right 递增：最小值在 [left, mid]
        else left = mid + 1;                   // mid 在高的那段：最小值在 [mid+1, right]
    }
    return nums[left];                         // 只剩一个数，它就是最小值
}
# 旋转排序数组的最小值（各不相同）：闭区间 [left, right]，最小值始终在区间里。
def find_min_rotated(nums):
    left, right = 0, len(nums) - 1
    while left < right:                        # 区间里还不止一个数
        mid = (left + right) // 2              # 向下取整，所以 mid < right
        if nums[mid] < nums[right]:            # mid 到 right 递增：最小值在 [left, mid]
            right = mid
        else:                                  # mid 在高的那段：最小值在 [mid+1, right]
            left = mid + 1
    return nums[left]                          # 只剩一个数，它就是最小值

还有一个要检查的地方：每一步区间都必须变小，否则会死循环。mid 是向下取整的，left < right 时 mid 一定小于 right，所以 right = mid 会让区间变小；left = mid + 1 也会。反过来，如果写成 left = mid，在只剩两个数时 mid 等于 left，区间不变，就会卡住。

什么时候写 lo < hi，什么时候写 lo <= hi

看每次判断完 mid，它会落到哪种结局。 mid 只有三种结局：

  1. mid 就是答案，而且能当场确定：直接 return；
  2. mid 一定不是答案：用 mid + 1 或 mid − 1 把它排除；
  3. mid 可能是答案，但还要往一边接着找：必须留住它。左闭右开时写 hi = mid，让它成为边界；闭区间时写 right = mid，让它留在区间里。
会出现的结局写法例子
只有 1 和 2闭区间 [lo, hi]，lo <= hi，两边都 ±1；区间空了还没返回就是不存在找等于 target 的位置（23.3）、4 题找正确的切口
有 3lo < hi，满足时 hi = mid；缩到只剩一个位置才知道答案firstAtLeast、lastAtMost、旋转数组最小值
有 3，但想用 lo <= hi先把 mid 记进 ans 再排除它，把"可能是"变成"排除"34 题的 findLeft、findRight

有第 3 种结局却写 lo <= hi，会在 lo == hi == mid 时执行 hi = mid，区间不再变小，程序卡死。所以 找边界、找最值这种"缩到最后才知道"的，写 lo < hi；找"那一个"、看到就能确定的，写 lo <= hi。

hi 一开始是 n 还是 n − 1

hi 的初值不是看"要不要访问下标"，而是看两件事：答案可能是 n 吗？循环里会读 nums[hi] 吗？

  • 答案可能是 n（表示一个都没有），比如 firstAtLeast 在所有数都比 x 小时返回 n：范围要包含 n，写成 [0, n)，hi = n。这种写法循环里只读 a[mid]，而 lo < hi 时 mid 一定小于 hi，所以不会越界。
  • 答案一定是 0 到 n − 1 之间的真实位置，比如旋转数组最小值的下标；或者 循环里要拿 nums[hi] 来比：hi 必须始终是真实的下标，写成闭区间 [0, n − 1]，hi = n − 1。

还要注意标准库的 lower_bound、upper_bound 用的都是左闭右开。要在闭区间 [left, right] 里查，结束位置要写成 begin() + right + 1。

C++ 标准库已经写好了这个函数，就是 lower_bound；只问在不在可以用 binary_search。它们和 find（从头一个一个看、不要求有序）有什么区别，见 2.5。

要点

  1. [lo, hi) 是还没确定的范围，范围变空时 lo 就是答案。
  2. 满足条件时 hi = mid，不满足时 lo = mid + 1。
  3. 每步排除一半，O(log n)；前提是数组有序（满足条件的都在右边一侧）。

练习 1　有序数组去重

一个从小到大排好的数组，原地去掉重复的数，每个数只留一个，返回剩下几个。写函数 removeDuplicates(a)。

样例：a = 1、1、2、3、3、3，返回 3，数组前 3 个变成 1、2、3。

提示

同向双指针：read 读每个数，只有和已经留下的最后一个（a[write − 1]）不同时才写。数组有序，相同的数挨在一起，所以只要和最后留下的比。

参考答案
// 练习 12.8-1：a 从小到大排好，原地去掉重复的数，返回剩下几个。
int removeDuplicates(vector<int>& a) {
    int write = 0;
    for (int read = 0; read < (int)a.size(); ++read) {
        // 和已经留下的最后一个不同，才留下
        if (write == 0 || a[read] != a[write - 1]) a[write++] = a[read];
    }
    return write;
}
# 练习 12.8-1：a 从小到大排好，原地去掉重复的数，返回剩下几个。
def remove_duplicates(a):
    write = 0
    for read in range(len(a)):
        if write == 0 or a[read] != a[write - 1]:  # 和已留下的最后一个不同才留
            a[write] = a[read]
            write += 1
    return write

练习 3　平均分达标的连续几天

score 是每天的分数。有几段连续 k 天，平均分不低于 60？写函数 goodWindows(score, k)。

样例：score = 50、70、65、40、80，k = 2，答案 3：(50, 70)、(70, 65)、(40, 80) 的平均分都不低于 60。

提示

窗口长度固定为 k：每次右边进来一天、左边出去一天，总和只要加一个减一个。平均分不低于 60 等价于总分不低于 60k，不用算除法。

参考答案
// 练习 12.8-3：score[i] 是第 i 天的分数，返回有几段连续 k 天的平均分不低于 60。
int goodWindows(const vector<int>& score, int k) {
    int count = 0;
    long long sum = 0;                         // sum = 最近 k 天的总分
    for (int i = 0; i < (int)score.size(); ++i) {
        sum += score[i];                       // 新的一天进窗口
        if (i >= k) sum -= score[i - k];       // 最早的一天出窗口
        if (i >= k - 1 && sum >= 60LL * k) ++count;
    }
    return count;
}
# 练习 12.8-3：score[i] 是第 i 天的分数，返回有几段连续 k 天的平均分不低于 60。
def good_windows(score, k):
    count = 0
    total = 0                                  # total = 最近 k 天的总分
    for i, x in enumerate(score):
        total += x                             # 新的一天进窗口
        if i >= k:                             # 最早的一天出窗口
            total -= score[i - k]
        if i >= k - 1 and total >= 60 * k:
            count += 1
    return count
