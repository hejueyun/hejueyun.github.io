15.1 二叉树的基本概念与性质 必读

目录、公司组织架构、比赛对阵表都有"一个上级、多个下级"的层级关系，用一条直线（数组、链表）画不出来，这就需要树。笔试里关于树的计算题，几乎都建立在几条性质上，这一节我们把它们推出来。

树由结点和连接它们的边组成：有一个特殊的结点叫根；除根以外，每个结点恰好有一个父结点（双亲）；从根出发能到达所有结点，并且没有环。几个基本术语：

术语含义
结点的度这个结点的孩子个数
树的度所有结点度的最大值
叶子（终端结点）度为 0 的结点
层次根在第 1 层，根的孩子在第 2 层，依次类推
高度（深度）树中结点的最大层数
宽度结点最多的那一层的结点个数

二叉树是每个结点最多有两个孩子、并且孩子分左右的树。"只有左孩子"和"只有右孩子"是两棵不同的二叉树。

这棵树有 6 个结点、3 层，所以高度是 3；A 的度是 2，C 的度是 1；D、E、F 是叶子；第 3 层有 3 个结点，宽度是 3。

五条性质

我们用 n0、n1、n2 分别表示度为 0、1、2 的结点个数，n 表示总结点数。

性质 1：n0 = n2 + 1。 从两个角度数边：除根以外每个结点向上连一条边，所以边数是 n − 1；从父亲往下数，度为 1 的结点贡献 1 条边，度为 2 的贡献 2 条，所以边数也等于 n1 + 2·n2。两式相等，再代入 n = n0 + n1 + n2：

n0 + n1 + n2 − 1 = n1 + 2·n2，化简得 n0 = n2 + 1。

这条推导只用到"每个结点最多两个孩子"，所以对任何非空二叉树成立。上图 n2=2（A、B），n0=3（D、E、F），确实 3 = 2 + 1。

性质 2：第 i 层最多有 2^(i−1) 个结点。 每往下一层，结点数最多翻一倍：第 1 层 1 个，第 2 层 2 个，第 3 层 4 个。

性质 3：高度为 h 的二叉树最多有 2^h − 1 个结点。 把每层的最大值加起来：1 + 2 + 4 + … + 2^(h−1) = 2^h − 1。正好达到这个数的叫满二叉树，例如高度 5 的满二叉树有 31 个结点。

性质 4：n 个结点的完全二叉树，高度为 ⌊log₂n⌋ + 1（也等于 ⌈log₂(n+1)⌉）。** 完全二叉树**是指：除最后一层外每层都填满，最后一层的结点从左往右连续排列。高度为 h 的完全二叉树，结点数介于"前 h−1 层满再加 1 个"和"h 层全满"之间：2^(h−1) ≤ n ≤ 2^h − 1。对 n 取对数就得到上式。例如 n=10：2³=8 ≤ 10 < 16=2⁴，高度 4；n=1000：2⁹=512 ≤ 1000 < 1024，高度 10。

一般的二叉树没有形状限制，n 个结点最高可以是 n 层（退化成一条链），最矮就是完全二叉树的 ⌊log₂n⌋ + 1 层。

性质 5：给完全二叉树按层从 1 开始编号，结点 i 的左孩子是 2i、右孩子是 2i+1、父结点是 ⌊i/2⌋。 如果 2i > n，结点 i 就没有左孩子，是叶子。这条性质让完全二叉树可以不用指针、直接存进数组，堆就是这样存的（15.9）。

n=10 的完全二叉树按层编号：结点 i 的孩子是 2i、2i+1；绿色 6～10 是叶子，高亮的 5 是唯一的度 1 结点

完全二叉树的叶子数和度为 1 的结点数

完全二叉树的形状由 n 唯一决定，所以 n0、n1、n2 也由 n 唯一决定。我们有两种推法。

推法一（用编号）。 最后一个结点编号是 n，它的父亲是 ⌊n/2⌋。编号大于 ⌊n/2⌋ 的结点都没有孩子，所以叶子数 n0 = n − ⌊n/2⌋ = ⌈n/2⌉。

推法二（用性质 1）。 完全二叉树里度为 1 的结点最多 1 个（只可能是最后一个结点的父亲，而且它只有左孩子）。把 n0 = n2 + 1 代入 n = n0 + n1 + n2，得 n = 2·n0 − 1 + n1：

  • n 为偶数时，n1 必须是 1，n0 = n/2；
  • n 为奇数时，n1 = 0，n0 = (n+1)/2。

上图 n=10 是偶数：n0=5（编号 6～10），n1=1（编号 5，只有左孩子 10），n2=4。核对：5 = 4 + 1。

再算一个：n=1000 的完全二叉树，叶子 500 个、度为 1 的结点 1 个、度为 2 的结点 499 个。

一般的树（不限两个孩子）也能这样数边。 结点数 = 边数 + 1 = Σ(度 × 该度的结点数) + 1。例如一棵树有 2 个度为 3 的结点、1 个度为 2 的结点，其余都是叶子，那么 n = 2×3 + 1×2 + 1 = 9，叶子数 = 9 − 3 = 6。

单选 · 理解检查 1　一棵完全二叉树有 25 个结点。它的高度、叶子数、度为 1 的结点数分别是？

A. 高度 5，叶子 13，度为 1 的结点 0 个

B. 高度 5，叶子 12，度为 1 的结点 1 个

C. 高度 4，叶子 13，度为 1 的结点 0 个

D. 高度 6，叶子 13，度为 1 的结点 0 个

查看答案与每个选项的解析

A · 正确：2⁴=16 ≤ 25 < 32，高度 ⌊log₂25⌋+1=5；n 为奇数，n1=0，n0=(25+1)/2=13。

B · 错误：n 为奇数时 n=2·n0−1+n1 要求 n1=0；n1=1 只在 n 为偶数时出现。

C · 错误：高度 4 的二叉树最多 2⁴−1=15 个结点，装不下 25 个。

D · 错误：完全二叉树前面的层都是满的，25 个结点只到第 5 层。

单选 · 理解检查 2　一棵完全二叉树的第 5 层有 6 个叶子结点（根为第 1 层）。这棵树最多有多少个结点？

A. 51

B. 21

C. 37

D. 63

查看答案与每个选项的解析

A · 正确：要结点最多，第 5 层应排满 16 个，其中 6 个是叶子，另外 10 个各有 2 个孩子（第 6 层 20 个）。总数 31 + 20 = 51。

B · 错误：这是结点最少的情况：第 5 层就是最后一层、只有 6 个结点，15 + 6 = 21。

C · 错误：31 + 6 = 37 把 6 个叶子当成了第 6 层的结点，题目说的是第 5 层有 6 个叶子。

D · 错误：高度 6 的满二叉树第 5 层没有叶子，与题设矛盾。

易错点：

  • 高度的两种口径。按边数计时，只有根的树高度是 0，高度 h 的满二叉树有 2^(h+1) − 1 个结点；按层数计（本书和 408）时是 2^h − 1。两者只差 1：层数 = 边数 + 1。看到英文教材、LeetCode 的"深度"题时，先看题目怎样定义。
  • "满二叉树"在英文里有两种意思：perfect（每层都满，等于中文的满二叉树）和 full（每个非叶结点都恰有两个孩子，各层未必满）。中文题按每层都满理解。
  • n0 = n2 + 1 对所有二叉树成立；"叶子数 = ⌈n/2⌉"只对完全二叉树成立。

小结： 二叉树中 n0=n2+1；第 i 层最多有 2^(i−1) 个结点，高为 h 的树最多有 2^h−1 个结点；n 个结点的完全二叉树高为 ⌊log₂n⌋+1，叶子有 ⌈n/2⌉ 个，n 为偶数时 n1=1；从 1 开始编号时，结点 i 的孩子是 2i 和 2i+1，父结点是 ⌊i/2⌋。

15.2 树的存储，以及树、森林与二叉树的转换 选读

一个结点可能有 0 个、3 个甚至 100 个孩子，结构体里该放几个孩子指针？放多了浪费，放少了不够。这一节的三种表示法给出不同答案，其中"孩子兄弟表示法"能把任意树变成二叉树，于是二叉树的算法都能直接拿来用。

我们用这棵树做例子：A 有孩子 B、C、D；B 有孩子 E、F；D 有孩子 G。

双亲表示法

用一个数组按顺序存所有结点，每个结点额外记一个 parent 字段，存父结点的下标，根存 −1。

双亲表示法：parent 存父结点下标，根存 −1。找 E 的父亲：parent[4]=1，即 B

找父亲是 O(1)，直接读 parent；找孩子要扫描整个数组，看谁的 parent 等于自己。并查集就是双亲表示法的直接应用：每个集合是一棵树，"两个元素是否同属一个集合"变成"沿 parent 往上找，根是否相同"。并查集的路径压缩和按秩合并留到第 10 章细讲。

孩子表示法

每个结点挂一条链表，链表里是它所有孩子的下标。找孩子方便，找父亲要遍历所有链表。图的邻接表就是这个思路（第 16 章）。

孩子兄弟表示法（二叉链表）

每个结点固定两个指针：

  • 左指针指向它的第一个孩子；
  • 右指针指向它的下一个兄弟（同一父亲、紧挨在右边的那个）。
struct CSNode {
    char data;
    CSNode* firstChild;    // 第一个孩子
    CSNode* nextSibling;   // 右边的兄弟
};
class CSNode:
    def __init__(self, data):
        self.data = data
        self.first_child = None    # 第一个孩子（Python 没有指针：存对象引用，空就是 None）
        self.next_sibling = None   # 右边的兄弟

结构体和二叉树结点完全一样，只是两个指针的含义变了。所以任何一棵树都能唯一对应一棵二叉树，下面我们把转换过程画出来。

走一遍：A 的第一个孩子是 B，所以 B 是 A 的左孩子；B 的右兄弟是 C，C 是 B 的右孩子；C 的右兄弟是 D，D 是 C 的右孩子。B 的第一个孩子 E 是 B 的左孩子，E 的兄弟 F 是 E 的右孩子。D 的第一个孩子 G 是 D 的左孩子。

转换后的二叉树有一个特点：根 A 没有右孩子，因为一棵树的根没有兄弟。

森林转二叉树

森林是若干棵互不相交的树。把每棵树先转成二叉树，再把各棵树的根看成"兄弟"：第二棵树的根挂到第一棵树根的右指针上，第三棵挂到第二棵根的右指针上，依此类推。

左：三棵树组成的森林；右：转换后的二叉树。各棵树的根 A、D、F 被当作兄弟，沿右链串起来（橙色是右指针）

反过来，二叉树转森林：从根出发沿右指针一路走，经过的每个结点都是一棵树的根；把每个根的右指针断开，再把每棵子二叉树按"左孩子 = 第一个孩子，右孩子 = 兄弟"还原。

多选 · 理解检查 3　把树 A（B（E,F）, C, D（G））按孩子兄弟表示法转成二叉树。下列说法哪些正确？

A. C 是 B 的右孩子

B. F 是 B 的右孩子

C. 二叉树的根 A 没有右孩子

D. 二叉树的中序序列是 E F B C G D A

查看答案与每个选项的解析

A · 正确：C 是 B 右边紧挨的兄弟，兄弟挂在右指针上。

B · 错误：F 是 E 的兄弟，所以 F 是 E 的右孩子；B 的右孩子是 C。

C · 正确：一棵树的根没有兄弟，右指针为空。

D · 正确：二叉树中序对应树的后根遍历：E F B C G D A。

易错点：

  • 树的后根遍历对应二叉树的中序，而不是后序；这是笔试最常设的陷阱。
  • 森林转成的二叉树，根可以有右孩子（第二棵树的根）；单棵树转成的二叉树，根的右指针一定为空。
  • "树的度为 m"与"m 叉树"含义不同：前者要求至少有一个结点有 m 个孩子，后者只要求每个结点最多 m 个孩子，可以一个结点都没有达到 m。

小结： 双亲表示法找父结点快，孩子表示法找孩子快；孩子兄弟表示法让左指针指向第一个孩子、右指针指向下一个兄弟，从而把树变成二叉树；树的先根遍历对应二叉树的前序遍历，后根遍历对应中序遍历。

15.3 二叉树的四种遍历 必读

二叉树没有天然的"从头到尾"顺序，遍历就是规定一个顺序，让每个结点恰好被访问一次。前序、中序、后序这三个名字里的"前中后"说的是根在什么时候被访问，左子树总在右子树之前。

递归写法

三种深度优先遍历的递归代码只差"访问根"那一行的位置。

void preorder(TreeNode* root, vector<int>& out) {
    if (root == nullptr) return;

}

void postorder(TreeNode* root, vector<int>& out) {

    postorder(root->right, out);
    out.push_back(root->val);
}
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left           # 对象引用，相当于 C++ 的 TreeNode*；空孩子是 None
        self.right = right

# out 是列表，函数里 append 会改到调用者那一份（相当于 C++ 的 vector<int>&）。
# 递归深度等于树高；Python 默认上限约 1000 层，链状大树要 sys.setrecursionlimit 或改用栈写法。
def preorder(root, out):
    if root is None: return
    out.append(root.val)           # 根
    preorder(root.left, out)       # 左
    preorder(root.right, out)      # 右

def inorder(root, out):
    if root is None: return
    inorder(root.left, out)
    out.append(root.val)
    inorder(root.right, out)

def postorder(root, out):
    if root is None: return
    postorder(root.left, out)
    postorder(root.right, out)
    out.append(root.val)

每个结点进入一次函数，时间 O(n)；递归栈的深度等于树高 h，所以辅助空间 O(h)，最坏（链状）O(n)。

非递归写法：用栈模拟

前序：栈里先放根。每次弹出一个结点就访问它，然后先压右孩子、再压左孩子。栈是后进先出，后压的左孩子会先弹出，于是保证"左子树先于右子树"。

vector<int> preorderIter(TreeNode* root) {
    vector<int> out;
    if (root == nullptr) return out;
    stack<TreeNode*> st;
    st.push(root);
    while (!st.empty()) {
        TreeNode* node = st.top(); st.pop();
        out.push_back(node->val);
        if (node->right) st.push(node->right);   // 先压右
        if (node->left) st.push(node->left);     // 后压左，左先出栈
    }
    return out;
}
def preorder_iter(root):
    out = []
    if root is None: return out
    st = []                                    # 列表当栈：append 压栈，pop() 弹出栈顶
    st.append(root)
    while st:
        node = st.pop()                        # C++ 要 top() 再 pop()，Python 的 pop() 一步取出
        out.append(node.val)
        if node.right: st.append(node.right)   # 先压右
        if node.left: st.append(node.left)     # 后压左，左先出栈
    return out

中序：变量 cur 表示"接下来要处理的子树的根"，栈里存"左子树还没处理完、自己还没访问"的祖先。先沿左链一路压栈，左边走到头就弹出一个访问，再转向它的右子树。

vector<int> inorderIter(TreeNode* root) {
    vector<int> out;
    stack<TreeNode*> st;
    TreeNode* cur = root;
    while (cur != nullptr || !st.empty()) {
        while (cur != nullptr) {          // 沿左链一路入栈
            st.push(cur);
            cur = cur->left;
        }
        cur = st.top(); st.pop();         // 左边走到头，弹出并访问
        out.push_back(cur->val);
        cur = cur->right;                 // 转向右子树
    }
    return out;
}
def inorder_iter(root):

层序遍历：用队列

先把根放进队列；每次从队头取出一个结点访问，再把它的左、右孩子依次放到队尾。先放进去的结点先被处理，所以一层处理完才轮到下一层。Python 里用 collections.deque 的 popleft()，它是 O(1)；list.pop(0) 要把后面所有元素前移，是 O(n)。[6]

vector<int> levelOrder(TreeNode* root) {
    vector<int> out;
    if (root == nullptr) return out;
    queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        TreeNode* node = q.front(); q.pop();
        out.push_back(node->val);
        if (node->left) q.push(node->left);
        if (node->right) q.push(node->right);
    }
    return out;
}
from collections import deque

def level_order(root):
    out = []
    if root is None: return out
    q = deque()                       # popleft() 是 O(1)；list.pop(0) 是 O(n)
    q.append(root)
    while q:
        node = q.popleft()
        out.append(node.val)
        if node.left: q.append(node.left)
        if node.right: q.append(node.right)
    return out

应用：翻转二叉树

把每个结点的左右孩子交换，就得到镜像。在前序位置交换（先交换再递归）或后序位置交换（先递归再交换）都对；层序遍历时每出队一个结点就交换它的两个孩子，也对。

TreeNode* invertTree(TreeNode* root) {
    if (root == nullptr) return nullptr;
    swap(root->left, root->right);
    invertTree(root->left);
    invertTree(root->right);
    return root;
}
def invert_tree(root):
    if root is None: return None
    root.left, root.right = root.right, root.left   # 元组赋值完成交换，相当于 swap
    invert_tree(root.left)
    invert_tree(root.right)
    return root

翻转上图后，层序变成 A C B F E D，中序变成 F C A E B D，正好是原中序倒过来。

易错点：

  • 前序非递归要先压右再压左；顺序写反，输出就变成"根右左"。
  • 翻转二叉树时，如果在中序位置交换（先递归左、再交换、再递归 root->right），交换后的 root->right 其实是原来已经翻转过的左子树，它会被翻回去。翻转用前序或后序位置。

小结： 前序、中序、后序的区别在于访问根的时机；递归遍历用 O(n) 时间和 O(h) 的栈空间；迭代写法中，前序先压右孩子，中序沿左链压栈，层序使用队列。

15.4 由遍历序列确定二叉树 必读

笔试常给出两个遍历序列让你画出二叉树，或者问"能否唯一确定"。关键是：前序或后序告诉你谁是根，中序告诉你左右子树各有哪些结点。

前序 + 中序：完整走一遍

2 / 4

4 / 4

第4步 · 右子树前序 CF、中序 CF：C 是根，中序里 C 左边没有结点，F 在右边，所以 F 是 C 的右孩子。重建完成。

验证：这棵树的后序是 D G E B F C A，层序是 A B C D E F G。

规律： 每一步都按中序里数出的结点个数去切前序。左子树有 k 个结点，前序里根后面紧跟的 k 个就是左子树的前序。

后序 + 中序

后序的最后一个是根，其余步骤相同。例如后序 D G E B F C A、中序 D B G E A C F：A 是根，中序切出左 4 个、右 2 个；后序前 4 个 D G E B 是左子树（最后一个 B 是左子树的根），接着 F C 是右子树。得到的正是上面那棵树。

前序 + 后序：一般不能唯一确定

前序是"根 左 右"，后序是"左 右 根"，两者都只告诉你谁是根，分不出剩下的结点在左边还是右边。最小反例：

两棵不同的树，前序和后序完全相同；只有中序能分出 B 在左还是在右

只有当每个结点要么没有孩子、要么有两个孩子时，前序 + 后序才能唯一确定。层序 + 中序也能唯一确定，因为层序的第一个就是根。

代码：由前序和中序重建

变量表：pre[pl..pr] 是当前子树的前序区间；il 是当前子树在中序里的起点；pos[x] 是值 x 在中序中的下标（用哈希表预存，省掉每次线性查找）；k 是根在中序中的位置；leftSize = k − il 是左子树的结点数。

TreeNode* buildPI(const vector<int>& pre, int pl, int pr, int il, unordered_map<int, int>& pos) {
    if (pl > pr) return nullptr;
    TreeNode* root = new TreeNode(pre[pl]);      // 前序第一个是根
    int k = pos[pre[pl]];                         // 根在中序中的位置
    int leftSize = k - il;                        // 左子树结点数
    root->left = buildPI(pre, pl + 1, pl + leftSize, il, pos);
    root->right = buildPI(pre, pl + leftSize + 1, pr, k + 1, pos);
    return root;
}

TreeNode* buildPreIn(const vector<int>& pre, const vector<int>& in) {
    unordered_map<int, int> pos;
    for (int i = 0; i < (int)in.size(); ++i) pos[in[i]] = i;
    return buildPI(pre, 0, (int)pre.size() - 1, 0, pos);
}
def build_pi(pre, pl, pr, il, pos):
    if pl > pr: return None
    root = TreeNode(pre[pl])                   # 前序第一个是根
    k = pos[pre[pl]]                           # 根在中序中的位置
    left_size = k - il                         # 左子树结点数
    root.left = build_pi(pre, pl + 1, pl + left_size, il, pos)
    root.right = build_pi(pre, pl + left_size + 1, pr, k + 1, pos)
    return root

def build_pre_in(pre, ino):                    # in 是 Python 关键字，中序序列改名 ino
    pos = {}                                   # dict 相当于 unordered_map
    for i in range(len(ino)): pos[ino[i]] = i
    return build_pi(pre, 0, len(pre) - 1, 0, pos)

手工模拟上面的例子：第一层 pre[0]='A'，k=4，leftSize=4，左子树的前序区间是 [1,4]，即 B D E G；右子树的前序区间是 [5,6]，即 C F，中序起点是 5。每个结点只创建一次，总时间为 O(n)。由后序和中序重建的写法与此相同，区别只是根取 post[pr]。

单选 · 理解检查 4　已知某二叉树的后序序列为 D B F G E C A，中序序列为 B D A F E G C。它的前序序列是？

A. A B D C E F G

B. A B D E F G C

查看答案与每个选项的解析

A · 正确：后序末尾 A 是根；中序 A 左边 B D、右边 F E G C。左子树后序 D B，根 B，D 在 B 右边；右子树后序 F G E C，根 C，中序 F E G 都在 C 左边；再往下 E 是根，F 左 G 右。前序为 A B D C E F G。

B · 错误：这把 E 当成了 A 的右孩子。右子树的后序 F G E C 最后一个是 C，所以右子树的根是 C。

C · 错误：左子树后序 D B 的最后一个 B 才是根，D 是 B 的孩子。

D · 错误：后序 + 中序（键互不相同）可以唯一确定二叉树。

易错点：

  • 切分前序（或后序）时要按中序数出的个数切，凭图形猜很容易切错。
  • 前序 + 后序一般不能确定二叉树；但如果题目说"每个结点度为 0 或 2"，就可以。
  • 序列里有重复值时，中序里根的位置会有歧义，重建算法要求值互不相同。

小结： 前序的第一个、后序的最后一个是根，中序中根把左右子树分开，再按左子树的结点数切分另一个序列；前序加中序、后序加中序、层序加中序都能唯一确定二叉树，前序加后序一般不能。

15.5 线索二叉树：利用空指针找前驱和后继 了解

了解即可：线索二叉树，主要是 408 考点。点击展开

n 个结点的二叉链表有 2n 个指针，其中只有 n−1 个指向孩子（每个非根结点被指一次），剩下 n+1 个是空指针。中序遍历时，我们经常想知道"某个结点的下一个是谁"，每次都从头遍历太浪费。线索二叉树把这 n+1 个空指针利用起来，直接记录前驱和后继。

结构

每个结点加两个标志位：

字段值为 0值为 1
ltaglchild 指向左孩子lchild 指向中序前驱（线索）
rtagrchild 指向右孩子rchild 指向中序后继（线索）

规则：左指针为空就让它指向前驱，右指针为空就让它指向后继。中序第一个结点的前驱和最后一个结点的后继都是 NULL。

中序线索二叉树（中序 D B E A C F）。实线是孩子指针；橙色虚线是左线索（指向中序前驱），绿色虚线是右线索（指向中序后继）

走一遍：中序是 D B E A C F。D 是第一个，左线索为 NULL，右线索指向后继 B；E 两边都空，左线索指前驱 B，右线索指后继 A；C 左边空，左线索指前驱 A；F 左线索指前驱 C，右线索为 NULL。数一下线索：D 两条、E 两条、C 一条、F 两条，共 7 条，正好是 n+1 = 7。

找中序后继和前驱

找 p 的后继：

  • 如果 rtag = 1，右指针就是后继；
  • 如果 rtag = 0（有右孩子），后继是右子树中最左下的结点：从右孩子出发，一直沿左指针走到 ltag = 1 为止。

找 p 的前驱（左右对称）：

  • 如果 ltag = 1，左指针就是前驱；
  • 否则前驱是左子树中最右下的结点。

例如 A 有右孩子 C，C 的 ltag=1，所以 A 的后继是 C；A 有左孩子 B，B 子树的最右下是 E，所以 A 的前驱是 E。

代码：中序线索化与遍历

变量表：pre 始终指向"刚刚访问过的结点"，也就是当前结点 p 的中序前驱；ltag/rtag 为 1 表示该指针是线索。

void inThread(ThreadNode* p, ThreadNode*& pre) {
    if (p == nullptr) return;
    inThread(p->lchild, pre);
    if (p->lchild == nullptr) { p->lchild = pre; p->ltag = 1; }              // 左空：指向前驱
    if (pre != nullptr && pre->rchild == nullptr) { pre->rchild = p; pre->rtag = 1; }  // 前驱右空：指向我
    pre = p;
    inThread(p->rchild, pre);
}

ThreadNode* firstNode(ThreadNode* p) {           // 子树中序第一个：最左下
    while (p->ltag == 0) p = p->lchild;
    return p;
}

ThreadNode* nextNode(ThreadNode* p) {            // 中序后继
    if (p->rtag == 1) return p->rchild;          // 右指针就是线索
    return firstNode(p->rchild);                 // 否则是右子树的最左下
}
class ThreadNode:
    def __init__(self, data):
        self.data = data
        self.lchild = None
        self.rchild = None
        self.ltag = 0                 # 0：指向孩子；1：线索
        self.rtag = 0

# C++ 用引用参数 ThreadNode*& pre 把"刚访问过的结点"带出来；
# Python 没有引用参数，这里改成返回更新后的 pre，调用处用返回值接住。
def in_thread(p, pre):
    if p is None: return pre
    pre = in_thread(p.lchild, pre)
    if p.lchild is None:                              # 左空：指向前驱
        p.lchild = pre; p.ltag = 1
    if pre is not None and pre.rchild is None:        # 前驱右空：指向我
        pre.rchild = p; pre.rtag = 1
    pre = p
    return in_thread(p.rchild, pre)

def first_node(p):                    # 子树中序第一个：最左下
    while p.ltag == 0: p = p.lchild
    return p

def next_node(p):                     # 中序后继
    if p.rtag == 1: return p.rchild   # 右指针就是线索
    return first_node(p.rchild)       # 否则是右子树的最左下

线索化就是一次中序遍历，在"访问"的位置把当前结点和前驱互相连上。遍历时从 firstNode(root) 出发反复调用 nextNode，不需要栈，额外空间 O(1)。

前序线索树、后序线索树的做法相同，只是"前驱、后继"换成对应遍历的顺序。后序线索树找后继最麻烦，往往还需要知道父结点。

易错点：

  • 遍历线索树时，遇到 tag=1 的指针要当作"跳转"，而不是孩子；把线索当孩子递归会绕回祖先，形成死循环。
  • 线索二叉树的空指针个数是 n+1，线索个数也最多 n+1（首尾两个可能是 NULL，但仍记 tag=1）。

小结： n 个结点的二叉链表有 n+1 个空指针，可以改作线索；ltag 或 rtag 为 1 表示对应指针是线索；找中序后继时，有右线索就直接沿它走，否则取右子树的最左下结点；找前驱时，有左线索就直接走，否则取左子树的最右下结点。

15.6 二叉搜索树（BST）：查找、插入、删除和平均查找长度 必读

有序数组能二分查找，但插入一个数要把后面的元素全部后移。二叉搜索树（BST，也叫二叉排序树）把"有序"放进树的结构里：插入只需改一个空指针。

定义： 对每个结点，左子树中所有键都小于它，右子树中所有键都大于它，并且左右子树也都是 BST。约束的是整棵子树，而不只是直接孩子。由此得到最重要的性质：BST 的中序遍历是递增序列。

查找和插入

查找 35：35 < 50 向左，35 > 30 向右，35 < 40 向左，命中，共比较 4 次。查找 45：45 < 50 向左，45 > 30 向右，45 > 40 向右，40 的右孩子为空，查找失败，共比较 3 次。如果要插入 45，就把这个空位置换成新结点 45。

TreeNode* bstSearch(TreeNode* root, int key) {
    TreeNode* cur = root;
    while (cur != nullptr && cur->val != key) {
        cur = (key < cur->val) ? cur->left : cur->right;
    }
    return cur;                                  // 找到返回结点，找不到返回 nullptr
}

TreeNode* bstInsert(TreeNode* root, int key) {
    if (root == nullptr) return new TreeNode(key);   // 空位置就是新结点的家
    if (key < root->val) root->left = bstInsert(root->left, key);
    else if (key > root->val) root->right = bstInsert(root->right, key);
    return root;                                      // 键已存在：不重复插入
}
def bst_search(root, key):
    cur = root
    while cur is not None and cur.val != key:
        cur = cur.left if key < cur.val else cur.right
    return cur                                   # 找到返回结点，找不到返回 None

def bst_insert(root, key):
    if root is None: return TreeNode(key)        # 空位置就是新结点的家
    if key < root.val: root.left = bst_insert(root.left, key)
    elif key > root.val: root.right = bst_insert(root.right, key)
    return root                                  # 键已存在：不重复插入；调用者要用返回值接回根

删除的三种情况

  1. 叶子：直接删掉。
  2. 只有一个孩子：让父结点直接连到这个孩子上（孩子"顶替"它）。
  3. 有两个孩子：用中序后继（右子树最小值）或中序前驱（左子树最大值）的值替换它，再去删除那个后继或前驱。后继最多只有一个右孩子，所以问题变成了情况 1 或 2。

平均查找长度 ASL

ASL（Average Search Length）是查找时平均要比较多少次。在 BST 里，查找一个位于第 L 层的结点要比较 L 次。

查找成功的 ASL：把每个结点的层数加起来，除以结点数（假设每个键被查的概率相等）。

上图：第 1 层 1 个、第 2 层 2 个、第 3 层 4 个、第 4 层 1 个，

ASL成功 = (1×1 + 2×2 + 3×4 + 4×1) / 8 = 21/8 ≈ 2.63。

查找失败的 ASL：把每个空指针看成一个"失败位置"。n 个结点有 n+1 = 9 个失败位置。落到某个失败位置之前，比较的次数等于它父结点的层数。20、60、80 各有 2 个空指针（第 3 层），40 有 1 个（第 3 层），35 有 2 个（第 4 层）：

ASL失败 = (3×7 + 4×2) / 9 = 29/9 ≈ 3.22。

同样的 8 个键，按递增顺序插入会得到一条向右的链，高度 8：ASL成功 = (1+2+…+8)/8 = 36/8 = 4.5。树的形状决定效率：平衡时查找约 O(log n)，退化成链时 O(n)。这正是下一节 AVL 树要解决的问题。

易错点：

  • 验证 BST 时只比较父子是不够的。例如根 8、左孩子 4、4 的右孩子 9：4<9 局部没问题，但 9 落在 8 的左子树里，违反定义。正确做法是检查中序是否递增，或者给每个结点传上下界。

小结： BST 要求整个左子树都比根小、整个右子树都比根大，所以中序遍历递增；删除有两个孩子的结点时，用它的中序后继或前驱代替；成功查找的平均长度是各结点层数之和除以 n，失败查找的平均长度是各空位置的父结点层数之和除以 n+1；各种操作的时间都是 O(h)。

15.7 AVL 树：平衡因子、四种旋转与最少结点数 选读

BST 的效率取决于高度。AVL 树在 BST 的基础上加一条约束：每个结点左右子树的高度差的绝对值不超过 1，从而把高度压在 O(log n)。

平衡因子 BF = 左子树高度 − 右子树高度，合法取值只有 −1、0、1。插入新结点后，从它往上回溯更新高度，找到第一个 |BF| = 2 的祖先，称为最小不平衡子树的根，只需调整这棵子树。

上面的例子里子树都是空的，看不出旋转真正做了什么。一般情况下，对 x 右旋时，y = x 的左孩子，B = y 的右子树：

右旋的一般形式：A、B、C 是整棵子树。B 原来是 y 的右子树，旋转后改挂为 x 的左子树。两边中序都是 A y B x C

右旋做三件事：x 的左指针改指 B；y 的右指针改指 x；原来指向 x 的父指针改指 y。B 里的键都满足 y < B < x，挂到 x 的左边仍然有序。

AVLNode* rotateRight(AVLNode* x) {   // LL：x 的左孩子 y 上来
    AVLNode* y = x->left;
    AVLNode* B = y->right;            // 中间子树
    y->right = x;
    x->left = B;                      // B 转接到 x 的左边
    update(x);                        // 先更新下面的 x
    update(y);
    return y;                         // y 成为这棵子树的新根
}
def rotate_right(x):     # LL：x 的左孩子 y 上来
    y = x.left
    B = y.right          # 中间子树
    y.right = x          # 改的是对象属性，作用和 C++ 改指针相同
    x.left = B           # B 转接到 x 的左边
    update(x)            # 先更新下面的 x
    update(y)
    return y             # y 成为这棵子树的新根，父结点要用返回值重新接上

update 按照 1 加上左右子树高度中的较大者重新计算高度（叶子的高度为 1）。必须先更新 x 再更新 y，因为旋转后 x 位于 y 的下方。左旋与右旋互为镜像，LR 和 RL 型就是两次单旋的组合。

最少结点数：1, 2, 4, 7, 12, 20, 33, 54

设 N(h) 是高度为 h 的 AVL 树最少有多少个结点。要结点最少，就让根的一棵子树高 h−1、另一棵高 h−2（高度差恰好为 1），两棵子树也各自取最少：

N(h) = N(h−1) + N(h−2) + 1，N(0) = 0，N(1) = 1。

逐项算：N(2) = 1+0+1 = 2，N(3) = 2+1+1 = 4，N(4) = 4+2+1 = 7，N(5) = 7+4+1 = 12，N(6) = 20，N(7) = 33，N(8) = 54。它与斐波那契数的关系是 N(h) = F(h+2) − 1。

两条曲线都随高度指数增长，所以 AVL 的高度是 O(log n)

反过来用： 给定 n 个结点，AVL 树的最大高度是满足 N(h) ≤ n 的最大 h。例如 n = 20：N(6)=20 ≤ 20 < N(7)=33，最大高度 6；n = 15：N(5)=12 ≤ 15 < 20，最大高度 5。最小高度和普通二叉树一样是 ⌊log₂n⌋ + 1。

N(h) 像斐波那契数一样按约 1.618 倍增长，所以高度最多约 1.44·log₂n，查找、插入、删除最坏都是 O(log n)。插入时修复最小不平衡子树只需 1 次单旋或 1 次双旋，修完后这棵子树高度恢复原样，上面的祖先不会再失衡；删除可能让高度降低，需要一路向上检查，最多旋转 O(log n) 次。

15.8 红黑树：用颜色换取"大致平衡" 了解

了解即可：红黑树只需知道性质和用途。点击展开

AVL 树对高度差要求严格，插入删除时旋转比较频繁。红黑树放宽条件：只保证最长路径不超过最短路径的 2 倍，调整代价更小，C++ 的 map/set、Java 的 TreeMap、Linux 内核的进程调度都用它。

五条性质：

  1. 每个结点是红色或黑色；
  2. 根是黑色；
  3. 所有叶子（NIL 空结点）是黑色；
  4. 红结点的两个孩子都是黑色（不能有两个相连的红结点）；
  5. 从任一结点到它所有后代 NIL 的路径上，黑结点个数相同（称为黑高）。

图中从 10 经过 5 到 NIL、从 10 经过 15 到 NIL 的两条路径上各有 2 个黑结点（10 和 NIL），黑高一致，也没有两个红结点相连。NIL 只是为了说明规则而画出的空位置，不计入结点数 n。红结点的孩子可以是 NIL；颜色规则也不要求一层红一层黑。

插入：新结点先染红

在某个 NIL 位置插入新结点并染成红色：这样不改变任何路径上的黑结点数，性质 5 自动保持，最多破坏性质 4（父亲也是红色）。如果父亲是黑色，插入就结束了；父亲是红色时，看叔叔（父亲的兄弟）的颜色：

  • 叔叔红：把父亲和叔叔染黑、祖父染红，然后把祖父当作新插入的结点继续向上检查；到根时把根染黑。
  • 叔叔黑：按 LL/RR/LR/RL 形状做一次或两次旋转，再把新的局部根染黑、它的两个孩子染红。

叔叔为红：只变色，不旋转

1 / 2

第1步 · 插入 1（红）到 5（红）下面，出现红红相连。父亲 5 红，叔叔 15 也红。

2 / 2

第2步 · 5 和 15 染黑，祖父 10 染红；10 是根，再染回黑。各路径黑高都是 2（加上 NIL），没有红红相连。

如果依次插入 10, 5, 1，插入 1 时叔叔是黑色 NIL，形状是 LL：对 10 右旋，5 成为局部根并染黑，1 和 10 染红，得到 5 黑（1 红, 10 红）。

删除黑结点会让某些路径少一个黑结点，需要根据兄弟和侄子的颜色做借黑、旋转或向上传递，分情况较多。笔试和面试一般只要求说出思路，并能检查一棵树是否满足五条性质。

为什么高度是 O(log n)

由性质 4，任何路径上红结点不会比黑结点多；由性质 5，从根出发的各路径黑结点数相同。所以最长路径（红黑交替）不超过最短路径（全黑）的 2 倍。可以证明 n 个内部结点的红黑树，按层数计高度不超过 2·log₂(n+1)，查找、插入、删除最坏 O(log n)。

15.9 堆：用数组存的完全二叉树 必读

银行排队时 VIP 客户优先、操作系统里高优先级任务先跑，这类"反复取出当前最重要的那个"的需求叫优先队列。每次都排序太慢，用 BST 又要维护整棵树的全序；堆只维护"父子之间的大小关系"，取最值 O(1)，插入删除 O(log n)。

定义： 堆是一棵完全二叉树，并且每个结点都满足：

  • 大根堆：父结点 ≥ 孩子结点，堆顶是最大值；
  • 小根堆：父结点 ≤ 孩子结点，堆顶是最小值。

兄弟之间没有大小要求。因为是完全二叉树，堆直接按层存进数组，不需要指针。

变量表：a 是存堆的数组；n 是当前堆的大小（只看 a[0..n-1]）；i 是正在移动的元素的位置；p 是父结点下标；j 是较大孩子的下标。

void siftUp(vector<int>& a, int i) {
    while (i > 0) {
        int p = (i - 1) / 2;                 // 0 起下标的父结点
        if (a[p] >= a[i]) break;             // 父不小于子：已满足大根堆
        swap(a[p], a[i]);
        i = p;
    }
}

void siftDown(vector<int>& a, int i, int n) {    // 只看 a[0..n-1]
    while (2 * i + 1 < n) {
        int j = 2 * i + 1;                         // 左孩子
        if (j + 1 < n && a[j + 1] > a[j]) ++j;     // 选较大的孩子
        if (a[i] >= a[j]) break;
        swap(a[i], a[j]);
        i = j;
    }
}

void heapPush(vector<int>& a, int x) {
    a.push_back(x);                      // 先放末尾，保持完全二叉树形状
    siftUp(a, (int)a.size() - 1);
}

int heapPop(vector<int>& a) {
    int top = a[0];
    a[0] = a.back();                     // 末尾元素补到根
    a.pop_back();
    if (!a.empty()) siftDown(a, 0, (int)a.size());
    return top;
}
# 0 起下标的大根堆，下标规则与 C++ 版相同，便于对照图里的数组。
# 另一种现成写法是标准库 heapq（heappush / heappop / heapify），但它只有小根堆，
# 要大根堆通常把数取负再存进去。
def sift_up(a, i):
    while i > 0:
        p = (i - 1) // 2                  # 0 起下标的父结点；i > 0 时 // 与 C++ 的 / 结果相同
        if a[p] >= a[i]: break            # 父不小于子：已满足大根堆
        a[p], a[i] = a[i], a[p]
        i = p

def sift_down(a, i, n):                   # 只看 a[0..n-1]
    while 2 * i + 1 < n:
        j = 2 * i + 1                     # 左孩子
        if j + 1 < n and a[j + 1] > a[j]: j += 1   # 选较大的孩子
        if a[i] >= a[j]: break
        a[i], a[j] = a[j], a[i]
        i = j

def heap_push(a, x):
    a.append(x)                           # 先放末尾，保持完全二叉树形状
    sift_up(a, len(a) - 1)

def heap_pop(a):
    top = a[0]
    a[0] = a[-1]                          # 末尾元素补到根
    a.pop()
    if a: sift_down(a, 0, len(a))
    return top

为什么建堆是 O(n)

下滤的代价和结点到底部的距离成正比。以满二叉树为例，n ≈ 2^H：

  • 约 n/2 个叶子，不用下滤；
  • 约 n/4 个结点最多下滤 1 层；
  • 约 n/8 个结点最多下滤 2 层；
  • ……

总代价 ≤ n/4·1 + n/8·2 + n/16·3 + … = n·Σ k/2^(k+1) = n。所以建堆是 O(n)。直观地说：大多数结点在底部，下滤距离很短；只有少数靠近根的结点才可能走很远。逐个插入建堆则相反，大多数新元素放在底部，上滤距离最长可达 log n，总共 O(n log n)。

升序排序用大根堆：

  1. 把整个数组建成大根堆；

  3. 堆的大小减 1，对新堆顶下滤；
  4. 重复 2～3，共 n−1 趟。

void buildHeap(vector<int>& a) {
    int n = (int)a.size();
    for (int i = n / 2 - 1; i >= 0; --i) siftDown(a, i, n);   // 从最后一个分支结点往前
}

void heapSort(vector<int>& a) {
    buildHeap(a);
    for (int end = (int)a.size() - 1; end > 0; --end) {
        swap(a[0], a[end]);              // 当前最大值放到末尾
        siftDown(a, 0, end);             // 堆缩小 1，再调整
    }
}
def build_heap(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1): sift_down(a, i, n)   # 从最后一个分支结点往前；终点 -1 不含，最后一次是 i=0

def heap_sort(a):
    build_heap(a)
    for end in range(len(a) - 1, 0, -1):
        a[0], a[end] = a[end], a[0]       # 当前最大值放到末尾
        sift_down(a, 0, end)              # 堆缩小 1，再调整

发电报或压缩文件时，每个字符要编成 0/1 串。如果出现频率高的字符用短码、频率低的用长码，总长度就能变短。哈夫曼树给出最优的分配方式。

带权路径长度 WPL

给每个叶子一个权值 w（比如字符出现次数），它的路径长度 l 是从根到它经过的边数。树的带权路径长度 WPL = Σ wᵢ·lᵢ。** 哈夫曼树**是给定权值下 WPL 最小的二叉树，也叫最优二叉树。

构造算法

  1. 把 n 个权值看成 n 棵只有一个结点的树，放进一个集合（优先队列）；
  2. 取出权值最小的两棵，作为新结点的左右子树，新结点权值为两者之和，放回集合；
  3. 重复第 2 步，直到只剩一棵树。

前缀码：为什么不用分隔符就能解码

前缀码是指任何一个字符的编码都不是另一个字符编码的前缀。哈夫曼编码一定是前缀码，因为所有字符都在叶子上：从根走到一个叶子就停，这条路径不会经过别的叶子。

解码时从根出发，读到 0 向左走，读到 1 向右走，到达叶子就输出一个字符并回到根。例如 011100000111 依次切分为 01、11、000、001、11，分别对应 E、F、A、B、F，得到 EFABF，没有任何歧义。如果编码中有 A=0、B=01 这样的前缀关系，读到 0 时就无法判断它是 A 还是 B 的开头。

结点数：必定是 n−1 个内部结点

每次合并把两棵树变成一棵，树的数目减 1；从 n 棵到 1 棵恰好合并 n−1 次，每次产生一个内部结点。所以 n ≥ 2 时，哈夫曼树必定有 n−1 个内部结点、总共 2n−1 个结点，并且没有度为 1 的结点。这也和 n0 = n2 + 1 一致。

long long huffmanWPL(const vector<long long>& w) {
    priority_queue<long long, vector<long long>, greater<long long>> pq(w.begin(), w.end());
    long long wpl = 0;
    while (pq.size() > 1) {
        long long a = pq.top(); pq.pop();
        long long b = pq.top(); pq.pop();
        wpl += a + b;                    // 每次合并的和累加起来就是 WPL
        pq.push(a + b);
    }
    return wpl;
}
import heapq

def huffman_wpl(w):
    pq = list(w)                          # 复制一份，不改动调用者的列表
    heapq.heapify(pq)                     # heapq 本身就是小根堆，对应 C++ 的 greater<> 优先队列
    wpl = 0                               # Python 整数不会溢出，不用操心 long long
    while len(pq) > 1:
        a = heapq.heappop(pq)
        b = heapq.heappop(pq)
        wpl += a + b                      # 每次合并的和累加起来就是 WPL
        heapq.heappush(pq, a + b)
    return wpl

用小根堆每次取两个最小值，n−1 次合并各 O(log n)，总共 O(n log n)。对 {4,7,8,10,15,20} 返回 157。

15.12 B 树：定义、查找与插入 选读

数据库的数据放在磁盘上，磁盘按"页"（例如 4KB）读写，一次读一页的代价远高于在内存里比较几十次。如果用二叉树，100 万条记录要 20 层左右，可能读 20 次磁盘。把一个结点做成一页、里面放上百个键，树就变得又矮又胖，三四层就够了。这就是 B 树（多路平衡查找树）。

m 阶 B 树的定义（408 约定）

一棵 m 阶 B 树，每个结点最多有 m 棵子树。具体要求：

  1. 每个结点最多 m 个孩子、最多 m−1 个关键字；
  2. 根如果不是叶子，至少有 2 个孩子（至少 1 个关键字）；
  3. 除根以外的非叶结点至少有 ⌈m/2⌉ 个孩子；除根以外的所有结点至少有 ⌈m/2⌉−1 个关键字；
  4. 有 k 个关键字的非叶结点恰有 k+1 个孩子，结点内关键字递增，第 i 个孩子里的键都落在相邻两个关键字之间；
  5. 所有叶子在同一层。

52～4（非根至少 2）3～5

插入：先插到叶子，溢出后分裂

插入总是先查找到某个最底层的结点，把新键按顺序放进去。如果放进去后关键字数超过 m−1（溢出），就分裂：

  • 取第 ⌈m/2⌉ 个关键字（中间那个）上移到父结点；
  • 它左边的关键字留在原结点，右边的关键字组成新结点；
  • 如果父结点因此也溢出，继续向上分裂；根分裂时产生新根，树高加 1。

高度与关键字数的关系

设 B 树有 h 层（按层数，不算最下面的空指针层），记 c = ⌈m/2⌉：

  • 最多：每个结点 m−1 个键、m 个孩子，共 (1 + m + … + m^(h−1))·(m−1) = m^h − 1 个关键字；
  • 最少：根 1 个键、2 个孩子；第 2 层 2 个结点；第 3 层 2c 个；第 h 层 2c^(h−2) 个，非根结点各 c−1 个键。总数 1 + (c−1)·2·(1 + c + … + c^(h−2)) = 2c^(h−1) − 1。

所以 n 个关键字的 m 阶 B 树满足 2c^(h−1) − 1 ≤ n ≤ m^h − 1。例如 m=3、8 个关键字：h=2 时最多 3²−1=8，h=3 时最少 2·2²−1=7，所以高度可能是 2 或 3。m=5、3 层：最少 2·3²−1 = 17 个，最多 5³−1 = 124 个。

  • 两种插入算法结果不同。 408 和多数国内教材是"先插入、溢出再分裂"；CLRS 是"下降时遇到满结点先分裂"（预分裂），4 阶树里插 6 会得到根 [10]、叶子 [5 | 6] 和 [20]。CLRS 用最小度 t 描述：每个非根结点 t−1～2t−1 个键，相当于 m = 2t 阶。按题目指定的算法做，默认用 408 做法。

15.13 B 树的删除：直接删、借位、合并 了解

了解即可：B 树删除，主要是 408 考点。点击展开

删除比插入复杂，因为删掉一个键后结点可能少于 ⌈m/2⌉−1 个键（下溢）。处理顺序是：先把问题转到最底层，再看够不够，不够就先借，借不到就合并。

规则（408 约定）：

  1. 被删的键在非底层结点：用它的前驱（左子树中最大的键）或后继（右子树中最小的键）替换它，转化为删除最底层结点里的那个前驱或后继。
  2. 在最底层结点删除后键数仍 ≥ ⌈m/2⌉−1：直接删除，结束。
  3. 删除后下溢，且相邻兄弟有多余的键（兄弟键数 > ⌈m/2⌉−1）：** 借位**。父结点里夹在两者之间的分隔键下移到下溢结点，兄弟里最靠近的那个键上移补到父结点。
  4. 删除后下溢，且相邻兄弟也只有最少的键：合并。把下溢结点、兄弟、以及父结点中夹在两者之间的分隔键合成一个结点。父结点少了一个键，如果也下溢，就对父结点重复 3 或 4；如果根的键被拿空，删掉根，树高减 1。

小结： 删除非最底层的关键字时，先用它的前驱或后继代替；删除后关键字数仍然足够就结束，不够时先向兄弟借（父结点的关键字下移，兄弟的关键字上移），借不到就与兄弟合并（连同父结点中的分隔关键字）；根变空时树高减 1。

15.14 B+ 树：数据库索引的标准结构 选读

B 树的键散在各层，做范围查询（例如"金额在 100 到 500 之间"）时要在树里上下来回走。B+ 树把所有数据都放到叶子，叶子之间用链表按顺序连起来，非叶结点只做"路标"。范围查询找到起点后沿叶子链扫描即可，这正是数据库最常见的需求，MySQL InnoDB 等存储引擎的索引都用 B+ 树。[10]

m 阶 B+ 树的定义（408 约定）

  1. 每个分支结点最多 m 棵子树；
  2. 非叶的根至少 2 棵子树，其他分支结点至少 ⌈m/2⌉ 棵子树；
  3. 结点的子树个数与关键字个数相等：n 个关键字对应 n 棵子树；
  4. 分支结点里的每个关键字是对应子树中的最大关键字；
  5. 所有叶子在同一层，包含全部关键字及指向记录的指针，按关键字从小到大排列，相邻叶子用指针相连。本章约定叶子也存 ⌈m/2⌉～m 个关键字。

B+ 树通常有两个头指针：一个指向根，用于随机查找；一个指向最左边的叶子，用于从小到大顺序扫描。

这是一棵 3 阶 B+ 树。根的 30 表示"左子树最大键是 30"，50 表示"右子树最大键是 50"。

查找 25： 在根里找第一个 ≥ 25 的关键字，是 30，走第 1 棵子树；在 [15 | 30] 里第一个 ≥ 25 的是 30，走第 2 棵子树，到叶子 [20 | 25 | 30]，找到。即使在非叶结点里遇到了要找的键（例如查 30 时根里就有 30），也要继续走到叶子，因为记录只在叶子上。所以 B+ 树每次查找都走根到叶的完整路径，查找时间稳定。

范围查询 18 ≤ key ≤ 42： 先按上面的方法找到第一个 ≥ 18 的位置，在叶子 [20 | 25 | 30]；从这里沿叶子链往右读：20, 25, 30，跳到下一片叶子 35, 40，再下一片的 45 > 42，停止。结果 20, 25, 30, 35, 40。

插入：叶子分裂与分支结点分裂

插入时找到对应的叶子放进去；如果新键比整棵树的最大键还大，就放进最右边的叶子，并把路径上各分支结点的最大键更新为它。叶子超过 m 个键时分裂成两半，父结点多一个关键字（左半的最大键），原来的关键字仍对应右半；父结点超过 m 棵子树时同样分裂，一直到根。

1 / 3

第1步 · 起点：根 [15 | 30 | 50]，3 片叶子。35 落在 30 < 35 ≤ 50 的范围，进入第 3 片叶子，变成 35 | 40 | 45 | 50，超过 m=3，溢出。

2 / 3

3 / 3

第3步 · 根分裂成 [15 | 30] 和 [40 | 50]，新根存两者的最大键 30 | 50。树高由 2 变 3，所有叶子仍在同一层。

和 B 树对比：B 树分裂时中间键上移、离开原结点；B+ 树叶子分裂后，所有键都留在叶子里，父结点里的只是"最大键"的副本。

删除：借位与合并

叶子删除后如果仍有 ≥ ⌈m/2⌉ 个键，直接删；如果删的恰好是该叶子的最大键，要把父结点（以及更上层）对应的关键字改成新的最大键。下溢时，兄弟有多余的键就借一个，兄弟也只有最少的键就合并，合并后父结点少一棵子树，可能继续向上合并。

B 树与 B+ 树对比

对比项B 树B+ 树（408 约定）
关键字与子树k 个关键字，k+1 棵子树n 个关键字，n 棵子树
数据（记录指针）位置所有结点都有只在叶子
非叶结点里的键每个键只出现一次是叶子中键的副本（子树最大值）
查找成功可能在非叶结点结束一定走到叶子，路径长度稳定
范围查询要中序遍历整棵树找到起点后沿叶子链扫描
同样页大小下的扇出较小（非叶结点还要存数据）较大（非叶结点只存键和指针）

标准答案： 数据库索引多用 B+ 树而不用 B 树，原因有三：一是非叶结点只存放关键字，一页能放下更多关键字，树更矮，磁盘 I/O 更少；二是所有查询都要走到叶子，查询性能稳定；三是叶子之间用链表相连，范围查询和全表顺序扫描只需遍历叶子链表。

页容量算例： 页 4096 字节，页头 128 字节，键 8 字节，指针 8 字节。按 408 的 B+ 树约定，n 个键配 n 个指针：16n ≤ 3968，n ≤ 248，即每个分支结点最多 248 棵子树。3 层 B+ 树的前两层就能指向 248² = 61504 个叶子页；如果每个叶子页存 100 条记录，约 615 万条记录只需 3 次页访问（上层页常驻内存时更少）。

多选 · 理解检查 16　按 408 约定，3 阶 B+ 树：根 [30 | 50]，分支结点 [15 | 30]（叶子 [5,10,15]→[20,25,30]）和 [40 | 50]（叶子 [35,40]→[45,50]）。哪些说法正确？

A. 查找 30 时在根里遇到 30，仍要继续走到叶子

B. 删除 30 后，根变成 [25 | 50]

C. 范围查询 18～42 的结果是 20, 25, 30, 35, 40

D. 根有 2 个关键字，所以它有 3 棵子树

查看答案与每个选项的解析

A · 正确：B+ 树的记录只在叶子，非叶结点的 30 只是子树最大键的副本。

B · 正确：30 是叶子 [20,25,30] 的最大键，删掉后最大键变为 25，路径上的分支结点都要更新。

C · 正确：定位到叶子 [20,25,30] 后沿叶子链读，到 45 超出范围停止。

D · 错误：408 的 B+ 树中关键字数等于子树数，根有 2 棵子树；k 个键 k+1 棵子树是 B 树的规则。

易错点：

  • B+ 树有两种常见约定。 408 和国内教材：n 个关键字对应 n 棵子树，关键字取子树的最大值。很多英文教材和数据库实现：n 个关键字对应 n+1 棵子树，关键字是右侧子树的最小值（或分隔值），叶子分裂时把右半的最小键复制到父结点。两种画法都对，但手算的数字不同，题目给的图属于哪一种要先看清。
  • 叶子之间的链表是逻辑上的顺序，叶子页在磁盘上的物理位置不一定连续。
  • 树的层数少，指的是页访问次数少；每一页内部仍要做二分或顺序比较。

小结： 408 约定的 B+ 树中，n 个关键字对应 n 棵子树，每个关键字是对应子树中的最大值，数据全部存放在叶子中，叶子之间用链表相连；查找一定走到叶子；插入导致分裂后，父结点中加入左半部分的最大关键字；删除最大关键字时要修改祖先中的关键字；数据库选用 B+ 树，是因为它更矮、查询性能稳定、范围查询快。

单选 · 理解检查 17　从一千万个数中找出最大的 100 个，只能扫描一遍并且内存有限。哪个方案合适？

A. 维护大小为 100 的小根堆，新数比堆顶大就替换堆顶

B. 维护大小为 100 的大根堆，新数比堆顶小就替换堆顶

C. 把所有数插入普通 BST，再中序遍历取最后 100 个

D. 先保存全部数据再排序

查看答案与每个选项的解析

A · 正确：堆顶是当前入选 100 个数里最小的“门槛”，总时间 O(n log 100)，空间 O(100)。

B · 错误：这样留下的是最小的 100 个数，目标反了。

C · 错误：要保存全部一千万个数，内存不够；普通 BST 还可能退化成链。

D · 错误：需要 O(n) 内存，违反题目条件。

易错点：

  • 平衡 BST 和 B+ 树都能做有序查找，区别在成本模型：前者按"比较次数"优化，适合内存；后者按"页访问次数"优化，适合磁盘。
  • 堆只能高效取最值，查找任意元素仍是 O(n)。

小结： 选择数据结构时，先列出需要支持的操作再做选择：需要有序时用平衡 BST，需要最值时用堆，磁盘上的范围查询用 B+ 树，精确查找用哈希表，判断连通性用并查集。
