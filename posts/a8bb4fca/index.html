1. 3. 中间件 — 符号执行与 SSA

前端给出一份”完整但啰嗦”的 IR，中间件的任务是在保持语义的前提下让它变小。

1.1. 3.1 死代码先删：no-op 与不可达消除

问题：源码经前端降级后，IR 里几乎总有两类”语法上等价于不存在”的指令：

  1. No-op（空操作）：SKIP、守卫为 false 的跳转、跳到紧邻下一条的跳转、(void)0、孤立的常量表达式语句。它们多半是降级器为简化代码生成而留下的占位。
  2. 不可达代码：return 之后、assume(false) 之后、被永远不命中的分支守卫遮蔽的整段 basic block。

这些垃圾必须在喂给切片器之前删掉。原因：

  • 切片器从断言反向追踪依赖（见 §3.2），判定的是”这条赋值是否影响某个 ASSERT”，而不是“这条赋值能否被执行到”。一段静态不可达但写全局变量的代码，切片器会把它当成 live。
  • No-op 看似无害，但它们携带的 label: 让符号执行器多走一个 PC 转移；标签让控制流的静态可计算性下降，下游 pass（k-induction 的循环识别、覆盖率工具）都得绕开这些噪音节点。

1.1.1. A. 语法 no-op 消除

四个 must-preserve 规则：

  1. 不动点迭代：删一个 SKIP 可能让前面某个”跳到下一行”的 goto 变成 no-op（target 移位），所以要反复跑到不变。
  2. 标签搬运：被删指令上挂的 label: 必须搬到下一条 live 指令，否则 goto L 会指空。
  3. 先重定向再回收：跨整个函数体重写所有 goto/catch 的 target 之后才物理删除，避免悬空指针。
  4. 保留语义哨兵：函数尾的 END_FUNCTION（或等价物）即使从不被执行到也保留——它是后续分析依赖的边界标记。

1.1.2. B. CFG 不可达消除

教科书级 O(N) 算法。两个工程要点：

  • get_successors 必须精确：goto L（无条件跳转）的下一条物理指令不是它的后继；只有 L 是。这一精度直接决定不可达集合的大小。
  • 默认不做”未使用函数”消除（whole-program reachability）：函数边界处的调用图/逃逸信息通常残缺，per-function 保守保留更安全。

1.1.3. 部署：在管线中要跑几次

死代码消除需要 跑两次（或者更精确地：每个会改 IR 的下游 pass 之后都跑一次）：

中间那批 instrumentation 会自己引入新的 no-op 和死代码：把 assert(P) 改写成 if (active) assert(P); else skip;、给契约前后置条件包一层”绕过”分支等。第二次清理不冗余——是必须。

1.1.4. 何时反而要关闭

死代码消除便宜又安全，但前端清理 vs 后端可观察性之间有取舍。三类语义需要主动关掉：multi-property bug-finding（静态不可达但配置下可达的代码可能藏断言）、覆盖率模式（要报告的就是未到达节点）、前端 bug 调试（要保持 IR 与源码 1:1）。工具应通过 CLI 开关让用户选择，而不是单方面决定。

1.1.5. 与切片器的分工

死代码消除按控制流可达性精确局部地删；切片器按与 ASSERT 的依赖关系保守目标导向地删。两者作用域不重叠，应按”精确→保守”顺序串联——先用便宜的精确分析削明显垃圾，再让昂贵的保守分析处理灰色地带。设计要点不在算法（教科书级），而在部署纪律：跑在切片之前、每个会改 IR 的下游 pass 后再跑一次、需要”观察未到达节点”的语义模式下必须可关闭。

ESBMC 落地

  • 算法实现：remove_no_op (src/goto-programs/remove_no_op.cpp) 实现节 A 的全部四个 must-preserve 规则；is_no_op() 列出 5 种识别形态（SKIP / false-guard goto / next-target goto / (void)0 / 常量语句）。remove_unreachable (src/goto-programs/remove_unreachable.cpp) 实现节 B 的 worklist 算法，保留 END_FUNCTION 作为哨兵，per-function 粒度。
  • 部署点：在 src/esbmc/esbmc_parseoptions.cpp 中跑两次——一次紧随 goto_convert，一次紧随 instrumentation/contracts/monitors，对应本节”双 pass 部署”。
  • CLI 开关：--no-remove-no-op / --no-remove-unreachable，默认两个 pass 都开启。
  • 强制跳过：多属性 (--multi-property) 与覆盖率 (--goto-coverage) 模式即使不传 flag 也会强制跳过 remove_unreachable，对应本节”覆盖率模式必须关掉”的取舍。

1.2. 3.2 切片器：能消除什么、不能消除什么

切片（slicing）把不影响任何断言的 SSA 赋值标记为”忽略”。核心思路：从 ASSERT 反向追踪它依赖的变量，被追踪到的赋值标记 live，其余 ignore。

能消除：

  • 局部变量的中间计算结果（tmp = x + 1; y = tmp * 2; 当 tmp 没有别的用途）
  • 死分支的副作用
  • 调用了但返回值未使用的 pure 函数

不能消除：

  • 全局变量写：可能被任何后续读取，保守保留
  • 副作用调用：函数体不透明，无法判断是否影响断言
  • 跨函数依赖：函数边界处通常缺失精确别名/逃逸信息
  • 循环边界的写入：循环变量被守卫使用，无法纯局部分析

写代码时的优化原则：用局部变量优于全局；避免副作用函数（logger.log(x) 切不掉）；让循环可被静态展开。

1.2.1. 切片器的精确算法

维护依赖符号集 depends 和索引追踪表 indexes，反向扫描 SSA 步骤一次：

四个工程要点：

  1. 反向扫描 + SSA 单赋值：因为每个 SSA 符号只被赋值一次，反向遍历恰好让”下游消费者”先被处理。这是 SSA 形式带给切片器的最大便利——不必做迭代到不动点的复杂数据流分析。
  2. lhs 从 depends 移除：处理 x#5 := f(x#4) 时，把 x#5 移出后才加入 x#4。x#5 不会再被任何更早的 step 使用（SSA 唯一赋值），把它留在集合里只会膨胀状态。
  3. ASSERT 永不 ignore：断言本身永远 live，它只贡献依赖根。
  4. ASSUME 默认 live：assume 不被切片，除非显式开 --slice-assumes。原因是 assume 表达约束，删错了会让公式从 SAT 变 UNSAT（或反之），破坏 soundness。

1.2.2. 数组索引特殊化：避免”整数组依赖膨胀”

朴素反向追踪在数组面前会过保守：arr[const_idx] := v 把整个 arr 符号引入 depends，导致 arr 上的所有 store 都被保留。但实际上一个 ASSERT 只读 arr[k]，其它索引上的 store 完全无关。

精确切片器额外维护索引集追踪表 indexes: arr_sym ↦ set<const_idx>：

  • ASSERT 读 arr[const_k] 时，把 (arr → {k}) 加入 indexes，不把 arr 整体加入 depends。
  • 遇到 arr_new := arr_old WITH [const_j := v]：
    • 若 j ∈ indexes[arr_new]：保留 update，传播 indexes[arr_old] = indexes[arr_new] ∖ {j}，并把 v 的符号加入 depends。
    • 若 j ∉ indexes[arr_new]：把 step 改写为 arr_new := arr_old（短路 update），让上游沿用旧版本——后续这条 store 在 SMT 编码时变成纯赋值。
  • 若索引出现符号值（非常量）：退化为整数组依赖，回退到普通 depends。

效果：对 arr[0..N-1] 中只用了少数索引的工作负载，切片可削掉 O(N) 条无关 store。这一招对SMT array 的写链长度有直接影响——求解器对越长的 store-select 链就越慢。

1.2.3. --no-slice 不等于 “零优化”

--no-slice 不是直接关闭所有切片——而是把昂贵的反向依赖切片器降级为最朴素的”末段切片”：

最后一个 ASSERT 之后的所有 step 一律切掉。这一点是无条件 sound 的——没有任何后续 ASSERT 会读它们的值。

这个降级版本揭示了切片的两层责任：

  1. 末段死代码消除：廉价、精确、单次线性扫描。
  2. 中段不相关代码消除：昂贵，需反向依赖追踪。

--no-slice 关掉 (2)，保留 (1)。

什么时候应当关闭切片器：测试用例生成（--generate-testcase 隐式置 slice_nondet=false）、保留完整反例（--compact-trace 自动隐含 --no-slice）、per-symbol opt-out（--no-slice-name、--no-slice-id，典型于 witness 验证 / debug 输出 / 跨工具对比）。

1.3. 3.3 表达式简化器：跨阶段的常驻折叠

切片器是一次性、全局的 SSA 削减；简化器（simplifier）则是反复调用、本地的表达式重写。两者在 IR 削减上互补，但工作方式截然不同。

简化器是什么

简化器是一个纯函数式的、自底向上的表达式重写器：给一棵表达式树，递归地

  1. 先对每个子表达式调用自己；
  2. 再对当前节点尝试一组结构性重写规则。

规则集按作用域分四类（不同 BMC 工具实现细节有差异，但下表覆盖典型范围）：

类别规则示例
常量折叠1 + 2 → 3、5 < 3 → false、(int)0x42 → 66
代数恒等式x + 0 → x、x * 1 → x、x & 0 → 0、x | -1 → -1、!!x → x
结构化简(T)((T)x) → (T)x、(arr WITH [i := v])[i] → v、(arr WITH [i := v])[j] → arr[j] 当 i ≠ j 为常量
类型/指针(bool)x → (x != 0)、address_of(*p) → p、pointer_offset(p + c) → pointer_offset(p) + c

关键限制：简化器不知道路径条件、不知道 SSA 上下文、不依赖外部别名信息。它只看表达式自身的语法结构。这让它非常便宜（O(N) per 表达式树），但也把它的能力局限在”本地结构”上。

简化器的”多调用点”特性

不同于切片器（一次性运行），简化器在管线的多个阶段被反复调用。每个调用点都受 --no-simplify 控制：

  1. 前端类型转换：每次插入 typecast 节点都尝试折叠常量 cast。(uint32_t)42 直接变为常量节点，不留 cast 表达式。
  2. 解引用断言合成：每生成一条”指针有效性”断言时先简化它；若折叠为 true，跳过插入。这避免大量恒真断言污染 VCC 集合。
  3. 符号执行 RHS 评估：每次产生 SSA 赋值 lhs := rhs，先简化 rhs。
  4. Assume / 守卫：每条 ASSUME 的条件、每条 ASSERT 的守卫都被简化。
  5. memcpy / memset 特殊化：常量字节数的 memcpy(dst, src, n) 被前端特殊化为一组直接的 dst[i] = src[i] 赋值；这条路径要求 n 简化为常量，否则回退到通用字节级循环。

--no-simplify 的级联后果

--no-simplify 不只是”少做点折叠”——它会级联触发后续 pass 的退化分支：

  1. 每个常量都保留为常量表达式节点，而不是被压成纯字面量。SMT 编码器要为每个 cast / 算术节点生成结构化 SMT 项。
  2. 恒真断言保留：assert(true) 不会被消除，它们以恒真断言形式进入 IR，再由切片器/SMT 编码兜底，浪费 VCC 计数和编码时间。
  3. memcpy/memset 退回到符号循环：原本能特殊化为 N 步常量赋值（每步 1 SSA），现在每步走完整的 __memcpy_impl 循环（每步 ~10 SSA + 边界检查）。单次 memcpy(dst, src, 32) 可能从 32 条 SSA 膨胀到 320+ 条。
  4. 大量恒真 typecast 保留：(int)(int)x 不被折叠为 (int)x，SMT 端要把两层 cast 都编码进 BV operations。
  5. with 折叠失效：(arr WITH [0 := 5])[0] 不被简化为 5，每次数组读都走 SMT array select。

净效果：raw SSA、post-slice SSA、encoding time、solving time 四个指标同时上涨。

--no-simplify 仅用于：诊断简化器自身 bug、跨工具苹果对苹果对比、教学 / 可观察性需求。生产使用没有任何理由打开。

与切片器的分工：简化器跨多阶段反复调用、作用于单棵表达式树；切片器一次性、作用于整个 SSA 序列。前者像编译器的常量折叠 + peephole；后者像死代码消除 + 反向程序切片。两者作用域几乎不重叠——简化器不是”切片器的小预处理”，而是IR 降级路径的结构性合作伙伴：许多前端特殊化（memcpy 展开、解引用断言剪枝、常量 cast 消除）依赖简化器把表达式折叠到可识别常量形式。关掉它不只是少做折叠，而是触发这些路径的退化分支——这是为什么 §3.3 反复强调”假定简化器存在”是 IR 降级器的合约。

1.4. 3.4 常量传播：SSA-time 的字面量内联

简化器只看「眼前这棵表达式树」，它不知道某个符号此刻已经等于一个常量；要把 x = 5; y = x + 1; 化简成 y = 6，必须有一个跨指令的、跟随数据流的代换层。这个代换层就是常量传播。它和简化器不可互相替代：

  • 简化器：单棵表达式内部，「5+1 → 6」这种语法重写。
  • 常量传播：跨指令、沿 SSA 数据流，「x 当前 = 5，所以遇到 x 就替换成 5」这种符号代换。

两者级联——传播负责把符号变成字面量，简化器负责把字面量参与的式子折叠掉。单独有任何一边都几乎拿不到值：没有传播，简化器看到的几乎全是 符号 + 符号；没有简化器，传播只是把 5 内联进 (typecast)((5)+(0)) 这种未化简结构。

1.4.1. 通用算法：在哪个 IR 层做？

理论上常量传播可以放在任意有「单赋值」性质的 IR 层。三种常见放置：

放置知识载体时机代价
前端 AST编译器符号表类型检查阶段仅看到源码可见的常量
GOTO/CFG抽象解释 fixpoint（lattice 上的 meet）编译期需要解决控制流合并（⊥ ⊓ 5 = 5，5 ⊓ 7 = ⊤）
符号执行 / SSAL2 重命名表的「当前版本号 → 常量值」槽路径展开期单路径无需 fixpoint；每条路径独立

第三种最便宜：BMC 沿单一执行路径展开，每个变量的 L2 版本号只对应一个赋值，根本不存在控制流合并的问题——一个变量的版本号能查到常量，就是常量；查不到，就是符号。没有 lattice，没有不动点迭代。这就是 ESBMC 选用的层次。

1.4.2. 工程权衡：哪些 RHS 不该传播

把任何能算的都传播会出问题。三类常见黑名单：

  1. 不确定值（nondet symbol）：把它们当字面量 inline 走，反例信息就丢了——求解器返回的 model 里看到的是常量而非输入名，用户读不出「需要什么输入触发 bug」。
  2. 巨型常量结构（无限大小数组、多维数组、长字符串）：inline 会让后续每条引用都拖着整个结构再拷一份，SSA 体积爆炸。让它们走 SMT 数组理论的引用语义反而便宜。
  3. 副作用入口（指针 dereference、volatile、外部函数返回）：本来就不是「值」，谈不上常量。

剩下的（标量字面量、字面量算术、address_of(全局常量)、typecast(常量)、NULL）才放行。判定本身是纯语法递归——不调用求解器，不需要状态——所以代价摊在每条赋值上几乎可忽略。

1.4.4. --no-propagation 是死开关

  • src/esbmc/options.cpp:799 注册了 --no-propagation，文档写「Disable constant propagation」
  • src/goto-symex/symex_assign.cpp:28 据此设置 goto_symext::constant_propagation 布尔
  • grep 全 src/：这个布尔只在构造和拷贝里被赋值，没有任何条件分支读它。goto_symex_state.cpp:303 的判定是无条件运行的。

也就是说，--no-propagation 当前没有任何实际效果。要真正关闭传播必须改源码（把 line 303 改成 expr2tc const_value;）。这对调试 propagation-induced 现象偶尔有用，但对常规验证不推荐——会让简化器在大多数 RHS 上失去素材，CE 反而更长、SMT 体积更大。

核心要点：常量传播不是「nice-to-have 优化」，而是简化器的数据流前置。BMC 因为单路径展开而不需要 lattice，所以这个常量传播可以做得极廉价——但仍是必需的。--no-propagation 是历史遗留接口，文档化但未生效，不要试图用它来定位性能问题。

1.5. 3.5 区间分析：从「单值」到「值集」的过近似

常量传播只能记录「这个符号等于 5」；遇到 int x = nondet(); if (x > 0 && x < 100) ... 时它毫无办法——x 没有单一字面量。但程序里大量分析需要的是值集的上下界而不是确切值：数组越界检查、整数溢出、循环边界、断言剪枝……这就是区间分析的舞台。

它是抽象解释（Abstract Interpretation, Cousot & Cousot 1977）最经典的实例：把每个变量的具体值映射到一个区间 [lo, hi]，所有操作在区间上以「保守」方式重新定义（即结果区间包含所有可能的具体值）。这是一个有损但单调的近似：分析永远不会漏掉真实值，但可能把不可能值也包含进来。

1.5.1. 格论三件套

区间分析（以及任何抽象解释）的骨架是一个三元组：（抽象域，传递函数，不动点算法）。

1. 抽象域：每个变量映射到 (extended-int × extended-int) ∪ {⊥}：

抽象状态含义
[a, b] 其中 a ≤ b变量可能取 {a, a+1, …, b} 中任意值
(-∞, +∞) = ⊤没有任何信息（top）
⊥ (bottom)该程序点不可达 / 已发生矛盾

格上的操作：

  • 偏序 ⊑：I1 ⊑ I2 ↔ I1 ⊂ I2（区间包含）
  • join ⊔（并集的过近似 / hull）：[a,b] ⊔ [c,d] = [min(a,c), max(b,d)]——注意这是「凸包」，把 [0,1] ⊔ [3,4] 推成 [0,4]，包含了 2，这就是「过近似」
  • meet ⊓（交集，精确）：[max(a,c), min(b,d)]，若结果空则归为 ⊥

2. 传递函数：每条指令对状态的影响。这是抽象解释里最需要小心的部分——必须保证抽象语义包含具体语义，否则整个分析失去 soundness。例如：

  • x = y + z：新区间 = [lo(y)+lo(z), hi(y)+hi(z)]（不考虑溢出的话）
  • x = y * z：四个端点交叉相乘取 min/max（因为乘负数会反转方向）
  • assume(x < 10)：把 x 的 hi 收紧到 min(hi, 9)
  • if (cond) ...：taken 分支上 narrow cond 的条件，fall-through 分支上 narrow ¬cond（de Morgan）

3. 不动点算法：CFG 上的工作集传播（worklist）。每个程序点维护一份当前抽象状态，每条边触发一次传递函数 + join；当所有状态都不再变化时停止。

1.5.2. Widening：为什么需要它

朴素 worklist 在含循环的 CFG 上不一定终止：

第 1 次迭代：循环头 i ∈ [0,0]；第 2 次：[0,1]；…… 区间每次只长 1。如果 N 是符号（已知 ≥ 0 但上界未知），这个 join 序列永远不到不动点。

抽象解释经典的解法是widening operator ∇：放弃精度换收敛。常见规则：「如果新区间在某个方向上比旧区间走得更远，就把那个方向直接推到 ±∞」。

第 2 次迭代后立即得到 i ∈ [0, +∞]，第 3 次确认不动点。代价：精度从 [0, N-1] 退到 [0, +∞]，丢失了上界信息。

Narrowing（Δ）是 widening 的”逆动作”：在不动点之后，对那些被推到 ±∞ 的端点，看下一步迭代是否给出了有限值——如果给了，就把它收回来。理想情况下能从 [0, +∞] 通过循环出口 i < N 的条件 narrow 回 [0, N-1]。

extrapolate-limit（在 ESBMC 里默认是 5，options.cpp 里默认是 1）控制多少次普通 join 之后启用 widening——给精确分析一些喘息空间，避免对短循环也粗暴推到 ±∞。

1.5.3. ESBMC 的两层部署

ESBMC 把同一个 interval_domaint 类用在了两个完全不同的阶段，这是 grep CLI 选项时最容易混淆的事。

A. 离线 GOTO-level pass（--interval-analysis）

入口 esbmc_parseoptions.cpp:3239，走经典 AI 框架：ait<interval_domaint> 模板维护 per-instruction state_map，sequential_fixedpoint 按 location_number worklist 反复 visit → transform → merge（ai.cpp:90-113）；跨函数调用点把 actuals 抽象赋给 formals，返回时合并 callee 状态。

不动点收敛后 interval_analysis() 做两件事（interval_analysis.cpp:267）：

  1. optimize_function：用所在程序点的区间状态做表达式重写——interval.singleton() 替换为字面量；bool 表达式区间不含 0 → gen_true_expr()、区间 [0,0] → gen_false_expr()；再调 simplify(expr) 让简化器做后续折叠
  2. instrument_intervals：在选定指令前插入 ASSUME (a ≤ x ∧ x ≤ b ∧ ...)，把区间显式喂给后续 symex/SMT。插入策略由 INTERVAL_INSTRUMENTATION_MODE enum 选择，从 NO_INSTRUMENTATION 到 ALL_INSTRUCTIONS_FULL/LOCAL、GUARD_INSTRUCTIONS_FULL/LOCAL（默认）、LOOP_MODE（仅循环入口/出口/末尾）共 6 档（interval_analysis.h:10-24）

B. 在线 symex-time domain（--no-interval-symex-guard 默认开；--interval-symex-assert opt-in）

完全不同的部署：在 goto_symext 构造时 emplace 单实例 interval_domaint（symex_assign.cpp:148-155），随 symex 一路走、不分叉。symex_step 每条指令处理完后 process_instruction(pre_step_pc)，只处理 ASSIGN / ASSUME / DECL / DEAD——GOTO 边的 assume 故意不做。两类用途：guard 剪枝（默认开，symex_goto.cpp:70-79，循环 GOTO 上对 eval_boolean_expression 永真时直接跳出循环）；assertion 剪枝（opt-in，symex_main.cpp:102-120，区间域证 claim 永真则跳过 SMT）。

单实例带来的三条硬约束——若在分支上调 assume(guard)，事实会污染 sibling 分支：(1) symex_goto.cpp:102 注释明确”intentionally do NOT call assume() here”；(2) guard 剪枝只剪 TRUE，不剪 FALSE（永假可能是污染残留，剪了丢真 bug）；(3) guard 剪枝仅限 loop GOTO（loop_number != 0），非循环 if 分支共享状态会被污染。

1.5.5. 几个非显然的工程要点（读代码而非读注释才能发现）

  1. --interval-analysis-eval-assumptions 是有名无实：assume() 函数里相关代码块整段被 #if 0 包起来（line 1340-1350），CLI 选项目前不会改变行为
  2. --interval-analysis-narrowing 主动 abort：不是「未实现」而是「会让程序崩」，配合 #1738 标注的 join+narrowing 兼容性问题
  3. 真正的 narrowing 替代：因为 narrowing 关闭，循环出口的精度回收靠 --interval-analysis-assume-asserts——让 ASSERT 当成 ASSUME 反向窄化区间，迂回拿到 widening 后丢失的下界

1.5.6. 与常量传播、简化器的关系

三层抽象形成一条「精确 → 过近似 → 字面量折叠」流水线：常量传播（§3.4）跟随 SSA 单赋值记录单点字面量；区间分析（§3.5）做 CFG-level worklist + widening 推值集；简化器（§3.3）每个调用点把常量子树折成字面量。常量传播 O(每赋值) 纯语法，区间分析 O(CFG × widening) 全程序，简化器 O(表达式大小) 局部。单独任何一层都拿不到当前 ESBMC 在循环密集程序上的剪枝效果。

1.5.7. 何时开 --interval-analysis

离线 pass 默认 off——典型 BMC 任务（小程序、低循环深度、求解器够快）的 CFG fixpoint 是纯开销。开的场景：循环边界是符号但有约束（区间 narrow 出有限边界）、断言里有大量”区间不含 0”型平凡 case（叠加 -simplify -assume-asserts）、SMT 求解器是瓶颈（用 instrument 模式把区间注入为 ASSUME 给 SMT 先验）。online guard 剪枝默认就开（--no-interval-symex-guard 才关），专剪循环尾部已不可达的迭代，无需用户操心。
