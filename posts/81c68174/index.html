13.1 进制与转换：同一个数的不同写法

计算机内部只有 0 和 1，程序员却常用十六进制看内存（0x7FFFFFFF）、用八进制写 Linux 权限（chmod 755）、用十进制和人交流。笔试第一类计算题就是"把这个数换成另一种进制"，后面的补码、浮点、IP 地址、掩码全都建立在它之上。

位权：每种进制都是"数字 × 位权"再相加

R 进制有 R 个数字（0 到 R−1），从小数点往左第 k 位（k 从 0 起）的位权是 R^k，往右第 k 位的位权是 R^(−k)。一个数的值就是"每位数字 × 该位位权"之和。十六进制用 A～F 表示 10～15。

进制数字位权（从右往左）例子
二进制 B0、11, 2, 4, 8, 16 …1011.101B = 8+2+1+0.5+0.125 = 11.625
八进制 O0～71, 8, 64, 512 …752O = 7×64+5×8+2 = 490
十进制 D0～91, 10, 100 …490
十六进制 H0～9、A～F1, 16, 256 …1EAH = 1×256+14×16+10 = 490

所以任意进制转十进制只有一个方法：按位权展开求和。

十进制整数转 R 进制：除 R 取余，倒序读

把十进制整数不断除以 R，记下每次的余数，直到商为 0；第一个余数是最低位，所以要倒过来读。为什么？因为 x = R×商 + 余数，余数恰好是 x 在 R 进制下的个位；商再除以 R，得到的余数就是"十位"，依此类推。

二、八、十六进制互转：3 位一组、4 位一组

8 = 2³、16 = 2⁴，所以 1 个八进制位正好对应 3 个二进制位，1 个十六进制位正好对应 4 个二进制位。转换时以小数点为界，整数部分从右往左分组、小数部分从左往右分组，不够的位补 0，再把每组单独翻译。

灰色的 0 是为凑满 3 位补的前导 0。3 位一组读出 234O，4 位一组读出 9CH

反方向的转换同样简单：3AH 拆成 3 = 0011、A = 1010，得到 0011 1010B = 111010B = 58。八进制和十六进制之间互相转换时，先转成二进制最方便：752O 先写成 111 101 010B，再按 4 位一组重新分组为 1 1110 1010B，得到 1EAH。

十进制小数转二进制：乘 2 取整，顺序读

小数部分反复乘 2，每次取出整数部分（0 或 1）作为下一位，剩下的小数部分继续乘，直到小数部分为 0 或达到精度要求。第一个取出的整数是小数点后第一位，所以顺序读。

以 0.625 为例：0.625×2 = 1.25 取 1，剩 0.25；0.25×2 = 0.5 取 0；0.5×2 = 1.0 取 1，剩 0 停止。得 0.625 = 0.101B（验算：0.5+0.125）。

并非所有十进制小数都能乘到 0。0.1 会进入循环：

0.2 → 0.4 → 0.8 → 0.6 → 0.2 形成环，所以 0.1 = 0.0 0011 0011 0011…B 无限循环

规律： 一个最简分数的二进制小数有限，当且仅当分母是 2 的幂。0.5、0.25、0.375 = 3/8 都有限；0.1 = 1/10、0.2 = 1/5 都无限。这正是 13.5 里 0.1+0.2 出现误差的根源。

位、字节与容量单位

1 位（bit，b）存一个 0 或 1；1 字节（Byte，B）= 8 位。存储容量用字节、传输速率用位每秒，计算前先统一单位。容量单位有两套：

写法含义常见场合
KiB / MiB / GiB2¹⁰ / 2²⁰ / 2³⁰ 字节内存、地址空间（教材常写作 KB/MB/GB）
kB / MB / GB（SI）10³ / 10⁶ / 10⁹ 字节硬盘标称容量、网络速率 Mbps

地址空间 = 地址个数 × 每个地址对应的单元大小。 20 根地址线、按字节编址，可寻址 2²⁰ × 1B = 1MiB；32 根地址线、每个地址对应 4B（按字编址，字长 32 位），可寻址 2³² × 4B = 16GiB。传输时间 = 数据位数 ÷ 速率：100Mbps 链路发送 10MB（十进制），10×8 = 80Mb，80 ÷ 100 = 0.8 秒（只算发送时延）。

代码：除基取余和乘 2 取整

x 是待转换的非负整数；base 是目标进制；s 依次收集余数（先低位后高位）；f 是 [0,1) 内的小数部分；bit 是本轮乘 2 后的整数部分。

string toBase(unsigned long long x, int base) {
    const string digits = "0123456789ABCDEF";
    if (x == 0) return "0";
    string s;
    while (x > 0) {
        s += digits[x % base];   // remainder = next lower digit
        x /= base;
    }
    return string(s.rbegin(), s.rend());   // first remainder is the lowest digit
}

string fracToBinary(double f, int maxBits) {
    string s = "0.";
    for (int i = 0; i < maxBits && f > 0; ++i) {
        f *= 2;
        int bit = (f >= 1) ? 1 : 0;   // integer part is the next bit
        s += char('0' + bit);
        f -= bit;
    }
    return s;
}
def to_base(x, base):                 # Python int 无上限，x 不受 unsigned long long 的 64 位限制
    digits = "0123456789ABCDEF"
    if x == 0: return "0"
    s = ""
    while x > 0:
        s += digits[x % base]   # remainder = next lower digit
        x //= base              # 必须用 //：Python 3 的 / 总是得到浮点数
    return s[::-1]              # first remainder is the lowest digit；[::-1] 相当于 rbegin/rend 反转

def frac_to_binary(f, max_bits):      # Python float 就是 C++ double（64 位双精度）
    s = "0."
    for i in range(max_bits):
        if not f > 0: break           # C++ for 的第二个条件 f > 0，range 写不进去，放到循环体开头
        f *= 2
        bit = 1 if f >= 1 else 0      # integer part is the next bit
        s += str(bit)                 # str(1) == "1"，对应 char('0' + bit)
        f -= bit
    return s

手工模拟：toBase(156, 16) 先得到余数 12，即 'C'，再得到 9，依次收集为 "C9"，反转后得到 "9C"。fracToBinary(0.1, 10) 返回 "0.0001100110"，只截取了 10 位，因为 0.1 的二进制展开本身不会终止。可以用 Python 内置的 bin(156)、oct(156)、hex(156) 和 int('9C', 16) 直接核对。

要点：

  • R 进制数转十进制，按位权展开后相加。
  • 十进制整数转 R 进制，用除 R 取余法，余数倒序排列；十进制小数转 R 进制，用乘 R 取整法，整数部分顺序排列。
  • 二进制与八进制互转时 3 位一组，与十六进制互转时 4 位一组；从小数点向两边分组，位数不足时补 0。
  • 一个十进制小数能精确地转成二进制，当且仅当它化成最简分数后分母是 2 的幂。

单选 · 理解检查 1　十进制 45.375 写成二进制和十六进制分别是？

A. 101101.011B，2D.6H

B. 101101.110B，2D.CH

C. 110101.011B，35.6H

D. 101101.011B，2D.3H

查看答案与每个选项的解析

A · 正确：45 = 32+8+4+1 = 101101B；0.375 = 0.25+0.125 = 0.011B。整数部分 0010 1101 = 2D，小数部分 .0110 = .6。

B · 错误：小数部分乘 2 取整要顺序读：0.375×2=0.75 取 0，×2=1.5 取 1，0.5×2=1 取 1，得 .011，不能倒过来。

C · 错误：整数部分除 2 取余要倒序读，正序读出的 110101 是 53。

D · 错误：十六进制小数部分从小数点往右 4 位一组，.011 要补成 .0110 = 6，不是补在左边。

易错点：

  • 整数部分倒序读，小数部分顺序读，两者方向相反。
  • 小数部分分组要在右侧补 0：0.011B = 0.0110B = 0.6H。
  • "8GB 内存"是字节，"100Mbps 带宽"是位，相差 8 倍。

小结： 转十进制按位权求和；整数部分除基取余、倒序读出，小数部分乘基取整、顺序读出；二进制与八进制三位一组，与十六进制四位一组。

13.2 原码、反码、补码、移码：四种表示负数的方法

无符号整数只表示 0 和正数：8 位能表示 0～255。要表示负数，就要拿出一些位串"当负数用"。怎么分配，决定了加减法电路是否简单、0 有几种写法、表示范围多大。历史上有四种方案，408 和银行笔试常考它们的写法、范围和区别。

四种编码的定义（n 位，以 8 位为例）

  • 原码：最高位是符号位（0 正 1 负），其余 7 位写绝对值。最直观，像我们写 "−5"。
  • 反码：正数同原码；负数在原码基础上，符号位不变、数值位按位取反。
  • 补码：正数同原码；负数 = 反码 + 1。等价的定义是 [x]补 = 2ⁿ + x（模 2ⁿ）：−5 的 8 位补码就是 256 − 5 = 251 = 11111011。
  • 移码：[x]移 = x + 2^(n−1)，8 位时就是"真值加 128"。它把整个范围平移到非负数，所以移码越大，真值越大，可以直接按无符号数比较大小。

补码有一个更好记的读法：最高位的位权是 −2^(n−1)，其余位权照常为正。8 位补码 11111011 = −128+64+32+16+8+2+1 = −5。

−128 为什么特殊

补码只有一个 0，所以省出了一个位串 1000 0000。按"最高位权 −128"来读，它的值正好是 −128。−128 在 8 位里没有原码和反码，它的补码也无法用"取反加一"从 +128 得到，因为 +128 本身超出了 8 位补码的范围。对 1000 0000 再做"取反加一"，得到的还是 1000 0000：−(−128) 在 8 位里溢出回到自己。同理，32 位 int 的 INT_MIN = −2147483648 取绝对值会溢出。

为什么计算机用补码

补码让减法变成加法：A − B = A + [−B]补，CPU 只要一个加法器；符号位也直接参与运算，不需要单独判断；0 只有一种写法。移码则用在浮点数的阶码中，因为阶码需要频繁比较大小，移码可以直接按无符号数比较。

符号扩展： 把 8 位补码扩成 16 位时，复制符号位填满高位。−5 = 1111 1011 扩成 1111 1111 1111 1011，值不变；无符号数扩展则补 0。

要点：

  • 正数的原码、反码、补码相同；移码与补码只有符号位不同（符号位取反）。
  • 负数的补码等于反码加 1；[x]补 = 2ⁿ + x，最高位的位权是 −2^(n−1)。
  • 8 位补码的范围是 −128～127，1000 0000 表示 −128；原码和反码有 +0 和 −0，范围是 −127～127。
  • 计算机采用补码的原因（标准答案）：加减法可以统一用加法器完成，符号位直接参与运算，0 的表示唯一，并且能多表示一个负数。

  • 移码偏置在整数编码里取 2^(n−1)（8 位是 128）；IEEE 754 阶码的偏置是 127，二者在 13.4 对照。

小结： 原码用最高位表示符号，反码对负数的数值位取反，补码在反码基础上加 1，移码是真值加 128；8 位补码的范围是 −128 到 127，0 只有一种表示。

13.3 补码加减法与溢出判断：数轮上转圈

CPU 里的加法器只管把两个位串相加、丢掉超出位宽的进位。结果是否还代表正确的数，要靠"溢出判断"。408 和银行笔试常给两个数让你算补码和、判断是否溢出，并问用哪种方法判断。

运算规则

  • 加法：[A+B]补 = [A]补 + [B]补，符号位与数值位一起相加，最高位产生的进位直接丢弃（模 2ⁿ）。
  • 减法：[A−B]补 = [A]补 + [−B]补。求 [−B]补 的方法：把 [B]补 连同符号位一起取反再加 1。

例：5 − 9 = 5 + (−9)。[5]补 = 0000 0101，[−9]补 = 1111 0111，相加得 1111 1100 = −4，正确。

模 256 数轮：溢出为什么会"绕回去"

8 位补码只有 256 个位串，把它们按"加 1"的顺序首尾相接，就是一个环。0 往顺时针走是正数，走到 127 再加 1，位串从 0111 1111 变成 1000 0000，读出来是 −128；继续走，−127、…、−1，再加 1 回到 0。

顺时针每走一格加 1。从 100 出发走 60 格，越过 127→−128 的边界，停在 −96：这就是正溢出。−1→0 处虽然有最高位进位，但没有越界

数轮把两件事分开了：越过 127 / −128 之间那条边才是有符号溢出；越过 −1 / 0 之间那条边只是最高位产生进位，结果仍然正确（例如 −1 + 1 = 0）。所以"最高位有进位"和"有符号溢出"是两回事。

三种溢出判断方法

只有同号相加（或异号相减）才可能溢出，因为异号相加的结果绝对值不会超过两个加数中较大的那个。

  1. 符号位判断法（单符号位）：两个正数相加得负数，或两个负数相加得正数，就是溢出。
  2. 双符号位法（变形补码）：用两个符号位（正数 00、负数 11）参与运算。结果符号位为 01 表示正溢出，10 表示负溢出，00、11 表示没有溢出；最左边那位总是正确的符号。
  3. 进位判断法：设 C_s 为符号位产生的进位，C_1 为最高数值位向符号位的进位，V = C_s ⊕ C_1，V = 1 表示溢出。

代码：两种判断法

a、b 是 −128～127 的整数；ua、ub 是它们的 8 位位串（无符号）；cin 是低 7 位相加向符号位的进位 C₁；cout 是 8 位相加向外的进位 Cₛ。

int wrap8(int x) {
    x &= 0xFF;
    return x >= 128 ? x - 256 : x;
}
bool overflowBySign(int a, int b) {          // a, b in [-128, 127]
    int r = wrap8(a + b);
    bool sameSign = (a < 0) == (b < 0);
    return sameSign && ((r < 0) != (a < 0)); // same signs in, different sign out
}
bool overflowByCarry(int a, int b) {
    unsigned ua = a & 0xFF, ub = b & 0xFF;
    unsigned cin = ((ua & 0x7F) + (ub & 0x7F)) >> 7;  // carry into the sign bit
    unsigned cout = (ua + ub) >> 8;                   // carry out of the sign bit
    return cin != cout;
}
def wrap8(x):                         # Python int 无限精度、永不溢出，8 位绕回只能靠掩码模拟
    x &= 0xFF                         # 只保留低 8 位
    return x - 256 if x >= 128 else x # 最高位按 -128 解读
def overflow_by_sign(a, b):           # a, b in [-128, 127]
    r = wrap8(a + b)                  # a + b 是精确值（如 160），wrap8 把它折回 8 位（-96）
    same_sign = (a < 0) == (b < 0)
    return same_sign and ((r < 0) != (a < 0))   # same signs in, different sign out
def overflow_by_carry(a, b):
    ua, ub = a & 0xFF, b & 0xFF       # 负数 & 0xFF 直接得到 8 位补码位串：-5 & 0xFF == 0xFB
    cin = ((ua & 0x7F) + (ub & 0x7F)) >> 7   # carry into the sign bit
    cout = (ua + ub) >> 8                    # carry out of the sign bit
    return cin != cout

wrap8 模拟"只保留低 8 位再按补码解读"：wrap8(160) 得 −96。

语言层面的补充： Java 的 int 溢出按补码绕回；C/C++ 的有符号整数溢出是未定义行为，编译器可以假设它不发生，所以 C/C++ 程序要在运算前用 long long 防溢出；C/C++ 无符号整数按 2ⁿ 取模，绕回有保证。[1] [2]

要点：

  • 减法可以变成加法：[A−B]补 = [A]补 + [−B]补。
  • 只有两个同号的数相加才可能溢出：正数加正数得到负数，或负数加负数得到正数，就是溢出。
  • 采用双符号位时，00 表示正，11 表示负，01 表示正溢出，10 表示负溢出。
  • 用进位判断溢出：V = Cₛ ⊕ C₁，即符号位的进位与最高数值位的进位做异或。

13.4 IEEE 754 浮点数：格式与换算

整数表示不了 3.14，也表示不了 6×10²³ 这样的大数。浮点数借用科学计数法：用一部分位存"有效数字"，一部分位存"指数"，于是用 32 位就能表示从 10⁻³⁸ 到 10³⁸ 的数。银行和 408 笔试最爱考"把 −5.75 写成 IEEE 754 单精度"和"把 41360000H 换算成十进制"。

二进制科学计数法与三个字段

任何非零二进制数都可以写成 ±1.xxxx × 2^e，小数点前恰好是一个 1，这种形式叫规格化。例如 101.11B = 1.0111 × 2²。IEEE 754 把它拆成三段存储：

值 = (−1)^S × 1.M × 2^(E−127)。双精度格式相同，宽度为 1 + 11 + 52，偏置 1023

格式总位数符号 S阶码 E尾数 M偏置有效位（含隐含 1）十进制有效数字
单精度 float32182312724约 7 位
双精度 double6411152102353约 15～16 位
  • 符号 S：0 正 1 负。
  • 阶码 E：存的是"真实指数 e + 偏置"，单精度偏置 127。这种"加一个常数"的做法就是 13.2 的移码思想，好处是阶码可以当无符号数比较大小；IEEE 754 选的偏置是 2^(k−1)−1 = 127，比整数移码的 128 小 1。规格化数的 E 取 1～254，所以真实指数 e = E − 127 的范围是 −126～+127。
  • 尾数 M：规格化后小数点前那个 1 每次都有，干脆不存，称为隐含位。M 只存小数点后的 23 位，于是实际有 24 位有效二进制数字。

13.5 浮点数的特殊值与精度：±0、∞、NaN 和 0.1+0.2

阶码全 0 和全 1 这两种位串被 IEEE 754 留作特殊用途，分别用来表示 0、极小数、无穷和"不是数"。理解它们，才能回答"float 最大值是多少""1.0/0 等于几""为什么 0.1+0.2 ≠ 0.3"这类面试题。

按阶码 E 分五类

先看阶码是全 0、全 1 还是其他，再看尾数是否为 0；符号位 S 决定正负

类别EM值例子（单精度）
±0全 00±000000000H = +0，80000000H = −0
非规格化数全 0≠ 0(−1)^S × 0.M × 2⁻¹²⁶00000001H = 2⁻¹⁴⁹ ≈ 1.4×10⁻⁴⁵（最小正数）
规格化数1～254任意(−1)^S × 1.M × 2^(E−127)3F800000H = 1.0

非规格化数用来填补 0 和最小规格化数 2⁻¹²⁶ 之间的空隙：它的隐含位是 0，指数固定为 −126（注意不是 0 − 127），这样数值能从 2⁻¹²⁶ 平滑地降到 0，这叫"逐渐下溢"。

±0 是两个位串，但比较时 +0 == −0 为真。** ∞** 由溢出或非零数除以 0 得到，例如 1.0/0.0 = +∞。** NaN**（Not a Number）由 0.0/0.0、∞−∞、负数开平方等无意义运算得到，而且 NaN 与任何数比较都为假，包括它自己，所以 x != x 是判断 NaN 的经典写法。

精度：为什么 0.1 + 0.2 ≠ 0.3

13.1 说过，0.1 的二进制无限循环。双精度只有 53 位有效数字，只能存一个最接近 0.1 的二进制数，它比 0.1 略大一点点；0.2 同理。两个近似值相加再舍入，结果的位串是 3FD3333333333334H，而 0.3 的最近近似是 3FD3333333333333H，最后一位差 1。Python 里 0.1 + 0.2 显示 0.30000000000000004。

只差最后一个二进制位：两个舍入误差叠加后落到了相邻的另一个浮点数上

整数也会丢精度。 float 只有 24 位有效数字，2²⁴ + 1 = 16777217 需要 25 位，存进 float 后变成 16777216。所以 int 转 float 可能丢精度，int（32 位）转 double（53 位）不会。

工程上的做法：

  • 比较浮点数用误差范围：fabs(a - b) < 1e-9，Python 用 math.isclose(a, b)。
  • 金额用整数（以"分"为单位）或十进制定点类型：Java 的 BigDecimal、Python 的 decimal.Decimal、数据库的 DECIMAL。银行笔试常考这一条。[3]

要点：

  • 阶码全为 0 时，尾数为 0 表示 ±0，否则是非规格化数；阶码全为 1 时，尾数为 0 表示 ±∞，否则是 NaN。
  • NaN 不等于任何值，包括它自己；+0 与 −0 相等。
  • 0.1+0.2 ≠ 0.3 的原因（标准答案）：十进制的 0.1 和 0.2 在二进制中是无限循环小数，用有限位存储时必须舍入，误差累积后，结果与 0.3 的近似值不同。
  • 比较浮点数时使用误差阈值；表示金额时用以分为单位的整数，或者 BigDecimal / Decimal。

C · 正确：16777217 = 2²⁴ + 1 需要 25 位有效数字，float 只有 24 位，舍入到 16777216。

D · 错误：NaN 与任何值比较都为假，包括自身。

易错点：

  • 非规格化数的指数是 −126，隐含位是 0；按 E − 127 = −127 计算会错。
  • "float 精度约 7 位"指十进制有效数字（24 × log₁₀2 ≈ 7.2），和小数点后几位无关。
  • 浮点误差来自有限位舍入，加法电路本身是按规则正确执行的。

小结： 阶码全 0 表示零和非规格化数，全 1 表示无穷和 NaN；NaN 不等于自己；0.1 在二进制中无限循环，所以会产生误差，比较时使用误差阈值，金额用以分为单位的整数表示。

13.6 字符编码：ASCII、Unicode 与 UTF-8

文件、网页、数据库里存的都是字节。同一串字节按不同编码解读，会得到不同的字符，这就是"乱码"。面试常问"一个汉字占几个字节""UTF-8 为什么是变长的"，SQL 题也会遇到 utf8mb4。

三个层次：字符集、码点、编码方式

  • ASCII：最早的字符集，用 7 位表示 128 个字符（英文字母、数字、标点、控制字符），存储时占 1 字节。要记住三个码值：'0' = 48，'A' = 65，'a' = 97，大小写差 32。
  • Unicode：给世界上所有字符各分配一个编号，叫码点，写作 U+十六进制。"中"的码点是 U+4E2D，"A"是 U+0041。Unicode 只规定编号，没有规定怎样存成字节。[4]
  • UTF-8：把码点变成字节的一种方案，变长 1～4 字节，ASCII 字符仍是 1 字节，完全兼容 ASCII。另有 UTF-16（2 或 4 字节）、UTF-32（固定 4 字节）。中文 Windows 常见的 GBK 是另一套字符集，汉字占 2 字节（"中"在 GBK 中是 D6D0H）。

UTF-8 的编码规则

    vector<unsigned char> out;
    if (cp <= 0x7F) {
        out.push_back(cp);                                   // 0xxxxxxx
    } else if (cp <= 0x7FF) {
        out.push_back(0xC0 | (cp >> 6));                     // 110xxxxx
        out.push_back(0x80 | (cp & 0x3F));                   // 10xxxxxx
    } else if (cp <= 0xFFFF) {

        out.push_back(0x80 | ((cp >> 6) & 0x3F));
        out.push_back(0x80 | (cp & 0x3F));

        out.push_back(0x80 | (cp & 0x3F));

}

三个经典技巧

  2. x & (−x) 取出最低位的 1（lowbit）。 补码中 −x = ~x + 1，最低位的 1 及右边保持不变、左边全部取反，相与后只剩最低位的 1。12 & −12 = 4。树状数组就用它。

13.8 大端与小端：多字节数在内存里的排列

一个 int 占 4 字节，内存按字节编址，那么这 4 个字节谁放在低地址？不同 CPU 的答案不同。两台机器通过网络交换整数、读取二进制文件、做内存取证时，如果排列方式不一致，读出来的数就是错的。

两种排列

  • 大端（Big-Endian）：高位字节放在低地址，和我们书写数字的顺序一致。网络传输统一使用大端，所以大端也叫网络字节序。
  • 小端（Little-Endian）：低位字节放在低地址。x86、x86-64 以及常见的 ARM 配置都是小端。

以 0x12345678 存放在地址 0x100 开始的 4 个字节为例。这个数的最高位字节是 12，最低位字节是 78。

第 0 行是地址（从低到高）。大端在最低地址放最高位字节 12；小端在最低地址放最低位字节 78

端序只影响多字节数据内部各字节的先后。单个字节内部的位序不变；char 数组、字符串按下标顺序存放，也不受端序影响。

代码：判断本机端序

x 是已知内容的 4 字节整数；first 是 x 所在内存中地址最低的那个字节。

bool isLittleEndian() {
    uint32_t x = 0x12345678;
    unsigned char first;
    memcpy(&first, &x, 1);   // the byte at the lowest address
    return first == 0x78;
}
import struct

def is_little_endian():
    x = 0x12345678
    first = struct.pack('=I', x)[0]   # '=' 按本机字节序排成 4 个字节，[0] 是最低地址那个字节
    return first == 0x78              # Python 没有指针和 memcpy；也可直接看 sys.byteorder == 'little'

在 x86 上返回 true。网络编程中，发送前用 htonl / htons 把主机字节序转成网络字节序，接收后用 ntohl / ntohs 转回来；在大端机器上这些函数什么也不做。Python 中 struct.pack('<I', x) 按小端打包，'>I' 或 '!I' 按大端（网络序）打包。

要点：

  • 大端模式把高位字节存放在低地址，网络字节序采用大端；小端模式把低位字节存放在低地址，x86 采用小端。
  • 判断机器端序的方法：把一个已知的整数（如 1 或 0x12345678）存入内存，查看最低地址处的字节。
  • 端序只影响多字节数据内部字节的排列顺序，与字节内位的顺序以及数组元素的顺序无关。

13.9 数据结构与算法：从数据怎样组织到算法怎样评价

前面讲的是"一个数怎样存"，从这里开始讲"一批数怎样组织、怎样处理"。笔试的概念题常问"逻辑结构有哪几种""算法有哪五个特性"，这一节把这些基础术语一次讲清，后面几章都会用到。

数据结构的三要素

  • 逻辑结构：数据元素之间的关系，与怎样存储无关。分四类：** 集合**（只是同属一个集合）、线性结构（一对一，如线性表、栈、队列）、树形结构（一对多）、图状结构（多对多）。
  • 存储结构（物理结构）：关系在内存中怎样表示。分四种：** 顺序存储**（相邻元素放在相邻地址，如数组）、链式存储（用指针连接，如链表）、索引存储（另建索引表）、散列存储（按关键字算地址，如哈希表）。
  • 数据的运算：定义在逻辑结构上，实现在存储结构上。

同一种逻辑结构可以用不同的存储结构实现：线性表既可以顺序存储（数组），也可以链式存储（链表）

抽象数据类型（ADT） 只规定"有哪些操作、每个操作的含义"，不规定实现。例如"栈只在一端进出"是 ADT 的规定，可以用数组或链表实现。

顺序存储的地址公式： 首地址为 LOC，每个元素占 L 字节，则 a[i] 的地址 = LOC + i × L。int 占 4 字节、首地址 1000 时，a[6] 在 1000 + 6×4 = 1024。按下标访问只需这一次乘加，所以是 O(1)；链式存储要从头逐个跟着指针走，按位置访问是 O(n)。

算法的五个特性与"好算法"的标准

算法是解决问题的有限步骤序列，必须具备五个特性：有穷性（有限步内结束）、确定性（每步含义明确，相同输入得到相同输出）、可行性（每步都能通过基本操作实现）、输入（零个或多个）、输出（一个或多个）。好算法的设计目标是正确性、可读性、健壮性、高效率与低存储量。最后一条就是下面几节的主题：时间复杂度和空间复杂度。

要点：

  • 数据结构的三要素是逻辑结构、存储结构和数据的运算。
  • 逻辑结构分为集合、线性结构、树形结构、图状结构四类；存储结构有顺序、链式、索引、散列四种。
  • 算法有五个特性：有穷性、确定性、可行性、输入、输出。程序可以无限运行（如操作系统），而算法必须在有限步内结束。

  • "有序表""栈"是逻辑层面的概念；"顺序表""链表"已经带有存储结构的含义。
  • 数组可以分配在全局区、栈或堆上，链表节点也一样，存储结构与分配位置是两条独立的轴。

小结： 数据结构的三要素是逻辑结构、存储结构和运算；逻辑结构有集合、线性、树形、图状四类，存储结构有顺序、链式、索引、散列四种；算法具有有穷性、确定性、可行性、输入和输出五个特性。

13.10 时间复杂度与空间复杂度：大 O、Ω、Θ

两个程序都能算出正确答案，n = 100 时都很快；n = 10⁶ 时，一个 0.02 秒，另一个要几小时。差别来自"运行步数随 n 增长的速度"。复杂度就是描述这种增长速度的语言，它和具体机器、编程语言无关。

定义

  • 问题规模 n：输入数据的量，如数组长度、图的顶点数。
  • 时间复杂度 T(n)：算法中基本语句（执行最多的那条语句）的执行次数随 n 增长的数量级。
  • 空间复杂度 S(n)：算法运行时需要的辅助空间随 n 的增长量级，输入本身占的空间通常不计；递归调用栈要计入。

只关心数量级，是因为 n 足够大时，最高次项决定一切：T(n) = 3n² + 100n + 5000，n = 10⁴ 时 3n² 是 3×10⁸，后两项合计约 10⁶，可以忽略。

三个渐近记号

  • 大 O（上界）：若存在常数 c > 0 和 n₀，使得所有 n ≥ n₀ 都有 f(n) ≤ c·g(n)，记 f(n) = O(g(n))。意思是"f 增长得不比 g 快"。
  • 大 Ω（下界）：若存在 c > 0 和 n₀，使得 n ≥ n₀ 时 f(n) ≥ c·g(n)，记 f(n) = Ω(g(n))。
  • 大 Θ（紧确界）：既是 O(g) 又是 Ω(g)，记 f(n) = Θ(g(n))，表示"同阶"。

以 f(n) = 3n + 10 为例：取 c = 4、n₀ = 10，n ≥ 10 时 3n + 10 ≤ 4n，所以 f(n) = O(n)；取 c = 3，所有 n 都有 3n + 10 ≥ 3n，所以 f(n) = Ω(n)。两者都成立，f(n) = Θ(n)。

n ≥ 10 之后，f(n) 被夹在 3n 和 4n 之间：f(n) = Θ(n)

笔试和面试里写的"时间复杂度 O(n²)"，习惯上指的是最紧的那个上界，也就是 Θ 意义下的数量级。

常见数量级的增长

n 只到 8，2ⁿ 已经是 256；n = 30 时 2ⁿ 超过 10 亿。多项式与指数的差距随 n 迅速拉大

从小到大的顺序要背熟：

O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)

两条运算规则

  • 加法规则：顺序执行的两段代码，T = T₁ + T₂ = O(max(f, g))。先遍历一遍（n）再双重循环（n²），总共 O(n²)。
  • 乘法规则：嵌套执行，T = T₁ × T₂ = O(f × g)。外层 n 次、每次调用一个 O(log n) 的函数，总共 O(n log n)。

对数的底数不影响数量级：log₂n = log₁₀n / log₁₀2，只差常数倍，所以统一写 O(log n)。

空间复杂度举例： 原地反转数组只用两个下标，O(1)；归并排序需要长度 n 的辅助数组，O(n)；递归求链表长度，调用栈深度 n，O(n)。

要点：

  • O 表示上界，Ω 表示下界，Θ 表示同阶；计算时去掉常数和低次项。
  • 常见数量级从小到大依次为：1 < log n < n < n log n < n² < n³ < 2ⁿ < n! < nⁿ。
  • 顺序执行的代码取其中最大的复杂度，嵌套的代码复杂度相乘；对数的底数可以忽略。
  • 空间复杂度只计算辅助空间，递归还要计算调用栈的深度。

13.11 循环计数法：一步一步数出执行次数

求复杂度最可靠的办法是"数"：找出执行最多的那条语句，写出它的执行次数，再化简。很多题故意让循环看起来像 n²，实际却是 n 或 n log n，只看"有几层 for"会选错。

片段 1：单层循环

for (int i = 0; i < n; ++i) ++c;
for i in range(n): c += 1         # range(n) 是 0..n-1；Python 没有 ++c

i 取 0, 1, …, n−1，共 n 次，Θ(n)。

片段 2：i 每次乘 2

for (int i = 1; i <= n; i *= 2) ++c;
i = 1
while i <= n:                     # range 只能等差递增，i 翻倍要改写成 while
    c += 1
    i *= 2

i 依次取 1, 2, 4, …, 2^k，循环在 2^k ≤ n 时继续。设执行了 t 次，最后一次的 i = 2^(t−1) ≤ n，下一次 2^t > n，所以 t = ⌊log₂n⌋ + 1，Θ(log n)。

n = 20 时 i *= 2 循环执行几次

1 / 4

第1步 · 第 1 次：i = 1 ≤ 20

2 / 4

第2步 · 第 2、3 次：i = 2、4

3 / 4

第3步 · 第 4、5 次：i = 8、16

4 / 4

第4步 · i 变成 32 > 20，循环结束

共 5 次 = ⌊log₂20⌋ + 1 = 4 + 1

同理，i = i * 3 是 log₃n 次；while (i * i <= n) ++i; 在 i² > n 时停止，是 Θ(√n)，n = 100 时执行 10 次。

片段 3：内层上界依赖外层

for (int i = 0; i < n; ++i)
    for (int j = 0; j < i; ++j) ++c;
for i in range(n):
    for j in range(i): c += 1     # range(0) 为空：i = 0 时内层一次也不执行

i = 0 时内层 0 次，i = 1 时 1 次，……，i = n−1 时 n−1 次。总数 0 + 1 + … + (n−1) = n(n−1)/2，Θ(n²)。n = 5 时是 10 次，画出来正好是一个三角形：

行号是 i、列号是 j，打勾的格子是执行的 (i, j)：共 10 = 5×4/2 格，约为整个方阵的一半，仍是 n² 量级

三重依赖循环 for i in [0,n) for j in [i,n) for k in [j,n) 的次数是 n(n+1)(n+2)/6，n = 4 时为 20，Θ(n³)。

片段 4：外层翻倍、内层跟着外层

for (int i = 1; i <= n; i *= 2)
    for (int j = 0; j < i; ++j) ++c;
i = 1
while i <= n:                     # 外层翻倍，用 while
    for j in range(i): c += 1     # 内层次数就是 i
    i *= 2

外层只有 log n 次，但内层次数是 i 本身：总数 1 + 2 + 4 + … + 2^k，其中 2^k ≤ n。等比数列求和得 2^(k+1) − 1 < 2n，所以是 Θ(n)。n = 16 时 1+2+4+8+16 = 31。

对比片段 5：外层 n 次，内层每次都从 1 翻倍到 n。

for (int i = 0; i < n; ++i)
    for (int j = 1; j < n; j *= 2) ++c;
for i in range(n):
    j = 1                         # 内层翻倍，用 while；每轮外层都从 1 重新开始
    while j < n:
        c += 1
        j *= 2

内层每次 ⌈log₂n⌉ 次，与 i 无关，总数 n·⌈log₂n⌉，Θ(n log n)。n = 8 时 8 × 3 = 24。

两段代码都是"一层普通循环 + 一层翻倍"，区别在于内层次数是否依赖外层：依赖时要逐项求和，不依赖时直接相乘。

数循环的步骤：

  1. 找基本语句（最内层那条）。
  2. 写出外层每一轮里内层执行几次，记为 f(i)。
  3. 求和 Σ f(i)，常用三个公式：1+2+…+n = n(n+1)/2；1+2+4+…+2^k = 2^(k+1)−1；1+1/2+1/3+…+1/n ≈ ln n。
  4. 保留最高阶项。

要点：

  • 循环变量每次加减一个常数时，循环 n 次；每次乘除一个常数时，循环 log n 次；条件为 i*i ≤ n 时，循环 √n 次。
  • 内层循环的上界依赖外层变量时，要逐项求和：三角形求和 n(n−1)/2 的量级是 n²；等比数列求和不超过最后一项的 2 倍。
  • 内外层循环相互独立时，次数相乘。

13.12 递归的复杂度：递归树与主定理

递归代码没有显式的循环，没法直接数。我们先写出递推式，比如归并排序"把问题分成两半各自递归，再花 n 步合并"，写成 T(n) = 2T(n/2) + n，再用递归树或主定理求解。

递归树法：一层一层算代价

把每次递归调用画成一个节点，节点上写这次调用自己做的工作（不含子调用）。总代价 = 所有节点之和，通常按层求和最方便。

T(n) = 2T(n/2) + n 的递归树：

  • 第 0 层有 1 个节点，代价为 n；第 1 层有 2 个节点，各为 n/2，合计 n；第 2 层有 4 个节点，各为 n/4，合计 n。每一层的合计都是 n。
  • 规模每层减半，从 n 降到 1 需要 log₂n 次，所以共有 log₂n + 1 层。
  • 总代价为 n × (log₂n + 1) = Θ(n log n)。按 T(1) = 1 递推，n = 1024 时恰好得到 1024 × 11。

递归的空间复杂度 = 递归深度 × 每层的空间。 归并排序递归深度 log n，加上 O(n) 的辅助数组，空间 O(n)。斐波那契的朴素递归 fib(n) = fib(n−1) + fib(n−2) 调用树近似满二叉树，调用次数指数级（约 1.618ⁿ），但同一时刻栈上最多 n 层，空间 O(n)。

主定理

对形如 T(n) = a·T(n/b) + f(n)（a ≥ 1，b > 1）的递推式：问题分成 a 个子问题，每个规模 n/b，分解与合并花 f(n)。把 f(n) 与 n^(log_b a) 比较：

  1. 若 f(n) = O(n^(log_b a − ε))，某个 ε > 0（f 比 n^(log_b a) 小一个多项式因子），则 T(n) = Θ(n^(log_b a))。叶子层的工作占主导。
  2. 若 f(n) = Θ(n^(log_b a))（两者同阶），则 T(n) = Θ(n^(log_b a) · log n)。每层工作差不多，乘以层数。
  3. 若 f(n) = Ω(n^(log_b a + ε))，某个 ε > 0，并且存在 c < 1 使 a·f(n/b) ≤ c·f(n)（正则条件），则 T(n) = Θ(f(n))。根节点的工作占主导。

主定理就是比较“叶子层的总工作 n^(log_b a)”和“根节点的工作 f(n)”谁更大

T(n) = T(n/2) + 11, 2n⁰ = 112（同阶）Θ(log n)二分查找
T(n) = 2T(n/2) + n2, 2n¹n2（同阶）Θ(n log n)归并排序
T(n) = 7T(n/2) + n²7, 2n^2.81n²1（f 更小）Θ(n^2.81)Strassen 矩阵乘法

要点：

  • 用递归树分析时，把每层的代价求和再乘以层数；规模每次除以 b 时，层数为 log_b n。
  • 主定理比较 f(n) 与 n^(log_b a)：f(n) 较小时取后者；两者同阶时乘以 log n；f(n) 较大时取 f(n)。
  • 常用结论：二分查找为 Θ(log n)，归并排序为 Θ(n log n)，T(n)=T(n−1)+n 为 Θ(n²)，汉诺塔为 Θ(2ⁿ)。
  • 递归的空间复杂度等于最大递归深度乘以每层占用的空间。

13.13 最好、最坏、平均与均摊：同一个算法的四种账

同一个算法，输入不同，步数可能差很多。快速排序平时 n log n，遇到有序数组却退化到 n²；动态数组 push_back 大部分时候 O(1)，偶尔要搬全部元素。复杂度要说清是哪一种情况。

四种分析

  • 最好情况：对所有规模为 n 的输入，步数的最小值。
  • 最坏情况：步数的最大值。它给出保证，所以默认说复杂度时指最坏情况。
  • 平均情况：在给定的输入概率分布下，步数的期望值。
  • 均摊（摊还）：对一串连续操作求总代价，再平均到每次操作上。它不依赖概率，保证的是"任意一串 n 次操作的总时间"。

顺序查找（长度 n，从头找）：目标在第一个位置时比较 1 次，最好 O(1)；在最后或不存在时比较 n 次，最坏 O(n)；若目标一定存在且等可能出现在每个位置，平均比较 (1 + 2 + … + n)/n = (n+1)/2 次，平均 O(n)。

均摊分析：动态数组为什么是 O(1)

单次代价偶尔出现尖峰（复制全部元素），但平均代价始终在 3 以下

为什么平均不超过 3？ n 次追加中，写入共 n 次；复制总数 = 1 + 2 + 4 + … ≤ 最后一次容量 < 2n。总代价 < 3n，平均每次 < 3，所以均摊 O(1)。触发扩容的那一次本身是 O(n)，所以单次最坏仍是 O(n)。

换一个角度理解（记账法）：每次追加"预付" 3 个硬币，1 个付自己的写入，2 个存起来；容量从 m 扩到 2m 时，后加入的 m/2 个元素攒下了 m 个硬币，正好够复制 m 个旧元素。

如果每次只扩容固定的 10 个格子，复制总数是 10 + 20 + 30 + … ≈ n²/20，均摊 O(n)。所以按倍数扩容是均摊 O(1) 的关键，倍数取 1.5（Java ArrayList）或 2 都可以。

代码：模拟扩容代价

size 是当前元素个数；cap 是当前容量；c 是本次追加的代价；cost 记录每次的代价。

vector<int> appendCosts(int n) {
    vector<int> cost;
    int size = 0, cap = 1;
    for (int k = 1; k <= n; ++k) {
        int c = 1;                    // write the new element
        if (size == cap) {            // full: copy every old element first
            c += size;
            cap *= 2;
        }
        ++size;
        cost.push_back(c);
    }
    return cost;
}
def append_costs(n):
    cost = []
    size, cap = 0, 1                  # 自己模拟容量；Python list 内部也按比例扩容，但不暴露 cap
    for k in range(1, n + 1):         # k = 1..n
        c = 1                         # write the new element
        if size == cap:               # full: copy every old element first
            c += size
            cap *= 2
        size += 1
        cost.append(c)
    return cost

appendCosts(16) 返回上面那 16 个数；n = 10⁵ 时，总代价也小于 3n。

要点：

  • 没有特别说明时，复杂度指最坏情况；平均复杂度需要给出输入的概率分布；均摊分析对一串操作计算总代价。
  • 顺序查找最好 O(1)，最坏 O(n)，成功查找的平均比较次数是 (n+1)/2。
  • 动态数组在尾部追加元素的均摊复杂度为 O(1)，单次最坏为 O(n)，前提是按倍数扩容。
  • 快速排序最好和平均 O(n log n)，最坏 O(n²)。

  • 均摊是对一串操作的总代价求平均，平均情况是对输入分布求期望，两者的前提不同。

13.15 P、NP 与 NP 完全：哪些问题可能有高效算法

前面都在分析"某个算法要多少步"。还有一个更大的问题：对某些问题（如旅行商问题），至今没人找到多项式时间的算法，这是我们不够聪明，还是这类问题本身就难？面试常问"什么是 NP 完全""P 和 NP 有什么区别"，回答到下面的深度就够了。

判定问题与多项式时间

复杂度理论先研究判定问题：答案只有"是 / 否"。例如"图中是否存在一条长度不超过 K、经过每个城市恰好一次并回到起点的路线？"这样"是"的答案可以被核对。输入规模 n 指输入编码的长度（多少位）。

一个算法如果最坏运行时间不超过 n^k（k 是与输入无关的常数），就叫多项式时间算法。这里的"算法"指普通计算机那样每一步只做一件确定动作的程序，理论上用确定型图灵机来刻画。n、n log n、n³ 都是多项式时间；2ⁿ、n! 不是。

四个类别

  • P：存在多项式时间算法求解的判定问题。例：排序后判断、最短路是否 ≤ K、图是否连通。
  • NP：对每个答案为"是"的实例，存在一个证书（候选解），能在多项式时间内验证它确实正确。例：子集和问题"是否存在一组数和为 S"，有人给出一组数，我们加一遍就能核对。P 中的问题直接求解一遍就算验证，所以 P ⊆ NP。

要定义"最难"的问题，先要能比较两个问题的难度，这就是归约。

归约（多项式时间归约）：如果能在多项式时间内，把问题 A 的任意实例 x 改写成问题 B 的实例 f(x)，并且 x 的答案为"是"当且仅当 f(x) 的答案为"是"，就说 A 可以归约到 B，记作 A ≤ₚ B。它的含义是：只要会解 B，就能解 A（先改写，再调用 B 的解法），所以 B 至少和 A 一样难。

A ≤ₚ B：A 借用 B 的解法得到答案。B 若有多项式算法，A 也有

有了归约，就可以定义：

  • NP-hard（NP 难）：NP 中每一个问题都能多项式归约到它。它至少和 NP 中最难的问题一样难，本身不要求属于 NP（例如旅行商的优化版"最短路线是多少"）。
  • NP-complete（NP 完全，NPC）：既属于 NP，又是 NP-hard。它们是 NP 中最难的一批问题。

NP 完全 = NP ∩ NP-hard。若任何一个 NP 完全问题有多项式算法，则 P = NP

怎样证明一个新问题 B 是 NP 完全的。 分两步：第一步，证明 B ∈ NP，即给出证书，并说明能在多项式时间内验证它；第二步，找一个已知的 NP 完全问题 A，构造归约 A ≤ₚ B。归约的方向是从已知的难题归约到新问题。第一个被证明为 NP 完全的问题是 SAT（布尔可满足性问题，Cook–Levin 定理），之后的 NP 完全问题都是从它出发逐步归约得到的。

伪多项式时间

0/1 背包的动态规划是 O(nW)，W 是背包容量。看起来是多项式，但输入里 W 只用 log₂W 位存储：W = 10⁹ 只占 30 位，DP 表却有 10⁹ 列。用输入长度 L ≈ log₂W 表示，nW = n·2^L，对输入长度是指数级的。这种"对输入的数值是多项式、对输入的长度是指数"的算法叫伪多项式时间算法，O(nW) 的背包 DP 就是伪多项式时间算法。所以它和"0/1 背包（判定版）是 NP 完全"并不矛盾：当 W 较小时 DP 很快，W 很大时依然困难。

要点：

  • P 是能在多项式时间内求解的问题，NP 是能在多项式时间内验证解的问题；P ⊆ NP，P 是否等于 NP 是尚未解决的问题。
  • 归约 A ≤ₚ B 的含义是：会解 B 就会解 A，所以 B 至少和 A 一样难。
  • 所有 NP 问题都能归约到的问题叫 NP-hard；NP 完全问题就是既属于 NP、又是 NP-hard 的问题。
  • 标准答案：“NP 完全问题是 NP 中最难的问题，目前没有已知的多项式时间算法；只要其中一个有多项式算法，所有 NP 问题都有，即 P = NP。”
  • 背包问题的 O(nW) 算法是伪多项式时间的：它对数值 W 是多项式的，对 W 的二进制位数却是指数的。

多选 · 理解检查 17　关于 P、NP 与 NP 完全，哪些说法正确？

A. 所有 P 问题都属于 NP

B. NP 的含义是“非多项式”（Non-Polynomial）

C. 已知 A 是 NP 完全，A ≤ₚ B，且 B ∈ NP，则 B 是 NP 完全

D. 0/1 背包的 O(nW) 动态规划说明背包问题属于 P

查看答案与每个选项的解析

A · 正确：能在多项式时间求解，就能在多项式时间验证一个候选解。

B · 错误：NP 是 Nondeterministic Polynomial，指多项式时间可验证，而且 P 包含于 NP。

C · 正确：A ≤ₚ B 说明 B 至少和 A 一样难，因而是 NP-hard；再加上 B ∈ NP，就是 NP 完全。

D · 错误：O(nW) 是伪多项式：W 用 log W 位存储，nW 对输入长度是指数级。

易错点：

  • 证明 B 是困难问题时，归约的方向是从已知难题 A 到新问题 B（A ≤ₚ B）；反方向的归约只能说明 B 不比 A 难。
  • NP-hard 问题可以不属于 NP（如优化版的 TSP、停机问题），只有同时属于 NP 的才叫 NP 完全。
  • “目前没有已知的多项式算法”与“已证明不存在多项式算法”是两回事，后者等价于证明了 P ≠ NP。

小结： P 类问题能快速求解，NP 类问题能快速验证，P ⊆ NP；归约 A ≤ₚ B 表示 B 不比 A 简单；NP 完全等于 NP 与 NP-hard 的交集；背包问题的 O(nW) 算法是伪多项式时间的。
