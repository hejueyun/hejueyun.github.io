2.1. 4.1 IR 的基础：irep2 与 expr2tc

在揭开 GOTO 程序的盒子之前，我们必须先聊一聊所有 IR 的最小公分母——
表达式（expression）和类型（type）。
ESBMC 的 GOTO 指令、symex 的 SSA 步骤、SMT lowering 的输入，
统统是用同一套对象表示的：expr2tc 和 type2tc。
读懂它们，就掌握了 ESBMC 的”通用货币”。

2.1.1. 4.1.1 两份遗产：CBMC 的 irept 与 ESBMC 的 irep2

ESBMC 最初 fork 自 CBMC，因此继承了 CBMC 那套字符串式的 irep（src/util/irep.h）。
打开它你会看到：

irept 是个极度通用的树节点。它通过一个字符串 id（如 "+"、"if"、"symbol"）标识自己的种类，
通过 subt（一个 vector<irept>）保存位置型操作数，
通过 named_subt（一个 map<string, irept>）保存命名属性（比如 "type"、"identifier"、"value"）。

这套设计的优点是惊人地通用：新增一种表达式不需要改类层次结构，
只要约定好它的字符串 id 和它需要哪些子节点 / 命名属性就够了。
缺点也同样明显：

  1. 类型检查全在运行时——所有”取这个 expr 的左操作数”都要去 subt[0] 取，
    编译器没法帮你检查这个表达式是不是真的二元运算。
  2. 字段名是字符串——拼写错误（"idntifier"）只能在运行时炸。
  3. 每次属性访问都要经过哈希表——慢。
  4. 没有显式枚举——想做 switch over kinds 必须比对字符串。

CBMC 的策略是把这套通用结构沿用到底；
ESBMC 在 2013 年左右意识到 symex 阶段这种用法实在太频繁，
于是新写了一套强类型版本叫 irep2，存在 src/irep2/ 下。
从此 ESBMC 内部有两套并存的 IR：

  • exprt / typet——基于 irept 的字符串式遗产，
    存在于 src/util/std_expr.h、src/util/std_code.h，
    目前仅前端在用（clang frontend 解析出 AST 时构造这类对象）。
  • expr2tc / type2tc——基于 irep2t 的强类型版本，
    ESBMC 中间件与后端的整个工作流（GOTO 程序、symex、SMT lowering）都建立在它之上。

两套之间用一组 migrate_expr / migrate_type 函数双向转换——前端产出 exprt，
进入 GOTO 转换时被 迁移 成 expr2tc，然后一去不返。

2.1.2. 4.1.2 expr2t / type2t：强类型 + 共享 + 元编程

这套设计的几个关键属性：

  • 每个 expr2t 子类都自带强类型字段。add2t 一眼看出有两个 expr2tc 操作数，

类型层（type2t）的设计完全平行：枚举 type_ids 列出所有种类（bool、empty、struct、array、pointer、unsignedbv、signedbv、fixedbv、floatbv…），每种类型也是一个独立的 C++ 类。

  • 多处共享同一个表达式不增加内存代价。

  • 写时复制（COW）：在确需修改时，调用 expr->Foreach_operand([](expr2tc &op){ ... }) 这类接口
    会触发先 clone 再改的语义；或者用 simplify(expr) / 各种 utility 函数构造新的 expr2tc 替换它。

2.1.5. 4.1.5 类层次结构总览

四层结构：

  1. irep2t —— 顶层基类，提供 enable_shared_from_this；
  2. expr2t / type2t —— 表达式与类型两条平行基类，
    持有 id 枚举、type 字段（仅 expr）、几个虚函数（do_simplify、clone、hash）；
  3. _data / _expr_methods mix-in —— 由元编程模板生成，
    按”字段个数 + 字段类型”批量给出 hash / equality / clone 等实现；
  4. 具体类（add2t、symbol2t、code_assign2t …） —— 在 irep2_expr.h 中各占几十行，
    构造函数把字段传给上层 mix-in 即可。

每个具体类都不到 30 行代码——绝大部分功能由元编程自动产出。
新增一种表达式的成本：在 ESBMC_LIST_OF_EXPRS 加一行 + 写一个十几行的类。

2.1.6. 4.1.6 与 GOTO IR 的接缝

回到 GOTO 程序。再看一眼 instructiont（src/goto-programs/goto_program.h:88）的字段：

code 和 guard 都是 expr2tc——
也就是说整个 GOTO 程序的”语义负载”都驻留在 expr2tc 子树里。
一条 ASSIGN 的 code 是一个 code_assign2t，
内部嵌套两个 expr2tc（lhs、rhs）；
一条 GOTO 的 guard 直接是一个 expr2tc 布尔表达式；
一条 FUNCTION_CALL 的 code 是 code_function_call2t，里头有函数表达式、返回左值、参数列表……

由此 GOTO IR 本质上 = GOTO 控制流骨架（指令序列 + 跳转目标） + expr2tc 数据流子树。
前者负责”程序怎么走”，后者负责”算什么”。

2.1.7. 4.1.7 为什么这样设计：背后的取舍

回头看这套架构，背后的几个工程权衡值得点破：

  • 共享 + 不可变 → 复制廉价。
    symex 主循环每遇到一次分叉，整个 state（包括 value-set、L2 表里成千上万个 expr2tc 引用）需要被克隆一份。
    如果 expr 是可变对象，必须深拷贝；用共享指针 + 不可变约定，复制成本仅相当于把指针引用计数加 1。
    这是 ESBMC 在大型程序上”还能跑得动”的关键基础设施决定。
  • 强类型 + enum dispatch → 后续编译期检查与高速分派。
    symex 在 dispatch GOTO 指令、SMT 后端在 dispatch 100+ 种 expr_ids，
    全部是 switch(expr_id)——既快又安全。
  • 元编程而非继承爆炸。
    100 多个表达式种类如果靠手写，光是 hash 函数就要打几千行；
    用 _data / _expr_methods mix-in 自动派生后，每种 expr 只剩”声明字段”的责任。
  • 保留旧 exprt 作为前端语言。
    Clang frontend 这种”AST 解析”层用旧 irept 更舒服：能自由附加属性、不用预先穷举种类。
    在前端 → GOTO 的边界一次性 migrate_expr 转成 expr2tc，
    从此 ESBMC 内部就只跟强类型 IR 打交道。

这种”前端宽松、中端严格”的双层设计在编译器领域并不少见——
LLVM 用 Clang AST 做前端、用 LLVM IR 做中端；
ESBMC 用 CBMC exprt 做前端、用 expr2tc 做中端。
不同的是 ESBMC 把”中端 IR”同时也用作”后端 IR”——
SMT lowering 直接吃 expr2tc，没有再低一层的中间表示。
这是 ESBMC 与传统编译器最大的差别之一。

小结：expr2tc 是 ESBMC 的通用 IR 货币。
强类型、共享、不可变的设计让它能高效承载从 GOTO 程序到 SMT 公式的全部数据流；
旧的 exprt 还在前端使用，但在进入中端时一次性被 migrate_expr 翻译过来。
理解这套基础设施后，后面几节里反复出现的 is_symbol2t、to_code_assign2t、expr->Foreach_operand 就不再神秘。

2.2. 4.2 IR 形态：goto_programt / instructiont / 指令枚举

ESBMC 的”中间形态”叫 GOTO 程序，这个名字来自它最显著的特征：
所有的高级控制流都被还原成基本块 + GOTO 跳转。
没有 while，没有 for，没有 switch——只有”按条件跳到那条指令去”。

  • 没有任何 while / if 等高级语义——只有跳转和顺序执行。
  • 数组下标 a[i] 之前自动多了一条 ASSERT 0 ≤ i < N：这是 4.4 节会讲的属性插桩。
  • 原本的用户 assert(sum >= 0) 也变成一条 ASSERT，
    与系统插桩的断言完全同质——后续 symex 与 SMT 不会区分它们。

2.6. 4.6 抽象解释：interval analysis

到目前为止 ESBMC 看起来全是”精确推理”：symex 把每个赋值都写成 SSA、丢给 SMT 一个不漏地求解。
但 SMT 不是免费的——公式越冗余、变量取值越宽，求解时间越糟糕。
如果在送进 symex 之前就预先算出”x 在这里一定属于 [0, 99]”，
就能在 SMT 公式里少掉一大堆”越界路径”的可能性。

这正是 interval analysis（区间分析） 的用途。
它是 ESBMC 里唯一成熟的抽象解释（abstract interpretation）实例，
住在 src/goto-programs/abstract-interpretation/ 这个独立目录里，
约 7000 行代码。
启用方式是命令行 --interval-analysis（或被 --goto-contractor 间接打开），
入口在 esbmc_parseoptions.cpp:2236。

2.6.1. 4.5.1 抽象解释的两个基本承诺

抽象解释是 Cousot 夫妇 1977 年提出的经典框架。一句话概括：

用”近似的、可计算的状态”代替”精确的、不可计算的状态”，
并保证近似永远是程序真实行为的超集（over-approximation）。

区间是最简单的抽象状态：每个变量被记成一个区间 [lo, hi]，
而不是它在某条具体路径上的精确值。
两个承诺随之而来：

  • Sound（可靠）：如果区间分析说 x ∈ [0, 99]，那程序所有可能执行中 x 都不会超出这个范围。
  • Imprecise（不精确）：可能给出比真实情况更宽的区间，
    例如真实情况是 x ∈ {0, 3, 7} 而分析得到 [0, 7]。

这种”宁可放宽，绝不漏报”的姿态正适合作为 BMC 的前置加速器：
区间永远是真实路径的子超集，所以基于它做的化简（删除明显走不到的 GOTO 分支、
把 assert(x < 200) 变成 assert(true)）一定保留语义。

if (x < 10) ... then 分支{x ↦ [5,5]}条件被 assume 但已包含
x++; 后{x ↦ [6,6]}区间加 1
与 else 分支合流{x ↦ [5,5]}两支并集

2.6.4. 4.5.4 transform：每种指令如何更新区间

transform（interval_domain.cpp:913）就是抽象语义的”传译器”——
拿一条 GOTO 指令、当前 state，算出下一个 state：

四件最关键的工作：

  • havoc_rec(expr)（interval_domain.cpp:1247）—— “弄脏”。把表达式里出现的所有符号从 intervals 中删除，
    让它们退回 TOP。新声明变量、*p = ... 这种没法精确追踪的赋值、函数返回时的参数清理都走这条。

  • assign(code_assign)（interval_domain.cpp:1220）—— 计算 RHS 的区间，把它赋给 LHS。
    如果 LHS 是 dereference（写到指针指向的对象），直接 clear_state()——保守地把整张表清空。

  • assume(expr)（interval_domain.cpp:1333）—— 把 expr 当真值假设，收紧相关变量的区间。
    比如 assume(x < 10) 会把 x 的上界压到 9；如果原区间已经超出，结果可能变 ⊥（不可达）。

  • GOTO 分叉——同一个 GOTO 指令在 transformer 里对应两条边：

    • 跳走那条边：把 guard 当 assume；
    • 不跳那条边：把 ¬guard 当 assume。

    正是这一步让区间分析能在 if (x < 10) 的 then/else 两侧得到不同的 x 区间。

2.6.5. 4.5.5 widening（外推）与 narrowing（收敛）

抽象解释最微妙的部分是循环。
朴素的不动点迭代在循环里可能要走 n 次才收敛——for(int i=0; i<10000; i++) 就要迭代一万次。
更糟糕，无界循环根本不会收敛：

第 1 次：i ∈ [0,0]；第 2 次：[0,1]；第 3 次：[0,2]……永远不停。

经典的解药是 widening（拓宽/外推）：
当检测到区间在单调增长，直接把不动的那一端推到无穷：

在 ESBMC 中（interval_domain.cpp:1067 的 join_intervals + 私有函数 extrapolate_intervals），
每次 join 时如果检测到上界单调上升，就把上界推到 +∞。
迭代 2 次就能从 [0,0] 跳到 [0,+∞]，立刻不动点。

但这样精度损失太大。 narrowing（收敛/内插） 接着把精度找回来——
利用循环条件 i < 10，从 [0,+∞] 收敛回 [0,9]。
ESBMC 的 narrowing 当前因为 #1738 bug 暂时禁用（见 interval_domain.cpp:1140），
但 widening 启用方式是 --interval-analysis-extrapolate，
最大迭代数由 --interval-analysis-extrapolate-limit（默认 5）控制。

2.6.6. 4.5.6 分析完成之后：化简 + 插桩

不动点收敛后，每条指令前都有了一个 interval_domaint。interval_analysis() 用这份信息做两件事：

(1) 表达式化简（optimize_function / optimize_expression，interval_analysis.cpp:50）：
遍历每条指令的 code 与 guard，对每个子表达式：

  • 如果区间是单点（[k,k]），把整个子表达式替换成常量 k——常量传播。
  • 如果是布尔类型且区间不含 0，替换成 true；
  • 如果是布尔类型且区间恰好是 [0,0]，替换成 false。

随后调一次 simplify(expr) 让代数化简捡走剩下的便宜。

(2) 区间插桩（instrument_intervals，interval_analysis.cpp:190）：
把”x ∈ [a,b]”这样的事实编码成一条 ASSUME (x >= a && x <= b)，
插到 GOTO 程序中合适的位置。
插桩模式由 INTERVAL_INSTRUMENTATION_MODE 枚举（interval_analysis.h:10）控制：

枚举值行为
NO_INSTRUMENTATION只化简、不插桩
ALL_INSTRUCTIONS_FULL每条指令前插完整函数符号集的区间约束
ALL_INSTRUCTIONS_LOCAL每条指令前只插与该指令相关的变量
GUARD_INSTRUCTIONS_FULL只在 GOTO/ASSUME/ASSERT 前插，但插完整集合
GUARD_INSTRUCTIONS_LOCAL同上但只插局部相关变量（默认）
LOOP_MODE走 instrument_loops，给每个循环的入口/体内/出口前后都插一条

默认 GUARD_INSTRUCTIONS_LOCAL 是 性能与精度 的折中：
只在控制流分叉处（决定路径的关键点）告诉 symex”这些变量在这里只可能落在这个区间里”，
让 symex 早点剪掉不可达分支，避免冗余的 SMT 公式。

instrument_symbol_constraints（interval_analysis.cpp:107）是真正插指令的函数。
看它的核心几行：

make_expression（interval_domain.cpp:1516）把区间渲染回 expr2tc：
对 x ∈ [2, 42] 它返回 AND(x >= 2, x <= 42)，对 TOP 返回 true，对 ⊥ 返回 false。
得到的 ASSUME 指令插在原指令的位置，原指令向后挪一个槽。

2.6.7. 4.5.7 online 模式：symex 边跑边问区间

除了”分析完一次性插桩”的离线模式，
interval_domaint 还能在 symex 阶段被实时调用——
入口是 process_instruction（interval_domain.cpp:1590）：

symex_step 每跑一条指令都调一次这个函数（命令行 --interval-symex-guard / --interval-symex-assert 启用），
然后用 interval_domaint::eval_boolean_expression 检查”这条 GOTO 的 guard 是不是恒真/恒假”——
是的话直接关闭这条路径，省掉一次分叉。
这就是 Symex 篇 §5.5 中我们曾经一闪而过提到的”基于区间域的守卫裁剪”。

小结：interval analysis 给 ESBMC 提供了一只”先验眼镜”。
它用经典的工作集 + 不动点 + widening 算法在 GOTO 层先把变量区间算出来，
再以化简 + ASSUME 插桩两种方式把信息回灌给 symex 与 SMT。
它不是 ESBMC 的核心 证明 引擎——一切结论最终都靠 SMT 验证——
但它是让 ESBMC 在循环、多分支、大型程序上”跑得动”的关键加速器。

2.7. 4.7 GOTO 二进制：编译与验证分离

GOTO 程序可以序列化成 goto-binary 文件（.goto 扩展），
将”编译”与”验证”解耦。

  • write_goto_binary（src/goto-programs/write_goto_binary.cpp:8）—— 写出。
  • goto_binary_reader（src/goto-programs/goto_binary_reader.h:25）—— 读入。
  • 文件格式：魔数 GBF + 版本号 + 符号表 + 各函数体。

工程上的意义有两点：
(1) 大型工程可以分模块预编译成 .goto，最后合并；
(2) 同一份 .goto 可以用不同 --unwind、不同求解器反复跑实验，无需重新解析源代码。

小结：本章铺好了 ESBMC 中端的地基与骨架——
expr2tc 提供强类型、共享、不可变的通用表达式 IR；
GOTO 程序在这之上拼出”控制流骨架 + 数据流子树”；
goto_check 把语言层面的隐含假设变成显式 ASSERT；
interval analysis 用抽象解释先给变量框个范围加速后续推理。
一切就绪后，下一章我们把这堆 GOTO 指令”喂”给符号执行引擎。
