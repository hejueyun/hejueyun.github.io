16.1 散列函数：把关键字直接换算成下标 必读

在 10 万个账号里找一个账号，顺序查找要比较几万次，二分查找也要十几次。如果能由账号直接算出它存放的位置，一次就能找到。散列表（hash table，也叫哈希表）就是按这个想法设计的：用一个函数把关键字换算成数组下标，查找时再算一遍，直接去那个位置取。

散列函数 H(key) 把关键字映射到 0～m−1 之间的整数，m 是表长（数组的格数），每一格叫一个槽或桶。最常用的是除留余数法：

H(key) = key mod p，p 取不超过表长 m 的最大质数。

两个不同的关键字算出同一个地址，叫冲突（collision），这些关键字互称同义词。冲突无法完全避免：关键字的可能取值远多于槽数，总有一些会挤到同一格。所以设计散列表要回答两个问题：散列函数怎么选，才能让关键字分布均匀；冲突发生后，第二个关键字放到哪里（下一节）。

散列函数把关键字换算成下标；41 和 30 算出同一个下标 8，这就是冲突

为什么 p 要取质数。 实际数据常带有规律，比如订单号都是 4 的倍数、价格都以 0 结尾。如果 p 和这些规律有公因子，余数只会落在少数几个值上，其余的桶永远空着，冲突集中爆发。质数除了 1 和自身没有别的因子，和数据里的规律"对不上"，余数就分散得开。下表用 8 个 4 的倍数做对比：

关键字都是 4 的倍数：除以 12 只落进 0、4、8 三个桶；除以质数 11 落进 8 个不同的桶

除以 12 时，12 和 4 有公因子 4，余数只能是 0、4、8，8 个关键字挤进 3 个桶；除以 11 时，8 个关键字各占一个桶，完全没有冲突。

其他散列函数（了解名字即可）。 直接定址法 H(key)=a·key+b，没有冲突，但关键字范围大时浪费空间；数字分析法取关键字中分布均匀的几位；平方取中法取 key² 的中间几位；折叠法把关键字分段相加。笔试最常考的是除留余数法。

要点：

  • 除留余数法 H(key)=key mod p，p 取不大于表长 m 的最大质数。
  • 冲突只能减少、无法避免；好的散列函数让关键字均匀分布、计算简单。
  • 散列表查找的效率取决于三件事：散列函数、冲突处理方法、装填因子（16.3）。

练习 16.1-3【综合】冲突什么时候一定发生

题面：表长 m=7，H(key)=key mod 7。(1) 最多插入几个关键字，仍有可能完全不冲突？插入第几个时一定发生冲突？(2) 设每个关键字的地址等可能地落在 0～6 且相互独立，插入 3 个关键字时完全不冲突的概率是多少？插入 5 个时呢？

提示

(1) 用抽屉原理。(2) 第 1 个关键字随便放；第 2 个要避开 1 个已占的地址，概率 6/7；第 3 个要避开 2 个……把这些概率相乘。

参考答案

(1) 7 个地址最多容纳 7 个互不冲突的关键字。插入第 8 个时，8 个关键字分到 7 个地址，必有两个地址相同，一定冲突。

(2) 3 个不冲突的概率 = 7/7 × 6/7 × 5/7 = 210/343 ≈ 0.612。5 个不冲突的概率 = (7×6×5×4×3)/7⁵ = 2520/16807 ≈ 0.150。表只装到 5/7 时，"一次冲突都没有"的可能只剩 15%，所以任何散列表都必须配一种冲突处理方法。

易错点： p 取"不大于 m"的质数；取比 m 大的质数，算出来的下标会越界。

小结： 除留余数法取 H=key mod p，p 取不大于表长 m 的最大质数；质数与数据中的规律没有公因子，余数才会分散。

16.2 处理冲突：开放定址法与链地址法 必读

上一节的 41 和 30 都算到下标 8。41 先来占了位，30 来了怎么办？两大类做法：在表内另找一个空槽（开放定址法），或者让同一个下标挂一串元素（链地址法）。

本节和下一节用同一组数据：

关键字依次为 22、41、53、46、30、13、1、67，表长 m=11，H(key)=key mod 11。 散列地址分别是 0、8、9、2、8、2、1、1。

开放定址法：沿探测序列找空槽

冲突时按一个固定的增量序列 d₀=0, d₁, d₂, … 依次尝试地址 Hᵢ=(H(key)+dᵢ) mod m，直到找到空槽。增量序列决定了方法：

方法增量 dᵢ特点
线性探测0, 1, 2, 3, …逐格向后找，到表尾绕回表头；容易让元素连成一片，产生堆积
二次探测（平方探测）0, 1², −1², 2², −2², …跳着找，减轻堆积；表长取形如 4k+3 的质数时能探到所有槽
双重散列i × H₂(key)用第二个散列函数算步长；步长与 m 互质才能探遍全表
伪随机序列一串伪随机数例如 CPython 的 dict 使用伪随机探测 [1]

链地址法：同义词挂在一条链上

链地址法（拉链法）的表里每格存一个链表头指针，散列地址相同的关键字都挂在这条链上。插入时我们约定尾插（新结点接在链尾），这也是多数教材画图的方式。

链地址法：下标 1、2、8 各挂 2 个结点（尾插），下标 0、9 各 1 个，其余 6 个桶为空

链地址法没有堆积：只有真正的同义词才会在同一条链上，30 不会去占 9 号桶的位置。代价是每个结点多一个指针。Java 的 HashMap 采用链地址法（JDK 8 起链太长时还会转成红黑树）。

要点：

  • 开放定址法：Hᵢ=(H(key)+dᵢ) mod m。线性探测 dᵢ=i，二次探测 dᵢ=0, 1², −1², 2², −2², …
  • 线性探测会产生堆积：非同义词之间也会争夺同一个地址；二次探测、双重散列可以减轻堆积。
  • 链地址法把同义词存在同一链表中，没有堆积，装填因子可以大于 1。

16.3 平均查找长度 ASL：成功与失败怎么数 必读

散列表"理想中 O(1)"，但有冲突就要多比较几次。笔试用平均查找长度 ASL（Average Search Length，平均要和多少个关键字比较）衡量实际效率，并且分成查找成功、查找失败两种情况出题。这是本章最常考的计算题。

我们采用 408 和多数国内教材的约定：

  • ASL 成功 = 每个已存关键字"查到它所需的比较次数"之和 ÷ 关键字个数 n。某个关键字的比较次数，等于当初插入它时探测的格子数。
  • ASL 失败 = 对每一个可能的散列地址（0～p−1，共 p 个），从该地址开始一直比较到遇见空槽所需的次数之和 ÷ p。开放定址法中，和空槽的那一次比较也计入。

失败的分母是 p（散列函数能算出的地址个数），这一点和表长 m 无关。本例 p=m=11，两者相同。

成功：把上一节每次插入的比较次数列出来。

失败：从地址 h 出发，要和这条链上的每个结点都比一次才能确认不存在。链长依次为 1、2、2、0、0、0、0、0、2、1、0，ASL 失败 = 8/11 ≈ 0.73（按 408 约定，与空指针的比较不计）。

装填因子决定 ASL

装填因子 α = 表中记录数 n / 表长 m，表示表"装得有多满"。本例 α=8/11≈0.73。对分布均匀的散列函数，教材给出下面的近似公式：

方法ASL 成功ASL 失败
线性探测½ (1 + 1/(1−α))½ (1 + 1/(1−α)²)
链地址法1 + α/2α

代入 α=0.5：线性探测成功 1.5 次、失败 2.5 次；链地址法成功 1.25 次。α=0.9 时，线性探测失败要约 50.5 次，链地址法成功只要 1.45 次。

α 过了 0.7，线性探测的平均比较次数开始陡升；链地址法几乎是一条斜率 1/2 的直线

公式里只出现 α，这就是标准答案句的来源。小例子算出的 ASL 和公式值有偏差，因为公式描述的是"大量随机关键字的平均情况"。

标准答案：

  • 散列表的平均查找长度依赖于装填因子 α，而不直接依赖于 n 或 m。 α 越大，冲突越多，ASL 越大。
  • ASL 成功的分母是关键字个数 n；ASL 失败的分母是散列函数可能的地址个数 p。
  • 开放定址法算失败次数时，与空槽的比较算一次；链地址法只数与关键字的比较。
  • 同一组数据，线性探测的失败 ASL 通常最大，原因是堆积。

const int EMPTY = -1;     // 从未用过
const int TOMB = -2;      // 墓碑：删除过，查找要跨过去

struct LinearTable {
    vector<int> slot;     // 表本身，存关键字或 EMPTY / TOMB
    int p;                // 除留余数法的除数 H(k) = k % p
    LinearTable(int m, int p_) : slot(m, EMPTY), p(p_) {}

    // 插入 k，返回比较次数（= 探测到的位置个数）
    int insert(int k) {
        int m = slot.size(), i = k % p, cnt = 1;
        while (slot[i] >= 0) { i = (i + 1) % m; ++cnt; }
        slot[i] = k;
        return cnt;
    }
    // 查找 k：返回 {是否找到, 比较次数}。遇到 EMPTY 才停，TOMB 继续向后
    pair<bool, int> find(int k) const {
        int m = slot.size(), i = k % p, cnt = 1;
        for (int step = 0; step < m; ++step) {
            if (slot[i] == EMPTY) return {false, cnt};
            if (slot[i] == k) return {true, cnt};
            i = (i + 1) % m; ++cnt;
        }
        return {false, cnt - 1};
    }
};

// 失败 ASL 的分子：对每个散列地址 0..p-1，一直比到空位（空位那次也算）
int failTotal(const LinearTable& t) {
    int m = t.slot.size(), s = 0;
    for (int h = 0; h < t.p; ++h) {
        int i = h, cnt = 1;
        while (t.slot[i] != EMPTY) { i = (i + 1) % m; ++cnt; }
        s += cnt;
    }
    return s;
}
EMPTY = -1     # 从未用过
TOMB = -2      # 墓碑：删除过，查找要跨过去

class LinearTable:
    def __init__(self, m, p):
        self.slot = [EMPTY] * m   # 表本身，存关键字或 EMPTY / TOMB
        self.p = p                # 除留余数法的除数 H(k) = k % p

    # 插入 k，返回比较次数（= 探测到的位置个数）
    # 注意：Python 的 % 结果和除数同号，负关键字也落在 0..p-1；C++ 的 % 对负数会得到负下标
    def insert(self, k):
        m, i, cnt = len(self.slot), k % self.p, 1
        while self.slot[i] >= 0:
            i = (i + 1) % m; cnt += 1
        self.slot[i] = k
        return cnt

    # 查找 k：返回 (是否找到, 比较次数)，用元组代替 pair。遇到 EMPTY 才停，TOMB 继续向后
    def find(self, k):
        m, i, cnt = len(self.slot), k % self.p, 1
        for step in range(m):
            if self.slot[i] == EMPTY: return (False, cnt)
            if self.slot[i] == k: return (True, cnt)
            i = (i + 1) % m; cnt += 1
        return (False, cnt - 1)

# 失败 ASL 的分子：对每个散列地址 0..p-1，一直比到空位（空位那次也算）
def fail_total(t):
    m, s = len(t.slot), 0
    for h in range(t.p):
        i, cnt = h, 1
        while t.slot[i] != EMPTY:
            i = (i + 1) % m; cnt += 1
        s += cnt
    return s

16.4 删除、装填因子与扩容 选读

散列表要支持删除，还要在元素越来越多时保持高效。开放定址法里，一个槽同时承担着"存元素"和"告诉后来者继续往后找"两个作用，删除时如果只考虑第一个作用，就会把查找链切断。

墓碑删除。 在开放定址法中删除一个元素，我们把那个槽标记为墓碑（删除标记）而清空它：

  • 查找时遇到墓碑继续往后探测，遇到真正的空槽才停；
  • 插入时，确认表中没有这个关键字之后，可以复用路上遇到的第一个墓碑位置。

扩容与 rehash。 装填因子 α 太大时，ASL 迅速上升（见 16.3 的曲线）。常见做法是给 α 设一个阈值（Java HashMap 默认 0.75），超过后申请一张更大的表，把旧表中每个元素用新表长重新计算地址再插入，这个过程叫 rehash（重散列）。[2]

rehash：每个旧元素用新表长重新算地址，再按原规则插入；旧表里 12、3 的冲突在新表里都消失了

旧表 m=5 时，7、12、3 的地址是 2、2、3，12 和 3 都被挤到后面；换成 m=11 后地址变成 7、1、3，全部一次命中。扩容时搬家的成本是 O(n)，但每次扩容把容量翻倍，平摊到每次插入上仍是 O(1)。

要点：

  • 开放定址法删除元素只能做逻辑删除（标记墓碑），物理清空会截断其他元素的探测链。
  • 链地址法可以直接删除结点。
  • 装填因子 α=n/m；α 超过阈值就扩容，扩容后所有元素按新表长重新散列。
  • 散列表查找、插入、删除的平均复杂度是 O(1)（α 有上限时），最坏 O(n)（所有关键字冲突到一起）。

16.5 布隆过滤器：用几个比特判断“一定没有” 选读

一个网站有 10 亿个已注册用户名，新用户注册时要先判断名字是否被占用。把 10 亿个字符串全放进内存散列表太占空间。如果有一个结构能用很少的内存先排除掉"一定没注册过"的名字，只把"可能注册过"的那一小部分交给数据库确认，大部分请求就不用访问数据库了。这就是布隆过滤器（Bloom filter）。

一个长度为 m 的比特数组，初始全 0，加上 k 个散列函数。

  • 插入 x：算出 k 个位置 h₁(x)…h_k(x)，把这些位都置 1。
  • 查询 x：算出同样 k 个位置。只要有一位是 0，x 一定没插入过；全是 1，x 可能插入过。

"可能"来自假阳性（误判）：x 自己没插入过，但它对应的几位恰好都被其他元素点亮了。反过来，插入过的元素对应的位一定全是 1，所以没有假阴性。

示例： m=10，两个散列函数 h₁(x)=x mod 10，h₂(x)=(3x+1) mod 10。先插入 3 和 17，再查询 5 和 27：

布隆过滤器：m=10 位，h1(x)=x mod 10，h2(x)=(3x+1) mod 10

1 / 5

第1步 · 初始：10 个位全为 0

2 / 5

第2步 · 插入 3：h1=3，h2=10 mod 10=0，把位 3、位 0 置 1

3 / 5

第3步 · 插入 17：h1=7，h2=52 mod 10=2，把位 7、位 2 置 1

4 / 5

第4步 · 查询 5：h1=5，h2=16 mod 10=6，位 5 是 0，所以 5 肯定没插入过

5 / 5

第5步 · 查询 27：h1=7，h2=82 mod 10=2，两位都是 1，回答“可能存在”，其实 27 没插入过（假阳性）

27 从没插入过，但它的两个位置 7、2 恰好都是 17 点亮的，于是被误判为"可能存在"。这时再去数据库精确查一次，就能纠正。

误判率。 插入 n 个元素后，误判率约为 (1 − e^(−kn/m))^k。本例 k=2、n=2、m=10，约 0.109，也就是大约 11% 的未插入元素会被误判。m 越大（位越多）误判率越低；k 存在一个最优值 k=(m/n)·ln2。

删除的问题。 位是多个元素共用的。删除 17 时如果把位 7、2 清零，而另一个元素恰好也用到位 2，它就会被误判为"一定没有"，产生假阴性。所以标准布隆过滤器不支持删除；需要删除时用计数布隆过滤器（每位换成一个小计数器，插入加 1、删除减 1）。

要点：

  • 布隆过滤器：位数组 + k 个散列函数；判"不存在"一定准确，判"存在"可能误判。
  • 有假阳性、无假阴性；标准版不支持删除。
  • 典型用途：缓存穿透防护、爬虫 URL 去重、垃圾邮件黑名单——先过滤掉一定不存在的，再查精确存储。

16.6 LRU 缓存与一致性哈希：哈希表的两个组合用法 选读

LRU：哈希表 + 双向链表

缓存容量有限，满了要淘汰一个。LRU（Least Recently Used，最近最少使用）策略淘汰最久没被访问的那个，理由是最近用过的数据很可能马上还会用。要做到 get、put 都是 O(1)，需要同时满足两件事：按 key 一步找到数据；把某个数据挪到"最近"位置、找到"最久"的数据都只需一步。

哈希表负责第一件事：保存从 key 到链表结点地址的映射。双向链表负责第二件事：靠近 head 的是最近使用的，靠近 tail 的是最久未使用的；在双向链表中摘下一个结点、插到头部，都只需修改几个指针。

哈希表一步找到结点；双链表一步摘下结点、插到 head 后。靠 tail 的就是下一个被淘汰的

示例： 容量 2，访问序列 A、B、A、C、B：

容量 2 的 LRU：访问序列 A B A C B

1 / 5

第1步 · 访问 A：未命中，放入

2 / 5

第2步 · 访问 B：未命中，放到最前

3 / 5

第3步 · 访问 A：命中，A 移到最前

4 / 5

第4步 · 访问 C：未命中且已满，淘汰最久的 B

5 / 5

第5步 · 访问 B：未命中且已满，淘汰最久的 A

第 3 步 A 被访问后移到最前，所以第 4 步满了时淘汰的是 B。如果换成 FIFO（先进先出）策略，访问 A 不改变顺序，第 4 步淘汰的会是最早进来的 A。完整的 C++ 实现（LeetCode 146）见 9.11。Redis 的 LRU 淘汰用的是采样近似算法，思想相同。[3]

一致性哈希：增删服务器时少搬数据

把数据分到 N 台缓存服务器，最直接的写法是 server = hash(key) mod N。可一旦 N 从 3 变成 4，几乎所有 key 的余数都变了，缓存大面积失效。

把哈希值空间想象成一个首尾相接的环（例如 0～2³²−1）。服务器按自己的哈希值放在环上，每个 key 也算出一个位置，顺时针找到的第一台服务器就负责它。

哈希环，箭头是顺时针方向。加入 S4 之前：key1 归 S2，key2 归 S3，key3 归 S1。S4 插在 key2 与 S3 之间后，key2 顺时针先遇到 S4，改归 S4（橙色），其他 key 不动

新增 S4 时，只有 S2 到 S4 这段弧上的 key（图中的 key2）从 S3 改归 S4，其他 key 不动。服务器少时分布可能不均，常用虚拟节点（每台物理服务器在环上放多个点）来平衡。分布式系统中的细节见「计算机系统导论」第 13 章。

要点：

  • LRU = 哈希表（O(1) 定位）+ 双向链表（O(1) 调整顺序）；访问一次就移到链表头，淘汰链表尾。
  • 一致性哈希：节点和 key 都映射到环上，key 归顺时针第一个节点；增删节点只影响相邻一段，虚拟节点解决负载不均。

(4) k mod 3 与 k mod 4 只在 k=0、1、2 时相等，其余 9 个 key（75%）都要换服务器，缓存几乎全部失效。一致性哈希把每次变动限制在环上相邻的一段。

易错点： LRU 的 get 命中也算一次"使用"，要把结点移到头部；只在 put 时调整顺序，算法就退化成 FIFO 了。

小结： LRU 用哈希表定位结点，用双向链表维护使用顺序，命中时把结点移到表头，满了就删除表尾；一致性哈希在环上顺时针寻找节点，增删节点时只影响一段数据。

16.7 跳表：给有序链表加“快速通道” 了解

了解即可：跳表只需知道思想。点击展开

有序数组能二分查找，但插入要整体搬移元素；有序链表插入方便，查找却只能从头一个个走，O(n)。跳表（skip list）在有序链表上加几层"索引链表"，让查找也能像二分一样每次跳过一大段。Redis 的有序集合（sorted set）就用跳表加散列表实现。[4]

最底层（第 0 层）是包含全部元素的有序链表。每往上一层，只保留下一层的一部分元素（插入时抛硬币决定一个新元素升几层，每升一层的概率是 1/2）。每层首尾各有一个哨兵 −∞、+∞。

查找规则： 从最高层的 −∞ 出发。看当前结点在本层的下一个结点：小于目标就向右走；等于目标就找到了；大于目标（过头了）就从当前结点下降一层，继续同样的比较。

完整走一遍：查找 26。

查 26：第2层走到 20，下一个 +∞ 过头，下降；第1层下一个 35>26，下降；第0层下一个就是 26。绿线是走过的路，橙线是“看一眼发现过头”

步骤所在层当前结点下一个结点判断动作
1第 2 层−∞2020 < 26右移到 20
2第 2 层20+∞过头下降到第 1 层的 20
3第 1 层203535 > 26下降到第 0 层的 20
4第 0 层2026相等找到

第 0 层上 3、8、12 三个结点都被第 2 层的 −∞→20 一步跳过了。元素越多、层数越多，跳过的就越多。

插入与删除。 插入时先按查找的路线找到每一层的前驱结点，再抛硬币决定新结点的层数，在这几层里分别做链表插入。删除时在各层把它摘掉。

要点：

  • 跳表：多层有序链表，上层是下层的索引；查找"能右则右、过头就降"。
  • 查找、插入、删除的期望时间 O(log n)，空间期望 O(n)（每个元素平均出现在 2 层）。
  • 跳表的平衡靠随机层数，最坏情况是 O(n)，但概率极小；相比红黑树，跳表实现简单、范围查询方便（底层就是有序链表）。

16.8 Trie：按字符分叉的前缀树 选读

输入法、搜索框要根据已输入的前缀快速列出候选词；判断"有没有单词以 app 开头"，用散列表只能一个个词去比。Trie（字典树、前缀树）把共同前缀合并存储，沿着前缀走下去就到了所有候选词的公共祖先。

根结点为空，每条边代表一个字符，从根到某个结点的路径拼起来就是一个前缀。结点上的终止标记（下图的 ✓）表示"从根到这里是一个完整的单词"。插入 an、and、ant、at、be：

  • 查单词 an：沿 a、n 走到结点，结点有 ✓，存在。
  • 查单词 a：能走到结点 a，但它没有 ✓，说明 a 只是前缀，单词不存在。
  • 查前缀 an 开头的所有词：走到 n 结点，遍历它的子树，得到 an、and、ant。

查找或插入长度为 L 的字符串只与 L 有关，时间 O(L)，和词典里有多少个词无关。代价是空间：如果每个结点开一个长 26 的孩子数组，大量结点的孩子指针是空的。C++ 实现（LeetCode 208）见第 10 章。

要点：

  • Trie 利用公共前缀减少比较；查找、插入 O(L)，L 是字符串长度。
  • 结点上要有"是否为单词结尾"的标记，用来区分完整单词和前缀。
  • 典型用途：前缀匹配、自动补全、词频统计、按字典序输出。

16.9 图的基本概念与计数性质 必读

城市之间的道路、课程之间的先修关系、转账账户之间的资金往来，都是"一些对象 + 对象之间的连接"。图就是描述这种关系的结构。图的计数题（多少条边、度数和是多少）是银行笔试的高频选择题，靠几个公式就能秒答。

图 G=(V, E)：V 是顶点集，E 是边集。记顶点数 n=|V|，边数 e=|E|。

概念含义
无向图 / 有向图边没有方向，写 (u,v)；边有方向，写 ⟨u,v⟩，也叫弧，u 是弧尾，v 是弧头
简单图没有自环（自己连自己）和重边（两点间多条同向边）；考题默认简单图

路径、回路顶点序列中相邻两点都有边；首尾相同的路径是回路（环）
连通 / 连通分量无向图中两点间有路径称连通；极大连通子图叫连通分量
强连通 / 强连通分量有向图中 u 能到 v 且 v 能到 u；极大强连通子图叫强连通分量
完全图任意两点之间都有边（有向完全图则两个方向都有弧）

连通分量。 下图 7 个顶点、6 条边，却分成 3 块：

7 个顶点、6 条边，却有 3 个连通分量：{1,2,3,4}、{5,6}、{7}。边数达到 n−1 也可能不连通

强连通分量。 有向图中，判断两个点是否在同一个强连通分量里，要看它们能否互相到达。

三个强连通分量：{1,2,3}（绿）、{4,5}（紫）、{6}（黄）。3→4 只有单向，所以 3 和 4 分属不同分量

n=6：前 5 个点两两相连（C(5,2)=10 条边），第 6 个点孤立。10 条边仍不连通；再加任何一条边都只能连到 6

生成树计数（了解）。 一个图可以有多棵不同的生成树。n 个顶点的完全图有 n^(n−2) 棵生成树（Cayley 公式），例如 K₄ 有 4²=16 棵。一般图的生成树个数可以用矩阵树定理计算，考试一般只考到概念。

  • 度数和 = 2 × 边数；有向图入度和 = 出度和 = 弧数。
  • 无向完全图 n(n−1)/2 条边，有向完全图 n(n−1) 条弧。
  • n 个顶点：连通最少 n−1 条边；保证连通至少 (n−1)(n−2)/2+1 条边；强连通最少 n 条弧。
  • 连通分量看"能否到达"，强连通分量看"能否互相到达"。

题面：有向图顶点 1～7，弧为 1→2、2→3、3→1、3→4、4→5、5→6、6→4、6→7。求所有强连通分量。最少再加几条弧能使整张图强连通？

提示

先找环：1、2、3 在一个环上，4、5、6 在另一个环上。再看两个环之间的弧是单向还是双向。

参考答案

1→2→3→1 是一个环，环上三个顶点互相可达；4→5→6→4 也是一个环。从 {1,2,3} 能经 3→4 到达 {4,5,6}，但没有弧从 {4,5,6} 回到 {1,2,3}，所以它们是两个不同的分量。7 没有出弧，单独成一个分量。强连通分量为 {1,2,3}、{4,5,6}、{7}。

加一条弧 7→1 后，从任一顶点都能先走到 7、再经 7→1 回到 1，进而到达所有顶点，图变成强连通。所以最少加 1 条。

易错点： "最少几条边能连通"（n−1）和"至少几条边才保证连通"（(n−1)(n−2)/2+1）问的是两件事，先看题目里有没有"保证、一定、无论如何"。

小结： 无向图的度数之和等于 2e；n 个顶点的无向完全图有 n(n−1)/2 条边；连通至少需要 n−1 条边，保证一定连通需要 C(n−1,2)+1 条边；有向图强连通至少需要 n 条边。

16.10 图的存储：邻接矩阵、邻接表及其变体 必读

算法要反复问两个问题："u 和 v 之间有没有边""u 的邻居有哪些"。不同的存储方式让这两个问题的代价不同，选错了存储，算法复杂度就会差一个数量级。

我们用同一张有向图演示：

有向图：5 条弧 V0→V1、V0→V2、V1→V3、V2→V1、V3→V2

邻接矩阵

用 n×n 的二维数组 A，A[i][j]=1 表示有弧 Vi→Vj，否则为 0。带权图把 1 换成权值，没有边的位置记 ∞（对角线记 0）。

邻接矩阵：第 i 行第 j 列为 1 表示有弧 Vi→Vj。第 i 行之和=出度，第 j 列之和=入度

  • 判断 Vi→Vj 是否存在：直接看 A[i][j]，O(1)。
  • 找 Vi 的所有邻居：扫一整行，O(n)。
  • 空间 O(n²)，与边数无关。无向图的矩阵是对称的，可以只存上三角或下三角。

邻接表

每个顶点一个表头，后面挂一条链表，链上是它的所有邻接点。

邻接表（出边表）：每个顶点挂一条链，链上的数字是弧头的编号。链结点总数 = 弧数 5

  • 找 Vi 的所有邻居：只走它的链，O(度数)。
  • 空间 O(n+e)。无向图每条边在两个端点的链上各出现一次，链结点共 2e 个；有向图（出边表）共 e 个。
  • 求出度只要数链长；求入度要扫描所有链，可以另建一个逆邻接表（入边表）。
  • 链表中结点的顺序取决于建表时的插入顺序，所以同一个图的邻接表不唯一，遍历序列也随之不同（16.11）。

十字链表与邻接多重表（了解）

十字链表用于有向图，把邻接表和逆邻接表合在一起：每条弧只存一个结点，结点里有弧尾、弧头和两个指针，tlink 串起"同一弧尾"的弧（出边链），hlink 串起"同一弧头"的弧（入边链）。顶点结点有 firstin、firstout 两个指针。求入度、出度都方便。

十字链表（只画了一部分）：实线 firstout→tlink 串起 V0 的出边链（弧尾同为 V0）；虚线 firstin→hlink 串起 V1 的入边链（弧头同为 V1）

邻接多重表用于无向图：邻接表中每条边会存两次，删除一条边要改两处；邻接多重表让每条边只存一个结点，结点里有两个端点 i、j 和两个指针 ilink、jlink，分别串到 i 的边链和 j 的边链上。

存储方式适用图空间判断边 (u,v)遍历 u 的邻居
邻接矩阵稠密图O(n²)O(1)O(n)
邻接表稀疏图O(n+e)O(度数)O(度数)
十字链表有向图O(n+e)O(度数)出边、入边都 O(度数)
邻接多重表无向图O(n+e)O(度数)O(度数)，每条边只存一次

要点：

  • 邻接矩阵唯一，邻接表不唯一（链中结点顺序可变）。
  • 稠密图用邻接矩阵，稀疏图用邻接表。
  • 用邻接矩阵存储，BFS/DFS 的时间是 O(n²)；用邻接表存储，是 O(n+e)。
  • 十字链表对应有向图，邻接多重表对应无向图。

单选 · 理解检查 12　一个无向图有 n 个顶点、e 条边，用邻接表存储。边结点一共有多少个？

A. 2e

B. e

C. n+e

D. n²

查看答案与每个选项的解析

A · 正确：每条边 (u,v) 在 u 的链和 v 的链上各存一次。

B · 错误：有向图的出边表才是 e 个结点。

C · 错误：n+e 是总空间的量级（表头 n 个 + 边结点），问的只是边结点。

D · 错误：这是邻接矩阵的空间。

练习 16.10-2【变形】估算存储空间

题面：图有 1000 个顶点。(1) 邻接矩阵每格 1 字节，共占多少字节？(2) 有向图有 3000 条弧，用邻接表存储，顶点表每项 12 字节，边结点每个 12 字节（4 字节顶点号加 8 字节指针），共多少字节？(3) 有 3000 条边的无向图呢？

提示

无向图的每条边在两个端点的链上各存一次。

参考答案

(1) 1000×1000 = 1,000,000 字节，与边数无关。

(2) 1000×12 + 3000×12 = 48,000 字节。

(3) 共 6000 个边结点：1000×12 + 6000×12 = 84,000 字节。这张图很稀疏（3000 远小于 1000²），邻接表的空间不到邻接矩阵的十分之一。

练习 16.10-3【综合】头插法建邻接表

题面：无向图顶点 0～4，边按 (0,1)、(0,2)、(1,2)、(1,3)、(2,4)、(3,4) 的顺序读入。每读入一条边 (u,v)，就把 v 插到 u 的链头、把 u 插到 v 的链头。(1) 写出最终的邻接表。(2) 从 0 出发，按这个邻接表写出 BFS 和 DFS 序列。(3) 若改为插到链尾，BFS 和 DFS 序列又是什么？

提示

头插时后读入的边排在前面，所以每条链是读入顺序的倒序。

参考答案

(1)

顶点01234
链（从头到尾）2, 13, 2, 04, 1, 04, 13, 2

(2) BFS：0 出队，2、1 入队；2 出队，4 入队；1 出队，3 入队；序列为 0 2 1 4 3。DFS：0 先进入 2，2 先进入 4，4 先进入 3，3 的邻居 4 已访问、1 未访问，进入 1；序列为 0 2 4 3 1。

(3) 尾插时每条链按读入顺序排列：0 的链为 1、2；1 的链为 0、2、3；2 的链为 0、1、4；3 的链为 1、4；4 的链为 2、3。BFS 为 0 1 2 3 4，DFS 为 0 1 2 4 3。同一张图、同一组边，只因建表方式不同，遍历序列就不同，这就是"邻接表不唯一"的含义。

易错点： 有向图邻接矩阵中，第 i 行之和是 Vi 的出度，第 j 列之和是 Vj 的入度。

小结： 稠密图用邻接矩阵存储，空间 O(n²)；稀疏图用邻接表，空间 O(n+e)；邻接矩阵是唯一的，邻接表不唯一；十字链表用于有向图，邻接多重表用于无向图。
