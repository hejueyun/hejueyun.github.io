本章前半讲散列，后半讲图。两部分共用一个思路：先画出结构，再一步一步填表。散列部分的表是"每个关键字比较了几次"，图部分的表是"每个顶点当前的距离 / key / 入度"。考试的计算题，几乎都是把这张表填对。

04.1 散列函数：把关键字直接换算成下标

为什么需要它。 在 10 万个账号里找一个账号，顺序查找要比较几万次，二分查找也要十几次。如果能由账号直接算出它存放的位置，一次就能找到。散列表（hash table，也叫哈希表）就是按这个想法设计的：用一个函数把关键字换算成数组下标，查找时再算一遍，直接去那个位置取。

它是什么。 散列函数 H(key) 把关键字映射到 0～m−1 之间的整数，m 是表长（数组的格数），每一格叫一个槽或桶。最常用的是除留余数法：

H(key) = key mod p，p 取不超过表长 m 的最大质数。

两个不同的关键字算出同一个地址，叫冲突（collision），这些关键字互称同义词。冲突无法完全避免：关键字的可能取值远多于槽数，总有一些会挤到同一格。所以设计散列表要回答两个问题：散列函数怎么选，才能让关键字分布均匀；冲突发生后，第二个关键字放到哪里（下一节）。

散列函数把关键字换算成下标；41 和 30 算出同一个下标 8，这就是冲突

为什么 p 要取质数。 实际数据常带有规律，比如订单号都是 4 的倍数、价格都以 0 结尾。如果 p 和这些规律有公因子，余数只会落在少数几个值上，其余的桶永远空着，冲突集中爆发。质数除了 1 和自身没有别的因子，和数据里的规律"对不上"，余数就分散得开。下表用 8 个 4 的倍数做对比：

关键字都是 4 的倍数：除以 12 只落进 0、4、8 三个桶；除以质数 11 落进 8 个不同的桶

除以 12 时，12 和 4 有公因子 4，余数只能是 0、4、8，8 个关键字挤进 3 个桶；除以 11 时，8 个关键字各占一个桶，完全没有冲突。

其他散列函数（了解名字即可）。 直接定址法 H(key)=a·key+b，没有冲突，但关键字范围大时浪费空间；数字分析法取关键字中分布均匀的几位；平方取中法取 key² 的中间几位；折叠法把关键字分段相加。笔试最常考的是除留余数法。

考场结论：

  • 除留余数法 H(key)=key mod p，p 取不大于表长 m 的最大质数。
  • 冲突只能减少、无法避免；好的散列函数让关键字均匀分布、计算简单。
  • 散列表查找的效率取决于三件事：散列函数、冲突处理方法、装填因子（04.3）。

04.2 处理冲突：开放定址法与链地址法

为什么需要它。 上一节的 41 和 30 都算到下标 8。41 先来占了位，30 来了怎么办？两大类做法：在表内另找一个空槽（开放定址法），或者让同一个下标挂一串元素（链地址法）。

开放定址法：沿探测序列找空槽

冲突时按一个固定的增量序列 d₀=0, d₁, d₂, … 依次尝试地址 Hᵢ=(H(key)+dᵢ) mod m，直到找到空槽。增量序列决定了方法：

链地址法：同义词挂在一条链上

链地址法（拉链法）的表里每格存一个链表头指针，散列地址相同的关键字都挂在这条链上。插入时我们约定尾插（新结点接在链尾），这也是多数教材画图的方式。

链地址法：下标 1、2、8 各挂 2 个结点（尾插），下标 0、9 各 1 个，其余 6 个桶为空

链地址法没有堆积：只有真正的同义词才会在同一条链上，30 不会去占 9 号桶的位置。代价是每个结点多一个指针。Java 的 HashMap 采用链地址法（JDK 8 起链太长时还会转成红黑树）。

考场结论：

  • 开放定址法：Hᵢ=(H(key)+dᵢ) mod m。线性探测 dᵢ=i，二次探测 dᵢ=0, 1², −1², 2², −2², …
  • 线性探测会产生堆积：非同义词之间也会争夺同一个地址；二次探测、双重散列可以减轻堆积。
  • 链地址法把同义词存在同一链表中，没有堆积，装填因子可以大于 1。

04.3 平均查找长度 ASL：成功与失败怎么数

为什么需要它。 散列表"理想中 O(1)"，但有冲突就要多比较几次。笔试用平均查找长度 ASL（Average Search Length，平均要和多少个关键字比较）衡量实际效率，并且分成查找成功、查找失败两种情况出题。这是本章最常考的计算题。

它是什么。 我们采用 408 和多数国内教材的约定：

  • ASL 成功 = 每个已存关键字"查到它所需的比较次数"之和 ÷ 关键字个数 n。某个关键字的比较次数，等于当初插入它时探测的格子数。
  • ASL 失败 = 对每一个可能的散列地址（0～p−1，共 p 个），从该地址开始一直比较到遇见空槽所需的次数之和 ÷ p。开放定址法中，和空槽的那一次比较也计入。

失败的分母是 p（散列函数能算出的地址个数），这一点和表长 m 无关。本例 p=m=11，两者相同。

线性探测的 ASL

成功：把上一节每次插入的比较次数列出来。

关键字224153463013167
散列地址08928211
比较次数11113214

ASL 成功 = (1+1+1+1+3+2+1+4) / 8 = 14/8 = 1.75。

失败：对每个地址 h，从 h 开始向后数，一直数到第一个空槽（含空槽本身）。表中空槽是下标 5、6、7。

起始地址 h012345678910
比较到的格子0～51～52～53～54～55678～10,0～59～10,0～510,0～5
比较次数65432111987

ASL 失败 = 47/11 ≈ 4.27。地址 8 那一格要绕过表尾回到表头，一直比到下标 5，共 9 次，这是堆积的直接代价。

二次探测的 ASL

成功：比较次数与线性探测恰好相同（30 比 3 次、13 比 2 次、67 比 4 次），ASL 成功 = 14/8 = 1.75。

失败：二次探测后的表为 [22, 1, 46, 13, _, 67, _, 30, 41, 53, _]，空槽是 4、6、10。每个起点按 h, h+1, h−1, h+4, h−4, … 探测到空槽：

起始地址 h012345678910
比较次数36421213521

例如 h=0：比 0（占）、1（占）、0−1=10（空），3 次；h=1：比 1、2、0、5、8（全占），再比 1+9=10（空），6 次。ASL 失败 = 30/11 ≈ 2.73，比线性探测的 4.27 小很多，因为没有长段堆积。

链地址法的 ASL

成功：链上第 1 个结点比 1 次，第 2 个结点比 2 次。22、41、53、46、1 都在链首，各比 1 次；30、13、67 在第二位，各比 2 次。ASL 成功 = (5×1 + 3×2)/8 = 11/8 = 1.375。

失败：从地址 h 出发，要和这条链上的每个结点都比一次才能确认不存在。链长依次为 1、2、2、0、0、0、0、0、2、1、0，ASL 失败 = 8/11 ≈ 0.73（按 408 约定，与空指针的比较不计）。

装填因子决定 ASL

装填因子 α = 表中记录数 n / 表长 m，表示表"装得有多满"。本例 α=8/11≈0.73。对分布均匀的散列函数，教材给出下面的近似公式：

方法ASL 成功ASL 失败
线性探测½ (1 + 1/(1−α))½ (1 + 1/(1−α)²)
链地址法1 + α/2α

代入 α=0.5：线性探测成功 1.5 次、失败 2.5 次；链地址法成功 1.25 次。α=0.9 时，线性探测失败要约 50.5 次，链地址法成功只要 1.45 次。

α 过了 0.7，线性探测的平均比较次数开始陡升；链地址法几乎是一条斜率 1/2 的直线

公式里只出现 α，这就是标准答案句的来源。小例子算出的 ASL 和公式值有偏差，因为公式描述的是"大量随机关键字的平均情况"。

考场结论（原样记住）：

  • 散列表的平均查找长度依赖于装填因子 α，而不直接依赖于 n 或 m。 α 越大，冲突越多，ASL 越大。
  • ASL 成功的分母是关键字个数 n；ASL 失败的分母是散列函数可能的地址个数 p。
  • 开放定址法算失败次数时，与空槽的比较算一次；链地址法只数与关键字的比较。
  • 同一组数据，线性探测的失败 ASL 通常最大，原因是堆积。

代码：线性探测散列表与 ASL。 变量表：

变量含义
slot表本身，存关键字；EMPTY(−1) 表示从未用过，TOMB(−2) 表示删除过（04.4）
p除留余数法的除数
cnt本次操作的比较次数
const int EMPTY = -1;     // 从未用过
const int TOMB = -2;      // 墓碑：删除过，查找要跨过去

struct LinearTable {
    vector<int> slot;     // 表本身，存关键字或 EMPTY / TOMB
    int p;                // 除留余数法的除数 H(k) = k % p
    LinearTable(int m, int p_) : slot(m, EMPTY), p(p_) {}

    // 插入 k，返回比较次数（= 探测到的位置个数）
    int insert(int k) {
        int m = slot.size(), i = k % p, cnt = 1;
        while (slot[i] >= 0) { i = (i + 1) % m; ++cnt; }
        slot[i] = k;
        return cnt;
    }
    // 查找 k：返回 {是否找到, 比较次数}。遇到 EMPTY 才停，TOMB 继续向后
    pair<bool, int> find(int k) const {
        int m = slot.size(), i = k % p, cnt = 1;
        for (int step = 0; step < m; ++step) {
            if (slot[i] == EMPTY) return {false, cnt};
            if (slot[i] == k) return {true, cnt};
            i = (i + 1) % m; ++cnt;
        }
        return {false, cnt - 1};
    }
};

// 失败 ASL 的分子：对每个散列地址 0..p-1，一直比到空位（空位那次也算）
int failTotal(const LinearTable& t) {
    int m = t.slot.size(), s = 0;
    for (int h = 0; h < t.p; ++h) {
        int i = h, cnt = 1;
        while (t.slot[i] != EMPTY) { i = (i + 1) % m; ++cnt; }
        s += cnt;
    }
    return s;
}
EMPTY = -1     # 从未用过
TOMB = -2      # 墓碑：删除过，查找要跨过去

class LinearTable:
    def __init__(self, m, p):
        self.slot = [EMPTY] * m   # 表本身，存关键字或 EMPTY / TOMB
        self.p = p                # 除留余数法的除数 H(k) = k % p

    # 插入 k，返回比较次数（= 探测到的位置个数）
    # 注意：Python 的 % 结果和除数同号，负关键字也落在 0..p-1；C++ 的 % 对负数会得到负下标
    def insert(self, k):
        m, i, cnt = len(self.slot), k % self.p, 1
        while self.slot[i] >= 0:
            i = (i + 1) % m; cnt += 1
        self.slot[i] = k
        return cnt

    # 查找 k：返回 (是否找到, 比较次数)，用元组代替 pair。遇到 EMPTY 才停，TOMB 继续向后
    def find(self, k):
        m, i, cnt = len(self.slot), k % self.p, 1
        for step in range(m):
            if self.slot[i] == EMPTY: return (False, cnt)
            if self.slot[i] == k: return (True, cnt)
            i = (i + 1) % m; cnt += 1
        return (False, cnt - 1)

# 失败 ASL 的分子：对每个散列地址 0..p-1，一直比到空位（空位那次也算）
def fail_total(t):
    m, s = len(t.slot), 0
    for h in range(t.p):
        i, cnt = h, 1
        while t.slot[i] != EMPTY:
            i = (i + 1) % m; cnt += 1
        s += cnt
    return s

04.4 删除、装填因子与扩容

为什么需要它。 散列表要支持删除，还要在元素越来越多时保持高效。开放定址法里，一个槽同时承担着"存元素"和"告诉后来者继续往后找"两个作用，删除时如果只考虑第一个作用，就会把查找链切断。

墓碑删除。 在开放定址法中删除一个元素，我们把那个槽标记为墓碑（删除标记）而清空它：

  • 查找时遇到墓碑继续往后探测，遇到真正的空槽才停；
  • 插入时，确认表中没有这个关键字之后，可以复用路上遇到的第一个墓碑位置。

墓碑越积越多，查找会越来越慢（墓碑也要比较），所以墓碑数量多时要整体重建一次表。链地址法删除就简单得多：从链上摘掉那个结点即可。

扩容与 rehash。 装填因子 α 太大时，ASL 迅速上升（见 04.3 的曲线）。常见做法是给 α 设一个阈值（Java HashMap 默认 0.75），超过后申请一张更大的表，把旧表中每个元素用新表长重新计算地址再插入，这个过程叫 rehash（重散列）。[2]

rehash：每个旧元素用新表长重新算地址，再按原规则插入；旧表里 12、3 的冲突在新表里都消失了

旧表 m=5 时，7、12、3 的地址是 2、2、3，12 和 3 都被挤到后面；换成 m=11 后地址变成 7、1、3，全部一次命中。扩容时搬家的成本是 O(n)，但每次扩容把容量翻倍，平摊到每次插入上仍是 O(1)。

考场结论：

  • 开放定址法删除元素只能做逻辑删除（标记墓碑），物理清空会截断其他元素的探测链。
  • 链地址法可以直接删除结点。
  • 装填因子 α=n/m；α 超过阈值就扩容，扩容后所有元素按新表长重新散列。
  • 散列表查找、插入、删除的平均复杂度是 O(1)（α 有上限时），最坏 O(n)（所有关键字冲突到一起）。

04.5 布隆过滤器：用几个比特判断“一定没有”

为什么需要它。 一个网站有 10 亿个已注册用户名，新用户注册时要先判断名字是否被占用。把 10 亿个字符串全放进内存散列表太占空间。如果有一个结构能用很少的内存先排除掉"一定没注册过"的名字，只把"可能注册过"的那一小部分交给数据库确认，大部分请求就不用访问数据库了。这就是布隆过滤器（Bloom filter）。

它是什么。 一个长度为 m 的比特数组，初始全 0，加上 k 个散列函数。

  • 插入 x：算出 k 个位置 h₁(x)…h_k(x)，把这些位都置 1。
  • 查询 x：算出同样 k 个位置。只要有一位是 0，x 一定没插入过；全是 1，x 可能插入过。

"可能"来自假阳性（误判）：x 自己没插入过，但它对应的几位恰好都被其他元素点亮了。反过来，插入过的元素对应的位一定全是 1，所以没有假阴性。

误判率。 插入 n 个元素后，误判率约为 (1 − e^(−kn/m))^k。本例 k=2、n=2、m=10，约 0.109，也就是大约 11% 的未插入元素会被误判。m 越大（位越多）误判率越低；k 存在一个最优值 k=(m/n)·ln2。

删除的问题。 位是多个元素共用的。删除 17 时如果把位 7、2 清零，而另一个元素恰好也用到位 2，它就会被误判为"一定没有"，产生假阴性。所以标准布隆过滤器不支持删除；需要删除时用计数布隆过滤器（每位换成一个小计数器，插入加 1、删除减 1）。

考场结论：

  • 布隆过滤器：位数组 + k 个散列函数；判"不存在"一定准确，判"存在"可能误判。
  • 有假阳性、无假阴性；标准版不支持删除。
  • 典型用途：缓存穿透防护、爬虫 URL 去重、垃圾邮件黑名单——先过滤掉一定不存在的，再查精确存储。

04.6 LRU 缓存与一致性哈希：哈希表的两个组合用法

LRU：哈希表 + 双向链表

为什么需要它。 缓存容量有限，满了要淘汰一个。LRU（Least Recently Used，最近最少使用）策略淘汰最久没被访问的那个，理由是最近用过的数据很可能马上还会用。要做到 get、put 都是 O(1)，需要同时满足两件事：按 key 一步找到数据；把某个数据挪到"最近"位置、找到"最久"的数据都只需一步。

它是什么。 哈希表负责第一件事：key → 链表结点的地址。双向链表负责第二件事：靠 head 的是最近使用的，靠 tail 的是最久未用的；双向链表摘下一个结点、插到头部都只要改几个指针。

哈希表一步找到结点；双链表一步摘下结点、插到 head 后。靠 tail 的就是下一个被淘汰的

第 3 步 A 被访问后移到最前，所以第 4 步满了时淘汰的是 B。如果换成 FIFO（先进先出）策略，访问 A 不改变顺序，第 4 步淘汰的会是最早进来的 A。完整的 C++ 实现（LeetCode 146）见 25.11。Redis 的 LRU 淘汰用的是采样近似算法，思想相同。[3]

一致性哈希：增删服务器时少搬数据

为什么需要它。 把数据分到 N 台缓存服务器，最直接的写法是 server = hash(key) mod N。可一旦 N 从 3 变成 4，几乎所有 key 的余数都变了，缓存大面积失效。

它是什么。 把哈希值空间想象成一个首尾相接的环（例如 0～2³²−1）。服务器按自己的哈希值放在环上，每个 key 也算出一个位置，顺时针找到的第一台服务器就负责它。

哈希环，箭头是顺时针方向。加入 S4 之前：key1 归 S2，key2 归 S3，key3 归 S1。S4 插在 key2 与 S3 之间后，key2 顺时针先遇到 S4，改归 S4（橙色），其他 key 不动

新增 S4 时，只有 S2 到 S4 这段弧上的 key（图中的 key2）从 S3 改归 S4，其他 key 不动。服务器少时分布可能不均，常用虚拟节点（每台物理服务器在环上放多个点）来平衡。分布式系统中的细节见第 28 章。

考场结论：

  • LRU = 哈希表（O(1) 定位）+ 双向链表（O(1) 调整顺序）；访问一次就移到链表头，淘汰链表尾。
  • 一致性哈希：节点和 key 都映射到环上，key 归顺时针第一个节点；增删节点只影响相邻一段，虚拟节点解决负载不均。

04.7 跳表：给有序链表加“快速通道”

为什么需要它。 有序数组能二分查找，但插入要整体搬移元素；有序链表插入方便，查找却只能从头一个个走，O(n)。跳表（skip list）在有序链表上加几层"索引链表"，让查找也能像二分一样每次跳过一大段。Redis 的有序集合（sorted set）就用跳表加散列表实现。[4]

它是什么。 最底层（第 0 层）是包含全部元素的有序链表。每往上一层，只保留下一层的一部分元素（插入时抛硬币决定一个新元素升几层，每升一层的概率是 1/2）。每层首尾各有一个哨兵 −∞、+∞。

查找规则： 从最高层的 −∞ 出发。看当前结点在本层的下一个结点：小于目标就向右走；等于目标就找到了；大于目标（过头了）就从当前结点下降一层，继续同样的比较。

完整走一遍：查找 26。

查 26：第2层走到 20，下一个 +∞ 过头，下降；第1层下一个 35>26，下降；第0层下一个就是 26。绿线是走过的路，橙线是“看一眼发现过头”

步骤所在层当前结点下一个结点判断动作
1第 2 层−∞2020 < 26右移到 20
2第 2 层20+∞过头下降到第 1 层的 20
3第 1 层203535 > 26下降到第 0 层的 20
4第 0 层2026相等找到

第 0 层上 3、8、12 三个结点都被第 2 层的 −∞→20 一步跳过了。元素越多、层数越多，跳过的就越多。

插入与删除。 插入时先按查找的路线找到每一层的前驱结点，再抛硬币决定新结点的层数，在这几层里分别做链表插入。删除时在各层把它摘掉。

考场结论：

  • 跳表：多层有序链表，上层是下层的索引；查找"能右则右、过头就降"。
  • 查找、插入、删除的期望时间 O(log n)，空间期望 O(n)（每个元素平均出现在 2 层）。
  • 跳表的平衡靠随机层数，最坏情况是 O(n)，但概率极小；相比红黑树，跳表实现简单、范围查询方便（底层就是有序链表）。

04.8 Trie：按字符分叉的前缀树

为什么需要它。 输入法、搜索框要根据已输入的前缀快速列出候选词；判断"有没有单词以 app 开头"，用散列表只能一个个词去比。Trie（字典树、前缀树）把共同前缀合并存储，沿着前缀走下去就到了所有候选词的公共祖先。

它是什么。 根结点为空，每条边代表一个字符，从根到某个结点的路径拼起来就是一个前缀。结点上的终止标记（下图的 ✓）表示"从根到这里是一个完整的单词"。插入 an、and、ant、at、be：

  • 查单词 an：沿 a、n 走到结点，结点有 ✓，存在。
  • 查单词 a：能走到结点 a，但它没有 ✓，说明 a 只是前缀，单词不存在。
  • 查前缀 an 开头的所有词：走到 n 结点，遍历它的子树，得到 an、and、ant。

查找或插入长度为 L 的字符串只与 L 有关，时间 O(L)，和词典里有多少个词无关。代价是空间：如果每个结点开一个长 26 的孩子数组，大量结点的孩子指针是空的。C++ 实现（LeetCode 208）见第 26 章。

考场结论：

  • Trie 利用公共前缀减少比较；查找、插入 O(L)，L 是字符串长度。
  • 结点上要有"是否为单词结尾"的标记，用来区分完整单词和前缀。
  • 典型用途：前缀匹配、自动补全、词频统计、按字典序输出。

04.9 图的基本概念与计数性质

为什么需要它。 城市之间的道路、课程之间的先修关系、转账账户之间的资金往来，都是"一些对象 + 对象之间的连接"。图就是描述这种关系的结构。图的计数题（多少条边、度数和是多少）是银行笔试的高频选择题，靠几个公式就能秒答。

它是什么。 图 G=(V, E)：V 是顶点集，E 是边集。记顶点数 n=|V|，边数 e=|E|。

04.10 图的存储：邻接矩阵、邻接表及其变体

为什么需要它。 算法要反复问两个问题："u 和 v 之间有没有边""u 的邻居有哪些"。不同的存储方式让这两个问题的代价不同，选错了存储，算法复杂度就会差一个数量级。

我们用同一张有向图演示：

有向图：5 条弧 V0→V1、V0→V2、V1→V3、V2→V1、V3→V2

邻接矩阵

用 n×n 的二维数组 A，A[i][j]=1 表示有弧 Vi→Vj，否则为 0。带权图把 1 换成权值，没有边的位置记 ∞（对角线记 0）。

邻接矩阵：第 i 行第 j 列为 1 表示有弧 Vi→Vj。第 i 行之和=出度，第 j 列之和=入度

  • 判断 Vi→Vj 是否存在：直接看 A[i][j]，O(1)。
  • 找 Vi 的所有邻居：扫一整行，O(n)。
  • 空间 O(n²)，与边数无关。无向图的矩阵是对称的，可以只存上三角或下三角。

邻接表

每个顶点一个表头，后面挂一条链表，链上是它的所有邻接点。

邻接表（出边表）：每个顶点挂一条链，链上的数字是弧头的编号。链结点总数 = 弧数 5

  • 找 Vi 的所有邻居：只走它的链，O(度数)。
  • 空间 O(n+e)。无向图每条边在两个端点的链上各出现一次，链结点共 2e 个；有向图（出边表）共 e 个。
  • 求出度只要数链长；求入度要扫描所有链，可以另建一个逆邻接表（入边表）。
  • 链表中结点的顺序取决于建表时的插入顺序，所以同一个图的邻接表不唯一，遍历序列也随之不同（04.11）。

十字链表与邻接多重表（了解）

十字链表用于有向图，把邻接表和逆邻接表合在一起：每条弧只存一个结点，结点里有弧尾、弧头和两个指针，tlink 串起"同一弧尾"的弧（出边链），hlink 串起"同一弧头"的弧（入边链）。顶点结点有 firstin、firstout 两个指针。求入度、出度都方便。

十字链表（只画了一部分）：实线 firstout→tlink 串起 V0 的出边链（弧尾同为 V0）；虚线 firstin→hlink 串起 V1 的入边链（弧头同为 V1）

邻接多重表用于无向图：邻接表中每条边会存两次，删除一条边要改两处；邻接多重表让每条边只存一个结点，结点里有两个端点 i、j 和两个指针 ilink、jlink，分别串到 i 的边链和 j 的边链上。

存储方式适用图空间判断边 (u,v)遍历 u 的邻居
邻接矩阵稠密图O(n²)O(1)O(n)
邻接表稀疏图O(n+e)O(度数)O(度数)
十字链表有向图O(n+e)O(度数)出边、入边都 O(度数)
邻接多重表无向图O(n+e)O(度数)O(度数)，每条边只存一次

考场结论：

  • 邻接矩阵唯一，邻接表不唯一（链中结点顺序可变）。
  • 稠密图用邻接矩阵，稀疏图用邻接表。
  • 用邻接矩阵存储，BFS/DFS 的时间是 O(n²)；用邻接表存储，是 O(n+e)。
  • 十字链表对应有向图，邻接多重表对应无向图。

04.11 BFS 与 DFS：按邻接表写出遍历序列

为什么需要它。 "从某个顶点出发访问图中所有顶点，每个顶点只访问一次"是几乎所有图算法的骨架：求连通分量、判断有没有环、找最短路、拓扑排序，都建立在遍历之上。笔试最常见的题型是：给出邻接表，写出 BFS 或 DFS 序列。

它是什么。

  • BFS（广度优先）：像水波一样一圈圈向外扩散。用队列：出发点入队；每次出队一个顶点，把它尚未访问的邻居按邻接表顺序依次入队。
  • DFS（深度优先）：一条路走到底，走不通再回退。用递归（或栈）：访问一个顶点后，按邻接表顺序找它第一个未访问的邻居，递归进去；所有邻居都访问过了就返回。

两种遍历都用一个 visited 数组防止重复访问。BFS 我们在入队时就标记 visited，这样同一个顶点不会因为被多个邻居发现而重复入队。

生成树与森林。 遍历过程中"第一次发现某个顶点所经过的边"（图中的绿边）构成一棵树，叫 BFS 生成树或 DFS 生成树。非连通图从一个点出发只能遍历它所在的连通分量；要遍历全图，就在主循环里对每个还没访问的顶点再启动一次，启动的次数就是连通分量的个数，得到的是生成森林。

BFS 求无权图最短路。 BFS 按"离起点的边数"一层层扩展：先访问所有距离 1 的点，再访问所有距离 2 的点……所以第一次访问到某点时经过的边数就是最短的。图 H 中从 A 出发，B、C、D 距离 1，E、F 距离 2，G 距离 3，H 距离 4。只需在入队时记录 dist[v] = dist[u] + 1。

代码要点（C++）。 刷题模板见第 22、26 章；核心就是下面几行：

queue<int> q; q.push(s); vis[s] = true; dist[s] = 0;
while (!q.empty()) {
    int u = q.front(); q.pop();
    for (int v : adj[u]) if (!vis[v]) { vis[v] = true; dist[v] = dist[u] + 1; q.push(v); }
}
q = deque([s]); vis[s] = True; dist[s] = 0     # from collections import deque；list.pop(0) 是 O(n)，别拿列表当队列
while q:
    u = q.popleft()
    for v in adj[u]:
        if not vis[v]:
            vis[v] = True; dist[v] = dist[u] + 1; q.append(v)

考场结论：

  • BFS 用队列、按层访问，类似树的层序遍历；DFS 用递归栈、一路深入，类似树的先序遍历。
  • 时间复杂度：邻接表 O(n+e)，邻接矩阵 O(n²)；空间 O(n)。
  • 遍历序列依赖存储结构：邻接矩阵存储时序列唯一，邻接表存储时序列随链中顺序变化。
  • 无权图单源最短路用 BFS；对无向图调用遍历函数的次数 = 连通分量数。

04.12 最小生成树：Prim 与 Kruskal

为什么需要它。 要在 6 个城市之间铺光缆，使任意两城都能通信，每段光缆有不同造价。我们要选出一组边，把所有城市连通，并让总造价最小。这组边一定没有环（有环就能去掉环上一条边而保持连通，造价更低），所以它是一棵生成树，总权最小的那棵叫最小生成树（MST）。

它是什么。 对连通无向带权图，MST 包含全部 n 个顶点、n−1 条边，边权之和最小。两个经典算法都基于同一个事实：把顶点分成两部分，连接两部分的边中权值最小的那条，一定可以出现在某棵 MST 里。这里"把顶点分成两部分"叫一个割，一端在这边、一端在那边的边叫跨越割的边。

  • Prim：从一个顶点开始"长"一棵树。每一步在"一端在树内、一端在树外"的边中选权值最小的，把树外那个端点拉进树。
  • Kruskal：一开始每个顶点自成一棵树。把所有边按权值从小到大看，若两端在不同的树里就选它（两棵树合并），在同一棵树里就跳过（会成环），直到选够 n−1 条。

Prim 的变量表：key[v] 是 v 到当前树的最轻边，inTree[v] 表示 v 是否已在树中，total 累加所选边的权值。

int prim(int n, const vector<vector<pair<int,int>>>& adj, int s, vector<int>& order) {
    vector<int> key(n, INF);          // key[v]：v 连到当前树的最轻边
    vector<bool> inTree(n, false);
    key[s] = 0;
    int total = 0;
    for (int round = 0; round < n; ++round) {
        int u = -1;
        for (int v = 0; v < n; ++v)
            if (!inTree[v] && (u == -1 || key[v] < key[u])) u = v;
        inTree[u] = true;
        order.push_back(u);
        total += key[u];
        for (auto [v, w] : adj[u])
            if (!inTree[v] && w < key[v]) key[v] = w;     // 只比边权，不加 key[u]
    }
    return total;
}

# INF 可以取 float('inf')：Python 整数不溢出，也不需要 INT_MAX / 2 这种防溢出写法
def prim(n, adj, s, order):
    key = [INF] * n                   # key[v]：v 连到当前树的最轻边
    in_tree = [False] * n
    key[s] = 0
    total = 0
    for _ in range(n):                # 循环变量没用到；round 是 Python 内置函数名，不拿来当变量
        u = -1
        for v in range(n):
            if not in_tree[v] and (u == -1 or key[v] < key[u]): u = v
        in_tree[u] = True
        order.append(u)
        total += key[u]
        for v, w in adj[u]:
            if not in_tree[v] and w < key[v]: key[v] = w      # 只比边权，不加 key[u]
    return total

Kruskal 的变量表：edges 是 (u, v, w) 三元组，d 是并查集，chosen 收集选中的边。

int kruskal(int n, vector<tuple<int,int,int>> edges, vector<tuple<int,int,int>>& chosen) {
    stable_sort(edges.begin(), edges.end(),
                [](const auto& x, const auto& y) { return get<2>(x) < get<2>(y); });
    DSU d(n);
    int total = 0;
    for (auto [u, v, w] : edges) {
        if (d.unite(u, v)) { total += w; chosen.push_back({u, v, w}); }
        if ((int)chosen.size() == n - 1) break;
    }
    return total;
}
# edges 是 (u, v, w) 元组的列表。C++ 按值传参、在副本上排序；
# Python 用 sorted 生成新列表，调用者的 edges 不变。sorted 是稳定排序（Timsort），等价 stable_sort
def kruskal(n, edges, chosen):
    edges = sorted(edges, key=lambda e: e[2])
    d = DSU(n)
    total = 0
    for u, v, w in edges:
        if d.unite(u, v):
            total += w; chosen.append((u, v, w))
        if len(chosen) == n - 1: break
    return total

04.13 并查集：快速判断“是不是在同一棵树里”

为什么需要它。 Kruskal 每看一条边都要问"两端是否已经连通"。如果每次都做一遍 DFS，代价是 O(n)。并查集（Disjoint Set Union，DSU）把这个问题做到几乎 O(1)。

它是什么。 用一个 parent 数组把每个集合组织成一棵树，树根就是这个集合的"代表"。

  • find(x)：沿 parent 一直往上走到根，返回根。两个元素的根相同，就在同一集合。
  • union(x, y)：分别找到两个根，把一个根的 parent 设为另一个根，两个集合就合并了。

两个优化让树保持矮：

  • 按秩合并 / 按大小合并：合并时把较小（或较矮）的树挂到较大的树下面。"秩"是树高的一个上界，按秩合并就是"矮树挂到高树下"；按大小合并用元素个数代替秩，效果相同。
  • 路径压缩：find(x) 走到根之后，把沿途每个结点的 parent 直接改成根，下次再查就一步到位。

struct DSU {
    vector<int> parent, sz;
    DSU(int n) : parent(n), sz(n, 1) { iota(parent.begin(), parent.end(), 0); }
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);                    // 小树挂到大树下
        parent[b] = a; sz[a] += sz[b];
        return true;
    }
};
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))  # 相当于 iota：parent[i] = i
        self.sz = [1] * n

    # 递归深度 = 树高。按大小合并保证树高 O(log n)，碰不到 Python 默认约 1000 层的递归上限；
    # 只做路径压缩、不按大小合并时，链状的树可能超限，那时改成循环写法
    def find(self, x):
        if self.parent[x] != x: self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def unite(self, a, b):
        a = self.find(a); b = self.find(b)
        if a == b: return False
        if self.sz[a] < self.sz[b]: a, b = b, a           # 小树挂到大树下
        self.parent[b] = a; self.sz[a] += self.sz[b]
        return True

考场结论：

  • 并查集支持"合并两个集合""查询两个元素是否同属一个集合"，用树（parent 数组）表示集合，根是代表。
  • 按秩（大小）合并 + 路径压缩后，单次操作均摊 O(α(n))，近似常数。
  • 典型用途：Kruskal 判环、连通分量计数、朋友圈 / 岛屿合并类题目。

04.14 Dijkstra：单源最短路径

为什么需要它。 地图导航要从当前位置找到各地点的最短路线，路段长度各不相同。BFS 只数边数，这里需要比较的是边权之和。Dijkstra 算法解决边权非负图上的单源最短路径问题。

它是什么。 维护两类顶点：已确定最短距离的集合 S，和其余的未确定顶点。dist[v] 是"目前已知的从源点到 v 的最短距离"。

  1. 初始 dist[源点]=0，其余 ∞。
  2. 在未确定顶点中选 dist 最小的 u，把它加入 S（u 的最短距离就此确定）。
  3. 松弛：对 u 的每个邻居 v，如果 dist[u]+w(u,v) < dist[v]，就把 dist[v] 改小，并记前驱 path[v]=u。
  4. 重复 2～3，直到所有顶点都确定。

为什么选出的 u 就确定了？因为所有边权非负，任何"绕道其他未确定顶点再到 u"的路径，长度至少是那个顶点的 dist，而它不小于 dist[u]，不可能更短。

代码（小根堆版）。 变量表：dist 是当前最短距离；pq 是按距离排序的小根堆，存 (距离, 顶点)；堆中可能有同一顶点的旧条目，出堆时若 d > dist[u] 说明过期，直接跳过。

vector<int> dijkstraHeap(int n, const vector<vector<pair<int,int>>>& adj, int s) {
    vector<int> dist(n, INF);
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;   // (距离, 点)
    dist[s] = 0;
    pq.push({0, s});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;                        // 过期条目
        for (auto [v, w] : adj[u])
            if (d + w < dist[v]) { dist[v] = d + w; pq.push({dist[v], v}); }
    }
    return dist;
}
# import heapq。heapq 只有小根堆，正好对应 greater<>；元组 (距离, 点) 先比第一项
def dijkstra_heap(n, adj, s):
    dist = [INF] * n
    pq = []                                               # 普通列表，由 heapq 维护成堆
    dist[s] = 0
    heapq.heappush(pq, (0, s))
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue                          # 过期条目
        for v, w in adj[u]:
            if d + w < dist[v]:
                dist[v] = d + w; heapq.heappush(pq, (dist[v], v))
    return dist

负权边的反例。 Dijkstra 的正确性依赖"边权非负"。看下面这张有向图：

有向图含负权边 C→B=−10。Dijkstra 依次确定 A(0)、B(2)、D(3)、C(5)；真正的最短距离 B=−5、D=−4

Dijkstra 第 2 步就以 dist=2 确定了 B，随后用 B 确定 D=3。等到最后处理 C（dist=5）时，才发现 C→B 能让 B 变成 5−10=−5，但 B 和 D 已经"定死"不再更新。真正的最短距离是 B=−5、D=−4。有负权边时改用 Bellman-Ford 算法：对所有边重复松弛 n−1 轮，复杂度 O(ne)，第 n 轮若还能松弛，说明存在负环。

考场结论：

  • Dijkstra 求非负权图的单源最短路径，每次选未确定顶点中 dist 最小者，再松弛它的邻居。
  • 时间：数组 O(n²)，二叉堆 O((n+e) log n)。
  • Dijkstra 不适用于含负权边的图；有负权用 Bellman-Ford（O(ne)），无权图用 BFS（O(n+e)）。
  • 松弛公式：dist[v] = min(dist[v], dist[u] + w(u,v))，改小时记录前驱用于还原路径。

04.15 Floyd：所有顶点对之间的最短路径

为什么需要它。 有时我们要的是"任意两个城市之间"的最短距离，例如给 4 个网点之间做一张距离表。对每个顶点各跑一次 Dijkstra 当然可以；Floyd 算法用三重循环一次算出全部，代码只有几行，还允许负权边（不允许负环）。

它是什么。 用矩阵 D 记录距离，初始就是带权邻接矩阵。然后依次让 k=0, 1, …, n−1 作为"允许经过的中转点"：

D[i][j] = min(D[i][j], D[i][k] + D[k][j])

第 k 轮结束时，D[i][j] 表示"中间只经过 V0～Vk 时，从 Vi 到 Vj 的最短距离"。k 轮全部做完，所有顶点都允许作中转，D 就是最终答案。

void floyd(vector<vector<int>>& D) {
    int n = D.size();
    for (int k = 0; k < n; ++k)                           // k 必须在最外层
        for (int i = 0; i < n; ++i)
            for (int j = 0; j < n; ++j)
                if (D[i][k] < INF && D[k][j] < INF && D[i][k] + D[k][j] < D[i][j])
                    D[i][j] = D[i][k] + D[k][j];
}
# D 是列表的列表，函数里原地改，调用者看得到（相当于 vector<vector<int>>&）
# Python 整数不溢出；INF 取 float('inf') 时 inf + inf 仍是 inf，两个 < INF 判断可省，保留是为了和 C++ 对应
def floyd(D):
    n = len(D)
    for k in range(n):                                    # k 必须在最外层
        for i in range(n):
            for j in range(n):
                if D[i][k] < INF and D[k][j] < INF and D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]

D[i][k] < INF 的判断防止两个"无穷大"相加溢出。

04.16 拓扑排序：给有依赖的任务排顺序

为什么需要它。 选课时有先修关系：学"数据结构"前要学"程序设计"；项目构建时，模块要在它依赖的模块之后编译。我们要把所有任务排成一列，使每条依赖 u→v 中 u 都排在 v 前面。这样的序列叫拓扑序列。

它是什么。 用顶点表示活动、有向边表示先后关系的图叫 AOV 网（Activity On Vertex）。它必须是有向无环图（DAG）：有环就意味着 A 要在 B 之前、B 又要在 A 之前，无法排序。

课程依赖图（DAG）：A→B 表示先修 A 才能修 B

方法一：Kahn 算法（入度法）

  1. 统计每个顶点的入度，把入度为 0 的顶点放进队列（或栈）。
  2. 取出一个顶点输出，把它所有后继的入度减 1；减到 0 的入队。
  3. 重复，直到队列为空。若输出的顶点数少于 n，图中有环。

vector<int> kahn(int n, const vector<vector<int>>& out) {
    vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; ++u) for (int v : out[u]) ++indeg[v];
    queue<int> q;
    for (int v = 0; v < n; ++v) if (indeg[v] == 0) q.push(v);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : out[u]) if (--indeg[v] == 0) q.push(v);
    }
    return order;                                         // size < n 说明有环
}
# from collections import deque：popleft 是 O(1)
def kahn(n, out):
    indeg, order = [0] * n, []
    for u in range(n):
        for v in out[u]: indeg[v] += 1
    q = deque()
    for v in range(n):
        if indeg[v] == 0: q.append(v)
    while q:
        u = q.popleft()
        order.append(u)
        for v in out[u]:
            indeg[v] -= 1                                 # Python 没有 --x，先减再判断
            if indeg[v] == 0: q.append(v)
    return order                                          # len(order) < n 说明有环

方法二：DFS 逆后序

对 DAG 做 DFS，记录每个顶点结束（所有后继都处理完、即将返回）的顺序，叫后序。把后序反过来就是一个拓扑序列。原因是：对任意边 u→v，v 总是比 u 先结束（v 要么在 u 的递归里先结束，要么更早就已经结束），所以逆过来 u 在 v 前面。

在本节 DAG 上按 A、B、C… 的顺序启动 DFS，各邻接表按字母顺序：

过程说明
A → B → D → FF 没有后继，F 结束；回到 D，D 结束；回到 B，B 结束
A → CC 的后继 D 已访问；走 E，E 的后继 F 已访问，E 结束；C 结束
回到 AA 结束

后序：F D B E C A；逆后序：A C E B D F，这也是一个合法的拓扑序列。DFS 过程中如果遇到一条指向"还在递归栈上"的顶点的边（回边），说明有环。

拓扑序列是否唯一

本节 DAG 的拓扑序列一共有 5 个：ABCDEF、ABCEDF、ACBDEF、ACBEDF、ACEBDF。判断唯一性只看一点：Kahn 算法的每一步，入度为 0 的顶点是否都只有一个。本例输出 A 之后 B、C 同时入度为 0，所以不唯一。等价的说法是：图中存在一条经过所有顶点的路径时，拓扑序列唯一。

考场结论：

  • 拓扑排序只对 DAG 有定义；Kahn 法输出顶点数小于 n 时说明有环，可用来判断有向图是否有环。
  • 两种方法时间都是 O(n+e)（邻接表）。
  • 每一步可选的入度为 0 的顶点不止一个时，拓扑序列不唯一。
  • DFS 法：按顶点结束时间的逆序输出。

04.17 AOE 网与关键路径

为什么需要它。 一个工程由许多活动组成，有些可以并行，有些必须等前面完成。项目经理关心两件事：整个工程最少要多少天？哪些活动一旦拖延，整个工程就会延期？关键路径方法回答这两个问题。

它是什么。 AOE 网（Activity On Edge）用边表示活动、边权表示活动持续时间，用顶点表示事件（"它之前的活动全部完成，它之后的活动可以开始"这一时刻）。只有一个入度为 0 的源点（开工）和一个出度为 0 的汇点（完工）。

最后两行说明：有多条关键路径时，只缩短其中一条上的活动，工期不变；要缩短所有关键路径共有的活动（例如 a8），或者同时缩短每条关键路径。

代码。 变量表：ve/vl 按事件编号存，e/l 按活动编号存；先用 Kahn 求拓扑序，正推 ve、逆推 vl。

void criticalPath(int n, const vector<tuple<int,int,int>>& acts,
                  vector<int>& ve, vector<int>& vl, vector<int>& e, vector<int>& l) {
    vector<vector<int>> out(n);
    for (auto [u, v, w] : acts) { (void)w; out[u].push_back(v); }
    vector<int> topo = kahn(n, out);
    ve.assign(n, 0);
    for (int u : topo)                                    // 正推：取最大
        for (auto [a, b, w] : acts) if (a == u) ve[b] = max(ve[b], ve[a] + w);
    vl.assign(n, ve[topo.back()]);
    for (int k = n - 1; k >= 0; --k) {                    // 逆推：取最小
        int u = topo[k];
        for (auto [a, b, w] : acts) if (a == u) vl[a] = min(vl[a], vl[b] - w);
    }
    e.clear(); l.clear();
    for (auto [a, b, w] : acts) { e.push_back(ve[a]); l.push_back(vl[b] - w); }
}
# acts 是 (起点, 终点, 时长) 元组的列表。C++ 用四个引用参数带回结果，Python 直接返回元组
def critical_path(n, acts):
    out = [[] for _ in range(n)]                          # 不能写 [[]] * n：那是 n 个同一列表的引用
    for u, v, w in acts: out[u].append(v)
    topo = kahn(n, out)
    ve = [0] * n
    for u in topo:                                        # 正推：取最大
        for a, b, w in acts:
            if a == u: ve[b] = max(ve[b], ve[a] + w)
    vl = [ve[topo[-1]]] * n                               # 整数列表用 * n 没问题
    for k in range(n - 1, -1, -1):                        # 逆推：取最小
        u = topo[k]
        for a, b, w in acts:
            if a == u: vl[a] = min(vl[a], vl[b] - w)
    e = [ve[a] for a, b, w in acts]
    l = [vl[b] - w for a, b, w in acts]
    return ve, vl, e, l

为了代码简短，内层每次扫描全部活动，复杂度是 O(n·e)；改为按邻接表只扫描 u 的出边就是 O(n+e)。

考场结论：

  • 关键路径是源点到汇点的最长路径，长度 = 工程最短完成时间。
  • ve 正推取 max，vl 逆推取 min；e(i)=ve(起点)，l(i)=vl(终点)−时长；l(i)=e(i) 的活动是关键活动。
  • 关键路径可能不止一条；缩短关键活动可以缩短工期，但缩短过多会出现新的关键路径；有多条关键路径时，只有缩短所有关键路径共有的活动才能缩短工期。
  • 延长任一关键活动，工期一定延长。

04.18 扩展：线段树与树状数组（了解）

为什么需要它。 数组既要支持"修改某个元素"，又要支持"查询某一段的和 / 最大值"，两种操作都很频繁时，直接扫区间是 O(n)，维护前缀和又让修改变成 O(n)。线段树和树状数组把两种操作都做到 O(log n)。它们不属于图算法，但常和本章一起考名字和复杂度。

线段树。 一棵二叉树，每个结点管理数组的一段区间并保存这段的和（或最大值），根管理整个数组，每个结点把区间对半分给两个孩子。数组 [2, 1, 5, 3]：

查询 [1,3] 的和：拆成 [1] 和 [2,3] 两个结点，1+8=9。任何区间最多拆成 O(log n) 个结点，单点修改只影响从叶子到根的一条路径，所以查询和单点修改都是 O(log n)。区间修改（把一段都加上 x）时，用懒标记：先把"这一段都要加 x"记在覆盖它的结点上，暂不往下改，等以后真的访问到它的孩子时再把标记传下去，这样区间修改也是 O(log n)。

树状数组（Fenwick 树）。 用一个数组 c，c[i] 保存原数组中以 i 结尾、长度为 lowbit(i) 的一段之和，lowbit(i)=i & (−i) 是 i 的二进制最低位 1 所代表的值（例如 lowbit(6)=2）。前缀和查询沿 i −= lowbit(i) 往前跳，单点更新沿 i += lowbit(i) 往后跳，都是 O(log n)。代码比线段树短得多，但只适合"前缀可加减"的统计（如求和），区间最值不方便。

考场结论：

  • 线段树：区间查询、单点修改 O(log n)；区间修改配合懒标记也是 O(log n)；空间约 4n。
  • 树状数组：前缀和查询、单点修改 O(log n)，空间 n；核心操作 lowbit(x)=x&(−x)。

易错点： 树状数组下标从 1 开始，因为 lowbit(0)=0，从 0 开始会死循环。

速记： 线段树二分区间存段和，配懒标记做区间改；树状数组靠 lowbit 跳，前缀和 O(log n)。
