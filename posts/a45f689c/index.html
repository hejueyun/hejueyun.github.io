14.1 Shell 与命令格式：一条命令由哪几部分组成

我们登录一台 Linux 服务器，看到的是一个闪烁的提示符。在这里输入的每一行字，都先交给一个叫 Shell 的程序解释，再由它去启动真正干活的程序。银行科技岗的日常运维、笔试里的命令题，都建立在"看懂一行命令"这件事上。

Shell 是什么。 Shell 是用户和内核之间的"翻译"：它读入一行文字，按空格切成若干个词，展开其中的变量和通配符，再找到对应的程序运行。Linux 默认的 Shell 是 Bash（Bourne Again Shell），其他常见的还有 sh、zsh、csh、ksh。提示符末尾是 $ 表示普通用户，是 # 表示 root（超级管理员）。

命令的三部分。 一条命令写成 命令 [选项] [参数]：

  • 命令：要运行的程序名，例如 ls、grep。
  • 选项：改变命令行为的开关，短选项是一个减号加一个字母（-l），多个短选项可以合写（-lh 等于 -l -h）；长选项是两个减号加单词（--human-readable）。
  • 参数：命令要处理的对象，通常是文件名、目录名或字符串。

Shell 按空格切成 4 个词：第 1 个是命令，以 - 开头的是选项，其余是参数

Shell 拿到一行命令后，要经过下面几步才真正执行：

Shell 先切词、展开，再查找并运行程序；程序通过系统调用请内核干活

第 ③ 步里有两类命令：内建命令（cd、echo、export、source 等，由 Shell 自己执行，不新开进程）和外部命令（ls、grep 等，是磁盘上的一个可执行文件）。type cd 会显示 cd is a shell builtin，type ls 会显示它的路径。cd 必须是内建命令，因为"当前目录"是 Shell 这个进程自己的属性，只有它自己能改。

man 手册分节：1 是用户命令，2 是系统调用，3 是库函数，5 是配置文件格式，8 是管理员命令。man 5 passwd 查的是 /etc/passwd 文件格式，man 1 passwd 查的是改密码命令。[6]

完整走一遍： grep -in error app.log 被切成 4 个词：grep 是命令；-in 是合写的两个短选项 -i（忽略大小写）和 -n（显示行号）；error 是第一个参数（要找的模式）；app.log 是第二个参数（要找的文件）。

考场结论：

  • 命令格式是"命令 + 选项 + 参数"，短选项可以合写，-lh = -l -h。
  • $ 提示符是普通用户，# 是 root。
  • 查帮助用 man、--help；cd 是 Shell 内建命令。

14.2 文件系统与 FHS：每个目录放什么

笔试常问"系统配置文件放在哪个目录""日志在哪看"，运维时也要知道去哪里找东西。Linux 用一套统一的目录约定回答这个问题。

一棵树，从根开始。 Windows 按"C 盘、D 盘"组织文件；Linux 只有一棵目录树，最顶层是根目录 /。各个磁盘分区通过挂载（mount）接到这棵树的某个目录上，例如第二块硬盘可以挂到 /data，之后访问 /data 就是访问那块硬盘。FHS（Filesystem Hierarchy Standard，文件系统层次结构标准）规定了顶层各目录的用途，各发行版基本遵守。[7] [8] [9]

目录放什么常见例子
/etc系统和软件的配置文件/etc/passwd（用户）、/etc/shadow（密码哈希）、/etc/fstab（开机挂载）、/etc/ssh/sshd_config
/home普通用户的家目录/home/alice，~ 就是它
/rootroot 用户的家目录和 /home 分开
/usr/bin、/usr/sbin用户命令、管理员命令/usr/bin/ls；Ubuntu 中 /bin 是指向 /usr/bin 的链接
/usr/lib、/usr/local库文件；自己编译安装的软件/usr/local/bin
/var/log日志/var/log/syslog、/var/log/auth.log（登录记录）
/var/lib、/var/spool程序状态数据；排队任务数据库文件、crontab 任务
/tmp临时文件，所有人可写重启可能清空
/boot内核和引导程序vmlinuz、grub/
/dev设备文件/dev/sda（第一块磁盘）、/dev/null（黑洞）
/proc、/sys内核提供的虚拟文件，不占磁盘/proc/cpuinfo、/proc/meminfo、/proc/1234/
/mnt、/media、/opt临时挂载点；U 盘；第三方软件

/proc 很特别。 它里面的"文件"由内核在读取时现场生成：cat /proc/meminfo 读到的是此刻的内存统计，/proc/PID/ 目录对应一个正在运行的进程。ps、free、top 这些命令的数据都来自 /proc。[10]

/etc/passwd 的 7 个字段。 每行一个用户，用冒号分隔：

alice:x:1001:1001:Alice Wang:/home/alice:/bin/bash
用户名:密码占位:UID:GID:说明:家目录:登录 Shell

第二个字段是 x，真正的密码哈希放在只有 root 可读的 /etc/shadow 里。UID 为 0 的是 root。[11]

路径的写法。 从 / 开始的是绝对路径（/home/alice/a.txt）；不以 / 开始的是相对路径，从当前目录算起。. 是当前目录，.. 是上一级，~ 是家目录，cd - 回到上一次所在的目录，pwd 显示当前目录。

考场结论：

  • 配置在 /etc，日志在 /var/log，用户家目录在 /home，命令在 /usr/bin，内核和进程信息在 /proc。
  • /etc/passwd 存用户信息，密码哈希在 /etc/shadow。
  • Linux 只有一棵目录树，分区通过挂载接入。

14.3 文件与目录操作：建、复制、移动、删除

整理日志、部署程序、备份数据，都离不开新建、复制、移动和删除文件。这几个命令每天都在用，也是笔试的基础题。

命令作用常用写法
mkdir新建目录mkdir -p a/b/c：父目录不存在就一并建出，已存在也不报错
touch文件不存在就新建空文件；存在就把时间改成现在touch a.txt
cp复制cp a.txt b.txt；复制目录要加 -r：cp -r dir1 dir2；-p 保留权限和时间
mv移动或改名（同一个命令）mv a.txt b.txt 改名；mv a.txt dir/ 移进目录
rm删除rm a.txt；删目录 rm -r dir；-f 强制、不提示
rmdir只删空目录比 rm -r 安全
ln -s建符号链接（快捷方式）ln -s 目标 链接名，详见 14.5

几个细节。

  • cp a.txt dir/ 与 mv a.txt dir/ 中，目标是已存在的目录时，文件放进目录里；目标不存在时，就当作新名字。
  • mv 在同一个文件系统内只是改目录项，瞬间完成，和文件大小无关；跨文件系统时等于"复制 + 删除"。
  • 文件名以 . 开头的是隐藏文件，ls 看不到，ls -a 才能看到。
  • 批量操作可以用通配符：* 匹配任意多个字符，? 匹配一个字符，[abc] 匹配其中一个。rm *.log 删除当前目录所有 .log 文件。通配符由 Shell 展开，命令收到的是展开后的文件名列表。

考场结论：

  • 建多级目录用 mkdir -p；复制目录用 cp -r；改名和移动都用 mv。
  • rm -rf 目录 递归强制删除，rmdir 只删空目录。
  • touch 既能建空文件，也能更新时间戳。

14.4 读懂 ls -l：权限、chmod、chown、umask 与特殊权限位

服务器上一个脚本"Permission denied"，一个配置文件被别人改了，排查的第一步都是 ls -l。这一节我们把一行 ls -l 的每一列拆开，再学会改权限。

一行 ls -l 的 7 个字段

$ ls -l notes.txt
-rw-r--r-- 2 alice dev 1288 Oct  1 09:30 notes.txt

ls -l 的一行由 7 个字段组成；第 ② 列是硬链接数

字段本例含义
① 类型 + 权限-rw-r--r--第 1 个字符是文件类型，后 9 个是三组权限
② 硬链接数2有几个文件名指向同一个 inode（14.5）；目录的这个数 = 2 + 子目录个数
③ 属主alice文件的拥有者（user）
④ 属组dev文件所属的用户组（group）
⑤ 大小1288字节数；目录常显示 4096，那是目录文件自身占的一个块，与里面文件的总大小无关（要看总大小用 du -sh）
⑥ 时间Oct 1 09:30最后修改时间 mtime；超过半年的文件改为显示年份
⑦ 文件名notes.txt符号链接会显示成 soft -> notes.txt

第一个字符：文件类型。

字符类型例子
-普通文件文本、二进制程序、压缩包
d目录/etc
l符号链接/bin -> usr/bin
b块设备/dev/sda 磁盘
c字符设备/dev/null、终端
s套接字/run/docker.sock
p命名管道mkfifo 创建

后 9 位：三组 rwx

9 个权限字符每 3 个一组，依次属于属主 u、属组 g、其他人 o。系统判断权限时，先看你是不是属主，是就只用第一组；不是属主但在属组里，就只用第二组；都不是，用第三组。

-rw-r--r--：普通文件；属主可读写，属组和其他人只读

r、w、x 对文件和目录的含义不同：

权限对普通文件对目录
r（读）读内容（cat）列出目录里的文件名（ls）
w（写）修改内容在目录里新建、删除、改名文件
x（执行）作为程序运行进入目录（cd）、访问其中的文件

所以删除一个文件看的是它所在目录的 w 和 x 权限，与文件自己有没有 w 无关。

数字权限：r=4、w=2、x=1

每组 3 位看成一个三位二进制数，r 在最高位（4），w 在中间（2），x 在最低位（1）。把一组里有的权限加起来，就得到一个 0～7 的八进制数字。

每个八进制数字对应 3 位：r=4、w=2、x=1；高亮的 4、5、6、7 最常用

三组拼起来就是三位数字：

数字权限串含义典型用途
755rwxr-xr-x属主全部；其他人读和执行目录、可执行程序、脚本
644rw-r--r--属主读写；其他人只读普通文件、网页
600rw-------只有属主能读写私钥 ~/.ssh/id_ed25519
700rwx------只有属主能进入~/.ssh 目录
777rwxrwxrwx所有人全部权限很少需要，生产环境应避免

完整走一遍： rwxr-x--- 换成数字：属主 rwx = 4+2+1 = 7；属组 r-x = 4+0+1 = 5；其他 --- = 0，结果 750。反过来，640 = 6(rw-) 4(r--) 0(---)，即 rw-r-----。

chmod：两种写法

chmod 755 deploy.sh          # 数字法：一次设定全部 9 位
chmod u+x deploy.sh          # 符号法：给属主加执行
chmod g-w,o-r report.txt     # 属组去掉写，其他人去掉读
chmod a=r readme.txt         # 所有人（a = u+g+o）都只剩读
chmod -R 755 site/           # -R：递归处理目录下的所有文件

符号法的格式是"谁 + 动作 + 权限"：谁是 u、g、o、a；动作 + 加上、- 去掉、= 设成；没提到的位保持不变。例如文件原来是 664（rw-rw-r--），执行 chmod u+x,g-w 后：属主加 x 变 rwx(7)，属组去 w 变 r--(4)，其他人不变 r--(4)，结果 744。[12]

chown、chgrp：改属主和属组

chown bob report.txt          # 属主改为 bob
chown bob:dev report.txt      # 同时改属主和属组
chgrp dev report.txt          # 只改属组
chown -R www-data:www-data /var/www   # 递归修改整个目录

普通用户只能改自己文件的属组，改属主需要 root，所以通常写成 sudo chown ...。sudo 以 root 身份执行一条命令；su - bob 切换成 bob 登录；id 显示自己的 UID、GID 和所属组；useradd/adduser 建用户，passwd 改密码。[13]

umask：新文件的默认权限

新建文件时，程序会申请一个"最大权限"：普通文件一般申请 666（不给执行位），目录申请 777。umask 是一个"屏蔽码"，它为 1 的位会从申请的权限中去掉：

最终权限 = 申请权限 & ~umask（按位与上 umask 的取反）

umask 022：把属组和其他人的 w 位屏蔽掉

umask新文件新目录场景
022644755Ubuntu 默认
027640750其他人完全不可访问
077600700只有自己可访问

这里要按位计算。umask 是 033 时，文件结果是 666 & ~033 = 644，而按十进制减法 666 − 033 会得到 633，是错的：申请的 666 里其他人本来就没有 x 位，屏蔽一个本来就没有的位，结果不变。umask 命令显示当前值，umask 027 修改当前 Shell 的值；umask 只影响之后新建的文件，已有文件用 chmod 改。[14]

特殊权限位：SUID、SGID、Sticky

在三位数字前面再加一位，就是特殊权限位：

位数字显示位置作用例子

14.5 inode、硬链接与软链接、三种时间

"磁盘还有 30% 空间却提示 No space left""删了大日志磁盘空间没释放""ln 和 ln -s 有什么区别"，这些问题都要从 inode 讲起。

inode 是什么。 文件系统把每个文件拆成两部分保存：

  • inode（索引节点）：保存文件的元数据——类型、权限、属主、属组、大小、三个时间戳、硬链接数，以及数据块在磁盘上的位置。每个 inode 有一个编号，ls -i 可以看到。
  • 数据块：文件的实际内容。

文件名不在 inode 里，它保存在所在目录的目录项中。目录本身也是一个文件，内容就是一张"文件名 → inode 号"的表。[15]

硬链接是同一个 inode 的第二个名字；软链接是一个独立的小文件，内容是目标路径

硬链接与软链接

ln notes.txt hard       # 硬链接：给 inode 953122 再起一个名字
ln -s notes.txt soft    # 软链接（符号链接）：新建一个文件，内容是路径 "notes.txt"
ls -li
# 953122 -rw-r--r-- 2 alice dev 1288 Oct  1 09:30 hard
# 953122 -rw-r--r-- 2 alice dev 1288 Oct  1 09:30 notes.txt
# 953123 lrwxrwxrwx 1 alice dev    9 Oct 16 10:00 soft -> notes.txt

注意输出里的三个信号：hard 和 notes.txt 的 inode 号相同、链接数都变成 2；soft 的 inode 号不同，大小是 9，正好是字符串 notes.txt 的长度。[16]

对比项硬链接 ln软链接 ln -s
本质同一个 inode 的另一个名字独立文件，内容是目标路径
inode 号与原文件相同自己有一个新的
删除原文件后仍能访问，内容还在变成"断链"，访问报 No such file
跨文件系统不支持（inode 号只在本文件系统内有效）支持
链接目录不允许允许
类似同一个人的两个名字Windows 的快捷方式

删除的真正含义。 rm notes.txt 只是删掉一个目录项，并把 inode 的链接数减 1。当链接数变成 0、并且没有进程还打开着它时，inode 和数据块才真正释放。这解释了一个经典现象：某个程序正在写一个 10 GB 的日志，你 rm 了它，df 显示空间没变——因为进程仍持有文件描述符。用 lsof | grep deleted 找到这个进程，重启它或清空文件（> big.log）才能释放。

inode 也会用完。 每个文件占一个 inode，inode 总数在格式化时确定。大量小文件（比如几百万个缓存文件）可能把 inode 用光，此时 df -h 显示还有空间，却无法新建文件。df -i 查看 inode 使用率。

三种时间：atime、mtime、ctime

时间全称什么时候更新查看
atimeaccess time，访问时间读取文件内容（cat）ls -lu
mtimemodify time，修改时间文件内容被修改ls -l（默认）
ctimechange time，状态改变时间inode 元数据改变：chmod、chown、改链接数、改名；修改内容时也会顺带更新ls -lc

ctime 是"状态改变时间"，不是创建时间。 名字里的 c 指 change。传统 Unix 的 inode 不记录创建时间；新版 Linux（ext4 等文件系统 + statx 接口）另有一个"诞生时间" birth time，stat 输出的 Birth: 一行就是它。stat 文件名 一次显示全部时间。[17]

14.7 重定向、文件描述符与管道

我们常把命令输出存进文件，或把错误信息单独记录，或把一个命令的输出交给另一个命令处理。这三件事分别叫输出重定向、错误重定向和管道，背后是同一个概念：文件描述符。

文件描述符是什么。 进程每打开一个文件，内核就在这个进程的"打开文件表"里占一个位置，位置编号就是文件描述符（fd），一个小整数。每个进程启动时自带三个：

fd名字默认指向用途
0标准输入 stdin键盘（终端）读入数据
1标准输出 stdout屏幕（终端）正常结果
2标准错误 stderr屏幕（终端）错误信息

程序只管往 fd 1 写结果、往 fd 2 写错误，至于 fd 1 最终连到屏幕还是文件，由 Shell 在启动程序前安排好。这就是重定向：改变 fd 指向哪里。[21]

写法含义
cmd > out.txtfd 1 指向 out.txt，覆盖原内容（文件不存在则新建）
cmd >> out.txtfd 1 指向 out.txt，追加到末尾
cmd 2> err.txtfd 2 指向 err.txt
cmd < in.txtfd 0 从 in.txt 读
cmd 2>&1让 fd 2 指向"fd 1 此刻指向的地方"
cmd > /dev/null 2>&1输出和错误都丢弃
cmd &> all.txtBash 写法，等价于 > all.txt 2>&1

2>&1 的顺序：从左到右处理

重定向按从左到右的顺序执行，2>&1 只是复制 fd 1 当时的去向，之后 fd 1 再变，fd 2 不会跟着变。我们用 ls nofile .（列出一个不存在的文件和当前目录）分别试两种顺序：

所以要把"输出和错误都存进文件"，标准写法是 cmd > file 2>&1，2>&1 放在后面。

sudo 与重定向。 sudo echo x >> /etc/hosts 会报 Permission denied：重定向由当前（普通用户的）Shell 在启动 sudo 之前完成，sudo 只提升了 echo 的权限。正确写法是 echo x | sudo tee -a /etc/hosts（tee 自己以 root 身份打开文件），或 sudo sh -c 'echo x >> /etc/hosts'。

管道：把前一个命令的输出接到后一个命令的输入

cmd1 | cmd2 让内核建一个管道（一块内存缓冲区），把 cmd1 的 fd 1 接到管道写端，cmd2 的 fd 0 接到管道读端。两个命令同时运行，cmd1 边写，cmd2 边读；缓冲区满了 cmd1 等待，空了 cmd2 等待。[22]

管道只连接 stdout；stderr 默认仍然打到终端，要一起送进管道写成 cmd 2>&1 | ...

退出码与逻辑连接。 每个命令结束时返回一个 0～255 的退出码：0 表示成功，非 0 表示失败，Shell 把它存在 $? 里。

写法含义
cmd1 ; cmd2顺序执行，不管成败
cmd1 && cmd2cmd1 成功（退出码 0）才执行 cmd2
cmd1 || cmd2cmd1 失败才执行 cmd2
cmd1 | cmd2管道；整体退出码默认取最后一个命令

例如 mkdir -p build && cd build 只有目录建成才进入；grep -q ERROR app.log || echo "没有错误"。管道 false | true 的退出码是 0，因为看的是最后的 true；执行 set -o pipefail 后，管道中任一命令失败，整体就算失败。

考场结论：

  • fd 0 标准输入、1 标准输出、2 标准错误；> 覆盖，>> 追加。
  • 重定向从左到右处理；cmd > file 2>&1 输出和错误都进文件，cmd 2>&1 > file 错误仍去终端。
  • 管道只传 stdout；&& 前成功才执行后者，|| 前失败才执行后者；退出码 0 表示成功。

易错点： > 会清空原文件，想追加要用 >>；2>&1 中间没有空格，写成 2> &1 会出错；Shell 把退出码 0 当"真"，这和 C 语言里 0 为假的习惯相反。

速记： 0 入 1 出 2 错；重定向从左到右，> file 2>&1；管道只接 stdout；0 是成功。

grep：按内容挑行

grep 输出包含指定模式的行。[23]

选项作用例子

sed：按行编辑

sed 逐行读入、按命令修改、再输出，默认不改原文件。[24]

写法作用
sed 's/old/new/' f每行把第一个 old 换成 new

awk：按列计算的小语言

awk 把每行按空白（或 -F 指定的分隔符）切成字段，$1、$2… 是各字段，$0 是整行。一个 awk 程序由三段组成：[25] [26]

awk 'BEGIN { 开始前执行一次 }  模式 { 每行满足模式时执行 }  END { 全部读完后执行一次 }' 文件

awk 的执行流程：BEGIN 一次 → 每行切字段、判断模式、执行动作 → END 一次

内置变量含义
$0、$1…$NF整行；第 1 个字段…最后一个字段
NR已读入的行数（当前是第几行）
NF当前行的字段个数
-F（即 FS）输入字段分隔符，如 -F:、-F,
OFS输出字段分隔符，默认空格
-v 名=值从 Shell 传变量进来

在 access.log 上的例子（输出都经过实际运行）：

awk '{print $1, $9}' access.log          # 打印 IP 和状态码
awk 'NR==2 {print NF}' access.log         # 第 2 行有几个字段 → 10
awk '$9 >= 400 {print $1, $7, $9}' access.log
# 10.0.0.3 /admin 404
# 10.0.0.2 /api/data 500
awk '{s += $10} END {print s, NR, s/NR}' access.log   # 总字节、行数、平均 → 1248 6 208
awk -F: '$3 >= 1000 {print $1}' /etc/passwd           # 列出 UID ≥ 1000 的普通用户
awk '{c[$7]++} END {for (u in c) print c[u], u}' access.log   # 用关联数组按 URL 计数

几个要点：awk 里没有赋值的变量初始为 0 或空串，所以 s += $10 不用先声明；print a, b 中的逗号输出为空格，print a b 直接拼接；单引号里的 $1 是 awk 的字段，Shell 不会碰它。

命令作用常用选项
sort排序（默认按字符串）-n 按数值，-r 倒序，-k2 按第 2 列，-t, 指定分隔符，-u 去重

wc计数-l 行数，-w 单词数，-c 字节数

uniq 只看相邻行，所以统计次数前一定先 sort，把相同的行排到一起。sort -u 等价于 sort | uniq。cut 只认单个字符作分隔符，连续两个空格之间会被当成一个空字段；awk 默认把连续空白看成一个分隔，处理对齐的输出（如 ps）时用 awk 更稳。

14.9 进程管理与信号

程序卡死要结束它、任务要放到后台跑、退出登录后程序还要继续运行，这些都要会管理进程。

进程与进程树。 每个运行中的程序是一个进程，有唯一编号 PID，以及创建它的父进程编号 PPID。系统启动后内核创建 1 号进程 systemd（所有用户进程的祖先）和 2 号进程 kthreadd（内核线程的祖先）；之后每个进程都由父进程 fork 出来，形成一棵树。pstree -p 能画出这棵树。

实线是父子关系；虚线是信号：kill 默认发 SIGTERM，Ctrl+C 给前台进程发 SIGINT

查看进程：ps 与 top

$ ps -ef | head -3
UID        PID  PPID  C STIME TTY          TIME CMD
root         1     0  0 06:50 ?        00:00:01 /sbin/init
root         2     0  0 06:50 ?        00:00:00 [kthreadd]

$ ps aux | head -2
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.1  0.0  20944  5896 ?        Ss   06:50   0:01 /sbin/init

ps -ef 是 System V 风格，带 PPID；ps aux 是 BSD 风格，带 CPU、内存占用。最常用的是 ps -ef | grep nginx 或 ps aux | grep nginx 找某个程序的进程，也可以直接 pgrep -a nginx。[27]

列含义
VSZ虚拟内存大小（KiB）：进程申请、映射的全部地址空间，含还没真正用到的部分和共享库
RSS常驻内存（KiB）：此刻真正占用的物理内存
STAT状态：R 运行、S 可中断睡眠、D 不可中断睡眠（多为等磁盘 I/O）、T 停止、Z 僵尸
TIME累计占用的 CPU 时间

top 是实时刷新的 ps：第一行是运行时间和 1、5、15 分钟平均负载；%Cpu(s) 行的 us 是用户态、sy 是内核态、id 是空闲、wa 是等待 I/O；进程列表里 VIRT 对应 ps 的 VSZ，RES 对应 RSS，SHR 是其中可共享的部分。排查"谁吃内存"看 RES，VIRT 大通常没关系。按 P 按 CPU 排序、M 按内存排序、k 输入 PID 发信号、q 退出。[28]

僵尸进程（Z）是已经结束、但父进程还没调用 wait 收尸的进程，它只占一个进程表项。kill 僵尸本身没有用，要处理它的父进程。

信号：通知进程"发生了某件事"

信号编号触发方式默认动作能否捕获
SIGHUP1终端断开终止能；守护进程常用它"重新加载配置"
SIGINT2Ctrl+C终止能
SIGQUIT3Ctrl+\终止并生成 core能
SIGKILL9kill -9立即终止不能捕获、不能忽略
SIGTERM15kill（默认）终止能，程序可以先清理再退出
SIGCONT18fg、bg继续运行
SIGSTOP19kill -STOP暂停不能
SIGTSTP20Ctrl+Z暂停能

（编号以 x86 和 ARM 上的 Linux 为准，kill -l 列出全部。）[29] [30]

kill 的正确用法。 kill PID 先发 SIGTERM，给程序机会保存数据、删除临时文件；等几秒还不退出，再 kill -9 PID 强制结束。killall nginx、pkill -f app.py 按名字发信号。被信号终止的进程，退出码是 128 + 信号编号：被 SIGKILL 杀死得 137，被 SIGTERM 终止得 143，Ctrl+C 中断得 130。

前台、后台与作业控制

jobs 列出当前 Shell 的作业；%1 是作业号，和 PID 是两回事

python3 train.py &          # 末尾 & 放到后台运行，Shell 打印 [1] 2400
jobs                        # [1]+  Running   python3 train.py &
fg %1                       # 调回前台
# 按 Ctrl+Z 暂停，再 bg %1 让它在后台继续
nohup python3 train.py > train.log 2>&1 &   # 退出登录后继续运行

nohup 解决什么问题。 关闭终端或 SSH 断开时，Shell 会给它的作业发 SIGHUP，默认动作是终止。nohup 让程序忽略 SIGHUP；如果没有重定向输出，它会把输出写进 nohup.out。& 只负责"放后台"，不负责"断线不死"，所以长任务的标准写法是 nohup 命令 > 日志 2>&1 &。需要断线后还能重新连回去看的，用 tmux 或 screen。[31]

考场结论：

  • ps -ef / ps aux 看进程，top 实时监控；RSS/RES 是实际占用的物理内存，VSZ/VIRT 是虚拟地址空间。
  • kill 默认发 15 SIGTERM，kill -9 发 SIGKILL，后者不能被捕获；Ctrl+C 是 SIGINT(2)，Ctrl+Z 是 SIGTSTP(20)。
  • & 后台运行，jobs 查看，fg/bg 切换；nohup 忽略 SIGHUP，断开终端后进程继续运行。

14.10 系统与网络状态：负载、内存、磁盘、端口

接到"系统变慢了""端口起不来""磁盘满了"的告警时，我们需要几条命令在一分钟内看清 CPU、内存、磁盘和网络的状态。[32]

排查时按问题选命令

uptime 与负载。 uptime 输出 07:08:19 up 17 min, 1 user, load average: 0.60, 0.83, 0.60，三个数是最近 1、5、15 分钟的平均负载：处于可运行状态（R）和不可中断等待（D）的进程数的平均值。负载持续高于 CPU 核数（nproc 查看），说明有任务在排队。[33]

free 看内存。

$ free -h
               total        used        free      shared  buff/cache   available
Mem:           7.8Gi       718Mi       6.6Gi        14Mi       798Mi       7.1Gi
Swap:             0B          0B          0B

Linux 会把空闲内存拿来做磁盘缓存（buff/cache），需要时再还给程序，所以 free 一列小不代表内存紧张。判断还能用多少，看 available。Swap 是磁盘上的交换空间，内存不足时把不常用的页换出去。[34]

df 与 du 看磁盘。 df -h 按文件系统（分区）显示总量、已用、可用和挂载点；du -sh 目录 统计某个目录下文件实际占用的空间。找大目录的惯用法：du -sh /var/* | sort -rh | head（-h 让 sort 能比较 1.2G 和 300M）。两者对不上时，常见原因是"文件已删除但仍被进程打开"（14.5）。

ss 与 netstat 看端口。 ss -lntp 是最常用的组合：

ss -lntp：列出正在监听的 TCP 端口及占用它的进程；-u 换成 UDP，-a 显示全部连接

$ sudo ss -lntp
State   Recv-Q  Send-Q   Local Address:Port   Peer Address:Port  Process
LISTEN  0       511            0.0.0.0:80          0.0.0.0:*      users:(("nginx",pid=812,fd=6))
LISTEN  0       128            0.0.0.0:22          0.0.0.0:*      users:(("sshd",pid=700,fd=3))

-n 让端口显示成 80 而不是 http，也省去反查域名的时间；-p 要看到其他用户的进程需要 sudo。netstat 是更老的工具（netstat -anp、netstat -lntp，选项含义相同），在 Ubuntu 上要先装 net-tools 包，新系统推荐用 ss。[35] [36]

lsof：列出打开的文件。 Linux 里网络连接也是文件，所以 lsof -i :80 能看出谁占用了 80 端口，lsof -p 2400 列出某进程打开的全部文件，lsof | grep deleted 找"已删除但未释放"的文件。[37]

其他常用。 who / w 看当前登录的用户（读 /var/run/utmp），last 看历史登录记录（读 /var/log/wtmp），这两个文件是二进制格式，要用命令读；uname -a 看内核版本；ip addr 看 IP 地址；ping、curl -I 测连通和 HTTP 状态；journalctl 看 systemd 日志。

考场结论：

  • 平均负载看 uptime/top 的 load average，三个数是 1、5、15 分钟。
  • free 看 available；df 看分区，du 看目录；df -i 看 inode。
  • ss -lntp = 监听 + 数字端口 + TCP + 进程；查端口占用也可用 lsof -i :端口。

14.11 Shell 脚本编程：变量、参数、条件、循环、函数

每天都要做的事——统计日志、备份目录、批量改名——写成脚本就能一条命令完成，还能交给 crontab 定时执行。银行笔试里的 Shell 题，几乎都考本节的特殊变量、test 和引号。[2] [38] [39]

第一个脚本与三种运行方式

#!/bin/bash
# hello.sh：第一行 #!（shebang）告诉系统用哪个解释器运行这个文件
name="World"
echo "Hello, $name"
运行方式需要 x 权限在哪个进程里执行脚本里的变量改动
chmod +x hello.sh; ./hello.sh需要新的子进程（按 #! 选解释器）脚本结束就消失
bash hello.sh不需要新的子进程（#! 被当成注释）脚本结束就消失
source hello.sh 或 . hello.sh不需要当前 Shell留在当前 Shell

./ 和 bash 会新开子进程，source 在当前 Shell 中执行；修改 ~/.bashrc 后用 source 让它立即生效

变量、引号与环境变量

count=3                 # 赋值：等号两边不能有空格
echo "$count"           # 引用：$变量名
echo "${count}rd"       # 花括号标明变量名到哪结束 → 3rd
today=$(date +%F)       # 命令替换：把命令的输出赋给变量；老写法是反引号 `date +%F`
n=$((count * 2 + 1))    # 算术展开：整数运算 → 7

Shell 变量没有类型，都按字符串存，算术时才当整数用；没赋值的变量是空串。

引号效果例子（name=Tom）
单引号 '…'全部原样，什么都不展开'$name' → $name

完整脚本一：日志统计

把 14.8 学的管道包装成一个带参数检查、函数、条件和循环的脚本 practice/ch14_logstat.sh：

#!/bin/bash
# 用法：ch14_logstat.sh 日志文件 [TOP条数]
# 统计访问日志：总请求数、访问最多的 IP、各状态码的次数和占比

usage() {
    echo "用法: $0 日志文件 [TOP条数]" >&2
    exit 1
}

[ $# -ge 1 ] || usage              # 一个参数都没有：打印用法，退出码 1
log=$1
top=${2:-3}                        # 第二个参数没给时取 3

if [ ! -f "$log" ]; then
    echo "错误: 找不到文件 $log" >&2
    exit 2
fi

total=$(wc -l < "$log")
echo "总请求数: $total"

echo "访问最多的 $top 个 IP:"
cut -d' ' -f1 "$log" | sort | uniq -c | sort -nr | head -n "$top"

echo "状态码统计:"
awk '{print $9}' "$log" | sort | uniq -c | while read -r cnt code; do
    pct=$(( cnt * 100 / total ))
    echo "  $code: $cnt 次 ($pct%)"
done

errors=$(awk '$9 >= 400' "$log" | wc -l)
if [ "$errors" -gt 0 ]; then
    echo "警告: 有 $errors 个错误请求"
    exit 3
fi
exit 0

变量表： log 日志文件路径；top 要显示前几名，默认 3；total 总行数；cnt、code 每种状态码的次数和代码；pct 整数百分比；errors 状态码 ≥ 400 的行数。

#!/bin/bash
# 用法：ch14_backup.sh 源目录 备份目录 [保留天数]
# 把源目录打包成 .tar.gz 放进备份目录，再删除超过保留天数的旧备份

die() {                            # $1 是退出码，$2 是错误信息
    echo "错误: $2" >&2
    exit "$1"
}

[ $# -ge 2 ] || die 1 "用法: $0 源目录 备份目录 [保留天数]"
src=$1
dest=$2
keep=${3:-7}

[ -d "$src" ] || die 2 "$src 不是目录"
mkdir -p "$dest"

name="$(basename "$src")_$(date +%Y%m%d_%H%M%S).tar.gz"
tar -czf "$dest/$name" -C "$(dirname "$src")" "$(basename "$src")" || die 3 "打包失败"

count=$(tar -tzf "$dest/$name" | grep -vc '/$')
echo "已备份 $count 个文件 -> $name"

find "$dest" -name '*.tar.gz' -mtime +"$keep" | while read -r old; do
    echo "删除旧备份: $(basename "$old")"
    rm -f "$old"
done

14.13 压缩归档与远程登录：tar、ssh、scp

备份日志要打包压缩，部署程序要把文件传到服务器，日常维护要远程登录。这一节的三个命令是笔试常客，尤其是 tar 的参数。[4]

tar：先打包，再压缩

打包是把一堆文件和目录合成一个文件（.tar），本身不变小；压缩是用算法把一个文件变小（gzip 生成 .gz）。gzip 只能压缩单个文件，所以目录要先 tar 再 gzip，tar 的 -z 选项把两步合成一步，生成 .tar.gz（也写作 .tgz）。[46]

tar -czvf logs.tar.gz logs/：-f 后面必须紧跟归档文件名

选项含义
-ccreate，创建归档
-xextract，解开归档
-tlist，只列出内容
-z / -j / -J用 gzip / bzip2 / xz 压缩或解压
-v显示处理的文件名
-f 文件指定归档文件
-C 目录先切换到这个目录再操作（解压到指定位置）
tar -czvf logs.tar.gz logs/          # 打包并压缩
tar -tzvf logs.tar.gz                # 不解开，只看里面有什么
tar -xzvf logs.tar.gz -C /tmp        # 解压到 /tmp
tar -cvf a.tar dir/                  # 只打包不压缩
gzip big.log                         # 压缩单个文件 → big.log.gz，原文件被替换
gunzip big.log.gz                    # 解压（等于 gzip -d）

记忆方法：c 是创建、x 是解开，z 是 gzip，v 显示过程，f 指定文件。解压一个 .tar.gz，答案就是 tar -xzvf。

ssh alice@10.0.0.5 'df -h'        # 不进入交互，只执行一条命令

私钥始终没有离开客户端，服务器只用公钥验证签名，这就是非对称加密在运维中的典型用法（第 16 章 16.6、16.9）。服务器配置 /etc/ssh/sshd_config 中常设 PasswordAuthentication no（禁止密码登录）和 PermitRootLogin no（禁止 root 直接登录），改完 systemctl restart ssh。

scp 与 rsync：传文件

scp app.tar.gz alice@10.0.0.5:/opt/          # 本地 → 远程
scp alice@10.0.0.5:/var/log/app.log .        # 远程 → 本地当前目录
scp -r site/ alice@10.0.0.5:/srv/            # -r 复制目录
scp -P 2222 a.txt alice@10.0.0.5:~           # 指定端口用大写 -P
rsync -av site/ alice@10.0.0.5:/srv/site/    # 增量同步，只传变化的部分

scp 的写法和 cp 一样，远程路径写成 用户@主机:路径。注意 ssh 用小写 -p 指定端口，scp 用大写 -P（scp 的小写 -p 表示保留时间和权限）。[48]

考场结论：

  • tar：c 创建、x 解压、t 列出、z gzip、v 显示、f 文件；解压 .tar.gz 用 tar -xzvf，打包用 tar -czvf。
  • tar 负责打包，gzip 负责压缩；.tar.gz 是两层。
  • ssh 默认端口 22；公钥放服务器的 authorized_keys，私钥留在本地。
  • scp 传文件，目录加 -r，端口用大写 -P。

C · 错误：x 是解开，打包要用 c。

D · 错误：scp 指定端口要用大写 -P，小写 -p 是保留文件属性。

14.14 Git 常用命令

写代码要保存每个版本、多人协作要合并修改，Git 是事实上的标准工具。笔试面试常问 merge 和 rebase、reset 三种模式、fetch 和 pull 的区别。[49] [50]

四个区域。 一次修改从写下到推送，要经过四个地方：

git clone 把远程仓库完整复制到本地，同时建好工作区

命令作用
git clone URL复制远程仓库到本地（含全部历史）
git status看哪些文件改了、哪些已暂存
git add 文件 / git add .把修改放进暂存区
git commit -m "说明"把暂存区的内容存成一个提交
git log --oneline --graph看提交历史
git branch dev新建分支（只是新建一个指针）
git switch dev（老写法 git checkout dev）切换分支；git switch -c dev 新建并切换
git merge dev把 dev 合并进当前分支
git rebase main把当前分支的提交"搬到" main 的最新提交之后
git fetch下载远程的新提交，不改动当前分支
git pullfetch 之后再 merge 进当前分支
git push origin main把本地提交推到远程
git stash / git stash pop把未提交的修改暂时收起 / 再取出来

分支就是指针。 每个提交记录了它的父提交，连成一张图；分支只是指向某个提交的可移动指针，HEAD 指向当前所在的分支。下图中 main 和 feature 从 C2 分叉，git merge feature 生成一个有两个父提交的合并提交 M：

箭头从子提交指向父提交（Git 的惯例）；M 有两个父提交 C3 和 F1，虚线是分支指针

merge 与 rebase。

  • merge：保留两条分叉的历史，用一个合并提交把它们连起来。如果当前分支是对方的祖先（没有分叉），Git 只需把指针往前挪，这叫快进合并（fast-forward），不产生合并提交。
  • rebase：把 feature 上的提交 F1 在 main 的最新提交 C3 之后重新做一遍，得到新提交 F1'（内容相同，哈希不同），历史变成一条直线。

rebase 让历史整洁，但会改写提交哈希，所以只对还没推送、只有自己用的分支 rebase，已经推送到公共分支的提交用 merge。[51]

reset：把分支指针移回去。 git reset 目标提交 让当前分支指向更早的提交，三种模式区别在于是否同时改暂存区和工作区：[52]

模式分支指针暂存区工作区效果
--soft移动不变不变撤销提交，改动仍是"已暂存"
--mixed（默认）移动重置不变撤销提交和 add，改动回到"未暂存"
--hard移动重置重置改动全部丢弃

git reset --soft HEAD~1 撤销最后一次提交但保留修改，常用来重写提交说明；git reset --hard 会丢掉未提交的工作，使用前先确认。对已经推送的提交，用 git revert 提交 生成一个"反向提交"来撤销，不改写历史。

stash：临时收起修改。 正在写一半，需要切到别的分支修 bug：git stash 把工作区和暂存区的修改存起来，工作区变干净；修完回来 git stash pop 取回。git stash list 查看存了几份。[53]

考场结论：

  • add 进暂存区，commit 进本地仓库，push 到远程；pull = fetch + merge。
  • 分支是指向提交的指针；merge 保留分叉并生成合并提交（无分叉时快进），rebase 把提交重放成直线并改写哈希。
  • reset --soft 只动指针，--mixed 还重置暂存区，--hard 连工作区一起重置。

单选 · 理解检查 20　你在本地提交了一次（尚未 push），想撤销这次提交但保留修改并让它们回到未暂存状态，应执行？

A. git reset HEAD~1

B. git reset --hard HEAD~1

C. git reset --soft HEAD~1

D. git stash pop

查看答案与每个选项的解析

A · 正确：默认是 --mixed：指针后移，暂存区重置，工作区保留。

B · 错误：--hard 会把工作区的修改也丢掉。

C · 错误：--soft 保留修改，但它们仍处于已暂存状态。

D · 错误：stash pop 是取回之前收起的修改，与撤销提交无关。

易错点： 在多人共用的分支上 rebase 后强推，会让别人的历史对不上；git pull 会自动合并，只想看远程有什么新提交用 git fetch；git reset --hard 丢掉的未提交修改无法用 Git 找回。

速记： add → commit → push；pull = fetch + merge；merge 留分叉，rebase 拉直线；reset soft 动指针、mixed 加暂存区、hard 全清。

14.15 Linux 启动流程

按下电源到出现登录提示，中间发生了什么？笔试常出"把启动步骤排序"，排障时也要知道卡在了哪一步。[54] [55]

固件 → 引导扇区/分区 → GRUB → 内核 → systemd(PID 1) → 登录

逐步说明。

  1. 加电：电源稳定后，CPU 复位寄存器，从固定地址开始执行主板上的固件。
  2. 固件自检：传统 BIOS 做加电自检 POST（检查内存、显卡、键盘），新机器用 UEFI，功能更多、启动更快。
  3. 找引导程序：BIOS 按启动顺序读启动盘的第一个扇区 MBR（512 字节）并执行其中的引导代码；UEFI 直接从 GPT 磁盘上的 EFI 系统分区（ESP）加载引导程序文件。
  4. GRUB2：读取 /boot/grub/grub.cfg，显示启动菜单，把内核 vmlinuz 和初始内存盘 initramfs 加载进内存。
  5. 内核：解压并初始化 CPU、内存管理、驱动；借助 initramfs 中的驱动找到真正的根分区并挂载；然后执行 /sbin/init。
  6. systemd：作为 PID 1，读取默认目标 default.target，按依赖关系并行启动各项服务。旧的 SysV init 按运行级别串行执行脚本，所以开机更慢。
  7. 登录：启动 getty（文本终端登录）或图形登录界面。

MBR 的 512 字节。

446 + 64 + 2 = 512：分区表只有 4 项，所以 MBR 最多 4 个主分区

对比MBRGPT
主分区数最多 4 个（再多要用扩展分区）默认 128 个
最大磁盘2 TiB（32 位扇区号 × 512 字节 = 2³² × 2⁹ = 2⁴¹ 字节）远超当前硬盘容量（64 位扇区号）
引导方式配合 BIOS配合 UEFI
可靠性分区表只有一份头部和尾部各存一份，带校验

运行级别与 target。

SysV 运行级别含义systemd target
0关机poweroff.target
1单用户（维护模式）rescue.target
3多用户、命令行multi-user.target
5多用户、图形界面graphical.target
6重启reboot.target

systemctl get-default 查看默认目标，systemctl set-default multi-user.target 设为开机进命令行。开机自动挂载的分区写在 /etc/fstab 里，每行 6 个字段：设备、挂载点、文件系统类型、挂载选项、dump 备份标志、fsck 检查顺序。[56]

考场结论：

  • 启动顺序：BIOS/UEFI 自检 → 读 MBR / ESP → GRUB 加载内核 → 内核初始化并挂载根 → init/systemd（PID 1）→ 启动服务 → 登录。
  • MBR 位于磁盘第一个扇区，512 字节 = 446 引导代码 + 64 分区表 + 2 标志；最多 4 个主分区、2 TiB。
  • 运行级别 0 关机、1 单用户、3 命令行多用户、5 图形、6 重启；systemd 用 target 代替运行级别。

单选 · 理解检查 21　写出结果：MBR 分区表用 32 位记录扇区号、每扇区 512 字节，能管理的最大磁盘容量是多少？

A. 2 TiB

B. 4 GiB

C. 16 TiB

D. 没有上限

查看答案与每个选项的解析

A · 正确：2^32 × 2^9 = 2^41 字节 = 2 TiB。

B · 错误：2^32 字节才是 4 GiB，这里还要乘每扇区 512 字节。

C · 错误：那需要 4096 字节的扇区。

D · 错误：32 位扇区号限定了最多 2^32 个扇区。

单选 · 理解检查 22　把 Linux 启动步骤排序：a 内核挂载根文件系统；b GRUB 加载内核；c BIOS 自检；d systemd 启动服务；e 读取 MBR。

A. c → e → b → a → d

B. e → c → b → a → d

C. c → b → e → a → d

D. c → e → b → d → a

查看答案与每个选项的解析

A · 正确：固件自检 → 读引导扇区 → 引导程序加载内核 → 内核初始化 → PID 1 启动服务。

B · 错误：必须先由 BIOS 运行，才能去读磁盘上的 MBR。

C · 错误：GRUB 的第一段代码就在 MBR 里，先读 MBR 才能运行 GRUB。

D · 错误：systemd 是内核挂载根文件系统之后才执行的程序。

易错点： 运行级别 3 和 5 的区别是有没有图形界面，两者都是多用户；systemd 是并行启动，SysV init 是串行；MBR 本身只是一个扇区，GRUB 的大部分代码放在其他位置。

速记： 固件 → MBR/ESP → GRUB → 内核 → systemd → 登录；MBR 446+64+2，4 主分区 2 TiB。

14.16 Docker 常用命令与 Dockerfile

"在我电脑上能跑，到服务器就不行"，往往是依赖版本不同造成的。Docker 把程序和它需要的运行环境一起打包成镜像，在任何装了 Docker 的机器上都能以同样方式运行。容器与虚拟机的原理对比放在第 28 章 28.15，这里只讲命令。[57] [58]

三个概念。 镜像（image）是只读的模板，像"类"；容器（container）是镜像运行起来的实例，像"对象"，在镜像之上多一层可写层；仓库（registry，如 Docker Hub）存放镜像。

Dockerfile 构建出镜像，镜像运行成容器；一个镜像可以启动多个容器

常用命令

命令作用
docker pull nginx:1.27从仓库下载镜像（: 后是标签，省略时为 latest）
docker images列出本地镜像
docker run -d -p 8080:80 --name web1 nginx:1.27后台（-d）启动容器，把主机 8080 端口映射到容器 80 端口
docker run -it ubuntu:24.04 bash交互式（-i 保持输入、-t 分配终端）进入一个新容器
docker ps / docker ps -a列出运行中的容器 / 全部容器（含已停止）
docker logs -f web1跟踪容器的输出
docker exec -it web1 bash在运行中的容器里再开一个 Shell
docker stop web1 / docker start web1停止 / 启动已有容器
docker rm web1 / docker rmi nginx:1.27删除容器 / 删除镜像
docker build -t web:1.0 .用当前目录的 Dockerfile 构建镜像，-t 起名和标签
docker tag、docker login、docker push改名、登录、上传到仓库

docker run 的其他常用选项：-v /host/data:/data 把主机目录挂进容器（数据不随容器删除而丢失），-e KEY=VALUE 设环境变量，--rm 容器退出后自动删除。docker build -t web:1.0 . 最后的 . 是构建上下文：把当前目录发给 Docker，Dockerfile 里的 COPY 只能复制这个目录里的文件。[59]

Dockerfile 常见指令

FROM python:3.12-slim              # 基础镜像，必须是第一条指令
WORKDIR /app                       # 之后的命令都在 /app 下执行（不存在就创建）
COPY requirements.txt .            # 从构建上下文复制文件进镜像
RUN pip install -r requirements.txt   # 构建镜像时执行命令
COPY . .
ENV APP_ENV=prod                   # 设置环境变量
EXPOSE 8000                        # 声明容器监听的端口（仅说明，不做映射）
CMD ["python", "main.py"]          # 容器启动时默认执行的命令
指令作用常考辨析
FROM指定基础镜像必须是第一条（ARG 除外）
RUN构建时执行命令，结果存进镜像与 CMD 的区别：RUN 在 build 时、CMD 在 run 时
COPY / ADD复制文件进镜像ADD 还能自动解压 tar、下载 URL；一般用 COPY
WORKDIR设置工作目录相当于 cd，但对之后所有指令有效
ENV / ARG环境变量 / 构建参数ENV 在容器运行时仍存在，ARG 只在构建时有效
EXPOSE声明端口真正对外映射要 docker run -p
CMD容器启动时的默认命令docker run 镜像 其他命令 会覆盖它
ENTRYPOINT容器的固定入口程序docker run 镜像 参数 时参数追加给它而不替换它（要替换需 --entrypoint）；CMD 作为它的默认参数

镜像由多层组成：每条 RUN、COPY、ADD 都会新增一层文件系统，其他指令只修改元数据。所以常把多条安装命令用 && 合并进一个 RUN，减少层数和体积。docker history web:1.0 可以看到每一层。[60]

考场结论：

  • pull 下载、run 运行、ps 列容器、exec 进入、logs 看输出、stop/rm 停止删除、build 构建。
  • -p 主机端口:容器端口；EXPOSE 只是声明。
  • RUN 在构建时执行，CMD 在容器启动时执行且可被覆盖；ENTRYPOINT 是固定入口；FROM 必须是第一条。
