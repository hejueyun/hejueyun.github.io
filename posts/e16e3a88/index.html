35.1 读题五问：把题面翻译成状态

为什么需要它

看到新题脑子一片空白，常见原因是题面还停留在"一段中文"，没有变成"几个变量"。代码只认变量。所以第一步不是想算法，而是把题面拆成五个问题的答案。五问答完，题目就从一段文字变成了一张表，很多题此时已经知道该怎么写了。

五问分别问什么

问问题要写下来的东西
① 输入拿到了哪些数据？各是什么类型？变量名和类型，例如 vector<long long> a、long long s
② 输出要交出什么？一个数、一个数组、还是 Yes/No？返回值类型；无解时输出什么
③ 规模n 最大多少？数值最大多少？允许的复杂度（35.2）；中间结果会不会超过 int
④ 限制有序吗？有负数吗？有重复吗？能为空吗？每条限制写一行，它们会决定能不能用双指针、二分等方法
⑤ 样例把样例手算一遍，结果和题目给的一致吗？一张手算表，表头就是你需要的变量

第⑤问最容易被跳过，也最值钱。手算时你会自然地问"我要记住哪些东西才能算下一步"，这些东西就是状态。状态的意思是：解题过程进行到某一刻，为了继续往下算，必须记住的最少信息。

用一道原创题完整走一遍

电梯总耗时：一栋楼的电梯一开始停在 1 层。依次给出 m 个请求楼层 a[0..m−1]，电梯按顺序前往每个请求楼层。每移动一层用 1 秒，每停靠一次（开门再关门）用 s 秒。如果某个请求楼层就是电梯当前所在楼层，这个请求直接忽略。求处理完所有请求一共用了多少秒。数据范围：1 ≤ m ≤ 10⁵，1 ≤ a[i] ≤ 10⁹，0 ≤ s ≤ 10⁹。样例：m=4，s=2，a=[3,3,1,4]，输出 13。

我们逐个回答五问。

  • ① 输入：整数 m、s，长度为 m 的数组 a。
  • ② 输出：一个整数，总秒数。
  • ③ 规模：m ≤ 10⁵，一次扫描 O(m) 足够。每次最多移动约 10⁹ 层、停靠 10⁹ 秒，共 10⁵ 次，总和可达约 2×10¹⁴，远超 int 的 2.1×10⁹，所以总时间要用 long long。
  • ④ 限制：a 无序（可以上上下下）；会有重复，而且"和当前楼层相同就忽略"这条只看当前楼层；s 可以是 0；楼层都是正数。
  • ⑤ 样例手算：下面这张表的表头就是状态。

考场结论

  • 五问先于算法。答完五问再想"用什么方法"，方向会准很多。
  • 手算样例时出现的那几列变量，就是代码里的状态变量。表头写出来了，代码的变量声明也就写出来了。
  • 第③问同时决定两件事：时间复杂度和整数类型。"数值 × 次数"超过 2×10⁹ 就用 long long。
  • 第④问里的每一条限制都要在代码里找到对应的那一行。例如"相同楼层忽略"对应 if (f == cur) continue;。

代码

变量表：cur 是电梯此刻所在楼层；total 是到此刻为止的总秒数；f 是正在处理的请求楼层。

long long elevatorTime(const vector<long long>& req, long long stopCost) {
    long long cur = 1;        // 状态 1：电梯此刻在哪一层
    long long total = 0;      // 状态 2：到此刻为止用了多少秒
    for (long long f : req) {
        if (f == cur) continue;                       // 已经在这一层：不移动也不开门
        total += (f > cur ? f - cur : cur - f);       // 移动 |f - cur| 层
        total += stopCost;                            // 开门一次
        cur = f;                                      // 更新状态
    }
    return total;
}

逐行读：

行做什么样例中第一次执行时的值为什么这样写
long long cur = 1;状态初值：题面说"一开始停在 1 层"cur=1楼层可到 10⁹，和 total 用同一类型省得转换
long long total = 0;还没花时间total=0总和可达 2×10¹⁴，必须 long long
for (long long f : req)按顺序取每个请求f=3题面要求"依次"，所以顺序扫描
if (f == cur) continue;第④问的那条限制3≠1，不跳过去掉这行，第二个 3 会多算 2 秒停靠，输出 15

如果用 int total 会怎样？ 请求 [1000000000, 1, 1000000000]、s=5 时，正确答案是 3000000012，已经超过 int 的上限 2147483647。用 int 会溢出，得到一个毫无意义的数。practice 文件里专门断言了这组数据。

练一练：电梯换方向要加时

题面：在上题基础上，电梯每次改变运行方向（上一次往上、这一次往下，或反过来）时，要额外花 turnCost 秒。第一次移动没有"上一次方向"，不加。样例：a=[3,3,1,4]，s=2，turnCost=10，输出 33。

提示：手算表多出一列"上一次方向"，这一列就是新增的状态。

long long elevatorTimeTurn(const vector<long long>& req, long long stopCost, long long turnCost) {
    long long cur = 1, total = 0;
    int dir = 0;                                      // 新增状态：上一次移动方向，0 表示还没动过
    for (long long f : req) {
        if (f == cur) continue;
        int nd = f > cur ? 1 : -1;
        if (dir != 0 && nd != dir) total += turnCost; // 方向变了才加
        total += (f > cur ? f - cur : cur - f) + stopCost;
        cur = f;
        dir = nd;
    }
    return total;
}

和例题相比改了哪一处： 状态从 (cur, total) 变成 (cur, total, dir)，转移里多了一句"方向变了就加 turnCost"。样例里 1→3 向上、3→1 向下（+10）、1→4 向上（+10），13 + 20 = 33。

A. 17

B. 20

查看答案与每个选项的解析

A · 正确：1→2：1+3=4；第二个 2 忽略；2→5：3+3=6，累计 10；5→1：4+3=7，累计 17。

B · 错误：把第二个 2 也算了一次停靠（+3），漏读了相同楼层忽略这条限制。

C · 错误：少算了一次停靠。三次真正的移动各停靠一次，共 9 秒停靠。

D · 错误：8 只是移动层数之和 1+3+4，没有加停靠时间。

易错点：

  • 只看样例输出、不手算，就发现不了"相同楼层忽略"这类藏在题面里的规则。
  • 第③问只想到时间、忘了数值，答案类型用 int，大数据直接溢出。
  • 状态初值要从题面来：本题 cur 从 1 开始，写成 0 会让第一次移动多算 1 层。

速记： 输入、输出、规模、限制、手算样例；手算表的表头就是状态。

35.2 数据范围决定复杂度，复杂度决定候选算法

为什么需要它

同一个问题，n ≤ 20 和 n ≤ 10⁵ 是两道完全不同的题。题目给出的数据范围其实是出题人留下的提示：它告诉你"多慢的算法会超时"。先算出允许的复杂度，候选算法就从几十种缩小到两三种。

一秒大约能做多少事

普通评测机上，C++ 一秒大约能做 10⁸ 次简单运算（加减、比较、数组访问）。这是一个粗略经验，只用来估数量级：哈希表、递归、map 的常数比数组大，实际可能慢几倍；时限 2 秒就按 2×10⁸ 估。[1]

估算方法：把 n 的最大值代入复杂度，算出运算次数，和 10⁸ 比较。

n 的上限允许的复杂度代入后的运算量典型算法
n ≤ 10O(n!)10! ≈ 3.6×10⁶全排列枚举（第 33 章）
n ≤ 20O(2ⁿ) 或 O(2ⁿ·n)2²⁰×20 ≈ 2.1×10⁷子集枚举、二进制 mask（第 33 章）
n ≤ 500O(n³)500³ = 1.25×10⁸三重循环、区间 DP、Floyd
n ≤ 5000O(n²)5000² = 2.5×10⁷二重循环、二维 DP
n ≤ 10⁶O(n log n) 或 O(n)10⁶×20 = 2×10⁷排序、二分、堆、双指针、哈希、前缀和、单调栈
n ≤ 10¹²O(√n)10⁶试除到 √n
n ≤ 10¹⁸O(log n) 或 O(1)log₂10¹⁸ ≈ 60二分答案、快速幂、数学公式

每一档代入上限后都落在 10⁷～10⁸（纵轴 7～8）附近：表格不是背出来的，是把 n 代进去算出来的

这张图说明了表格的来历：每一档的 n 上限，都恰好让对应复杂度的运算量落在 10⁸ 附近。遇到表里没有的范围，例如 n ≤ 2000，就自己代入：2000² = 4×10⁶，O(n²) 很宽松；2000³ = 8×10⁹，O(n³) 超时。

完整走一遍：同一个问题，三种范围

题目骨架：从 n 个正整数里选出若干个，问能否让它们的和恰好等于 T。

  1. n ≤ 20：子集一共 2²⁰ ≈ 10⁶ 个，每个子集求和 20 次，约 2×10⁷，直接枚举全部子集。
  2. n ≤ 100，T ≤ 10⁵：2¹⁰⁰ 没法枚举。但"凑出的和"只有 T+1 ≤ 10⁵+1 种取值，可以用 DP 记录"和为 x 能不能凑出"，O(n·T) = 10⁷。
  3. n ≤ 10⁵，T ≤ 10⁹：O(n·T) 也太大。这时出题人一定给了额外限制（例如"每个数都是 2 的幂"），要回到第④问找它。

同一句题面，范围一变，算法就跟着变。所以我们读题时把范围写在最显眼的地方。

另外三个要一起看的数

  • 多组数据：题目说"T 组测试，所有测试的 n 之和不超过 2×10⁵"，就按总和 2×10⁵ 估，而不是 T × 单组上限。
  • 内存：256 MB 大约能放 256×1024×1024 / 4 = 67108864 个 int，约 6.7×10⁷ 个。开 int a[5000][5000] 是 2.5×10⁷ 个，放得下；开 long long 的 10⁴×10⁴ 就是 800 MB，放不下。
  • 递归深度：递归一层就占一块栈空间。n = 10⁵ 的链状递归在某些平台上会栈溢出，这时改写成循环。

代码：把表格写成一个函数

string allowedComplexity(long long n) {
    if (n <= 10) return "O(n!)";
    if (n <= 20) return "O(2^n)";
    if (n <= 500) return "O(n^3)";
    if (n <= 5000) return "O(n^2)";
    if (n <= 1000000) return "O(n log n)";
    return "O(log n)";
}

逐行读： 每个 if 对应表格的一行，从小到大判断，第一个满足的就是答案。n 用 long long，因为要能接收 10¹⁸。比如 allowedComplexity(300) 依次检查：300 ≤ 10 不成立，300 ≤ 20 不成立，300 ≤ 500 成立，返回 "O(n^3)"。这个函数本身用不到考场上，写它是为了让你确认：表格就是一串"代入 + 比较"。

练一练：大数判质数

题面：给一个整数 n（1 ≤ n ≤ 10¹²），判断它是不是质数。

提示：n 的上限 10¹² 落在 O(√n) 那一档，√10¹² = 10⁶。一个合数一定有一个不超过 √n 的因子，所以只试 2 到 √n。

bool isPrimeSqrt(long long n) {
    if (n < 2) return false;
    for (long long i = 2; i * i <= n; ++i)        // 只试到 √n
        if (n % i == 0) return false;
    return true;
}

和例题相比改了哪一处： 例题按 n 选复杂度；这里 n 到了 10¹²，要从表里找到 √n 那一档，再设计出"试到 √n"的循环。注意 i 用 long long：i * i 会到 10¹²，int 装不下。practice 中断言了 999999999989 是质数、10¹² 不是。

多选 · 理解检查 2　某题 n ≤ 2×10⁵，时限 1 秒。哪些复杂度能通过？

A. O(n log n)

B. O(n)

C. O(n²)

D. O(2ⁿ)

查看答案与每个选项的解析

A · 正确：2×10⁵ × 18 ≈ 3.6×10⁶，远小于 10⁸。

B · 正确：只有 2×10⁵ 次。

C · 错误：(2×10⁵)² = 4×10¹⁰，是 10⁸ 的 400 倍。

D · 错误：2 的 20 万次方，天文数字；O(2ⁿ) 只适合 n ≤ 20 左右。

易错点：

  • 10⁸ 是数量级经验，只用来区分"差几倍"和"差几百倍"；运算量刚好在 10⁸ 附近时，要考虑常数。
  • 多组数据看"n 的总和"，按单组上限乘组数会把可行的算法误判成超时。
  • 复杂度够了，还要看内存和递归深度。

速记： 把 n 的上限代进复杂度，和 10⁸ 比；20 用 2ⁿ，5000 用 n²，10⁶ 用 n log n。

35.3 先写暴力：列出所有可能，再逐个检查

为什么需要它

想不出最优解时，最常见的结果是交白卷。其实几乎每道题都有一个"笨办法"：把所有可能的答案都列出来，一个个检查。这个办法慢，但它有三个用处：

  1. 一定对：逻辑最直白，几乎不会写错。
  2. 能拿部分分：笔试常按数据规模给分，例如 30% 的数据 n ≤ 200。暴力能稳拿这一部分。
  3. 能当标准答案：写完快的版本后，用随机小数据把两者对比，这叫对拍（35.6）。

暴力有固定三段

列出 → 检查 → 汇总。 先问"所有可能的候选是什么"，再问"怎么判断一个候选合格"，最后问"合格的要计数、求最大，还是找一个"。

完整走一遍：好区间计数

好区间计数：给一个整数数组 a（可能有负数）和两个整数 lo、hi，统计有多少个连续区间 [l, r]，它的元素和落在 [lo, hi] 之内。样例：a=[2,−1,3,1]，lo=2，hi=3，输出 4。

按三段写：列出所有区间（l 从 0 到 n−1，r 从 l 到 n−1）；检查区间和是否在 [lo, hi]；汇总为计数。

代码

变量表：l、r 是当前区间的左右端点；sum 是这个区间的和；cnt 是合格区间的个数。

long long countGoodRangesBrute(const vector<int>& a, long long lo, long long hi) {
    int n = (int)a.size();
    long long cnt = 0;
    for (int l = 0; l < n; ++l) {                  // 列出：左端
        for (int r = l; r < n; ++r) {              // 列出：右端
            long long sum = 0;
            for (int i = l; i <= r; ++i) sum += a[i];   // 检查：现算这一段的和
            if (lo <= sum && sum <= hi) ++cnt;     // 汇总
        }
    }
    return cnt;
}

逐行读：

  • 外两层循环负责"列出"：r 从 l 开始，保证区间至少有一个元素，也保证每个区间只出现一次。
  • 第三层循环负责"检查"：每次从头算区间和。它浪费（相邻区间的和其实只差一个数），但这正是暴力的定位：先求直白，优化留到 35.4。
  • sum 用 long long：n 个 10⁹ 相加会超过 int。
  • lo <= sum && sum <= hi 是数学上 lo ≤ sum ≤ hi 的正确写法。写成 lo <= sum <= hi 能编译通过，但含义是"(lo<=sum) 的结果 0 或 1，再和 hi 比较"，结果错误。
  • cnt 用 long long：区间个数最多 n(n+1)/2，n=10⁵ 时约 5×10⁹，超过 int。

暴力能拿多少分

这段代码是 O(n³)。假设题目分三档：30% 的数据 n ≤ 200，60% 的数据 n ≤ 2000，100% 的数据 n ≤ 10⁵。

写法复杂度n=200n=2000n=10⁵得分
三重循环O(n³)8×10⁶ 通过8×10⁹ 超时超时30%
去掉第三层，r 右移时累加O(n²)通过4×10⁶ 通过约 5×10⁹ 超时60%
前缀和 + 有序结构O(n log n)通过通过通过100%

想不出最后一行时，交第二行也能拿 60%。第二行的改法很小：把 sum 移到 r 循环外面、每次 sum += a[r]。这种"把重复的计算挪出循环"的思路，正是下一节的第一类优化。

练一练：预算内的最大价值（子集暴力）

题面：有 n 件商品（n ≤ 20），第 i 件价格 price[i]、价值 value[i]，每件最多买一件。总价不超过 budget 时，最大总价值是多少？样例：price=[3,4,5]，value=[30,50,60]，budget=8，输出 90（买第 0、2 件，花 8 元）。

提示：n ≤ 20，查 35.2 的表是 O(2ⁿ)，候选是"所有子集"。用一个整数 mask 表示一种选法：第 i 位是 1 就表示买第 i 件（第 33 章详细讲 mask）。

long long bestValueBrute(const vector<int>& price, const vector<int>& value, long long budget) {
    int n = (int)price.size();
    long long best = 0;
    for (int mask = 0; mask < (1 << n); ++mask) {  // 每个 mask 是一种"选哪些"
        long long cost = 0, val = 0;
        for (int i = 0; i < n; ++i)
            if (mask >> i & 1) { cost += price[i]; val += value[i]; }
        if (cost <= budget) best = max(best, val);
    }
    return best;
}

和例题相比改了哪一处： 三段结构不变，只是"列出"的对象从区间换成了子集，"汇总"从计数换成了取最大。mask >> i & 1 取出 mask 的第 i 位：例如 mask=5（二进制 101），第 0 位和第 2 位是 1，表示买第 0、2 件。

易错点：

  • 暴力也要先算复杂度，确认它能拿到哪一档数据的分。
  • 暴力的价值在"直白"。为了快一点把暴力写复杂，就失去了当标准答案的意义。
  • 计数类答案常超过 int，计数器直接用 long long。

35.4 从暴力到优化：问自己五个固定问题

为什么需要它

暴力写完，下一步是"让它变快"。变快的办法看起来五花八门，其实绝大多数都在回答同一个问题：暴力在哪里做了白工？ 我们把白工分成五类，每一类对应一个固定的提问和一个固定的工具。面对新题时，按顺序问这五个问题，通常一两个问题就能找到突破口。

问题暴力里的白工工具常见提速
① 有没有重复计算？同一个子问题被算了很多遍记忆化 / DP指数级 → O(n)
② 能不能先排序？在乱序里找"接近的"元素，只能全部比一遍排序 + 双指针 / 二分O(n²) → O(n log n)
③ 能不能"查一下"代替"再扫一遍"？为了找某个值，回头把前面扫一遍哈希表O(n²) → O(n)
④ 区间和能不能预处理？每次询问都重新累加一段前缀和O(n·q) → O(n+q)
⑤ 能不能只保留有用的候选？每次都在全部旧元素里挑，其实大部分已经没用单调栈 / 单调队列 / 堆 / 贪心O(n²) → O(n)

拿着暴力解，依次问五个问题；哪个回答是，就用对应的工具

下面五道原创小题，每道都先给暴力，再指出白工在哪，最后给优化版。

问题①：有没有重复计算？—— 跳格子

跳格子：一排 n 个格子，格子 i 上写着分数 s[i]（可以为负）。从格子 0 出发，每次向右跳 1 格或 2 格，最后必须恰好落在格子 n−1。得分是踩过的所有格子的分数之和（含起点终点）。求最大得分。样例：s=[1,−5,2,−1,3,−2,4]，输出 10（踩 0→2→4→6：1+2+3+4）。

暴力：从格子 i 出发能拿到的最大分，记作 best(i)。站在 i 上，要么跳到 i+1，要么跳到 i+2，两种都试，取大的。这是第 32 章的递归写法。

long long jumpBrute(const vector<int>& s, int i, long long& calls) {
    ++calls;
    int n = (int)s.size();
    if (i == n - 1) return s[i];                          // 到终点
    long long best = jumpBrute(s, i + 1, calls);          // 跳 1 格
    if (i + 2 <= n - 1) best = max(best, jumpBrute(s, i + 2, calls));   // 跳 2 格
    return s[i] + best;
}

calls 用来数一共调用了几次。画出 n=5 时的调用树，白工一眼可见：

上图 12 次调用里，只有 5 次是第一次算（蓝色），其余 7 次（红色）都是重复。best(2) 被算了 2 次，best(4) 被算了 5 次。调用次数随 n 呈斐波那契式增长：n=7 时 33 次，n=30 时 2178308 次，n=50 时超过 10¹⁰ 次。

信号：递归函数的参数只有一个 i，取值只有 n 种，调用次数却是指数级。这说明同样的参数被反复调用。

优化：第一次算出 best(i) 后存起来，以后直接查。这叫记忆化。[2]

long long jumpMemo(const vector<int>& s, int i, vector<long long>& memo, vector<bool>& done) {
    int n = (int)s.size();
    if (i == n - 1) return s[i];
    if (done[i]) return memo[i];                          // 算过就直接查
    long long best = jumpMemo(s, i + 1, memo, done);
    if (i + 2 <= n - 1) best = max(best, jumpMemo(s, i + 2, memo, done));
    done[i] = true;
    return memo[i] = s[i] + best;                         // 记下来再返回
}
long long jumpBest(const vector<int>& s) {
    vector<long long> memo(s.size(), 0);
    vector<bool> done(s.size(), false);
    return jumpMemo(s, 0, memo, done);
}

逐行读： 和暴力相比只多了两行。if (done[i]) return memo[i]; 在算之前先查表；done[i] = true; return memo[i] = ... 在算完之后存表。每个 i 最多真正算一次，复杂度 O(n)。用 done 数组而不是"memo[i] 等于某个特殊值"来判断算没算过，是因为分数可以为负，任何数都可能是合法答案。

Python 对照，用标准库的缓存装饰器做记忆化：

from functools import lru_cache
def jump_best(s):
    n = len(s)
    @lru_cache(maxsize=None)
    def best(i):
        if i == n - 1: return s[i]
        return s[i] + max(best(i + 1), best(i + 2) if i + 2 <= n - 1 else float('-inf'))
    return best(0)

问题②：能不能先排序？—— 能力相近的搭档

搭档计数：n 个员工，能力值为 a[i]。两人能力差的绝对值不超过 d，就可以搭档。问一共有多少对 (i<j) 可以搭档。样例：a=[5,1,9,3,6]，d=2，输出 3（1 和 3、3 和 5、5 和 6）。n ≤ 10⁵。

暴力：两层循环检查每一对，O(n²)，n=10⁵ 时 5×10⁹ 次，超时。

long long countClosePairsBrute(vector<int> a, int d) {
    long long cnt = 0;
    for (int i = 0; i < (int)a.size(); ++i)
        for (int j = i + 1; j < (int)a.size(); ++j)
            if (abs(a[i] - a[j]) <= d) ++cnt;
    return cnt;
}

信号：答案只和"值"有关，和原来的下标顺序无关（数的是对数，不是哪两个下标）。这时可以放心排序。排好序后，能和 a[r] 搭档的、比它小的那些人，正好是挨在它左边的一段连续区间。

优化：排序后用两个指针。r 从左往右扫，l 指向"能和 a[r] 搭档的最小那个人"。r 右移时 a[r] 变大，太小的人只会更配不上，所以 l 只会右移、不回头。两个指针各走 n 步，加上排序，总共 O(n log n)。[3]

long long countClosePairs(vector<int> a, int d) {
    sort(a.begin(), a.end());                     // 排序后，"差 ≤ d"的伙伴挨在一起
    long long cnt = 0;
    int l = 0;
    for (int r = 0; r < (int)a.size(); ++r) {     // r 是这一对里较大的那个
        while (a[r] - a[l] > d) ++l;              // 太小的伙伴以后也用不上，丢掉
        cnt += r - l;                             // [l, r) 都能和 a[r] 配对
    }
    return cnt;
}

问题③：能不能"查一下"代替"再扫一遍"？—— 重复订单

重复订单：给一串订单号 ids，找两个相同订单号之间的最小下标距离 j−i。没有重复时输出 −1。样例：ids=[7,3,9,3,7,9,9]，输出 1（最后两个 9）。n ≤ 10⁵。

暴力：两层循环，看到 ids[j] 就回头把前面每个位置都比一遍，O(n²)。

int minRepeatGapBrute(const vector<int>& ids) {
    int best = INT_MAX;
    for (int i = 0; i < (int)ids.size(); ++i)
        for (int j = i + 1; j < (int)ids.size(); ++j)
            if (ids[i] == ids[j]) best = min(best, j - i);
    return best == INT_MAX ? -1 : best;
}

信号：内层循环在问"这个值以前出现过吗？在哪？"。只要能 O(1) 回答这个问题，就不必回头扫。而且，对于当前的 j，只有最近一次出现的位置有用：更早的位置距离更远，不会更优。

优化：用哈希表记"订单号 → 最近一次出现的下标"。[4]

int minRepeatGap(const vector<int>& ids) {
    unordered_map<int, int> last;                 // 订单号 → 最近一次出现的下标
    int best = INT_MAX;
    for (int j = 0; j < (int)ids.size(); ++j) {
        auto it = last.find(ids[j]);
        if (it != last.end()) best = min(best, j - it->second);   // 只和最近一次比
        last[ids[j]] = j;                         // 更新为最近一次
    }
    return best == INT_MAX ? -1 : best;
}

j=6 时 last = {7:4, 3:3, 9:5}：查到 9 上次在 5，距离 1；查表 O(1)，不用回头扫

逐行读： find 只查不插（22.7 讲过 [] 会插入新键）；查到了就用 j - it->second 更新答案；然后 last[ids[j]] = j 把位置改成最新的。顺序是"先查后存"：先存的话，查到的就是自己，距离变成 0。

问题④：区间和能不能预处理？—— 高温天数

高温天数：给 n 天的温度 t[i] 和阈值 limit。有 q 个询问，每个询问给出 [l, r]，回答这几天里温度严格高于 limit 的天数。样例：t=[30,36,35,38,29,40]，limit=35，询问 [0,2]、[1,4]、[2,2]、[0,5]，输出 1、2、0、3。n、q ≤ 10⁵。

暴力：每个询问从 l 数到 r，最坏 O(n·q) = 10¹⁰。

vector<int> countHotBrute(const vector<int>& t, int limit, const vector<pair<int, int>>& qs) {
    vector<int> out;
    for (auto [l, r] : qs) {
        int c = 0;
        for (int i = l; i <= r; ++i) if (t[i] > limit) ++c;
        out.push_back(c);
    }
    return out;
}

信号：数组不变，询问很多，每个询问都是"一段区间的和"（这里是"是否高温"的 0/1 之和）。不同询问的区间大量重叠，同一段被数了很多遍。

优化：先算前缀和 pre[i] = 前 i 天里的高温天数。区间 [l, r] 的答案就是 pre[r+1] − pre[l]：前 r+1 天减去前 l 天。预处理 O(n)，每个询问 O(1)。[5]

vector<int> countHot(const vector<int>& t, int limit, const vector<pair<int, int>>& qs) {
    int n = (int)t.size();
    vector<int> pre(n + 1, 0);                    // pre[i] = 前 i 天（下标 0..i-1）里的高温天数
    for (int i = 0; i < n; ++i) pre[i + 1] = pre[i] + (t[i] > limit ? 1 : 0);
    vector<int> out;
    for (auto [l, r] : qs) out.push_back(pre[r + 1] - pre[l]);   // 两个前缀相减
    return out;
}

t=[30,36,35,38,29,40] 中高温（>35）的是 36、38、40；pre 比 t 多一格，pre[0]=0 表示前 0 天

逐行读： pre 开 n+1 格，pre[0] = 0 代表"一天都没算"，这样从第 0 天开始的询问也能写成两个前缀相减，不用特判。(t[i] > limit ? 1 : 0) 把"是否高温"变成 0/1，计数问题就变成了求和问题。

问题⑤：能不能只保留有用的候选？—— 往前找更便宜的一天

更便宜的一天：给 n 天的价格 p[i]。对每一天 i，找它之前最近的一天 j（j<i），满足 p[j] < p[i]；没有就记 −1。样例：p=[5,3,4,4,2,6]，输出 [−1,−1,1,1,−1,4]。n ≤ 10⁵。

暴力：对每个 i 往回扫，碰到第一个更便宜的就停，最坏 O(n²)（例如价格一路下降，每次都扫到头）。

vector<int> prevCheaperBrute(const vector<int>& p) {
    int n = (int)p.size();
    vector<int> ans(n, -1);
    for (int i = 0; i < n; ++i)
        for (int j = i - 1; j >= 0; --j)
            if (p[j] < p[i]) { ans[i] = j; break; }
    return ans;
}

信号：每次都在"所有旧元素"里挑，但有些旧元素已经永远没用了。看 p=[…,5,3]：第 1 天价格 3，比它前面的 5 更便宜、也更靠近后来的日子。之后任何一天要找"更便宜的"，3 都比 5 更好（更近，而且只要 5 合格 3 就一定合格）。所以 5 可以扔掉。

优化：用一个栈只保留"还可能成为答案"的日子。新的一天 i 到来时，先把栈顶所有不比它便宜的日子弹掉（它们被 i 挡住了），剩下的栈顶就是答案，然后把 i 压栈。每天最多进栈一次、出栈一次，总共 O(n)。这种栈里元素保持单调的结构叫单调栈。[6]

vector<int> prevCheaper(const vector<int>& p) {
    int n = (int)p.size();
    vector<int> ans(n, -1);
    vector<int> st;                               // 栈里存下标，对应价格从底到顶严格递增
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && p[st.back()] >= p[i]) st.pop_back();   // 不比我便宜的，以后也没用
        if (!st.empty()) ans[i] = st.back();      // 栈顶就是最近的更便宜的那天
        st.push_back(i);
    }
    return ans;
}

用 vector 当栈：back() 看栈顶，pop_back() 出栈，push_back() 入栈，好处是调试时能直接遍历打印整个栈。这段代码怎么一步步跑，下一节用手跑表格完整演示。

同一个思路换个容器，就是"堆"和"贪心"：只关心当前最大或最小的候选时用堆（22.9 的 Top K）；能证明"某个候选现在不选、以后也不会更好"时就直接做决定，这就是贪心。

考场结论

  • 优化之前先有暴力，然后指着暴力里的某一行问"这一行在做什么白工"。
  • 五个问题对应五种白工：子问题重复、乱序比较、回头查找、重复求和、保留了无用候选。
  • 优化后要说出新复杂度和省掉了什么，例如"哈希表把回头扫的 O(n) 变成 O(1)，总复杂度 O(n)"。
  • 每个优化版都保留暴力版，二者对拍（35.6）。practice 文件里五道题都用随机数据把快慢两版比较了 300 轮。

练一练：价格不高于自己的最近一天

题面：同"更便宜的一天"，但条件改成 p[j] ≤ p[i]（不高于，允许相等）。样例：p=[5,3,4,4,2,6]，输出 [−1,−1,1,2,−1,4]。

提示：第 3 天价格 4，前一天也是 4，现在相等也算，所以答案变成 2。想一想：栈里该弹掉哪些？

vector<int> prevNotHigher(const vector<int>& p) {
    int n = (int)p.size();
    vector<int> ans(n, -1);
    vector<int> st;
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && p[st.back()] > p[i]) st.pop_back();    // 只把 >= 改成 >
        if (!st.empty()) ans[i] = st.back();
        st.push_back(i);
    }
    return ans;
}

和例题相比改了哪一处： 弹栈条件从 >= 改成 >。现在价格相等的日子也合格，所以要把它留在栈里；只有"严格更贵"的才被挡住。条件里的等号，决定了相等元素留不留下。

单选 · 理解检查 4　跳格子题：s=[2,−1,−1,3]，从格子 0 出发每次跳 1 或 2 格，必须落在格子 3。jumpBest 返回多少？

A. 4

B. 3

C. 5

D. 2

查看答案与每个选项的解析

A · 正确：0→1→3 得 2−1+3=4，0→2→3 也得 4，0→1→2→3 得 3。最大是 4。

B · 错误：这是把每格都踩一遍的得分，没有利用跳 2 格跳过负分。

C · 错误：2+3=5 需要从 0 直接跳到 3，跳了 3 格，题目只允许 1 或 2 格。

D · 错误：必须落在最后一格，终点的 3 一定要算进去。

易错点：

  • 先排序只适用于"答案和原顺序无关"的题；要输出原下标时，排序前把下标一起存进 pair。
  • 记忆化的"算没算过"要单独记，用一个特殊值（如 0 或 −1）当标记，遇到答案恰好等于它时会出错。
  • 单调栈里存下标而不是值：下标既能取到值，又能算距离。

速记： 重复计算→记忆化，乱序→排序+双指针，回头找→哈希，区间和→前缀和，没用的候选→单调栈/队列。

35.5 手跑与画图：用表格和不变式确认每一步

为什么需要它

代码写完不知道对不对，或者看别人的代码看不懂，最可靠的办法是手跑：拿一个小输入，像计算机一样一行行执行，把每个变量的值写下来。手跑有两个工具：一张表格，和一句不变式。

工具一：每轮一行的表格

表格的列 = 循环变量 + 所有会变的变量 + 这一轮的输出。每执行完一轮循环，写一行。写满之后对照预期，第一处不一致的那一行就是 bug 所在。

不变式是一句"每轮循环开始时都成立"的话。第 21 章用它解释过双指针。写不变式的方法是：盯住表格的最后一列，问"这一列每一行都满足什么"。

练一练：往后找更便宜的一天

题面：对每一天 i，找它之后最近的一天 j（j>i），满足 p[j] < p[i]；没有就记 −1。样例：p=[5,3,4,4,2,6]，输出 [1,4,4,4,−1,−1]。先写不变式，再写代码。

提示：从右往左扫，"之后"就变成了"已经扫过的"。不变式：第 i 轮开始时，栈里是 (i, n) 中还可能成为答案的日子，从底到顶下标递减、价格严格递增。

vector<int> nextCheaper(const vector<int>& p) {
    int n = (int)p.size();
    vector<int> ans(n, -1);
    vector<int> st;
    for (int i = n - 1; i >= 0; --i) {            // 只改扫描方向
        while (!st.empty() && p[st.back()] >= p[i]) st.pop_back();
        if (!st.empty()) ans[i] = st.back();
        st.push_back(i);
    }
    return ans;
}

和例题相比改了哪一处： 只改了循环方向，从 i = 0 往右改成 i = n-1 往左。不变式里"[0, i)"相应变成"(i, n)"，其余完全相同。

单选 · 理解检查 5　对 p=[4,6,5,7,3] 执行 prevCheaper。i=3 这一轮刚结束（已压栈）时，栈里从底到顶的下标是什么？

A. [0, 2, 3]

B. [0, 1, 2, 3]

C. [3]

D. [0, 2, 3, 4]

查看答案与每个选项的解析

A · 正确：i=1 压入 1；i=2 时 6≥5 弹出 1，压入 2；i=3 时 5<7 不弹，压入 3。栈对应价格 4,5,7，严格递增。

B · 错误：i=2 时 p[1]=6 ≥ 5，下标 1 已被弹出。

C · 错误：只有更大或相等的才弹出；4 和 5 都比 7 小，留在栈里。

D · 错误：这是还没处理 i=4 的时候；而且 i=4 时 3 会把前面全部弹掉，栈只剩 [4]。

易错点：

  • 手跑只跑样例，样例往往太"顺"；自己补一个有重复、有一次弹多个的输入。
  • 不变式要在"每轮开始时"成立，写成"循环结束后成立"的句子解释不了中间的每一步。
  • 调试输出写到 cout 会混进答案，导致评测判错；调试一律用 cerr。

速记： 每轮一行填表格，最后一列写容器内容；用一句不变式解释每一行为什么这样写。

35.6 对拍：让暴力替你检查快的版本

为什么需要它

快的版本写完，样例过了，就一定对吗？样例只有一两组，覆盖不到所有情况。对拍的做法是：随机生成大量小数据，同时喂给暴力 brute() 和优化版 fast()，比较输出。暴力几乎不会错，所以两者一旦不一致，多半是 fast() 错了，而且你手里立刻有一个让它出错的输入。

对拍由四个零件组成

零件作用要点
随机数生成器产生输入固定种子，每次运行生成同样的数据，出错可以复现
数据生成造一组输入规模要小（n ≤ 8，值 ≤ 10），值域小才会出现重复、相等等边界情况
比较brute 和 fast 各跑一次不一致就打印输入并停下
缩小把反例变短反复删元素，删了仍出错就保留删除

对拍循环：同一份随机输入喂给两个函数，结果不同就停下来打印

完整走一遍：抓住一个忘了排序的 bug

假设我们把 35.4 的搭档计数写成了下面这样，忘了排序（第④问"有序吗"没答好）：

long long countClosePairsBuggy(vector<int> a, int d) {
    long long cnt = 0;
    int l = 0;
    for (int r = 0; r < (int)a.size(); ++r) {
        while (a[r] - a[l] > d) ++l;
        cnt += r - l;
    }
    return cnt;
}

样例 [5,1,9,3,6]、d=2 上它输出 4（正确答案是 3）。这里样例碰巧暴露了问题；很多时候样例恰好能过，就要靠对拍。对拍的代码如下：[7]

int randInt(mt19937& rng, int lo, int hi) {      // [lo, hi] 里的随机整数，各平台结果一致
    return lo + (int)(rng() % (unsigned)(hi - lo + 1));
}
string showCase(const vector<int>& a, int d) {
    ostringstream os;
    os << "n=" << a.size() << " d=" << d << " a=[";
    for (int i = 0; i < (int)a.size(); ++i) os << (i ? "," : "") << a[i];
    os << "]";
    return os.str();
}
using PairFn = long long (*)(vector<int>, int);
// 返回第一次不一致的轮次（从 1 开始）；全部一致返回 0。不一致时把输入写到 out。
int duipai(PairFn fast, int rounds, unsigned seed, ostream& out, vector<int>& badA, int& badD) {
    mt19937 rng(seed);                            // 固定种子：每次运行生成同样的数据
    for (int round = 1; round <= rounds; ++round) {
        int n = randInt(rng, 0, 8);               // 小数据：n 在 0..8
        vector<int> a(n);
        for (int& x : a) x = randInt(rng, 0, 10); // 值也小：0..10
        int d = randInt(rng, 0, 3);
        long long want = countClosePairsBrute(a, d);
        long long got = fast(a, d);
        if (want != got) {
            out << "round " << round << ": " << showCase(a, d)
                << " brute=" << want << " fast=" << got << "\n";
            badA = a; badD = d;
            return round;
        }
    }
    return 0;
}

逐行读：

  • mt19937 rng(seed);：mt19937 是标准库的随机数引擎，给定同一个种子，每次产生的序列都一样。固定种子的意义是：今天抓到的反例，明天重新运行还能抓到。
  • randInt：rng() 返回一个很大的无符号整数，对区间长度取余再加上 lo，就落在 [lo, hi]。标准库还有 uniform_int_distribution，分布更均匀，但它的具体输出各家编译器可以不同；这里用取余，让书里的输出在任何平台上都能复现。
  • using PairFn = long long (*)(vector<int>, int);：给"函数指针"类型起个别名。这样 duipai 能接收任何签名相同的函数，正确版和错误版都能传进来。
    • 先这样理解：函数名也可以像变量一样传给另一个函数。long long (*)(vector<int>, int) 读作"指向一个函数的指针，这个函数收一个 vector<int> 和一个 int，返回 long long"；写 duipai(fastAnswer, ...) 时，fast 就代表 fastAnswer，调用 fast(a, d) 等于调用 fastAnswer(a, d)。
    • 一时看不懂也没关系：考场上可以不用函数指针，直接在循环里写 long long x = brute(a, d), y = fast(a, d);，要换成错误版时改这一行即可，对拍的思路完全一样。
  • n 从 0 开始：空数组也是合法输入，要一起测。
  • 值域只取 0..10：值域小，随机数组里才会频繁出现相等、相邻的数，边界情况才容易被撞到。
  • ostream& out：传 cout 就打印到屏幕；practice 里传一个 ostringstream，用断言检查打印的内容。

缩小反例

8 个数的反例还是不好手跑。缩小的办法很朴素：试着删掉一个元素，如果删完两者仍然不一致，就真的删掉；重复到删哪个都会让两者一致为止。

vector<int> shrinkCase(vector<int> a, int d, PairFn fast) {
    bool changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i < (int)a.size(); ++i) {
            vector<int> b = a;
            b.erase(b.begin() + i);
            if (countClosePairsBrute(b, d) != fast(b, d)) { a = b; changed = true; break; }
        }
    }
    return a;
}

对拍的 Python 写法与"两个程序"版本

Python 写对拍更短，适合在纸上或面试白板上讲思路：

import random
random.seed(2024)                       # 固定种子
for rnd in range(1, 1001):
    a = [random.randint(0, 10) for _ in range(random.randint(0, 8))]
    d = random.randint(0, 3)
    if brute(a, d) != fast(a, d):
        print("round", rnd, a, d)
        break

笔试是 ACM 模式（22.1）时，暴力和优化版是两个完整程序。这时写一个生成器程序 gen，用命令行循环比较两个程序的输出：

for i in $(seq 1 1000); do
  ./gen $i > in.txt                     # 第 i 组随机数据，种子用 i
  ./brute < in.txt > b.txt
  ./fast  < in.txt > f.txt
  if ! cmp -s b.txt f.txt; then echo "diff at $i"; cat in.txt; break; fi
done

考场结论

  • 对拍 = 固定种子 + 小数据 + 1000 轮比较 + 不一致就打印输入。
  • 数据要小、值域要窄：这样才会撞到相等、空数组、一个元素这些边界。
  • 抓到反例先缩小，再手跑；两三个数的反例通常一眼就能看出原因。
  • 对拍有盲区：小数据测不出溢出和超时。这两项用 35.7 的边界清单单独测最大值。

练一练：给"重复订单"写对拍

题面：为 35.4 的 minRepeatGap 写一个对拍函数 duipaiGap(rounds, seed)，和 minRepeatGapBrute 比较，返回第一次不一致的轮次（全部一致返回 0）。订单号取值范围应该怎么选？

提示：订单号的值域要小（例如 1..4），否则随机数组里几乎不会出现重复，测不到有重复的情况。

int duipaiGap(int rounds, unsigned seed) {
    mt19937 rng(seed);
    for (int round = 1; round <= rounds; ++round) {
        int n = randInt(rng, 0, 9);
        vector<int> ids(n);
        for (int& x : ids) x = randInt(rng, 1, 4);   // 值域小，重复才会多
        if (minRepeatGap(ids) != minRepeatGapBrute(ids)) return round;
    }
    return 0;
}

和例题相比改了哪一处： 生成的数据换成订单号数组，比较的两个函数换成 minRepeatGap 和它的暴力；值域收窄到 1..4，专门制造重复。practice 中断言 1000 轮全部一致。

多选 · 理解检查 6　关于对拍，下列哪些说法正确？

A. 固定随机种子，是为了让出错的数据可以重新生成、反复调试

B. 随机数据应该尽量大，n 取 10⁵ 才能测出 bug

C. 对拍全部通过，也可能还有溢出问题

B · 错误：暴力在大数据上跑不动；而且小数据更容易撞到边界，反例也更容易手跑。

C · 正确：小数据的和很小，不会溢出；最大值要单独测。

D · 正确：值域窄，随机数组里出现重复、相等的概率高，能覆盖相等这类边界。

易错点：

  • 暴力要独立地写，不复用优化版的函数；两边共用一段错误代码，对拍永远一致。
  • 随机数据要满足题目限制（例如"数组有序""d ≥ 0"），否则抓到的"反例"其实是非法输入。
  • 不一致时要打印输入，只打印两个输出没法复现。

速记： 固定种子、小数据、1000 轮、不一致就打印输入，再删元素缩小反例。

35.7 调试清单：打印、断言和边界输入

为什么需要它

答案错了却不知道错在哪，最耗时间的做法是盯着代码看。更快的做法是让程序自己"开口"：打印中间状态、在关键处放断言、用一份固定的边界清单逐个试。这三样工具组合起来，能在几分钟内把问题缩到某一行。

工具一：打印中间状态

在循环里把关键变量打印到 cerr，和手跑表格（35.5）逐行对照，第一处不一致就是 bug 的位置。一个常用的小宏能少打很多字：

#define DBG(x) cerr << #x << " = " << (x) << "\n"
// 用法：DBG(l); DBG(cnt);   输出：l = 2   cnt = 3

#x 会把括号里的表达式原样变成字符串，所以输出里自带变量名。

工具二：assert 断言

assert(条件) 在条件为假时立刻终止程序，并报告文件名、行号和条件原文。[8] 它最适合检查"我以为一定成立的前提"。比如双指针要求数组有序，就在开头写：

assert(is_sorted(a.begin(), a.end()));   // 前提：已排序；不成立时程序立刻停下并报出这一行

如果在 35.6 那个忘了排序的版本开头加上这一行，第一次传入 [9,7,8,…] 就会停下，报出类似 Assertion `is_sorted(a.begin(), a.end())' failed. 的信息，比对拍还早一步发现问题。断言在编译时加上 -DNDEBUG 会被整体关掉，所以它是自测工具，提交前可以留着，也可以删掉。

大多数"样例过了、提交错了"的情况，都出在下面几类输入上。每写完一道题，把清单过一遍：

练一练：最大值与最小值之差

题面：给一个 int 数组（元素在 −2×10⁹～2×10⁹ 之间，可能为空），返回最大值减最小值；空数组返回 0。

提示：按边界清单逐项过一遍：空、一个、负数、最大值。

long long maxMinGap(const vector<int>& a) {
    if (a.empty()) return 0;                      // 边界：空输入
    int mx = a[0], mn = a[0];
    for (int x : a) { mx = max(mx, x); mn = min(mn, x); }
    return (long long)mx - mn;                    // 先转 long long 再相减
}

和例题相比改了哪一处： 和上面的初版相比，加了空输入判断，返回类型和减法改成 long long。注意必须是 (long long)mx - mn：先把 mx 转型，减法就按 long long 做；写成 (long long)(mx - mn) 时，减法已经在 int 里溢出，转型来得太晚。

另外，给 35.4 的 minRepeatGap 也列一份带手算答案的清单，practice 文件里的 runGapEdgeCases 就是参考答案：

多选 · 理解检查 7　int mx = 2000000000, mn = -2000000000; 下列哪些写法能得到正确的 4000000000？

B. long long g = (long long)(mx - mn);

C. long long g = mx - mn;

查看答案与每个选项的解析

A · 正确：mx 先转成 long long，减法按 long long 计算，不会溢出。

B · 错误：括号里的 mx - mn 先按 int 计算，已经溢出，之后再转型来不及。

C · 错误：右边两个 int 相减，结果按 int 计算后才赋给 long long。

D · 正确：1LL * mx 已经是 long long，后面的减法也按 long long 做。

易错点：

  • 调试输出写到 cout 会混进答案；用 cerr，提交前删掉。
  • 清单里"最大值"那一组最容易漏，而它恰好是对拍测不到的。
  • assert 里只写检查，不写有副作用的语句（如 assert(++i < n)），关掉断言时那条语句也会消失。

速记： cerr 打印、assert 守前提、七类边界逐个试；溢出靠"全部取最大值"那一组单独测。

新题 ①：长度不超过 k 的最大收益区间

题面：给 n 笔交易金额 a[i]（收入为正，支出为负），选一段连续的交易，笔数在 1 到 k 之间，使金额总和最大，输出这个最大和。1 ≤ k ≤ n ≤ 10⁵，|a[i]| ≤ 10⁹。样例：a=[2,−3,4,−1,5,−6,3]，k=3，输出 8（选 4,−1,5）。

第 1 步 读题五问。 输入 a、k；输出一个整数；规模 n ≤ 10⁵；限制：有负数、区间非空、长度有上限 k；和最大可达 10⁵×10⁹ = 10¹⁴，用 long long。手算样例：长度 ≤3 的区间里，[4,−1,5] 和为 8 最大；[4,−1,5,−6,3] 虽然更长，但长度 5 超过了 k。

第 2 步 复杂度。 n ≤ 10⁵，查表要 O(n log n) 或 O(n)。

第 3 步 暴力。 列出所有长度不超过 k 的区间，边走边累加，O(n·k)，k=n 时是 O(n²)。

long long maxSumAtMostKBrute(const vector<int>& a, int k) {
    int n = (int)a.size();
    long long best = LLONG_MIN;
    for (int l = 0; l < n; ++l) {
        long long sum = 0;
        for (int r = l; r < n && r - l + 1 <= k; ++r) {   // 长度不超过 k
            sum += a[r];
            best = max(best, sum);
        }
    }
    return best;
}

best 初值是 LLONG_MIN（long long 的最小值），因为全是负数时答案也是负数，用 0 当初值会错。

第 4 步 优化：问五个问题。 问题④"区间和能不能预处理"：设前缀和 P[i] = a[0]+…+a[i−1]，区间 a[j..r−1] 的和是 P[r] − P[j]，长度是 r − j。固定右端 r，要让 P[r] − P[j] 最大，就要在 j ∈ [r−k, r−1] 里找最小的 P[j]。这是一个"滑动窗口的最小值"。

问题⑤"能不能只保留有用的候选"：两个候选 j1 < j2，如果 P[j1] ≥ P[j2]，那么 j1 既更早过期、又不更小，永远不会被选中，可以扔掉。留下来的候选，下标递增、P 值也严格递增，最小的在最前面。两头都要操作（队尾加新候选、踢掉没用的；队头删过期的），用 deque，这叫单调队列。[9] [10]

long long maxSumAtMostK(const vector<int>& a, int k) {
    int n = (int)a.size();
    vector<long long> P(n + 1, 0);                 // P[i] = a[0..i-1] 之和
    for (int i = 0; i < n; ++i) P[i + 1] = P[i] + a[i];
    long long best = LLONG_MIN;
    deque<int> dq;                                 // 存下标 j，P[j] 从队头到队尾严格递增
    for (int r = 1; r <= n; ++r) {                 // 区间是 (j, r]，和为 P[r] - P[j]
        while (!dq.empty() && P[dq.back()] >= P[r - 1]) dq.pop_back();   // 新候选 r-1 入队前，踢掉不如它的
        dq.push_back(r - 1);
        while (dq.front() < r - k) dq.pop_front();  // 长度 r-j 超过 k 的左端过期
        best = max(best, P[r] - P[dq.front()]);     // 队头是窗口里最小的前缀
    }
    return best;
}

long long maxSumAtLeastK(const vector<int>& a, int k) {
    int n = (int)a.size();
    vector<long long> P(n + 1, 0);
    for (int i = 0; i < n; ++i) P[i + 1] = P[i] + a[i];
    long long best = LLONG_MIN, minPre = LLONG_MAX;
    for (int r = k; r <= n; ++r) {
        minPre = min(minPre, P[r - k]);           // 左端 j 可选 0..r-k，每轮只多一个新候选
        best = max(best, P[r] - minPre);
    }
    return best;
}

新题 ②：两个人分任务，耗时差最小

题面：有 n 个任务，第 i 个耗时 t[i]。每个任务整件交给 A 或 B 中的一人。求两人总耗时之差的绝对值最小是多少。1 ≤ n ≤ 8，1 ≤ t[i] ≤ 1000。样例：t=[3,1,4,2,2]，输出 0（A 做 3,1,2，B 做 4,2，各 6）。

第 1 步 读题五问。 输入 t；输出一个整数；规模 n ≤ 8，非常小；限制：任务不能拆、一个人可以一件都不做；手算样例：总和 12，能凑出 6 就是 0。

第 2 步 复杂度。 n ≤ 8，2⁸ = 256 种分法，直接枚举所有子集。到了这一档，暴力就是正解。

第 3 步 暴力。 每个任务"给 A 或给 B"，正好对应子集：mask 的第 i 位为 1 表示任务 i 给 A（第 33 章讲过 mask）。A 的总耗时是 a，B 就是 total − a，差是 |total − 2a|。

int splitTasks(const vector<int>& t) {             // 子集枚举：mask 的第 i 位为 1 表示任务 i 给 A
    int n = (int)t.size(), total = 0;
    for (int x : t) total += x;
    int best = INT_MAX;
    for (int mask = 0; mask < (1 << n); ++mask) {
        int a = 0;
        for (int i = 0; i < n; ++i) if (mask >> i & 1) a += t[i];
        best = min(best, abs(total - 2 * a));       // |A - B| = |A - (total - A)|
    }
    return best;
}

第 4 步 第二种写法，用来对拍。 规模小的题没有"更快的版本"可以对拍，但可以写另一种思路互相检查。递归逐个分配，每个任务两种选择，画出来是一棵二叉树（第 32、33 章的选/不选模型）：

void splitDfs(const vector<int>& t, int i, int a, int b, int& best) {   // 另一种写法：递归逐个分配
    if (i == (int)t.size()) { best = min(best, abs(a - b)); return; }
    splitDfs(t, i + 1, a + t[i], b, best);         // 任务 i 给 A
    splitDfs(t, i + 1, a, b + t[i], best);         // 任务 i 给 B
}
int splitTasksDfs(const vector<int>& t) {
    int best = INT_MAX;
    splitDfs(t, 0, 0, 0, best);
    return best;
}

t=[10,3,3] 时的递归树：每层决定一个任务，左孩子给 A、右孩子给 B，叶子写出"A 的耗时:B 的耗时"和最终的差。

void split3Dfs(const vector<int>& t, int i, vector<int>& load, int& best) {
    if (i == (int)t.size()) { best = min(best, *max_element(load.begin(), load.end())); return; }
    for (int p = 0; p < 3; ++p) {
        load[p] += t[i];
        split3Dfs(t, i + 1, load, best);
        load[p] -= t[i];                           // 撤销
    }
}
int splitTasks3(const vector<int>& t) {
    vector<int> load(3, 0);
    int best = INT_MAX;
    split3Dfs(t, 0, load, best);
    return best;
}

新题 ③：先拿钥匙才能过门的迷宫

题面：R×C 的网格迷宫，S 是起点，E 是出口，# 是墙，. 是空地，K 是钥匙，D 是门。每步走到上下左右相邻的格子。没拿钥匙时门不能进；走到 K 上就自动拿到钥匙，之后所有门都能进。求从 S 到 E 的最少步数，到不了输出 −1。R, C ≤ 100。

样例：

S 在 (0,0)，门 D 在 (0,2)，钥匙 K 在 (2,0)。最短路线先下去拿钥匙，再原路返回过门，共 10 步

第 1 步 读题五问。 输入是字符网格；输出最少步数或 −1；规模 100×100 = 10⁴ 个格子；限制：门要钥匙、钥匙拿了不会丢、可能没有钥匙；手算样例：直接往右走到 (0,1) 就被门挡住，只能先下去拿钥匙，4 步到 K，再 6 步到 E，共 10 步。

第 2 步 复杂度。 "最少步数 + 网格"是 BFS 的信号（第 34 章）：BFS 按距离一层层往外扩，第一次到达某个状态时的步数就是最少步数。[11]

第 3 步 找对状态。 手算时我们注意到，同一个格子 (1,1) 走过两次：第 2 步时没钥匙，第 6 步时有钥匙。这两次能做的事不同（后者能过门），所以它们是两个不同的状态。状态 = (行, 列, 有没有钥匙)，一共 R×C×2 个。

先看只按位置记 visited 的错误写法会怎样（keyDoorBFSWrong，完整代码在 practice 文件中）：

vector<vector<int>> dist(R, vector<int>(C, -1));     // 少了钥匙这一维
// ……其余和正确版相同……
if (ch == '#' || (ch == 'D' && k == 0) || dist[nr][nc] != -1) continue;

样例上它输出 −1。原因：BFS 第 4 步在 (2,0) 拿到钥匙后，想回到 (2,1)、(1,1)、(0,1)，但这些格子在没钥匙时已经走过，dist 不是 −1，全被跳过，带着钥匙的那条路被堵死了。改法是给 dist 加一维钥匙状态。

第 4 步 正确代码。

int keyDoorBFS(const vector<string>& g) {
    int R = (int)g.size(), C = (int)g[0].size();
    int sr = 0, sc = 0;
    for (int r = 0; r < R; ++r)
        for (int c = 0; c < C; ++c)
            if (g[r][c] == 'S') { sr = r; sc = c; }
    // dist[r][c][k]：走到 (r,c) 且钥匙状态为 k（0 没有，1 有）的最少步数，-1 表示还没到过
    vector<vector<vector<int>>> dist(R, vector<vector<int>>(C, vector<int>(2, -1)));
    queue<tuple<int, int, int>> q;
    dist[sr][sc][0] = 0;
    q.push({sr, sc, 0});
    int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};
    while (!q.empty()) {
        auto [r, c, k] = q.front(); q.pop();
        if (g[r][c] == 'E') return dist[r][c][k];   // BFS 第一次到出口就是最少步数
        for (int t = 0; t < 4; ++t) {
            int nr = r + dr[t], nc = c + dc[t];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;   // 出界
            char ch = g[nr][nc];
            if (ch == '#') continue;                                // 墙
            if (ch == 'D' && k == 0) continue;                      // 没钥匙进不了门
            int nk = (ch == 'K') ? 1 : k;                           // 踩到钥匙就拿上
            if (dist[nr][nc][nk] != -1) continue;                   // 这个状态来过
            dist[nr][nc][nk] = dist[r][c][k] + 1;
            q.push({nr, nc, nk});
        }
    }
    return -1;
}

逐行读：

  • dist 是三维的：前两维是位置，第三维是钥匙状态。-1 同时表示"没到过"，省掉单独的 visited 数组。
  • queue<tuple<int,int,int>>：队列里放的是完整状态（行、列、钥匙），取出时用结构化绑定 auto [r, c, k] 拆开。
  • dr、dc 两个数组写出四个方向，循环 4 次就是上下左右。
  • 判断顺序：出界 → 墙 → 门 → 算出新钥匙状态 → 查这个新状态来过没有。nk 必须在查 dist 之前算好，因为"来没来过"要按新状态查。
  • 入队时就写 dist，保证每个状态只入队一次，总复杂度 O(R×C×2)。

Python 对照，状态直接用元组当字典的键：

from collections import deque
def key_door_bfs(g):
    R, C = len(g), len(g[0])
    s = next((r, c) for r in range(R) for c in range(C) if g[r][c] == 'S')
    dist = {(s[0], s[1], 0): 0}; q = deque([(s[0], s[1], 0)])
    while q:
        r, c, k = q.popleft()
        if g[r][c] == 'E': return dist[(r, c, k)]
        for nr, nc in ((r-1, c), (r+1, c), (r, c-1), (r, c+1)):
            if 0 <= nr < R and 0 <= nc < C and g[nr][nc] != '#' and (g[nr][nc] != 'D' or k):
                nk = 1 if g[nr][nc] == 'K' else k
                if (nr, nc, nk) not in dist: dist[(nr, nc, nk)] = dist[(r, c, k)] + 1; q.append((nr, nc, nk))
    return -1

练一练：两种钥匙、两种门。 钥匙 a 开门 A，钥匙 b 开门 B。状态里的"有没有钥匙"变成"有哪些钥匙"，用两位二进制表示：第 0 位是 a，第 1 位是 b，一共 4 种（第 33 章的 mask）。

int keyDoor2BFS(const vector<string>& g) {
    int R = (int)g.size(), C = (int)g[0].size(), sr = 0, sc = 0;
    for (int r = 0; r < R; ++r)
        for (int c = 0; c < C; ++c)
            if (g[r][c] == 'S') { sr = r; sc = c; }
    vector<vector<vector<int>>> dist(R, vector<vector<int>>(C, vector<int>(4, -1)));
    queue<tuple<int, int, int>> q;
    dist[sr][sc][0] = 0;
    q.push({sr, sc, 0});
    int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};
    while (!q.empty()) {
        auto [r, c, m] = q.front(); q.pop();
        if (g[r][c] == 'E') return dist[r][c][m];
        for (int t = 0; t < 4; ++t) {
            int nr = r + dr[t], nc = c + dc[t];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            char ch = g[nr][nc];
            if (ch == '#') continue;
            if ((ch == 'A' || ch == 'B') && !(m >> (ch - 'A') & 1)) continue;   // 门 A 要第 0 位，门 B 要第 1 位
            int nm = m;
            if (ch == 'a' || ch == 'b') nm |= 1 << (ch - 'a');                 // 拿钥匙：把对应位设成 1
            if (dist[nr][nc][nm] != -1) continue;
            dist[nr][nc][nm] = dist[r][c][m] + 1;
            q.push({nr, nc, nm});
        }
    }
    return -1;
}

和例题相比改了哪一处： 第三维从 2 变成 4；判断门时检查 mask 的对应位，拿钥匙时用 |= 把对应位设成 1。网格 {"S.A.E", "#.###", "b.Ba#"} 的答案是 14：先拿 b，过门 B 拿 a，再一路回来过门 A。practice 里还断言了：把一种钥匙的迷宫改写成 a/A 后，两个函数结果相同。

单选 · 理解检查 9　钥匙迷宫的网格是 50×60，只有一种钥匙。BFS 的状态最多有多少个？

A. 6000

B. 3000

C. 12000

D. 3000 的 2 次方

查看答案与每个选项的解析

A · 正确：50×60 = 3000 个位置，每个位置有"有钥匙/没钥匙"两种，共 3000×2 = 6000 个状态。

B · 错误：这是只按位置算，正是 keyDoorBFSWrong 的错误：同一位置有无钥匙是不同状态。

C · 错误：一种钥匙只有 2 种钥匙状态；两种钥匙才是 4 种，那时才是 12000。

易错点：

  • 状态少了一维，BFS 会把"带着钥匙回头走"当成重复状态跳过；手算时同一格子走两次，就是要加维度的信号。
  • 最大和类问题的初值用 LLONG_MIN；全负数时用 0 当初值会输出 0。
  • n 很小时暴力就是正解，省下的时间用来写对拍和测边界。

        {"3 5\n1000000000 1 1000000000\n", "3000000012\n"},   // 自造：最大值，检查溢出
    };
    int bad = 0;
    for (auto& [in, want] : samples)
        if (solveElevatorText(in) != want) ++bad;
    return bad;
}

逐行读： istringstream in(input) 把字符串变成一个输入流，后面的 in >> 和 cin >> 用法完全一样（22.12）。三组样例分别是：题目给的、最小边界、最大值。提交时 main 里改成从 cin 读入整段输入，再调用同样的逻辑。

练一练：把"重复订单"包成 ACM 模式

题面：输入第一行是 n，第二行是 n 个订单号；输出最小距离（没有重复输出 −1）。写 solveGapText，并准备三组自测样例。

string solveGapText(const string& input) {
    istringstream in(input);
    int n;
    in >> n;
    vector<int> ids(n);
    for (int& x : ids) in >> x;
    return to_string(minRepeatGap(ids)) + "\n";
}

和例题相比改了哪一处： 输入格式从"m s + m 个楼层"换成"n + n 个订单号"，核心逻辑换成 minRepeatGap。三组样例："7\n7 3 9 3 7 9 9\n" → "1\n"，"3\n1 2 3\n" → "-1\n"，"0\n" → "-1\n"（n=0 时第二行为空，循环不读任何数）。

多选 · 理解检查 10　笔试还剩 15 分钟，你只想出了 O(n²) 的暴力，题目 n ≤ 10⁵，其中 40% 的数据 n ≤ 3000。哪些做法合理？

A. 先把暴力写完整并提交，拿到 n ≤ 3000 那部分分

B. 放弃暴力，继续想正解，到最后再一起写

C. 提交前用样例、空输入、最大值三组数据自测一遍

D. 如果题目说明一部分数据全是正数且有简单做法，可以按情况分支处理

查看答案与每个选项的解析

A · 正确：3000² ≈ 10⁷，暴力能过这 40% 的测试点。

B · 错误：时间不够时可能一行都交不上，连 40% 也拿不到。

C · 正确：格式或边界的错误会让本来能过的测试点也失分。

D · 正确：按数据特点分段处理，能多拿一部分分。

易错点：

  • 一上来就写代码，写到一半发现思路不对；先说清楚思路、得到面试官认可再写，返工最少。
  • 只测题目样例就提交；至少再加一组最小边界、一组最大值。
  • 笔试时调试输出忘了删，并且写到了 cout，所有测试点都会判错。

速记： 先说暴力再说优化，边写边讲，写完测三组；卡住就退回暴力，保住部分分。
