32.1 函数调用时到底发生了什么

递归就是函数调用它自己。要理解递归，先要理解普通的函数调用：调用另一个函数时，当前函数停在哪里？被调用函数的变量存放在哪里？return 之后程序回到哪一行？弄清这三个问题后，递归只是多了一个条件：被调用的恰好是函数自己。

调用栈：一摞便签

设想你在桌上计算一张表（main）。算到一半需要 f(1) 的值，于是拿一张新便签，写上“算 f(1)，x=1”，压在表的上面。计算 f 时又需要 g(2)，再拿一张便签压在最上面。g 算完后，把答案抄回 f 的便签，撕掉 g 的便签；f 算完后，把答案抄回表上，撕掉 f 的便签。整个过程中，你始终只在最上面的那张便签上工作。

计算机中与这摞便签对应的概念如下：

术语中文解释对应便签
调用栈（call stack）程序运行时记录"哪些函数正在执行、执行到哪"的一块内存，只在顶部放入和取出整摞便签
栈帧（stack frame）每调用一次函数，栈顶就多一个帧；帧里有这次调用的参数、局部变量、返回后要回到的位置一张便签
压栈（push）调用函数时，把新帧放到栈顶压上一张新便签
弹栈（pop）函数 return 时，栈顶帧被移走，程序回到下面那一帧记住的位置撕掉最上面那张

C++ 把函数里的普通局部变量叫作"自动存储期"（automatic storage duration）的对象：执行进入它所在的代码块时创建，离开时销毁 [1]。所以每次调用都有一份全新的局部变量，函数返回后这一份就消失。return 语句结束当前函数，把值交回给调用它的表达式 [2]；调用表达式本身的含义是"转去执行被调函数，结束后用它的返回值作为这个表达式的值" [3]。

要点

  1. 每调用一次函数，就新建一个栈帧；参数和局部变量都在这个帧里，名字相同的变量在不同帧里互不影响。
  2. 调用者在调用处暂停，等被调用者 return；return 只回到上一层，从调用语句的下一步继续（先把返回值用掉，例如赋给 r）。
  3. 栈顶永远是正在执行的函数；栈里同时存在的帧数，叫作调用深度。
  4. 函数返回后，它的帧和帧里的局部变量一起消失。

题面： 预测下面的 stepA(1) 打印什么、返回什么。

int stepC(int x) {
    cout << "c" << x << " ";
    return x + 100;
}
int stepB(int x) {
    cout << "b" << x << " ";
    int t = stepC(x * 2);
    cout << "b" << t << " ";
    return t + 1;
}
int stepA(int x) {
    cout << "a" << x << " ";
    int t = stepB(x + 1);
    int u = stepC(x);
    cout << "a" << t + u << " ";
    return t;
}
def step_c(x):
    print(f"c{x}", end=" ")
    return x + 100

def step_b(x):
    print(f"b{x}", end=" ")
    t = step_c(x * 2)
    print(f"b{t}", end=" ")
    return t + 1

def step_a(x):
    print(f"a{x}", end=" ")
    t = step_b(x + 1)
    u = step_c(x)
    print(f"a{t + u}", end=" ")
    return t

提示： 画出调用栈。stepA 的帧中有 x、t、u；stepB 的帧中也有一个 x 和一个 t，它们是另外的变量。stepC 被调用了两次，每次都有一个新的帧。

参考答案： 输出 a1 b2 c4 b104 c1 a206，返回 105。stepA(1) 打印 a1，调用 stepB(2)；stepB 打印 b2，调用 stepC(4)，stepC 打印 c4 并返回 104；stepB 打印 b104，返回 105，于是 stepA 的 t=105；接着 stepC(1) 打印 c1 并返回 101，u=101；最后打印 a206。

与例题的区别： 例题中每个函数只调用下一层一次；这里 stepC 被两个不同的调用者各调用一次，两次的 x 分别是 4 和 1，用来确认每次调用都有一个新的帧。

更多练习

练习 32.1-1【基础】调用日志里最深有几层

题面：程序运行时记下一份调用日志 log：元素是函数名，表示调用这个函数（压一帧）；元素是 "ret"，表示栈顶函数 return（弹一帧）。日志开始时栈里只有 main，main 不出现在日志里，也不计入层数；日志保证合法，"ret" 时栈里一定有 main 之外的帧。写 maxCallDepth(log) 返回 main 之外的帧最多同时有几个，0 ≤ 日志长度 ≤ 10⁵。样例：{"f","g","ret","h","ret","ret"} 返回 2（f 调 g 时栈里是 f、g 两帧；g 返回后 f 再调 h，仍是两帧）；{"a","ret","b","ret"} 返回 1；空日志返回 0。

提示

思路提示：问的是栈的高度，栈里具体是谁用不到，所以一个整数 depth 就够了。调用让 depth 加 1，ret 让 depth 减 1；最大值只可能在压栈之后出现，所以只在加 1 之后更新 best。这就是 32.1 结论 3 里的"调用深度"。

参考答案
int maxCallDepth(const vector<string>& log) {
    int depth = 0, best = 0;
    for (const string& e : log) {
        if (e == "ret") --depth;                 // 弹一帧
        else best = max(best, ++depth);          // 压一帧，更新最深
    }
    return best;
}
def max_call_depth(log):
    depth, best = 0, 0
    for e in log:
        if e == "ret":
            depth -= 1                           # 弹一帧
        else:
            depth += 1                           # 压一帧，更新最深
            best = max(best, depth)
    return best

练习 32.1-2【变形】return 之后回到哪个函数

题面：日志格式与上一题相同。每遇到一个 "ret"，记下 return 之后继续执行的函数名，也就是弹栈之后的新栈顶；如果只剩 main，记 "main"。写 returnTargets(log) 按顺序返回这些名字。样例：{"f","g","ret","h","ret","ret"} 返回 {"f","f","main"}；{"a","b","c","ret","ret","d","ret","ret"} 返回 {"b","a","a","main"}（c 返回到 b，b 返回到 a，d 返回到 a，a 返回到 main）。

提示

思路提示：上一题只要高度，这一题要知道新栈顶是谁，所以必须把每一帧的名字存下来。用 vector<string> 当栈：调用时 push_back 名字，ret 时 pop_back，然后读 back()。pop 之后如果栈空，说明回到了 main，此时不能读 back()。和上一题相比，状态从一个整数换成了整摞帧。

参考答案
vector<string> returnTargets(const vector<string>& log) {
    vector<string> st, res;                      // st：main 之外的帧，back() 是栈顶
    for (const string& e : log) {
        if (e != "ret") { st.push_back(e); continue; }
        st.pop_back();                           // 栈顶函数 return
        res.push_back(st.empty() ? "main" : st.back());   // 回到新的栈顶
    }
    return res;
}
def return_targets(log):
    st, res = [], []                             # st：main 之外的帧，st[-1] 是栈顶
    for e in log:
        if e != "ret":
            st.append(e)
            continue
        st.pop()                                 # 栈顶函数 return
        res.append(st[-1] if st else "main")     # 回到新的栈顶
    return res

练习 32.1-3【综合】找出调用日志的第一处错误

题面：日志改成带名字的成对格式："+f" 表示进入 f，"-f" 表示 f 返回。合法的日志满足两条：每个 "-name" 返回的必须正是当前栈顶函数；日志结束时 main 之外没有帧。写 firstBadEntry(log)：返回第一条出错日志的下标；每一条都没错、但结束时还有帧没返回，返回日志长度；完全合法返回 −1。0 ≤ 日志长度 ≤ 10⁵。样例：{"+f","+g","-g","-f"} 返回 −1；{"+f","+g","-f"} 返回 2（栈顶是 g，f 在等 g，不可能先返回）；{"-f"} 返回 0（栈里只有 main）；{"+f","+g","-g"} 返回 3；空日志返回 −1。

提示

思路提示：用 vector<string> 模拟调用栈，错误分三种。"-name" 时栈空：没有帧可弹。"-name" 的名字和栈顶不同：return 只能弹栈顶那一帧（32.1 结论 2）。前两种在扫描中发现就立刻返回当前下标；栈空时读 back() 是越界，所以先判空再比名字。第三种是结束时栈非空，只能在循环之后检查。测试另写一个暴力版：对每个 "-name" 往回扫，用计数器跳过已经配对的进出，找到它对应的 "+name"，与栈模拟的结果对拍。

参考答案
int firstBadEntry(const vector<string>& log) {
    vector<string> st;
    for (int i = 0; i < (int)log.size(); ++i) {
        string name = log[i].substr(1);
        if (log[i][0] == '+') { st.push_back(name); continue; }
        if (st.empty() || st.back() != name) return i;   // 没有帧可弹，或弹的不是栈顶
        st.pop_back();
    }
    return st.empty() ? -1 : (int)log.size();            // 还有帧没 return
}
def first_bad_entry(log):
    st = []
    for i in range(len(log)):
        name = log[i][1:]
        if log[i][0] == "+":
            st.append(name)
            continue
        if not st or st[-1] != name:             # 没有帧可弹，或弹的不是栈顶
            return i
        st.pop()
    return -1 if not st else len(log)            # 还有帧没 return

易错点：

  • 把不同帧里同名的变量当成同一个。f 的 x 和 g 的 x 只是名字相同，各自存在自己的帧里。
  • 以为 return 会直接回到 main。return 只弹出栈顶一帧，回到紧挨着的调用者。

小结： 每次调用都压入一个新的帧，局部变量各有一份；return 只弹出一帧，回到调用点继续执行。

32.2 第一个递归：倒数和阶乘

有些问题的内部包含一个形状相同、规模更小的问题。例如从 3 倒数到发射：先喊 3，剩下的事情是从 2 倒数到发射，与原来的事情完全相同，只是数字小了 1。函数可以调用自己来处理这个规模更小的问题，这就是递归（recursion）。

基例与递推

一个能够结束的递归函数由两部分组成：

  • 基例（base case，也叫停止条件）：最小的情况，直接给出答案，不再调用自己。倒数的基例是"数到 0，喊发射"。
  • 递推（recursive case）：把问题变小一点，调用自己处理小问题，再用小问题的结果完成当前这一步。
void countdown(int n) {
    if (n == 0) {                 // 基例：数到 0 就发射，不再往下调用
        cout << "发射!\n";
        return;
    }
    cout << n << "\n";            // 当前这一层负责打印 n
    countdown(n - 1);             // 剩下的交给 countdown(n-1)
}
def countdown(n):
    if n == 0:                    # 基例：数到 0 就发射，不再往下调用
        print("发射!")
        return
    print(n)                      # 当前这一层负责打印 n
    countdown(n - 1)              # 剩下的交给 countdown(n-1)

countdown(3) 输出 3、2、1、发射! 四行。

逐行说明：

行作用去掉会怎样
if (n == 0)判断是否到了最小情况永远停不下来（见下面的错误示范）
cout << "发射!"; return;基例的答案，并立刻结束这一层去掉 return，会接着往下打印 0 并调用 countdown(-1)
cout << n这一层只做自己那一份工作少打印一个数
countdown(n - 1)把更小的问题交给下一层只打印一个数就结束

每一层只打印自己的 n，再把更小的问题交给下一层；n 变成 0 时停下（绿色是基例）

有返回值的递归：阶乘

n! = n × (n−1) × … × 1，并规定 0! = 1。由于 n! = n × (n−1)!，大问题的答案可以由规模小 1 的问题的答案得到：

long long fact(int n) {
    if (n == 0) return 1;         // 基例：0! = 1
    return n * fact(n - 1);       // 递推：n! = n × (n-1)!
}
def fact(n):
    if n == 0:                    # 基例：0! = 1
        return 1
    return n * fact(n - 1)        # 递推：n! = n × (n-1)!；Python 整数不溢出

逐行说明： 第 2 行是基例，n 为 0 时直接返回 1。第 3 行先调用 fact(n - 1) 拿到 (n−1)!，再乘上本帧自己的 n。注意顺序：乘法要等子调用返回之后才能算，所以本帧的 n 必须一直保存在帧里，这正是调用栈的作用。

Segmentation fault

Segmentation fault（段错误）是操作系统把访问越界内存的程序强行终止时给出的提示。同一份代码加上 -O2 编译时，编译器可能把这种"最后一步调用自己"的写法改成循环，程序就不再崩溃，而是一直打印不停，直到被超时杀掉。两种现象的原因相同：没有基例。g++ 开 -Wall 时，对某些明显停不下来的递归会给出 -Winfinite-recursion 警告 [4]，例如把 fact 的第一行删掉，编译器会提示 "infinite recursion detected"。

要点

  1. 递归函数由基例和递推组成，先写基例，再写递推。
  2. 每次递推都必须让问题向基例靠近（n 变小、区间变短、字符串变短）。
  3. 有返回值的递归，计算发生在“归”的阶段：先得到子问题的答案，再计算当前的答案。

练习 32.2-3【综合】3n+1 要变几次才到 1

题面：对正整数 n 反复变换：偶数变成 n/2，奇数变成 3n+1，直到变成 1。写递归函数 collatzSteps(n) 返回变换次数，1 ≤ n ≤ 10⁶。样例：1 返回 0；6 返回 8（6、3、10、5、16、8、4、2、1）；7 返回 16。

提示

思路提示：递推按奇偶分两种写法，但每层只走其中一种，调用过程仍是一条链。本题范围内最多变换 524 次（n=837799），递归深度不成问题。真正的边界是溢出：n=704511 的变换过程中最大值是 56,991,483,520，int 最大约 2.1×10⁹，3n+1 会溢出成负数，之后再也等不到基例 n == 1。所以参数用 long long。测试另写一个 while 循环版，在随机的 n 上对拍。

参考答案
int collatzSteps(long long n) {                  // long long：3n+1 会超过 int
    if (n == 1) return 0;                        // 已经是 1
    if (n % 2 == 0) return 1 + collatzSteps(n / 2);
    return 1 + collatzSteps(3 * n + 1);
}
def collatz_steps(n):                            # Python 整数不溢出，C++ 必须用 long long
    if n == 1:                                   # 已经是 1
        return 0
    if n % 2 == 0:
        return 1 + collatz_steps(n // 2)
    return 1 + collatz_steps(3 * n + 1)

易错点：

  • 基例只写了 n == 0，但递推会跳过 0（步长为 2，或输入本身是负数）。基例条件要能接住所有越界的情况。
  • 在基例里忘了 return。程序会继续执行下面的递推代码。
  • 把 return n * fact(n - 1) 写成 fact(n - 1); return n;：子调用的结果被丢掉了。

小结： 先写基例，再写递推；每一步都要向基例靠近；没有基例的递归会导致栈溢出。

32.3 怎样设计递归：三句话与“相信函数”

看懂 fact 之后，自己写递归时常会遇到一个困难：试图把每一层都在头脑中展开，展开三层就跟不上了。设计递归的正确方法是只考虑一层，下面的三句话就是这种方法的具体步骤。

三句话

写递归函数之前，先写下三句话：

  1. 含义：这个函数接收什么、返回什么（或者完成什么）。要具体到参数，例如“sumFrom(a, i) 返回 a[i] 到 a[n−1] 的和”。
  2. 最小情况：哪种输入小到可以直接回答？答案是什么？
  3. 相信函数：假设这个函数对规模更小的输入已经正确，即按照第 1 句的含义返回了正确结果，用这个结果得出当前的答案。

第 3 句最关键，也最违反直觉：写第 3 句时不去展开规模更小的调用，而是直接把它当作一个已经写好并测试过的库函数来使用。

类比：排队报数。 你站在一条长队中，想知道自己排第几。你问前面的人排第几，他也不知道，于是再问他前面的人……队首的人知道自己是第 1，这是最小情况。每个人得到前面那人的答案后加 1，再告诉后面的人。你自己只需要做一件事：相信前面那人告诉你的数是对的，然后加 1，至于他是怎么得到这个数的，不需要知道。

之所以可以这样相信，是因为最小情况的答案是正确的，而且只要规模更小时正确就能推出当前正确，那么从最小情况开始一层层向上推，每一层都正确。这与数学归纳法是同一个道理：第 2 句是归纳基础，第 3 句是归纳步骤。

例 1：数组求和 sumFrom(a, i)

三句话：

  1. 含义：sumFrom(a, i) 返回 a[i] + a[i+1] + … + a[n−1]。
  2. 最小情况：i == n 时区间为空，和为 0。
  3. 相信函数：sumFrom(a, i + 1) 已经正确返回了 a[i+1..n−1] 的和，所以当前的答案是 a[i] + sumFrom(a, i + 1)。
int sumFrom(const vector<int>& a, int i) {
    if (i == (int)a.size()) return 0;          // 最小情况：空区间，和为 0
    return a[i] + sumFrom(a, i + 1);           // 相信 sumFrom(a, i+1) 已经算对
}
def sum_from(a, i):
    # a 传的是同一个列表对象的引用，不复制（作用相当于 C++ 的 const&），这里只读不改
    # 递归深度是 len(a)+1：Python 默认上限约 1000 层，列表上千个元素就会 RecursionError
    if i == len(a):                            # 最小情况：空区间，和为 0
        return 0
    return a[i] + sum_from(a, i + 1)           # 相信 sum_from(a, i+1) 已经算对

调用时写 sumFrom(a, 0)，表示整个数组的和。

a 按 const 引用传递，既不复制也不修改；i 是当前区间的起点，每深入一层加 1；返回值是 a[i..n−1] 的和。

例 2：字符串反转

  1. 含义：reverseStr(s) 返回 s 倒过来的字符串。
  2. 最小情况：s 的长度 ≤ 1 时，倒过来还是它自己。
  3. 相信函数：reverseStr(s.substr(1)) 已经把去掉首字符后的部分正确地倒了过来，当前答案就是它再接上首字符。例如 s="abc"：相信 reverseStr("bc") = "cb"，接上 'a' 得到 "cba"。
string reverseStr(const string& s) {
    if (s.size() <= 1) return s;               // 空串或一个字符：倒过来还是自己
    return reverseStr(s.substr(1)) + s[0];     // 后面部分倒过来，再把首字符接到最后
}
def reverse_str(s):
    if len(s) <= 1:                            # 空串或一个字符：倒过来还是自己
        return s
    return reverse_str(s[1:]) + s[0]           # str 不可变：s[1:] 和 + 都生成新串，同样 O(n²)

s.substr(1) 取从下标 1 到末尾的子串 [5]。这种写法每层都复制一次子串，总时间 O(n²)，用来练习思路是足够的；需要效率时，改用传下标的写法（见练习中的 isPal）。

例 3：求最大值

  1. 含义：maxFrom(a, i) 返回 a[i..n−1] 中的最大值，要求 i ≤ n−1，即区间非空。
  2. 最小情况：只剩一个元素（i == n−1）时，最大值就是 a[i]。
  3. 相信函数：maxFrom(a, i + 1) 已经是后面部分的最大值，当前答案是它与 a[i] 中较大的一个。
int maxFrom(const vector<int>& a, int i) {
    if (i == (int)a.size() - 1) return a[i];   // 只剩一个元素
    return max(a[i], maxFrom(a, i + 1));
}
def max_from(a, i):
    if i == len(a) - 1:                        # 只剩一个元素
        return a[i]
    return max(a[i], max_from(a, i + 1))

这里的最小情况是一个元素，而 sumFrom 的最小情况是零个元素。原因在于第 1 句：空区间的和有确定的值 0，而空区间的最大值没有定义，所以 maxFrom 的含义中要求区间非空。第 1 句写清楚了，第 2 句也就随之确定了。

例 4：快速幂 power(x, n)

  1. 含义：power(x, n) 返回 x 的 n 次方，n ≥ 0。
  2. 最小情况：n == 0 时返回 1。
  3. 相信函数：power(x, n / 2) 已经正确返回 x^(n/2)（整数除法，向零截断），记为 half。n 为偶数时 x^n = half × half；n 为奇数时 n = 2×(n/2) + 1，所以 x^n = half × half × x。
long long power(long long x, int n) {
    if (n == 0) return 1;                      // x^0 = 1
    long long half = power(x, n / 2);          // 相信它返回 x^(n/2)
    if (n % 2 == 0) return half * half;        // n 偶数：x^n = half²
    return half * half * x;                    // n 奇数：多乘一个 x
}
def power(x, n):
    if n == 0:                                 # x^0 = 1
        return 1
    half = power(x, n // 2)                    # 相信它返回 x^(n//2)；n >= 0 时 // 与 C++ 的 / 相同
    if n % 2 == 0:                             # n 偶数：x^n = half²
        return half * half
    return half * half * x                     # n 奇数：多乘一个 x；Python 整数不会溢出

逐行说明： 第 3 行只调用一次自己，并把结果存入 half。如果写成 return power(x, n/2) * power(x, n/2);，同一个子问题会被计算两遍，速度就退回到与逐个相乘一样慢。第 4、5 行按 n 的奇偶得出答案。

每次把 n 折半：13 只需要 5 次调用；每格第二行是归的路上算出的值

关于“相信函数”的三个常见疑问

问：没有展开规模更小的调用，怎么知道它确实正确？ 答：由两点保证。第一，最小情况的答案是直接写出的，一眼就能判断对错；第二，第 3 句中由小问题得到当前答案的方法本身是正确的（a[i] 加上后面部分的和，等于从 i 开始的和）。最小情况正确，每一步的推导也正确，那么从最小情况向上，每一层都正确。写完代码后，再用最小的两三个输入（例如空数组、一个元素、两个元素）手工模拟一遍，这一步是验证，它与设计是分开进行的。

问：规模更小的调用内部还在调用更小的，这么多层同时存在，会不会互相干扰？ 答：每一层都有自己的帧（32.1），各自的 i 互不覆盖。每一层只完成自己的那一份工作：读取自己的 a[i]，等待下一层返回一个数，相加后返回。整体之所以正确，正是因为每一层都严格按照第 1 句的含义返回结果。

问：规模更小的问题应当怎样选择？ 答：看第 1 句中哪个参数决定问题的规模。sumFrom 的规模是区间长度 n−i，i 加 1 就短了一个；power 的规模是 n，折半比减 1 更快；reverseStr 的规模是字符串的长度，去掉首字符就短了一个。选好之后检查两点：规模每次都严格变小；最终一定能到达第 2 句的最小情况。

n 每次减半时，n ≥ 1 的调用次数是 ⌊log₂n⌋ + 2；逐个相乘的 powerSlow（x * powerSlow(x, n-1)）则需要 n+1 次。例如 n=13 时，两者分别调用 5 次和 14 次。

要点

  1. 写递归之前先写三句话：含义、最小情况、相信函数。三句话写对了，代码基本上就是逐句翻译。
  2. 第 1 句要具体到参数的含义（如“a[i..n−1] 的和”），而不是笼统地说“求和”。
  3. 写第 3 句时只考虑一层，把递归调用当作已经正确的函数直接使用。
  4. 规模更小的问题可以是 i+1、n−1、n/2、去掉首字符等，只要每一步都更接近最小情况。

题 1：各位数字之和。 digitSum(n) 返回非负整数 n 的各位数字之和，例如 digitSum(2026) = 2+0+2+6 = 10。

提示：含义如题；最小情况是一位数（n < 10），答案就是 n；相信 digitSum(n / 10) 已经是去掉个位以后的各位数字之和，再加上个位 n % 10。

int digitSum(int n) {                          // n >= 0
    if (n < 10) return n;                      // 一位数：各位和就是它自己
    return digitSum(n / 10) + n % 10;          // 去掉个位的部分 + 个位
}
def digit_sum(n):                              # n >= 0
    if n < 10:                                 # 一位数：各位和就是它自己
        return n
    return digit_sum(n // 10) + n % 10         # 去掉个位的部分 + 个位（// 是整除）

与例题的区别：sumFrom 每次去掉数组最前面的一个元素，这里每次去掉数字的最后一位。

题 2：递归判断回文串。 isPal(s, l, r) 判断 s[l..r] 是否从左读和从右读一样。例如 "level" 是回文，"abca" 不是。

提示：含义如题；最小情况是 l ≥ r（0 个或 1 个字符），一定是回文；否则两端字符不同就直接返回 false，相同就相信 isPal(s, l + 1, r - 1) 能判断中间的那一段。

bool isPal(const string& s, int l, int r) {    // s[l..r] 是不是回文
    if (l >= r) return true;                   // 0 个或 1 个字符
    if (s[l] != s[r]) return false;            // 两端不同，直接否定
    return isPal(s, l + 1, r - 1);             // 两端相同，看里面
}
def is_pal(s, l, r):                           # s[l..r] 是不是回文
    if l >= r:                                 # 0 个或 1 个字符
        return True
    if s[l] != s[r]:                           # 两端不同，直接否定
        return False
    return is_pal(s, l + 1, r - 1)             # 两端相同，看里面

与例题的区别：规模缩小的方式是从两端同时缩短；并且多了一个提前返回 false 的出口。用下标而不复制子串，每层只需 O(1)。

题 3：汉诺塔。 三根柱子 A、B、C，A 上有 n 个盘子，大的在下。每次移动一个盘子，大盘不能压在小盘上。输出把全部盘子从 A 移到 C 的步骤，n=3 时应输出 7 步。

提示，三句话如下：

  1. 含义：hanoi(n, from, via, to, moves) 把 from 柱上最上面的 n 个盘子借助 via 移到 to，并把每一步记入 moves。
  2. 最小情况：n == 0，什么都不用做。
  3. 相信函数：hanoi(n−1, …) 能正确移动 n−1 个盘子。于是先把上面的 n−1 个盘子从 from 移到 via（以目标柱作为中转），再把最大的盘子从 from 移到 to，最后把 n−1 个盘子从 via 移到 to。
void hanoi(int n, char from, char via, char to, vector<string>& moves) {
    if (n == 0) return;                                   // 0 个盘子：什么都不用做
    hanoi(n - 1, from, to, via, moves);                   // 相信：上面 n-1 个先挪到中转柱
    moves.push_back(string(1, from) + "->" + to);         // 最大的盘子一步到位
    hanoi(n - 1, via, from, to, moves);                   // 相信：n-1 个再从中转柱挪到目标柱
}
def hanoi(n, frm, via, to, moves):             # from 是 Python 关键字，改名 frm
    # moves 是列表：各层拿到的是同一个列表对象，append 直接改到调用者手里的列表（等同 C++ 的 &）
    if n == 0:                                            # 0 个盘子：什么都不用做
        return
    hanoi(n - 1, frm, to, via, moves)                     # 相信：上面 n-1 个先挪到中转柱
    moves.append(frm + "->" + to)                         # 最大的盘子一步到位
    hanoi(n - 1, via, frm, to, moves)                     # 相信：n-1 个再从中转柱挪到目标柱

上图中 h 是 hanoi 的简写，h(2, A→B) 表示把 2 个盘子从 A 移到 B；中间一层的 A->C 是移动最大盘子的那一步。每个 h(1, …) 再展开就是一次移动。

hanoi(3, 'A', 'B', 'C', moves) 得到 7 步：A->C、A->B、C->B、A->C、B->A、B->C、A->C。步数满足 T(n) = 2T(n−1) + 1，T(0)=0，所以 T(n) = 2ⁿ − 1。

与例题的区别：前面的例子每层只调用自己一次，汉诺塔每层调用两次，而且两次调用中柱子的角色不同。这道题几乎无法靠展开来理解，只能依靠“相信函数”。

附加题：快速幂取模。 powMod(a, n, m) 返回 aⁿ mod m（a ≥ 0，m ≥ 1）。和 power 相同，只是每次乘法后取模，防止溢出：r = half * half % m; if (n % 2 == 1) r = r * (a % m) % m;，基例返回 1 % m（m=1 时答案是 0）。

多选 · 理解检查 3　设计 countChar(s, i, c)：返回 s[i..] 中字符 c 出现的次数。下列哪些写法符合三句话、结果正确？

A. if (i == (int)s.size()) return 0; return (s[i] == c ? 1 : 0) + countChar(s, i + 1, c);

B. if (i == (int)s.size()) return 0; if (s[i] == c) return 1 + countChar(s, i + 1, c); return countChar(s, i + 1, c);

C. if (s[i] == c) return 1 + countChar(s, i + 1, c); return countChar(s, i + 1, c);

D. if (i == (int)s.size()) return 0; return countChar(s, i + 1, c);

查看答案与每个选项的解析

A · 正确：最小情况是空后缀，次数 0；相信后面部分已算对，再加上当前字符的贡献。

B · 正确：拆成两种情况写，含义与上一项相同，结果正确。

C · 错误：没有最小情况：i 会一直增加，越过字符串末尾去读 s[i]。

D · 错误：相信了小一号，却把当前字符的贡献丢掉了，结果永远是 0。

练习 32.3-1【基础】零下的天数

题面：数组 t 按日期记录每天的最低气温（0 ≤ 长度 ≤ 500）。写 countBelowZero(t, i) 返回 t[i..n−1] 中低于 0 度的天数，调用 countBelowZero(t, 0) 得到整个数组的结果。0 度不算零下。样例：{3,−1,0,−5} 返回 2；{} 返回 0；{−2,−2} 返回 2。

提示

思路提示：三句话。含义：t[i..n−1] 中负数的个数。最小情况：i == n，区间为空，0 天。相信 countBelowZero(t, i + 1) 已经数好了后面，当前答案是它加上 t[i] 自己的贡献：负数算 1，否则算 0。和 sumFrom 相比只改了一处，"加上 a[i]"换成"加上 t[i] < 0 ? 1 : 0"。

参考答案
int countBelowZero(const vector<int>& t, int i) {
    if (i == (int)t.size()) return 0;                      // 空区间：0 天
    return (t[i] < 0 ? 1 : 0) + countBelowZero(t, i + 1);  // 当前这天 + 后面的天数
}
def count_below_zero(t, i):
    if i == len(t):                                        # 空区间：0 天
        return 0
    return (1 if t[i] < 0 else 0) + count_below_zero(t, i + 1)   # 当前这天 + 后面的天数

练习 32.3-2【基础】把空格换成 %20

题面：网址里不能直接出现空格，要写成 %20。写 encodeSpaces(s, i) 返回 s[i..] 中每个空格替换成 "%20" 后的字符串，其他字符不变，0 ≤ |s| ≤ 500。样例："a b" 返回 "a%20b"；两个空格 " " 返回 "%20%20"；"" 返回 ""。

提示

思路提示：返回值是字符串，"拼"从加法换成字符串连接。含义：s[i..] 替换后的结果。最小情况：i == s.size()，空后缀替换后仍是空串。相信 encodeSpaces(s, i + 1) 已经替换好后面，当前答案是 s[i] 替换后的样子接在它前面：空格变成 "%20"，其他字符保持原样。s[i] 在原串里排在后缀之前，所以写成 head + 递归结果，顺序反过来就成了 reverseStr。

参考答案
string encodeSpaces(const string& s, int i) {
    if (i == (int)s.size()) return "";                     // 空后缀
    string head = (s[i] == ' ') ? "%20" : string(1, s[i]); // 当前字符替换后的样子
    return head + encodeSpaces(s, i + 1);                  // 接上后面替换好的部分
}
def encode_spaces(s, i):
    if i == len(s):                                        # 空后缀
        return ""
    head = "%20" if s[i] == " " else s[i]                  # 当前字符替换后的样子
    return head + encode_spaces(s, i + 1)                  # 接上后面替换好的部分

练习 32.3-3【变形】成绩是否一次比一次高

题面：数组 a 是一名学生按时间顺序的考试成绩（0 ≤ n ≤ 500）。写 isRising(a, i) 判断 a[i..n−1] 是否严格递增，即每一次都比上一次高。空数组和只有一个成绩都算严格递增。样例：{60,72,85} 返回 true；{60,72,72} 返回 false；{} 返回 true；{90} 返回 true。

提示

思路提示："严格递增"要比较相邻两个，所以最小情况是区间里不足 2 个元素：i >= n − 1，直接返回 true。照搬 maxFrom 写成 i == n − 1 会漏掉空数组：n=0 时 n−1 是 −1，i=0 不等于 −1，接着读 a[0] 越界。递推：a[i] >= a[i+1] 时这一步没有上升，立即返回 false；否则相信 isRising(a, i + 1) 判断后面那段。和 maxFrom 相比，最小情况多接住了空数组，并多了一个提前返回 false 的出口（与 isPal 相同）。

参考答案
bool isRising(const vector<int>& a, int i) {
    if (i >= (int)a.size() - 1) return true;               // 0 个或 1 个成绩
    if (a[i] >= a[i + 1]) return false;                    // 这一步没有上升
    return isRising(a, i + 1);                             // 相信后面那段能判断
}
def is_rising(a, i):
    if i >= len(a) - 1:                                    # 0 个或 1 个成绩
        return True
    if a[i] >= a[i + 1]:                                   # 这一步没有上升
        return False
    return is_rising(a, i + 1)                             # 相信后面那段能判断

练习 32.3-4【变形】铺满地面的最大正方形地砖

题面：一块长 a、宽 b 的矩形地面（a、b 是整数，0 ≤ a, b ≤ 10¹⁸），要用同一种边长为整数的正方形地砖恰好铺满，地砖边长最大是多少？答案就是 a 和 b 的最大公约数。写递归函数 gcdRec(a, b)，约定 gcdRec(0, 0) = 0。样例：(12, 18) 返回 6；(7, 0) 返回 7；(17, 5) 返回 1。

提示

思路提示：三句话。含义：gcdRec(a, b) 返回 a 和 b 的最大公约数。最小情况：b == 0，任何数都整除 0，所以答案是 a。相信 gcdRec(b, a % b)：a % b = a − k·b，能同时整除 a、b 的数也整除 a % b，能同时整除 b、a % b 的数也整除 a，所以两对数的公约数完全相同。和前几题相比，小一号不再是下标加 1，而是第二个参数从 b 变成 a % b；a % b 一定小于 b，所以每层都严格变小，最终落到 b == 0。a < b 时第一层只是把两数交换：gcdRec(12, 18) 的下一层是 gcdRec(18, 12)。

参考答案
long long gcdRec(long long a, long long b) {
    if (b == 0) return a;                                  // gcd(a, 0) = a
    return gcdRec(b, a % b);                               // 公约数与 (b, a%b) 完全相同
}
def gcd_rec(a, b):
    if b == 0:                                             # gcd(a, 0) = a
        return a
    return gcd_rec(b, a % b)                               # 公约数与 (b, a%b) 完全相同

练习 32.3-5【综合】递归二分：第一个不小于 x 的位置

题面：升序数组 a（可能有重复值，0 ≤ n ≤ 10⁵）。写 lowerBoundRec(a, lo, hi, x) 返回区间 [lo, hi) 中第一个满足 a[k] >= x 的下标 k；区间里没有这样的元素时返回 hi。调用 lowerBoundRec(a, 0, n, x)。样例：a={1,3,3,5} 时，x=3 返回 1，x=4 返回 3，x=9 返回 4，x=0 返回 0；a={} 时任何 x 返回 0。

提示

思路提示：第 1 句里"没有就返回 hi"这半句决定了最小情况：lo == hi 时区间为空，返回 hi。递推取 mid = lo + (hi − lo) / 2。a[mid] >= x 时，答案在 [lo, mid] 中，mid 本身也可能是答案；相信 lowerBoundRec(a, lo, mid, x)，左半没有时它按含义返回 mid，正好就是答案，所以不用再单独判断 mid。a[mid] < x 时 mid 和它左边都小于 x，相信 lowerBoundRec(a, mid + 1, hi, x)。mid < hi，两个分支的区间都至少短 1，深度约 log₂n。重复值不需要特殊处理：等于 x 的元素走"往左找"的分支，自然找到最左边那个。测试用从左往右逐个扫描的暴力版对拍。

参考答案
int lowerBoundRec(const vector<int>& a, int lo, int hi, int x) {
    if (lo == hi) return hi;                               // 空区间：没有，返回 hi
    int mid = lo + (hi - lo) / 2;
    if (a[mid] >= x) return lowerBoundRec(a, lo, mid, x);  // 答案在 [lo, mid]：左半没有时返回 mid
    return lowerBoundRec(a, mid + 1, hi, x);               // mid 及左边都小于 x
}
def lower_bound_rec(a, lo, hi, x):
    if lo == hi:                                           # 空区间：没有，返回 hi
        return hi
    mid = lo + (hi - lo) // 2
    if a[mid] >= x:                                        # 答案在 [lo, mid]：左半没有时返回 mid
        return lower_bound_rec(a, lo, mid, x)
    return lower_bound_rec(a, mid + 1, hi, x)              # mid 及左边都小于 x

相近题型：LeetCode 35、34。

易错点：

  • 第 1 句写得含糊，导致最小情况选错（例如求最大值时选了空区间却返回 0，遇到全负数数组就错）。
  • 写第 3 句时忍不住展开。展开是验证时做的事，设计时只看一层。
  • 同一个子调用写两遍（power(x,n/2) * power(x,n/2)），复杂度大幅上升。结果要复用时先存进变量。

小结： 写递归前先写清含义、最小情况、相信函数三句话，代码按这三句话翻译；设计时只考虑一层。

32.4 递归调用之前和之后：前序位置与后序位置

同样是打印 1 到 n，把一行 cout 从递归调用的上面移到下面，输出的顺序就完全反过来。理解这个现象，是理解二叉树前序、后序遍历以及回溯中“做选择、撤销选择”的关键：一段代码写在递归调用之前还是之后，决定了它在“递”的阶段执行还是在“归”的阶段执行。

在一个递归函数中，以递归调用的那一行为界：

  • 写在调用之前的代码处于前序位置：刚进入这一层、还没有向下调用时执行，执行顺序从外层到内层。
  • 写在调用之后的代码处于后序位置：下一层全部返回、回到这一层时执行，执行顺序从内层到外层。
void printDown(int n) {           // 打印 n n-1 ... 1
    if (n == 0) return;
    cout << n << " ";             // 前序位置：先打印，再进入下一层
    printDown(n - 1);
}

void printUp(int n) {             // 打印 1 2 ... n
    if (n == 0) return;
    printUp(n - 1);
    cout << n << " ";             // 后序位置：下一层全部返回后才打印
}
def print_down(n):                # 打印 n n-1 ... 1
    if n == 0:
        return
    print(n, end=" ")             # 前序位置：先打印，再进入下一层
    print_down(n - 1)

def print_up(n):                  # 打印 1 2 ... n
    if n == 0:
        return
    print_up(n - 1)
    print(n, end=" ")             # 后序位置：下一层全部返回后才打印

printDown(3) 输出 3 2 1，printUp(3) 输出 1 2 3。两段代码只差一行的位置。

用三句话分析 printUp：含义是按从小到大的顺序打印 1..n；最小情况 n == 0，什么也不打印；相信 printUp(n - 1) 已经打印好 1..n−1，接下来只需补上 n。n 是最大的数，要最后出现，所以打印 n 必须放在调用之后。

把两个位置放进同一个函数，可以同时看到两个阶段：

void printBoth(int n) {
    if (n == 0) return;
    cout << "进" << n << " ";     // 前序位置
    printBoth(n - 1);
    cout << "出" << n << " ";     // 后序位置
}
def print_both(n):
    if n == 0:
        return
    print(f"进{n}", end=" ")      # 前序位置
    print_both(n - 1)
    print(f"出{n}", end=" ")      # 后序位置

练习 32.4-4【变形】前缀和往下传，后缀和往上收

题面：数组 a（0 ≤ n ≤ 500）。写 fillPreSuf(a, i, acc, pre, suf)：acc 是 a[0..i−1] 的和；函数填好 pre[i..n−1]（pre[k] = a[0]+…+a[k]）和 suf[i..n−1]（suf[k] = a[k]+…+a[n−1]），并返回 a[i..n−1] 的和。pre、suf 在调用前已开成长度 n。调用 fillPreSuf(a, 0, 0, pre, suf)。样例：a={2,5,1} 得到 pre={2,7,8}、suf={8,6,1}，返回 8；a={} 返回 0。

提示

思路提示：pre[i] 需要 a[0..i−1] 的和，这些元素在往下走的路上已经经过，所以用参数 acc 往下传，在前序位置算 pre[i] = acc + a[i]，再把 pre[i] 作为下一层的 acc。suf[i] 需要 a[i+1..] 的和，这些元素要等下一层返回才知道，所以在后序位置用返回值算 suf[i] = a[i] + 下一层的返回值。最小情况 i == n：空后缀，返回 0。同一个函数里，参数负责把信息带下去，返回值负责把信息带上来。

参考答案
long long fillPreSuf(const vector<int>& a, int i, long long acc,
                     vector<long long>& pre, vector<long long>& suf) {
    if (i == (int)a.size()) return 0;            // 空后缀的和
    pre[i] = acc + a[i];                         // 前序：用上面传下来的 acc
    long long rest = fillPreSuf(a, i + 1, pre[i], pre, suf);
    suf[i] = a[i] + rest;                        // 后序：用下面返回的和
    return suf[i];
}
def fill_pre_suf(a, i, acc, pre, suf):

        return 0
    pre[i] = acc + a[i]                          # 前序：用上面传下来的 acc
    rest = fill_pre_suf(a, i + 1, pre[i], pre, suf)
    suf[i] = a[i] + rest                         # 后序：用下面返回的和

提示

参考答案

    if (n < 1000) return to_string(n);           // 最高段：不补零
    string low = to_string(n % 1000);
    low = string(3 - low.size(), '0') + low;     // 非最高段：补足 3 位
    return withCommas(n / 1000) + "," + low;     // 后序：高位段先拼好
}
def with_commas(n):                              # n >= 0
    if n < 1000:                                 # 最高段：不补零
        return str(n)
    low = str(n % 1000)
    low = "0" * (3 - len(low)) + low             # 非最高段：补足 3 位

易错点：

  • 以为递归调用之后的代码"不会执行"。它会执行，只是要等下一层全部结束。
  • 二进制转换时把打印放在调用之前，输出顺序反了。需要反序时，想想能否放到后序位置。

小结： 递归调用之前的代码在前序位置，从外层到内层执行；之后的代码在后序位置，从内层到外层执行；两者之间夹着下一层的全部执行。

32.5 递归树：斐波那契与记忆化

到目前为止，除汉诺塔外，每个函数每层只调用自己一次，调用过程是一条链。一层调用自己两次时，调用过程会分叉成一棵树。这棵树可能非常大，而且其中有大量重复的计算。看清这棵树，就能知道程序为什么慢、怎样让它变快。

递归树

斐波那契数列定义为 fib(0)=0，fib(1)=1，fib(n) = fib(n−1) + fib(n−2)。写成递归几乎就是照抄定义：

long long callCount = 0;

long long fib(int n) {
    ++callCount;                                  // 每进入一次函数就记一次
    if (n <= 1) return n;                         // fib(0)=0, fib(1)=1
    return fib(n - 1) + fib(n - 2);
}
call_count = 0

def fib(n):
    global call_count             # 要改模块级变量必须声明 global，否则 += 报 UnboundLocalError
    call_count += 1               # 每进入一次函数就记一次（Python 没有 ++）
    if n <= 1:                    # fib(0)=0, fib(1)=1
        return n
    return fib(n - 1) + fib(n - 2)

把每一次调用画成一个节点，它所调用的函数画成它的孩子，得到的树叫作递归树。根是最初的调用，叶子是基例。

标为红色的节点是重复的：它们的值前面已经算过一次，这里又把整棵子树重新算了一遍。在 fib(5) 的 15 次调用中，fib(3) 计算了 2 次，fib(2) 计算了 3 次，fib(1) 被调用 5 次，fib(0) 被调用 3 次。

调用次数满足 C(n) = 1 + C(n−1) + C(n−2)，C(0) = C(1) = 1，于是 C(5)=15，C(6)=25，C(30)=2,692,537。n 每增加 1，调用次数大约乘以 1.6，是指数增长。

逐行说明： ++callCount 写在函数第一行，每进入一次函数加 1，用来统计节点数；基例同时处理 n=0 和 n=1；最后一行先调用 fib(n−1)，等它的整棵子树执行完，才调用 fib(n−2)。

记忆化：把算过的结果记下来

重复计算的根源在于 fib(3) 每次的值都一样，却被重新计算。解决办法是准备一张表 memo，memo[k] 存放 fib(k) 的值，初值为 −1，表示还没有算过。进入函数时先查表，算出结果后写入表中。这种做法叫作记忆化（memoization）。

long long fibMemo(int n, vector<long long>& memo) {
    ++callCount;
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];            // 算过：直接查表
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);   // 第一次算：算完写进表
    return memo[n];
}
# 调用方式：memo = [-1] * (n + 1); fib_memo(n, memo)

Python 中可以用 functools.lru_cache 自动实现记忆化 [6]：

    if n <= 1:

    return fib(n - 1) + fib(n - 2)

要点

  1. 一层调用自己 k 次时，调用过程是一棵每个节点最多有 k 个孩子的递归树；总时间约等于节点数乘以每个节点的工作量。
  2. 递归树中出现参数完全相同的节点，说明存在重复计算，可以用记忆化（查表加写表）消除。
  3. 记忆化的前提是相同的参数一定得到相同的结果，即函数的结果只由参数决定。
  4. 记忆化递归与第 27 章的动态规划是同一种方法的两种写法：前者从大问题向下拆分，后者从小问题向上填表。

练习 32.5-2【变形】有障碍的网格路线数

题面：r×c 网格（1 ≤ r, c ≤ 16），g[i][j] 为 1 表示障碍，为 0 表示可走。机器人从左上角 (0,0) 出发，每步只能向右或向下走一格，要到达右下角 (r−1, c−1)。写 gridPaths(g, i, j, memo) 返回从 (i, j) 到右下角的路线数，memo 是 r×c、初值 −1 的二维表；起点或终点是障碍时答案为 0。样例：3×3 无障碍返回 6；3×3 只有中心 (1,1) 是障碍返回 2；{{0}} 返回 1；{{1}} 返回 0；16×16 无障碍返回 155,117,520。

提示

思路提示：参数从一个 n 变成两个坐标 (i, j)，memo 也跟着变成二维的 memo[i][j]。三句话：含义是"从 (i, j) 到右下角的路线数"；最小情况有两类，出界或障碍返回 0，已在右下角返回 1；相信向右一步的 gridPaths(g, i, j + 1, memo) 和向下一步的 gridPaths(g, i + 1, j, memo) 都已算好，两者相加。判断顺序有讲究：出界检查必须排在读 g[i][j] 和 memo[i][j] 之前；障碍检查排在终点检查之前，终点是障碍时才会返回 0。不记忆化时同一个格子会被它左边和上边的格子各问一次，16×16 的答案是 155,117,520，朴素递归至少要这么多次调用。

参考答案
long long gridPaths(const vector<vector<int>>& g, int i, int j, vector<vector<long long>>& memo) {
    int r = g.size(), c = g[0].size();
    if (i >= r || j >= c || g[i][j] == 1) return 0;          // 出界或障碍
    if (i == r - 1 && j == c - 1) return 1;                  // 到达右下角
    if (memo[i][j] != -1) return memo[i][j];                 // 算过：查表
    memo[i][j] = gridPaths(g, i, j + 1, memo) + gridPaths(g, i + 1, j, memo);   // 向右 + 向下
    return memo[i][j];
}

练习 32.5-3【综合】数字串有几种解码方式

题面：字母 A 到 Z 依次编码成 1 到 26，一串字母编码后首尾相接得到数字串 s（1 ≤ |s| ≤ 80，只含 '0' 到 '9'）。反过来把 s 切成若干段，每段必须是 1 到 26 之间的数，并且没有前导零（"06" 不合法）。写 decodeCount(s, i, memo) 返回 s[i..] 的切法数，memo 长度为 |s|、初值 −1。样例："226" 返回 3（2|2|6、22|6、2|26）；"11106" 返回 2（1|1|10|6、11|10|6）；"10" 返回 1；"06" 返回 0；"100" 返回 0；80 个 '1' 返回 37,889,062,373,143,906。

提示

思路提示：每层决定"这一段取 1 位还是 2 位"，最多两个分支。s[i] == '0' 时两个分支都不合法（任何一段都不能以 0 开头），直接返回 0。取 1 位总是合法；取 2 位要求 i+1 < n 且两位数不超过 26。最小情况 i == n：全部切完，算 1 种。记忆化的"没算过"标记必须用 −1：子问题的真实答案可以是 0，例如后缀 "30" 中 3 后面的 0 无法单独成段，30 又大于 26；用 0 当标记，这些子问题每次都会被当成没算过而重算。80 个 '1' 的答案是第 81 个斐波那契数，约 3.8×10¹⁶，必须用 long long。测试用暴力法对拍：|s|−1 个间隙每个切或不切，枚举全部 2^(|s|−1) 种切法逐个检查。

参考答案
long long decodeCount(const string& s, int i, vector<long long>& memo) {
    int n = s.size();
    if (i == n) return 1;                                    // 全部切完：1 种
    if (s[i] == '0') return 0;                               // 任何一段都不能以 0 开头
    if (memo[i] != -1) return memo[i];                       // 算过：查表
    long long r = decodeCount(s, i + 1, memo);               // 这一段取 1 位
    if (i + 1 < n && (s[i] - '0') * 10 + (s[i + 1] - '0') <= 26)
        r += decodeCount(s, i + 2, memo);                    // 这一段取 2 位
    memo[i] = r;
    return r;
}
def decode_count(s, i, memo):
    n = len(s)
    if i == n:                                               # 全部切完：1 种
        return 1
    if s[i] == "0":                                          # 任何一段都不能以 0 开头
        return 0
    if memo[i] != -1:                                        # 算过：查表
        return memo[i]
    r = decode_count(s, i + 1, memo)                         # 这一段取 1 位
    if i + 1 < n and int(s[i]) * 10 + int(s[i + 1]) <= 26:
        r += decode_count(s, i + 2, memo)                    # 这一段取 2 位
    memo[i] = r
    return r

易错点：

  • memo 按值传：每层写进的是自己的副本，返回后就丢了，速度没有任何改善。
  • 用 0 表示"没算过"，而某些子问题的真实答案恰好是 0（例如 fib(0)），会被当成没算过反复计算；挑一个答案里不可能出现的值作标记。
  • 查表写在基例之前时，要保证下标不越界（例如 ways 中 n < 0 必须先判断）。

小结： 一层调用自己多次时，调用过程是一棵树；相同的参数重复出现时用记忆化：先查表，算完写表。

32.6 多个分支的递归：每一层做一个决定

本章开头提到的题目是把 123456 的所有排列写进一个数组。它的难点在于答案有很多个，每个答案都由一串选择组成。这类要求列出所有可能情况的题目叫枚举，标准写法是：** 每一层递归做一个决定，每种选择对应一个分支。** 下面先用最简单的例子练习：生成所有长度为 n 的 01 串。掌握它之后，排列只是把每一层的选择从 {0, 1} 换成尚未使用的数字（第 33 章）。

决定树

长度为 3 的 01 串，可以看成连续做 3 个决定：第 1 位填 0 还是 1？第 2 位？第 3 位？把这个过程画出来就是一棵树：

每个节点是一次 gen01 调用时的 cur；第 k 层决定第 k 位；8 个叶子就是 8 个答案，从左到右就是输出顺序

这棵树有三个特点：

  • 第 k 层的节点表示前 k 位已经确定，节点上写的是已确定的前缀。
  • 每个节点有 2 个孩子，分别对应下一位填 0 和填 1。
  • 第 n 层的叶子恰好是全部答案，共 2³ = 8 个。

递归函数所做的，就是从根出发把这棵树走一遍，走到叶子时记录答案。

三句话

  1. 含义：gen01(n, cur, out) 中 cur 是已经确定的前缀，函数把所有以 cur 开头、长度为 n 的 01 串放进 out。
  2. 最小情况：cur 的长度已经是 n，以它开头、长度为 n 的串只有它自己，把它放进 out。
  3. 相信函数：以 cur 开头的全部串，等于以 cur+"0" 开头的全部串加上以 cur+"1" 开头的全部串。相信 gen01(n, cur + "0", out) 和 gen01(n, cur + "1", out) 各自把自己那一半放好了。

调用 gen01(n, "", out)，以空前缀开头的全部串，就是所有长度为 n 的 01 串。

void gen01(int n, string cur, vector<string>& out) {
    if ((int)cur.size() == n) {      // n 个位置都决定好了
        out.push_back(cur);
        return;
    }
    gen01(n, cur + "0", out);        // 这一位选 0，剩下的交给下一层
    gen01(n, cur + "1", out);        // 这一位选 1，剩下的交给下一层
}
def gen01(n, cur, out):
    # cur 是 str，不可变：cur + "0" 生成新对象交给下一层，本层的 cur 不变，效果同 C++ 按值传
    # out 是列表：所有层共享同一个对象，append 会改到调用者手里的 out，效果同 C++ 的 &
    if len(cur) == n:                # n 个位置都决定好了
        out.append(cur)
        return
    gen01(n, cur + "0", out)         # 这一位选 0，剩下的交给下一层
    gen01(n, cur + "1", out)         # 这一位选 1，剩下的交给下一层

从零写出 gen01 的四个步骤

没有答案可以参考时，可以按下面四个固定的步骤写出 gen01。

第 1 步：写函数签名和含义注释。 先想清楚每一层需要知道什么：目标长度 n、已经确定的前缀 cur，以及存放答案的 out。于是写下 void gen01(int n, string cur, vector<string>& out)，并在上面写一行注释“把所有以 cur 开头、长度为 n 的 01 串放进 out”。这行注释就是第 1 句。

第 2 步：写基例。 前缀长度达到 n 时，不需要再做决定，答案就是 cur 本身，放进 out 后 return。

第 3 步：写分支。 长度还没有达到 n 时，这一层要决定下一位。下一位有两种可能，每种可能交给一次递归调用，前缀分别加上 "0" 和 "1"。写这一步时只考虑第 1 句：gen01(n, cur + "0", out) 的含义就是把以 cur+"0" 开头的全部串放好，直接相信它。

第 4 步：用最小的输入验证。 n=0 时，cur="" 的长度已经是 0，记录空串，out 中有 1 个元素，这是正确的，因为长度为 0 的 01 串只有空串。n=1 时，根层调用 "0" 和 "1"，两者都立即被记录，out = [0, 1]，正确。再用 n=2 运行一遍（见上面的逐步图），确认顺序。

这四个步骤适用于任何枚举题：参数中记录已经做了哪些决定，基例是所有决定都已做完，分支是这一步有哪些选择。

什么时候使用这种写法

题目中出现下面这些情况时，可以考虑每层做一个决定的递归：

  • 要求输出所有方案、列出全部情况、返回所有可能的结果；
  • 答案是由若干步选择组成的序列或集合，例如每一位填什么、每个元素选不选、下一个位置放哪个数；
  • n 很小（例如 n ≤ 10 或 n ≤ 20），因为答案的个数本身就是指数级的。

题目条件变化时，只需修改这一写法中的某一处：

题目条件改骨架的哪一处本书位置
每位可选的字符变成 a、b、c分支：两行调用改成 for 循环本节练一练题 1
相邻两位不能都是 1分支：选 1 之前加条件（剪枝）本节练一练题 2
恰好有 k 个 1参数：多带一个计数；基例：多一个条件32.7 练一练
每个数只能用一次，求所有排列分支：遍历还没用过的数，需要 used 数组第 33 章
每个元素选或不选，求所有子集层：第 k 层决定第 k 个元素选不选第 33 章、第 27 章

要点：枚举的通用骨架

  1. 每一层递归做一个决定，参数中带着已经做了哪些决定（cur）。
  2. 有几种选择就有几个分支，写成几次递归调用或一个 for 循环。
  3. 决定全部做完（到达叶子）时，记录答案并 return。
  4. 答案总数等于叶子数，也等于每层选择数的乘积；每层 k 种选择、共 n 层时，有 kⁿ 个叶子。
  5. 推广到排列时，每层的选择改为尚未使用的数，需要一个 used 数组记录哪些数已经用过，第 33 章将详细讲解。

void genABC(int n, string cur, vector<string>& out) {

    const string letters = "abc";

def gen_abc(n, cur, out):

        out.append(cur)
        return

    if ((int)path.size() == n) {
        out.push_back(path);
        return;

    for (int bit = 0; bit <= 1; ++bit) {
        path.push_back(bit);         // 做选择

def gen01_path(n, path, out):
    # path、out 都是列表，全场各只有一个对象（相当于 C++ 的 &），所以 path 必须撤销
    if len(path) == n:
        out.append(path[:])          # 复制！C++ 的 push_back 会复制，Python 的 append(path) 存的是同一个列表
        return
    for bit in range(2):             # bit = 0, 1
        path.append(bit)             # 做选择
        gen01_path(n, path, out)     # 进入下一层
        path.pop()                   # 撤销选择

要点

  1. 需要所有层共享的数据（结果 out、记忆表 memo、used 数组）按引用传递。
  2. 每一层的当前状态（前缀 path 或 cur）可以按值传递（不需要撤销），也可以按引用传递（必须撤销）。
  3. 按引用传递时，做选择与撤销成对出现，撤销紧跟在递归调用的下一行；函数返回时，状态与进入时相同。
  4. out.push_back(path) 存入的是副本，之后修改 path 不会影响已经记录的答案。

题面：恰好 k 个 1。 生成所有长度为 n、恰好含 k 个 1 的 01 序列，结果放进 vector<vector<int>>，按字典序。n=4、k=2 时有 6 个：0011、0101、0110、1001、1010、1100。

void genK(int n, int k, int ones, vector<int>& path, vector<vector<int>>& out) {
    if ((int)path.size() == n) {
        if (ones == k) out.push_back(path);       // 1 的个数正好是 k 才收
        return;
    }
    path.push_back(0);
    genK(n, k, ones, path, out);
    path.pop_back();
    if (ones < k) {                               // 1 已经够了就不再放 1
        path.push_back(1);
        genK(n, k, ones + 1, path, out);
        path.pop_back();
    }
}
def gen_k(n, k, ones, path, out):
    # ones 是 int（不可变），ones + 1 是新对象，本层的 ones 不变，无须撤销；path 共享，要撤销
    if len(path) == n:
        if ones == k:                             # 1 的个数正好是 k 才收
            out.append(path[:])
        return
    path.append(0)
    gen_k(n, k, ones, path, out)
    path.pop()
    if ones < k:                                  # 1 已经够了就不再放 1
        path.append(1)
        gen_k(n, k, ones + 1, path, out)
        path.pop()

与例题的区别：多了一个按值传递的计数参数，记录答案时多了一个条件，选 1 之前多了一个剪枝条件。答案个数是组合数 C(n, k)，例如 C(4,2)=6、C(10,3)=120；全部结束后 path 为空。

提示

思路提示：两个状态，传法不同。path 按引用传：选了卡 i 就 push_back(i)，递归返回后 pop_back()。remain 是 int，按值传 remain − a[i] 给下一层，本层的 remain 没被改过，不用撤销。"不用"这个分支没有改 path，也不用撤销。剪枝：面额都是正数，a[i] > remain 时用了一定超，"用"的分支直接跳过。最小情况 i == n：remain == 0 才收下。和本节 genK 相比，计数参数从"已有几个 1"换成"还差多少钱"。

void pickCards(const vector<int>& a, int i, int remain, vector<int>& path, vector<vector<int>>& out) {

        if (remain == 0) out.push_back(path);    // 正好凑够
        return;

    pickCards(a, i + 1, remain, path, out);      // 不用卡 i：path 没动，无须撤销

    }
}

提示

思路提示：全局写法要做对两件事。第一，每组数据开始前清空 gLockAns，否则第二次调用会带着第一组的答案；gLockCur 在撤销写对时返回后本来就是空的，开头再清一次，可以防止上一组异常中断留下字符。第二，gLockCur 全场只有一份，做选择后要撤销。相邻不同用剪枝实现：放 d 之前看 gLockCur.back()，相同就 continue。答案个数是 m·(m−1)ⁿ⁻¹，m=1、n ≥ 2 时为 0。

        return;

}

练习 32.7-5【综合】网格里不重复经过的路线

题面：r×c 网格（1 ≤ r·c ≤ 12），'#' 是墙，'.' 可走。从左上角走到右下角，每步向上下左右走一格，同一格最多经过一次，到达右下角就结束。有多少条不同路线？写 countSimplePaths(g)，内部用递归 walkGrid(g, i, j, seen) 返回"当前在 (i, j)、seen 中已标记的格子不能再走"时到达终点的路线数。起点或终点是墙返回 0。样例：{"..",".."} 返回 2；{"..","#."} 返回 1；{"...","...","..."} 返回 12；{"."} 返回 1；{"#."} 返回 0。

提示

思路提示：可以往回、往上走，所以不能像 32.5 那样按坐标记忆化：从 (i, j) 出发有几条路线，取决于哪些格子已经被这条路线占用，只看坐标不够。seen 按引用传，记录当前这条路线占用的格子：走进邻格前设 true（做选择），递归返回后改回 false（撤销）。漏写撤销的后果是一条路线走过的格子对后面所有兄弟分支都关闭，结果偏小。最小情况：(i, j) 是终点，算 1 条，不再往外走。起点在进入递归前先标记。测试另写一个不用递归的计数方法：按"已走过的格子集合 + 当前所在格"逐步累加路线数，在随机小网格上对拍。

参考答案
long long walkGrid(const vector<string>& g, int i, int j, vector<vector<bool>>& seen) {
    int r = g.size(), c = g[0].size();
    if (i == r - 1 && j == c - 1) return 1;                  // 到终点：一条路线
    const int di[4] = {-1, 1, 0, 0}, dj[4] = {0, 0, -1, 1};
    long long total = 0;
    for (int d = 0; d < 4; ++d) {
        int x = i + di[d], y = j + dj[d];
        if (x < 0 || x >= r || y < 0 || y >= c || g[x][y] == '#' || seen[x][y]) continue;
        seen[x][y] = true;                                   // 做选择：占用 (x, y)
        total += walkGrid(g, x, y, seen);
        seen[x][y] = false;                                  // 撤销
    }
    return total;
}

long long countSimplePaths(const vector<string>& g) {
    int r = g.size(), c = g[0].size();
    if (g[0][0] == '#' || g[r - 1][c - 1] == '#') return 0;  // 起点或终点是墙
    vector<vector<bool>> seen(r, vector<bool>(c, false));
    seen[0][0] = true;                                       // 起点先占用
    return walkGrid(g, 0, 0, seen);
}
def walk_grid(g, i, j, seen):
    r, c = len(g), len(g[0])
    if i == r - 1 and j == c - 1:                            # 到终点：一条路线
        return 1
    total = 0
    for di, dj in ((-1, 0), (1, 0), (0, -1), (0, 1)):
        x, y = i + di, j + dj
        if x < 0 or x >= r or y < 0 or y >= c or g[x][y] == "#" or seen[x][y]:
            continue
        seen[x][y] = True                                    # 做选择：占用 (x, y)
        total += walk_grid(g, x, y, seen)
        seen[x][y] = False                                   # 撤销
    return total

def count_simple_paths(g):
    r, c = len(g), len(g[0])
    if g[0][0] == "#" or g[r - 1][c - 1] == "#":             # 起点或终点是墙
        return 0
    seen = [[False] * c for _ in range(r)]
    seen[0][0] = True                                        # 起点先占用
    return walk_grid(g, 0, 0, seen)

易错点：

  • 撤销写在 for 循环外面，或干脆漏写：兄弟分支带着上一个选择出发，答案重复、缺失，甚至停不下来。
  • 存答案的容器按值传，结果全部丢失。
  • Python 里 out.append(path) 没有复制，最后 out 里全是同一个（已经被清空的）列表。

小结： 多层共享的数据按引用传递；按值传递的状态不需要撤销，按引用传递的状态由 push 的那一层负责 pop；记录答案时存一份副本。

32.8 递归与循环互换、栈溢出与递归深度

面试中常被问到：这个递归能改成循环吗？数据量很大时会不会出问题？理解了调用栈，这两个问题都有明确的答案：递归能做到的，用循环加上一个自己管理的栈都能做到；递归的深度受调用栈大小的限制，深度太大会栈溢出。

只调用一次自己的递归，可以直接写成循环

countdown、sumFrom、fact 每层只调用一次自己，调用过程是一条链。这种递归可以直接改写成循环，用循环变量表示当前处在哪一层：

void countdownLoop(int n) {
    while (n != 0) {
        cout << n << "\n";
        n = n - 1;                   // 相当于"进入 countdown(n-1)"
    }
    cout << "发射!\n";
}

long long factLoop(int n) {
    long long r = 1;
    for (int k = 1; k <= n; ++k) r *= k;
    return r;
}
def countdown_loop(n):
    while n != 0:
        print(n)
        n = n - 1                    # 相当于"进入 countdown(n-1)"；循环不受递归深度上限限制
    print("发射!")

def fact_loop(n):
    r = 1
    for k in range(1, n + 1):        # k = 1..n
        r *= k
    return r

对照两种写法：递归的基例变成了循环的结束条件；进入下一层变成了更新循环变量；fact 在“归”的阶段做的乘法，在循环中按 1, 2, …, n 的顺序完成。快速幂也有循环版本（见练一练）。

多个分支的递归：使用显式栈

gen01 每层调用两次，调用过程是一棵树，一个循环变量无法记住还有哪些分支没有走。这时用一个 std::stack [8] 存放尚未处理的前缀，代替调用栈：

vector<string> gen01Stack(int n) {
    vector<string> out;
    stack<string> st;
    st.push("");
    while (!st.empty()) {
        string cur = st.top();
        st.pop();
        if ((int)cur.size() == n) {
            out.push_back(cur);
            continue;
        }
        st.push(cur + "1");          // 先压 1，后压 0：0 在栈顶，先被处理
        st.push(cur + "0");
    }
    return out;
}
def gen01_stack(n):
    out = []
    st = []                          # 用 list 当栈：append 压栈，pop() 弹出栈顶
    st.append("")
    while st:
        cur = st.pop()               # 相当于 C++ 的 top() + pop()
        if len(cur) == n:
            out.append(cur)
            continue
        st.append(cur + "1")         # 先压 1，后压 0：0 在栈顶，先被处理
        st.append(cur + "0")
    return out

栈溢出与递归深度

递归深度是调用栈里同时存在的最大帧数，等于递归树的高度：sumFrom 处理 n 个元素时深度是 n+1（例如 10000 个元素时最大深度为 10001），power 是 log₂n 级别，gen01 是 n+1。

每个线程的调用栈都有大小上限。在 Linux 上，这个上限由资源限制 RLIMIT_STACK 决定，可以用命令 ulimit -s 查看（单位 KB）[9]；不同的系统、编译和运行环境，默认值不同。每一帧占用的字节数取决于函数的参数和局部变量。所以递归多少层会溢出没有固定的答案，它由栈的大小除以每帧的大小决定。

递归深度 = 栈里同时存在的帧数；vector 的元素放在堆上，帧里只有很小的管理信息

由此可以得到两个实用的结论：

  • vector 的元素存放在堆上，帧中只有很小的管理信息；如果在递归函数中定义一个很大的局部数组（如 int buf[100000];），每一帧都会占用大量栈空间，递归不深就可能溢出。
  • Python 在解释器层面对递归深度另有一个上限，超过时抛出 RecursionError，可以用 sys.getrecursionlimit() 查看、用 sys.setrecursionlimit() 调整 [10]。

什么时候用递归

情况建议原因
问题本身是递归定义的：树、分治、枚举所有选择用递归代码直接对应三句话，最容易写对
深度是 log n 级别（快速幂、二分、平衡树）放心用递归深度很小
枚举题，n 很小（例如 n ≤ 20）用递归深度只有 n+1，耗时主要在答案个数上
只调用一次自己，深度与 n 同阶，n 可能达到百万级改成循环循环没有深度限制，也省去调用开销
图上 DFS，图可能是一条很长的链考虑显式栈深度可能等于点数

要点

  1. 每层只调用一次自己的递归，可以直接改成循环；多个分支的递归可以用显式栈改写。
  2. 递归深度等于调用栈中同时存在的帧数，也等于递归树的高度。
  3. 能递归多少层由栈的大小和每帧的大小共同决定；深度可能很大时，改用循环或显式栈。
  4. 递归的缺点：有函数调用的开销；深度大时可能栈溢出；朴素写法可能有大量重复计算（可用记忆化解决）。

题面：快速幂改为循环。 把 32.3 的 power(x, n) 改写成循环版本 powerLoop，要求循环次数约为 log₂n，并与递归版本比较（x 取 −3..3，n 取 0..20，结果应全部相同）。

提示：把 n 写成二进制。例如 13 = 1101₂，所以 x¹³ = x⁸ · x⁴ · x¹。循环中让 x 依次变成 x、x²、x⁴、x⁸……；n 当前的最低位是 1 时，就把当前的 x 乘进答案；然后 n 除以 2，去掉最低位。

long long powerLoop(long long x, int n) {
    long long result = 1;
    while (n > 0) {
        if (n % 2 == 1) result *= x;   // 当前最低位是 1：把这一份乘进答案
        x = x * x;                     // x, x², x⁴, x⁸ …
        n /= 2;                        // 去掉最低位
    }
    return result;
}
def power_loop(x, n):
    result = 1
    while n > 0:
        if n % 2 == 1:               # 当前最低位是 1：把这一份乘进答案
            result *= x
        x = x * x                    # x, x², x⁴, x⁸ …
        n //= 2                      # 去掉最低位（n > 0 时 //= 与 C++ 的 /= 相同）
    return result

与例题的区别：递归版本从高位向低位组合结果（在“归”的阶段平方），循环版本从低位向高位扫描。两者每一步都把 n 减半，所以都是 O(log n)。

练习 32.8-1【基础】辗转相除改成循环

题面：把 32.3 更多练习中的 gcdRec 改写成不用递归的 gcdLoop(a, b)，0 ≤ a, b ≤ 10¹⁸。样例：(12, 18) 返回 6；(7, 0) 返回 7；(0, 0) 返回 0。测试中与 gcdRec 在随机输入上对拍。

提示

思路提示：gcdRec 每层只调用一次自己，调用过程是一条链，可以直接改成循环。对应关系：基例 b == 0 变成循环的结束条件；"进入 gcdRec(b, a % b)"变成把 (a, b) 同时更新为 (b, a % b)。同时更新要先把 a % b 存进临时变量 t，再令 a = b、b = t；先写 a = b 的话，a % b 就算错了。

参考答案
long long gcdLoop(long long a, long long b) {
    while (b != 0) {                             // 基例 b == 0 变成循环结束条件
        long long t = a % b;                     // 相当于进入 gcdRec(b, a % b)
        a = b;
        b = t;
    }
    return a;
}
def gcd_loop(a, b):
    while b != 0:                                # 基例 b == 0 变成循环结束条件
        t = a % b                                # 相当于进入 gcd_rec(b, a % b)
        a = b
        b = t
    return a

练习 32.8-2【变形】genABC 改用显式栈

题面：用 std::stack 改写 32.6 练一练的 genABC：genABCStack(n) 返回所有长度为 n、只含 a、b、c 的串，顺序必须和递归版相同（字典序），0 ≤ n ≤ 8。样例：n=2 返回 aa、ab、ac、ba、bb、bc、ca、cb、cc；n=0 返回 {""}；n=8 共 6561 个，且与递归版逐个相同。

提示

思路提示：和 gen01Stack 相同，栈里放"还没处理的前缀"，弹出一个前缀相当于进入一层。分支从 2 个变成 3 个：栈是后进先出，要让 'a' 分支最先处理，它就必须最后压栈，所以按 c、b、a 的顺序压，写成从 'c' 递减到 'a' 的循环。n=0 时最初压入的空串长度已经是 0，第一次弹出就被收下。

参考答案
vector<string> genABCStack(int n) {
    vector<string> out;
    stack<string> st;
    st.push("");
    while (!st.empty()) {
        string cur = st.top();
        st.pop();
        if ((int)cur.size() == n) {
            out.push_back(cur);
            continue;
        }
        for (char c = 'c'; c >= 'a'; --c) st.push(cur + c);   // 后压的先处理：a 最后压
    }
    return out;
}
def gen_abc_stack(n):
    out = []
    st = [""]                                    # list 当栈，末尾是栈顶
    while st:
        cur = st.pop()
        if len(cur) == n:
            out.append(cur)
            continue
        for c in "cba":                          # 后压的先处理：a 最后压
            st.append(cur + c)
    return out

练习 32.8-3【综合】解码计数改成循环

题面：32.5 更多练习的 decodeCount 递归深度等于 |s|。现在 |s| 最大到 10⁵，递归版有栈溢出的风险，Python 默认 1000 层的上限也一定会超。写不用递归的 decodeCountLoop(s)，规则不变，答案对 1,000,000,007 取模。样例："226" 返回 3；"11106" 返回 2；"06" 返回 0；"0" 返回 0。

提示

思路提示：memo[i] 只依赖 memo[i+1] 和 memo[i+2]，所以从右往左填表 dp：dp[n] = 1 对应基例 i == n；i 从 n−1 降到 0，按递归版的两条规则算 dp[i]。递归版的"查表或递归"在这里变成直接读 dp[i+1]、dp[i+2]，从右往左的顺序保证它们已经算好。i+1 < n 的判断要保留：i = n−1 时只剩一个数字，取两位会越界。每次加法后取模。测试用 32.5 的 decodeCount 在长度不超过 60 的随机串上对拍（取模后比较），再在长度 10⁵ 的串上运行，确认不会栈溢出。

参考答案
long long decodeCountLoop(const string& s) {
    const long long MOD = 1000000007;
    int n = s.size();
    vector<long long> dp(n + 1, 0);
    dp[n] = 1;                                               // 对应基例 i == n
    for (int i = n - 1; i >= 0; --i) {                       // 从右往左：dp[i+1]、dp[i+2] 已算好
        if (s[i] == '0') { dp[i] = 0; continue; }            // 0 开头：0 种
        dp[i] = dp[i + 1];                                   // 这一段取 1 位
        if (i + 1 < n && (s[i] - '0') * 10 + (s[i + 1] - '0') <= 26)
            dp[i] = (dp[i] + dp[i + 2]) % MOD;               // 这一段取 2 位
    }
    return dp[0];
}
def decode_count_loop(s):
    MOD = 1000000007
    n = len(s)
    dp = [0] * (n + 1)
    dp[n] = 1                                                # 对应基例 i == n
    for i in range(n - 1, -1, -1):                           # 从右往左：dp[i+1]、dp[i+2] 已算好
        if s[i] == "0":                                      # 0 开头：0 种
            dp[i] = 0
            continue
        dp[i] = dp[i + 1]                                    # 这一段取 1 位
        if i + 1 < n and int(s[i]) * 10 + int(s[i + 1]) <= 26:
            dp[i] = (dp[i] + dp[i + 2]) % MOD                # 这一段取 2 位
    return dp[0]

易错点：

  • 改成显式栈时压栈顺序写反，结果顺序变成 11、10、01、00。想先处理的分支要后压。
