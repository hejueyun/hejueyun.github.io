17.1 查找的基本概念与平均查找长度

查找就是"给一个关键字，在一堆记录里找到它，或者确认它不存在"。银行系统按账号查客户、按交易号查流水，做的都是这件事。不同查找方法的快慢，要用一个统一的尺子来比，这把尺子就是平均查找长度。

几个术语：

  • 查找表：被查找的记录集合。只做查询的叫静态查找表；查找时还要插入、删除的叫动态查找表（BST、B 树、散列表属于这一类）。
  • 关键字：用来识别记录的数据项，例如账号。能唯一确定一条记录的叫主关键字。
  • 平均查找长度 ASL（Average Search Length）：查找过程中关键字的平均比较次数。

ASL = Σ Pᵢ × Cᵢ（i 从 1 到 n）

其中 Pᵢ 是查第 i 个记录的概率，Cᵢ 是找到它需要比较的次数。没有特别说明时，考试默认等概率：Pᵢ = 1/n。

ASL 分两种：查找成功的 ASL（目标在表里）和查找失败的 ASL（目标不在表里，要比较到能确定"没有"为止）。题目只说"ASL"时一般指成功的情况。

示例： 4 个关键字 A、B、C、D 依次存放，顺序查找时找到它们分别要比较 1、2、3、4 次。

ASL = 0.4+0.6+0.6+0.4 = 2.0：把常查的放在前面，平均比较次数就小

  • 若查找概率是 0.4、0.3、0.2、0.1：ASL = 0.4×1 + 0.3×2 + 0.2×3 + 0.1×4 = 2.0。
  • 若概率倒过来是 0.1、0.2、0.3、0.4：ASL = 0.1 + 0.4 + 0.9 + 1.6 = 3.0。
  • 若等概率：ASL = (1+2+3+4)/4 = 2.5。

同一张表、同一种方法，概率分布不同 ASL 就不同。所以顺序查找时，把查得多的记录放在前面能降低 ASL。

要点：

  1. ASL 是"比较次数的期望"，公式 Σ Pᵢ·Cᵢ，默认等概率。
  2. 题目给出"成功"与"失败"时，分别计算，分母分别是成功情况数 n 和失败情况数。
  3. ASL 衡量的是比较次数，不是秒数；它是选择查找方法的主要依据。

17.2 顺序查找：从头比到尾

顺序查找适用于任何线性表，不要求有序，链表也能用。数据量小、或者数据没排序又只查一两次时，它是最省事的选择。

从表的一端开始，逐个把记录的关键字与目标比较，相等就成功；比完全部仍没找到就失败。

教材常用一个小技巧叫哨兵：把数据放在 a[1..n]，查找前把目标放进 a[0]，然后从 a[n] 往前比。因为 a[0] 一定等于目标，循环必然停下，于是每一轮省掉了"下标是否越界"的判断。停在 0 就表示失败。

a[0] 放入待查关键字作"哨兵"。查 3 停在 i=3，成功；查 7 时一路比到 a[0] 才停，返回 0 表示失败

示例： 表 a[1..4] = 5 8 3 9，查 3：从 i=4 开始，9≠3，i=3，3=3，停下，返回 3，比较 2 次。查 7：9、3、8、5 都不等，最后与 a[0]=7 相等，返回 0，共比较 5 次（含哨兵那一次）。

代码（变量表：a 是数组，a[0] 预留给哨兵；i 是当前比较的下标；返回值 0 表示失败）：

int seqSearch(vector<int>& a, int key) {
    a[0] = key;                       // 哨兵：保证循环一定停下
    int i = (int)a.size() - 1;
    while (a[i] != key) --i;          // 从后往前比，不必每次检查 i>=1
    return i;
}
# a 是列表，a[0] = key 会改到调用者那一份（相当于 vector<int>&）
def seq_search(a, key):
    a[0] = key                        # 哨兵：保证循环一定停下
    i = len(a) - 1
    while a[i] != key: i -= 1         # 从后往前比，不必每次检查 i>=1
    return i

算 ASL： 从后往前比时，第 i 个位置的记录需要比较 n−i+1 次，等概率下

ASL成功 = [n + (n−1) + … + 1] / n = (n+1)/2

失败时每次都比较到哨兵，共 n+1 次，所以 ASL失败 = n+1。

有序表的顺序查找可以提前结束失败：从前往后比，一旦遇到比目标大的元素就能确定"不存在"。n 个元素把数轴分成 n+1 个失败区间，落在第 i 个区间（i=1..n）要比较 i 次，落在最后一个区间要比较 n 次，于是

ASL失败 = (1+2+…+n+n) / (n+1) = n/2 + n/(n+1)

n=10 时约 5.91，比无序表的 11 少了将近一半；成功 ASL 仍是 (n+1)/2。

要点：

  1. 顺序查找：成功 ASL = (n+1)/2，时间 O(n)；无序表失败 ASL = n+1（带哨兵）。
  2. 有序表顺序查找只能缩短失败的查找，成功 ASL 不变。
  3. 对存储结构和有序性都没有要求，顺序表、链表都可以。

单选 · 理解检查 2　10 个元素的无序表用带哨兵的顺序查找，等概率下查找成功和查找失败的 ASL 分别是？

A. 5.5 和 11

B. 5 和 10

C. 5.5 和 5.91

D. log₂10 和 11

查看答案与每个选项的解析

A · 正确：成功 (n+1)/2 = 5.5；失败要与 10 个元素和哨兵都比一次，共 11 次。

B · 错误：成功平均是 (1+…+10)/10 = 5.5；失败还要算上与哨兵的那一次比较。

C · 错误：5.91 是有序表顺序查找的失败 ASL，本题是无序表。

D · 错误：log 级别属于折半查找，顺序查找是线性的。

易错点：

  • 带哨兵时失败比较 n+1 次；不带哨兵的写法通常记作 n 次，看题目约定。

小结： 顺序查找成功的 ASL 为 (n+1)/2，失败为 n+1；表有序只能让查找失败时提前停止。

17.3 折半查找：每次排除一半

顺序查找在 100 万条记录里平均要比 50 万次。如果表有序，并且能随机访问（数组），就可以先看中间那个：比它小就只在左半边找，比它大就只在右半边找。每比较一次，范围缩小一半，100 万条最多比较 20 次。

维护一个"目标可能在其中"的区间 [lo, hi]。每轮取中点 mid=⌊(lo+hi)/2⌋：

  • a[mid] 等于目标：成功；
  • a[mid] 小于目标：目标只可能在右边，lo = mid+1；
  • a[mid] 大于目标：目标只可能在左边，hi = mid−1；
  • lo > hi：区间空了，失败。

示例： 在 [2,4,6,8,10,12,14,16] 中查 11。

代码（变量表：lo、hi 是还没排除的闭区间两端；mid 是本轮比较的位置）：

int binarySearch(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size() - 1;      // 未排除区间 [lo, hi]
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;        // 防止 lo+hi 溢出
        if (a[mid] == x) return mid;
        if (a[mid] < x) lo = mid + 1;        // 目标只可能在右半
        else hi = mid - 1;                   // 目标只可能在左半
    }
    return -1;
}
def binary_search(a, x):
    lo, hi = 0, len(a) - 1                   # 未排除区间 [lo, hi]
    while lo <= hi:
        mid = lo + (hi - lo) // 2            # Python 整数不溢出，写 (lo + hi) // 2 也行；/ 是浮点除，要用 //
        if a[mid] == x: return mid
        if a[mid] < x: lo = mid + 1          # 目标只可能在右半
        else: hi = mid - 1                   # 目标只可能在左半
    return -1

mid = lo + (hi - lo) / 2 与 (lo + hi) / 2 数学上相同，前者在 C++/Java 里避免了 lo+hi 超出 int 范围（Python 整数没有这个问题）。写完至少测四种输入：空数组、目标是首元素、目标是末元素、目标不存在。

重复值与边界： 在 [2,4,4,7] 里查 4，普通二分可能停在任意一个 4。要找"第一个 ≥x 的位置"用 lower_bound，"第一个 >x 的位置"用 upper_bound，两者相减就是 x 的个数。C++ 的 std::lower_bound/upper_bound、Python 的 bisect_left/bisect_right 就是这两个函数；Python 的 insort 定位是 O(log n)，但插入要移动元素，整体仍是 O(n)。这部分的刷题写法见 8.4 节。

要点：

  1. 折半查找要求：有序 + 顺序存储（能 O(1) 取中点）。链表不适用。
  2. 时间复杂度 O(log n)。
  3. 闭区间写法：while (lo <= hi)，lo = mid + 1、hi = mid − 1。

单选 · 理解检查 3　a=[1,3,3,3,8]（下标从 0 起），lower_bound(3) 和 upper_bound(3) 分别是什么？

A. 1 和 4

B. 1 和 3

C. 2 和 4

D. 必须先去重才能求

查看答案与每个选项的解析

A · 正确：第一个 ≥3 的位置是 1，第一个 >3 的位置是 4；4−1=3 个 3。

B · 错误：3 是最后一个 3 的位置，不是第一个严格大于 3 的位置。

C · 错误：普通二分第一次 mid=2 会命中，但 lower_bound 要的是第一个 3。

D · 错误：边界二分本来就是为重复值设计的。

易错点：

  • 半开区间 [lo, hi) 的写法初值 hi=n、条件 lo<hi、收缩 hi=mid，与闭区间写法混用就会死循环或漏解。
  • lower_bound 返回 n 表示"没有满足条件的元素"，此时不能读 a[n]。

小结： 只有有序并且顺序存储的表才能折半查找；采用闭区间写法时循环条件是 lo≤hi，更新为 mid±1；查找边界时使用 lower_bound 或 upper_bound。

17.4 折半查找判定树：算 ASL 与最多比较次数

考试问"折半查找成功的 ASL""最多比较几次""查某个数要比较哪几个元素"，都靠一张图回答：判定树。

把折半查找的过程画成二叉树。第一次比较的元素 mid 作根；如果目标更小就走向左子树（左半区间的中点），更大就走向右子树。每个结点代表"和这个元素比较一次"。

  • 结点在第 k 层，找到它就要比较 k 次（根在第 1 层）。
  • 把每个空指针补成一个方块，叫失败结点。n 个关键字一共有 n+1 个失败结点，对应 n+1 个"落空"的区间。走到失败结点所比较的次数 = 它的父结点所在层数。

11 个关键字 7 14 18 21 23 29 31 35 38 42 46，按 mid=⌊(low+high)/2⌋ 构造（下标从 1 起，方括号里是位置）。

补上失败结点后：

圆圈是 11 个关键字（成功结点），方块 × 是 12 个失败结点；查 23 走 29→18→21→23，比较 4 次

示例：

  • 查 23：low=1, high=11, mid=6（29），23<29；high=5, mid=3（18），23>18；low=4, mid=4（21），23>21；low=5, mid=5（23），命中。比较 29、18、21、23，共 4 次，正好是 23 所在的第 4 层。
  • 查 30：mid=6（29），30>29；low=7, mid=9（38），30<38；high=8, mid=7（31），30<31；high=6 < low=7，失败。比较 3 次，失败结点挂在第 3 层的 31 下面。

判定树的性质：

  1. 判定树是一棵平衡二叉树，任意结点左右子树结点数相差不超过 1。
  2. n 个结点的判定树高度为 h = ⌊log₂n⌋ + 1（与 n 个结点的完全二叉树相同）。所以查找成功最多比较 ⌊log₂n⌋+1 次；失败时最多也比较 ⌊log₂n⌋+1 次。
  3. 当 n = 2ʰ − 1 时判定树是满二叉树，例如 n=7：

ASL成功 = (1×1+2×2+3×4)/7 = 17/7 ≈ 2.43；8 个失败结点都挂在第 3 层，ASL失败 = 3。n 较大时 ASL ≈ log₂(n+1) − 1。

n 每翻一倍：顺序查找的 ASL 也翻倍，折半只多 1 左右（n=128 时三者分别为 64.5、「计算机系统导论」1.3、6.07）

代码： 递归地"走"一遍判定树，就能算出任何 n 的两种 ASL 和树高（变量表：depth 是当前结点层数；succSum 累加成功比较次数；failSum 累加失败比较次数；height 记录最大层数）。

void walkTree(int low, int high, int depth, long long& succSum, long long& failSum, int& height) {
    if (low > high) {                        // 失败结点：比较次数 = 父结点层数 = depth-1
        failSum += depth - 1;
        return;
    }
    int mid = (low + high) / 2;
    succSum += depth;                        // 成功找到 mid 要比较 depth 次
    height = max(height, depth);
    walkTree(low, mid - 1, depth + 1, succSum, failSum, height);
    walkTree(mid + 1, high, depth + 1, succSum, failSum, height);
}

ASL binaryASL(int n) {
    long long s = 0, f = 0;
    int h = 0;
    walkTree(1, n, 1, s, f, h);
    return {double(s) / n, double(f) / (n + 1), h};
}
# Python 的 int 不可变，没有 long long& 这样的引用参数：三个累加量放进一个列表 acc 里传下去
# acc = [succ_sum, fail_sum, height]；递归深度只有树高 ⌊log₂n⌋+1，不会碰到递归上限
def walk_tree(low, high, depth, acc):
    if low > high:                           # 失败结点：比较次数 = 父结点层数 = depth-1
        acc[1] += depth - 1
        return
    mid = (low + high) // 2
    acc[0] += depth                          # 成功找到 mid 要比较 depth 次
    acc[2] = max(acc[2], depth)
    walk_tree(low, mid - 1, depth + 1, acc)
    walk_tree(mid + 1, high, depth + 1, acc)

# 返回元组 (成功 ASL, 失败 ASL, 树高)，代替 C++ 的 struct ASL；/ 直接得到浮点数，不用 double() 转换
def binary_asl(n):
    acc = [0, 0, 0]
    walk_tree(1, n, 1, acc)
    return (acc[0] / n, acc[1] / (n + 1), acc[2])

binaryASL(11) 返回 {3, 3.667, 4}，binaryASL(7) 返回 {2.43, 3, 3}；n=1..3000 时，判定树的高度都等于 ⌊log₂n⌋+1。

要点：

  1. 判定树中第 k 层结点比较 k 次；失败比较次数 = 失败结点父结点的层数。
  2. 最多比较次数 = 树高 = ⌊log₂n⌋+1（也可写作 ⌈log₂(n+1)⌉）。
  3. 成功 ASL 按层累加：Σ(层号 × 该层结点数) / n。

17.5 分块查找：索引表 + 块内顺序查找

折半查找快，但要求整张表有序，插入一条记录可能要移动大量元素。顺序查找不要求有序，但太慢。分块查找取了个折中：块与块之间有序，块内部可以无序。

把 n 个记录分成 b 块，满足"前一块的最大关键字 < 后一块的所有关键字"。另建一张索引表，每项记录一块的最大关键字和起始位置，索引表按关键字有序。

查找分两步：

  1. 在索引表里确定目标在哪一块（顺序或折半都行，因为索引表有序）；
  2. 在那一块里顺序查找。

查 33：索引表里 33>20、33≤45，定位到第 2 块；块内顺序比较 27、45、33，命中

示例： 15 个记录分 3 块，每块 5 个。查 33：

  1. 索引表：33 与 20 比，33>20；与 45 比，33≤45，在第 2 块。比较 2 次。
  2. 块内：27、45、33，第 3 次命中。

共比较 5 次。插入新记录 30 只需放进第 2 块末尾（块内无序），不必移动其他块。

算 ASL： n 个记录均分成 b 块，每块 s 个（n=b·s），两步都用顺序查找：

ASL = (b+1)/2（找块）+ (s+1)/2（块内）= (n/s + s)/2 + 1

当 s = √n 时最小，为 √n + 1。

  • 本例 b=3、s=5：ASL = 2 + 3 = 5（对 15 个记录逐个查找再求平均，结果也是 5）。
  • n=10000、s=100 时：ASL = 50.5 + 50.5 = 101，远小于顺序查找的 5000.5。
  • 如果索引表用折半查找，ASL ≈ ⌈log₂(b+1)⌉ + (s+1)/2，10000 个记录分为 100 块时约为 7 + 50.5 = 57.5。

要点：

  1. 分块查找又叫索引顺序查找：块间有序、块内无序。
  2. 两步都顺序查找时 ASL = (b+1)/2 + (s+1)/2，s=√n 时最优，ASL=√n+1。
  3. 性能介于顺序查找和折半查找之间，插入方便，适合动态变化的表。

17.7 排序的基本概念：稳定性、内部与外部排序

排序把记录按关键字重新排列。很多题目的第一步就是排序（去重、二分、双指针、合并区间）。考试关心的不只是"能排好"，还有稳定吗、用多少额外空间、每趟之后长什么样。

稳定性： 如果两条记录关键字相等，排序前 A 在 B 前面，排序后 A 仍在 B 前面，就说这种排序算法是稳定的。我们用 2A、2B 表示键都是 2、但是两条不同的记录：

两行结果按键都有序；只有第二行保留了"2A 在 2B 前"的原有次序

稳定性在多关键字排序中很重要：例如交易记录先按时间排好，再按"账户"做一次稳定排序，同一账户内仍然按时间有序。17.17 的基数排序就靠这一点工作。

判断稳定性的方法： 看算法会不会让一个元素"跳过"和它相等的元素。

  • 只交换或移动相邻元素、并且相等时不动的（直接插入、冒泡），稳定。
  • 发生远距离交换的（简单选择、快速排序、堆排序、希尔排序），一般不稳定。
  • 要证明一个算法不稳定，举一个反例就够了，例如 [2A, 2B, 1]。

内部排序与外部排序：

  • 内部排序：数据全部放在内存里排序。17.8–17.18 讲的都是内部排序。
  • 外部排序：数据太大，内存放不下，要在内存和磁盘之间多次交换数据。重点是减少磁盘读写次数，见 17.19–17.21。

算法分类： 按基本操作，内部排序分为五类：

前四类靠比较关键字；非比较类利用关键字本身的数值或数位

比较排序的下界： 只通过比较来排序，n 个互不相同的元素有 n! 种排列，每次比较最多把可能性分成两半，所以最坏至少需要 ⌈log₂(n!)⌉ 次比较，量级是 Ω(n log n)。例如 5 个元素至少要 ⌈log₂120⌉ = 7 次比较。计数、基数排序不靠比较，因此可以做到线性。[1]

要点：

  1. 稳定 = 相等关键字的相对次序不变。
  2. 稳定的：直接插入、折半插入、冒泡、归并、计数、基数。不稳定的：简单选择、希尔、快速、堆。（口诀："快些选堆"不稳定——快排、希尔、选择、堆。）
  3. 基于比较的排序，最坏情况下界是 Ω(n log n)。

17.8 直接插入排序与折半插入排序

打牌时我们整理手牌的方式就是插入排序：左手的牌已经排好，右手每摸一张，就从右往左找到它该在的位置插进去。数据基本有序或者数据量很小时，它比快排还快，所以常见的 C++ std::sort 实现在小区间上也会切换成插入排序；标准只规定它平均 O(n log n) 且不保证稳定，需要稳定时用 std::stable_sort。[2]

把数组分成"有序区 a[0..i−1]"和"无序区 a[i..n−1]"。第 i 趟取出 a[i]，记为 x，在有序区里从右往左找：比 x 大的元素都右移一格，直到遇到不比 x 大的元素，把 x 放在它后面。

示例： 对 49 38 65 97 76 13 27 49* 排序，每一行是插入 a[i] 之后的整个数组：

浅色底 = 有序区（还会变动，未必是最终位置）；第 i 行是把 a[i] 插入后的结果

  • i=1：x=38，49 右移，38 放到 a[0]。
  • i=2、3：65、97 都比前一个大，原地不动，各比较 1 次。
  • i=5：x=13，比有序区所有元素都小，97、76、65、49、38 依次右移 5 格，13 放到最前面。
  • i=7：x=49*，97、76、65 右移；遇到 49，49 ≤ 49*，停下，49* 放在 49 后面——稳定的来源就是"只移动严格更大的"。

代码（变量表：x 是本趟待插入的元素；j 从 i−1 往左扫，指向当前比较的有序区元素）：

void insertionSort(vector<int>& a) {
    for (int i = 1; i < (int)a.size(); ++i) {
        int x = a[i];                         // 待插入的元素先拿出来
        int j = i - 1;
        while (j >= 0 && a[j] > x) {          // 只移动严格更大的：稳定
            a[j + 1] = a[j];
            --j;
        }
        a[j + 1] = x;
    }
}
# 原地排序：a 是列表，改动调用者看得到。日常写代码直接用 a.sort() / sorted(a)：
# 它们是稳定的 Timsort（归并 + 插入的混合），最坏 O(n log n)
def insertion_sort(a):
    for i in range(1, len(a)):
        x = a[i]                              # 待插入的元素先拿出来
        j = i - 1
        while j >= 0 and a[j] > x:            # 只移动严格更大的：稳定
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x

复杂度：

  • 最好情况（已经有序）：每趟只比较 1 次、不移动，共 n−1 次比较，O(n)。
  • 最坏情况（逆序）：第 i 趟比较 i 次、移动 i 次，共 n(n−1)/2，O(n²)。
  • 平均 O(n²)，辅助空间 O(1)，稳定。

本例 7 趟的比较次数分别是 1、1、1、2、5、6、4，共 20 次。

折半插入排序： 有序区本来就有序，找插入位置可以用折半查找代替从右往左逐个比较。注意两点：

  1. 遇到相等关键字时继续往右找（low = mid + 1），把新元素放在相等元素之后，才能保持稳定。
  2. 找到位置后，元素仍要一个一个右移，移动次数和直接插入完全一样。
void binaryInsertionSort(vector<int>& a) {
    for (int i = 1; i < (int)a.size(); ++i) {
        int x = a[i], low = 0, high = i - 1;
        while (low <= high) {                 // 在有序区 [0, i-1] 里找插入位置
            int mid = (low + high) / 2;
            if (x < a[mid]) high = mid - 1;
            else low = mid + 1;               // 相等时往右走：保持稳定
        }
        for (int j = i - 1; j >= low; --j) a[j + 1] = a[j];   // 移动次数和直接插入一样多
        a[low] = x;
    }
}
# 标准库 bisect.bisect_right(a, x, 0, i) 就是这段 while 循环（相等往右走）
def binary_insertion_sort(a):
    for i in range(1, len(a)):
        x, low, high = a[i], 0, i - 1
        while low <= high:                    # 在有序区 [0, i-1] 里找插入位置
            mid = (low + high) // 2
            if x < a[mid]: high = mid - 1
            else: low = mid + 1               # 相等时往右走：保持稳定
        for j in range(i - 1, low - 1, -1): a[j + 1] = a[j]   # 移动次数和直接插入一样多
        a[low] = x

本例折半插入共比较 16 次（直接插入 20 次），但移动次数相同，所以时间复杂度仍是 O(n²)。折半插入的比较次数与初始顺序关系不大，约 O(n log n)；而直接插入的比较次数强烈依赖初始顺序。

要点：

  1. 直接插入：最好 O(n)，平均和最坏 O(n²)，空间 O(1)，稳定，顺序表和链表都适用。
  2. 每趟后前 i+1 个元素有序，但不一定在最终位置（后面可能还有更小的元素插进来）。
  3. 折半插入只减少比较次数，移动次数不变，时间复杂度仍为 O(n²)，稳定，只适用于顺序表。

d=4 这一趟，第 2 组 (38, 13) 交换，13 一步从下标 5 跳到下标 1；d=2 后，序列已经很接近有序，d=1 的插入排序只需少量移动。

代码（变量表：d 是当前增量；i 从 d 开始逐个处理，相当于各组交替进行插入；j 每次向左跳 d 格）：

void shellSort(vector<int>& a, const vector<int>& gaps) {
    int n = (int)a.size();
    for (int d : gaps) {                      // 每个增量做一趟
        for (int i = d; i < n; ++i) {         // 各组交替做"间隔为 d 的插入排序"
            int x = a[i], j = i - d;
            while (j >= 0 && a[j] > x) {
                a[j + d] = a[j];
                j -= d;
            }
            a[j + d] = x;
        }
    }
}
def shell_sort(a, gaps):
    n = len(a)
    for d in gaps:                            # 每个增量做一趟
        for i in range(d, n):                 # 各组交替做"间隔为 d 的插入排序"
            x, j = a[i], i - d
            while j >= 0 and a[j] > x:
                a[j + d] = a[j]
                j -= d
            a[j + d] = x

代码和直接插入排序几乎一样，只是把"左移 1 格"换成"左移 d 格"。

复杂度： 希尔排序的时间复杂度依赖增量序列，至今没有对一般序列的精确结论。考试常用的口径：** n 在某个范围内约为 O(n^1.3)，最坏 O(n²)**。空间 O(1)。

稳定性： 相等的元素可能被分到不同组，各自在组内移动后次序颠倒。例如 [5, 2, 2*, 1]、增量 2、1：d=2 时第 1 组 (5, 2*) 变 (2*, 5)，第 2 组 (2, 1) 变 (1, 2)，得到 2* 1 5 2；d=1 后得到 1 2* 2 5，不稳定。

要点：

  1. 希尔排序 = 分组插入排序，最后一趟增量必须是 1。
  2. 时间复杂度依赖增量序列，常记 O(n^1.3)，最坏 O(n²)；空间 O(1)；不稳定。
  3. 只适用于顺序表（需要按下标跳着访问）。

17.10 冒泡排序：相邻比较，大的往后冒

冒泡排序是最容易写对的排序，面试常让手写；它也是理解"每趟后某些元素到达最终位置"的最好例子。

从前往后比较相邻两个元素，前者大于后者就交换。一趟下来，最大的元素被一路换到末尾，像气泡浮上水面。第 k 趟只需处理前 n−k+1 个元素。如果某一趟一次交换都没发生，说明已经有序，可以提前结束。

示例：

深色 = 已到最终位置。第 k 趟后末尾 k 个元素就位；第 6 趟没有发生交换，提前结束

第 1 趟：49 与 38 交换；49 与 65 不换；65 与 97 不换；97 依次与 76、13、27、49* 交换，97 到末尾。49 与 49* 相等时不交换，所以冒泡稳定。第 6 趟没有交换，算法结束，只用了 6 趟而不是 7 趟。

代码（变量表：i 是已完成的趟数，末尾 i 个已就位；swapped 记录本趟是否交换过）：

void bubbleSort(vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {
        bool swapped = false;
        for (int j = 0; j + 1 < n - i; ++j)
            if (a[j] > a[j + 1]) { swap(a[j], a[j + 1]); swapped = true; }
        if (!swapped) break;                  // 一趟没有交换：已经有序
    }
}
def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):            # 即 j + 1 < n - i
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]   # 元组赋值代替 swap
                swapped = True
        if not swapped: break                 # 一趟没有交换：已经有序

复杂度： 最好情况（有序）比较 n−1 次、0 次交换，O(n)；最坏情况（逆序）比较和交换都是 n(n−1)/2，O(n²)；平均 O(n²)；空间 O(1)；稳定。

有些教材从后往前冒泡，每趟把最小的元素换到前面。对本例，从后往前的第 1 趟得到 13 49 38 65 97 76 27 49*。做题时先看清题目是哪个方向。

要点：

  1. 冒泡每趟使一个元素（当前最大或最小）到达最终位置，第 k 趟后一端有 k 个元素就位。
  2. 带"无交换则停止"的冒泡，最好 O(n)；平均和最坏 O(n²)；空间 O(1)；稳定。
  3. 顺序表和链表都可以用。

17.11 快速排序（上）：一次划分的完整过程

快速排序是实际使用最多的排序，平均最快。笔试最常考的就是"第一趟划分后的序列"，所以这一节把一次划分的每一步都画出来。

选一个元素作枢轴（pivot），通过一趟划分把序列分成两部分：左边都 ≤ 枢轴，右边都 ≥ 枢轴，枢轴本身落在最终位置。然后对左右两部分递归做同样的事。

本书采用国内教材（严蔚敏版、408）的划分方法，这种方法常被称为“挖坑法”：

  1. 取首元素作枢轴，存进变量 pivot，a[low] 就空出一个"坑"。
  2. high 从右往左找第一个小于枢轴的元素，把它填进左边的坑，于是 a[high] 成了新坑。
  3. low 从左往右找第一个大于枢轴的元素，把它填进右边的坑，a[low] 成了新坑。
  4. 重复 2、3，直到 low 与 high 相遇；把 pivot 填进最后的坑。

代码（变量表：pivot 保存枢轴值；low、high 两个指针相向移动，二者之一始终指向"坑"）：

int partition(vector<int>& a, int low, int high) {
    int pivot = a[low];                       // 枢轴取首元素，a[low] 成了"坑"
    while (low < high) {
        while (low < high && a[high] >= pivot) --high;
        a[low] = a[high];                     // 比枢轴小的填到左边的坑
        while (low < high && a[low] <= pivot) ++low;
        a[high] = a[low];                     // 比枢轴大的填到右边的坑
    }
    a[low] = pivot;                           // low == high：枢轴的最终位置
    return low;
}

void quickSort(vector<int>& a, int low, int high) {
    if (low < high) {
        int p = partition(a, low, high);
        quickSort(a, low, p - 1);
        quickSort(a, p + 1, high);
    }
}
def partition(a, low, high):
    pivot = a[low]                            # 枢轴取首元素，a[low] 成了"坑"
    while low < high:
        while low < high and a[high] >= pivot: high -= 1
        a[low] = a[high]                      # 比枢轴小的填到左边的坑
        while low < high and a[low] <= pivot: low += 1
        a[high] = a[low]                      # 比枢轴大的填到右边的坑
    a[low] = pivot                            # low == high：枢轴的最终位置
    return low

# 递归深度最坏是 O(n)（输入已有序时）。Python 默认递归上限约 1000 层，
# 几千个有序元素就会 RecursionError；要么 sys.setrecursionlimit，要么随机选枢轴
def quick_sort(a, low, high):
    if low < high:
        p = partition(a, low, high)
        quick_sort(a, low, p - 1)
        quick_sort(a, p + 1, high)

要点：

  1. 一趟划分后，枢轴到达最终位置；左侧都不大于它，右侧都不小于它。
  2. 挖坑法：先动 high（找小的），再动 low（找大的），轮流填坑。
  3. 相等元素 49* 留在了右边并越过了别的元素，快速排序不稳定。最简单的反例：[2, 2*, 1] 以 2 为枢轴，第一趟得到 1 2* 2。

17.12 快速排序（下）：每趟结果、最好最坏与空间

划分会递归进行。考试问"第二趟后的结果""最坏比较多少次""递归栈多深"，都要先把递归过程看清楚。

"一趟"是什么： 408 等考试把同一层递归里的所有划分合起来算一趟。第一趟对整个序列划分一次；第二趟对左右两个子序列各划分一次……

每个方框是一次划分；同一层的划分合起来算"一趟"。递归深度 3 层

深色 = 本趟及之前的枢轴，已在最终位置。第 2 趟后 13 27 38 49 49* 65 76 97 数值上已有序，但 49* 65 还要第 3 趟确认

  • 第 1 趟：49 就位（下标 3）。
  • 第 2 趟：左边 [27 38 13] 以 27 为枢轴，得 13 27 38；右边 [76 97 65 49*] 以 76 为枢轴，得 49* 65 76 97。27、76 就位。此时一共有 3 个枢轴（49、27、76）在最终位置。
  • 第 3 趟：只剩 [49* 65] 需要划分，49* 就位。13、38、97、65 这些长度为 1 的子序列不需要划分。

由此得到判断规律：第 k 趟后，至少有 k 个元素在最终位置。更精确地说，若每次枢轴都不在端点，第 2 趟后至少 3 个元素就位；若第 1 趟枢轴落在端点（另一侧为空），第 2 趟只多 1 个，至少 2 个。

最好、最坏、平均：

  • 最好：每次枢轴都把序列平分。递归树高约 log₂n，每层划分的总比较量约 n，时间 O(n log n)。递推式 T(n)=2T(n/2)+O(n)，按第 13 章的主定理得 Θ(n log n)。
  • 最坏：序列已经有序（或逆序），首元素作枢轴时每次划分一边为空，另一边只少 1 个。比较次数 (n−1)+(n−2)+…+1 = n(n−1)/2，时间 O(n²)。8 个有序元素的递归深度达到 7 层，而本例只有 3 层。
  • 平均：O(n log n)，而且常数小，是内部排序中平均性能最好的。

空间复杂度： 快速排序不需要额外数组，但递归要用栈。

情况递归深度辅助空间
最好 / 平均约 log₂nO(log n)
最坏（每次一边为空）n−1O(n)

只对较短的一侧递归、较长的一侧改成循环，可以把栈深度压到 O(log n) 以内，但最坏时间仍是 O(n²)。

怎样避免最坏情况： 随机选枢轴，或"三数取中"（取首、中、尾三个元素的中位数作枢轴），使有序输入也能分得比较均匀。

要点：

  1. 快速排序：平均 O(n log n)，最坏 O(n²)（初始有序或逆序时）；空间平均 O(log n)、最坏 O(n)；不稳定。
  2. 初始序列越乱越快，越有序越慢——这一点和插入、冒泡相反。
  3. 第 k 趟后至少 k 个元素在最终位置；只适用于顺序表。

17.13 简单选择排序：每趟选出最小的

选择排序的思路最直接：每一趟从剩下的元素里找出最小的，放到前面。它的交换次数很少（最多 n−1 次），在"交换代价很大"的场合有用。

第 i 趟（i 从 0 起）在 a[i..n−1] 中找到最小元素的下标 k，然后交换 a[i] 与 a[k]。

示例：

深色 = 已就位的前缀。第 1 趟 13 与 49 交换，49 一步跳到下标 5（橙色）。这种远距离交换可能越过等值元素：本例碰巧没越过 49*，换成 [2, 2*, 1] 就会得到 1 2* 2

  • 第 1 趟：最小值 13 在下标 5，与 a[0]=49 交换，49 被甩到下标 5。
  • 第 2 趟：在 a[1..7] 中最小值 27 在下标 6，与 38 交换。
  • 第 5 趟：剩下 76 97 65 49*，最小 49*，与 76 交换。
  • 第 7 趟后完成。

代码（变量表：k 记录本趟找到的最小元素下标）：

void selectionSort(vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {
        int k = i;
        for (int j = i + 1; j < n; ++j)
            if (a[j] < a[k]) k = j;            // 记住最小者的下标
        swap(a[i], a[k]);                     // 远距离交换：破坏稳定性
    }
}
def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        k = i
        for j in range(i + 1, n):
            if a[j] < a[k]: k = j             # 记住最小者的下标
        a[i], a[k] = a[k], a[i]               # 远距离交换：破坏稳定性

复杂度： 不管初始序列如何，第 i 趟都要比较 n−1−i 次，总比较次数固定为 n(n−1)/2（n=8 时 28 次），所以最好、平均、最坏都是 O(n²)。交换最多 n−1 次，移动次数 O(n)。空间 O(1)。

稳定性： 对 [2, 2*, 1]，第 1 趟把 1 和 2 交换，得到 1 2* 2，2 跳到了 2* 后面，不稳定。

要点：

  1. 比较次数与初始顺序无关，恒为 n(n−1)/2；时间始终 O(n²)。
  2. 每趟使一个最小元素到达最终位置，第 k 趟后前 k 个元素就位。
  3. 空间 O(1)，不稳定；顺序表、链表都适用。

17.14 堆排序：用大根堆每次取出最大值

简单选择排序每趟都要从头扫描找最小值，前面比较过的信息全浪费了。堆排序用一个堆把比较结果保存下来，每次取最大值只需 O(log n)。

大根堆是一棵完全二叉树，每个结点都不小于它的孩子，所以堆顶是最大值。用数组存储时（下标从 0 起），结点 i 的孩子是 2i+1 和 2i+2，父结点是 ⌊(i−1)/2⌋。堆的结构见 15.9 节。

堆排序分两个阶段：

  1. 建堆：从最后一个非叶结点 ⌊n/2⌋−1 开始，往前依次对每个结点做下沉（sift down）：与较大的孩子比较，孩子更大就让孩子上移，自己继续往下，直到不小于孩子或到达叶子。
  2. 排序：把堆顶（最大值）与当前堆的最后一个元素交换，堆的大小减 1，再对新堆顶做下沉。重复 n−1 次。

代码（变量表：n 是当前堆的大小，堆占 a[0..n−1]；c 是较大孩子的下标；x 是正在下沉的元素）：

void siftDown(vector<int>& a, int i, int n) {    // 堆的范围是 a[0..n-1]
    int x = a[i];
    while (2 * i + 1 < n) {
        int c = 2 * i + 1;                         // 左孩子
        if (c + 1 < n && a[c + 1] > a[c]) ++c;      // 取较大的孩子
        if (a[c] <= x) break;
        a[i] = a[c];                               // 孩子上移
        i = c;
    }
    a[i] = x;
}

void buildMaxHeap(vector<int>& a) {
    int n = (int)a.size();
    for (int i = n / 2 - 1; i >= 0; --i) siftDown(a, i, n);   // 从最后一个非叶结点往前
}

void heapSort(vector<int>& a) {
    buildMaxHeap(a);
    for (int end = (int)a.size() - 1; end > 0; --end) {
        swap(a[0], a[end]);        // 堆顶（当前最大）放到末尾
        siftDown(a, 0, end);       // 剩下的 a[0..end-1] 重新调成堆
    }
}
def sift_down(a, i, n):                          # 堆的范围是 a[0..n-1]
    x = a[i]
    while 2 * i + 1 < n:
        c = 2 * i + 1                              # 左孩子
        if c + 1 < n and a[c + 1] > a[c]: c += 1    # 取较大的孩子
        if a[c] <= x: break
        a[i] = a[c]                                # 孩子上移
        i = c
    a[i] = x

def build_max_heap(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1): sift_down(a, i, n)   # 从最后一个非叶结点往前

# 标准库 heapq 只有小根堆（heapify / heappop），没有现成的大根堆原地堆排序；这里照教材手写
def heap_sort(a):
    build_max_heap(a)
    for end in range(len(a) - 1, 0, -1):
        a[0], a[end] = a[end], a[0]    # 堆顶（当前最大）放到末尾
        sift_down(a, 0, end)           # 剩下的 a[0..end-1] 重新调成堆

复杂度：

  • 建堆：看上去是 n/2 次下沉、每次 O(log n)，但大多数结点在底层，下沉距离很短，精确分析得建堆总时间 O(n)。
  • 排序阶段：n−1 次下沉，每次最多 log₂n 层，O(n log n)。
  • 合计最好、平均、最坏都是 O(n log n)；原地进行，空间 O(1)；不稳定。

要点：

  1. 升序用大根堆，降序用小根堆。
  2. 建堆从 ⌊n/2⌋−1（1 起编号时是 ⌊n/2⌋）往前下沉，时间 O(n)；整体 O(n log n)，空间 O(1)，不稳定。
  3. 第 k 趟后末尾 k 个元素在最终位置。适合"从大量数据中选出前 k 大"：只需建堆再做 k 次，O(n + k log n)。

17.15 归并排序：自顶向下与自底向上

归并排序是"分治"思想最标准的例子：把问题分成两半，各自解决，再合并。它的最坏情况也是 O(n log n)，并且稳定，所以 Java 对对象数组排序、Python 的 sorted 都用归并的改进版（TimSort）。它的合并思想也是外部排序的基础。

代码（变量表：tmp 是与原数组等长的辅助数组；i、j 分别指向左段 a[lo..mid] 和右段 a[mid+1..hi] 的当前元素；w 是自底向上时的有序段长度）：

void merge(vector<int>& a, vector<int>& tmp, int lo, int mid, int hi) {
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi)
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];   // 相等先取左段：稳定
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi) tmp[k++] = a[j++];
    for (k = lo; k <= hi; ++k) a[k] = tmp[k];
}

void mergeSort(vector<int>& a, vector<int>& tmp, int lo, int hi) {   // 自顶向下
    if (lo >= hi) return;
    int mid = (lo + hi) / 2;
    mergeSort(a, tmp, lo, mid);
    mergeSort(a, tmp, mid + 1, hi);
    merge(a, tmp, lo, mid, hi);
}

void mergePass(vector<int>& a, vector<int>& tmp, int w) {   // 把相邻两段长 w 的有序段合并
    int n = (int)a.size();
    for (int lo = 0; lo + w < n; lo += 2 * w)
        merge(a, tmp, lo, lo + w - 1, min(lo + 2 * w - 1, n - 1));
}

void mergeSortBU(vector<int>& a) {                           // 自底向上
    vector<int> tmp(a.size());
    for (int w = 1; w < (int)a.size(); w *= 2) mergePass(a, tmp, w);
}
# Python 没有 tmp[k++] 这种后置自增，拆成"赋值 + 加一"两步
def merge(a, tmp, lo, mid, hi):
    i, j, k = lo, mid + 1, lo
    while i <= mid and j <= hi:
        if a[i] <= a[j]:                             # 相等先取左段：稳定
            tmp[k] = a[i]; i += 1
        else:
            tmp[k] = a[j]; j += 1
        k += 1
    while i <= mid:
        tmp[k] = a[i]; i += 1; k += 1
    while j <= hi:
        tmp[k] = a[j]; j += 1; k += 1
    for k in range(lo, hi + 1): a[k] = tmp[k]

def merge_sort(a, tmp, lo, hi):                      # 自顶向下；递归深度只有 log n
    if lo >= hi: return
    mid = (lo + hi) // 2
    merge_sort(a, tmp, lo, mid)
    merge_sort(a, tmp, mid + 1, hi)
    merge(a, tmp, lo, mid, hi)

def merge_pass(a, tmp, w):                           # 把相邻两段长 w 的有序段合并
    n = len(a)
    for lo in range(0, n - w, 2 * w):                # 即 lo + w < n
        merge(a, tmp, lo, lo + w - 1, min(lo + 2 * w - 1, n - 1))

# Python 的 sorted / list.sort 就是归并的改进版 Timsort，同样稳定
def merge_sort_bu(a):                                # 自底向上
    tmp = [0] * len(a)
    w = 1
    while w < len(a):
        merge_pass(a, tmp, w)
        w *= 2

a[i] <= a[j] 中的等号让相等时先取左段，49 先于 49* 输出，这就是归并排序稳定的原因。

复杂度：

  • 时间：递归树有 ⌈log₂n⌉ 层，每层合并的总工作量是 n，所以最好、平均、最坏都是 O(n log n)（递推式 T(n)=2T(n/2)+n，见第 13 章主定理）。趟数为 ⌈log₂n⌉。
  • 空间：合并需要一个长度为 n 的辅助数组，所以数组上的归并排序辅助空间是 O(n)（递归栈 O(log n) 是次要项）。用户博客里把归并排序空间写成 O(1)，这是错误的，应为 O(n)。
  • 链表上的归并排序只改指针、不需要辅助数组，自底向上实现可以做到 O(1) 额外空间，这是链表排序的首选方法。

要点：

  1. 二路归并：时间恒为 O(n log n)，空间 O(n)，稳定；趟数 ⌈log₂n⌉。
  2. 合并长度为 m 和 n 的两个有序表，最少比较 min(m, n) 次，最多 m+n−1 次。
  3. 归并排序每趟后没有元素保证在最终位置，但每 2^k 个一段有序。

17.16 计数排序与桶排序：不比较也能排序

前面的排序都靠比较，最坏至少 Ω(n log n)。如果关键字是范围不大的整数（比如年龄 0–150、考试分数 0–100），就可以不比较，直接"数一数每个值有几个"，做到线性时间。

计数排序是什么： 设关键字都在 0..K−1 之间。

  1. 计数：C[v] = 关键字等于 v 的个数。
  2. 前缀和：C[v] += C[v−1]，此后 C[v] = 关键字 ≤ v 的个数，也就是"关键字为 v 的最后一条记录在输出中的位置（从 1 数）"。
  3. 放置：从后往前扫描输入，对每条记录 x，先把 C[x] 减 1，再把 x 放到输出 B[C[x]]。

示例： A = 3 1 4 1* 0 3* 2 1′（三个 1 是不同记录），K=5。

为什么要从后往前？键为 1 的三条记录占输出下标 1..3。从后往前扫描时先遇到 1′，放到最后一个位置 3；再遇到 1*，放到 2；最后遇到 1，放到 1。三条记录在输出中的先后与输入一致，所以稳定。如果从前往后扫描，同时仍从位置 C[v] 往前填，次序就会反过来。

代码（变量表：c 是计数数组，前缀和之后 c[v] 是"≤v 的个数"；out 是输出数组）：

vector<int> prefixCounts(const vector<int>& a, int K) {
    vector<int> c(K, 0);
    for (int x : a) c[x]++;                       // 计数
    for (int v = 1; v < K; ++v) c[v] += c[v - 1];  // 前缀和：c[v] = 不超过 v 的元素个数
    return c;
}

vector<int> countingSort(const vector<int>& a, int K) {
    vector<int> c = prefixCounts(a, K), out(a.size());
    for (int i = (int)a.size() - 1; i >= 0; --i)  // 从后往前放：稳定
        out[--c[a[i]]] = a[i];
    return out;
}
def prefix_counts(a, K):
    c = [0] * K
    for x in a: c[x] += 1                         # 计数
    for v in range(1, K): c[v] += c[v - 1]        # 前缀和：c[v] = 不超过 v 的元素个数
    return c

def counting_sort(a, K):
    c, out = prefix_counts(a, K), [0] * len(a)
    for i in range(len(a) - 1, -1, -1):           # 从后往前放：稳定
        c[a[i]] -= 1                              # Python 没有 --c[...]，先减再用
        out[c[a[i]]] = a[i]
    return out

复杂度： 时间 O(n+K)，空间 O(n+K)（计数数组 + 输出数组），稳定。K 远大于 n 时（例如 n=10、关键字范围 0..10⁹）不划算。只需排序整数本身、不带其他数据时，也可以按计数直接重写数组，但前缀和写法才能排序带数据的记录。

桶排序： 把值域均分成若干个区间（桶），每个元素按值放进对应的桶，各桶内部再用插入排序等方法排序，最后按桶号依次连接。

桶号 = ⌊10x⌋。5 号桶里 .52 在 .51 前，桶内排序后调换。各桶排好后按桶号依次连接：.23 .25 .32 .42 .47 .51 .52

数据在值域上均匀分布、桶数与 n 同阶时，每个桶里平均只有常数个元素，期望时间 O(n)；如果所有数据都挤进同一个桶，就退化为桶内排序的复杂度，用插入排序时为 O(n²)。空间 O(n+桶数)。桶内用稳定排序时，桶排序稳定。

要点：

  1. 计数排序：关键字为小范围整数，时间 O(n+K)，空间 O(n+K)，稳定（从后往前放）。
  2. 桶排序：数据均匀分布时期望 O(n)，最坏取决于桶内排序。
  3. 非比较排序不受 Ω(n log n) 下界限制，因为它们利用了关键字的数值。

17.17 基数排序：按位分配、按位收集

计数排序要求关键字范围小。如果关键字是 9 位的账号，范围有 10⁹，计数数组就太大了。基数排序换个思路：一位一位地排，每一位只有 0–9 十种取值，用计数排序或者 10 个桶就够了。

它是什么（LSD，最低位优先）： 从个位开始，按当前位的数字把元素分配到 0–9 号桶（分配），再按桶号从小到大依次取出（收集）；然后对十位做同样的事，接着百位……共 d 趟，d 是最大数的位数。每一趟的分配-收集都必须是稳定的。

示例： 对 321 45 187 903 56 712 230 89 排序，最大数 3 位，做 3 趟。

LSD 基数排序 [321, 45, 187, 903, 56, 712, 230, 89]

1 / 3

第1步 · 按个位分配到 0–9 号桶，再按桶号从小到大收集

收集结果：230 321 712 903 45 56 187 89
2 / 3

第2步 · 按十位分配到 0–9 号桶，再按桶号从小到大收集

收集结果：903 712 321 230 45 56 187 89（187 与 89 十位都是 8，按上一趟的先后 187 在前）
3 / 3

第3步 · 按百位分配到 0–9 号桶，再按桶号从小到大收集

收集结果：45 56 89 187 230 321 712 903

把数补齐成 3 位看更清楚：每一趟只看一列数字，其余列保持上一趟的相对次序

为什么每趟必须稳定？看 187 和 89：按十位它们都在 8 号桶。第 1 趟按个位后 187 排在 89 前面（7<9），第 2 趟分配时保持这个先后，于是 8 号桶里是 187、89，十位相同的两个数按个位有序。如果第 2 趟打乱了这个次序，低位的成果就丢了。

为什么从低位开始？最后一趟按最高位排，最高位决定大小，最后排的位起决定作用；而它的稳定性保证了"最高位相同的元素按较低位排好的次序"保留下来。如果反过来从百位开始、最后排个位，结果是按个位有序，本例得到 230 321 712 903 45 56 187 89，没有排好。（按最高位优先的 MSD 方法也存在，但它要先按最高位分桶，再在每个桶内递归，做法不同。）

代码（变量表：exp 是当前位的权重 1、10、100……；x / exp % 10 取出当前位数字；每一趟就是一次以该位为关键字的稳定计数排序）：

void radixPass(vector<int>& a, int exp) {         // 按某一位做一趟稳定的计数排序
    vector<int> c(10, 0), out(a.size());
    for (int x : a) c[x / exp % 10]++;
    for (int d = 1; d < 10; ++d) c[d] += c[d - 1];
    for (int i = (int)a.size() - 1; i >= 0; --i) out[--c[a[i] / exp % 10]] = a[i];
    a = out;
}

void radixSort(vector<int>& a) {
    if (a.empty()) return;
    int mx = *max_element(a.begin(), a.end());
    for (int exp = 1; mx / exp > 0; exp *= 10) radixPass(a, exp);   // 个位、十位、百位……
}
# 只处理非负整数：Python 的 // 和 % 向下取整，负数取位的结果和 C++ 不同
def radix_pass(a, exp):                           # 按某一位做一趟稳定的计数排序
    c, out = [0] * 10, [0] * len(a)
    for x in a: c[x // exp % 10] += 1
    for d in range(1, 10): c[d] += c[d - 1]
    for i in range(len(a) - 1, -1, -1):
        c[a[i] // exp % 10] -= 1
        out[c[a[i] // exp % 10]] = a[i]
    a[:] = out        # 必须切片赋值改原列表；写 a = out 只是让局部变量 a 指向新列表，调用者看不到

def radix_sort(a):
    if not a: return
    mx = max(a)
    exp = 1
    while mx // exp > 0:                          # 个位、十位、百位……
        radix_pass(a, exp)
        exp *= 10

复杂度： 设 n 个元素、每个关键字 d 位、每位有 r 种取值（基数 r，十进制 r=10）。每趟分配 O(n)、收集 O(r)，共 d 趟，时间 O(d(n+r))。空间 O(n+r)（计数数组或 r 个桶 + 输出）；用链式队列作桶时常写作 O(r)。** 稳定**。

要点：

  1. LSD 基数排序：从最低位到最高位，每趟"分配 + 收集"，每趟必须稳定。
  2. 时间 O(d(n+r))，空间 O(n+r)，稳定；趟数 = 最大关键字的位数 d。
  3. 不基于比较，适合 d 小、n 大的整数或定长字符串（如日期、身份证号）。

  • n 很小（如 n≤10）或基本有序：直接插入排序。
  • 对链表排序：归并排序最合适。
  • 关键字位数少、n 很大：基数排序。

17.19 外部排序：多路归并与归并趟数

银行日终要对几亿条交易流水按账号排序，数据有几十 GB，内存装不下。这时只能把数据留在磁盘上，分批读进内存处理。磁盘读写比内存访问慢几个数量级，所以外部排序的目标是减少读写磁盘的次数（I/O 次数），而不是减少比较次数。

外部排序分两个阶段。

  1. 生成初始归并段：每次读入内存能装下的一批记录，用内部排序排好，写回磁盘，成为一个有序的归并段（run）。
  2. 多路归并：每次从 k 个归并段各读入一块，在内存里做 k 路归并，输出成一个更长的归并段。重复直到只剩一个段。

这就是 17.15 的归并思想，只是把"两段合并"推广到"k 段合并"，并且数据在磁盘上。[1]

归并趟数： m 个初始归并段做 k 路归并，每一趟段数变为 ⌈m/k⌉，所以

归并趟数 = ⌈log_k m⌉

示例： 一个文件有 2000 个磁盘块，内存一次能排序 25 块，于是生成 2000/25 = 80 个初始归并段。

5 路归并：80 → ⌈80/5⌉=16 → ⌈16/5⌉=4 → 1，共 ⌈log₅80⌉ = 3 趟

  • 5 路归并：段数从 80 依次变为 16、4、1，共 ⌈log₅80⌉ = 3 趟。
  • 2 路归并：段数依次变为 40、20、10、5、3、2、1，共 ⌈log₂80⌉ = 7 趟。
  • 10 路归并：段数依次变为 8、1，共 2 趟。

算 I/O 次数： 每一趟要把整个文件读一遍、写一遍。生成初始段也要读写一遍。

总 I/O = 2 × 块数 × (1 + 归并趟数)

5 路时 2×2000×(1+3) = 16000 次；2 路时 2×2000×(1+7) = 32000 次。可见增大 k、减少 m，都能减少趟数，从而减少 I/O。

两个方向，对应后两节的三种技术：

想减少的东西办法带来的问题解决技术
趟数 ⌈log_k m⌉增大归并路数 k每选一个最小值要比较 k−1 次，k 大了 CPU 开销上升败者树（17.20）
趟数 ⌈log_k m⌉减少初始段数 m（让每段更长）内存大小有限置换选择排序（17.21）
每趟读写的总量段长不等时，先合并短段合并顺序怎么定最佳归并树（17.21）

要点：

  1. 外部排序 = 生成初始归并段 + 多路归并；时间主要花在磁盘 I/O 上。
  2. 归并趟数 = ⌈log_k m⌉；增大 k 或减小 m 都能减少趟数。
  3. 总 I/O = 2 × 文件块数 ×（1 + 归并趟数），"1"是生成初始段那一遍。

17.20 败者树：k 路归并时快速选出最小值

k 路归并的每一步，都要从 k 个段的当前首元素中选出最小值输出。直接比较需要 k−1 次；n 个记录、每趟 (n−1)(k−1) 次比较。k 越大，比较越多，会抵消减少趟数的好处。败者树把每次选最小值的比较次数降到 ⌈log₂k⌉。

败者树是一棵完全二叉树：

  • k 个叶子对应 k 个归并段的当前首元素 b0..bk−1。
  • 每个内部结点 ls[1..k−1] 记录它下面两路比赛中的败者（较大的那个）的段号，胜者（较小的）继续往上比。
  • 额外的 ls[0] 记录全局冠军（最小值）的段号。

输出冠军后，冠军所在的段补进下一个元素，只需沿该叶子到根的路径重新比赛：每层与该结点记录的败者比较一次，输的留下，赢的往上走。路径长度 = 树高 = ⌈log₂k⌉。

为什么记败者而不是胜者： 新元素来自冠军所在的叶子，向上比赛时的对手正是当初输给冠军的那些元素，它们恰好记在路径上的结点里。记败者就能直接拿来比较，不必再去查兄弟结点。

17.21 置换选择排序与最佳归并树

上一节靠增大 k 减少趟数，这一节从另外两个方向下手：让初始归并段更长、更少；段长不等时，按最省 I/O 的顺序合并。

置换选择排序：用同样大的内存生成更长的段

普通方法每次读满内存、排序、写出，段长等于内存容量 w。置换选择排序在输出的同时不断读入新记录，只要新记录不小于刚输出的值，就能接到当前段后面，段长平均可达 2w。

内存工作区 WA 能放 w 个记录。

  1. 先读入 w 个记录。
  2. 从 WA 中选出不小于当前段最后输出值的最小记录，输出到当前段。
  3. 从输入读一个新记录放进 WA；如果它比刚输出的值小，就冻结它（标记为下一段的成员）。
  4. WA 中全部记录都被冻结时，当前段结束；解冻，开始下一段。

示例： 输入 17 21 5 44 10 12 56 32 29 8 60 15，w=3。

带 * 的元素比刚输出的值小，只能留给下一段；工作区全是 * 时，当前段结束

得到 3 个段：5 17 21 44 56、10 12 29 32 60、8 15。如果按普通方法每次读 3 个排序，要生成 ⌈12/3⌉ = 4 个长度为 3 的段。置换选择得到的段更少、更长，前两段都超过了 w。

实际实现中，WA 里选最小值用败者树或小根堆完成，冻结的记录比当前段的任何记录都"大"即可。

最佳归并树：段长不等时怎么合并最省

置换选择生成的段长度不一。合并时，每个记录在被合并几次，就要被读写几次。短段先合并、长段晚合并，总 I/O 就少。

把每个初始段看成一个叶子，权值是它的长度（块数），每次合并对应一个内部结点。总读写量 = 2 × 树的带权路径长度 WPL。使 WPL 最小的树就是 k 叉哈夫曼树（构造方法同 15.11 节，只是每次取 k 个最小的合并），称为最佳归并树。

虚段： k 叉哈夫曼树要求每次恰好合并 k 个。若 (m−1) mod (k−1) = u ≠ 0，就补 k−1−u 个长度为 0 的虚段。

示例： 8 个初始段，长度 2 3 6 9 12 17 18 24，做 3 路归并。

  1. (8−1) mod (3−1) = 1 ≠ 0，补 3−1−1 = 1 个虚段 0。
  2. 取最小的 0、2、3，合并成 5。
  3. 取 5、6、9，合并成 20。
  4. 取 12、17、18，合并成 47。
  5. 取 20、24、47，合并成 91，完成。

三叉哈夫曼树：叶子是初始段长度，内部结点是一次归并产生的新段。WPL = 163

WPL = 5 + 20 + 47 + 91 = 163（每个内部结点的权值之和，等于各叶子"长度 × 深度"之和：(2+3)×3 + (6+9+12+17+18)×2 + 24×1 = 163）。若长度以块计，归并阶段总 I/O = 2×163 = 326 次。如果不排序，直接按给定顺序三个一组合并，总量是 193，比 163 多。

要点：

  1. 置换选择排序生成的初始段长度平均为工作区大小的 2 倍，段数减少，归并趟数随之减少。
  2. 最佳归并树 = k 叉哈夫曼树，总 I/O = 2 × WPL。
  3. 虚段个数：u = (m−1) mod (k−1)，u≠0 时补 k−1−u 个；u=0 时不补。

17.22 分治法：拆成独立的子问题，再合并

本章的折半查找、归并排序、快速排序其实都用了同一种设计思路。考试会问"哪些算法采用了分治策略"，面试也常问"归并和快排都是分治，区别在哪"。

分治法（Divide and Conquer）分三步：

  1. 分解：把原问题分成若干个规模更小、形式相同、相互独立的子问题；
  2. 解决：递归地解决子问题，规模足够小时直接求解；
  3. 合并：把子问题的解组合成原问题的解。

归并排序的递归树。

归并排序的递归树：每层的合并工作量都是 n，层数 log₂n

示例： 用分治的三步对照本章的三个算法：

算法分解解决合并递推式结果
折半查找比较中点，只留一半递归查那一半不需要T(n)=T(n/2)+1O(log n)
归并排序按位置平分（不比较）递归排两半双指针合并，O(n)T(n)=2T(n/2)+nO(n log n)
快速排序按枢轴划分，O(n)递归排两侧不需要平均 T(n)=2T(n/2)+n平均 O(n log n)

归并"分得容易、合得辛苦"；快排"分得辛苦、合得容易"。快排的两侧大小取决于枢轴，所以最坏会退化；归并按位置平分，始终平衡。这些递推式用第 13 章的主定理即可求解。

其他典型的分治算法：求最大子数组和的分治解法、大整数乘法、Strassen 矩阵乘法、求第 k 小（快速选择）、汉诺塔。

要点：

  1. 分治三步：分解、解决、合并；子问题相互独立。
  2. 采用分治的有：折半查找、归并排序、快速排序。
  3. 复杂度用递推式 + 主定理求（第 13 章）。

17.23 动态规划：最优子结构 + 重叠子问题

用分治的写法算斐波那契 f(n)=f(n−1)+f(n−2)，同一个子问题会被反复计算：

f(5) 的调用树共 15 个结点；f(3) 被算了 2 次（橙色那棵是重复的），f(2) 被算了 3 次

f(5) 一共调用了 15 次，f(30) 要调用 2692537 次，增长是指数级的。如果把每个 f(k) 算一次就记下来，只需要算 n+1 个值，时间 O(n)。动态规划就是"把子问题的解存起来，不再重复计算"。

一个问题能用动态规划求解，需要两个性质（选择题常考，标准答案原样记住）：

  1. 最优子结构：问题的最优解包含其子问题的最优解。
  2. 重叠子问题：在递归求解过程中，相同的子问题会被多次计算。

此外，状态的定义要满足无后效性：某个状态一旦确定，之后的决策只与这个状态有关，与它是怎么得到的无关。

两种实现方式：记忆化搜索（自顶向下，递归 + 缓存）和递推填表（自底向上，按顺序算 dp 数组）。五步写法（状态、转移、初始化、顺序、答案）的完整讲解见 11.4 节。

完整走一遍：0/1 背包。 3 件物品（重量, 价值）= (2,4)、(3,5)、(4,7)，背包容量 5，每件最多选一次。令 dp[i][w] 表示"只考虑前 i 件、容量为 w 时的最大价值"：

dp[i][w] = max( dp[i−1][w]（不选第 i 件）, dp[i−1][w−wᵢ] + vᵢ（选第 i 件，要求 w ≥ wᵢ） )

dp[2][5] = max(不选 dp[1][5]=4, 选 dp[1][5−3]+5 = 4+5) = 9；最后一行 dp[3][5]=9 是答案

答案 dp[3][5] = 9，选前两件（重 2+3，价 4+5），而不是选价值最高的那件 (4,7)。

int knapsack01(const vector<pair<int, int>>& items, int W) {   // (重量, 价值)
    vector<int> dp(W + 1, 0);
    for (auto [w, v] : items)
        for (int c = W; c >= w; --c)           // 倒序：dp[c-w] 还是"上一件"的值
            dp[c] = max(dp[c], dp[c - w] + v);
    return dp[W];
}
def knapsack01(items, W):                      # items 是 (重量, 价值) 元组的列表
    dp = [0] * (W + 1)

        for c in range(W, w - 1, -1):          # 倒序：dp[c-w] 还是"上一件"的值；range 右端不含，所以写 w - 1

17.24 贪心算法：每一步选当前最好的

有些问题每一步都"看起来最好"的选择，最后恰好就是全局最优，这时不需要像 DP 那样考虑所有子问题，算法更简单、更快。难点在于判断什么时候能这样做。

贪心算法每一步都做出当前看来最好的选择，做了就不回头。它能得到最优解，需要问题具有两个性质：

  1. 贪心选择性质：全局最优解可以通过一系列局部最优（贪心）选择得到。
  2. 最优子结构：做出贪心选择后，剩下的子问题的最优解与这次选择合起来，就是原问题的最优解。

完整走一遍（贪心成功）：活动安排问题。 6 个活动的时间区间如下，一个会议室同一时间只能安排一个活动，最多能安排几个？贪心策略：每次选结束时间最早、且与已选活动不冲突的活动。

按结束时间排好序；深色是贪心选中的 A、D、F，灰色是因与已选活动重叠而跳过的

完整走一遍（贪心失败）：找零钱。 硬币面值 1、3、4，凑出 6。贪心先拿最大的 4，再拿 1、1，共 3 枚；而 3+3 只要 2 枚。用 DP 计算：dp[x] 是凑出 x 的最少枚数，dp[0..6] = 0 1 2 1 1 2 2，dp[6]=2。面值 1、5、10、25 这种"规范"币制下贪心才是对的（例如 41 = 25+10+5+1，4 枚，与 DP 结果相同）。

背包问题的对照：

  • 部分背包（物品可以切开拿一部分）：按"价值/重量"从高到低贪心是最优的。上节 3 件物品、容量 5：单位价值 2、1.67、1.75，先拿 (2,4)，再拿 (4,7) 的 3/4，总价值 4+5.25 = 9.25。
  • 0/1 背包：按单位价值贪心可能出错。物品 (10,60)、(20,100)、(30,120)，容量 50：按单位价值选 (10,60)、(20,100) 得 160，最优是后两件 220。所以 0/1 背包要用 DP。

典型的贪心算法：活动安排、哈夫曼编码（15.11）、Prim 和 Kruskal 最小生成树、Dijkstra 单源最短路径（16.12、16.14）、部分背包。贪心的刷题写法和证明思路见 11.12 节。

要点：

  1. 贪心算法的两个要素：贪心选择性质和最优子结构。
  2. 贪心与 DP 的区别：贪心每步只做一个选择、不回头，自顶向下；DP 要比较所有子问题的解，通常自底向上。
  3. 部分背包可以贪心；0/1 背包不行，要用 DP。

17.25 回溯法与分支限界法：在解空间树上搜索

为什么需要它们： 有些问题（N 皇后、子集和、0/1 背包、旅行商）没有已知的多项式算法，只能在所有可能的解中搜索。如果把每个选择画成树的一条边，所有候选解就构成一棵解空间树（状态空间树）。回溯法和分支限界法都是在这棵树上搜索，并通过剪枝跳过不可能产生解的子树。

0/1 背包 (2,4)、(3,5)、(4,7)，容量 5 的解空间树。每层决定一件物品"选"或"不选"。

结点里写"已用重量/已得价值"；第 1、2、3 层分别决定物品 (2,4)、(3,5)、(4,7)。红框是被约束剪掉的分支，绿色叶子 5/9 是最优解

不剪枝时这棵树有 2⁴−1 = 15 个结点；用"超重就不往下走"的约束剪掉 3 个结点后，回溯法实际访问 12 个结点，找到最优 5/9。

回溯法是什么： 按深度优先搜索解空间树。走到一个结点时，先用约束函数（如"不超重"）判断，不满足就剪掉这棵子树、退回上一层（回溯），再试下一个选择。退回时要撤销刚才的选择（"恢复现场"）。回溯法适合找所有解或任一解。代码模板（路径、选择列表、结束条件）见 11.1 节。

分支限界法是什么： 按广度优先或最小耗费（最大收益）优先搜索。用一个队列或优先队列保存活结点，每次取出一个结点，一次性生成它的全部孩子；用限界函数估计每个结点可能达到的最好结果，估计值不可能超过当前最优解的结点直接丢弃。分支限界法适合找一个最优解。

例如把物品按单位价值排序为 (2,4)、(4,7)、(3,5)，根结点的上界是把背包装满时部分背包问题的价值 9.25。优先展开上界最大的结点，一旦找到价值为 9 的解，所有上界不超过 9 的结点都不必再扩展。对同样的输入，分支限界法只生成 6 个结点，回溯法则要访问 11 个。

两者对照（选择题高频）：

回溯法分支限界法
搜索方式深度优先广度优先或最小耗费优先
求解目标所有解或任一解一个最优解
存储结构递归栈，O(树高)队列 / 优先队列，可能很大
结点扩展一次生成一个孩子，可能多次成为扩展结点一次生成全部孩子，每个结点只扩展一次
剪枝依据约束函数（+ 限界函数）限界函数为主
典型问题N 皇后、子集、排列、图着色0/1 背包、旅行商、单源最短路径

要点：

  1. 回溯 = 深度优先 + 剪枝 + 恢复现场；分支限界 = 广度/最佳优先 + 限界函数。
  2. 回溯法求所有解，分支限界法求最优解。
  3. 剪枝函数分两种：约束函数（剪去不可行的）、限界函数（剪去不可能更优的）。

多选 · 理解检查 26　关于回溯法和分支限界法，下列说法正确的是？

A. 回溯法通常按深度优先搜索解空间树

B. 分支限界法常用队列或优先队列保存活结点

C. 分支限界法更适合求出所有可行解

D. 回溯法中每个结点只能成为一次扩展结点

查看答案与每个选项的解析

A · 正确：走到底再退回，用递归栈实现。

B · 正确：按广度优先或最小耗费优先扩展。

C · 错误：它的目标是一个最优解；求所有解通常用回溯。

D · 错误：这是分支限界法的特点；回溯法中一个结点回溯回来后会继续扩展下一个孩子。

易错点：

  • 回溯法也可以用限界函数剪枝，区别主要在搜索顺序和求解目标。

小结： 回溯法用 DFS 求全部解，依靠栈实现；分支限界法用 BFS 或最佳优先搜索求最优解，依靠队列实现；约束函数剪去不可行的分支，限界函数剪去不可能更优的分支。
